# TraceWave Studio

PCB 패턴 안테나의 설계, CAD 출력과 EM 해석을 연결하는 내부 검증용 데스크톱 제품입니다. 저장소는 아래 세 영역으로 구분합니다.

| 영역 | 역할과 관리 규칙 |
| --- | --- |
| [00_참고자료](00_참고자료) | 레퍼런스 저장소입니다. 내부 폴더명/파일명과 원문 내용/출처/해시를 보존하며 이름 변경이나 재정리를 하지 않습니다. |
| [01_개발문서](01_개발문서/README.md) | 개발하면서 작성하는 요구, 화면, 기능, 명세, 분석, 검증과 계획 문서입니다. 폴더와 파일은 `숫자번호_한글명` 형식으로 관리합니다. |
| [Code](Code/README.md) | 개발 코드 영역입니다. 제품 소스와 빌드 설정, 시험, fixtures, 실행/검증 도구를 두며 상세 설계 문서를 두지 않습니다. |

개발 문서의 폴더는 `01_요구사항`, 파일은 `01_문서명.md`처럼 한글 이름을 사용하고 각 폴더에서 01부터 새로 번호를 매깁니다. 기존 RFAD 문서, 그림과 기계 판독 JSON도 같은 파일명 규칙을 적용하며 `README.md`만 안내 이름을 유지합니다. 승인 보관본도 파일명은 정리하되 본문/해시/manifest 기록은 그대로 보존하고 이전 경로 대응표로 검증합니다. 문서 안의 요구/FN/API/VT 등 안정 ID는 바꾸지 않습니다. 코드와 참고자료 원본은 적용 대상이 아닙니다. 과거 `Code/runtime_profiles`는 당시 실행 증거를 보존하는 예외이며 이동하거나 내용을 고쳐 쓰지 않습니다.

- [현행 버전의 남은 작업](01_개발문서/09_개발계획/04_현행버전_남은작업.md)에서 단계별 구현과 종료 조건을 확인합니다.
- [현재 개발 상태](01_개발문서/09_개발계획/02_개발착수와_현재상태.md)와 [개발 완료 계획](01_개발문서/09_개발계획/03_개발완료_계획.md): 기존 1~13번 순서를 유지합니다.
- [Studio 화면 설계](01_개발문서/04_화면설계/README.md): 화면별 기능, 버튼 동작, 전환/복귀, 사용성, 이름 정책과 DrawIO/SVG/PNG.
- [기능 계약](01_개발문서/05_기능설계/README.md), [시스템 명세](01_개발문서/02_시스템명세/README.md), [검증과 요구 추적](01_개발문서/07_검증/README.md).
- [승인 원문 보관](01_개발문서/12_보관이력/01_승인기준선/01_삼점사/README.md): 승인 당시 원문/해시와 현재 편집본을 구분합니다.

승인 기준선 RFAD-D0-3.4는 커밋 `6ebeda156e9d31b893bf69046550f5df9b16dc64`입니다. 사용자의 개발 착수 지시에 따라 R1을 부분 구현하고 있으며, 현재 문서의 편집이 새 기준선 승인이나 전체 기능 완료를 뜻하지 않습니다.

Windows 11 + WSL2를 우선합니다. GUI 구성은 wxWidgets + wxAUI + 사용자 정의 2D DesignCanvas + wxGLCanvas/OpenGL ModelView입니다. Qt와 필수 유료 GUI 부품은 사용하지 않습니다. 일반 편집 60 fps/대형 장면 30 fps는 초기 목표이며 전체 성능 수용은 남아 있습니다. Linux GUI와 R2/R3, 비평면 3차원 안테나 해석은 후속 범위입니다.

직접 입력, 카탈로그 출처, 사용자 수정값, 과거 결과와 실제 제작/측정 조건의 미정값을 보존합니다. 원호/IFA 초기 후보와 탐색 근사는 실측 재현이나 성능 합격으로 표시하지 않습니다. RO4350B 국부 방사 도체 손실 변화 2.788446%는 초기 2% 기준을 만족하지 않았고, GHz PTH 독립 물리 정확도도 미확립입니다.
