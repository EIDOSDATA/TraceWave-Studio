# TraceWave Studio 창·렌더러 시제품

리팩토링 중인 독립 C++20 실행 파일이다. SDL3으로 창과 입력을 처리하고 Dear ImGui docking과 ImPlot의 그리기 명령을 bgfx에 제출한다. Windows Vulkan에서 예제 기판과 B0 S11 곡선을 확인했다. Windows UI Automation과 실제 내레이터 검수, 두벌식 조합과 확정 및 취소를 확인했다. 본창과 분리 입력 창의 한자 후보창 위치와 첫 후보 확정을 확인했다. 이동한 분리 창에서 실제 후보창이 캐럿을 따라가는 것도 확인했다. [Windows 1단계 수용 기록](../../../01_개발문서/07_검증/432_창과_렌더러_시제품_검증.md) [리팩토링 계획](../../../01_개발문서/09_개발계획/07_현행버전_완료후_리팩토링.md)

## 빌드와 실행

저장소 루트에서 실행한다. CMake 3.24 이상, Ninja, C++20 컴파일러, GitHub 소스 다운로드 연결이 필요하다. Windows에서 확인한 도구는 Kitware CMake 4.4.3, Ninja 1.13.2, WinLibs MinGW-w64 GCC 16.1.0이다. 다운로드는 소스 개정 및 SHA-256을 검사한다.

```powershell
cmake -S Code/ui/prototype -B Code/build/shell-prototype -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build Code/build/shell-prototype --target tracewave_shell_prototype
ctest --test-dir Code/build/shell-prototype --output-on-failure -V
.\Code\build\shell-prototype\tracewave_shell_prototype.exe
```

현재 개발과 검수는 Windows에서 먼저 진행한다. 후속 Linux·macOS 검수에서는 같은 CMake 명령과 확장자 없는 실행 파일을 사용한다. Linux의 bgfx 빌드에는 X11, OpenGL, Wayland EGL 개발 헤더가 필요하며, 실행에는 Vulkan 로더와 드라이버가 필요하다. macOS에는 Xcode Command Line Tools와 Metal 지원 기기가 필요하다. 테스트에는 접근 가능한 실제 데스크톱 세션과 한글 글꼴이 필요하다. 다른 글꼴을 선택하려면 실행에 `--font <파일>`을 추가한다. Windows는 Malgun Gothic, macOS는 Apple SD Gothic Neo, Linux는 시스템 Noto CJK나 나눔고딕을 우선 탐색한다.

| 조작 | 방법 |
| --- | --- |
| PCB 보기 | 마우스 휠로 확대하고 드래그로 이동한다. **보기 초기화**로 돌아간다. |
| S11 곡선 | ImPlot에서 확대, 이동, 표본 값 확인을 한다. |
| 입력에 초점 | `F6` |
| 입력을 별도 창으로 | `Shift+F8` 또는 **창 > 입력을 별도 창으로**. 같은 메모를 편집한다. 분리 창을 닫으면 본창 메모에 초점이 돌아온다. |
| S11 패널 닫기·다시 열기 | `F7` 또는 패널의 닫기 버튼과 **창 > S11 결과** |
| 별도 결과 창 | `F8` 또는 **창 > 결과를 별도 창으로**. SDL3 플랫폼과 bgfx가 별도 스왑 체인을 지원할 때 활성화한다. |
| 기본 배치 복원 | `F9` 또는 **창 > 기본 배치 복원** |
| 메뉴와 입력 탐색 | `F10`으로 창 메뉴를 열고 방향키와 `Enter`로 조작한다. `Esc`로 닫는다. 메모와 지우기 버튼 사이를 `Tab`과 `Shift+Tab`으로 이동한다. |

패널 위치와 크기는 사용자별 `TraceWave/ShellPrototype/layout.ini`에 저장한다. CTest의 `--smoke` 실행은 메모리에서만 배치를 사용한다. Wayland에서는 ImGui SDL3 백엔드에 따라 기본 창 내부 도킹을 사용한다. Linux와 macOS의 실제 화면 검수 상태는 개발문서에 기록한다.

## Windows Python 서비스 연결

Windows에서는 실행 파일에 세 경로를 지정해 현재 시제품 작업 영역에 기존 Python 서비스를 연결할 수 있다. 명령행에서 연결만 확인하려면 `--service-check`를 추가한다. 상태줄에 연결 상태가 표시되고, 명령행 출력에서 공개 API 계약 버전과 메서드 수를 확인할 수 있다. 작업 영역은 새 시험 폴더 또는 확인할 프로젝트의 작업 사본을 사용한다.

```powershell
$python = 'C:\검수자료\rf-venv\Scripts\python.exe'
$source = (Resolve-Path -LiteralPath 'Code/src').Path
$workspace = 'C:\검수자료\시제품 시험 작업 영역'
.\Code\build\shell-prototype\tracewave_shell_prototype.exe --python $python --source $source --workspace $workspace
```

일반 실행에서는 `capabilities.get`으로 공개 계약을 확인한다. `--service-replay`는 검수용 작업 사본에 표준 입력의 UTF-8 JSON-RPC 요청을 한 줄씩 보낸다. 각 줄에는 요청 ID가 필요하다. 표준 출력은 같은 ID의 응답만 전달하며 서비스 진단은 표준 오류에 기록한다. 응답은 공개 오류를 포함하며 한 요청의 대기 시간은 최대 30초다.

기능 대조는 최신 공개 Windows 설치본의 서비스와 같은 프로젝트의 독립 시험 사본에서 실행한다. [공개 명령 재생 검수](../../../01_개발문서/07_검증/432_창과_렌더러_시제품_검증.md#새-클라이언트의-공개-명령-재생)

## Windows 프로젝트 열기와 2D 편집

앞 절의 서비스 경로를 지정하고 작업 영역에 등록된 상대 경로를 사용한다. 편집 검수는 별도 작업 사본에서 실행한다.

```powershell
.\Code\build\shell-prototype\tracewave_shell_prototype.exe --python $python --source $source --workspace $workspace --open-project 'projects/검수 프로젝트'
```

기판 패널에서 도체를 클릭해 선택한다. 선택 이름에 마우스를 놓으면 객체 ID를 볼 수 있다. 도체가 이동 가능한 경우 도체 이동 줄의 `-X`, `+X`, `-Y`, `+Y` 단추가 활성화된다. 한 번 누르면 해당 축으로 1 mm 이동하고 새 개정을 읽는다. **되돌리기**로 서비스 편집 이력을 실행한다. **저장** 또는 `Ctrl+S`로 현재 개정을 보관하고, **다시 열기** 또는 `F5`로 현재 프로젝트와 저장 개정을 다시 조회한다. 다시 열 때 남아 있는 같은 객체의 선택을 유지한다.

도체를 선택하고 `F2` 또는 **이름 바꾸기 (F2)**를 누른다. 선택이 비어 있으면 프로젝트 이름을 편집한다. 새 이름은 Enter 또는 **이름 변경**으로 적용하고, Esc 또는 **취소**로 초안을 닫는다. **고급 정보**에서 현재 대상의 안정 ID를 읽고 복사할 수 있다. 중복 이름이 거절되면 입력란의 초안을 고쳐 다시 적용한다. 적용한 이름의 영속 저장과 재열기는 위의 프로젝트 조작을 사용한다.

기판의 표시와 저장은 현재 프로젝트 개정에 결합된다. 저장 개정에 마우스를 놓으면 현재 개정과 마지막 저장 개정의 전체 ID를 볼 수 있다. 게시된 3D 형상과 최신 완료 해석 결과는 아래 절차로 읽는다.

## Windows 3D 형상과 S11 결과

- **3D 형상**을 누르면 작업 영역에서 마지막으로 게시된 표시용 메시를 읽는다. 왼쪽 단추 드래그로 회전하고 가운데 단추 드래그로 이동하며 휠로 배율을 바꾼다. 보기 초기화로 시작 각도와 배율을 복원한다. 현재 개정에 대응하는 원본 도체를 클릭하고 **2D 편집**으로 돌아가면 같은 도체가 선택된다.
- **3D 다시 읽기**로 기존 CAD에서 새로 게시한 형상을 불러온다. STEP과 표시 형상을 별도로 게시한 프로젝트에서는 표시 범위의 메시를 사용한다. 3D 개정에 포인터를 두면 전체 개정, 스냅샷과 실행 ID를 볼 수 있다. 현재 개정이 다르면 **이전 설계**로 표시한다.
- **S11 결과**는 최신 완료 해석의 표본을 읽고 주파수(GHz)와 크기(dB)를 그린다. 결과 개정에 포인터를 두면 출처와 자료 SHA-256을 볼 수 있다. **결과 다시 읽기**로 조회를 반복한다. 조회한 설계 개정이 현재 편집 개정과 다르면 **이전 설계**로 표시한다.

## Windows 프로젝트 선택과 저장본 비교

서비스 인수 `--python`, `--source`, `--workspace`를 지정하고 `--open-project`를 생략하면 시작 화면에서 프로젝트를 선택한다. 이미 프로젝트가 열려 있다면 기판의 **프로젝트 선택** 또는 `Ctrl+O`로 선택 화면을 연다. `projects/` 아래에 등록한 폴더 이름을 정확히 입력하고 Enter를 누른다. 개정과 기판이 확인되면 화면을 교체한다.

**최근 프로젝트 열기**는 이 작업 영역에서 성공적으로 열린 항목을 최대 8개까지 유지하며, 목록 이동만으로 프로젝트를 열지 않는다. **보존 묶음 복원**에서 ZIP과 저장본 및 복원 개정, 누락 자료를 확인한 뒤 **승인 후 복원**을 누른다. 완료 후 **복원한 프로젝트 열기**로 확인한다.

`Ctrl+N` 또는 **새 프로젝트**는 입력한 이름으로 새 프로젝트를 만든다. 이미 등록된 이름 또는 읽을 수 없는 경로는 오류를 표시한다. 저장하지 않은 변경이나 실행 중인 작업이 있으면 프로젝트 전환이 대기한다.

**저장본 비교**에서 저장본과 현재 개정, 변경 수를 확인한다. **이전 변경/다음 변경**은 선택한 속성의 두 값을 보여 준다. 이 비교는 읽기 전용이다. 저장 또는 편집으로 개정이 변경되면 **비교 다시 읽기**를 사용한다.

## Windows 목표 편집

기판의 **목표 편집**에서 **새 목표**, **목표 목록**, **대역 프리셋**을 사용한다. 프리셋 목록에는 근거의 판과 적용 범위를 표시한다. **대역과 표본**에서 시작, 끝, 기준 주파수와 임피던스, 평가 포트와 기준면을 편집한다. 등간격 방식은 표본 수를 입력한다. 명시 표본은 `2402 MHz`처럼 숫자와 단위를 한 줄에 하나씩 적는다.

**성능 기준**에서 지정하지 않은 상태, 미정과 직접 입력을 선택한다. 기준의 비교 방향과 단위는 입력란 옆에 표시된다. 변경 사유를 입력하고 **목표 적용**을 누른다. 오류가 나오면 기존 입력을 고쳐 다시 적용할 수 있다. **초안 취소**로 바뀐 입력을 원래대로 돌린다. 기존 목표를 삭제하려면 **목표 삭제**를 선택하고 사유를 입력한 뒤 **삭제 적용**을 누른다. 프로젝트에 저장하려면 `Ctrl+S`를 사용한다.

**출처와 이력**에서 선택한 목표의 원출처, 수량 상태, 변경 전후 개정과 사유를 읽는다. 대상이나 개정이 바뀐 뒤에는 **목표 다시 읽기**로 다시 조회한다.

## Windows 문헌 후보

기판의 **문헌 후보**에서 카드, 방식, 도체층과 연결할 목표를 선택한다. 원문 값이 있는 입력에는 **원문**을 표시한다. 배치는 직접 입력한다. G001 초기식 방식은 식과 적용 조건, 주파수와 가정의 사유를 표시한다. 카드와 방식마다 초안을 유지하며 **초안 취소**로 초안을 비운다.

**형상 미리보기**에서 서비스가 반환한 새 도체, 기준 개정, 미정 입력과 후보 해시를 확인한다. 차단된 후보는 적용할 수 없다. 입력을 수정하면 후보를 다시 검토한다. **검토한 형상 적용**으로 현재 프로젝트에 반영하고 `Ctrl+S`로 저장한다. 기판으로 돌아가 반영된 도체를 확인하거나 기존 되돌리기를 사용한다.

## Windows 출처와 변경 이력

기판의 **출처와 변경 이력**에서 서비스가 현재 개정에서 조회한 채택 기록, 가정과 생략, 변경 이력을 읽는다. **이전 기록**과 **다음 기록**으로 항목을 찾고, 채택 이력의 **이전 값**과 **다음 값**으로 각 항목의 원본과 적용 및 현재 값을 읽는다. 변경 이력에는 서비스가 반환한 변경 전후 개정, 접수 시각과 사유가 표시된다. 저장이나 편집 후 새 응답을 받으려면 **출처 다시 읽기**를 누른다.

## Windows 과거 RF 결과

RF 결과 패널의 **과거 결과**에서 현재 프로젝트의 게시 완료 목록을 읽는다. **이전 결과**와 **다음 결과**로 항목을 이동하면 당시 개정, 완료 시각 또는 봉인 시각, 현재 설계 여부를 확인할 수 있다. **결과 열기**를 누른 뒤 선택한 원본의 pin과 전체 표본을 검증하면 곡선을 교체한다. 결과 개정에 포인터를 두면 전체 개정, 자료 SHA-256과 출처를 볼 수 있다.

**목록 다시 읽기**는 첫 항목부터 조회한다. 페이지 이동 중 목록 변경이 보고되면 목록부터 다시 읽는다. 봉인된 결과를 읽지 못했을 때는 오류를 표시하고 마지막 정상 곡선을 유지한다. **결과 다시 읽기**는 최신 완료 실행을 다시 조회한다. 다중 포트 결과는 `result.open`이 가리키는 봉인 원문에서 S 행렬을 읽는다. **이전 수신/다음 수신**, **이전 입사/다음 입사**로 채널의 dB 곡선을 바꾼다. **이전 주파수/다음 주파수**는 해당 주파수의 실수부, 허수부 또는 자료 상태를 표시한다. **행렬 표**에서 같은 주파수의 모든 채널을 보고 셀을 선택할 수 있다. 포트 이름, 기준면과 임피던스는 원문 값을 사용한다.

## Windows 끝점 편집과 3D 단면

- 2D에서 선이나 원호를 선택하고 **끝점 편집**을 연다. 시작점 또는 끝점과 X/Y 좌표를 고른다. **캔버스에서 지정**으로 클릭하면 **스냅** 설정에 따라 같은 층의 다른 끝점 또는 1 mm 격자를 사용한다. 미리보기를 확인한 뒤 **끝점 적용**을 누른다. **좌표 되돌리기**는 아직 적용하지 않은 좌표를 원래 값으로 돌린다.
- **3D 형상**에서 개정과 원본 메시를 확인하고 **단면 도구**를 연다. X/Y/Z 축, 위치(mm), 보존 방향을 선택한 뒤 **단면 적용**을 누른다. 삼각형 수와 적용한 평면을 확인할 수 있다. 단면을 닫으면 전체 형상을 표시한다. 단면 조작은 저장 개정을 변경하지 않는다.

## Windows CAD 작업 실행

RC10과 동일한 격리 CAD Python을 연결하려면 프로젝트 실행 인수에 `--cad-python`을 추가한다. 작업 영역은 시험 사본을 사용한다.

```powershell
$cadPython = 'C:\검수자료\cad-venv\Scripts\python.exe'
.\Code\build\shell-prototype\tracewave_shell_prototype.exe --python $python --source $source --workspace $workspace --open-project 'projects/검수 프로젝트' --cad-python $cadPython
```

- **3D 생성**은 현재 편집 개정의 입력을 봉인한 뒤 기존 CAD 작업자를 실행한다. 입력 봉인 뒤에는 2D 편집과 저장을 계속할 수 있다. 3D는 바이트와 스냅샷을 확인한 다음 표시하며, 그동안 앞서 게시한 형상을 유지한다.
- **CAD 취소**를 누르면 기존 작업자의 종료 결과를 기다린다. 실행 중 취소된 작업은 이전 형상을 유지한다. 종료 결과를 확인하면 다시 시작할 수 있다.
- **STEP 출력**은 별도 봉인 입력에서 AP242 묶음을 게시한다. 게시 뒤 STEP 개정에 포인터를 두면 작업 영역의 상대 경로와 SHA-256을 볼 수 있다. 같은 화면의 표시 형상은 별도 게시 개정을 유지한다.

## Windows openEMS 해석 실행

설치된 RC10의 서비스 Python과 소스 경로를 사용한다. 서비스가 Windows x64 openEMS 실행 환경을 보고하고 프로젝트에 저장된 해석 조건이 있어야 한다. 조건을 추가하거나 고칠 때는 RC10의 해석 조건 편집 화면에서 저장한다.

1. RF 결과 패널에서 **해석 도구**를 연다. **조건 읽기**로 현재 개정에 저장된 조건을 읽고, **이전 조건**과 **다음 조건**으로 선택한다. 조건 이름에 포인터를 두면 저장된 설정을 볼 수 있다.
2. **계획 검토**에서 입력 검증, 스냅샷 봉인과 계획 생성을 실행한다. 주파수 범위, 표본 수, 예상 격자와 메모리, 실행 시간 상한을 확인한다. 요약에 포인터를 두면 계획과 개정의 전체 ID, 확인된 설정 및 모델 보고서를 볼 수 있다. 입력 오류가 있으면 오류와 해당 항목을 표시한다.
3. 검토한 계획으로 진행하려면 **해석 실행**을 누른다. 이때 기존 서비스가 준비와 openEMS 실행을 시작한다. 승인 전에 편집 개정이 바뀌면 조건부터 다시 읽는다. 실행 중에는 봉인된 입력으로 계산하면서 현재 프로젝트 편집과 저장을 계속할 수 있다.
4. **해석 취소**를 누른 뒤 작업 종료 상태를 확인한다. 실제로 취소되면 직전에 표시한 결과를 유지한다. 단일 포트 해석이 완료되면 그 작업이 게시한 봉인 결과를 읽어 S11 곡선에 표시한다. 다중 포트가 완료되면 봉인된 S 행렬을 열어 포트별 복소 표본과 주파수 곡선을 표시한다. 완료가 먼저 확정된 경우 **결과 다시 읽기**로 새 결과를 확인한다.

## Windows 기술 도면과 PCB/CAM 출력

프로젝트 실행 인수에 설치본의 별도 출력 Python을 지정한다.

~~~powershell
$exchangePython = 'C:\검수자료\exchange-venv\Scripts\python.exe'
.\Code\build\shell-prototype\tracewave_shell_prototype.exe --python $python --source $source --workspace $workspace --open-project 'projects/검수 프로젝트' --exchange-python $exchangePython
~~~

1. 기판의 **출력 도구**에서 **이전 형식**과 **다음 형식**으로 PDF/SVG/DXF 기술 도면, KiCad 보드와 풋프린트, Gerber / XNC / Job 중 하나를 고른다.
2. **출력 검토**로 현재 개정을 봉인한다. 기술 도면은 서비스 기본 용지와 뷰에 저장된 도면 주석 및 배치를 적용한다. 풋프린트는 봉인한 목록에서 대상을 고르고 **선택 검토**를 눌러 대상 부품의 범위를 검토한다. Gerber는 봉인 입력의 전체 구리층과 사용 중인 제조 이미지 층을 검토한다. 검토 요약에 포인터를 두면 개정, 검토 해시와 제외 항목을 볼 수 있다.
3. **승인 후 생성**으로 검토한 입력을 기존 작업자에게 보낸다. 승인 전에 개정이 바뀌면 다시 검토한다. 실행 중에는 **출력 취소**로 종료를 요청할 수 있다. 취소 전 게시한 출력은 유지된다.
4. **재검수**는 게시한 파일과 manifest를 고정해 형식 재읽기 검사를 실행한다. **기록 다시 읽기**는 선택한 형식의 최신 완료 개정과 파일 참조를 복원한다. 게시 개정에 포인터를 두면 상대 경로와 파일 및 manifest의 SHA-256을 볼 수 있다.

## Windows 제조 교환 후보 저장

1. **출력 도구**에서 **KiCad 보드**를 선택한다. **승인 후 생성**으로 보드를 게시하거나 **기록 다시 읽기**로 앞서 게시한 보드의 개정과 manifest를 읽는다.
2. 형식 버튼으로 **IPC-2581C + ODB++**, **IPC-2581C**, **ODB++** 중 하나를 고른다. **제조 후보 ZIP 저장**을 눌러 KiCad의 `kicad-cli.exe`와 작업 영역 밖의 새 ZIP 경로를 선택한다.
3. ZIP에 선택한 제조 파일, 봉인 원본과 `report.json`을 저장한다. 보고서에서 사용한 KiCad 버전, 원본 manifest와 출력의 SHA-256, 수신 검증 상태를 확인한다. 파일 선택 취소, 기존 이름 충돌 또는 원본 해시 불일치 시 원본과 저장된 파일을 유지한다.

## Windows RF 결과 내보내기

RF 결과 패널에서 단일 포트의 최신 완료 곡선을 읽거나 과거 목록에서 내보낼 결과를 연다. **RF 내보내기**에서 해당 결과가 제공하는 CSV, Touchstone, HDF5 또는 보존 원문을 고른다. **결과와 조건 저장**에서 작업 영역 밖의 새 경로를 선택한다. 자료와 *.conditions.json*을 함께 저장하며 조건 파일은 당시 개정, 출처와 고정 해시를 담는다. 저장 대화상자의 취소와 기존 이름 충돌은 원본과 이미 저장한 파일을 보존한다.

## Windows 한글 입력과 화면 읽기

1. 본창에서 `F6`으로 메모를 선택한다. 작업 표시줄에서 Microsoft 입력기의 한글 모드를 확인한다. `g k s r m f`를 누르면 끝 글자 `글`이 조합 중인지 확인한다. `Enter`로 확정한 메모의 값은 `한글`이어야 한다.
2. `r k`로 `가`를 조합한 뒤 `Esc`를 누른다. 조합 표시가 사라지고 앞서 확정한 `한글`이 유지되는지 확인한다.
3. 검수 메모를 비우고 `g k s`를 누른다. `Enter`를 누르기 전에 한자 키 또는 작업 표시줄 Microsoft 입력기 메뉴의 한자 변환을 사용한다. 후보창이 조합 중인 `한`의 캐럿 가까이에 표시되는지 확인하고 창과 후보창의 위치를 기록한다. [Microsoft 한국어 IME 사용법](https://learn.microsoft.com/globalization/input/korean-ime)
4. `Shift+F8`로 분리 입력 창을 열고 같은 절차를 반복한다. 분리 창의 빈 제목 영역을 클릭한 뒤 가로로 드래그한다. 이동한 창에서 `F6`으로 메모에 다시 초점을 주고 후보창 위치를 확인한다.

UI Automation에서 메모의 편집 역할과 값, 창 메뉴의 펼치기와 각 항목의 상태 및 실행, 기판과 RF 결과 및 입력 패널의 이름을 확인한다. Windows 내레이터를 켠 상태에서 `F10`과 방향키, `F6`과 `Tab`을 사용하고, 분리 창에서 `Alt+F4`를 누른 뒤 본창의 메모가 다시 읽히는지 확인한다. 운영체제 IME와 내레이터 확인은 CTest의 합성 SDL 이벤트 시험과 별도로 기록한다.

내레이터는 화면 읽기 호환성을 검수할 때 켠다. 시제품과 CTest는 내레이터를 끈 상태에서도 실행할 수 있다. 실제 발화는 내레이터의 음성 요약 창에서도 확인할 수 있다. [Windows 내레이터 키 명령](https://support.microsoft.com/en-gb/accessibility/windows/narrator/appendix-b-narrator-keyboard-commands-and-touch-gestures)

Windows의 `--smoke`는 분리 입력 창을 같은 모니터에서 옮기고, 이동 전후와 본창 초점 복귀 뒤 메모 캐럿의 SDL IME 위치를 대조한다. 실제 한자 후보창의 화면 위치는 위 절차로 검수한다. [자동 시험 관찰값](../../../01_개발문서/07_검증/432_창과_렌더러_시제품_검증.md#windows-분리-입력-창-이동과-ime-좌표-자동-시험)

## 표시 데이터와 의존성

프로젝트 경로가 없는 예제 실행에서는 원형 기판을 표시한다. 예제 S11은 B0 보존본 `B0-public-api.json`의 `result.page` 응답에서 확보한 8–12 GHz 주파수와 `magnitude_db` 31개를 사용한다. 데이터셋 SHA-256은 `ffdb9e19f126f8a0d4f17a584f88601bf2ad031f41f68689c642d7edb819dd42`다. [B0 고정 기록](../../../01_개발문서/07_검증/430_알원_비제로_기준선_확정.md)

고정 소스는 SDL 3.4.14(zlib), Dear ImGui 1.91.9b docking(MIT), ImPlot 0.16(MIT), bgfx/bx/bimg(BSD-2-Clause), bgfx.cmake(CC0)다. ImGui용 배포 셰이더 바이트코드는 동일 bgfx 소스의 예제 헤더에서 읽는다. 시제품은 시스템 글꼴을 읽으며 자체 글꼴을 포함하지 않는다. [실행 검증](../../../01_개발문서/07_검증/432_창과_렌더러_시제품_검증.md)
