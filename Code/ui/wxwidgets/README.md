## UX 구현 방향

보기 메뉴의 출처와 채택 이력, 파일 메뉴의 저장본 비교는 보존 개정을 읽는다. 저장본 비교는 속성별 이전값과 현재값을 표시한다. 프로젝트 속성의 이름과 설명은 필드 폭에 맞춰 줄을 나눈다. 3D 형상 탭에서 표시 단면을 지정하고 해석을 시작하기 전에 메시와 출력 범위를 검토한다. [실행 화면과 확인 범위](../../../01_개발문서/07_검증/314_윈도우_잔여화면과_시간초과_재검증.md)

완료 계획 8번의 [독립 검증 기록 화면](../../../01_개발문서/04_화면설계/22_독립검증_기록화면.md)은 비교 작업 공간에서 연다. 저장된 계획과 명시적인 판정 기록을 구분하며 사례/6개 검증 축/관찰값, 초기 기준과 누적 예약을 읽는다. 관련 결과는 원래 source/pin을 유지하여 공통 결과와 방사 화면으로 연결한다. 이 화면은 실행 버튼이나 자동 재평가를 제공하지 않으며, 미정 제작/측정 조건과 차단된 사례를 그대로 표시한다.

화면의 기준은 승인된 [05 화면과 사용자 경험 설계](../../../01_개발문서/04_화면설계/01_화면과_사용자_경험_설계.md)다. 원래 사용 흐름과 비교 자료는 [23 추가 요구사항 원본](../../../01_개발문서/01_요구사항/02_원본_추가_요구사항.md), 자료별 검토 수준과 채택 근거는 [18 출처와 근거](../../../01_개발문서/06_분석연구/02_출처와_근거.md)에 보존한다. 과거의 도구 문서 비교와 현재 제품의 실행 검증은 구분한다.

05번의 목표는 상단 프로젝트/저장 상태, 왼쪽 작업/객체 트리, 중앙 2D/3D/표/그래프, 오른쪽 선택 속성, 하단 문제/작업/로그의 작업 공간이다. 현재 wxAUI로 탐색/중앙 2D와 3D 및 해석 결과 탭/선택 속성/문제/로그/CAD 출력을 배치하고 `보기 > 기본 패널 배치 복원`을 제공한다. 결과/비교에서는 별도 원본 목록과 고정 source/pin의 조건 그룹을 표시한다. 제조 출력은 고정 원본의 유한 형식과 실제 포함/손실·검수 범위를 표시하며 전체 UX 수용은 후속이다. 기능별 작업 공간은 사용 맥락에 따라 열며 모든 화면을 동시에 배치하는 구성을 목표로 삼지 않는다.

현재 속성 편집에는 다음 행동을 구현했다.

- 미적용 입력, 적용됨(저장 필요), 저장됨을 구분하고 프로젝트 이름을 표시한다. 프로젝트/설계/저장 개정 식별자는 tooltip의 상세 정보로 제공한다.
- 한글 속성/선택지와 읽기 전용 표시값을 사용한다. 화면에 보이는 표현과 API의 원래 value/UUID는 분리하여 저장값을 바꾸지 않는다.
- 값과 단위를 같은 행에 놓고 입력 방식에서 사용하지 않는 표현식/변수 결합/참조 선택을 숨긴다. 미정 입력은 숫자로 채우지 않으며, 표현식과 참조의 적용된 값은 읽기 전용으로 표시한다.
- ID와 좌표계 같은 상세 필드는 접어두고 필요할 때 펼친다. 입력 도움말은 관련 컨트롤의 tooltip으로 제공한다.
- 서비스 진단의 객체 UUID를 선택 객체와 대응시키고 한글 필드 이름으로 오류를 표시하며 입력 위치로 초점을 이동한다.
- 실행 취소는 Ctrl+Z, 다시 실행은 Ctrl+Y와 승인된 Ctrl+Shift+Z를 지원한다.

2D 작업 공간에는 기판/패턴/재료/급전/입력 검사 접근 동작, 선/원호 생성, 이동/삭제와 수치 좌표 입력을 연결했다. 새 도체층과 유전체층의 위치/두께/재료는 미정으로 보존한다. `해석 입력 검사` 문제 목록은 관련 객체/필드로 이동하며 이전 revision의 진단이면 재검사를 안내한다. 재료/네트/포트는 `설계` 메뉴에서 추가하고 필수 물성/참조/급전 상자를 명시적으로 입력한다.

이 범위의 자동 시험은 아래 기록을 따른다. 12번에서는 실제 한글 IME의 최종 글자 저장, 스크린리더 오류 안내와 입력 초점 복귀, 혼합 DPI 모니터 사이를 이동한 뒤의 배치를 확인한다. 화면 시안은 목표 구성의 검토 자료이며 구현된 창이나 실제 계산 결과의 증거와 구분한다.

[완성형 UI 시안과 wxWidgets 구현 대응](../../../01_개발문서/04_화면설계/09_스튜디오_화면시안.md)은 별도 개발 보조자료로 관리한다. 단위만 바꾼 입력은 적용 후 숫자가 환산된다는 안내와 원래 값/단위를 보여준다. 표현식이나 참조의 기존 숫자는 마지막 적용값이며 미적용 초안의 계산 결과로 표시하지 않는다.

## 개발 환경과 빌드

Windows 11 x64, CPython 3.12, CMake, Ninja, MinGW-w64 GCC를 사용한다. 이번에 확인한 버전과 원본 URL, SHA256은 `Code/runtime_profiles/native-windows-x64.json`에 기록한다. `.local` 의존성과 `build` 산출물은 Git에 넣지 않는다.

Code 폴더에서 실행한다.

```powershell
.\tools\setup_native.ps1 -Jobs 4
```

스크립트는 고정한 wxWidgets 3.2.12와 nlohmann/json 3.12.0을 준비하고 SHA256을 검사한다. 이미 추출한 wxWidgets 폴더는 재사용한다. 수정된 의존성 소스까지 검증하는 기능은 없으므로 검증 빌드에서는 새로 추출한 원본 소스를 사용해야 한다. 컴파일러와 CMake는 PATH에서 제공해야 하며 스크립트가 설치하거나 업데이트하지 않는다.

GNU MinGW의 Windows Release 프리셋은 PE 링크 시각, 빌드 루트 경로와 wxWidgets 빌드 정보 시각을 고정한다. 동일한 테스트 도구 버전과 원본 소스에서 독립 경로 EXE의 SHA256을 비교했다. [재빌드 검증](../../../01_개발문서/07_검증/79_윈도우_독립경로_재빌드검증.md)

wxWidgets는 core/base/aui/gl을 정적으로 연결한다. 3D는 wxGLCanvas와 Windows OpenGL(opengl32), 표시 파일 SHA256은 Windows BCrypt를 사용한다. webview, media, STC, ribbon은 제외한다. CAD Python의 기존 44개 고정 패키지 환경은 유지하며 GUI에 OCCT나 Python을 내장하지 않는다. MinGW의 C++/thread runtime DLL은 설치된 컴파일러 폴더에서 실행 파일 옆으로 복사한다. Qt와 필수 유료 GUI 부품은 사용하지 않는다.

의존성이 이미 준비된 경우 다음 명령도 사용할 수 있다. 이 방법은 runtime DLL을 복사하지 않으므로 컴파일러의 bin이 PATH에 있어야 한다.

```powershell
cmake --preset windows-release
cmake --build --preset windows-release --parallel 4
```

## 실행

기본 개발 환경에서는 Code 폴더에서 다음 명령으로 실행한다. 창에서 프로젝트를 만들거나 연다.

- 보기 > 환경설정에서 패널 표시를 바꾸고 키보드 단축키와 현재 Windows 표시 상태를 확인할 수 있다.
- Ctrl+F는 현재 프로젝트의 객체 검색으로 이동한다. 이름과 종류를 함께 좁힐 수 있다.
- Ctrl+Shift+P는 이름, 메뉴 또는 단축키로 명령을 찾는다. 검색칸에서 Tab으로 목록에 이동한 뒤 방향키와 Enter를 사용한다.
- 보기 > 실행 환경 / 진단은 구성 요소 상태, 이 세션에서 선택한 경로와 현재 로그를 보여 준다.


```powershell
.\tools\launch_gui.ps1
```

Code 폴더를 기준으로 모든 경로를 절대 경로로 전달한다. Python과 source 경로는 GUI와 서비스를 별도로 교체할 수 있도록 명시한다. 개발용 `.venv`는 프로젝트의 Python 환경 설정 절차로 준비한다.

실행 도우미는 `.venv-cad/Scripts/python.exe`가 있으면 CAD 환경도 연결한다. 다른 설치는 `-CadPython <경로>`로 지정한다. 기본 CAD 환경이 없으면 편집/저장은 계속 사용할 수 있고 새 CAD 출력은 비활성화된다. 과거 게시 완료된 mesh의 복원에는 CAD Python을 다시 실행하지 않는다. 프로젝트 파일이 실행 환경이나 worker 코드를 선택하지 않는다.

```powershell
$codeRoot = (Get-Location).Path
$guiArguments = @(
    '--python', (Join-Path $codeRoot '.venv/Scripts/python.exe'),
    '--source', (Join-Path $codeRoot 'src'),
    '--workspace', (Join-Path $codeRoot '.local/gui-workspace'),
    '--cad-python', (Join-Path $codeRoot '.venv-cad/Scripts/python.exe')
)
& (Join-Path $codeRoot 'build/windows-release/bin/tracewave_gui.exe') @guiArguments
```

CAD 환경 없이 직접 실행할 때는 `--cad-python` 항목을 생략한다. `--open-project projects/이름`을 추가하면 같은 workspace의 등록 프로젝트를 바로 연다.

WSL2 openEMS를 설치/감사한 개발 환경에서는 `tools/launch_gui.ps1 -OpenEmsWsl`로 해석을 연결한다. 직접 실행할 때는 `--openems-wsl`을 추가한다. 고정 runtime profile과 설치 감사 자료는 서비스가 확인하며 프로젝트 파일에서 WSL 배포판이나 실행 명령을 지정하지 않는다. 연결하지 않은 경우에도 편집/저장과 이전에 게시한 결과 조회는 가능하다.

`프로젝트` 메뉴에서 새 프로젝트를 만들고 속성을 변경한 뒤 `변경 적용`을 누른다. `저장`은 현재 개정을 저장 기준점으로 지정하고 `스냅샷 만들기`는 불변 프로젝트 사본을 만든다. 열기는 같은 작업 영역에 등록된 `projects/이름` 경로를 받는다. 보존 프로젝트 묶음은 파일 메뉴의 복원으로, 지원 PCB/CAM과 제조사 원문은 `설계 > PCB / CAM 원문 가져오기`로 연다. [형식별 지원과 조건](../../../01_개발문서/05_기능설계/05_출력교환/05_기판형상과_제조파일_교환.md), [제조사 라이브러리](../../../01_개발문서/05_기능설계/05_출력교환/07_제조사_안테나_라이브러리.md)

`편집` 메뉴의 `매개변수 추가`에서 이름, 입력 방식, 물리 차원과 단위를 지정한다. 표현식 방식에서는 원문과 변수 결합 표를 사용한다. 참조 대상은 목록에서 고르며 GUI가 UUID를 결합 값으로 전달한다. 현재 입력 방식에 사용하지 않는 편집 필드는 숨기고 적용된 계산값은 읽기 전용으로 구분한다. 단위만 바꾸면 실제 SI 값은 유지되며 값과 단위를 함께 바꾸면 새 입력으로 해석한다.

`Ctrl+Z`와 `Ctrl+Y` 또는 `Ctrl+Shift+Z`는 서비스의 영속 실행 취소/다시 실행을 요청한다. 이름과 설명은 한 번에 적용되므로 한 번의 실행 취소로 돌아간다. 미적용 입력이 있는 상태에서 선택 변경/열기/이력 이동/종료를 요청하면 확인한다. 저장과 스냅샷은 먼저 현재 입력을 적용하며 검증 실패 시 기존 원본과 폼 입력을 유지한다. `F5`는 현재 저장소 상태를 다시 읽는다. 사용자 프로젝트 파일에 직접 쓰지 않는다.

## 2D 편집과 입력 검사

1. `설계 > 직사각 기판 만들기`에서 폭/길이를, `원형 기판 만들기`에서 중심 x/y와 반지름을 mm로 입력한다. 두 외곽은 같은 보드의 대안이며 원형 PCB를 만들었다고 ground 도체를 채우지 않는다. `도체층 추가` 또는 `유전체층 추가`에서 층 이름을 지정한다. 새 층의 z 위치/두께/재료는 미정이며 물리 입력은 속성에서 별도로 지정한다. 유전체층을 만들었다는 이유로 대표 FR4 물성이나 코어 두께를 채우지 않는다.
2. 활성 도체층과 선폭을 고른다. `선` 도구는 시작점/끝점 두 번 클릭으로 생성한다. `원호` 도구는 중심/시작점/끝 방향 순서로 클릭한다. 원호 반지름은 중심과 시작점 사이 거리이며 마지막 클릭은 끝 방향을 정한다. 기본은 CCW, Shift는 CW다.
3. 정확한 수치가 필요하면 `좌표 입력`을 연다. 원호 도구를 선택한 상태에서는 중심/반지름/시작각/signed sweep/선폭을 입력하고 다른 상태에서는 선분의 양 끝 좌표와 선폭을 입력한다. 좌표는 mm, 각도는 deg이며 음수 sweep은 CW다.
4. 선택 도구로 클릭하거나 드래그하여 이동한다. 드래그 중에는 임시 그림만 갱신하며 놓을 때 명령 하나로 확정한다. `Delete`는 선택 형상 삭제, `Esc`는 진행 중 입력 취소다. 좌표가 매개변수에 결합된 형상은 직접 이동하지 않고 속성에서 수정한다.
5. 휠은 확대/축소, 가운데 버튼은 보기 이동, `보기 > 전체 형상 맞춤`은 전체 형상에 맞춘다. 문맥 도구막대의 스냅을 켜서 같은 보이는 층의 선/원호 끝점 또는 표시 격자에 맞춘다. 선택한 선/원호의 파란 사각형으로 끝점을 드래그한다. 원호의 반지름과 회전 방향은 유지한다. 보기와 그리드/층 숨김은 EM/export 포함 여부를 바꾸지 않는다.
6. `해석 입력 검사`로 현재 revision의 EM 입력 누락을 확인한다. 문제를 활성화하면 관련 객체/필드로 이동한다. 설계를 바꾼 뒤 이전 진단의 위치 이동은 거절하며 다시 검사해야 한다. 검사 완료는 solver 실행이나 RF 성능 합격이 아니다.

2D 표시는 [canvas.get/canvas.apply 계약](../../../01_개발문서/05_기능설계/02_설계편집/03_이차원표시와_직접편집.md)을 따른다. 원본의 미정값을 임의 숫자로 채우지 않으며 기판 외곽과 선/원호를 구분한다. 원형 외곽의 표시/전체 보기에는 실제 중심과 반지름을 사용한다. 미정 치수는 외곽을 꾸며 그리지 않고 입력 진단으로 유지한다. 회전/미러, 일반 구속/Boolean과 고급 도면은 후속이다.

### 다각형 접지, 패드와 비아

`설계 > 다각형 도체 면 추가`는 활성 도체층에 면을 만든다. 한 줄에 `x, y`를 mm로 입력하며 첫 좌표 묶음은 외곽, 빈 줄 다음 묶음들은 구멍이다. 첫 점을 마지막에 반복하지 않는다. 외곽/구멍을 합해 최대 64점, 구멍은 최대 8개를 입력한다. 자가 교차나 잘못된 구멍 배치는 서비스가 거절한다. 생성된 면의 접지/도체 역할과 네트/재료는 선택 속성에서 확인한다. 예시는 외곽 안의 작은 직사각 구멍이다.

```text
-20, -20
20, -20
20, 20
-20, 20

-4, -4
4, -4
4, 4
-4, 4
```

면의 외곽과 각 구멍은 속성의 `좌표 N점 편집` 표에서 수정한다. 각 x/y 좌표를 직접 입력, 미정 또는 매개변수 참조로 구분한다. 숫자 옆의 읽기 전용 단위는 보통 mm이며 mm 환산이 표현 범위를 넘으면 서비스가 m 단위로 제공한다. 참조는 이름과 UUID가 함께 표시되는 목록에서 고른다. 좌표 표의 점 개수는 고정이며 편집 후 `변경 적용`으로 한 명령을 보낸다. 변경하지 않은 좌표의 원래 단위/입력 상태/출처/참조는 서비스가 보존한다. 많은 점의 수량 필드를 모두 펼쳐 전송하는 대신 작은 표 DTO와 한 번만 제공하는 공통 참조 목록을 사용한다.

`원형 패드 추가`는 중심과 지름, `직사각 패드 추가`는 중심/폭/높이/반시계 회전각을 받는다. 치수는 mm, 회전은 deg다. 패드의 네트와 재료도 사용자가 명시한다. 면 내부와 패드는 클릭/드래그할 수 있으며 면의 구멍 내부는 도체로 선택하지 않는다. 면은 아래, 패턴과 패드는 그 위, 비아는 마지막에 그려 넓은 접지가 작은 객체를 가리지 않게 한다. 드래그는 외곽과 구멍을 함께 한 번의 이동 명령으로 바꾸고 실행 취소/다시 실행을 지원한다. 참조 좌표가 있는 면은 직접 드래그로 참조를 끊지 않는다.

`도금 비아 추가`에서 활성 시작 도체층과 명시적으로 선택한 끝 도체층을 연결한다. 끝 층은 적층 순서상 시작보다 뒤에 있는 도체층이다. 목록이 비어 있으면 앞선 층을 활성화하거나 층을 추가한다. 완성 구멍 지름, 도금 두께, 제작 공구 구멍 지름은 서로 다른 mm 입력이며 비운 칸은 미정으로 보존한다. 도금 두께나 제작 구멍을 다른 값으로부터 임의 계산하지 않는다. 연결할 기존 패드들은 체크 목록으로 선택하고 이후 속성의 `연결 패드` 목록에서 변경할 수 있다. 패드나 도금 물성을 자동 생성하지 않으며 빈 패드 목록은 물리 검증 전 초안이다.

비아는 범위 내 도체층 중 하나라도 표시 중이면 보인다. 완성 구멍과 도금이 확정된 경우 원환 외곽을 사용하며 미정 제작 치수는 중심의 점선 십자로 구분한다. 십자 크기는 선택용 화면 표식이며 추정한 물리 지름이 아니다. 비아 중심 선택, 속성 편집, 평행 이동, 이력과 저장은 다른 형상과 같은 안정 ID를 사용한다. 유효한 화면 입력/저장은 실제 비아 접속, IFA 급전, 제작 가능성이나 RF 성능의 합격 판정이 아니다.

## STEP 출력과 3D 형상

서비스의 `export.preview` (API-023), `geometry.build` (API-008), `export.build` (API-024)는 불변 snapshot 기반 비동기 TaskRef다. 상단 `STEP 출력`은 export.build, `3D 형상 > 3D 갱신`은 geometry.build에 연결한다. 현재 두 동작은 같은 기계 형상 패키지를 생성한다. 적용 전 폼 입력은 먼저 검증/적용하고 새 snapshot으로 고정한다. 잘못된 입력은 원본과 폼을 보존한 채 실패하며 CAD를 시작하지 않는다.

별도 호스트 Open CASCADE worker가 실제 두께의 선/원호 도체와 사각/원형 유전체를 생성한다. 결과는 workspace의 `projects/<이름>/artifacts/<run_id>/`에 model.step, model.brep, mesh.json, sidecar.json, validation.json, manifest.json의 6개 파일로 게시한다. 하단 `CAD 출력`에서 진행 상태와 결과 경로를 확인하고 `출력 폴더 열기`로 접근한다. 임의 외부 경로로 복사/덮어쓰는 기능은 아직 제공하지 않는다. 완료 전 staging 파일은 출력으로 표시하지 않는다.

CAD 접수 후에는 2D 편집과 저장을 계속할 수 있다. `작업 취소`는 취소 요청 뒤 실제 worker 종료 확인까지 기다린다. 실패/취소는 이전 정상 출력과 표시 형상을 보존한다. 실행 중 프로젝트 전환은 막으며 종료 시 소유한 CAD 프로세스도 회수한다. 현재 개정과 다른 snapshot의 3D는 `이전 설계의 형상`으로 표시하고 그 선택으로 현재 속성을 변경하지 않는다. 프로젝트를 다시 열면 `cad.latest`가 같은 프로젝트의 마지막 게시 완료 참조를 복원한다. 이전 버전의 mesh 없는 STEP 패키지는 출력 파일 참조만 복원할 수 있다.

3D는 첫 파일을 열 때 wxGLCanvas를 생성한다. worker가 실제 고체에서 tessellation한 표시 mesh만 사용하며 STEP/B-rep의 정확 원호를 삼각형으로 대체하지 않는다. GUI background에서 파일 상한, 경로, SHA256, snapshot/run, 객체 ID, 유한 좌표와 triangle index를 확인한 같은 바이트를 렌더링한다. 초기 표시 상한은 100000 triangles, 300000 vertices, 16 MiB다. 드래그는 회전, Shift/가운데 버튼 드래그는 이동, 휠은 확대/축소, `전체 보기` 또는 F는 맞춤이다. `위에서`/`입체 보기`를 제공하고 현재 개정의 body 선택은 안정 source ID로 속성과 연결한다. 보기 조작은 원본 개정을 바꾸지 않는다.

새 도체층/유전체층의 z 위치 또는 두께가 미정이면 CAD 출력은 차단된다. 속성에서 실제 위치와 양수 두께를 입력하고 패턴이 기판 안에 있도록 구성한다. 유전율/손실/전도도 등 RF 물성 미정은 sidecar에 보존하며 임의 값으로 채우지 않는다. 표시용 float 변환 뒤 퇴화/방향 뒤집힘 또는 허용 범위를 넘는 변 길이 왜곡은 3D 오류로 처리하고 이전 정상 장면을 유지한다. 이 검사는 이미 게시한 STEP의 정밀 기하나 원본을 바꾸지 않는다.

OpenGL 생성/표시 실패는 3D 오류로 표시하며 프로젝트 편집/저장과 STEP 결과 접근은 유지한다. 기존 장면과 canvas가 있는 오류 상태에서는 `전체 보기`로 wxGLContext 재생성과 이전 장면의 재표시를 시도한다. 최초 context 생성에 실패해 canvas가 없으면 `3D 갱신`으로 다시 시도한다. 이는 제한된 복구 경로이며 실제 GPU reset, 여러 DPI와 도킹 조합의 복구 수용 시험을 통과했다는 뜻은 아니다.

[개발 CLI](../../README.md#현재-실행-방법)의 `tools/export_step.py`도 유지한다. CLI를 별도로 실행할 때는 GUI 입력을 적용/저장하고 같은 workspace의 GUI/서비스를 정상 종료한다. CLI는 등록된 현재 영속 개정으로 새 스냅샷을 만들거나 기존 SnapshotRef를 받으며 화면에만 남은 미적용 초안을 읽지 않는다.

AP242 실제 schema/단위와 이름/형상 재입력 확인은 같은 OCCT kernel에서 수행한다. 결과 상태는 내부 기하 검증용 `generated_unverified`이며 제조, 독립 kernel 또는 RF 합격을 표시하지 않는다. 지원 형상과 실패 조건은 [CAD/STEP 계약](../../../01_개발문서/05_기능설계/05_출력교환/02_기계형상_입력과_출력계약.md), 프로세스 취소/복구는 [worker 연결 경계](../../../01_개발문서/03_아키텍처/05_형상과_해석작업_연결경계.md)를 따른다.

## 단일 포트 PCB 해석과 그래프

`설계` 메뉴에서 재료/네트/포트를 만들고 속성에서 물성, 유효 주파수 범위, 두 도체의 참조, 저항, 방향과 급전 상자를 입력한다. 새 항목은 실제 물성을 추정하지 않는다. 포트 좌표는 보드 좌표계의 세 축 값이며 지원 해석 프로필의 접촉/격자 조건도 준비 단계에서 검사한다. 직사각/원형 외곽과 선/원호를 지원하지만 이는 임의 PCB의 모든 구조를 해석한다는 뜻이 아니다.

`해석 > 설정 및 해석 실행` 또는 `해석 결과` 탭에서 시작/끝 주파수, 주파수 표본 수, 최대 격자 간격, 공기 여유, 곡선 허용오차, 최대 시간 단계와 종료 에너지 비율을 확인한다. 대화상자의 초기 제안값은 물성이나 격자 수렴을 확정하지 않는다. `조건 검토`를 누르면 현재 개정에 적용되는 X/Y/Z 격자와 PML, 계산 형상 포함 여부를 미리 읽을 수 있다. 격자 상한 오류가 발생하면 최대 격자 간격으로 이동하며 입력값을 보존한다. 외부 공기에는 가변 격자와 성장률을 지정하고 모델의 임계 구간 최소 분할은 1~8 사이에서 설정할 수 있다. 검토 후 입력을 바꾸면 다시 검토해야 실행할 수 있다. [원호와 IFA 검증](../../../01_개발문서/07_검증/315_윈도우_해석전검토와_실제격자_검증.md)

조건 저장 / 재사용 탭에서 유효한 해석 조건을 이름으로 저장하고, 과거 결과의 조건과 현재 입력이 다른 항목을 비교할 수 있다. 결과 탭의 결과 조건 다시 사용 버튼에서도 열 수 있다. [검증 기록](../../../01_개발문서/07_검증/317_해석조건_저장재사용과_원호아이에프에이_검증.md)

재료나 급전 오류가 발생하면 `문제 속성으로 이동`을 눌러 관련 입력을 편집한다. 미적용 입력은 `변경 적용 후 해석 검토로`에서 적용할 수 있다. 이미 적용했다면 `해석 검토로 돌아가기`를 눌러 방금 입력한 해석 조건을 다시 열고, 현재 개정에서 `조건 검토`를 눌러 확인한다. [원호와 IFA 검증](../../../01_개발문서/07_검증/318_해석오류_속성이동과_조건복귀_검증.md)

현재 서비스의 제한/실행 예산은 [solver 계약](../../../01_개발문서/05_기능설계/04_해석결과/02_해석작업_계약.md)을 따른다.

`국부 격자` 탭에서 급전, 비아 또는 좌표 상자로 정의한 좁은 간극을 추가하고 X/Y/Z별 최대 셀 폭과 우선순위를 입력한다. 검토한 결과표에는 실제 적용 구간과 더 높은 순위의 규칙이 적용된 구간이 표시된다. 선택 구간을 격자에서 열어 경계선과 수치 표의 좌표를 대조할 수 있다. [원호·IFA·PTH 검증](../../../01_개발문서/07_검증/319_객체별_국부격자_윈도우와_준비_검증.md)

`격자 품질` 탭은 축별 실제 셀 폭, 성장률, 모델 종횡비와 파장당 셀 수를 보여준다. 경고를 고르면 최악 구간의 실제 격자선과 확인할 설정을 표시한다. 격자에서도 관련 설정으로 이동할 수 있다. [원호와 IFA 검증](../../../01_개발문서/07_검증/320_격자품질과_수정위치_윈도우검증.md)

`종료 / 기록 출력`에 최대 시간 단계 기준 예상 시간, 메모리와 원시 출력 용량이 표시된다. 해석 결과의 `실행 비용과 종료`에서 실제 실행 시간, 최대 RSS, 원시 출력 바이트를 비교하고 종료 사유를 읽을 수 있다. 최근 미완료 시도는 완료 결과와 별도로 선택한다. [원호와 IFA 실행 검증](../../../01_개발문서/07_검증/321_실행비용과_종료원인_검증.md)

완료된 사용자 PCB 결과에서 `해석 입력과 출처`를 누르면 당시 설계와 조건을 열 수 있다. `재료와 급전`에서 선택한 재료, 급전, 양단 도체 또는 적층의 계산값, 설계 원본 값과 출처를 확인한다. 공통 결과의 `결과 조건`과 방사 패턴 창에서도 같은 화면을 연다. [원호와 IFA 역추적 검증](../../../01_개발문서/07_검증/322_해석결과_출처역추적_검증.md)

설계 탐색의 `프로젝트 기록 찾기`에서 당시 개정 또는 객체 이름·ID를 입력하고 조건, 실행이나 보고서를 고른다. 개별 기록에서 당시 설계, 연결된 결과 곡선과 해석 출처를 연다. 결과 없이 저장한 조건과 실패 시도의 보존 기록도 조회한다. [원호와 IFA 프로젝트 탐색 검증](../../../01_개발문서/07_검증/323_프로젝트기록_개정객체검색_검증.md)

2D 도구줄의 `스마트 치수`에서 두 홀 중심이나 급전 양단을 찍거나 목록에서 선택한다. 거리와 방향을 확인하고 참조 치수 또는 구동 치수로 보존한다. `미리 보기`와 `적용`으로 후보를 적용한 뒤 프로젝트를 저장한다. [원호와 IFA 검증](../../../01_개발문서/07_검증/324_스마트치수_원호와_역에프안테나_검증.md)

2D 도구줄의 `스케치 자동 구속`에서 선·원호·패드와 기준점, 기판 X/Y축을 고른다. `제안 검토`로 적용 전후 자유도와 중복·충돌을 읽고 확인한 제안만 적용한다. `저장 구속`에서 다시 연 구속을 확인하거나 삭제를 검토한다. [원호와 IFA 검증](../../../01_개발문서/07_검증/325_스케치자동치수와_구속_검증.md)

적용 전 폼은 먼저 검증/적용하고 `snapshot.create -> solver.plan -> solver.prepare -> job.submit` 순서로 작업한다. 각 단계는 별도 TaskRef이며 마지막 실행은 준비된 동일 PreparedPlanRef를 사용한다. 스냅샷을 고정한 이후에는 편집과 저장을 계속할 수 있다. 현재 revision과 결과 snapshot이 다르면 `이전 설계의 결과`를 표시하며 옛 결과를 현재 설계의 계산으로 취급하지 않는다. 실행 중 프로젝트 전환은 막는다.

`해석 취소`는 요청 후 실제 작업 종료 확인을 기다린다. 단계 사이에 취소해도 다음 단계를 시작하지 않으며 실패/취소는 기존 정상 그래프를 지우지 않는다. 서비스 연결을 잃으면 guest의 종료/완료를 추정하거나 자동으로 다시 실행하지 않는다. 창을 닫을 때 실행 중인 CAD/해석 작업은 우선 취소하고 최대 30초 동안 상태 확인을 기다린다. 끝내 확인하지 못한 작업은 기존 worker 회수/복구 계약에 따라 처리하며 성공으로 표시하지 않는다.

완료된 결과의 파일 참조를 조회하고 `solver.samples`의 최대 201개 표시 DTO로 S11(dB), VSWR, 임피던스 실수/허수를 그린다. RF 계산/정규화는 GUI에서 반복하지 않으며 표현 불가능한 null 표본은 선을 끊는다. 재열기는 `solver.latest`로 마지막 게시 완료 결과를 복원한다. 결과 파일 URI와 작업 상태 로그는 길이를 제한해 표시한다.

이 프로필은 내부 런타임 검증 단계다. 에너지 종료, 불변 입력과 실제 FDTD 계산/정규화가 확인되어도 격자 수렴, 실제 IFA 측정 일치, 이득/효율 및 NF2FF 방사 패턴의 정확도를 통과한 것은 아니다. 선택적 방사 기록과 기존 읽기 전용 2D 절단면 화면은 [방사 계산 계약](../../../01_개발문서/05_기능설계/04_해석결과/04_사용자기판_방사계산.md)을 따른다. 이를 재사용한 공통 비교/3D 방사 화면은 다음 절의 유한 조회 계약을 사용하고, 8~9번 RF 모델의 적용 범위는 [RF 연구 안내](../../../01_개발문서/06_분석연구/README.md)에 있다. 11번 측정 비교는 외부 측정 파일이 있는 프로젝트에서 선택한다.

## 공통 결과, 비교와 방사/필드 보기

`ResultWorkspace`는 프로젝트 수명/선택 세대와 원본 source/pin을 대조하고 기능별 View에 표시 DTO를 전달한다. 현재 개정의 library뿐 아니라 명시 과거 개정, 봉인 solver 결과와 스윕 후보를 선택하며 식별자가 없는 자료를 현재 결과로 바꾸지 않는다. native 표와 사용자 정의 그래프는 최대 201개 실제 표본을 조회한다. Smith의 개방/단락/정합/능동 영역/overflow와 입력 임피던스/어드미턴스는 서비스가 계산하고 GUI는 받은 값과 상태만 표시한다.

비교는 최대 8개 원본의 곡선을 겹쳐 보고 명시 포트 대응과 정확히 같은 Hz에서 복소 차이를 조회한다. 서로 다른 기하/제작 조건은 별도 표시하며 수학 비교 가능성과 물리 동등성/과거 목표 판정을 합치지 않는다. 우측 조건은 원본/기준/검증 상태의 접기 그룹과 기본 접힌 고급 원문이다. 비교 조건은 32개씩 이전/다음으로 교체하고 시작~끝/총수를 표시한다. 긴 본문은 스크롤과 복사로 확인하며 조건 복사는 현재 표시 문장과 비교 페이지에 한정된다. 늦은 조건 응답은 다른 선택에 붙이지 않는다.

방사 View는 실제 최대 3개 기록 주파수의 복소 Etheta/Ephi와 무차원 투영을 사용하여 OpenGL 3D/2D 절단면, 편파/축비 상태와 지향성/이득 색 단위를 표시한다. 3D CAD mesh, 물리 거리와 표시 반경을 구분한다. 필드는 보존된 primary Yee E/J/rotH의 성분별 좌표와 최대 4096점 ROI/stride를 읽는다. 미기록 필드, 연속파 절대 단위, 벡터 합성이나 원문 rotH 위상 보정을 임의 생성하지 않는다.

고정 원본의 CSV/Touchstone/정규 HDF5와 실제 존재하는 원문 내보내기는 조건 파일을 동반한다. 기존 출력이나 workspace 원본을 덮지 않으며 파일 게시 실패를 성공으로 표시하지 않는다. 과거 목표/출처와 제작·측정 미정값은 저장/재열기 이후에도 보존한다. [상세 기능 계약](../../../01_개발문서/05_기능설계/04_해석결과/07_다중결과와_방사표시.md)에 각 지원 범위와 수치/물리 미확립 경계를 명시한다.

## 연결과 실패 처리

PCB 자료 선택은 `설계 > 기판 설정 / 제조업체 자료`로 연다. 업체/검색어와 자료 종류를 선택하고 층 대응, 물성, 급전 변경을 검토한 뒤 단면 미리보기에서 적용한다. 기존 직접 입력은 유지한다. `launch_gui.ps1 -Catalog <경로>` 또는 `-NoCatalog`를 사용할 수 있으며 실행 파일에는 `--catalog <절대 경로>`를 전달한다. [화면 사용법과 검증 재현](../../../01_개발문서/04_화면설계/11_제조업체와_적층선택_화면.md)을 참고한다.

- C++ GUI는 모델 계산이나 프로젝트 파일 저장 규칙을 복제하지 않고 `rfad.api/2.0` 명령을 호출한다.
- `rfad.editor/0.1`의 작은 선택 DTO를 조회하고 변경 필드만 전송한다. 수식/단위/물성 검증은 서비스가 소유하며 오류 위치와 메시지를 표시한다. 전체 설계 원본을 매 편집마다 다시 받지 않는다.
- `rfad.canvas/0.1`의 mm/deg 표시 DTO와 원본 UUID를 사용한다. 생성/이동/삭제는 expected_revision을 고정한 명령 하나로 보내며 stale 또는 실패 응답에서 부분 원본을 게시하지 않는다. 좌표 참조를 직접 이동으로 리터럴로 바꾸지 않는다.
- 셸 없이 명시한 Python 실행 파일을 시작한다. 공백, 한글과 따옴표를 포함한 경로는 Windows 인수 규칙에 따라 인코딩한다.
- stdin writer와 stdout/stderr reader는 별도 thread다. UI thread는 주기적으로 도착한 응답만 처리하며 pipe read/write를 기다리지 않는다.
- stdout 프레임은 최대 1 MiB, 송신/수신/로그 큐는 각각 최대 64개, GUI pending request는 최대 16개다. stdout 큐 초과와 잘못된 프레임은 연결 오류로 표시한다.
- stderr는 stdout과 별도 큐에서 읽는다. 긴 로그는 약 2 KiB로 자르고 로그 큐 초과는 건너뛴 개수로 표시한다. 화면 기록도 길이를 제한한다.
- 응답 제한 시간은 30초이며 자동 mutation 재전송은 하지 않는다. 오류 뒤에는 작업 영역을 다시 열어 저장된 상태를 확인해야 한다.
- 종료 시 창을 숨긴 뒤 별도 thread에서 자신이 시작한 서비스의 stdin을 닫고 종료를 기다린다. 응답하지 않는 자신 소유의 프로세스만 Windows Job Object로 종료한다. writer 취소 최대 0.5초, 정상 종료 대기 2.5초, 강제 종료 확인 1초를 사용하며 비정상 종료 처리 목표 상한은 5초다. pipe 회수 후 UI 완료 이벤트에서 창을 파괴한다. 일반 편집 명령 중에는 동기 Stop을 호출하지 않는다.
- 프로젝트 한 개정은 최대 24 MiB까지 저장한다. 인라인 전달은 512 KiB, 전송 프레임은 1 MiB까지다. 큰 프로젝트의 트리와 편집 데이터는 페이지 단위로 조회하며 형상 10000개, 매개변수 1000개의 저장과 재열기를 검증했다. [대형 설계 복원 검증](../../../01_개발문서/07_검증/156_대형_탐색트리와_복원_재검증.md)

## 실제 프로세스 시험

```powershell
$env:RFAD_GUI_EXE = (Join-Path (Get-Location).Path 'build/windows-release/bin/tracewave_gui.exe')
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_gui_process.py -v
```

시험은 실제 wxWidgets 이벤트 루프와 Python 프로세스를 실행한다. 한글/공백 경로에서 프로젝트 생성, 이름/설명 변경, 저장, 스냅샷, 서비스 종료/재시작, 재열기 후 내용과 저장 개정 일치를 검사한다. stderr 폭주, 과대 stdout 프레임, 서비스 조기 종료, 없는 Python 실행 파일도 검사한다. `RFAD_GUI_EXE`를 지정하지 않은 Python 기본 시험에서는 이 GUI 시험만 건너뛴다.

기계 형상 시험은 `test_gui_features_process.py`와 `--features-smoke-test`를 사용한다. 실제 홀 폼/미정/거절 후 수정, 단위만 바꿀 때 원문과 검토 유지, 단일 적용/undo/redo/서비스 재시작을 검사한다. `test_gui_pcb_exchange_process.py`와 `--pcb-exchange-smoke-test`는 별도 출력 환경에서 실제 CAM 생성/재검수, 두 청크의 KiCad 전송·읽기, 명시 층/net과 손실 확인, 적용/이력/저장·재시작을 검사한다. 실행에는 `RFAD_GUI_EXE`와 `RFAD_EXCHANGE_PYTHON`을 명시한다. 기능 시험의 성공을 일반 제조/독립 물리 검증으로 사용하지 않는다.

공통 결과 시험은 `test_gui_results_process.py`와 `--results-smoke-test`를 사용한다. 실제 원본 선택/과거 개정/Smith/명시 비교/조건 페이지/늦은 응답 폐기/고정 원본 내보내기와 저장·서비스 재시작을 검증한다. 분석식 입력 fixture는 RF 실측 자료가 아니다. 실제 과거 NF2FF/필드 원문 조회 및 Windows 수동 시각 검수는 [7번 검증 기록](../../../01_개발문서/07_검증/17_다중결과_표시검증.md)에서 별도 근거로 관리한다.

추가 편집 시험은 실제 폼 컨트롤과 같은 처리 경로로 매개변수 생성, UUID 결합 표현식, 의존 재계산, 0 나눗셈 오류의 입력/개정 보존, undo/redo와 재시작을 확인한다. `--editor-smoke-test --smoke-report <절대 JSON 경로>`로 별도 실행할 수 있다. 성공 시 editor_stage=11과 실제 통과한 editor_checks를 기록한다. 속성 편집 버전의 전체 GUI 시험은 6개였다.

2D 시험은 `--canvas-smoke-test --smoke-report <절대 JSON 경로>`를 사용한다. 2D 버전의 전체 GUI 7개에 포함되며 성공 시 canvas_stage=15와 canvas_checks 18개를 기록한다. 검사 항목은 도킹, Esc 취소, 두 점 선분, 원호와 hit testing, 선택 동기화, 드래그 단일 명령, 격자/끝점 스냅, 선·원호 끝점 편집/취소, undo/redo, 속성의 장면 반영, 거절 후 선택 복원, 삭제/취소, 표시 제한, 보기의 원본 불변성, 입력 검사와 실제 해석 구분, 저장/스냅샷/재시작이다. 테스트가 합성한 wx 이벤트의 성공과 실제 화면 시각 확인은 별도로 기록한다.

GUI에 `--smoke-test --smoke-report <절대 JSON 경로>`를 추가하면 같은 정상 흐름을 실행하고 60초 안에 성공/실패 보고서를 남긴다. 정상은 종료 코드 0, 흐름 실패는 2, 보고서 쓰기 실패는 3이다. 보고서는 `physics_tested=false`, `frame_budget_tested=false`를 명시한다.

GUI CAD 통합 시험은 별도 CAD 환경도 지정한다.

```powershell
$env:RFAD_CAD_PYTHON = (Resolve-Path '.venv-cad/Scripts/python.exe').Path
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_gui_cad_process.py -v
ctest --preset windows-release
```

CAD smoke는 `--cad-smoke-test --open-project projects/이름 --smoke-report <절대 JSON 경로>`로 사전에 등록한 기하 fixture를 사용한다. 적용 전 입력, 실행 중 편집/저장, 고정 snapshot과 이전 개정 표시, 실제 GL frame, 취소 후 이전 결과 보존, 서비스 재시작 후 결과 복원을 확인하도록 구성했다. `--cad-expect-failure`는 미정 필수 기하 입력을 정상 출력으로 게시하지 않는 경로다. CAD smoke의 자체 제한 시간은 180초다. CTest에는 표시 mesh 경계/hash/경로와 카메라/picking의 C++ 시험이 포함된다. 최종 실행 수치와 확인 범위는 [개발 기록](../../../01_개발문서/09_개발계획/02_개발착수와_현재상태.md)의 GUI STEP/3D 검증 문단을 따른다. 기능 시험만으로 성능 예산이나 모든 GPU/DPI 조합의 수용을 판정하지 않는다.

실제 WSL PCB GUI 시험은 아래 명령을 사용한다. 등록된 fixture는 작은 원형 PCB와 원호, 명시적 시험 물성을 사용하며 실제 IFA/FR4 기준을 대신하지 않는다.

```powershell
$env:RFAD_TEST_WSL = '1'
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_gui_solver_process.py -v
```

`--solver-smoke-test --openems-wsl --open-project projects/이름 --solver-settings <절대 JSON 경로> --smoke-report <절대 JSON 경로>`는 준비/실행, 실행 중 편집/저장, 고정 snapshot과 이전 개정 표시, 그래프 paint, 후속 작업 취소 시 이전 결과 보존, 서비스 재시작 후 복원을 확인한다. `--solver-expect-failure`는 원형 보드 생성 후 물성/급전이 미정인 입력을 실제 결과로 게시하지 않는 경로다. 자체 제한 시간은 600초이며 통과 시 solver_stage=7과 solver_checks를 기록한다. 이 결과는 GUI 기능과 연결 검증이며 RF 정확도나 프레임 성능 인증이 아니다.

면/패드/비아 시험은 `test_gui_primitives_process.py`를 실행한다. `--primitives-smoke-test`는 구멍 있는 면, 회전 사각/원형 패드, 확정/미정 비아를 생성하고 실제 마우스 선택/드래그, 속성 변경, 패드 다중 참조, 층 숨김, 실행 취소/다시 실행과 저장/스냅샷/재시작을 확인한다. `--coordinate-table-smoke-test`는 64점 다각형의 작은 좌표 표 DTO와 변경/이력/재열기를 확인한다. 둘 다 성공 시 primitives_stage=22와 실제 수행한 primitives_checks를 기록한다. CTest의 canvas_geometry에는 구멍의 선택 거리, 회전 패드와 수치 좌표 파서의 실패 경계도 포함한다.

2026-11-10 속성 화면 UX 보완본의 Windows 전체 207개 시험이 48.800초에 스킵 없이 통과했다. Linux는 207개 중 201개 통과, Windows GUI 6개 스킵이며 19.513초였다. 전체 로그는 `Code/.local/ux-windows-tests.log`, `Code/.local/ux-linux-tests.log`다. 이후 단위 변경 초안 안내와 마지막 적용값 라벨을 보완하고 관련 GUI 6개를 13.780초에 다시 통과했다. 최종 로그는 `Code/.local/ux-gui-final.log`다. 편집 smoke는 기존 editor_checks 7개와 상태/모드/오류 위치/단위 안내의 ux_checks 14개를 검증한다.

위 속성 화면 버전의 초기 시각 점검 후 여백/초점 처리를 수정했다. 당시 이어진 화면 자동화는 사용자의 Esc 입력으로 중단했으며 수정 후 시각 확인을 완료하지 못했다. 이는 이후 2D 작업 공간의 시각 확인과 구분하는 과거 기록이다.

wxAUI/2D 작업 공간 초기 버전의 실제 GUI 7개는 22.337초에 통과했다. 미정 보드 치수, 큰 좌표와 표시 범위를 보완한 뒤 Windows 전체 227개가 스킵 없이 76.152초에 통과했고 Linux는 227개 중 220개 통과/Windows GUI 7개 스킵으로 30.312초였다. 로그는 `Code/.local/canvas-windows-tests.log`, `Code/.local/canvas-linux-tests.log`다. native CTest `canvas_geometry` 1개도 0.13초에 통과했다.

실제 창에서 발견한 도구막대 높이와 DPI 초기 창 크기, 입력 검사 진단의 한국어 본문 연결과 전체/표시 건수 안내를 보완했다. 최종 Release 빌드 후 GUI 7개가 25.908초에 통과했고 실제 창의 배치/기판/선/원호/선택 속성/문제 위치 이동도 확인했다. 로그는 `Code/.local/canvas-gui-final.log`다. 이 기록은 당시 디스플레이에서 확인한 범위다. 실제 한글 IME와 혼합 DPI에서의 조작은 12번 Windows 사용성 검수에 포함한다. 자세한 근거는 [개발 기록](../../../01_개발문서/09_개발계획/02_개발착수와_현재상태.md)에 기록한다.

## 의존성과 배포 범위

명시적 설계/수치/회로 연구는 `test_gui_sweep_process.py`와 `--sweep-smoke-test`로 검증한다. 실제 네이티브 폼에서 후보 검토/단위 보존/검토 무효화/저장-실행 분리, 실제 이상 회로 계산/취소/재개/중복 재사용, 서비스 재시작 후 원문/미정/과거 결과 보존을 확인한다. FDTD는 별도 `test_design_sweep_runner.ActualNativeSweepTests`로 고정 WSL 환경에서 수행한다. [단계 6 기록](../../../01_개발문서/07_검증/13_설계스윕과_연구_검증.md)에 실행 시점과 실제 수동 화면 검수를 분리한다.

현재는 내부 개발 검증용이다. 프로필에 wxWidgets/nlohmann 라이선스 원문 위치와 링크에 들어간 PCRE2, zlib, IJG JPEG, libpng, libtiff 및 NanoSVG의 라이선스 위치를 기록했다. 이 목록은 배포 심사가 끝났다는 의미가 아니다. 외부 배포 전에 최종 실행 파일과 runtime DLL의 실제 포함 목록, 원문 고지, 컴파일러 runtime 조건, 설치 프로그램을 함께 검토해야 한다.

선택적 기록 거리와 격자/각도/전력 예산의 독립 비교는 [PCB 방사 수렴 연구](../../../01_개발문서/06_분석연구/10_사용자기판_방사수렴.md)를 따른다. 완료된 방사 연구 보고서는 기존 수렴 비교 창에서 읽을 수 있으며 실제 제작/측정 입력과 전체 흡수 손실 적분의 미평가 상태를 유지한다.
