# RO4350B 도체 손실의 후속 정밀 연구

갱신일: 2026-11-12 KST. 승인 기준선 RFAD-D0-3.4와 기존 탐색 재료/출처를 유지한다. 실제 납품 재료의 미정 물성, 마스크/표면처리와 제작/측정 조건은 확정하지 않는다.

## 목적과 사전 고정 조건

직전 [개별 손실 연구](pcb_loss_precision.md)의 0.40/0.36 mm 도체 합계 변화는 3.430551%였고, 국부 4분할은 300초 제한으로 중단됐다. 그 연구와 실패를 보존하며 [별도 manifest](../fixtures/ro4350b_loss_refinement_study.json)에서 미확립 격자/국부 축을 다시 검사한다. 종료/곡선 축의 과거 판정을 새 소스로 수행한 추가 FDTD로 집계하지 않는다.

- 격자 축: 0.36/0.32/0.30/0.28 mm. 국부 최소 분할은 기존 기본값이다.
- 국부 축: grid_mm=0.40 mm에서 feature_subdivisions=3/4/5/6.
- 원본 snapshot, 물성/급전, 곡선 허용 오차 0.025 mm, 에너지 종료 1e-5, 외곽/PML/기록 면과 각도는 각 축에서 고정한다.
- 포트 2.4~2.4835 GHz 201점, 직접 손실 2.4/2.44175/2.4835 GHz, NF2FF 30 mm/5 degree를 유지한다.
- 모든 8개 고유 조건과 실제 비교 가드를 첫 실행 전에 만든다. 격자점과 파일 예산을 넘으면 실행하지 않는다.

초기 기준은 그대로 minimum_levels=3, max_relative_delta=0.02, absolute_fraction_floor=0.00001이다. 모든 직접 주파수와 유전체/전체 도체/sheet/via 및 원본 성분의 수용 전력 비율을 비교한다. 전체 에너지 잔차 예산은 3%다. 거친 인접 쌍의 실패를 보존하고, 사전 고정한 마지막 쌍만 최종 설정 안정성으로 판정한다. 합계의 상쇄나 작은 via의 절대 바닥을 상대 2% 물리 정확도로 해석하지 않는다.

## 명시적 실행 예산

```json
"compute_profile": {"kind": "loss_refinement/0.1", "num_threads": 4}
```

profile이 없는 과거 설정은 그대로 최대 1500000 격자점/300초/2스레드다. 독립 손실 기록이 있는 PCB의 명시적 profile만 확장 예산을 사용한다.

| profile kind | 격자점 상한 | 요청 시간 상한 | 손실 필드 추정 상한 |
| --- | --- | --- | --- |
| 없음 | 1500000 | 300초 | 48 MiB |
| loss_refinement/0.1 | 2400000 | 900초 | 48 MiB |
| loss_refinement_deep/0.1 | 3000000 | 1800초 | 96 MiB |

확장 profile은 1~8개 스레드를 명시한다. 0이나 자동 스레드 수, 알 수 없는 profile과 추가 필드는 거절한다. worker CLI는 계획의 num_threads를 소비하고 native 로그의 스레드 값과 대조한다. [설치한 pinned openEMS의 CLI](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/openems.cpp)는 사용 가능 스레드 수로 제한한 값을 출력하므로 다른 값으로 축소된 실행을 그대로 성공시키지 않는다. 최신 배포의 엔진 변경을 소급 적용하지 않는다.

solver.prepare/job.submit의 timeout_seconds는 여전히 요청에 명시해야 한다. 공통 입력 상한은 1800초지만 접수 때 등록된 불변 plan의 max_wall_time_seconds와 다시 비교하므로 기본 계획의 301초, 표준 확장 계획의 901초 요청은 거절된다. 손실 CLI는 각 계획의 상한을 요청에 고정한다. 일반 연구 GUI의 기본 실행 예산은 300초이며 이번에 확장 profile 편집 UI를 추가한 것은 아니다.

공통 CLI 단계 조회의 기존 420초 한도도 함께 보완했다. 대기는 max(420, 요청 예산+120)초이며 900/1800초 요청은 최대 1020/1920초까지 원래 작업을 조회한다. 500초 뒤 완료한 작업을 모사한 시험에서 기본 요청의 이전 한도와 확장 요청의 완료 판독을 구분한다. 이 대기는 native 실행 제한을 연장하거나 취소/종료 확인을 우회하지 않는다.

단일 native 파일 64 MiB, 전체 패키지 128 MiB와 최소 간격 0.0001 mm는 유지한다. 심화 8분할의 실제 계획은 2422035 격자점, 손실 필드 추정 70785792 bytes, 메모리 추정 663314912 bytes다. 메모리 수치는 초기 추정이며 OS의 hard limit이나 제품 전체 메모리 검증이 아니다. 시간 제한/취소/서비스 소유권 상실에서도 원래 process group의 확정 종료와 슬롯 반환을 확인하며, timeout을 성공으로 게시하거나 자동 대체 작업을 만들지 않는다.

## 계산 비용과 동등성

기존 실제 기록의 FDTD 자체가 약 160~260초를 사용했다. 시간을 늘리기만 한 변경과 후처리 최적화를 구분한다. native 라이브러리 관찰 polling은 0.02초에서 0.1초로 줄이고, raw execution 시간과 방사/손실/전체 후처리 시간을 따로 보존한다. 스레드 수 증가의 속도 개선은 장비의 코어/캐시/메모리 및 동시 부하에 따라 달라지므로 자동으로 보장하지 않는다.

단일 Cartesian 유전체 Box만 실제 XML의 재료 종류/개수/이름, 무변환 좌표, 경계, 등방성과 전도도/가중 함수를 확인한 뒤 QuarterCell 면적 평균을 배열로 계산한다. native XML의 7자리 전도도 표현도 명시적으로 대조하되, 가중 전도도는 기존 일반 경로와 같은 계획 값을 사용한다. 원형/다층/비아/변환/가중 재료나 다른 native 기하는 기존 CSXCAD 조회 경로로 돌아간다. 필드, 격자, sheet/source edge 제외 및 손실 합계 규칙은 같다.

실제 원시 필드의 비용 대조는 다음 도구로 수행한다. 기존 보고서/Journal/원시 파일은 변경하지 않고 추가 FDTD도 실행하지 않는다. 첫 개발 가드가 XML 표현을 허용하지 않아 일반 경로로 돌아간 기록은 보존하고, 실제 가속 경로를 사용했는지 검사한다. 계수 상대 오차 1e-14와 세 주파수 손실 상대 오차 1e-13을 검사하며 모든 반복 시간을 공개한다. 이 비율은 재료 분할 단계만의 비용이다.

```bash
PYTHONPATH=src:tests:tools /home/tracewave/rfad-runtime/openems-venv/bin/python tools/benchmark_pcb_loss_partition.py --report .local/pcb-loss-precision-current/report.json --workspace .local/pcb-loss-precision-current/workspace --output .local/new-box-cost.json
```

## 실행과 재열기

Code의 PowerShell에서 새 경로로 시작한다.

```powershell
$env:PYTHONPATH='src;tests;tools'
.\.venv\Scripts\python.exe -X utf8 tools/verify_pcb_loss_precision.py --workspace .local/new-ro-refinement/workspace --report .local/new-ro-refinement/report.json --manifest fixtures/ro4350b_loss_refinement_study.json --catalog .local/pcb-catalog/catalog.sqlite --continue-independent
```

완료한 같은 소스의 연구에는 --reassess-only로 해석기 없는 재판정을 사용한다. --resume은 캡처한 원본/worker identity가 같아야 한다. --continue-independent는 확정 종료/슬롯 반환을 확인한 원래 실패를 보존하고 나머지 독립 조건만 진행하며 같은 실패 조건을 자동 재실행하지 않는다.

후처리만 바뀐 경우 원래 FDTD 생산자와 새 계산기를 나눠 기록하는 tools/recompute_pcb_loss.py를 사용한다. 원시 생산자의 source/snapshot/plan/설치와 새 계산기의 source/hash를 서로 같다고 표시하지 않는다. 수정 결과는 원래 normalized_result를 덮어쓰지 않는다.

첫 실행의 격자 4수준은 완료했고, 상위 대기 한도와 XML 가드를 보완하기 위해 국부 축 진입 때 조정기를 중단했다. 같은 run_id/nonce의 guest를 명시적으로 reconcile하여 확정 종료와 슬롯 반환을 확인했다. 이 중단을 정상 완료로 바꾸지 않는다. tools/derive_loss_study_axis.py는 사전 고정한 격자 축의 완료 수준만 공개 결과/해시와 대조해 새 보고서로 추출한다. 원래 8개 조건 연구가 완료됐다는 주장은 하지 않으며 기존 실패/미실행 조건은 그대로 남는다.

국부 4/5/6분할은 [별도 사전 고정 manifest](../fixtures/ro4350b_loss_local_study.json)로 최신 worker/대기 정책에서 실행한다. 두 축의 물리 투영/정규화/설치가 같은지 확인하고, 서로 다른 snapshot과 소스 identity를 하나의 동일 worker 연구로 합치지 않는다. 격자 축의 새 배열 계산은 같은 원시 필드의 별도 재계산으로 검증한다.

## 확인한 격자 결과와 비용

격자 4수준의 최종 0.30/0.28 mm 비교는 모든 직접 주파수/개별 성분의 초기 기준을 충족했다. 유전체 합계 최대 상대 변화는 0.060111%, 도체 합계는 0.262782%다. 0.36/0.32 및 0.32/0.30 mm의 미충족 비교는 그대로 보존한다. 완료 격자 사례의 최대 전체 전력 잔차는 0.193263%이며, 총 수지로 개별 손실 판정을 대신하지 않았다.

격자 native 4개는 XML 가드 보완 전 일반 분할을 선택한 소스로 실행됐다. 이후 현재 배열 계산기로 같은 raw를 새 경로에서 재계산해 모든 주파수의 손실 행이 원래 생산자와 동일함을 확인했다. 원래 producer identity를 현재 worker와 같다고 표시하지 않는다. 최신 worker를 사용한 국부 연구와 두 연구의 기하/물성/정규화/설치가 같은지도 별도로 확인한다.

실제 원시 필드의 최종 비용 대조에서 일반 재료 분할은 9.619147초, 배열 경로 5회의 중앙값은 0.014203초였다. 측정 중 다른 native 작업도 실행 중이었으며 재료 분할 단계만의 대조다. 전체 FDTD가 이 비율로 빨라졌다는 주장은 하지 않는다. 최신 worker의 국부 4분할은 FDTD 387.273601초/손실 후처리 0.381237초, 5분할은 FDTD 578.742612초/손실 후처리 0.513383초로 완료됐다. 실제 실행이 이전 300초와 상위 420초를 넘어서도 예산 안에서 완료됨을 확인했다.

국부 4/5분할에서 도체 합계의 변화는 0.293893%지만, 접지/방사 원본 성분 일부는 최대 약 2.87%여서 이 인접 쌍은 미확립이다. 5/6분할도 합계 1.370818%, 급전 도체 최대 4.398922%로 전체 개별 기준은 미확립이다. 6분할 native 754.329280초와 손실 후처리 0.573314초를 포함하여 세 수준 모두 실행은 완료했다. 합계의 상쇄를 초기 개별 손실 합격으로 바꾸지 않는다.

## 심화 6/7/8분할과 검증된 원시 참조 재사용

사전에 고정한 [심화 manifest](../fixtures/ro4350b_loss_deep_study.json)는 7/8분할의 필드 예산과 8분할의 격자 예산을 명시적으로 확장한다. 원래 재료/급전/곡선/종료 및 손실 기준은 바꾸지 않는다. 다음 도구는 같은 원본 snapshot으로 세 비교 계획을 먼저 준비한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/verify_ro_loss_followup.py --producer-report .local/ro-loss-local-final/report.json --manifest fixtures/ro4350b_loss_deep_study.json --destination .local/new-ro-deep
```

6분할 기준은 기존 실제 raw와 새 준비 XML의 전체 바이트/SHA256, 동일 source/snapshot/물리 case/정규화/native 설치와 실행 스레드/종료 정책을 대조한 경우에만 재사용한다. 두 계획에서 compute_profile 외의 case 차이는 허용하지 않는다. 기존 raw는 원래 생산자 계획으로 현재 계산기에 다시 전달한다. 현재 RF 계산 모듈의 소스 hash가 새 native 실행과 같아야 한다.

비교 계획과 원래 생산자 계획은 별도 ID로 보존한다. 재사용 기준은 source_kind=verified_existing_raw로 표시하며 원래 power_balance.analysis_plan_id를 새 비교 ID로 바꾸지 않는다. 연구 schema는 rfad.pcb-loss-equivalent-input-study/0.1로 구분하며 일반 동일 worker 연구로 위장하지 않는다. 신규 FDTD는 7/8분할 두 개다. 입력 불일치/미완료 raw를 자동 재실행으로 대체하지 않으며 검증 실패로 중단한다. 이 경로는 일반 제품의 자동 결과 cache가 아닌 명시적 연구 검증 도구다.

원시 참조 재사용으로 약 754초의 동일 6분할 FDTD를 반복하지 않았다. 재후처리/재열기 검증은 현재 worker에서 새로 생성한 7/8분할 중 가장 큰 것을 사용하고 재사용 기준을 포함한 이전 등록 파일의 봉인도 확인한다.

심화 6/7/8분할은 세 수준 모두 비교 자료를 확보했다. 마지막 7/8분할의 직접 주파수별 최대 변화와 판정은 다음과 같다. 기준은 최초 2% 및 수용 전력 비율의 절대 바닥 1e-5이며 변경하지 않았다.

| N7 | 2087280 | 26536 | 953.720996초 | 0.605467초 |
| N8 | 2422035 | 30845 | 1223.548302초 | 0.713162초 |

native가 보고한 순수 반복 시간은 N7 946.905998초, N8 1215.905264초다. 위 native 실행 시간은 프로세스 시작/관찰/종료를 포함하며, 분석/준비 결과 조회/전송/후처리를 포함한 조정기 시간 980.438/1253.625초와도 다르다. 심화 예산 1800초 안에서 실제 완료했으며 모든 이전 입력/실패와 원시 생산자 ID는 유지한다.

이번 고정 연구는 N8에서 끝낸다. 다음 RF 정밀 검증에서는 유한 폭 급전/접합부와 독립 sheet 손실 참조를 먼저 검토하고 필요한 새 연구를 사전 고정한다. 현재 결과만으로 어느 모델이 원인인지 단정하지 않으며, 분할 수만 더 늘리는 자동 확장은 하지 않는다. 전체 제품의 후속 순서는 [개발 완료 계획](completion_plan.md)을 따른다.

최종 N8 raw의 postprocess_only와 해석기 없는 재열기는 통과했다. 원본 등록 파일 135개와 기존 native 실행 ID 5개는 그대로이며 포트/방사/독립 손실 결과가 같았다. 새 FDTD는 없고 새 후처리 산출물만 별도로 등록했다. 이전 N4/5/6의 재사용 참조도 포함하여 봉인을 확인했다.

## 급전 주변 격자 진단

현재 탐색 fixture의 이상적 y 방향 포트는 start=[9,50,0.797], stop=[9,52,0.797] mm로 x/z 방향 범위가 0이다. [포트 구현](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/python/openEMS/ports.py)과 [native lumped 요소](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/FDTD/extensions/operator_ext_lumpedRLC.cpp)는 box를 격자에 배치하고 직렬/병렬 cell로 요소를 구성한다. 같은 시작/끝 좌표를 유지해도 해당 위치의 Yee dual 폭은 세분화에 따라 줄어든다.

| 국부 분할 | x dual 폭 mm | z dual 폭 mm |

| 4 | 0.125000 | 0.217413 |
| 6 | 0.083333 | 0.143855 |
| 8 | 0.062500 | 0.100722 |

이는 실제 제작 급전 폭이나 native 여기의 전체 물리 aperture를 측정한 수치가 아닌 격자 지지 영역의 기하 진단이다. 급전/접합부의 개별 손실 변화와 관련된 검토 후보이며 인과관계를 확정하지 않는다. 후속에서는 명시적 유한 폭 급전/접합부와 독립 참조 대조를 우선 검토한다. 이번 고정 연구의 원래 포트나 판정 기준은 그 가설에 맞춰 바꾸지 않는다.
