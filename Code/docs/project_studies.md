# 일반 프로젝트의 연구 GUI

설계 기준선 RFAD-D0-3.4를 유지한다. 기존 리터럴 fixture 생성 도구와 별도로 현재 프로젝트의 수식, 매개변수 결합, 출처 확장과 미정 물성을 그대로 스냅샷에 봉인한다. 승인 원문과 실제 납품/제작/측정 조건은 변경하지 않는다.

## 사용 순서

1. 기존 프로젝트를 열고 적용할 편집 내용을 확인한다. `해석` 메뉴의 `프로젝트 연구` 또는 해석 결과 탭의 같은 버튼을 선택한다. 창을 열기 전의 미적용 초안은 기존 편집 명령으로 적용한다.
2. `격자 / 해석 조건`에서 연구 이름, 감소하는 격자 수준, 주파수 대역/표본, 공기 여백/격자, 곡선 근사와 종료 조건을 지정한다. 초기 제안은 수치 설정이며 기판/도체 물성의 기본값이 아니다.
3. 필요하면 `방사 / 독립 손실`에서 NF2FF 주파수, 각도 간격과 상자 거리를 정하고 독립 손실 기록을 선택한다. 독립 손실에는 방사 기록과 직접 포트 주파수가 필요하다. [PTH 체적 손실](pcb_loss_precision.md)은 원본 재료/구멍을 보존하여 분리하며 누락된 물성은 계획 단계에서 차단한다.
4. `초기 판정 기준`을 실행 전에 확인한다. `새 연구 저장`은 모든 실제 계획을 미리 검사하고 원본 snapshot과 설정/기준을 고정한다. 계산은 아직 시작하지 않는다.
5. `선택 연구 실행`으로 준비/해석을 순서대로 수행한다. `진행 / 전력 수지`에서 각 사례와 입사/반사/수용/방사/유전체/도체/잔차를 확인한다.
6. `연구 취소`는 현재 작업에 취소를 전달하고 실제 종료 확인을 기다린다. 취소/실패/서비스 중단 뒤에는 사용자가 `선택 연구 재개`를 눌러야 다음 단계를 진행한다. 완료 결과와 준비 계획은 재사용하고 이전 시도는 보존한다.

조건을 수정하면 기존 연구에 덮어쓰지 않고 새 연구로 저장한다. 선택한 연구의 조건과 화면 초안이 다르면 실행/재개 버튼을 비활성화한다. 프로젝트 개정이 바뀌면 새로 읽기로 현재 개정을 확인한 뒤 새 연구를 만든다. 이미 실행한 연구는 원래 개정에 묶이고 결과에는 이전 개정 여부를 표시한다. 창만 닫으면 서비스가 실행 중인 연구는 계속된다. 프로그램/서비스 재시작 후 자동 재실행은 하지 않는다.

이전 연구를 조회/재개할 때 없던 loss_profile은 삽입하지 않는다. 같은 화면에서 독립 손실을 켜고 새 연구 저장을 선택하면 표시한 초기 손실 기준을 새 정의에 명시적으로 고정한다. 기존 연구의 판정은 그대로 보존한다.

## 현재 범위와 판정

현재 GUI는 일반 프로젝트에서 1~6개 격자의 한 축 연구를 실행한다. 방사/손실 조건은 각 사례에 공통으로 고정한다. 기록 거리나 각도를 바꾸는 별도 연구는 새 설정으로 만든다. 기존 [방사 3축 연구](pcb_radiation_convergence.md)의 독립 변화 행렬은 보존하지만 이번 화면이 세 축 모두의 수렴을 자동 판정하는 것은 아니다.

1~2개 사례도 계산/조회할 수 있으나 수렴은 미확립이다. 최소 수준을 충족하면 모든 인접 비교를 보존하고 마지막 쌍의 포트/방사 격자 안정성을 표시한다. 표본 내부에 공진을 확인할 수 없으면 포트 수렴을 합격으로 바꾸지 않는다. 구면 적분/수동성 예산과 [독립 전력 수지](pcb_power_balance.md)는 별개 근거다. 에너지 잔차가 작아도 개별 손실이나 실제 안테나의 정확도가 보장되지 않는다.

표시 단위는 펄스 Fourier 전력 `W*s^2`다. 절대 W 출력은 미정이다. 음수 손실과 부호 있는 잔차를 자르지 않으며 `requires_review`를 표시한다. 실제 납품 물성과 제작/측정 조건, 제조/측정 검증 false를 유지한다.

## 공개 서비스와 원본 보존

| 메서드 | 종류 | 입력 | 동작 |
| --- | --- | --- | --- |
| study.context | 읽기 | 빈 input | 현재 개정, runtime 구성 여부와 초기 수치 제안 |
| study.list | 읽기 | 빈 input | 현재 프로젝트 소유 연구 목록 |
| study.get | 읽기 | study_id | 고정 입력/원본 참조, 진행과 제한된 전력/판정 DTO |
| study.create | 변경 | expected_revision, specification | 현재 원본의 snapshot과 전체 계획을 원자 저장 |
| study.start | 변경 | study_id | 실행 전 연구의 명시적 시작 |
| study.cancel | 변경 | study_id | 현재 연구 작업의 취소 및 종료 확인 |
| study.resume | 변경 | study_id | 원래 worker/입력으로 종료 확인과 명시적 재개 |

기존 API 2.0의 project context, request_key와 epoch/영수증 규약을 사용한다. 연구 생성/접수와 상태 참조는 같은 journal transaction에서 게시한다. 응답 유실에 같은 요청을 다시 보내면 기존 연구를 반환한다. 다른 프로젝트의 연구를 읽거나 제어할 수 없다. MCP는 같은 메서드를 발견/전달하며 별도의 물리 모델을 만들지 않는다.

specification은 name, grid_levels_mm, settings, port_profile, radiation_profile과 선택적 loss_profile이다. settings는 기존 PCB worker 계약을 사용하며 기준 grid_mm는 마지막 격자 수준과 같다. 최대 32개 연구와 사례별 24개 시도, 기존 512개 작업/1개 native 슬롯 및 파일/패키지 상한을 유지한다. 연구 목록은 작고 study.get은 60 KiB 이하다. 큰 복소 필드와 도체별 세부 손실은 별도 봉인 결과에서 조회한다. 초기 loss_profile은 최소 3수준/상대 2%/수용 전력 비율 바닥 0.00001을 명시하며 과거 연구에는 추가하지 않는다. 임계 구간 최소 분할도 GUI에서 공통 조건으로 고정한다.

생성은 현재 원본 revision 바이트를 기존 snapshot 저장 경로로 봉인한다. 매개변수를 리터럴로 변환하거나 카탈로그 출처를 제거하지 않는다. 현재 문서/저장 기준/undo/redo를 바꾸지 않는다. 계획은 동일 snapshot에서 미리 생성해 물성/급전/자원과 실제 격자 조건을 검사한 뒤 등록한다. 방사 기록이 있는 격자 비교는 외곽/PML/기록 면/위상 중심 불변도 확인한다.

프로젝트 편집 이후에도 실행은 고정 snapshot을 소비한다. 원본 정의/계획/결과/판정은 불변 파일이며 journal은 진행 참조와 시도만 갱신한다. 해석기가 없는 서비스에서도 완료 연구의 원본 참조와 전력을 읽을 수 있다. 현재 worker가 원래와 다르면 결과 조회는 가능하지만 실행/재개는 차단한다. native checkpoint를 이어 계산하는 기능이 아니라 완료 단계를 재사용하는 연구 수준 재개다.

## 상태와 복구

| 상태 | 의미와 다음 동작 |
| --- | --- |
| ready | 원본/계획 고정, 실행 대기 |
| running | 현재 준비/해석 또는 다음 단계 대기 |
| cancel_requested | 명시적 취소 전달 후 실제 종료 확인 중 |
| cancelled | 취소 종료 확인, 완료 단계 보존 |
| interrupted | 서비스 재시작/실행 중단, 자동 재실행 금지 |
| resuming | 명시적 재개, 필요하면 이전 guest 종료를 먼저 확인 |
| failed / blocked | 근거/실행 오류 보존, 자동 교체 실행 금지 |
| completed | 사례 계산/격자 비교 완료, 전체 물리 수용과 구분 |

동일 시점에는 연구 하나가 실행되며 기존 solver의 슬롯을 공유한다. 다른 작업이 슬롯을 소유하면 새 시도나 같은 상태 commit을 반복하지 않는다. 취소와 완료가 경합하면 이미 완료한 자료는 수집하되 다음 단계를 자동 시작하지 않는다. 종료 미확인 native 작업은 명시적 재개에서 원래 transport/nonce로 종료를 확인한 뒤 처리한다. worker 변경이나 종료 확인 실패를 새 계산으로 덮지 않는다.

## 모듈

- project_study_contract.py: 입력/예산과 원본 기반 전체 계획 preflight.
- project_study_commands.py: 원자 생성/제어와 소유권/정의 검증.
- project_studies.py: 상태 전이와 기존 solver 단계의 순차 접수/복구.
- project_study_results.py: 봉인 결과 확인, 작은 조회 DTO와 격자 비교.
- project_study_model.*: wx 없는 입력 변환/실행 정책과 표시 모델.
- project_study_dialog.* / project_study_form.cpp: 위젯, 공개 요청과 늦은 응답/창 수명.
- studio_study.cpp: 주 창의 공개 서비스 연결. native 계산은 포함하지 않는다.

시험은 원본/출처 보존, 멱등 생성, 취소/명시적 재개/재시작, 슬롯/변조 차단, 숫자 왕복과 실제 GUI/WSL 경로를 구분한다. 고정 RO4350B 탐색 프로젝트의 사본에서 선폭을 parameter.set_expression과 parameter_id로 결합해 실제 worker가 원문을 소비하는지 대조한다. 검증 원본 workspace는 덮어쓰지 않는다.

## 실제 검증 기록

최종 RO4350B GUI 연구는 0.50/0.45/0.40 mm, 2.400/2.44175/2.4835 GHz의 세 사례를 완료했다. 선폭을 원래 출처가 있는 매개변수와 `source_width * 1` 표현식으로 결합했고 모든 실제 계획의 source_semantics가 생성 전 문서와 동일했다. 카탈로그 출처 확장과 실제 납품 JLC/RO4350B의 6개 미정 물성은 그대로 유지됐다. 초기 생성 후 GUI에서 현재 메타데이터를 편집/저장해도 원래 snapshot은 바뀌지 않았고 이전 개정 결과로 표시됐다.

GUI에서 실행 중 취소한 해석 1개와 완료 해석 3개를 확인했다. 첫 사례는 준비 1회/해석 2회 시도를 보존했고 뒤의 사례는 각 준비/해석 1회다. 프로그램 재연결 후 동일한 연구 ID/전력/시도를 복원했으며 추가 native 실행은 없었다. 창은 원래 카탈로그 DB 없이 프로젝트에 보존된 출처를 사용했다. 검증 도구의 전체 경과 시간은 671.813초이며 원본 검증 workspace는 별도 사본을 만들어 보존했다.

마지막 방사 격자 비교와 기준 방사 전력 예산, 독립 전력 수지는 초기 예산을 충족했다. 최대 절대 상대 에너지 잔차는 0.191734%다. 포트 격자 수렴은 내부 공진을 확립하지 못해 `not_established`를 유지했다. 연구의 계산 완료를 포트 정합, 세 축 전체 수렴, 개별 손실 정밀도 또는 제조/실측 합격으로 표시하지 않는다.

별도 합성 gap fixture의 실제 WSL 시험에서는 native 실행 중 서비스를 종료했다. 재시작 후 자동 작업 추가가 없었고 명시적 재개로 원래 prepared_plan을 재사용했다. 준비/해석/해석 순서의 시도와 중단 작업 ID를 보존하며 34.853초에 완료했다. 이 합성 fixture는 실행 수명 검증이며 제조 재료나 실제 안테나 정확도의 근거가 아니다.

| 시험 | 통과 | 조건부 제외 | 시간 |
| --- | --- | --- | --- |
| 최종 Windows 전체 회귀 | 691 | 75 | 456.750초, 766개 수집 |
| GUI 회귀 | 14 | 4 | 157.675초, 18개 수집 |
| 최종 연구/비교 계약 | 50 | 0 | 17.524초 |
| CTest | 9 | 0 | 0.35초 |
| 별도 실제 WSL 중단/재개 | 1 | 0 | 34.853초 |

Windows 전체 수집 이후 추가한 종료 불명 guest의 재개 순서 시험은 최종 계약 50개에 포함했다. 실제 WSL 중단/재개는 별도 명시적으로 실행한 시험이며 Windows의 조건부 제외 수에 합쳐 집계하지 않는다. 원본/worker/실제 GUI 실행 파일과 시험 로그의 hash는 [실행 기록](../runtime_profiles/project-studies.json)을 따른다. 최종 worker 소스 117개가 세 실제 계산과 일치한다.

실제 완료 창을 해석기 설정 없이 열어 조건 탭, 완료 단계/시도 수, 이전 개정, W*s^2/미정 절대 W, 음수 잔차와 재개 차단 설명을 시각 확인했다. 검증 창은 정상 종료했다. 화면/기능 시험으로 60/30 fps나 전체 메모리 예산 합격을 주장하지 않는다.

최초 개발 검증에서는 손실 기록 인덱스/크기를 물리 입력으로 비교하여 계산 완료 후 비교가 차단됐다. 이전 원시 계산/취소/오류 기록을 보존했고 손실 관측 인덱스와 실제 재료/기하의 비교를 구분하는 회귀를 추가했다. 위 최종 연구는 수정한 worker와 GUI로 새 workspace에서 전부 다시 계산한 결과다.
