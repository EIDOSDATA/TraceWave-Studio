# 문서 관리와 변경 규칙

문서 ID: TWS-DOC-001. 기준일: 2026-11-16 KST.

## 권위와 목적

사용자의 승인 방향과 RFAD-D0-3.4의 요구/수용 기준을 유지한다. 현재 기능 계약은 실제 지원 동작을 정의하고 승인 요구와의 간극을 표시한다. 구현이 제한되어 있다는 이유로 승인 요구를 삭제하거나 완료 기준을 완화하지 않는다. 새로운 제안은 `설계안/미구현/검증 대기`로 표시한다.

| 종류 | 소유 위치 | 변경 원칙 |
| --- | --- | --- |
| 승인 기준선 | 저장소 `01_Docs` | 원문/ID/번호/manifest 보존. 개발 중 보강은 Code의 현재 명세와 결정 기록으로 연결 |
| 현재 명세/계약 | specifications, features, architecture | 현재형을 코드/공개 capability와 대조. 변경한 기능/버전/제한과 과거 호환 명시 |
| 화면설계서 | screen_design | 화면 ID/구성/입출력/이벤트/전환/예외, 그림과 사용자 설명을 함께 갱신 |
| 분석 | research, 00_REF의 검토 자료 | 원문/가정/생략/조건/결론/미확립 분리. 유사한 값만으로 새 검증 결론 생성 금지 |
| 검증/이력 | verification, audit, runtime_profiles, planning의 날짜 기록 | 날짜/환경/소스/실행 범위 고정. 새 실행은 새 기록이며 이전 숫자를 대체하지 않음 |
| 운영 | operations | 실행 명령의 기준 디렉터리와 필요한 환경 표시. 설치 당시 버전을 지금 설치 상태로 단정하지 않음 |
| 최초 제안 | archive/proposals | 현재 구현으로 대체된 제안임을 제목 다음에 알리고 최신 계약으로 연결 |

## 중복과 불필요한 내용

현재 API/수량/자원 제한은 기능 계약 또는 공통 명세 한 곳이 소유한다. 상위 안내는 짧은 요약과 링크를 제공한다. 서로 다른 문서가 같은 기능의 현재 상태를 다르게 설명하면 실제 코드/지원표를 확인해 현재형을 교정한다. 과거 날짜 아래의 `미구현` 문구는 그 시점 기록임을 명확히 한다.

버려진 제안은 현행 읽기 순서에서 빼고 archive로 분류한다. 원문/추출/검증 사본의 중복은 출처나 이력의 연결이 다를 수 있어 파일 hash만으로 삭제하지 않는다. 불필요한 반복이나 잘못된 현재 설명을 정리한 내역은 review에 기록한다. 이번에는 승인 근거와 과거 실행 파일을 삭제하지 않는다.

## 기능 구현 전 문서의 준비 조건

기능마다 목적, 지원 범위/제외 범위, 원본/DTO/파일의 소유자, 단위/상태/출처, 명령/역명령/버전, 정상/취소/실패/결과 불명, 화면/사용자 행동, 유한 자원 및 호환/검증 기준을 적는다. 이미 승인된 상세 수식/지원 범위는 해당 승인 UI/FN/API/EQ로 연결하고 비슷한 새 정의를 복제하지 않는다.

결정할 수 있는 UI/소프트웨어 정책은 문서에서 구체적으로 정한다. 실제 납품 물성/시료/교정/독립 비교/성능 수치는 필요한 증거와 확인 시점을 명시하고 미정으로 남긴다. 미정을 숨겨 문서상의 설계 완료를 만들지 않는다. 승인 문서가 있다고 해서 wire 필드나 capability가 이미 구현되었다고 가정하지 않는다.

## 변경과 검수

1. 담당 계약과 화면설계서를 먼저 수정하고 연결 UI/FN/API/기존 개발 단계를 기록한다.
2. 서비스/표시 모델/View를 분리해 구현하며 문서와 실제 동작의 차이를 갱신한다.
3. 필요한 회귀와 실제 GUI 시나리오를 실행한다. 문서만 바꾸면 링크/그림/내용 일치 검수만 새 증거로 기록한다.
4. `check_documents.py`, 필요한 경우 구현 감사 생성/`--check`로 링크와 추적을 확인한다.
5. 검토를 마친 작업 단위마다 한국어 커밋/푸시한다. 기존 미완료 작업은 섞어 완료 처리하지 않는다.

폴더 이동 때에는 상대 링크, 감사 JSON의 근거 경로, 안내 README와 path_map을 같이 갱신한다. 과거 runtime profile 안의 경로는 당시 소스 식별의 일부이므로 고치지 않는다. 문서 도구는 제품 GUI나 사용자 프로젝트를 수정하지 않는다.
