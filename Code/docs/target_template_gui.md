# RF 목표와 명시 형상 템플릿 GUI

기준일: 2026-11-12

추가 문헌 G001/G008/G009와 G001 초기식의 사용/가정/차단 범위는 [추가 문헌 GUI 계약](printed_templates_and_seeds.md)을 따른다. `문헌 / 형상 / 초기 후보`에서 후보 방식을 선택하며, 명시/초기식 초안과 검토 상태를 따로 유지한다. 기존 직접 입력과 목표 편집의 의미는 아래와 같다.

## 현재 구현 범위

주 작업 화면의 `목표 / 대역`에서 여러 RF 목표를 추가, 선택 수정, 삭제한다. 이름, 시작/종료 대역, 기준 주파수, 기준 임피던스, 포트, 선형/명시 표본, S11/방사 효율/총 효율/비대역폭 기준을 편집한다. 각 변경은 사유를 기록하고 기존 명령 이력과 실행 취소/다시 실행을 사용한다. 저장은 해석 합격을 의미하지 않는다.

기준 주파수/임피던스/포트와 성능 기준의 미정 상태를 유지한다. Hz/GHz 등 표시 단위만 바꾸는 경우 서비스가 원래 SI 값과 출처를 보존한다. 명시 표본은 줄별 값/단위를 전달하며, 변경하지 않은 표본의 상태와 출처를 유지한다. 기본 화면은 편집 입력과 근사/미정 요약을 보여주고 읽기 전용 출처와 상태는 상세 표시로 분리한다.

`원호 / IFA`는 카드의 필수 치수를 사용자가 명시하고 도체층을 선택한 뒤 읽기 전용 형상 미리보기를 확인하는 화면이다. 선택한 목표 한 개를 출처 참조로 연결할 수 있으며 연결하지 않아도 된다. 수치/단위 문자열의 해석과 모든 기하/물리 검증은 서비스가 담당한다. 목표 대역에서 치수를 자동 계산하는 RF 합성 기능은 이번 범위가 아니다.

원호 카드는 직사각형/원형 PCB, 평면 IFA 카드는 현재 직사각형 PCB를 지원한다. GUI의 템플릿 적용은 `port: null`인 형상 생성이다. 실제 급전 포트, 물성, 제작/측정 조건과 정합/방사 성능을 임의로 채우지 않는다. 미정 입력은 이후 프로젝트 편집 및 해석 입력 검사에서 계속 관리한다.

[G031 문헌 카드](literature_templates.md)도 같은 목록에 연결했다. 원문 치수는 `/ 원문` 라벨과 함께 표시하고 배치 이동 X/Y는 빈 입력으로 시작한다. 원문 값은 source marker로 선택하고 수정한 값은 숫자 원문으로 전송한다. 후보에는 원문 치수 사용/수정 필드, 부분 기하 생성과 초기 추정/해석/수렴/실측/제조의 상태를 각각 표시한다. 원문 해시와 줄 사본, 미정/생략 항목은 생성 당시 프로젝트 사본으로 보존한다. 전체 보드 외곽과 ground/물성/회로를 임의로 복원하지 않는다.

## 요청과 이력 계약

- 목표: `target.editor.get` / `target.editor.apply`.
- 템플릿: `template.context` / `template.synthesize` / `template.apply`.
- 후보 미리보기는 프로젝트를 변경하지 않는다. 입력, 카드, 층 또는 목표 선택이 바뀌면 이전 후보를 폐기한다.
- 적용은 현재 개정, 카드 해시, 입력과 미리보기 해시가 일치하는 경우에만 허용한다. 생성 객체 전체는 한 명령으로 실행 취소한다.
- 요청은 기존 비동기 디스패처를 사용한다. 이전 조회 세대, 닫힌 화면, 삭제된 화면의 응답을 무시한다.
- 적용 중에는 닫기와 중복 적용을 막는다. 전송 단절/시간 초과로 적용 여부가 불명인 경우 재전송하지 않고 편집을 잠근다.
- 확정 입력 오류는 입력을 보존한다. 개정 충돌/적용 후 재조회 실패는 최신 프로젝트 재열기가 필요하다.
- 여러 번 적용 후 화면을 닫아도 마지막 성공 개정을 주 창에 반영한다.
- 다른 목표 조회가 실패하면 목록 선택을 기존 폼의 실제 대상으로 복원한다. 적용 성공 후에는 생성된 목표 ID를 즉시 채택하고 최신 폼 조회가 끝날 때까지 다시 적용하지 못한다.
- 목표의 미적용 입력은 선택 전환과 닫기에서 폐기 여부를 확인한다. 템플릿은 카드별 미적용 치수를 대화상자 안에서 보존한다. X, Esc, 닫기 버튼으로 초안을 조용히 버리지 않는다. 한 카드 적용 후 다른 카드 초안이 남아 있으면 재조회 실패 중에도 확인한다.

## 구조와 제한

공통 요청/수명 경계는 `ProjectSetupDialog`, 목표의 표시와 동작은 `TargetEditorDialog`, 카드의 표시와 동작은 `TemplateDialog`로 나누었다. `EditorPanel`은 서비스 필드 설명자를 표시하고 `DesignCanvas`는 서비스의 후보 장면을 표시한다. UI에서 RF 계산, SI 단위 환산 또는 숨은 기본 물성을 생성하지 않는다.

이번 작업은 StudioTheme를 사용하는 기존 네이티브 입력 화면의 기능 연결이다. 완성 목표 시안 전체, 다크 테마, 자동 안테나 합성, 다중 목표 동시 연결, 3D 후보 창 또는 60/30fps 실측 완료를 뜻하지 않는다. 템플릿 출처 자료의 크기는 서비스 상한에 의해 제한되며 임의로 상한을 늘리지 않는다. 알려진 템플릿 출처 안의 명시 표본은 최대 1001개를 보존할 수 있으나, 표본 수와 별도로 출처 256 KiB 및 문서 512 KiB의 바이트 상한이 적용된다. 긴 출처나 여러 사본으로 바이트 상한을 넘으면 미리보기에서 이유를 표시하고 적용을 막는다. 미지 확장 자료의 일반 항목 수 제한은 유지한다.

## 검증

실제 GUI 통합 smoke는 큰 표본 프로젝트와 별도 작은 카드 프로젝트를 순서대로 연다. 이 시험 유형의 UI 전체 한도는 180초, 외부 프로세스 한도는 종료 여유를 둔 210초이다. 제품 요청 timeout, 해석 시간 제한, 성능 예산을 바꾼 것이 아니다.

주요 회귀 경계 이름은 다음과 같다.

- `failed_target_selection_restores_authoritative_identity`: 목표 조회 실패 후 목록/폼 대상 일치.
- `post_apply_query_failure_locks_without_duplicate_create`: 신규 목표 적용 후 조회 실패가 중복 생성을 허용하지 않음.
- `dirty_close_requires_explicit_discard`: 미적용 목표의 창 닫기/닫기 버튼 확인.
- `template_card_drafts_and_close_confirmation`: 카드 전환 초안 보존과 닫기 확인.
- `other_card_draft_survives_post_apply_query_failure`: 다른 카드의 초안은 재조회 실패 중에도 보존.
- `oversized_template_origin_blocks_without_mutation`: 실제 출처 바이트 초과 후보는 프로젝트 변경 없이 차단.


최종 Windows Release 빌드와 CTest 9개가 통과했다. 전체 GUI 프로세스 시험은 20개 중 18개 통과, 실제 WSL/FDTD 계산 2개 조건부 제외이며 소요 시간은 344.431초였다. 실제 CAD GUI 2개를 포함한다. 신규 목표/템플릿 GUI 2개는 별도 실행에서도 182.702초에 모두 통과했다. 시험 시간은 전체 작업 흐름의 벽시계 시간이며 UI 응답성 또는 물리 성능 합격 수치가 아니다.

실제 GUI에서 목표 1001개 명시 표본/출처 보존, 표시 단위만 변경할 때 SI 유지, 추가/수정/삭제, 실제 바이트 상한 차단, 원호/IFA 미리보기 및 적용, 최신 개정 반영, 저장/실행 취소/다시 실행/재열기를 확인했다. 미정 물성/포트를 임의로 추가하지 않았고 해석 작업을 생성하지 않았다.

수동 Windows 화면 검수는 현재 디스플레이의 주 창 진입, 새 목표의 빈 값/미정 표시, 저장 목표의 대역/단위 표시, 출처 상세 펼치기, 원호/IFA 카드 전환과 입력 배치, 미선택 도체층 오류 안내, Esc 복귀 범위다. 이 범위에서 텍스트 잘림이나 버튼 겹침은 관찰하지 않았다. 후보의 2D 표시/적용은 실제 프로세스 시험으로 검증했다. 다중 DPI/모니터, IME 조합, 60/30fps와 전체 메모리 실측은 이번 검수 범위가 아니다. 검수용 창과 프로세스는 종료했다.
