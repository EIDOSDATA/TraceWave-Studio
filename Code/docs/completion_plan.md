# TraceWave Studio 개발 완료 계획

갱신일: 2026-11-12 KST

이 문서는 승인된 RFAD-D0-3.4, 현재 Code 구현과 검증 기록을 대조하여 정한 개발 순서다. 이전 대화의 7/8단계 권장 목록을 대체한다. 기존 목록은 손실 검증 이후의 일부 작업만 다뤘으며 R1 전체 기능을 포함하지 않았다. 앞으로 작업 순서는 이 문서를 기준으로 관리하고, 실제 완료 증거는 [개발 상태](development_status.md)에 기록한다.

## 1. 무엇을 완성하는가

첫 완료 대상은 Windows 11 x64의 wxWidgets GUI와 local WSL2 openEMS worker를 사용하는 R1 내부 검증용 제품이다. 사용자가 원호/IFA 단일 포트 안테나를 만들고 PCB/물성/급전/환경을 설정하여 계산, 비교, 기본 측정 파일 확인과 2D/STEP/CAM 출력을 수행하는 전체 흐름을 완성한다.

- wxWidgets, Qt 제외, 필수 유료 GUI 부품 없음과 기존 직접 입력을 유지한다.
- 일반 편집 60 fps, 대형 장면 30 fps 및 승인된 성능 예산은 초기 목표다. 실제 측정 전 합격으로 표시하지 않는다.
- 제조업체 출처, 사용자 수정, 근사/가정과 실제 미정값을 구분한다.
- 코드 구현 완료, 수치 안정성, 목표 성능 충족, 제조/측정 검증은 서로 다른 상태다.
- R1의 모든 필수 수용 증거가 없는 중간 배포는 개발 검토용 빌드다. 이를 R1 완료로 표시하지 않는다.

근거는 [06 기능](../../01_Docs/06_RFAD_기능_설계.md), [12 출력](../../01_Docs/12_RFAD_도면과_제조_파일_출력.md), [13 스윕과 측정](../../01_Docs/13_RFAD_최적화와_측정.md), [14 수용](../../01_Docs/14_RFAD_검증과_수용_기준.md), [15 구현 선행](../../01_Docs/15_RFAD_구현_계획.md)이다. 승인 원문과 승인 hash는 변경하지 않는다.

## 2. 현재 출발점과 빠진 부분

프로젝트 명령/저장/표현식/snapshot, PCB 재료 카탈로그와 직접 입력, 기본 2D 편집, OCCT CAD/STEP/3D 표시, WSL 실행/취소/결과 재열기, 제한된 단일 포트 해석, NF2FF, 독립 손실/전력 수지와 격자 한 축 연구 GUI는 기초 구현과 개별 시험이 있다. 이 기능을 다시 처음부터 구현하지 않는다.

현재 GUI가 전체 사용자 흐름과 성능 수용을 마친 상태는 아니다. 기존 [화면 시안](ui_concept.md)은 배치의 참고이며 최신 기능/시험 상태는 개발 상태와 각 계약을 따른다. 시안 문서의 과거 미구현 표기를 최신 완료 증거로 사용하지 않는다.

현재 확인한 주요 미완성 범위는 다음과 같다.

| 분야 | 남은 구현 또는 수용 |
| --- | --- |
| 설계 | 명시 치수 템플릿과 목표 편집 이후의 문헌 원본 카드/초기 RF 후보, 목표 프리셋/제약, 연결/기본 DRC, 기본 외부 환경과 STEP 입력/배치 |
| 편집 GUI | 스냅, 끝점/치수, 필요한 평면 연산과 도구 간 일관성, 완결된 프로젝트 작업 흐름 |
| 연구 | 일반 설계 매개변수 스윕, 기록 거리/각도 등을 포함한 연구 행렬, 후보/예산/재개 관리 |
| 결과/회로 | 다중 실행 비교, 기본 외부 RLC와 검증된 network 변환, 목표 판정, 3D 방사/필드 조회 |
| 신뢰성 | 미확립 RO4350B 개별 손실, GHz PTH 모델/표피 깊이와 독립 참조, 원호/IFA 및 지원 조건별 검증 |
| 측정 | Touchstone/측정 CSV, 조건/교정/기준면 기록, 실제 계산과 같은 기준의 비교와 불확도 근거 |
| 출력 | PDF/SVG/DXF 연관 도면, KiCad/Gerber/Excellon/기본 Job과 입출력 검수, STEP 수신 도구 검증 |

이 표는 저장소와 실행 기록에서 확인한 간극이다. 2번에서 각 FN/VT의 실제 경로와 시험 본문을 대조했고 [구현 감사](implementation_audit.md)와 기계 판독 색인을 작성했다. 기능별 부분 구현을 재사용하며 연결한 시험을 모든 AC의 전체 수용으로 확대하지 않는다.

1번 종료는 수렴 성공을 보장한다는 뜻이 아니다. N8까지 확인한 결과가 미확립이면 그 상태와 원인을 검토할 후속 항목을 8번에 남긴다. 결과를 본 뒤 기준을 완화하거나 더 큰 FDTD 연구를 무기한 추가하지 않는다.

2번은 전체 설계를 다시 쓰는 단계가 아니다. 승인된 FN/VT와 현재 기능을 연결하는 구현 간극표를 확정하는 짧은 정리다. 공통 계약은 필요한 변경만 하고, 모든 모듈을 한 번에 다시 작성하지 않는다.

## 4. 순서 안에서 함께 진행할 일

- 3번의 기하/단위/연결 계약이 고정되면 10번의 파일 adapter 개발을 앞서 진행할 수 있다. 최종 roundtrip은 실제 완성 후보와 다시 확인한다.
- 5번의 데이터 계약이 고정되면 7번의 비교 화면과 11번의 측정 조건 폼을 함께 연결할 수 있다. 측정 파일 읽기와 graph 비교를 두 번 구현하지 않는다.
- 8번의 고비용 계산 대기 중에는 solver source identity를 바꾸지 않는 독립 GUI/문서/파일 작업을 진행한다. 원래 실행의 코드/입력을 보존한다.
- 제작/측정에 걸리는 외부 대기는 9/10번의 입력과 전달물이 준비되는 즉시 시작할 수 있다. 그동안 12번과 배포 준비를 진행한다. 미정 자료 때문에 가능한 소프트웨어 작업까지 중단하지 않는다.
- 상태머신, 비동기 작업, 페이지 조회, 단위/출처/명령 처리는 기존 모듈을 재사용한다. 새 화면마다 별도 실행기나 저장 형식을 만들지 않는다.
- 성능 예산/복구/접근성 검사는 각 단계에도 적용한다. 12번은 처음 검사하는 시점이 아니라 전체 제품 조건의 최종 수용이다.

이는 작업 의존관계상 가능한 동시 진행을 뜻하며 현재 별도 agent를 생성하거나 여러 작업을 무제한 실행한다는 지시가 아니다. 계산 자원과 수정 범위를 제한한다.

## 6. GUI 작업의 끝과 누락 보강

GUI는 2번에서 이동/상태 계약, 4번에서 설계 화면, 6번에서 연구/실행, 7번에서 결과, 10/11번에서 출력/측정 흐름을 완성한다. 12번에서 아이콘/간격/단축키/키보드 이동/한국어 입력, 오류 위치와 다음 행동, DPI/패널 배치 및 실제 성능을 전체 흐름으로 점검한다. 사용자는 구현 세부를 알아야만 기본 작업을 수행할 수 있는 구조가 되어서는 안 된다.

각 단계의 종료 때 요구사항, 실패 경로, 저장/재열기, 이전 revision과의 관계, 비용/메모리, 사용자 설명을 확인한다. 발견한 간극은 연결 FN/VT, 재현 조건, 영향, 담당 단계와 함께 기록한다. 필수 간극은 릴리스 전에 해결하고, 후속 기능은 지원표와 미결표에 남긴다. 단순히 나중에 찾겠다고 미루거나 검증 범위를 말없이 줄이지 않는다.

고비용 RF 계산은 수식/단위/계약/작은 참조를 먼저 검사한 뒤 지원 조건을 고정해 수행한다. 같은 완료 연구를 코드 수정마다 전부 재실행하지 않으며 변경 영향에 맞는 시험을 선택한다. 재사용에는 원본 입력/실행 identity/파일 봉인을 검증한다.

## 7. 실제 자료와 R1 이후의 경계

실제 제작 적층, 납품 물성, 동박/마스크/표면처리, SMA/케이블/지그, VNA 교정과 방사 측정은 확보 시 확정한다. 현재 탐색 모델을 실제 납품값으로 승격하지 않는다. 실제 자료 없이 측정 비교 기능을 구현/시험할 수 있지만 실물 정확도 검증을 합격시킬 수는 없다. 필수 실물 AC가 남으면 소프트웨어 기능 완료와 R1 전체 수용을 구분해 보고한다.

R1 이후에는 관련 선행이 끝난 범위에서 다음으로 확장한다. 이 순서는 장기 기능의 의존 방향이며 R1 완료 전에 모두 구현해야 한다는 뜻이 아니다.

1. R2 고급 재료/포트/복소 network/다중포트 field basis와 해당 독립 검증.
2. 해당 기반을 사용하는 UWB/MIMO/배열, 고급 보정/OTA 처리, 자동/다목적 최적화와 공차/정합 합성.
3. R3 NFC/RFID/flex/body 전문 물리, 추가 solver/원격 HPC, 장비 직접 연결, 대리모델/역설계/AI 확장.

Linux GUI는 승인한 후속 출시 범위이며 버전은 미정이다. 외부 공개/상용/소스 공개 방침도 내부 검증용 R1과 별도다. 이 계획으로 새 비용 지출이나 외부 배포를 실행하지 않는다.

## 9. 현재 위치

현재 1번의 고정 N8까지 계산과 후처리/해석기 없는 재열기를 완료했다. 격자 축은 초기 기준을 충족했지만 국부 7/8분할의 방사 도체 변화가 최대 2.788446%여서 전체 개별 손실은 미확립이다. 원본 봉인 파일 135개와 기존 native 작업 ID를 보존했으며 신규 FDTD 없이 재후처리 결과가 같았다. 세부 결과는 [RO4350B 연구](ro4350b_loss_refinement.md)를 따른다. 이 미확립 항목은 8번에서 후속 검증한다.

2번의 요구/FN/VT 대조와 공통 계약 정리를 완료했다. 3번의 첫 범위인 [다중 목표 대역 입력](target_contract.md)의 저장/명령/호환성을 구현했고, 4번의 일부로 공통 라이트 스타일/도킹/간격과 도구 줄바꿈을 실제 GUI에 적용했다. 가독성/편의성, 실제 구현 범위와 새 v2 목표 시안은 [GUI 설계](studio_gui_design.md)를 따른다. 이어 [원호/IFA 명시 기하 템플릿](template_contract.md)과 [목표 편집 GUI](target_template_gui.md)를 연결했다. 3/4번 전체 완료는 아니며 문헌 원본 카드/초기 합성/목표 제약, 연결/환경과 정밀 편집이 남아 있다. 이후 이 문서의 번호를 기준으로 완료/진행/미착수와 근거를 갱신한다. 완료 일정은 단계별 실제 구현량과 계산/외부 검증 시간으로 갱신하며 현재 근거 없이 날짜를 약속하지 않는다.
