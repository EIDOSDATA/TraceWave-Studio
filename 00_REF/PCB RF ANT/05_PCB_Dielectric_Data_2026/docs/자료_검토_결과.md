# PCB 유전율 자료 정리와 검토 결과

검토일: 2026-11-11. 이 문서는 수집 자료의 구조, 적용 조건 및 정리 결과를 설명한다. 실제 제조 lot의 물성이나 안테나의 실측 정확도를 인증하는 문서는 아니다.

## 1. 자료의 규모와 의미

| 항목 | 수량 | 해석 |
| --- | ---: | --- |
| 조건별 관측 | 57,340 | 같은 제품의 주파수, 두께, 직물, 수지 함량, 층, 출처가 다르면 별도 행 |
| 소재 공개 물성 | 26,815 | 소재 제조사 및 일반 참고 물성 |
| PCB 제작업체 공개 파라미터 | 30,525 | 공개 적층/계산기/소재 목록의 설계 파라미터 |

수집 자료는 이미 물성의 측정 조건과 원문 충돌을 상당 부분 보존하고 있었다. 따라서 관측 수치를 임의로 수정하거나 비슷한 값을 평균내지 않았다. 관측 ID를 제외한 완전 중복 행은 없었다.

## 2. 실제로 확인한 범위

1. 최초 2,747개 파일, 1,035,264,538 bytes를 검사했다. 기존 manifest 2,746개 파일의 바이트와 SHA-256이 일치했다. manifest 자신은 자기참조를 피하기 위해 제외되어 있었다.
2. 57,340행의 ID, 출처 연결, 명시 파일 경로와 주요 수치 범위를 검사했다. 전체 데이터 CSV 40개 및 출처/제품 CSV 2개를 JSON의 모든 필드와 대조했다. 비교 불일치와 중복 ID는 없었다.
3. 개별 PDF 949개의 모든 페이지에서 텍스트를 읽고, 원문 HTML 704개와 기존 안내 HTML 1개의 본문/제목을 파싱했다. ZIP 내부 648개 항목의 바이트를 읽고, 내부 PDF의 모든 페이지와 Altium 텍스트 및 IPC-2581 XML을 검사했다.
4. 중요 원문 PDF 4페이지와 AISLER 도표 7개를 시각 확인했다. 전체 PDF 페이지를 육안 검토한 것은 아니다. 개별 PDF에서 텍스트가 40자 미만인 페이지 113개가 있으며, 이번 작업에서 OCR이나 그래프 수치화는 하지 않았다.
5. JSONL 분할 전후 모든 키, 숫자/문자/배열/객체 타입, 미제공 키와 null, 관측 ID를 보존했다. 파일명 변경으로 바뀐 source_file 경로 및 JLC의 오래된 source_manifest_file 참조를 각 변경표에 따라 역변환하면 최초 관측 전체의 정규 해시와 일치한다.

기계적 전수 검사와 중요 원문의 시각 확인을 구분한다. 이 검사는 표 전체를 새로 전사하여 모든 측정값을 독립 검증했다는 뜻이 아니다. 세부 실행 근거는 [현재 검토 기록](../audit/current/)에서 확인한다.

## 3. 정리한 내용

- 사람이 사용하는 첫 화면을 전체 안내 엑셀과 회사별 엑셀로 구성했다. 전체 안내 1개와 36개 회사/일반 참고 자료 1개 그룹의 엑셀 37개로 총 38개다. 회사별 데이터는 소재명과 조건으로 필터링하고, 필드 설명과 조사 메모를 함께 읽는다.
- 원본 파일 1,682개는 회사, 소재 또는 자료 범위, 문서 용도, 출처 ID가 보이는 이름으로 변경했다. 원본 바이트는 바꾸지 않았다. [파일명 변경표](../catalog/source_filename_map.csv)에 이전/현재 경로를 남겼다.
- 검색용 TXT 1,115개도 회사별 폴더 24개에 회사/소재/문서명이 보이는 이름으로 정리했다. 바이트는 보존했고 [검색 텍스트 이름 변경표](../catalog/search_text_filename_map.csv)에 이전/현재 경로를 남겼다. PDF에서 추출된 본문 전체를 엑셀의 숫자 표처럼 취급하지 않고, 엑셀의 출처 목록과 원문/검색 텍스트로 연결한다.
- 전체 JSON 1개와 반복 CSV 40개는 자료 폴더에서 제거하고 복구용 작업 폴더에 격리했다. 기존 자료와 메타데이터의 압축 백업도 별도로 보존했다. 수치 관측과 원본 문서는 삭제하지 않았다.
- 프로그램용 단일 원본은 `data/observations/`의 회사별 JSONL 37개다. 필요한 CSV/JSONL은 필터 도구로 다시 내보낼 수 있다. 엑셀은 사람이 읽는 파생 보기다.
- 이전 엑셀 색인과 수집 당시 검사 기록은 `audit/collection/`에 분리했다. 현재 검토 기록과 혼동하지 않도록 역사적 자료로 표시했다.
- 기존에 검색되지 않던 ZIP 내부 자료 648건의 색인을 추가했다. 내부 PDF는 고유 168종이며, 기존 텍스트 2개를 재사용하고 검색 텍스트 166개를 추가했다. ZIP 원본 PDF를 중복 압축 해제하지 않았다.

파일명은 소재를 추정해서 붙이지 않는다. 여러 제품을 담은 자료는 종합표/선택표로, 제품이 확인되지 않는 자료는 실제 제목이나 용도로 표시한다. 이름 끝의 source ID는 같은 제목의 개정판과 출처를 구별하기 위한 식별자다.

추가 연결 검사에서 JLC 26,276행의 source_manifest_file이 수집 단계의 옛 파일명을 가리키는 것을 발견했다. 같은 FB240 출처의 실제 보관 파일로 연결을 수정했다. 수치나 출처 ID를 바꾸지 않았고 [별도 경로 변경 근거](../catalog/legacy_reference_path_map.json)에 전후 경로와 역변환 해시를 남겼다.

전체 집계와 업체/적층별 검토 사유는 [업체별 검토](../catalog/review_publishers.csv), [적층별 검토](../catalog/review_stackups.csv), [검토 규칙](../scripts/review_rules.py)을 따른다.

JLC의 template layer 관측 26,276행과 별도 공개 파라미터 15행을 합친 26,291행을 PCB 제품 수로 해석하면 안 된다. 동박 행은 물성 관측 표와 별개인 제조업체 적층 원자료에서 확인한다.

Wurth의 raw_fields 66,582개는 수집된 key/value 수다. 167개 원시 행에는 `0LAYERID`, `1COPTHICK` 같은 숫자 접두 키가 섞여 있다. native 표본 대조에서 `LAYER_V8_1`의 접두 검색이 `LAYER_V8_10`과 `LAYER_V8_11`까지 포함하여 다른 층의 필드가 들어간 것을 확인했다. 이를 해당 행의 독립 층 속성으로 그대로 매핑하지 않는다. 기본 필드와 정규화 물성의 오류를 확정한 것은 아니며, 후속 가져오기에서는 원 native 파일의 정확한 층 경계를 다시 검증한다.

## 6. 원문이 없는 관측과 미확보 자료

원문 미보관 241행은 경로 연결 실패가 아니다. ITEQ의 20출처/112행과 Fineline의 3출처/129행이다. 수집 기록에는 공식 웹 조회로 읽었지만 직접 파일 다운로드가 HTTP403 등으로 실패했다고 적혀 있다. 이번 작업에서 그 값을 원문 전체와 새로 대조했다는 뜻으로 표시하지 않는다.

출처 1,756개 중 다운로드 성공으로 기록된 것은 1,699개이고, 그 외 57개는 접근 실패/미확보/문의 전용/리다이렉트다. 리다이렉트 2개는 응답 자체를 보관했으나 기술 문서로 취급하지 않는다. 출처를 지우면 이런 공백이 숨겨지므로 접근 기록은 보존한다.

미확보 출처는 [별도 목록](../catalog/unavailable_or_request_only.csv), 해당 수치 관측과의 관계는 [미보관 원문 감사](../audit/current/missing_local_sources.json)를 따른다.

## 7. TraceWave Studio에서 사용할 방향

사용자 직접 입력, 소재 선택, PCB 제조업체 적층 선택을 같은 프로젝트 입력으로 연결한다. 카탈로그 값은 시작값이며 실제 프로젝트는 선택한 출처, 조건, 사용자 수정값과 근거를 자신의 불변 스냅샷에 보관한다.

형상은 기판 외곽, 층 순서와 실제 층별 두께로 만든다. 유전율은 해석 입력이며 유전율만 바뀌었다고 기판이나 안테나 치수를 자동 변경하지 않는다. 임피던스 선폭 합성이나 안테나 최적화는 별도 작업이다.

현재 프로그램은 카탈로그 검색/가져오기 UI를 구현한 상태가 아니다. 내부 동박, 마스크, 분산/이방성 등 현재 PCB solver가 소비하지 못하는 조건을 제조업체 선택 화면에서 지원 가능한 것처럼 보여 주지 않는다. 자세한 현재/후속 경계와 구현 순서는 [프로그램 연결 설계](../../../../Code/docs/pcb_material_catalog.md)를 따른다.

공개 원문과 사람이 보는 엑셀을 GUI 시작 시 모두 읽지 않는다. 후속 구현에서는 읽기 전용 검색 인덱스를 별도로 만들고 필요한 행만 조회한다. 원문 전체를 제품에 재배포할 범위는 자료별 권리 조건을 확인한 뒤 정한다.
