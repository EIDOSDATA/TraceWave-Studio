# TraceWave Studio 설계 문서 안내

개정: 3.4 / 2026-11-07 KST / 상태: 설계 기준선 승인 / 개발: 착수 전

## 1. 현재 목적과 상태

TraceWave Studio는 PCB 패턴 안테나의 주파수 목표, 형상, 적층, 재질, 급전과 환경을 하나의 의미 모델로 다루고, 같은 설계에서 2D 도면, 실제 동박을 포함한 STEP, 제조 파일과 EM 해석 결과를 만드는 데스크톱 도구의 설계안이다. 문서 식별자는 RFAD를 유지한다.

2026-11-07 사용자가 설계 기준선 3.4를 승인하여 D0 문서 승인을 완료했다. 이번 반영은 승인 상태와 인계 조건을 기록하며 설계 버전 3.4를 유지한다. 제품 개발은 아직 착수 전이고 별도 착수 지시 후 R0 구현과 wxWidgets 통합/성능 검증을 시작한다. 문서 정합성 확인은 실제 프로그램, 안테나 성능 또는 제조 검증 합격과 다르다.

GUI는 사용자 결정에 따라 **C++ wxWidgets로 확정**한다. **일반 편집 화면 60 fps, 대형 장면 30 fps**를 목표로 하며 **유료 GUI 부품을 기본 기능의 필수 의존성으로 사용하지 않는다**. Qt 계열은 제외하고 Avalonia는 과거 검토 이력으로만 남긴다. 선정된 GUI의 통합과 성능 검증은 [24번](24_RFAD_GUI_선정과_성능_설계.md)을 따른다. 24번 성능 예산과 기준 host/fixture는 초기 목표로 채택했다. 성능은 아직 측정하지 않았고 메모리 오버헤드가 0이라는 보장은 하지 않는다. 설계 기준선 3.4는 사용자 승인 완료이며 개발 착수 지시는 별도로 남는다.

R1 우선 출시는 Windows 11 x64 GUI+로컬 WSL2 Linux worker이며 Linux 데스크톱 GUI는 후속 출시로 둔다. Linux native/headless worker의 R0 기준 검증은 유지한다. R1 기능은 원호/IFA 중심의 단일 포트, 물성/급전/환경, 실제 출력과 기본 측정/스윕, 전력/방사 검증을 유지한다. 완전한 참조 사례 검증 후 물성이 갖춰진 단일 포트 IFA를 검증하고 원호의 R1 검증도 수행한다. G031은 기하 검수용이다. 초기 배포는 내부 검증용이며 외부 공개/상용 배포와 소스 공개 정책은 후속 결정한다.

최초 IFA의 2.400~2.4835 GHz, 폭 40 x 길이 60 mm, 2층 FR-4, 완성 보드 두께 목표 1.0 mm, 양면 완성 동박 두께 목표 각 35 um, 50 ohm SMA 급전을 초기 검증 기준으로 채택했다. 상세 기준과 후속 확정값은 [21번 IFA 초기 검증 기준](21_RFAD_사례와_계약.md#ifa-initial-baseline)에서 관리한다. 물성은 사용자 입력/자료 선택 변수이며 실제 재료와 제작/측정 조건의 확정은 후속 작업이다. 이 기준은 모든 사용자 프로젝트에 강제하는 제품 기본값이 아니다.

미결 사항은 [25번 미결 항목 처리 기준](25_RFAD_문서_검토와_승인.md#remaining-decision-policy)에서 개발 전 사용자 승인, 개발 중 기술 선정/검증, 제작/측정/내부 배포 전 확정, 후속 출시 결정으로 구분한다. 사용자는 이 추천 처리 방향을 채택했다. 전체 문서 기준선은 승인되었으며 남은 착수 조건은 사용자의 별도 개발 착수 지시다. 기술 검증은 해당 단계에서 수행하고 개발은 아직 시작하지 않는다.

## 6. 실제 폴더와 예정 산출물

현재 저장소에는 README, 01_Docs, 00_REF가 있다. 추출 데이터의 기준 위치는 `00_REF/PCB RF ANT/04_RF_Antenna_Extracted_Data/extraction/`이며 [20번](20_RFAD_참고_자료_통합.md)에서 연결한다. 원문 PDF/CAD는 00_REF의 자료 분류 아래에 있다.

문서에서 제안하는 src, tests, schemas, fixtures, runtime_profiles, 프로젝트 내부 runs/exports는 별도 개발 착수 지시 후 만들 구현/사용자 데이터 경로다. 현재 파일이 이미 존재한다는 의미가 아니다. `example_*.json`은 21번의 fixture 설계 이름이며 실제 실행 예제로 제공된 파일이 아니다.

## 7. 설계의 핵심 경계

물리 원본, solver 근사, 표시용 mesh와 제조 출력은 구분한다. 미정 재질이나 미지원 기능을 숨은 기본값으로 채우지 않는다. 실행 완료, 수렴, 물리 진단, 목표 충족, 출력 왕복 검사, 실측 근거는 서로 다른 상태다. 성능을 높이기 위한 cache/LOD/지연 로딩은 이 경계를 유지해야 한다.

원호와 IFA의 end-to-end 흐름을 우선하고 UWB, 다중 포트, NFC/RFID, 배열은 필요한 물리와 검증이 준비된 단계에서 확장한다. 모든 형상에 하나의 lambda/4 식을 적용하거나 S11 하나로 효율/시간응답/통신거리의 검증을 대신하지 않는다.
