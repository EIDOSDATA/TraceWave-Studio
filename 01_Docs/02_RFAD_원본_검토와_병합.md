- **관련 문서:** [범위 결정](01_RFAD_설계_결정과_범위.md), [최종 요구](03_RFAD_사용자_요구사항.md), [데이터 모델](08_RFAD_데이터_모델과_파일_형식.md), [검증](14_RFAD_검증과_수용_기준.md), [추적](17_RFAD_요구사항_추적표.md), [출처](18_RFAD_출처와_근거.md)

## 1. 병합 결과와 원본 고정

이전 병합 기록은 A의 137개 요구를 유지하고 B의 128개 요구 중 124개를 보강 조건으로 연결했으며 독립 계약 4개를 AUG로 추가한 것으로 설명한다. 현재 저장소의 [요구 전문](03_RFAD_사용자_요구사항.md)에는 그 결과인 141개 고유 요구와 404개 AC가 남아 있다. 원본 A JSON은 현재 저장소에 없으므로 이번 개정의 본문 보존 검사와 원본 A의 독립 재대조를 구분한다. 원본 복구 전에는 A 전체와 byte 단위로 재검증했다고 주장하지 않는다.

B의 79개는 변수 **군**이며 A의 136개 원자 필드와 같은 단위가 아니다. 변수 합계 215개를 주장하지 않으며 별도 데이터 사전의 다대다 대응으로 추적한다. 최종 의미 데이터 사전은 A 136개를 유지하고 PAR-137...PAR-162의 26개 세부 계약을 보강한 **162개 항목**이다. 이는 화면 입력칸 수가 아니며 기존 요구를 세분화한 것이므로 신규 AUG 4개의 개수와도 별개이다. A 12개와 B 18개 수용 시나리오는 원래 ID를 유지한 채 최종 VT 기준군에 연결한다.

| --- | --- | --- | --- |
| A | 요구 137, 변수 필드 136, AT 12, 출처 170 | `00_baseline_A_consolidated.json` (현재 없음; 보존 문장은 RFAD 03 참조) | `f3326e3a04941704b624367a800e02d051574483e731178447b1aa0b1106220c` |
| B | 요구 128, 변수군 79, AT 18, 출처 48 | [원본 B](23_RFAD_원본_추가_요구사항.md) | `e32c11b68c0f47ac8fbe562b813fc709d7678bc0d1357dedcb0f367f58ac777f` |

본문과 검수 기준을 함께 검토했다. B는 PRJ 10, TGT 8, LIB 6, GEO 9, MAT 10, ENV 8, FED 9, SIM 9, RES 10, OPT 9, DRW 5, STP 10, FAB 9, VAL 8, NFR 8개이다. 원본의 OPT-005와 VAL-006은 비어 있으므로 새 번호를 보충하지 않는다. 동일한 `PRJ-001`이라도 A는 목표 대역, B는 설계 시작 경로이므로 B 원본은 항상 `B::`를 붙인다.

이전 묶음의 병합 JSON, B 대응표 JSON, 출처 레지스트리는 현재 저장소에 없다. 현 검토에서는 이 문서의 병합 결정과 B 전체 대응표, RFAD 03의 보존 문장과 AC, RFAD 17의 추적표를 사용한다. 이전 파일명과 hash는 과거 기록의 식별 정보이며 현재 파일의 무결성 증거가 아니다. 복구된 자료와 차이가 발견되면 [RFAD 25](25_RFAD_문서_검토와_승인.md)의 변경 기록으로 처리한다.

### 1.1 최종 레지스트리와의 연결

현재 설계안은 **141개 요구와 404개 수용 기준**을 8개 사용 사례, 24개 UI, 46개 기능, 30개 검증 시험군에 연결한다. 요구와 AC 전문은 [RFAD 03](03_RFAD_사용자_요구사항.md), 기능 계약은 [RFAD 06](06_RFAD_기능_설계.md), AC별 검증 연결은 [RFAD 17](17_RFAD_요구사항_추적표.md#ac-trace), 시험 방법은 [RFAD 14](14_RFAD_검증과_수용_기준.md)가 각각 관리한다. 별도 JSON 레지스트리는 현재 저장소에 없으므로 존재하거나 동기화가 확인된 산출물로 인용하지 않는다.

연결 수식은 해당 기능과 검증 조건에서 참조되는 식이며 모든 안테나 형상에 같은 식을 적용한다는 의미가 아니다. 수식의 정의역과 규약은 [RFAD 09](09_RFAD_수식과_물리_모델.md), 계산 순서는 [RFAD 10](10_RFAD_연산_파이프라인.md)를 따른다. 이 문서의 연결 상태는 명세 작성 상태이고 구현, 실행, 합격 상태가 아니다.

## 2. 두 원본의 보완 관계

A는 수집 자료의 원문 위치와 추출 레코드, 원호 비콘의 원본 Gerber 좌표, 조건부 재질 모델, solver 근사, 수렴, 전력 정의, RFID/NFC/다중포트 등 물리 범위와 검증 등급을 세밀하게 연결한다. B는 사용자 입력부터 실제 제조 전달까지의 흐름을 확장한다. 특히 형상 자동 수리의 diff/undo, 메시 생성 후 단선, 갭 소실, 표시용 패드 높이와 제조용 실제 동박 두께, 중공 배럴과 충진 비아, 목표 버전 재평가, 원시/후처리 결과의 분리, 큐와 복구를 검수 가능한 동작으로 구체화한다.

따라서 A의 근거와 조건을 지우지 않고 B의 동작, 검수 문장을 기존 요구에 추가했다. 데이터 수집이 끝났다는 것과 물성의 모든 누락이 해소되었다는 것은 다르다. 미정 적층, 동박, 급전, 넷은 가져오기 이후에도 미정으로 남으며, 예제 형상 재현만으로 RF 검증 완료가 되지 않는다.

## 3. 범위, 우선순위, 물리 의미 결정

단계 변경은 이번 구현 기준의 설계 판단이며 사용자가 특정 OS, 라이선스, 정확도 값을 승인했다는 주장으로 쓰지 않는다. 현재 보존된 원본 문장과 AC는 RFAD 03에서 유지한다. 이전 JSON의 `baseline_A`, `original_requirement`, `original_acceptance_criteria` 필드는 과거 구조 설명이며 현재 파일이 존재한다는 의미가 아니다.

### 3.1 요구의 의미를 바꾸지 않도록 한 보정

- **형상 계열과 해석 검증:** 임의 원호, 슬롯, 패치, UWB 형상을 그릴 수 있는 상태, 초기 합성식이 있는 상태, 선택 재료, 주파수에서 해석 검증된 상태를 각각 저장한다. 모든 PCB 크기에 같은 유효 유전율이나 1/4파장 길이 식을 적용하지 않는다.
- **두께와 모델:** 제조 STEP의 실제 동박, 도금, 마스크 두께, solver의 sheet/PEC/체적 근사, 화면 표시용 offset을 별도로 기록한다. skin depth가 얇다는 이유 하나로 모든 sheet 근사를 허용하지 않는다.
- **관측, 포트 규약:** 50 ohm는 선택 프로파일의 제안값으로만 허용한다. 복소 Z0와 power/voltage wave, 포트 순서, 종단, 여기, 기준면이 다르면 동일 결과로 비교하지 않는다. 위상 중심 미정은 미정으로 내보낸다.
- **확인 수준:** 문서상 지원, 설치 성공, 기준 실행, 수렴, 독립 solver 비교, 실측, 제조 승인과 인증은 독립 상태이다. 도구 README의 자체 성능값을 이 프로그램의 검증 성적으로 채택하지 않는다.
- **실패의 의미:** 입력 없음, 미지원, 무효 형상, solver 실패, 미수렴, 목표 미달, 불완전 출력은 서로 다르다. 어느 것도 자동으로 0, 합격, 완료 또는 최적해가 되지 않는다.

## 5. B에서 새로 검토한 외부 도구의 실제 범위

## 7. 보존과 완료 조건

현재 B 원문은 RFAD 23에 있고 A 원본 JSON은 없다. 확보 참고 자료와 추출 레코드는 `../00_REF/PCB RF ANT/` 및 그 아래 `04_RF_Antenna_Extracted_Data/extraction/`에 있다. 이전 기록의 geometry 31, material 3,160, auxiliary layer 41, condition 47, validation 26, model 19는 조사 규모이며 모델 정확도나 제품 구현 성적이 아니다. 자료의 현재 수량과 locator 검수 범위는 [RFAD 20](20_RFAD_참고_자료_통합.md)을 따른다. 형상 계열별 생성, 초기식, 검증 범위는 [RFAD 22](22_RFAD_안테나_형상별_합성.md)를 따른다.

이전 병합 기록은 A의 모든 요구를 같은 ID로 유지한 것으로 설명한다. 이번 개정은 현재 본문의 141개 요구를 보존하며 B와 직접 대응하지 않는 요구도 삭제하지 않는다. 원본 Gerber/재질의 출처 추적, 인증 범위, 데이터 사용권, 실측 불확실도, VNA 직접 연결, 가변 정합, 재구성, AoA와 원격 실행처럼 다른 문서가 덜 다룬 기능은 기존 단계와 조건을 유지한다.

현 문서의 보존 검사는 141개 요구 ID, 404개 AC, B 128개 대응 관계를 대상으로 한다. 원본 A 전체 대조, 누락된 이전 레지스트리 복구, 제품 구현, solver 실행, 실측은 별도의 후속 조건이다. 문서 구조 검사가 통과해도 릴리스 수용시험이나 독립 출력 검사, 물리 benchmark가 통과한 것은 아니다.

## 8. 이번 개정의 충돌 처리

| 확인한 문제 | 이번 설계안의 처리 | 후속 확인 |
| --- | --- | --- |
| 현재 없는 A JSON과 레지스트리가 존재하는 것처럼 서술됨 | 역사적 병합 기록과 현재 본문을 구분하고 파일 가용성을 명시 | 원본 A를 복구할 경우 보존 문장과 재대조 |
| 요구 수준의 VT 연결이 개별 AC 검수를 대신할 수 있음 | RFAD 17에 모든 AC의 주 시험과 고유 subcase 및 필수 증거를 지정 | 구현 후 실제 실행 증거 연결 |
| GUI 근거에 Qt API가 구현 의무처럼 남음 | Qt를 채택 경로에서 제외하고 GUI 중립 명령/undo 계약 유지 | RFAD 24의 wxWidgets/Avalonia 동등 비교 |
| 기본 템플릿과 물리 검증 범위가 혼재함 | R1 필수는 원호/평면 IFA, 패치 초기식은 조건부 보조 경로 | 지원 범위와 승인된 시험 조합 확인 |
| 메모리와 응답성에 대한 설계 책임이 모호함 | DES-URS-004와 FN 공통 자원 계약으로 프로세스/데이터 소유권과 예산을 명시 | 수치 예산은 RFAD 24의 사전 고정 절차 |

이 개정은 요구/AC를 삭제하거나 우선순위를 낮추는 승인이 아니다. 추가 설계조건과 미결 사항은 RFAD 25에서 사용자가 검토할 수 있도록 관리한다.
