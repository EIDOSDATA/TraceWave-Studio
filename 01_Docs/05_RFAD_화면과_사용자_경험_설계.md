# RFAD 05 - UI, UX 상세 명세

개정: 3.0 / 2026-11-07 KST / 상태: 사용자 검토용 설계안

관련 문서: [요구사항](03_RFAD_사용자_요구사항.md), [기능 설계](06_RFAD_기능_설계.md), [아키텍처](07_RFAD_소프트웨어_아키텍처.md), [데이터 모델](08_RFAD_데이터_모델과_파일_형식.md), [수학, 물리](09_RFAD_수식과_물리_모델.md), [검증](14_RFAD_검증과_수용_기준.md).

이 문서는 화면을 그리는 데 그치지 않고, 사용자가 값을 입력한 뒤 어떤 객체가 변경되고 어떤 계산, 출력까지 유효한지를 정의한다. 각 화면은 하나의 작업 공간 또는 도킹 패널 집합이다. 24개 화면을 동시에 열어 놓는 구성이 아니다. `UI-*`는 화면 계약, `FN-*`는 실행할 도메인 기능이다. B 원문의 동일 이름 요구사항은 반드시 `B::`로 구분한다.

## 1. 공통 구현 원칙

### 1.1 환경과 화면 뼈대

GUI는 C++ wxWidgets를 우선 평가 후보로, C#/.NET Avalonia를 비교 후보로 둔다. Qt 계열은 제외한다. 낮은 메모리와 체감 반응은 [24번](24_RFAD_GUI_선정과_성능_설계.md)의 동일 조건 실험으로 비교한다. Python application service와 CAD/해석 worker는 별도 프로세스로 유지한다. toolkit의 scene 및 renderer 객체는 영구 설계 데이터가 아니다. 객체 선택과 표시 변경은 안정적인 도메인 UUID에 연결하고 물리 형상은 공통 파라미터 모델에서 재생성한다. undo/redo는 GUI toolkit stack만으로 끝내지 않고 core command, revision, 저장 및 결과 무효화와 연결한다. OpenGL/native VTK의 실제 통합, 도킹과 DPI, 한국어 입력, 작업 취소 시험 후 GUI 선택을 확정한다. [GUI 기술 비교와 공식 근거](24_RFAD_GUI_선정과_성능_설계.md).

화면 행동은 공통 domain command로 설계하며 특정 toolkit의 undo/scene 객체를 프로젝트 저장 형식으로 사용하지 않는다.

R1 지원 목표는 Windows 11 x64 UI와 로컬 WSL2 Linux worker의 조합, Linux x86_64 UI와 native Linux worker의 조합이다. Linux worker를 R0에서 먼저 검증하되 Windows 경로, 한글 파일명, 프로세스 취소, 파일 이동 검증도 R1 출시 게이트다. native Windows openEMS와 macOS는 검증 전 지원으로 표시하지 않는다.

| 영역 | 고정 표시와 동작 |
| --- | --- |
| 상단 | 프로젝트명, 작업 사본/고정 리비전, 저장 상태, 시나리오, 현재 작업 공간, 실행/출력 명령 |
| 왼쪽 | 작업 단계와 객체 트리. 보드, 층, 도체, 슬롯, 포트, 환경, 실행을 의미 있는 그룹으로 구분 |
| 중앙 | 작업에 따라 2D/3D/표/그래프. 2D와 3D 분할 보기 가능 |
| 오른쪽 | 선택 객체의 기본 속성, 조건부 고급 속성, 출처와 실제 사용 모델 |
| 하단 | 문제 목록, 계산 작업, 로그, 실행, 파일 검사 결과. 접어도 차단 오류 수 유지 |
| 상태 표시줄 | 좌표, 표시 단위, 활성 층, 스냅, 선택 수, worker 연결 상태, 데이터 출처, 유효 상태 |

폭이 좁거나 화면 배율이 큰 경우 속성, 문제 패널을 탭으로 전환한다. 버튼을 가로로 잘라 숨기거나 단위를 숫자와 분리하지 않는다. 기본 테마는 명확한 명암 대비와 절제된 색상을 사용하고, 재료 색, 층 색과 성공/실패 색을 동일 의미로 사용하지 않는다. 폰트, 줄 간격, 패널 너비는 DPI 독립 값으로 구현하며 출시 기준 환경에서 검증한다. 고정 픽셀 크기의 모형 화면을 수용 기준으로 삼지 않는다.

### 1.2 숫자, 단위, 출처 위젯

모든 물리량 입력은 **이름 / 식 또는 값 / 단위 / 평가된 값 / 상태 / 출처 / 적용 조건**을 가진다. 저장은 SI, 각도는 rad이며 표시 단위는 mm, um, mil, GHz, MHz,  deg 등을 허용한다. 기본 표시 단위는 mm, um(동박), GHz,  deg이며 물리 기본값과 다르다. `1.2 mm`, `width / 2` 같은 지원 식을 같은 파서로 처리한다. 단위 없는 수치는 입력칸 옆에 표시된 단위로 해석하고, 붙여넣은 값의 단위가 다르면 변환값을 즉시 보여준다. 표현식은 허용 문법만 해석하며 Python 실행을 허용하지 않는다.

빈 칸은 `null/미지정`이다. 0, 미지정, 해당 없음, 미지원은 다르다. `FR-4=4.4`, 동박 35 um, 보드 1.6 mm 또는 임의 손실 0을 숨은 기본값으로 넣지 않는다. 템플릿 값은 출처가 있는 제안으로 표시하고 한 번에 적용할 때 적용 목록을 보여준다. 포트의 50 ohm 제안도 화면에 표시하고 저장되는 선택값이다. 무손실, PEC는 별도로 선택하는 모델이다.

| 입력, 자료 표시 범주 | 표시 및 동작 |
| --- | --- |
| 확인 입력 | 값, 단위와 사용자 또는 원자료 식별자 표시 |
| 출처 기본값 | `기본값 ,  출처 있음`; 출처와 적용 대역을 열 수 있음 |
| 승인된 추정 | `추정`; 승인 사유, 범위, 작성자/시각 보존. 자동으로 확인 입력으로 승격하지 않음 |
| 미지정 | 빈 값과 필요한 이유 표시. 해당 연산의 필수 값이면 실행 차단 |
| 해당 없음 | 조건을 표시하고 값 입력 비활성화. 이전 값을 지우지 않고 적용 제외 이유 보존 |
| 미지원 | 선택 backend와 미지원 성분 표시. 값은 보존하고 지원 대안 또는 명시적 근사 선택 제공 |
| 보간, 외삽 | 원자료 구간과 모델 표시. 외삽 허용 여부는 해석 정책과 검증 게이트에 따름 |
| 충돌 | 양쪽 원자료, 조건과 선택 이력을 열 수 있음. 평균값으로 자동 합치지 않음 |

저장 enum은 RFAD 08의 `Quantity.status`를 사용한다. 위 표의 보간, 외삽은 독립 status enum이 아니라 provenance/interpolation flag이며, 실제 solver 사용 여부는 `consumption_report`의 `used/approximated/omitted/not_applicable/blocked`로 분리한다.

입력 중 오류는 해당 필드와 문제 목록에 같은 `issue_id`로 표시한다. 차원 오류는 `요구: 길이, 입력: 주파수`, 순환식은 변수 경로, 범위 오류는 현재값, 허용범위를 보여준다. `적용`은 트랜잭션 단위이며 일부 필드만 몰래 반영하지 않는다. 오류 상태에서는 직전 유효 형상과 편집 초안을 분리 표시한다.

### 1.3 선택, 조작, 접근성

트리, 2D scene, 3D 바디, 속성표, 오류 위치, 출력 포함 목록은 `{revision_id, entity_uuid, subentity_role}`로 선택을 동기화한다. solver voxel/메시 또는 병합된 CAD 바디는 원본 객체들의 매핑을 표시한다. 한 face 번호를 리비전이 바뀐 뒤 영구 식별자로 재사용하지 않는다. 여러 객체 선택 시 공통값만 일괄 편집하고 서로 다른 값은 `혼합`으로 표시한다.

전역 단축키는 `Ctrl+N/O/S`, `Ctrl+Z`, `Ctrl+Shift+Z`, `Ctrl+F`, `Ctrl+Shift+P`(명령 찾기), `F6`(패널 이동), `Esc`(현재 도구, 입력 취소)다. `Esc`는 실행 중 해석을 즉시 종료하지 않는다. 해석 취소는 작업 패널의 명시적 명령이다. `Tab/Shift+Tab`, 방향키, `Enter`, `Space`로 표, 트리, 버튼을 조작하고 키보드로 입력한 좌표만으로도 핵심 형상을 만들 수 있어야 한다. 2D/3D의 `F`는 선택 맞춤 보기이며 텍스트 입력에 포커스가 있으면 문자 입력을 우선한다. 삭제는 물리 객체를 바꾸는 undo 가능한 명령이고 참조 중인 포트, 구속, 출력에 미치는 영향을 보여준다.

성공, 경고, 실패, 미평가를 색과 함께 아이콘 및 한글 텍스트로 표시한다. 그래프는 선 종류, 마커, 범례로 구분한다. 값 표와 그래프 원자료를 함께 제공한다. 한국어 라벨에 `방사 효율 (radiation efficiency)`처럼 필요한 영문을 병기하고, `S11 dB`, `Return Loss`, `gain`, `realized gain`을 한 라벨로 합치지 않는다.

### 1.4 작업 상태와 결과 유효성은 독립이다

저장되는 JobState와 전이는 [RFAD 04 section 6](04_RFAD_시스템_명세.md)의 단일 정의를 따른다. 아래 한글 표시는 여러 내부 단계를 묶은 화면 라벨이며 새 enum을 만들지 않는다. `transport_state=connected/disconnected/reconnecting`는 실행 상태에 겹쳐 표시하는 독립 축이다.

| 실행 단계 또는 연결 표시 | 사용자에게 보여줄 내용, 허용 동작 |
| --- | --- |
| 미실행 | 필요한 입력과 다음 작업. 임의 예제 곡선을 계산 결과로 표시하지 않음 |
| 검사/준비 | 검사 단계와 차단 문제. 취소 가능; 설계 열람 가능 |
| 대기 | 불변 실행 리비전, 필요한 자원, 대기 순서. 순서 변경, 취소 가능 |
| 메시 생성/해석/후처리 | 실제 worker 단계, 경과 시간, 실측 자원, 마지막 갱신 시각. 진행률을 모르면 불확정 표시 |
| 취소 요청 | 요청이 접수됨을 즉시 표시. 종료 확인 전 `취소됨`으로 바꾸지 않음 |
| 완료 | 파일 검사 및 결과 수신 완료. 수렴, 물리, 목표, 제조, 실측은 별도 상태 |
| 실패 | 단계, 원인, 로그 위치, 입력 리비전, 남은 원시자료. 다시 실행은 새 run ID |
| 취소/중단 | 완료된 하위 작업 보존. 체크포인트 재개와 처음부터 재실행 구분 |
| worker 연결 끊김 | 마지막 확인 상태와 시각 표시. 연결 복구 전 실패 또는 완료로 단정하지 않음 |

결과에는 계산 출처, 입력 완비, 수치 수렴, 물리 일관성, 목표 판정, 제조 검사, 실측 비교를 각각 표시한다. `stale/이전 조건 결과`는 실행 상태가 아니다. 과거의 정상 완료 결과가 현재 작업 사본에 대해 오래될 수 있다. 유효 결과와 과거 결과를 같은 곡선 스타일로 기본 중첩하지 않는다.

출력 파일 상태는 `ExportStatus=preview_only/generated_unverified/verified_profile/failed`를 사용한다. `verified_profile`은 명시된 출력 profile의 재열기, 형상, 의미 검사를 통과했다는 뜻이며 solver capability의 `verified` 또는 RF 성능 합격과 별개다.

### 1.5 변경 영향 규칙

| 변경 | 기존 raw EM | 다시 만들어야 할 것 | 화면 안내 |
| --- | --- | --- | --- |
| 카메라, 색, 표시 단위, 범례 | 유지 | 표시만 | 계산 배지 변경 없음 |
| 목표 한계, 가중치 | 유지 | 목표 판정, 순위, 보고서 | `기존 해석으로 목표 재평가` |
| 외부 정합망의 소자값, 전자기 영역 밖 부하 | 포트 계약과 선형 가정이 동일하면 유지 | 파생 네트워크, 해당 방사 조합, 지표 | `raw EM 재사용, 회로 결과 재계산` |
| 후처리 재정규화, 지원 기준면 이동 | 원본 유지 | 변환 네트워크, 지표 | 변환된 기준면, Z0와 원본 표시 |
| 외부 여기 진폭, 위상 | 저장된 포트별 복소 응답이 충분하면 유지 | 여기 조합, 전력, 복소 방사장 | 충분하지 않으면 필요한 재해석 범위 표시 |
| 정합 패드, 배선, 내장 lumped 소자, 급전 기하 | 해당 모델 raw EM 재사용 불가 | 해석 모델, 메시, raw EM, 파생 결과 | `물리/solver 모델 변경` |
| 재질, 동박, 환경 포함, 형상, 포트, 경계, 메시 | 해당 solver 입력이 달라지면 재사용 불가 | 변경 의존 부분과 실행 | 원래 리비전 결과는 보존 |
| 표면/전도 모델에서 사용하지 않는 물리 두께의 변경 | 무조건 재사용 또는 무조건 무효화하지 않음 | CAD/제조는 갱신, solver mapping 재평가 | 실제 solver 입력 hash가 같을 때만 근사, 유효범위 재검사 후 재사용 |
| 도면 축척, 출력 선택, 제조 프로파일 | 유지 | 해당 도면/출력/DRC 및 인계 manifest | EM 결과가 바뀌지 않았음을 표시 |
| 환경 물체 숨기기 | 유지 | 표시만 | `숨김`과 `해석 포함`을 별도 열로 표시 |

이 표의 판단은 UI가 추측하지 않고 도메인의 의존성 결과를 표시한다. 회로 부품의 패키지나 정합 패드가 EM 모델 내부에 있으면 외부 정합망 변경으로 분류하지 않는다. 결과 이름을 바꾸는 것만으로 이전 값의 유효성을 복원하지 않는다.

### 1.6 적은 비용으로 빠르게 반응하는 화면

화면은 [24번](24_RFAD_GUI_선정과_성능_설계.md)의 지연 로딩, virtual row, LOD, bounded cache와 PERF 예산을 적용한다. 사용하지 않는 3D/field/reference 패널은 처음부터 native 자원을 만들지 않는다. 닫힌 패널은 GPU/context/file mapping을 해제하며 선택과 view 설정만 작은 상태로 보존한다.

drag는 2D preview를 즉시 갱신하고 확정 시 domain command 하나로 commit한다. 재료/치수 편집의 연속 입력은 짧은 debounce 이후 최신 revision으로만 build하며 이미 진행 중인 결과가 늦게 도착하면 현재 결과처럼 게시하지 않는다. undo는 사용자의 의미 있는 편집 단위로 묶는다.

긴 작업의 사용 흐름은 요청 접수, 실제 실행, 산출물 게시를 구분한다. 취소 버튼은 즉시 요청됨을 표시하고 실제 종료까지 상태를 유지한다. 재접속 때 event cursor가 만료되면 전체 상태를 새로 받는다. em_prepare와 em_analysis는 별도 job로 보여주며 준비 완료를 해석 완료로 표시하지 않는다.

미구현/미지원 기능은 단계와 필요한 조건을 설명하되 R2/R3의 비어 있는 설정을 R1 기본 작업에 강제하지 않는다. 기하만 저장 가능한 프로젝트는 미정 물성을 유지하며 화면이 열렸다는 이유로 계산값을 보충하지 않는다.

표/plot의 표시 표본과 실제 평가 표본을 구별하고, 사용자가 zoom/ROI를 변경하면 해당 구간만 읽는다. 모든 숫자는 복사할 때 값과 단위, status를 보존한다. 색상 외 텍스트와 키보드 초점을 제공하고 IME 조합 중 Enter를 값 확정으로 오인하지 않는다.

## 3. 대표 작업 경로와 중단점

### 3.1 원형 PCB의 열린 원호 모노폴

UI-02에서 빈 설계 또는 확인된 reference를 선택하고 UI-03에서 목표 대역을 입력한다. UI-05에서 보드 원과 별도의 열린 원호 도체를 만든다. 보드 반경을 변경해도 원호 반경, 선폭, gap을 자동 종속시킬지 사용자가 식으로 정한다. UI-07/08에서 실제 적층과 물성을 고르고 UI-09에서 급전, 기준 도체를 지정한다. UI-12/13에서 지원, 메시, 자원과 연결을 확인한 다음 불변 실행을 생성한다. UI-15/16의 결과는 수렴 검토와 별도로 표시하고, UI-20/21/22에서 같은 리비전의 도면, STEP, CAM, 보고서를 만든다.

원호 길이 값은 기하 계산 결과다. 목표 주파수만 입력하여 어느 원형 보드에서도 공진이 보장된다는 문구를 만들지 않는다. 연결된 short가 존재하면 IFA 계열인지 토폴로지를 확인한다. 도체를 원형 외곽과 같은 색으로 그려 외곽선 자체를 안테나로 오인하게 하지 않는다.

### 3.2 기존 PCB 가져오기

UI-02->UI-21/05 import preview에서 단위, 원점, 층, 구리, 홀, 넷 보존 범위를 확인한다. 누락된 재질, 두께, 포트는 UI-07/08/09로 이동해 보완한다. 미정 상태에서도 편집/저장은 가능하지만 해당 정보를 요구하는 STEP, EM, 제조 명세는 준비되지 않았음을 표시한다. 외부 파일을 읽었다는 사실을 전체 의미 복원으로 표시하지 않는다.

### 3.3 외부 정합만 바꾸는 튜닝

UI-15에서 유효 raw EM을 선택하고 UI-10에서 외부 RLC를 변경한다. 기준면, 포트 계약이 동일하면 FN-017/024가 파생 네트워크와 지원되는 복소 방사장 조합을 다시 계산한다. raw EM run ID는 유지되고 derived ID만 바뀐다. UI-18에서 이 변수만 sweep하면 EM 작업을 매번 재생성하지 않는다. 실제 pad/trace나 EM 내부 소자까지 바꾸면 별도 물리 변경으로 새 해석을 요구한다.

### 3.4 실패 후 복구와 인계

UI-14는 실패 단계와 불변 입력을 보존한다. 작업 사본 수정은 과거 실행을 바꾸지 않는다. 체크포인트가 없는 solver는 `처음부터 재실행`으로 안내한다. UI-22에서 미완료 보고서를 만들 수 있어도 결과, 검증 상태를 숨기지 않는다. 완전 인계 조건은 필수 산출물, hash, 의미 대응, 재열기 검증의 일치이며 RF 목표 충족과 다른 축이다.

## 4. UI 검수 포인트

이 항목은 수행할 시험의 설계이며 현재 통과 기록이 아니다. 최종 실행 절차와 VT ID는 [검증 명세](14_RFAD_검증과_수용_기준.md)를 따른다.

- 단위 변경, 한국어 경로, 공백 경로, 높은 DPI에서 값, 단위, 오류, 버튼을 읽고 조작할 수 있다.
- 키보드만으로 프로젝트 열기, 원호 수치 생성, 재료, 포트 지정, 검사, 실행 요청, 취소, 도면 출력이 가능하다.
- 2D/3D/표/포트/문제 선택이 UUID로 연결되고 리비전 변경 후 잘못된 객체를 선택하지 않는다.
- 동박 실제 두께와 표시 과장, view 숨김과 EM 포함, raw/derived/measurement, 목표 미달과 미수렴을 각각 구분한다.
- 실행 중에도 저장, 문제 열람, 취소 요청이 응답하며 UI 지연 목표는 정해진 benchmark 하드웨어에서 측정한다.
- 외부 정합, 목표, 카메라 변경으로 raw EM을 불필요하게 버리지 않으며 실제 solver 입력 변경에는 정확한 stale 이유를 표시한다.
- 실패, 취소, 연결 끊김, 디스크 부족에서 성공 그래프나 완전 package 배지가 생성되지 않는다.

## 5. 근거와 설계 정책의 경계

wxWidgets/Avalonia와 CAD/openEMS/scikit-rf 문서는 해당 구성요소의 공개 기능과 개념을 확인하는 근거다. 본 제품의 화면 배치, 단축키, 단계, 상태 조합, 리비전, 캐시 정책은 A와 B 요구를 통합한 **설계 정책**이다. 공식 도구의 존재만으로 이 UI의 성능, 호환성, 접근성, 물리 정확도가 검증된 것은 아니다. 본문 source ID의 전체 서지와 버전은 [근거 자료](18_RFAD_출처와_근거.md), 계산 규약은 [수학, 물리](09_RFAD_수식과_물리_모델.md), 실제 API는 [아키텍처](07_RFAD_소프트웨어_아키텍처.md) 및 [예제와 계약](21_RFAD_사례와_계약.md)을 기준으로 한다.
