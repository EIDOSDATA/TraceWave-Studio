# 문서 정비와 검토 기록

[문서 정비와 인계 검토](08_문서정비와_인계검토.md)는 시점별 정정 근거를 기록한다. 현재 개발은 [다음 작업 순서](../09_개발계획/15_기능채택과_개발검증_순서.md#다음-작업-순서)에서 이어간다.

2026-11-21의 [현행 버전 완료 계획 검토](07_현행버전_계획검토.md)에 전체 개발 문서와 첨부 제안서 두 건의 검토 범위, 현행 버전에 반영한 결정과 근거를 기록했다.

앞선 정비는 [개발 문서 통합과 기존 26개 설계 개정](01_문서통합_검토.md)과 [문서별 상세](02_기존설계_문서별검토.md)에서 확인할 수 있다. 아래 기록은 당시 범위와 검사 수를 보존한다.

검토일: 2026-11-16 KST. 대상: 현재 개발 설계 문서, 승인 기준선과 참고 자료의 분류/연결.

## 화면설계서 정비

사용자가 제공한 실제 도구/탐색 화면과 `2c88d26` 이후 작업 트리를 대조했다. [화면 설계 폴더](../04_화면설계/README.md)에 화면별 기능/입출력/이벤트/전환/예외, 이름/선택, 사용성/접근성 및 기능 개발 중 갱신 규칙을 작성했다. 승인 UI-01~24 전체를 화면과 후속 단계에 연결했다.

10개 DrawIO와 같은 정의의 SVG, 렌더 PNG를 생성했다. 로컬 Edge headless에서 한글 글자의 도형 경계 초과를 검사하고 10개 이미지를 직접 검토했다. 이는 문서 그림 검수이며 실제 Studio의 새로운 GUI 시험 또는 DrawIO 앱의 네이티브 재열기 검증이 아니다. 첨부 화면 2개는 원본 바이트를 보존했다.

재현 명령은 [화면 관리](../04_화면설계/07_화면설계_갱신과_검수.md)를 따른다. 제품 코드는 이 문서 작업의 대상이 아니며 기존 스냅/끝점 작업 트리는 별도 유지한다.

## 전체 문서 정비의 경계

현재 문서의 잘못된 구현 설명과 중복 안내를 수정하고 기능/시스템/분석/운영별 탐색을 제공한다. 승인 원문 `01_개발문서`와 승인 해시, `00_참고자료` 원문/추출 및 과거 `runtime_profiles`는 그대로 보존한다. 당시 기록을 현재 구현에 맞춰 소급 변경하지 않는다.

외부 원문 PDF의 전 페이지/수식 재검증, 납품 물성 확인 또는 실제 RF/제조/측정 수용은 문서 정비와 별도다. 파일을 목록에 분류했다는 사실을 전문 내용 검증으로 보고하지 않는다. 문서별 내용 검토와 원문 파일의 구조/연결 검토 수준은 분리 기록한다.

기존 개발 Markdown 48개는 본문/주 책임/현재 설명을 검토하고 실제 분야별 폴더로 이동했다. 기존 GUI/제품 README와 자동 생성 감사는 문서 진입 및 기계 추적 대상으로 함께 검사한다. 승인 26개는 담당 분야 본문과 구조/ID/참조를 확인했다. 대용량 요구/원본 병합/색인의 모든 외부 사실을 재검증했다는 의미는 아니며 시스템 검토에 정확한 읽기 범위를 기록했다.

불필요한 현재 안내와 충돌은 권위 문서 링크/현재 상태로 교체했다. 최초 제안 두 개는 archive/proposals로 옮겨 현재 계약과 분리했다. 승인 원문/과거 수치/외부 원문을 삭제하여 문서 수를 줄이지 않았다. 전체 파일은 [기계 목록](../10_문서목록/02_문서목록.json), 이동 대응은 [path_map](../10_문서목록/01_이전경로대응.json)에 기록한다.

## 독립 문서 검토에서 보완한 사항

새 화면 묶음의 별도 검토에서 D15 이름 중복 범위와 현재 모달 복귀 설명의 불일치, 상태도의 오류 복귀 누락을 발견해 고쳤다. DrawIO 흐름선에는 source/target 셀과 상대 접속점을 붙여 상자 이동 때 연결을 유지하도록 했다. 10개 그림을 재생성/렌더했고 글자 도형 경계 초과는 없었다.

현재와 과거 source hash의 차이는 원문 무결성 문제로 기록했다. `KEYSIGHT_NETWORK_ANALYSIS_HTML`은 새 근거로 채택하기 전에 확인해야 하며 이번에 복원/확정하지 않았다. RO4350B 개별 손실 2.788446%/초기2% 미확립, GHz PTH 독립 정확도와 실제 납품/교정/측정 조건의 미정도 그대로다.

## 검증의 의미

현재 개발 Markdown 86개의 로컬 링크와 그림 10세트의 구조/렌더를 검사했다. 현재 링크 수/실행 결과와 그림 해시는 [당시 문서 검사 기록](06_문서검증_기록.json)에 둔다. 아래 12개 회귀 수는 앞선 정비 시점이며 이번 통합은 14개다. 커밋에 포함할 문서와 게시된 제품 코드 기준을 임시 경로에 추출해 요구 추적 생성/`--check` 및 `test_implementation_audit.py` 12개 시험을 통과했다. 최초 감사 기준은 별도 필드에 보존하고 이번 문서 검토일/제품 기준을 갱신했다. 미커밋 FN-008 정밀 편집 근거는 작업 트리에 남겼으며 문서 커밋의 게시 기능으로 합치지 않았다.

승인 요구 141개/AC 404개/subcase 407개/FN 46개/VT 30개/API 30개의 연결을 확인했으며 수용 합격을 새로 주장한 항목은 0개다. 자동 목록 생성 성공을 설계의 모든 물리 주장이 참이라는 판정으로 사용하지 않는다. 이번 문서 변경에서 제품 GUI/native/FDTD/측정 시험은 새로 실행하지 않았다.

설계 자료는 분야별로 읽을 수 있게 정리했지만 모든 실증 의존성이 닫힌 것은 아니다. [R1 설계 준비표](../02_시스템명세/10_설계준비와_결정경계.md)에 후속 구현의 계약과 필요한 증거를 명시했고, 각 기능 구현 시 화면/계약/시험 문서를 함께 갱신한다. 사용자가 요청한 문서 정비를 마친 뒤 기존 개발 순서를 이어간다.
