# 기능 계약 문서 내용 검토

이 기록은 2026-11-16의 첫 문서 정비(80ce6b4/60b0938) 범위다. 이후 사용자 지시에 따라 기존 01_개발문서 현행 본문도 수정하고 개발 문서를 통합했다. 후속 변경은 [통합 검토 기록](01_문서통합_검토.md)을 따른다. 아래에서 승인 원문을 수정하지 않았다는 설명은 당시 작업과 보관 기준선에 한정한다.

검토일: 2026-11-16 KST. 승인 기준: RFAD-D0-3.4. 이 기록은 기능 계약 18개의 본문 전체와 아래 승인 문서 6개의 본문 전체를 읽고 현재 코드/시험 정의와 대조한 결과다. 새 제품 기능 구현, GUI 실행, FDTD 또는 실측 검증 기록은 아니다. 기존 단계 번호 3~13과 이전 실행 증거는 유지한다.

현재 작업 트리의 정밀 2D 스냅/끝점 변경을 읽었으며 해당 기존 코드/계약 변경을 제거하거나 새로 구현한 것으로 기록하지 않는다. 과거 프로젝트/카드 버전, 검증 수치와 제조사 원문 수치는 소급 변경하지 않았다. 현재 계약의 오래된 상태 설명과 문서 권위, 누락된 API 경계만 보완했다.

## 4. 충돌을 없앤 문서 권위

저장 원본은 project_persistence/design_data, 목표 원본은 target_contract, 목표 부분 편집은 target_editor_contract, 후보/원자 적용 공통 경계는 template_contract다. 문헌별 출처/적용 범위만 literature_templates와 printed_templates_and_seeds에서 상세화한다. 카탈로그 조회는 pcb_catalog_contract, 프로젝트 채택/보존은 pcb_selection_contract, 전기 모델 소비 의미는 material_loss_models가 담당한다.

화면 배치/전환/객체 이름 제안은 [화면 설계 폴더](../04_화면설계/README.md)에서 관리한다. 이 제안으로 현재 API와 schema 지원 상태를 덮어쓰지 않는다. 규칙과 외부 환경의 현재 기능은 design_rules/physical_setup이 소유한다. 최초 제안 두 문서의 과거 현재형을 최신 계약으로 인용하지 않는다.

문서 재배치 뒤에는 상대 링크/표/도구 참조를 전체 검사한다. 승인 원문 및 기존 검증 기록의 의미나 통과 수치를 재배치에 맞춰 변경하지 않는다.

재배치 전 자체 확인: 담당 기능문서 18개와 이 검토 기록/객체 이름 설계까지 20개 문서의 로컬 링크 225개가 존재했고 끝 공백이 없었다. 담당 기존 문서의 `git diff --check`도 통과했다. 이 수치는 문서 구조 점검이며 제품 시험 통과 수치에 합산하지 않는다. 재배치 후 최종 검사는 전체 문서 검토 기록을 따른다.
