# 01_개발문서 통합과 기존 설계 문서 개정 검토

검토일: 2026-11-16 KST. 사용자 지시: 개발 문서를 01_개발문서로 이동하고 해당 경로의 기존 문서도 검토/수정/정리/보강/재배치한 뒤 커밋과 푸시.

## 실제 정리한 내용

- Code/docs의 개발 명세/기능/화면/분석/계획/운영/검증/그림을 모두 01_개발문서로 옮겼다. Code/docs의 전달용 문서 3개와 폴더 자체를 제거했다.
- 기존 00~25 설계를 읽고 문서 역할/현재 구현/요구 추적을 대조했다. 현재 편집본을 화면, 기능, 명세, 요구, 구조, 분석, 검증, 계획으로 재배치했다. 번호/ID는 유지한다.
- 00과 저장소 README의 중복 목록/착수 대기 설명을 정리하고 유일한 분야별 문서 입구를 만들었다. 03의 141개 요구에 반복된 미구현 현황을 삭제하고 현재 감사에 연결했다.
- 현재 구현이 있는데도 전부 미실행/미구현/개발 전이라고 하던 문장, 가상 소스 폴더, 공개 DTO와 완성 목표의 혼동을 교정했다. 현행 API/core 버전, 6개 명시/문헌 카드, 조건부 초기식, 제약/기본 DRC, 적층/환경의 제한을 기존 설계와 연결했다.
- wxWidgets/wxAUI/사용자 정의 2D/wxGLCanvas 구성과 화면별 기능/버튼/전환/복귀/사용성/이름 계약을 한 화면 폴더에서 찾도록 했다. 영속 이름/F2와 전체 정밀 편집/선택 UX를 이미 구현된 것으로 표시하지 않는다.
- 기존 승인 당시 26개 문서/records 3개와 승인 커밋 README를 12_보관이력/01_승인기준선/01_삼점사에 보관했다. 현재 편집본을 새 승인 기준선으로 표시하지 않는다.
- 현재 링크, 감사 근거 경로, 생성/검사 도구와 이전 경로 대응을 함께 바꿨다. 과거 runtime/외부 원문 속 논리 경로와 hash는 그대로 두었다.

문서별 변경/보존 범위는 [담당별 상세](02_기존설계_문서별검토.md), 이동 전후 경로는 [path_map](../10_문서목록/01_이전경로대응.json), 정식 시작점은 [통합 안내](../README.md)다. 불필요한 현재 안내는 삭제하고 원본 B/수식/요구/승인 및 검증 이력은 근거로 보존한다.

## 검증과 기록의 경계

[문서 검사 기록](06_문서검증_기록.json)은 현재 문서 링크, 10개 DrawIO/SVG/PNG 세트와 승인 manifest 27개 Markdown의 hash를 검사한 결과다. 승인 요구 141개/AC 404개/subcase 407개/FN 46개/VT 30개/API 30개 연결은 구현 감사 생성/재검사 및 감사 회귀 시험으로 확인한다. 이동한 문서만 허용하는 근거 경로와 현행/아카이브 중복 선택 방지도 검사한다.

게시 제품 기준 코드와 이번 문서를 추출한 격리된 임시 경로에서 최종 감사 생성/--check를 확인하고 감사 회귀 14개, 문헌/출처 보존 10개와 JLC 검증 도구 3개, 총 27개를 통과했다. 제외/실패는 없다. 기존 미커밋 정밀 편집 파일은 작업 트리에 보존하고 문서 커밋에 섞지 않는다. 미커밋 FN-008의 상세 근거도 이동한 JSON의 작업 트리 변경으로 보존한다. 따라서 게시 감사와 변경 중인 작업 트리의 hash가 다른 것은 전체 제품 검증 실패를 뜻하지 않는다.

이번에는 새 Windows 제품 GUI, native CAD/FDTD, 실물 제작/측정 시험을 실행하지 않았다. 외부 원문 PDF 전 페이지/모든 외부 URL/41개 물리식의 독립 재유도나 R1 수용 완료를 주장하지 않는다. 현재 계약의 내용 검토와 참고 파일 목록/해시 검사의 수준은 [기계 목록](../10_문서목록/02_문서목록.json)에 구분한다.

## 계속 열린 조건

RO4350B 국부 도체 손실 변화 2.788446%/초기 2% 기준 미확립, GHz PTH 독립 정확도, 실제 납품 물성/실장/교정/측정 조건을 유지한다. KEYSIGHT_NETWORK_ANALYSIS_HTML의 출처 hash 불일치도 [분석 검토](05_해석과_참고자료_검토.md)에 그대로 남긴다. 문서 정비가 물리 근거를 새로 확보한 것은 아니다.

기능을 이어서 개발할 때에는 기존 [완료 계획](../09_개발계획/03_개발완료_계획.md) 1~13번 순서를 유지하며 기능 계약/화면 시나리오/시험과 검증 기록을 함께 갱신한다. Linux GUI/R2/R3와 비평면 3차원 안테나는 후속 범위다.

## 후속 지시와 최종 범위

개발 문서 루트와 내부 폴더는 번호_한글 이름으로 정리한다. 참고자료 내부까지 명명 규칙을 적용한 작업은 사용자 정정으로 철회했다. 사용자가 참고자료를 직접 복구하므로 이후 해당 경로의 파일/폴더를 수정하거나 복구하지 않는다.

참고자료 내부 이동에 맞춰 추가했던 카탈로그 경로표 처리, 도구 보강과 시험 코드는 이번 변경에서 제외하고 원래 상태로 되돌렸다. 개발 문서, 생성/검사 도구와 참고자료 루트 이름에 대한 최소 경로 대응만 최종 범위에 남긴다. 이전 이동 관련 시험은 최종 게시 코드의 시험으로 집계하지 않는다.


## 전체 문서 재검토와 최종 명명

현재 문서와 승인 사본, 최초 제안 및 검토 기록을 분야별로 다시 읽고 상태/계약/참조를 대조했다. README 20개를 제외한 162개 문서/그림/JSON/원문 사본의 파일명을 한글로 정리하고 폴더별 01부터 다시 번호를 매겼다. 승인 사본은 파일명만 바꾸고 본문 바이트/원래 manifest hash를 유지했다. README가 설명하는 논리 문서 ID와 파일 탐색 번호를 구분한다.

재검토에서 중복된 구현 현황 표의 core 0.3/문헌·제약 미구현 설명을 현행 0.4/문헌 카드/기본 DRC/환경 상태로 교정했다. 이미 완료한 고정 IFA/NF2FF 실행을 다음 작업으로 다시 안내한 문장과 동기 STEP 조회의 예외도 보강했다. 과거 날짜별 실행 수치/버전/수용 한계는 보존한다.

폴더 이름과 우연히 같은 기술 식별자 catalog/features/verification을 문서 경로로 잘못 치환한 부분은 원래 필드/모듈 이름으로 복원했다. 참고자료 내부 docs 경로를 개발 문서 경로로 오인한 검토 표, 공백을 포함한 링크와 이전 실행 제목 anchor도 바로잡았다. 부정확한 선정 상태 표현은 승인 당시 상태와 현재 개별 GUI 시험/전체 수용 미완료로 분리했다.

참고자료 내부는 사용자 복구본을 수정하지 않는다. 커밋에는 기존 Git blob을 그대로 사용한 00_REF에서 00_참고자료로의 루트 이름 변경과 사용자가 별도로 요청한 루트 README만 포함한다. 과거 source 경로를 가진 문헌 검증 도구와 JLC 도구 기본값은 루트 이름만 대응하며 원문 카드/manifest/내부 경로와 값은 바꾸지 않는다.

문서 정합성/명명 정비를 모든 후속 기능의 세부 설계 확정으로 표시하지 않는다. 후속 파일 파서의 수치 자원 상한, wire 필드/capability와 독립 수신기 검수 profile은 해당 구현 단계의 결정/증거 조건으로 계속 관리한다.
