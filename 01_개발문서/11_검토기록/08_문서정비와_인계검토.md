# 문서 정비와 새 채팅 인계 검토

## 2026-11-22 현행 R1 승인 범위 변경

사용자 결정에 따라 기준 PC 성능 검수(F0~F5)를 R1 승인표에서 제외했다. 재부팅 직후 첫 실행 5회와 기준 PC의 프레임 재계측은 R1 출시 조건에서 빠졌다. 과거 성능 측정값과 원래 설계 기준은 당시 기록에 보존한다. 9번 원호와 IFA의 대역 판정에 이어 12번에서 실제 한글 IME, 스크린리더 오류 안내와 혼합 DPI 창 이동을 확인한다. 13번에서 그 결과를 내부 후보에 인계한다. 별도 Windows 오프라인 수신은 환경이 준비되면 검수한다. [현행 요구 추적표](../07_검증/03_요구사항_추적표.md), [잔여 작업표](../09_개발계획/04_현행버전_남은작업.md)

## 2026-11-22 앞선 문서 정비 기록

이번 문서 검토의 저장소 기준 개정은 `59a988e`이고, 수신 검증한 내부 후보의 제품 소스는 `e28a982`다. 사용자가 허용한 RO4350B 고정 사례의 7/8분할 간 차이 2.788446%와 원래 2% 기준에 따른 판정을 구분했다. PTH의 독립 비교는 재현한 합성 모델 범위까지 기록한다. 원호와 IFA는 같은 정합 회로와 목표 대역에서 격자 및 외부 경계 조건에 따른 S11 판정이 남았다. [RF 연구 안내](../06_분석연구/README.md)

동일 개정의 STEP, 도면, CAM 수신을 반복하던 지시를 정리했다. 측정 비교는 외부 자료가 있을 때 선택한다. 이 정비 시점에는 개발 PC의 프레임 개선을 종료하고 Windows 환경 검수를 보류했다. 이후 재개할 항목은 [현행 인계](../09_개발계획/08_새채팅_개발인계.md)에서 확인한다.

문서 전체의 로컬 링크, 승인 보관본 27개의 해시와 전환도 12세트를 확인했다. 84개 GUI 시안은 기존 렌더 기록 및 자산 252개와 대조했다. 요구 141개, AC 404개, 세부 사례 407개의 추적표를 다시 생성하고 감사 회귀 14개를 통과했다. 고정 배포 후보 ZIP의 SHA-256도 수신 기록과 일치했다.

## 2026-11-21 정비 기록

당시 제품 기준은 `d3ef05c`, 승인 기준선은 RFAD-D0-3.4였다. 아래는 그 개정에서 확인한 범위와 변경 내용이다.

## 확인 범위

- 기존 목록의 4,229개 항목을 실제 파일과 대조했다. 이 가운데 기존 개발문서 846개는 자기 참조를 피하는 목록·집계 두 파일을 제외한 수다. 참조 자료 3,336개와 과거 실행·환경 기록 44개는 보존했다.
- 개발문서 Markdown 전문을 UTF-8로 읽고 현재형·이전 경로·중복 본문 후보를 찾았다. 다음 작업과 직접 연결되는 계획, 상태, 화면·기능 계약, 개발 진입 안내와 추적표는 코드 및 보존 검증을 대조해 편집했다.
- 개발문서의 JSON/JSONL, DrawIO/SVG, 화면 PNG/JPG는 형식을 검사했다. 기존 84개 화면 시안과 12개 전환도 검사는 문서 도구로 실행했다. 바이트가 같은 두 쌍의 검증 사진은 서로 다른 기록의 링크가 있어 보존했다.
- 승인 설계의 바이트, 외부 PDF·수집 원본과 과거 시험 환경을 보존했다. 외부 PDF의 모든 페이지를 다시 읽거나 물성을 재검산하는 대신 기존 검토와 연결된 출처 및 파일 해시를 확인했다. 이번 문서 변경에서 제품 GUI, FDTD와 실측은 새로 실행하지 않았다.
