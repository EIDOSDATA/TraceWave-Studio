# 문서 정비와 새 채팅 인계 검토

## 2026-11-23 문서 정비와 새 PC 인계

기능 기준 개정 `e7ce0a2`에서 추적 중인 개발 Markdown 461개(승인 보관본 포함), 저장소와 Code 안내 3개, 참고자료 안내 11개의 본문을 읽었다. 검증 보고서의 당시 입력, 결과와 날짜는 보존하고 현행 기능 계약, 계획, 운영 절차와 읽기 순서를 대조했다. 참고자료의 PDF, 제조 원본과 실행 환경 파일은 전수 목록과 해시로 확인했다.

| 정비한 곳 | 확인할 내용 |
| --- | --- |
| 기능 개발 순서 | 이미 검증한 403~407의 범위에서 다음 다섯 개발 작업을 구분하고 여섯 번째에 새 후보 수신 검수를 둔다. 각 작업 옆에 완료 조건과 근거가 있다. [다음 작업 순서](../09_개발계획/15_기능채택과_개발검증_순서.md#다음-작업-순서) |

개발 PC에 CPython 3.12 수치 가상환경을 새로 만들고 저장소의 해시 고정 목록으로 설치했다. 의존성 검사 통과 후 403번과 404번 예제에서 각각 세 주파수의 결과를 얻었고, 회귀 시험 7개가 제외 없이 통과했다. 구현 감사 회귀 15개, 승인 보관본 27개의 해시, 전환도 12세트, GUI 시안 84개의 자산 252개를 확인했다. 별도 Windows/WSL2 PC에서의 최종 후보 수신은 기능 개발 후 진행한다.

### 새 PC로 옮길 때의 연결 작업 트리

기능 개정 `e7ce0a2`의 `origin/main`과 세 작업 트리의 수정 파일, 미추적 파일을 Git 객체 내용으로 대조했다. 각 사본은 브랜치를 체크아웃하지 않은 상태(detached HEAD)였으며 따로 옮겨야 할 고유 소스 파일은 없었다.

| 작업 트리 | 용도 | 원격에서 찾는 위치 |
| --- | --- | --- |
| `stage-check` | 커밋할 파일을 따로 놓고 문서 목록과 구현 감사를 재생성한 검증 사본 | 733개 중 732개는 당시 `origin/main`과 같았다. 남은 `cli/floquet.py`는 `e6c1515`의 파일이며 `91f102f`에서 `cli/em_case.py`로 통합했다. |
| `tracewave-cadpose` | STEP 조립 부품의 기준축 회전과 독립 수신 검증 | 수정 파일 5개 모두 `e3ba1d1`에 포함됐다. |
| `tracewave-sensitivity` | 설계 변수에 따른 공칭 주파수 반사 응답 비교 | 수정 파일 4개 모두 `e1d38d9`에 포함됐다. |

## 2026-11-22 현행 R1 승인 범위 변경

사용자 결정에 따라 기준 PC 성능 검수(F0~F5)를 R1 승인표에서 제외했다. 재부팅 직후 첫 실행 5회와 기준 PC의 프레임 재계측은 R1 출시 조건에서 빠졌다. 과거 성능 측정값과 원래 설계 기준은 당시 기록에 보존한다. 9번 원호와 IFA의 대역 판정에 이어 12번에서 실제 한글 IME, 스크린리더 오류 안내와 혼합 DPI 창 이동을 확인한다. 13번에서 그 결과를 내부 후보에 인계한다. 별도 클린 Windows/WSL2 PC의 온라인 수신을 검수한다. 네트워크 조건 변경은 2026-11-23 사용자 결정이다. [현행 요구 추적표](../07_검증/03_요구사항_추적표.md), [잔여 작업표](../09_개발계획/04_현행버전_남은작업.md)

## 2026-11-22 앞선 문서 정비 기록

이번 문서 검토의 저장소 기준 개정은 `59a988e`이고, 수신 검증한 내부 후보의 제품 소스는 `e28a982`다. 사용자가 허용한 RO4350B 고정 사례의 7/8분할 간 차이 2.788446%와 원래 2% 기준에 따른 판정을 구분했다. PTH의 독립 비교는 재현한 합성 모델 범위까지 기록한다. 원호와 IFA는 같은 정합 회로와 목표 대역에서 격자 및 외부 경계 조건에 따른 S11 판정이 남았다. [RF 연구 안내](../06_분석연구/README.md)

동일 개정의 STEP, 도면, CAM 수신을 반복하던 지시를 정리했다. 측정 비교는 외부 자료가 있을 때 선택한다. 이 정비 시점에는 개발 PC의 프레임 개선을 종료하고 Windows 환경 검수를 보류했다. 이후 재개할 항목은 [현행 인계](../09_개발계획/08_새채팅_개발인계.md)에서 확인한다.

문서 전체의 로컬 링크, 승인 보관본 27개의 해시와 전환도 12세트를 확인했다. 84개 GUI 시안은 기존 렌더 기록 및 자산 252개와 대조했다. 요구 141개, AC 404개, 세부 사례 407개의 추적표를 다시 생성하고 감사 회귀 14개를 통과했다. 고정 배포 후보 ZIP의 SHA-256도 수신 기록과 일치했다.

## 2026-11-21 정비 기록

당시 제품 기준은 `d3ef05c`, 승인 기준선은 RFAD-D0-3.4였다. 아래는 그 개정에서 확인한 범위와 변경 내용이다.

## 확인 범위

- 기존 목록의 4,229개 항목을 실제 파일과 대조했다. 이 가운데 기존 개발문서 846개는 자기 참조를 피하는 목록·집계 두 파일을 제외한 수다. 참조 자료 3,336개와 과거 실행·환경 기록 44개는 보존했다.
- 개발문서 Markdown 전문을 UTF-8로 읽고 현재형·이전 경로·중복 본문 후보를 찾았다. 다음 작업과 직접 연결되는 계획, 상태, 화면·기능 계약, 개발 진입 안내와 추적표는 코드 및 보존 검증을 대조해 편집했다.
- 개발문서의 JSON/JSONL, DrawIO/SVG, 화면 PNG/JPG는 형식을 검사했다. 기존 84개 화면 시안과 12개 전환도 검사는 문서 도구로 실행했다. 바이트가 같은 두 쌍의 검증 사진은 서로 다른 기록의 링크가 있어 보존했다.
- 승인 설계의 바이트, 외부 PDF·수집 원본과 과거 시험 환경을 보존했다. 외부 PDF의 모든 페이지를 다시 읽거나 물성을 재검산하는 대신 기존 검토와 연결된 출처 및 파일 해시를 확인했다. 이번 문서 변경에서 제품 GUI, FDTD와 실측은 새로 실행하지 않았다.
