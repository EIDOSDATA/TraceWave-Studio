# 실행 소스 묶음과 환경 식별

개발 완료 계획 7번의 기능 추가에 앞서 도입한 실행 의존 소스 보존 계약이다. 기준 커밋은 6번 마감 `a256bf51f7b0959f814b6b524a123421827e2edf`다. 계산식/재료/제작/측정 조건을 바꾸지 않으며 승인 설계와 과거 실행 증거는 그대로 둔다.

## 1. 목적과 범위

기존 worker는 `src/rfad`의 모든 Python 파일을 복사했다. 6번 최종 openEMS 실행은 진입점을 포함해 189개로 공통 192개 상한에 가까웠다. 무관한 화면/교환 기능 모듈을 추가할 때도 native 실행이 막히는 결합을 줄이되, 실제 실행에 필요한 소스의 본문을 생략하지 않는다.

`application/source_bundle.py`가 실행 profile별 명시 진입점에서 전이 의존성을 수집한다. 실제 한 번 실행에서 로딩한 모듈만 고르는 방식이 아니다. AST의 모든 조건 분기/함수 내부/상대 import와 부모 패키지 `__init__.py`를 포함한다. 실행된 분기만 관측한 결과로 다른 분기의 소스를 삭제하지 않는다.

| profile | 명시 진입점과 보수적 범위 | 상한 |
| --- | --- | --- |
| `rfad.source.cad/0.1` | 실제 호스트 생성자의 entry bytes를 `worker.py`로 보존. 생성/외부 STEP 검토 분기의 제품 의존성 | 논리 Python 파일 192개, JSON 묶음 2 MiB |
| `rfad.source.openems/0.1` | `tools/openems_worker.py`, `tools/wsl_supervisor.py`. supervisor가 나중에 읽는 native_process, PCB/참조/방사/손실 분기의 전체 의존성 | 192개, 4 MiB |
| `rfad.source.host-calculation/0.1` | RPC, Projects, 설계 스윕 서비스/runner, 고정 supervisor. service 객체로 주입된 저장/명령/계산 호출도 빠뜨리지 않는 보수적 경계 | 192개, 4 MiB |

공통 파일 수/크기 상한을 늘리지 않는다. ZIP 하나나 합친 파일 하나로 세어 논리 파일 수를 우회하지 않는다. CAD entry는 별도 artifact를 유지하되 새 profile의 파일 수와 전체 비용 검사에 포함한다. 과거 CAD 묶음의 entry 별도 집계 증거를 소급 변경하지 않는다.

## 2. 봉인 형식

새 `source_bundle` descriptor는 다음 필드만 가진다.

- `schema`: `rfad.source-bundle/0.1`.
- `profile`: 위 실행 profile.
- `entry_points`: profile에 정해진 순서의 진입점.
- `dynamic_imports`: 명시 등록한 동적 import의 소스 경로/대상 목록.
- `source_sha256`: `path -> sha256` 사전의 정규 JSON 바이트 SHA256.

별도 `code_files`는 실제 실행할 각 경로/바이트 수/SHA256을 담고 정렬한다. source JSON에는 선택한 파일들의 UTF-8 본문 전체를 보존한다. CAD는 기존 entry artifact와 `src/rfad` source artifact를 별도로 두고, identity의 전체 파일 목록으로 두 대상을 함께 확인한다. CAD의 기존 `source_sha256`은 제품 패키지 소스만의 해시라는 의미를 유지하고 새 descriptor는 entry까지 포함한다.

CAD는 실제 entry와 패키지의 UTF-8 줄바꿈 바이트를 보존한다. openEMS와 host 패키지는 기존처럼 CRLF/CR을 LF로 정규화하여 그 바이트를 stage에 쓴다. supervisor는 transport가 실행하는 고정 원문과 같은 바이트로 보존한다. checkout 파일 hash와 정규화한 실행 소스 hash가 항상 같다고 가정하지 않는다.

host 계산의 `application_source`는 `rfad.host-calculation-source/0.2`로 식별하며 새 descriptor와 파일 목록을 포함한다. 이 필드는 실행 소스의 식별 manifest다. worker의 본문 source artifact와 같은 형식의 소스 원문 보관이라고 주장하지 않는다. 기존 `0.1` 기록은 과거 전체 소스 식별 그대로 읽고 고쳐 쓰지 않는다.

## 3. 명시 의존성과 실행 검증

Python은 `import` 문 외에도 `importlib`와 import hook으로 모듈을 읽을 수 있으므로 AST 목록만으로 모든 동적 실행을 증명할 수는 없다. 현재의 `network_hdf5` 상수 `h5py`/`numpy` 동적 import는 명시 등록하며, 가변 이름이나 미등록 동적 import/코드 로더를 발견하면 캡처를 차단한다. 고정 bootstrap과 source loader는 명시한 제품 코드 경계다. 향후 동적 플러그인/비 Python 코드 자산을 추가하려면 별도 의존성과 보존 계약을 먼저 추가해야 한다. [Python import 시스템](https://docs.python.org/3/reference/import.html), [importlib](https://docs.python.org/3/library/importlib.html).

모듈 이름은 지정 root의 실제 `.py` 또는 패키지 `__init__.py`로만 해결한다. 링크/Windows 재분석점, root 탈출, 중복 모듈/패키지, 비정규 경로를 거부한다. 설치된 동명 `rfad`를 의존 소스 누락의 대체물로 사용하지 않는다. 외부 NumPy/OCCT/openEMS 같은 배포와 native 파일은 기존 고정 설치 명세/감사/Qt 제외 검증을 따른다.

실행 전에 다음을 대조한다.

1. 봉인 descriptor/파일 개수/파일별 크기와 전체 비용.
2. 실제 stage의 추가/누락 `.py`, bytecode/native 대체 파일, 링크와 모든 실제 소스 바이트.
3. stage에서 다시 수집한 전이 의존성과 봉인 목록/descriptor의 일치.
4. Python 제품 import 전에 bootstrap 자체의 hash와 동일 바이트 실행.
5. 전용 import finder가 허용한 제품 모듈만 로딩. 이미 검증 전에 로딩된 `rfad`는 거부.
6. import 직전에도 바이트 상한/hash를 확인하고, 확인한 bytes를 직접 컴파일하여 기존 pyc를 사용하거나 새 pyc를 쓰지 않음.

이 경계는 native 작업의 소유권/취소/프로세스 종료 확인을 대체하지 않는다. 실행 중 임의 관리자 권한의 모든 파일/메모리 변조를 방어하는 운영체제 sandbox를 구현했다는 뜻도 아니다. 최초 검증 뒤 재읽기로 다른 소스를 실행하지 않는 경계를 명시적으로 검사한다.

## 4. runtime과 과거 자료 호환

새 solver identity는 기존 4필드에 `source_bundle`을 추가한다. 구형 4필드 identity는 계속 읽는다. 실제 준비/결과의 runtime 관측에도 descriptor를 남기고 호스트의 봉인과 대조한다. 고정 runtime manifest에 새 descriptor를 포함하므로 새 profile과 구형 전체 bundle은 같은 hash가 될 수 없다.

새 CAD identity에도 `source_bundle`과 `code_files`를 추가한다. 호스트는 실제 entry override를 포함해 현재 closure를 다시 계산하고, worker는 staged `CODE_ROOT`에서 같은 파일 집합을 확인한다. 외부 임시 경로의 시험용 custom entry는 호스트 생성자의 명시 설정으로만 허용하며 API 입력 경로로 실행 대상을 바꿀 수 없다.

구형 inline/새 compact 캡처 작업의 읽기 구조와 runtime 없는 결과 재열기는 유지한다. 과거 source/entry/계획/출처 artifact와 identity를 새 profile로 변환하지 않는다. 대기/중단 연구의 고정 identity와 현재 profile이 다르면 명시적으로 재계획/새 작업을 요구하며 과거 결과 조회는 유지한다. 옛 실행과 새 실행을 같은 환경으로 묶어 재개하지 않는다.

## 5. 검증과 미확립 사항

[검증 기록](../07_검증/15_실행소스_묶음_검증.md)에서 순수 closure/변조/수명 회귀, 실제 격리 OCCT, 실제 WSL openEMS와 후처리, host 회로 계산을 분리한다. 실제 생성/해석 사례의 재료/출처/미정값은 기존 원본과 비교한다.

이 변경은 모듈 포장과 실행 식별 경계의 보강이다. RF 계산식, 독립 물리 참조, 일반 격자 수렴, 제작/실측 정확도 또는 UX 프레임/최고 메모리 수용을 새로 합격 처리하지 않는다. RO4350B 국부 도체 손실 2.788446%/초기 2% 기준 미확립과 GHz PTH 독립 물리 정확도 미확립도 유지한다.
