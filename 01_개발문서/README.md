# TraceWave Studio 문서 안내

2026-11-22 KST. 개발하면서 작성하는 문서와 그림은 모두 `01_개발문서`에서 목적별로 관리한다. 폴더와 파일은 `숫자번호_한글명` 형식을 사용하며 각 폴더에서 01부터 새로 번호를 매긴다. 기존 RFAD 문서, 그림/편집 원본과 기계 판독 JSON도 포함하고 `README.md`만 안내 이름을 유지한다. 문서 안의 안정 식별자는 보존한다. 승인 보관본도 파일명만 정리하며 본문/해시/manifest 기록은 그대로 두고 이전 경로 대응표로 검사한다.

`Code`는 제품 소스, 빌드 설정, 시험, fixtures와 실행/검증 도구의 개발 코드 영역이다. 상세 설계 문서를 두지 않으며, 과거 `Code/runtime_profiles`만 당시 실행 증거를 보존하는 예외로 현재 위치에 유지한다. `00_참고자료`는 레퍼런스 저장소이고 내부 폴더/파일 이름과 내용은 변경하지 않는다. 새 검토/분석 결과는 참고자료 내부 대신 이 개발 문서 영역에 작성한다.

승인 기준선은 RFAD-D0-3.4이며, 아래 현재 문서의 갱신이 원래 승인 범위나 과거 검증 결과를 다시 쓰지 않는다.

현재 작업은 9번 설치 후보의 대역 판정과 13번 내부 후보 인계다. 허용한 RF 편차, 기존 검증을 재사용하는 범위와 환경 보류 항목은 [R1 잔여 작업표](09_개발계획/04_현행버전_남은작업.md)에서 확인한다. 새 작업을 시작할 때는 [개발 인계](09_개발계획/08_새채팅_개발인계.md) 및 [검증 선별 기준](09_개발계획/05_현행버전_검증선별_기준.md)을 따른다.

## 승인 설계와 외부 근거

기존 00~25 문서는 현행 편집본을 분야별로 재배치하고 오래된 상태 설명/중복/구현과 목표의 혼선을 정정했다. [번호별 분류](10_문서목록/04_기존설계분류.md)에서 찾는다. 당시 원문과 records는 [RFAD-D0-3.4 보관함](12_보관이력/01_승인기준선/01_삼점사/README.md)에 별도 보존했으며, 현재 편집본을 새 승인 원문으로 표시하지 않는다. [설계 개요](01_전체_안내.md)는 범위와 규범 소유권을 요약한다.

[00_참고자료](../00_참고자료)는 외부 원문, 수집 목록, 추출값과 기존 검토 기록의 증거 저장소다. 사용자의 최종 지시에 따라 내부 폴더명/파일명/내용은 보존하며 재배치나 정리를 하지 않는다. 원문과 추출본은 목적이 다르므로 내용이 비슷하다는 이유로 삭제하지 않는다. 현재 기능에서 채택한 근거와 실제 납품/제작/측정의 확정은 별개다. [참고 자료 분류](10_문서목록/05_참고자료분류.md)는 개발 문서의 안내 색인이며 참고자료 원본을 변경하는 규칙이 아니다.

과거 [runtime_profiles](../Code/runtime_profiles)는 당시 환경/소스/시험을 식별한다. 현재 문서 위치가 바뀌어도 기록 안의 옛 경로/소스 해시는 그대로 보존하며 [이전 경로 대응](10_문서목록/01_이전경로대응.json)과 당시 Git 개정으로 찾는다. 자동 생성된 [07_검증/01_구현감사](07_검증/01_구현감사/04_기능구현대조.md)는 현재 코드와의 연결 색인이며 전체 수용 합격표가 아니다.
