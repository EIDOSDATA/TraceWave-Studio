# TraceWave Studio 설계 개요

하나의 PCB 설계 개정이 편집기, 도면, CAD 및 전자기 해석의 공통 입력이다. 각 출력은 자신이 사용한 개정과 조건을 기록한다. 이후 설계를 편집해도 과거에 어떤 형상과 재료로 계산했는지 다시 확인할 수 있어야 한다. [제품 재현 안내](03_제품_재현_안내.md)

## 프로그램 구성

| 구성 | 역할 |
| --- | --- |
| Windows Studio | wxWidgets와 wxAUI가 주 창을 구성한다. 2D 캔버스에서 설계 객체를 편집하고 OpenGL 보기에서 CAD 작업자가 만든 표시 메시를 읽는다. [화면과 작업 공간](04_화면설계/README.md) |
| Python 서비스 | 설계 원본, 단위, 명령 이력, 저장 개정, 불변 스냅샷과 비동기 작업을 관리한다. [공통 구현 계약](02_시스템명세/08_공통구현_계약.md) |
| CAD, 출력 및 해석 작업자 | 고정된 입력을 각각 OCCT 형상, 도면 및 제조 파일, openEMS의 입력과 결과로 변환한다. Windows가 기본 해석 환경이며 기존 WSL2 경로는 명시적으로 선택한다. [작업자 경계](03_아키텍처/05_형상과_해석작업_연결경계.md) |
| 출처 및 연구 자료 | 제조사 관측값, 사용자가 채택한 값, 계산 결과와 실측값의 출처를 구분한다. [재료 계약](05_기능설계/03_재료/README.md) [수식과 물리 모델](02_시스템명세/04_수식과_물리_모델.md) |

원호와 평면 IFA가 대표 사례다. 초기 치수 생성, 계산 종료, 격자 수렴, 독립 비교, 목표 충족과 실제 제작은 각각 따로 판정한다. 비평면 3차원 안테나와 Linux 데스크톱은 후속 범위다. 실제 제작과 측정 조건은 대상 시료가 있는 프로젝트에서 정한다. [사례 계약](07_검증/04_사례와_계약.md#ifa-initial-baseline) [모델별 수용 판단](09_개발계획/04_현행버전_남은작업.md)

## 요구부터 검수까지

1. 요구 ID와 AC에서 사용자가 해야 할 일과 판정 조건을 찾는다. 승인 식별자는 요구 141개, AC 404개, UI 24개, FN 46개, API 30개, EQ 41개, VT 30개다. [요구와 승인 원본의 관계](06_분석연구/01_원본_검토와_병합.md)
2. 화면과 기능 계약에서 입력, 표시 상태, 서비스 호출과 실패 후 복구를 찾는다. 원본 A JSON처럼 저장소에 없는 자료는 검증에 필요한 조건으로 명시한다. [화면 설계](04_화면설계/README.md) [기능 설계](05_기능설계/README.md)
3. 해당 개정의 시험과 실행 기록에서 관찰값을 확인한다. 구현 감사는 요구와 코드를 연결하고, R1 작업표가 최종 수용에 필요한 별도 PC 검수를 관리한다. [구현 감사](07_검증/06_승인요구와_구현대조.md) [R1 작업표](09_개발계획/04_현행버전_남은작업.md)

승인 기준 커밋은 `6ebeda156e9d31b893bf69046550f5df9b16dc64`이다. 당시 설계 원문과 변경 기록은 별도로 보존한다. [RFAD-D0-3.4 승인 보관함](12_보관이력/01_승인기준선/01_삼점사/README.md) [전체 문서 안내](README.md)
