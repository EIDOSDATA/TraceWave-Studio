# 고정 설계 보고서와 인계 검증

2026-11-20 KST. 완료 계획 12번의 읽기 전용 인계 프로파일을 검증했다. [기능 계약](../05_기능설계/05_출력교환/06_고정설계_보고서와_인계.md)과 [52번 화면 대응](../04_화면설계/27_보고서와_인계_화면.md)을 기준으로 실행했다.

## Windows Studio에서 확인한 흐름

1. 합성 복소 원문, 이름 있는 테스트 재료와 미정 제작/측정 조건이 있는 별도 프로젝트를 열었다. 출력의 네 번째 탭에서 고정 입력을 선택했다.
2. 원문 반사 자료를 포함에 추가했다. 공유 권한 확인 전에는 검토가 비활성 상태였고 확인 후 인계 범위를 검토했다. 보고서의 5개 근거 중 고정 설계와 복소 파일이 포함 상태였고, 다른 3개는 기록 상태였다.
3. 보고서 미리보기에서 개정과 내용 hash, 제작/실측 미확립을 확인했다. 파일 목록에서 원문, 정규 JSON, HDF5, 설계 사본과 메타데이터를 확인했다. 검토 후 발행하여 작업 영역 밖 새 이름으로 저장했다.
4. 프로젝트를 저장하고 앱을 종료했다. 새 프로세스에서 다시 열고 같은 발행 기록을 선택하여 다른 이름으로 저장했다. 두 사본은 각각 36,625 B이며 SHA256이 일치했다.
5. 종료 후 별도 서비스가 보존한 발행물도 같은 바이트였다. 받는 쪽 ZIP의 모든 파일을 길이와 SHA256으로 확인했고, 스냅샷 바이트와 원문, 재료/목표, 네트워크 기준면과 제작/측정의 미정값, 원래 출처가 저장 설계와 일치했다.

## 자동 시험과 판정 범위

- 고정 개정과 후속 편집의 분리, 원래 접수 키 재시도/영수증, 재시작 후 청크 읽기, 권한 미확인과 검토 hash 변경의 거절을 확인했다.
- 중복 이름, 미등록 항목, 바뀐 바이트와 manifest를 다시 쓴 불일치 보고서의 거절을 분리해 확인했다. 큰 합성 원문은 두 청크에 걸쳐 원래 바이트와 비교했다.
- 초기 시험 오류 응답의 필드명을 정정했다. 강화한 ZIP 검증에서 발견한 파일 SHA256과 버전을 포함한 내용 hash의 차이는 기존 정규화 계약에 맞게 보완한 뒤 다시 실행했다. 각 실행 시점과 로그, 바이너리/화면 해시는 [30번 실행 기록](30_고정설계_보고서와_인계_실행기록.json)에 있다.

발행 형식은 읽기 전용이다. 편집 가능한 프로젝트 복원과 전체 개정/작업 이력의 이전, 전체 UX/성능/복구, EDA/MCP 통합은 12번에 남는다. 이번 자료를 실제 안테나 제작, 납품, 측정 또는 RF 정확도 증거로 승격하지 않는다.
