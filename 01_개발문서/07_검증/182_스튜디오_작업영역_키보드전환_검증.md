# Studio 작업 영역 키보드 전환 검증

2026-11-21 KST. 실제 Windows Studio에서 탐색 트리의 역방향 Tab이 탐색 패널 안에서 순환했다. 상단 작업 버튼은 기존 F6 순환에 들어 있지 않았다. 별도로 작업 버튼에 초점을 둔 뒤 방향키를 누르면 Windows가 초점만 움직이고 선택 화면은 그대로였다. 방향키와 활성 화면을 같은 동작으로 연결하고, 화면 배치 갱신 뒤 작업 버튼에 초점을 복원했다.

| 실제 키 입력 | 화면 또는 초점 확인 |
| --- | --- |
| 탐색에서 Shift+F6 | 현재 작업 버튼인 설계에 초점 |
| 오른쪽 키를 연속 네 번 | 해석 준비, 결과 네트워크, 결과/후보 비교, 기술 도면 차례로 표시 |
| Home | 2D 편집 복귀와 설계 버튼 초점 |
| F6, Shift+F6 | 프로젝트 탐색과 설계 버튼 사이 왕복 |
| End | 기술 도면 표시와 출력 버튼 초점 |

저장한 한글 프로젝트 이름과 2D 객체를 다시 확인했다. Windows 접근성 트리와 실제 가운데 화면을 함께 검사했다. 한/영 키 전환 시도에서는 한글 조합이 확인되지 않았다.

별도 2D 흐름은 키 전환, 도형 편집과 저장·재열기까지 155.77초에 통과했다. 동시 부하에서 시험 전용 종료 시간이 60초인 두 실행은 중간에 끝났고, 전체 기능 검증용 종료 시간을 180초로 사용했다. 프레임, 입력 지연 및 제품 동작의 시간 기준은 성능 설계에서 적용한다. [기존 키보드·결과 표시 검증](152_키보드와_결과표시_접근성_검증.md), [실행 관찰](183_스튜디오_작업영역_키보드전환_실행기록.json)
