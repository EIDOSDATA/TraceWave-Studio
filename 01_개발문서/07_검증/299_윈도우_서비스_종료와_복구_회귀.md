# Windows 서비스 종료 안내와 복구 회귀

2026-11-22 KST. 10번 GUI 회귀 중 Python 서비스 출력이 닫혔다는 보고를 받았고 같은 경로의 재실행은 통과했다. 그 한 차례 종료 원인은 확립하지 못했다. 이후 Windows 파이프 종료 시 운영체제가 프로세스 종료를 확인하고 반환한 코드가 있으면 기존 복구 안내와 함께 기록하도록 보완했다. 파이프만 끊긴 상태에 임의 종료 코드를 붙이지 않는다. 작업 영역의 기존 초기화 오류 안내를 우선한다.

실제 Release GUI에서 초기 응답 전 코드 7로 종료한 자식과 실제 프로토콜 응답 직후 코드 17로 종료한 자식을 각각 구별했다. 별도의 긴 stderr 로그가 프로토콜을 밀어내지 않았으며, 한도를 넘는 서비스 응답은 유한 오류로 끝냈다. 손상 원본 차단과 정확한 사본 복원, writer 충돌 구별, 저장 시 디스크 공간 부족/예약 거절 후 재시도, 공백·한글 경로 저장과 재열기를 확인했다. CAM 전송·적용·되돌리기·다시 실행과 원문 보존도 같은 Release GUI에서 확인했다. 실제 Windows GUI 회귀 10개가 통과했다. [실제 Windows GUI 시험](../../Code/tests/test_gui_process.py)

서비스 저널·편집 ZIP·재현과 원본·과거 결과 조회를 포함한 47개 회귀, CTest 13개와 별도 공식 MCP SDK와 KiCad 10.0.8의 게시/재저장/재수입 1개가 통과했다. [기존 복구와 왕복](272_윈도우_통합복구와_인계_재검증.md)

프레임 최적화의 개발 작업을 종료했다. 개발 PC의 마지막 계측은 이전 결과를 적용한다. 기준 PC의 공식 F0~F5, 서로 다른 재부팅 직후의 F0 5회, 실제 한글 IME 조합, 스크린리더 발화, 혼합 DPI는 별도 환경이 준비될 때 재개한다. 물리 전원 차단 복구 보장은 격리 환경의 조건이다. [표와 2D 계측 기록](291_드래그_부분갱신과_표_지연_검증.md) [검수 환경](285_윈도우_로컬휠_수신과_알원_인계.md)
