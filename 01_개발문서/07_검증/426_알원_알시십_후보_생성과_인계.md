## 빌드와 수신 검증

- Windows 11 Pro x64 빌드 26300에서 CMake 4.3.2, Ninja 1.13.2와 MinGW-w64 GCC 16.1.0으로 별도 Release 빌드 폴더를 만들었다. wxWidgets 3.2.12는 해시를 대조한 원본 압축에서 새로 풀었다. 고정 JSON 헤더, WinLibs DLL과 배포 고지의 해시도 대조했다. CTest 14건, Windows ZIP과 제거기 단위 시험 6건을 통과했다.
- 후보 ZIP의 개정과 manifest에 열거된 파일 1,191개를 검사했다. Windows 개발 PC의 새 경로에 ZIP을 풀고 고정 WinLibs 런타임을 연결했다. 선택형 worker 없이 CPython 3.12.10에서 실제 GUI로 캔버스를 편집하고 저장한 뒤 새 서비스 세션에서 같은 개정을 다시 열었다.

## 개발 PC 설치 사전 검수

- 기존 설치와 별도인 `%LOCALAPPDATA%\TW10-DevAudit`를 사용했다. 기존 시작 메뉴 바로 가기를 유지하기 위해 이 시험에서는 시작 메뉴 등록과 설치 직후 자동 실행을 생략했다. 설치는 Windows openEMS 기본 경로를 사용했다. CPython, WinLibs와 openEMS의 원 공급처 자산은 검증된 캐시 사본을 사용했고 Python 패키지는 이 PC의 다운로드 캐시를 사용했다. 클린 Windows PC의 신규 다운로드와 기본 시작 메뉴 등록은 독립 검수에서 확인한다.
- 다른 프로세스가 Setup.lock을 잡은 상태에서 같은 Setup.exe를 실행했다. 안내 메시지와 종료 코드 2를 확인했고 설치 상태 파일이 생기지 않았다. 잠금을 해제해 설치를 재시도했다.
- 설치 상태에 소스 개정, `windows_ready=true`, `simulation=ready`, `solver_platform=windows`가 기록됐다. openEMS 0.37.0 및 CSXCAD 0.7.0의 Windows native 감사를 통과했다. 설치 GUI의 SHA-256은 Release 빌드와 같았다. Windows 앱 등록의 버전은 R1 RC10이고 아이콘은 이 실행 파일을 참조했다.
- 설치 GUI와 해당 설치가 구성한 worker로 4건을 통과했다. 원형 PCB의 31주파수 설정 해석을 완료하고 두 번째 실행을 취소해 계산 종료와 첫 결과 재열기를 확인했다. PDF 생성 및 재검수에서는 실행 취소와 이미 게시한 원문의 보존을 검사했다. RF 결과 시험에서는 이전 원본 비교, Smith 표시, 내보내기, 다시 열기 전후의 원문 보존을 확인했다.
- RC10의 등록된 무인 제거 경로로 검증용 설치를 제거했다. 앱 등록, Versions, CPython과 설치 캐시가 정리됐고 수신 시험에서 만든 저장 작업 사본의 파일 83개는 제거 전후 SHA-256이 모두 같았다. 개발 PC의 기존 기본 경로 설치와 이 시험용 경로를 분리했다.

## 독립 PC에 전달할 파일

`r1-rc10` 태그의 GitHub 프리릴리스에서 Setup.exe와 해당 `.sha256`을 받는다. 태그가 위 소스 개정을 가리키는지 확인했다. 공개 링크로 다시 받은 설치 파일과 해시를 고정값에 대조했다. 개발 PC의 인계 폴더에는 검수 안내와 후보 ZIP도 보관했다. [RC10 다운로드](https://github.com/EIDOSDATA/TraceWave-Studio/releases/tag/r1-rc10) 별도 온라인 클린 Windows 11 x64 PC에서 이 Setup.exe의 SHA-256을 대조한 뒤 기본 설치를 시작한다. 시작 메뉴와 제목 표시줄 아이콘, 설치 후 실제 해석 및 취소, 저장과 복구, 결과 화면 첫 진입과 반복 전환, 표준 제거와 재설치를 확인한다. R1 최종 수용은 독립 PC의 검수 결과로 판단한다. [독립 PC 검수 절차](../08_운영환경/05_윈도우_내부검증_배포.md#별도-클린-windows-pc-온라인-검수), [R1 작업표](../09_개발계획/04_현행버전_남은작업.md)

별도 검수 PC에서 실행한 결과는 [427 독립 수신 검수](427_알원_알시십_클린피시_수신과_수용.md)에 기록했다.
