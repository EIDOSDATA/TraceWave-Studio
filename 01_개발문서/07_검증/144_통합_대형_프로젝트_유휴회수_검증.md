# 통합 대형 프로젝트의 Windows 유휴 회수

2026-11-21 KST. 동일 Windows Studio와 프로젝트 서비스에서 형상 10000개와 매개변수 1000개, 표시 삼각형 100만 개, 1 GiB 필드의 단면 10개와 복소 곡선 8개를 확인했다. 대기 프로젝트 전환 후 150초를 넘겨 자원을 계측했고 같은 과정으로 30회를 마쳤다. 작업 영역과 결과 원문을 검사용으로 분리했다.

| 관찰 범위 | 결과 |
| --- | --- |
| 대기 상태 기준 private commit | 104.76 MiB |
| 열려 있을 때 private commit 관찰 최대 | 935.98 MiB |
| 초기 5회 대기 private commit 중앙값 | 494.77 MiB |
| 마지막 10회 대기 private commit 중앙값 | 699.31 MiB |
| 대기 중앙값 증가 | 204.53 MiB |
| Studio 핸들 | 첫 332개, 마지막 387개, 최대 392개 |
| DXGI local 최대 | 열린 상태 159.58 MiB, 대기 상태 23.99 MiB |
| DXGI nonlocal 최대 | 열기와 대기 모두 0바이트 |

30회 모두 대형 장면과 OpenGL 문맥을 대기 상태에서 회수했다. Studio와 서비스의 private commit 증가 204.53 MiB는 32 MiB 기준을 초과했다. 후반에는 서비스가 약 443~444 MiB로 안정됐으며, 증가분은 주로 Studio에서 발생했다. 일부 회차에서 Studio의 대기 사용량이 크게 낮아진 뒤 다시 증가했다. 할당과 회수가 섞인 상태에서 모듈별 원인을 추가로 확인해야 한다.

이 실행에는 Windows 작업 영역 서비스의 OpenBLAS 기본 동시 실행 수 조정 전의 소스를 사용했다. 먼저 시도한 별도의 30초 유지 시험은 26회 뒤 OpenGL 문맥 유지 조건과 일치하지 않아 끝냈다. 두 시험을 합치거나 26회를 정식 30회 표본으로 사용하지 않았다. [통합 유휴 및 중단 실행 기록](145_통합_대형_프로젝트_유휴회수_실행기록.json)
