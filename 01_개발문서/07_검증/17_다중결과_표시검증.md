# 다중 결과와 방사/필드 표시 검증

기록일: 2026-11-17 KST. 완료 계획 7번의 검증 기록이다. 기준 구현은 `3e3121e37f42886a72d0e30c81859a17fea2b75f`이며 기능 변경은 이 기록에 연결한 작업 트리에서 검사한다. 승인 기준선 RFAD-D0-3.4, 원문 참고자료, 과거 runtime profile과 승인 보관본은 유지한다.

최종 Windows 직접 조작과 저장/재열기를 확인했다. 아래 실행 시점별 시험과 수용 경계를 구분하며 기능 구현을 전체 R1 수용으로 표시하지 않는다. 실행별 로그, 바이너리, 원본/조건 대조와 캡처 해시는 [기계 기록](18_다중결과_표시_실행기록.json)에 보존한다.

## 1. 기능 범위

[기능 계약](../05_기능설계/04_해석결과/07_다중결과와_방사표시.md)과 [화면 계약](../04_화면설계/21_다중결과와_방사필드_화면.md)에 source/pin 고정, 과거 개정/해석/후보 조회, 복소 표본/Smith/다중 비교, 전력/효율, 2D/3D 방사와 편파, 기록 필드 및 과거 결과 내보내기를 연결했다. 기존 가져오기/RLC/목표 평가/수렴 연구를 재사용한다.

원본에 없는 주파수, 효율, 필드나 과거 계산 격자를 만들지 않는다. 비교는 명시 포트/같은 수학 기저의 정확 공통 주파수만 사용하며 물리 조건 차이와 수학적 비교 가능성을 별도로 표시한다. GUI 선택과 조회는 프로젝트 원본이나 저장된 평가를 바꾸지 않는다.

## 2. 실제 보존 산출물 대조

기존 PCB 전력 수지 검증 workspace를 별도 시험 workspace에 복사하고 원래 workspace는 읽기 전용으로 보전했다. 실제 단일 포트 결과의 2.4/2.44175/2.4835 GHz, 주파수별 theta 37 x phi 72 표본을 공개 RPC로 읽었다. 방사 응답은 주파수별 19페이지이며 복소 Etheta/Ephi는 원문 배열과 일치했다. 전력 3행, Smith 201점, CSV 10,225바이트와 조건 sidecar를 확인했다.

CAD/openEMS 실행 환경 없이 서비스를 재시작한 뒤 같은 source/pin과 원본 개정/hash를 다시 확인했다. 제작/측정 조건은 null이며 조회 전후 journal과 프로젝트 문서는 같다. 원래 검증 workspace의 current/state 및 선택 산출물 해시도 같다. 새 FDTD 계산이나 독립 물리 검증은 수행하지 않았다.

필드는 실제 E/J/rotH, x/y/z 성분과 세 수직 단면의 27개 조합을 원본 HDF5 hyperslab과 대조했다. 같은 열린 파일을 스트리밍 해시 검사한 뒤 필요한 배열만 읽었다. 원래 normalized의 실제 전체 격자선으로 Yee 성분 위치를 구하고, 격자 없는 과거 자료는 명시 미지원으로 처리했다. 원문 격자를 현재 생성기로 재계산하지 않았다.

## 3. 편파 정의와 수치 정밀도

설치된 openEMS 0.37.0 nf2ff.py의 RHCP/LHCP 정의와 보존된 native HDF5를 대조했다. 3개 주파수의 양 원편파 총 15,984개 복소값을 검사했다. 원문 phi의 float32 sin/cos와 원래 요청 degree를 사용한 double 계산 사이의 반올림 차이를 분리했다.

최초 직접 상대 오차 1e-12 비교는 이 각도 정밀도 차이로 실패했다. native의 float32 회전을 해제하고 원래 degree로 다시 회전한 비교에서는 해당 허용 오차를 충족했다. 원래 복소 Etheta/Ephi는 그대로이며 최대 원편파 복소 차이는 6.438560081239292e-20 V*s/m, 각도 효과의 최대 상대값은 2.2841811565137407e-7, 각도 정밀도를 일치시킨 최대 차이는 1.262177448353619e-28이었다. 이 대조는 같은 원문에 대한 판독/표시 정의 확인이며 독립 방사 물리 정확도 시험이 아니다.

축비의 원형/타원형/직선 무한대/영전계 미정의와 작은 수치 스케일, 방향별 이득의 전력 비율, dB 바닥과 실제 0 상태를 별도 시험했다. 반사/손실의 음수, 효율 100% 초과와 잔차를 잘라 숨기지 않는다.

## 4. Windows와 회귀 시점

첫 통합 Windows 실행 파일 SHA256은 `a30f4b44883c471cd67f9457473cc7854074788c8228902c662cb36a2333ea58`이다. CTest 10개와 전용 결과 GUI 1시험의 9개 상태 검사가 통과했다. GUI 시험은 서비스 재시작 2회, 과거 개정/미정 원문, Smith 개방/단락/능동 표본, 정확 마커/명시 비교, CSV/조건 파일, 원본 보전과 설계 화면 복귀를 포함했다. 이 빌드는 이후 비교 행 선택의 오른쪽 조건 동기화 보완 전이다.

비교 행과 오른쪽 조건의 선택 동기화 보완 빌드 `2a5101b4...`에서 전용 GUI 10개 상태 검사, 오른쪽 세 접기 그룹/필드 조회 버튼 고정/Smith 격자/정확 반대 phi 절단면 보완 빌드 `93b7ccfd...`에서 CTest 10개가 통과했다. 최종 시각 검토 빌드 `3833cf41d7a0736ad2843945f8f5161f676c89652276e3212c785473ef4efcac`는 긴 원본 이름과 고정 페이지 제목을 분리하고 비교 조건의 이전/다음 32개 페이지를 연결했다. CTest 10개는 0.54초에 통과했다.

최초 전체 서비스 회귀는 1,132개 중 1,033개 통과, 98개 환경 조건 제외, 1개 실패, 849.038초였다. 실패 지점은 종료 동작을 시작하기 전 `transport.started.wait(3.0)`이며 실제 의존 소스 준비가 포함된 시작 대기였다. 같은 시험을 따로 실행했을 때 준비 2.204초와 준비 후 종료 0.031초를 확인했다. 실제 소스 준비/봉인을 시험 본문에서 먼저 수행하고 동일 job/run/nonce/plan을 검증한 뒤 실제 조정기 스레드에 전달하도록 시험만 보강했다. 기존 시작/종료 제한 시간과 종료 판정은 유지했다. 제품 실행/종료 코드는 바꾸지 않았다. 이후 관련 source/staging/solver 58개는 171.915초에 모두 통과했다.

전체 서비스 재실행은 1,132개 중 1,034개 통과, 98개 환경 조건 제외, 실패 0개, 887.196초다. 중복 시험을 합산하지 않는다. 전체 서비스 수집 후 추가한 40개 조건의 32개/나머지 페이지 시험은 별도 1개, 2.620초 통과로 구분한다. 원문 조건의 null, 총수, 원본 파일/개정 불변도 검사했다.

전체 Windows GUI 회귀는 29개 중 26개 통과, 1개 실패, 실제 WSL 계산 2개 제외, 638.028초다. 실제 OCCT GUI 2개와 새 결과의 12개 상태 검사/서비스 재시작 2회를 포함한다. 29개 수집 중 1개는 같은 모듈의 별도 조건 페이지 서비스 시험이며 GUI 창 시험과 구분한다. 실패한 문헌 초기식 시험은 상단 결과/비교의 옛 기본 페이지 6/4를 기대했다. 실제 제품의 새 기본 9/14와 기존 자료/정합 6, 수렴 연구 4의 접근 보존을 함께 검사하도록 시험 코드만 보강했다. 해당 1개/8개 상태 검사가 22.004초에 통과했다. 27개 검증 대상이 각각 통과했지만 이를 한 번의 전체 무실패 실행으로 적지 않는다.

시험 코드만 재링크한 최종 실행 파일은 `43b36d6e8c86ad2503e8fa137bd69cfce92e7610c1317e2d4fb0fa859449ce14`다. 제품 C++ 화면 동작은 시각 검토한 `3833cf41...` 이후 바뀌지 않았다.

이후 독립 수치 검토에서 작은 타원의 유한 축비가 두 원형 진폭의 소거로 무한대로 분류되는 경우와 총 효율/백분율 overflow를 발견했다. 축비는 원본 float의 정확한 행렬식과 큰 특이값으로 계산하여 유한 1e20, ulp 인접 벡터, 실제 직선, 정규화 underflow와 표현 범위 초과를 구분한다. 효율 원본은 유지하며 새 파생값의 표현 범위만 null/overflow로 표시한다. 최종 수치 경계 및 방사 시험 18개가 1.357초에 통과했다. 두 Python 모듈 보강 뒤 공통 서비스 호환 21개 중 20개 통과/실제 과거 workspace 환경 제외 1개, 28.766초를 별도로 확인했다. 실제 보존 자료의 공개 RPC 대조도 다시 통과했다(주파수별 19페이지, 전력 3행, Smith 201점, CSV 10,225바이트와 runtime 없는 재열기). 전체 서비스/GUI 회귀는 이 마지막 두 수치 경계 보강 전의 수집 및 실행이다.

호환 집중 시험의 첫 실행 중 축비 소스가 바뀌어 연구 정의/실행의 source identity 불일치 E_CONFLICT 1개가 발생했다. 이는 원래 변경 감지이며 제품 소스를 동결한 후 동일 시험을 재실행하여 위 결과를 얻었다. 최초 21개 실행의 19개 통과/1개 오류/1개 환경 제외, 30.875초 기록도 보존한다.

최초 통합 중 기존 프로세스에 구버전 resolver가 로딩된 상태에서 export 모듈이 수정되어 `numerical_details` KeyError가 발생했다. 제품 소스를 동결하고 새 프로세스로 같은 공개 RPC 경로를 다시 검사하여 통과했다. 해당 초기 실패를 최종 성공으로 덮어쓰지 않는다.

## 5. 실제 Windows 저장/재열기와 화면

격리 복사한 기존 JLC RO4350B 30 mil 탐색용 IFA 프로젝트를 시각 검토 빌드 `3833cf41...`로 열었다. 네트워크의 GHz 축/201개 실제 S11 표본, Smith 격자와 입력 임피던스, 세 주파수의 전력/효율, 기록 phi 0/180 deg의 전체 절단면, OpenGL 3D 회전, 편파 원문 표, Ex의 z=0.416 mm/32 x 32 실제 ROI와 마커를 확인했다. 두 실제 결과의 명시 포트 대응과 정확 공통 주파수 차이, 18개 물리/수학 조건도 화면에서 조회했다. 조건 32개 초과와 늦은 응답 폐기는 별도 GUI 회귀의 합성 자료로 검사한다.

Ctrl+S 후 저장됨 표시를 확인하고 종료한 뒤 CAD/openEMS 없이 서비스로 다시 읽었다. 프로젝트 내용 hash `8f01aad8901c8eb83843e3484590daff5e673e47891f134e8e97f2ab475724f6`, source/pin, 제작/측정 null, 기존 원본 workspace와 복사한 해석 산출물 해시가 그대로였다. 다시 같은 Windows 실행 파일로 열어 설계/객체/미정 설명을 확인하고 닫았다.

[실행 화면 23~32](02_실행화면/README.md)는 이 흐름의 캡처 원본이다. 23은 `93b7ccfd...`의 중간 재열기이고 24~32는 최종 시각 검토 빌드 `3833cf41...`이다. 2.4 GHz의 방사 효율 98.79385%, 총 효율 53.900538%와 해당 S11은 이 탐색 모델의 계산값이다. 사용자가 목표로 하는 대역의 설계 합격이나 실측 성능으로 표시하지 않았다.

## 6. 수용 경계

- RO4350B 국부 방사 도체 손실 변화 2.788446%는 초기 2% 기준 미확립을 유지한다.
- GHz PTH의 독립 물리 정확도는 미확립이며 전력 수지나 종료 조건 통과로 대신하지 않는다.
- 실제 제작/납품 물성/급전 실장/시료/교정/측정 조건을 확정하지 않았다.
- 실제 보존 결과 읽기와 새 방사·편파·필드 표시를 3차원 안테나 원본 모델링/해석 지원으로 확대하지 않는다.
- 84개 화면 전체, 모든 DPI/접근성/복구, 60/30 fps와 전체 메모리 수용은 별도 12번 검증이다.
- 원문 로그와 격리 workspace는 Code/.local의 비추적 실행 자료이며 제품 코드와 의미 시험은 저장소에서 재현할 수 있게 유지한다.
