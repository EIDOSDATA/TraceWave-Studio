# 출력 화면의 제조 교환 후보 검증

2026-11-23 / Windows / KiCad 10.0.8 / EDA15, EDA16

## 사용 순서

1. 출력 작업 화면에서 내보낼 개정의 스냅샷을 선택한다. PCB/CAM의 KiCad 보드에서 포함 범위를 검토한 뒤 패키지를 생성한다.
2. 출력 이력에서 완료된 KiCad 보드 기록을 선택하고 "IPC-2581C / ODB++ 내보내기"를 누른다.
3. IPC-2581C, ODB++, 두 가지 모두 중 하나를 선택한다. 설치된 KiCad의 kicad-cli.exe와 작업 영역 밖의 새 ZIP 파일 경로를 지정한다.
4. 변환이 끝나면 화면에 저장된 ZIP 경로가 표시된다. 파일 안에서 board.xml 또는 board-odb.zip, source 하위의 원본 보드/설정/검증 자료와 report.json을 확인한다.

## 기록과 파일

출력은 현재 편집 상태가 바뀌어도 선택한 기록의 manifest SHA-256을 다시 확인한다. 게시한 보드, KiCad 설정, 원본 sidecar, 검증 보고서와 manifest를 ZIP에 바이트 그대로 보존한다. report.json에는 사용한 KiCad 버전, 원래 스냅샷과 실행 ID, 제조 파일별 해시 및 제조 형식 판독 결과가 기록된다.

원본이 변경됐거나 후보를 기존 파일명으로 저장하면 변환기는 오류 이유를 반환한다. 임시 폴더에서 모든 파일을 만든 뒤 같은 파일시스템에서 새 ZIP 이름으로 게시한다. 동시 실행이 먼저 만든 파일도 보존한다. 실물 제작 조건과 수신 회사의 DFM 승인은 별도로 남는다.

## Windows 프로그램 검증

- Release 빌드에서 게시한 KiCad 보드 기록을 열고 제조 내보내기 버튼과 실제 형식/설치 파일/대상 ZIP 대화상자를 거쳐 IPC-2581C 및 ODB++를 함께 내보냈다. GUI가 성공을 표시한 뒤 두 파일을 다시 읽어 IPC 설계 단계와 ODB++의 EDA 자료가 있는 단계를 확인했고, 입력과 원본 이력의 모든 바이트가 보존됐다. 기존 ZIP, 잘못된 manifest SHA-256 및 게시 폴더 안 출력도 차단했다.
- 첫 Windows 실행은 서비스가 WMI에서 0xC0000005로 종료해 게시 기록 조회 단계에서 멈췄다. WMI 호출을 제거한 서비스로 같은 Release 실행 파일과 같은 시험을 다시 실행해 250.692초에 통과했다.
