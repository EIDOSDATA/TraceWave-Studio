# Windows 시작과 출처 탐색 검증

2026-11-20 KST. 완료 계획 12번 F0에서 Windows의 같은 Release EXE를 사용했다. 두 서비스 소스를 교대로 실행하고 각 조건의 준비 실행 1회와 본 표본 20회를 수집했다. 144 DPI, 2468 x 1316 client 영역에서 첫 2D canvas paint와 서비스가 새 프로젝트 편집을 준비한 시점을 같은 Windows 성능 카운터로 기록했다.

측정 후보 생성, 정렬 명세 검증과 Smith 변환의 의존 모듈은 해당 기능을 호출할 때 불러온다. 계산 근거를 봉인할 때는 같은 캡처 내부에서 모듈 경로 선택을 재사용한다. 캡처 마지막에 처음 없었던 이름을 포함해 모든 경로를 다시 해석한다. 경로가 달라지거나 모듈과 동명 패키지가 생기면 캡처를 거절한다. 두 번의 독립 캡처와 파일 내용, 링크 유형, 사용한 경로의 검사는 계속 수행한다.

같은 입력 소스를 두 경로 탐색 구현으로 각 6회 처리했다. 두 host 프로필의 파일 수, 봉인 소스 바이트, SHA256 및 descriptor가 모든 비교에서 일치했다. 경로 탐색 호출 수는 5345회에서 1710회로 줄었다. Windows의 Smith 비교, 과거 결과 내보내기, 저장 후 재열기를 개선 후보로 수행했다. 두 시작 항목의 p95는 목표를 초과했고 재부팅 직후 표본은 이번 검증에서 수집하지 않았다. [원시 표본](83_윈도우_시작과_출처탐색_실행기록.json)

이 변경 반영 전 전체 서비스 회귀 1415개에서 1268개가 통과했고 환경 조건으로 142개가 제외됐다. 프로세스 응답 8초 제한을 넘은 4개는 컴파일과 분리한 재실행에서 통과했다. 나머지 1개는 분리된 계산 coordinator가 프로젝트 IO 스레드를 직접 소유한다고 가정한 시험을 고쳤다. 실제 프로젝트 IO 스레드가 종료되고 writer 잠금이 반환됨을 다시 확인했다. 전체 수집과 실패 항목 재실행은 각각 기록했다.
