# Studio의 보존 묶음 복원 검증

2026-11-20 KST. [CLI에서 확인한 편집 복원](31_프로젝트_편집복원_검증.md)을 [Studio의 파일 선택과 검토 흐름](../04_화면설계/28_보존묶음_복원_화면.md)에서 직접 검사했다.

1. 프로젝트가 없는 새 작업 영역에서 **파일 > 프로젝트 보존 묶음 복원**을 열었다. 앞 단계에서 받은 읽기 전용 보고서 ZIP을 선택하자 적용이 비활성 상태로 유지됐다. [읽기 전용 차단](02_실행화면/79_읽기전용_묶음복원차단.jpg)
2. 같은 창에서 편집 복원 ZIP을 선택했다. 1,503,930 B 원문을 128 KiB 단위의 12개 청크로 받아 검토했다. 보존 저장본, 가져올 개정, 파일 8개, 명령 1개, 스냅샷 2개, 원본에서 보존되지 않은 상위 개정 1개와 제작/실측 미확립을 확인했다. [비교 표](02_실행화면/80_복원_보존개정과_누락검토.jpg)
3. 검토한 프로젝트 복원을 실행했다. 등록 완료 직후에도 프로젝트가 열리지 않았다. 사용자가 **복원 프로젝트 열기**를 선택했을 때 설계 작업 공간으로 이동했다. [등록 완료](02_실행화면/81_스튜디오_복원등록완료.jpg)
4. 복원된 설계에서 이름만 변경해 저장하고 종료했다. 같은 작업 영역을 다시 열어 새 이름과 저장 상태를 확인했다. [저장](02_실행화면/82_직접복원_프로젝트편집저장.jpg), [재열기](02_실행화면/83_직접복원_저장개정재열기.jpg)

두 작업 영역을 닫은 뒤 실제 원본 자료를 대조했다. 기존 프로젝트의 현재 개정과 스냅샷, 합성 네트워크 원문의 바이트, 출처와 미정값이 유지됐다. 받는 쪽에는 예약과 등록에 각각 요청 영수증이 있었고, 계산 이전이나 자동 실행은 없었다.

초기 RPC 시험에서 접수/등록 경로가 기능 공지에만 등록된 상태를 발견했다. 요청 검증 목록을 연결한 뒤 최종 10개 서비스 회귀를 통과했다. 청크 재전송, 수신 범위, 검토 전 적용 거절, 영수증 재조회 및 서비스 재시작은 자동 시험에 포함했다. [실행 기록](34_스튜디오_보존묶음복원_실행기록.json)에 실행별 결과와 화면/ZIP 해시가 있다.

이 기록은 복원용 ZIP의 수신, 등록과 기존 편집 기능을 검증한다. 전체 UX/성능, EDA/MCP 수용, 외부 worker 결과 이전은 12번에 남아 있다.
