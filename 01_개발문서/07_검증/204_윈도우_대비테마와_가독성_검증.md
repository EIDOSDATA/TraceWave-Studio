# Windows 대비 테마 전환과 가독성 검증

2026-11-21 KST. Windows 11의 접근성 설정에서 대비 테마를 없음에서 밤하늘로 전환하고 Studio를 열었다. 기존 빌드에서는 일부 도킹 제목이 어두운 배경에서 흐렸고 출력 확인 창의 읽기 전용 본문은 배경과 글자가 둘 다 밝았다.

Studio가 색을 지정하는 제목, 읽기 전용 본문, 트리, 목록, 탭, 검색 상자의 시스템 색 전환을 연결했다. 탐색 아이콘도 현재 테마에서 다시 만들고, Windows 레이어 체크 목록은 항목 색을 함께 갱신했다.

| 실제 Windows 검증 | 관찰 |
| --- | --- |
| 대비 테마를 활성화한 뒤 Studio 열기 | 도킹 제목, 탐색 아이콘과 글자, 두 레이어 행이 읽혔다. |
| 저장된 결과와 출력 확인 열기 | 201개 표본의 S11 곡선과 GHz 축을 읽을 수 있었고, 출력 근거 및 미정 조건 본문이 밝은 글자와 어두운 배경으로 표시됐다. 두 화면은 목록 행과 탭 복원 수정 직전의 빌드에서 관찰했다. |
| Studio를 열어 둔 채 대비 테마 끄기 | 최종 빌드에서 탐색 탭, 검색, 속성 및 레이어 행이 일반 테마로 돌아왔다. |
| 운영체제 화면 복원 | 원래 2560 x 1600, 배율 150%, 대비 테마 없음과 일치했다. |

최종 Release에서 2D 편집·재열기, 서비스 연결과 시작 지표, 출력 원문 보존, 실제 기록 필드 재열기, 과거 복소 결과·미정 조건의 Windows 회귀 7개가 모두 통과했다. Release CTest 13개도 통과했다. 밤하늘 팔레트의 관찰 범위이며 밝은 대비 테마, 한글 IME 조합, 화면 낭독, 모니터 간 DPI 이동은 별도 검수가 필요하다. [실행 기록](205_윈도우_대비테마와_가독성_실행기록.json), [키보드 출력](200_기술도면_키보드생성_검증.md)
