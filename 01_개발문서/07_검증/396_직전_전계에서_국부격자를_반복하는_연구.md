# 396. 직전 전계에서 국부 격자를 다시 결정하는 연구

## 사용자 경로

결과 화면의 필드 탭에서 실제 기록한 전기장 주파수와 Ex, Ey, Ez 중 한 성분, 단면과 영역을 고른다. 최소 복소 변화, 회차마다 추가할 규칙 수, 예상 메모리, 최대 반복 횟수, 공통 주파수에서 허용하는 복소 S11 차이를 입력하고 `이 단면으로 적응 격자 연구 실행`을 누른다. 프로젝트 연구의 진행 화면에서 원본 개정, 각 격자, 최대 변화와 해당 주파수, 종료 이유를 확인한다. `두 격자의 주파수별 포트 변화`에서는 선택한 인접 회차의 주파수, 복소 S11 차이 크기, 복소 임피던스 차이 크기와 허용값 이내 여부를 확인한다.

`python -m rfad field-study --help`에서 동일한 Windows 서비스의 명령행 인수를 확인할 수 있다. 다음 명령은 실제 원호 검수와 같은 조건을 사용한다. 작업 영역과 식별자는 사용자 프로젝트의 값으로 지정한다.

```text
python -m rfad field-study --workspace WORKSPACE --project PROJECT_ID --artifact RESULT_ID --monitor probe_electric --component x --frequency-index 0 --normal z --index 0 --roi 0 9 0 9 --threshold 0.01 --max-rules 2 --memory-mib 512 --rounds 2 --tolerance 1e-8
python -m rfad field-study --workspace WORKSPACE --project PROJECT_ID --resume STUDY_ID
```

## 자료와 판정

- 원래 관찰 영역은 선택 성분의 실제 Yee 좌표(mm)와 기록 주파수(Hz)로 고정한다. 후속 격자에서는 같은 물리 범위 안의 표본과 가장 가까운 기록 단면을 찾아 실제 사용한 좌표를 저장한다. 최대 4,096점 안에서 모든 이웃의 복소 전계 차이를 검사한다.
- 매번 직전 해석의 봉인 HDF5에서 최대 성분 크기 대비 복소 변화가 큰 구간을 찾는다. 문서 375의 실제 격자 생성기로 기존 규칙을 유지하고 선택한 셀을 절반 폭으로 분할한다. 사용자 메모리, 회차당 규칙 수, 전체 16개 국부 규칙, 격자 및 필드 표본 상한을 확인한 뒤에만 다음 해석을 접수한다. 원문 필드 참조, 실제 ROI, 새 규칙, 선택 점수, 전후 격자 해시, 계획과 결과 식별자를 봉인한다.
- 389의 공통 주파수 비교를 사용한다. 같은 원본 스냅샷, 재료, 급전, 정규화, 물리 설정과 고정 및 실제 worker에서 각 주파수의 `abs(S11_new - S11_previous)`를 계산한다. 원래 결과의 worker가 바뀌면 처음 한 번은 같은 조건의 기준 격자를 다시 푼다. 후속 결과의 실제 격자 해시가 제안 격자와 다르면 판정을 차단한다.
- 한 급전의 선택 전계로 격자를 고르고 모든 공통 주파수의 S11 차이가 허용값 이내일 때 연구를 종료한다. 횟수 소진, 메모리 초과, 규칙 상한, 자원 상한, 적격 구간 없음, 격자 불변을 따로 보존한다. 현재 개정이나 기존 결과를 수정하지 않는다. 전체 모드의 연속체 해 오차, 실물 정밀도, 제작 및 측정 조건은 미정이다.

## 원호의 실제 Windows 및 WSL2 해석

`Code/tools/verify_arc_field_study.py`로 빈 작업 영역에 명시적 시험 물성의 원호 PCB를 만들었다. 원호가 있는 원 개정은 `643b96f6-0168-4d19-a50e-5e8170d689b4`, 연구는 `89246978-d2e3-44b4-91c1-01c71df73a7e`다. 10 GHz Ex, z = 0.5 mm, x = 2.25 ~ 6.25 mm, y = 0 ~ 4 mm 단면에 변화 기준 0.01과 회차당 2개 규칙을 적용했다. 8 ~ 12 GHz의 실제 S11 표본 31개로 비교했다.

| 격자 | 실제 점 수 | 실제 시간 단계 | 다음 격자에 반영한 구간 | 이전 결과와 최대 복소 S11 차이 |
| --- | ---: | ---: | --- | ---: |
| 기준 | 78,204 | 1,085 | X 23, 24 | 해당 없음 |
| 1회 | 80,948 | 1,519 | X 16, 17 | 0.000432992420 |
| 2회 | 83,692 | 1,519 | 종료 | 0.000213739058 |

서로 다른 두 실제 HDF5 전계의 SHA-256은 `f184744b711dc9e9d0bcf0612b3be695441331f06fe567035d8e600b4cffa0d5`, `9cca8ba847409bd3c1b149aeb227668d369cf1b708947416ea043f4c941417f3`였다. 각 쌍의 최대값은 8 GHz였다. 의도적으로 작은 시험 허용값 1e-8에서 두 쌍 모두 31개 중 0개가 기준 이내여서 2회 횟수 소진으로 종료했다. 작업공간을 재열어 두 원문에서 다시 선정한 격자 해시와 62개 표본별 변화값이 봉인 결과와 일치했다.

같은 원호 원본에서 예상 139.93 MiB인 기준 격자에 128 MiB를 지정하자 공개 API가 E_RESOURCE로 거절했고 등록 연구 수가 같았다. 상한만 512 MiB로 바꾸자 연구를 생성했다. 기존 완료 연구는 Windows 명령행의 `--resume`으로 다시 열어 두 쌍의 62개 표본을 조회했다.

## Windows 실행과 IFA 기록

Windows Release의 실제 결과 목록에서 원호의 첫 해석을 선택하고 필드 탭에서 10 GHz Ex의 9 x 9 전계 표본을 조회했다. 5% 전계 변화, 회차당 2개 규칙, 예상 메모리 2048 MiB, 최대 2회, 복소 S11 허용차 0.02를 사용했다. 실행 단추에서 연구 `cd44e8e9-a13a-4aa6-90d7-148460d4a1d7`를 생성하고 해당 연구 진행 창을 열었다. 이 연구는 수치 worker가 달라 기준 격자를 새로 풀었다. 실제 78,204점(1,085단계)과 80,948점(1,519단계)에서 8 ~ 12 GHz의 31개 표본이 모두 허용값 이내였다. 최대 차이 0.000432992420는 8 GHz였다. 최종 상태는 `stability_reached`이며 두 결과와 31개 표본 증거가 별도로 봉인됐다.

독립 원호 연구의 실제 Windows 진행 화면에는 3개 완료 결과, 선택 주파수와 성분, 회차마다 증가한 규칙 수와 두 쌍의 최대 변화가 표시됐다. 각 회차의 실제 격자점 열을 추가하고 완료 연구의 자동 조회를 멈춰 저장 자료를 읽을 때 선택 단추가 주기적으로 꺼지지 않게 했다. 좁은 필드 패널에서 숫자와 화살표까지 보이도록 반복 입력의 레이블과 값을 위아래로 배치했다. [원호 연구의 Windows 화면](02_실행화면/105_직전_전계에_따른_원호_격자연구.png)

최종 Windows 빌드에서 보존 원호의 81개 복소 표본을 다시 조회했다. 같은 창에서 다섯 입력값 5%, 규칙 2개, 2048 MiB, 최대 2회, 허용차 20(0.001 단위)과 숫자 조절 화살표를 모두 읽을 수 있었고 연구 실행 단추가 활성화됐다. [원호 전계와 반복 격자 입력 화면](02_실행화면/106_직전_전계의_반복격자_입력.png)

기존 40 x 60 mm IFA 원본 개정 `60dc8d59-dd05-4877-895a-71a522aded45`의 연구 `a46c99d4-dd92-4993-9a00-9bec269ff6bf`에는 375의 결과 `8cbcb526-f64a-4755-913f-377be31b97c7`를 지정했다. 물성과 수치 입력을 보존하고 변경된 worker에서 기준 격자를 다시 풀었다. 첫 시도는 supervisor의 10초 lease가 만료되어 489.44초에 종료 확인됐고 어떤 콜백이 지연됐는지는 기록되지 않았다. 명시적으로 재개한 같은 준비 계획은 1,078,053점, 10,633단계, native 609.87초에서 원래 -50 dB 기준에 도달했다. 최종 에너지 -51.46 dB이며 결과는 `acb96eea-21d7-47c3-915e-4728f11098c7`다.

실제 2.44175 GHz Ey 전계 SHA-256 `75975e2383baefba79111390f432f7f208ffd7f5043138d6fbae3c79e3c26c37`에서 Y 방향 140, 141번 구간을 선택해 후속 1,089,835점을 생성했다. 두 구간의 목표 셀 폭은 각각 약 0.166667 mm에서 0.083333 mm로 줄었다. 격자점 수는 1.09% 늘었지만 openEMS의 시간 간격은 3.97272e-13 s에서 2.12927e-13 s로 46.4% 줄었다. 같은 약 2.347 ns 여기 신호에 필요한 시간 단계는 5,907에서 11,021로 늘었다.

| 900초를 지정한 후속 시도 | 감독 기록 | 마지막 진행 표본 | 그 표본의 처리율 | 에너지 감쇠 |
| --- | --- | --- | ---: | ---: |
| `6096fc64-9075-4086-a6db-6d8cf3db17db` | guest가 자체 시간 상한으로 종료 | 14분 43초, 12,640단계 | 12.8 MCells/s | -16.41 dB |
| `86ce4640-b3da-494f-a4a4-eb70c3b2a633` | Windows가 guest 종료 확인 기한을 넘겨 취소, worker 895.47초 | 14분 14초, 12,640단계 | 16.2 MCells/s | -16.41 dB |

두 번째 시도는 같은 연구, 봉인 입력, 소스와 4스레드를 사용했다. Windows 저널에는 `WSL guest의 종료 확인 기한을 넘었습니다.`와 `interrupted`, guest에는 `cancelled`, 종료 확인 및 반환값 -15가 남았다. 기준 해석의 실제 최종 물리 시각은 약 4.22419 ns이며 두 후속 시도의 마지막 관측 시각은 약 2.69140 ns였다. 두 시도 모두 요구한 -50 dB에 도달하지 않아 후속 S11 비교 표본은 0개다. 기존 기준 결과와 준비 계획을 보존했다. ## 8 mm 공기 영역을 둔 별도 IFA

기존 40 x 60 mm IFA 회귀 예제 개정 `d7633f64-39fc-4add-b474-8936129aceb7`는 공기 8 mm, 목표 격자 0.5 mm, 4스레드, 최대 100,000단계, 에너지 비 1e-5와 900초 상한을 사용했다. 실제 2.44175 GHz Ey를 급전 부근 X 6 ~ 12 mm, Y 46 ~ 54 mm, Z 0.965 mm에서 기록했다. 기준 해석 `a82eabdf-093d-4613-8149-b5267da3263c`는 639,693점에서 5,075단계, -50.45 dB로 종료했다.

최초 연구 `51f17745-323f-42be-94ac-8e4b3edcee1f`에는 `no_eligible_change`가 저장됐으나 보드 윗면의 약 1 ULP 차이 때문에 국부 셀을 놓친 판정이었다. 이를 오판으로 보존했다. 독립 연구 `1345d3e0-2e32-4be4-9e02-42383eb6e7a2`에서는 동일한 221개 복소 Ey 표본, 원본 해시 `7f5d85a755710236f1edf684ea3f98f04b5bc469470a68cee4729dc655ad9187`와 5% 변화 기준에서 21개 구간이 후보가 됐고, 상위 2개에 규칙을 적용해 648,055점 격자를 만들었다.

실제 후속 결과 `1b5d6219-7c03-4f5c-86fe-7784ac8cd1bc`는 7,105단계, -50.49 dB에서 종료했다. 기준과 후속의 FDTD 시간 간격은 각각 9.39488447e-13 s와 6.71414035e-13 s였고 native 반복 계산에는 각각 133.87초와 197.72초가 들었다. 두 봉인 결과의 2.4 ~ 2.4835 GHz 공통 51개 표본이 모두 복소 S11 허용차 0.02 이내였다. 최대 복소 S11 차이는 2.4 GHz에서 0.00053528936324, 최대 입력 임피던스 차이는 0.05332609 ohm이었다. 연구는 첫 국부 재계산에서 `stability_reached`로 종료했다. 이 판정은 이 IFA, 지정한 급전, 대역과 8 mm 공기 영역에서 비교한 두 해석의 결과다.

최종 경계 판정 코드로 봉인 전계를 다시 읽어 같은 21개 후보, 물리 영역, 두 규칙과 격자를 재현했다. 전체 후속 계획 SHA-256 `8cc2b756c8d94434038c1ccd78a6e0482d3007bf3070c5cc8eb0514db4376cff`와 실제 격자 SHA-256 `0f8daa5d3acc814a7dd8dccf56d2d2b5d27425cc1a0e71a134e4bfc1b5b95ade`가 openEMS에서 사용한 입력과 일치했다.
