# Windows 해석 취소 접수 최적화 검증

2026-11-21 KST. 완료 계획 12번 F4에서 같은 Windows Release GUI, 원형 기판·원호 해석 입력, WSL2 openEMS와 초당 약 1000행의 로그를 사용했다. 개선 전과 후를 별도 시험 영역에서 각 6회 실행했고, 쌍마다 실행 순서를 교대로 바꿨다. [결합 계측 방법](96_윈도우_실해석과_고속로그_취소시험.md)

| 구간 | 개선 전 중앙값 / p95 / 최대 (ms) | 개선 후 중앙값 / p95 / 최대 (ms) |
| --- | ---: | ---: |
| 버튼 상태 변경 | 29.92 / 34.91 / 35.77 | 34.90 / 43.21 / 45.05 |
| Windows 서비스 요청 수신부터 응답 송신 | 161.03 / 196.08 / 202.42 | 118.71 / 138.78 / 139.98 |
| GUI 접수 확인 | 242.47 / 250.54 / 250.91 | 190.68 / 195.51 / 196.74 |
| GUI 종료 관찰 | 1574.04 / 1612.55 / 1622.78 | 1457.17 / 1625.50 / 1650.74 |

Windows 서비스 구간은 모든 쌍에서 35.83~67.26 ms 감소했다. 개선 후 GUI 접수는 여섯 번 모두 200 ms 안에 들어왔고, 한 쌍에서는 서비스 외 구간이 길어져 전체 접수가 6.47 ms 늘었다. 12회 모두 실제 guest 종료와 연속 작업 이벤트, 이전 결과 및 저장 개정의 재열기를 확인했다. p95와 p99는 소표본의 선형 보간값으로 기록했다. PERF-007의 정식 수용에 필요한 1000개 이상 timestamp 표본과 기준 장비 반복 시험은 남아 있다. [원시 실행 기록](99_윈도우_취소접수_교차실행기록.json)

## 변경과 재현

- 정규 JSON의 문자열은 기존 UTF-8 유효성 검사 후 문자열 전용 JSON 인코더로 처리한다. Unicode scalar 1,112,064개의 값과 키, 시험 작업 영역의 상태 119개에서 기존 바이트와 SHA256이 일치했다. 짝 없는 surrogate, 부적합한 키와 숫자도 계속 거절했다.
- 저널 경로는 이미 얻은 `lstat`의 모드로 심볼릭 링크를 검사하고 Windows reparse 검사도 수행한다. 기존 상태·매니페스트·포인터의 쓰기, 동기화, 재읽기와 해시 검사를 통과한 뒤 접수를 반환한다.
- [Windows 결합 계측 도구](../../Code/tools/measure_windows_f4.py)의 절차로 같은 EXE에서 두 Git 소스 개정을 비교할 수 있다. 진단용 stdout과 응답 계측은 분리한 복제본에만 들어간다. 이 기록의 두 구성은 계측 패치와 실행 파일이 동일하고 두 Python 모듈만 다르다.

## 제품 회귀

계측 패치 없이 실제 Windows Studio와 WSL2 해석 취소·재열기 시험 1개를 통과했다. 실제 해석이 진행 중임을 확인하고 취소 접수와 guest 종료, 이전 결과와 저장 개정을 대조했다.

정규 인코딩, 저장소, 서비스·RPC, 작업 취소, 소스 봉인 및 요구 추적 회귀 115개와 Windows Release CTest 13개를 모두 통과했다.
