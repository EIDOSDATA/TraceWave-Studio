# Windows 시작 지연 개선 검증

2026-11-20 KST. 같은 Windows 11 Release 경량 서비스 구성에서 [F0 기준선](49_윈도우_에프영_시작시간_검증.md), 서비스 병렬 시작 실험, 의존 소스 분석만 개선한 채택 빌드를 비교했다. 각 구간은 별도 빈 작업 영역에서 준비 실행 1회와 warm 20회다. 첫 화면은 2D 캔버스 첫 버퍼 그리기 완료이며, 새 프로젝트 준비는 첫 화면과 새 프로젝트 명령 활성화를 모두 확인한 시점이다.

| 구성 | 첫 화면 중앙값 (초) | p95 | 최대 | 새 프로젝트 준비 중앙값 (초) | p95 | 최대 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 이전 기준선 | 1.381 | 1.424 | 1.551 | 3.803 | 4.011 | 4.103 |
| 서비스 병렬 시작 실험 | 1.788 | 2.235 | 2.347 | 2.564 | 2.890 | 2.972 |
| 채택한 의존 소스 분석 개선 | 1.406 | 1.686 | 1.686 | 3.670 | 4.024 | 4.030 |

채택 빌드의 첫 화면 p95는 1.686초로 1.500초 목표 초과, 새 프로젝트 준비 p95는 4.024초로 2.000초 목표 초과다. 서비스 병렬 시작 실험은 새 프로젝트 준비를 앞당겼으나 첫 화면 p95가 2.235초로 늘어 실행 순서를 되돌렸다. 두 실험의 서비스 소스 해시와 화면·장치 조건을 비교했으며 원시 표본에는 각 실행 바이너리 해시를 담았다. PC 재부팅 후 cold 5회는 수집하지 않았다.

## 같은 바이너리에서 서비스 교차 비교

동일 GUI 실행 파일과 Python에서 같은 깊이에 복제한 두 서비스 원문을 번갈아 연결했다. 작업 영역도 조건별로 분리했다. 변경한 두 Python 파일만 기준선과 달랐다. 각 조건 준비 실행 1회에 이어 20개 쌍을 측정하고, 매 쌍의 실행 순서를 교대했다.

| 구성 | 첫 화면 중앙값 (초) | p95 | 최대 | 새 프로젝트 준비 중앙값 (초) | p95 | 최대 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 기준 서비스 | 1.343 | 1.420 | 1.513 | 3.789 | 4.023 | 4.119 |
| 의존 소스 분석 개선 | 1.331 | 1.413 | 1.623 | 3.558 | 3.869 | 3.900 |

교차 비교에서 새 프로젝트 준비 중앙값은 3.789초에서 3.558초, p95는 4.023초에서 3.869초로 줄었다. 첫 화면 p95는 두 조건 모두 1.500초 목표 이내였다. 별도 연속 실행에서 첫 화면 목표를 넘긴 표본도 있어 재현 가능한 수용과 cold 확인은 남는다.

## 출처와 실행 경계

- 각 계산 프로필은 파일을 따로 읽고 경로를 검증한다. 같은 캡처 안에서 경로와 원문이 같은 경우에만 AST에서 추린 import와 호출 노드를 재사용한다. 매 캡처가 끝나면 재사용 데이터는 폐기한다.
- 두 프로필의 공유 파일 원문이 달라지면 합집합을 거부한다. 디스크에서 읽은 원문과 세션이 읽어 둔 계산 소스도 기존 방식으로 대조한다. 192개 상한, CAD 2 MiB, 다른 대상의 4 MiB 상한은 유지한다.
- 변경 전후 CAD 73, 교환 24, openEMS 89, 계산 제어 135, 수학 69개 경로를 대조했다. 진입점과 동적 import 목록은 일치했고 이 구현이 수정한 소스 파일만 개별 해시가 바뀌었다. 구형 전체 host 프로필은 양쪽 모두 기존 파일 수 한도로 거부됐다. 두 읽기 사이 원문 교체 시 두 번째 의존성도 다시 검증하는 회귀를 추가했다.

## 유휴와 회귀

정상 시작한 빈 창에서 GUI 자동화 조회 전에 30초 구간 두 개를 연속 수집했다. 한 논리 코어 기준 CPU는 1.093%와 0.937%로 이번 구간에 1%를 넘긴 관측이 있다. GUI private commit의 최대 표본은 39.66 MiB, 경량 서비스와 하위 프로세스를 포함한 최대 표본은 101.57 MiB였다. 이전 구간의 CPU 변동도 [기록](45_유휴확인주기_비교_검증.md)에 보존한다.

관련 서비스/RPC 43개, 같은 suite에서 환경 조건으로 제외됐던 실제 OCCT 2개, 신규 원문 교체 회귀 1개, Windows GUI 10개와 CTest 13개가 통과했다. F1/F2 조작 프레임과 전체 제품 성능 수용은 별도다. 재현은 [이전 F0 계측 명령](49_윈도우_에프영_시작시간_검증.md#재현)을 따른다. [실행 기록](52_윈도우_시작지연_개선_실행기록.json)에 채택 및 회수 실험, 별도 유휴, 실행 파일과 시험 결과를 보존한다.
