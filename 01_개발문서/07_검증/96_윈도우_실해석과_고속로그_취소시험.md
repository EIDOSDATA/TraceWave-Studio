# Windows 실제 해석과 고속 로그의 취소 시험

2026-11-21 KST. 완료 계획 12번 F4의 실제 WSL2 PCB 해석과 초당 약 1000행의 로그를 한 실행에 결합했다. Windows Release GUI는 통합 묶음에 사용한 실행 파일이다. 계측 도구는 지정한 Git 커밋의 Code를 새 시험 폴더에 복제해 계측과 합성 로그를 연결한다. 시험용 원호·기판·급전은 고정 fixture이며 실제 제조 조건이나 RF 정확도 근거로 사용하지 않는다. [이전 분리 시험](84_윈도우_취소접수와_더블유에스엘_로그_검증.md)

## 입력과 판정

- 실제 openEMS 프로세스와 라이브러리 매핑을 확인했다. 같은 WSL worker의 표준 출력에 합성 로그를 추가했으며 원래 solver 로그 파일은 보존했다. 2000행의 송신과 실제 프로세스 생존을 확인한 뒤 GUI가 취소 버튼 이벤트를 전달했다.
- 버튼 상태 변경, 서비스의 요청 수신부터 NDJSON 응답 송신까지, GUI 접수 확인과 guest 종료를 나누어 잰다. 종료 확인, journal event 순서, 이전 결과의 ID와 저장 개정 및 재열기를 대조한다.
- 첫 도구 시도에서는 native 경로 형식이 `Path`인 경우의 판정 오류 때문에 취소 준비 상태가 게시되지 않았다. 두 실제 해석은 완료됐다. 경로 이름을 검사하도록 고친 뒤 유효 표본을 수집했다.

| 구간 | 검증 표본 |
| --- | ---: |
| 버튼 상태 변경 | 28.936 ms |
| 서비스 요청 수신부터 응답 송신 | 169.7951 ms |
| GUI 접수 확인 | 246.368 ms |
| GUI 종료 관찰 | 1618.872 ms |
| 취소 준비까지 송신한 합성 로그 | 2000행 / 2.0001초 |
| 종료까지 읽은 합성 로그 | 3720행 |

같은 해석의 종료를 확인했고, 새 계산 결과를 게시하지 않고 이전 결과를 다시 열었다. 접수 시간은 200 ms 목표를 초과했다. 이 기록은 계측 경로를 확인한 단일 표본이다. [실행 기록](97_윈도우_실해석과_고속로그_취소실행기록.json)

## 재실행

Code에서 이미 검증한 Windows GUI와 WSL 현장 감사 파일을 사용한다. 표본별로 새 작업 영역을 생성한다.

```powershell
.venv/Scripts/python.exe -X utf8 tools/measure_windows_f4.py . .local/f4-probe build/windows-release/bin/tracewave_gui.exe --prepare --revision 22decf6
.venv/Scripts/python.exe -X utf8 tools/measure_windows_f4.py . .local/f4-probe build/windows-release/bin/tracewave_gui.exe --index 1
```

계측용 변경과 합성 로그는 시험 폴더의 복제 소스로만 실행한다. 원래 저장소의 서비스는 그대로 실행할 수 있다. 반복 표본과 F4 전체 판정은 별도로 기록한다.
