# Windows 스윕 후보 추적과 독립 재실행 검증

2026-11-21 KST. 실제 Windows Release와 Python 서비스에서 스윕 검토, 저장, 취소, 명시 재개, 후보 CSV와 재열기를 대조했다. 후보의 원래 순번과 단위 동치로 계산을 재사용한 순번을 구분했다. 연결된 회로 값이 미정인 후보와 허용 범위 밖인 후보는 실행 전 검토에서 사유를 보였다.

Windows에서 외부 회로 후보 3개를 보고 저장했다. 50 ohm과 0.05 kohm은 각각의 입력 행을 유지하며 같은 계산 결과 해시를 참조했다. CSV의 후보 기록 해시와 원본 계산 행을 저장소의 불변 파일과 맞췄다. 그리드 2 x 2 검토와 단일 변수 입력, 완료되지 않은 행의 빈 결과도 확인했다. [Windows 검증](../../Code/tests/test_gui_sweep_process.py), [스윕 계약](../05_기능설계/06_연구/01_명시적스윕과_실행계약.md)

과거 RF 결과의 worker 소스와 현재 WSL2 환경의 봉인이 달라 별도 작업 공간에서 24 mm IFA 검증용 후보 한 행을 계산했다. 같은 후보를 새 프로젝트로 채택하고 한 번의 undo/redo, 저장, 독립 스냅샷 재실행 및 런타임 없는 재열기를 확인했다. 각 작업은 native solve 1회를 사용했다. 2.400~2.4835 GHz의 51개 공통 표본에서 원본과 재실행 복소 S11의 최대 절대 차이는 0.0이었고 허용 기준은 1e-10이었다. 원본 프로젝트 파일 46개의 해시를 대조했다. 두 실행과 재열기는 234.265초였다. 실제 제조와 측정은 미정으로 두었다. 목표 대역과 물리 수렴은 해당 사례의 검증에서 판정한다. [후보 채택과 재실행 도구](../../Code/tools/verify_tuning_adoption.py)

스윕과 채택 회귀 64개 중 63개가 통과했고 환경 조건이 필요한 1개를 건너뛰었다. Windows GUI 1개(43.932초)와 Release CTest 13개가 통과했다.
