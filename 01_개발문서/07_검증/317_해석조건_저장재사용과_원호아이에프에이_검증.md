# 해석 조건의 저장·재사용과 원호·IFA 검증

2026-11-22 KST. 원호와 IFA의 기존 설치 결과와 프로젝트를 검수 사본에 열었다. Windows Studio의 해석 결과에서 `결과 조건 다시 사용`을 열고 각 원래 결과의 입력으로 돌아갔다. 격자 간격을 0.5 mm에서 0.55 mm로 바꾸면 비교표에 그 항목 한 줄과 전후값만 표시됐다. 원래 입력을 불러온 뒤 실행 버튼을 잠그고 현재 개정으로 다시 검토하는 동작을 확인했다.

| 사례 | 저장 이름 | 과거 결과 | 재열기 뒤 실제 격자선 수 X/Y/Z | 실제 격자점 |
| --- | --- | --- | --- |
| 원호 | 원호 설치 기준 | `8ab10b14-6873-4927-b84c-65c50e682ff8` | 117 / 157 / 42 | 771,498 |
| IFA | IFA 설치 기준 | `0b09a11a-fe1d-46e7-869a-167f35bec98a` | 117 / 157 / 42 | 771,498 |

Windows에서 조건을 이름으로 저장하고 Studio를 종료했다. 새 세션에서 프로젝트를 열어 저장 이름, 0.5 mm 모델 격자, 2,441,750,000 Hz NF2FF 주파수와 재검토를 확인했다. 저장 목록은 현재 프로젝트의 영속 적용 개정에서 읽는다. 기존 프로젝트가 저장돼 있는 상태에서 조건을 추가하면 새 개정을 저장한다.

WSL2 검수 사본에서는 실제 과거 결과의 분석 계획을 읽어 이름으로 저장하고, 서비스를 종료한 뒤 `project.open`으로 같은 프로젝트를 열었다. 기존 설정의 주파수 대역과 표본 수, 가변 공기 격자, 종료 기준, 4개 계산 스레드, NF2FF 상자 여유를 포함한 모든 설정과 JSON 숫자 표현을 대조했다. 새 검토 모델의 계획 해시와 실제 준비에서 소비한 case 해시가 일치하고, 모든 X/Y/Z 좌표가 일치했다. 두 사례의 원본 포인터와 기존 결과 파일 해시도 보존됐다. 이 검증은 openEMS 준비까지다.

Python 테스트에서 WSL2 전용 한 항목은 Windows 실행에서 건너뛰었다. 이번 기능의 WSL2 준비는 위 두 실제 사례로 별도 확인했다. 단위 시험에서 중복 이름 거절, 같은 요청의 영수증 재사용, 실행 취소·다시 실행과 서비스 재열기, 다른 프로젝트와 합성 참조 결과의 접근 차단도 확인했다.
