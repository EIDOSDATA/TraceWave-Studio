# Windows 해석 취소와 로그 부하 검증

2026-11-20 KST. 12번 F4에서 같은 작업의 취소 버튼 이벤트, 컨트롤 변경, 영속 서비스 응답과 종료 확인을 각각 기록했다. Windows의 기존 wxWidgets 버튼이 메뉴의 실제 해석 취소 명령으로 이어지는 경로로 입력했다. 컨트롤 시간은 버튼을 비활성화하고 취소 상태를 설정한 시점이다. 화면 합성과 OS 입력 배송은 이 시간에 포함하지 않았다. 접수 시간은 GUI에 응답이 도착한 시점이며 종료 시간은 다음 상태 조회에서 terminal을 확인한 시점이다.

## 실제 Windows GUI와 WSL2

| 실행 | 단계 | 버튼 상태 변경 (ms) | 서비스 응답 (ms) | 응답 상태 | 종료 관찰 (ms) | 종료 상태 |
| --- | --- | ---: | ---: | --- | ---: | --- |
| 초기 원호 | snapshot | 14.90 | 486.83 | completed | 486.87 | completed |
| 초기 방사 | snapshot | 12.69 | 429.58 | completed | 488.71 | completed |
| 최종 실행 중 후보 | analysis | 24.55 | 241.67 | cancel_requested | 1514.82 | cancelled |
| 최종 원호 | snapshot | 14.81 | 360.66 | cancelled | 429.09 | cancelled |
| 최종 방사 | snapshot | 11.96 | 554.82 | completed | 554.85 | completed |

기존 스냅샷 단계의 완료 경합은 스냅샷을 보존하고 후속 해석만 멈췄다. 750 ms 고정 대기 실험에서는 호스트가 running인 동안에도 취소된 WSL 실행에 not_started가 남았다. 실제 실행 중 시험은 새 스위치 `--solver-active-cancel-smoke-test`를 사용해 두 번째 작업의 `em_analysis/running` 상태와 같은 작업 ID의 `guest_worker_attached`를 확인한 뒤 취소했다. 같은 작업 ID로 영속 종료 확인과 불명 상태 false를 확인하고 이전 결과를 저장·재연결했다. 완료된 전 단계 응답과 실제 해석 취소 결과를 구분한다.

이번 실행 중 해석에서 버튼 상태 변경은 24.55 ms, 서비스 응답은 241.67 ms, 종료 관찰은 1514.82 ms였다. 재현 가능한 p95 수용에는 추가 반복과 같은 backend 부하에서 로그를 함께 올리는 실행이 필요하다. 해석의 물리 정확도나 제작/측정 상태는 이 시험으로 판정하지 않는다.

## 별도 Windows native 감독기의 로그 부하

평균 초당 1,000행을 목표로 두 초 동안 쓰고, 다음 로그를 쓰는 동안 취소했다. 취소 요청 전에 연 Windows 동기화 핸들로 후손 종료를 확인했다. 첫 진단에서 원자 교체 직후 준비 파일을 읽을 때 일시적 공유 위반이 발생했다. 시험 도구는 같은 실행의 제한 시간 안에서 재시도하도록 고쳤다.

| 실행 | 완료 시점 전 평균 행/초 | 읽은 stdout 행 | 취소부터 감독기 반환 (ms) |
| --- | ---: | ---: | ---: |
| 1 | 999.79 | 2020 | 10.35 |
| 2 | 998.91 | 2020 | 5.26 |
| 3 | 999.76 | 2020 | 10.14 |

모든 실행에서 소유한 후손의 종료와 전체 행 바이트 수를 확인했다. 이 부하는 관리 중인 Windows 작업 트리의 별도 진단이었다. 같은 WSL2 solve에서의 GUI 로그 표시와 이벤트 누락, 지속 부하 p95는 남는다.
