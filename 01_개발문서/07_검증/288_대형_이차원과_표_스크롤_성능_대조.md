# 대형 2D와 표 스크롤 성능 대조

2026-11-22 KST. 5f3042a의 GUI와 두 변경을 포함한 Windows Release GUI를 개발 PC에서 비교했다. 내장 화면은 2560 x 1600, DPI 144, 120 Hz였다. 승인된 F1 p95 16.667 ms와 실제 화면 갱신의 최소 30초 및 1000개 조건을 유지했다. 이 개발 PC 계측은 기준 PC 수용과 따로 기록한다. [표시 판독](283_윈도우_연속표시_유효표본_검증.md)

## 적용한 변경

- 일반 선분은 기존 좌표 범위 검사와 자르기 후에 wxGraphicsContext의 두 점 stroke를 사용한다. 같은 색상, 폭, 둥근 끝과 그리기 순서를 보존한다. 선택 강조, 제거 경계, 윤곽, 원호와 같은 native float 위치로 겹치는 양 끝은 기존 path를 사용한다.
- 카탈로그 요청은 25행에서 64행으로 늘렸다. 응답 48 KiB 한도와 최대 8페이지를 유지한다. 각 페이지의 최대 행 수는 늘고 긴 응답은 이전과 같은 offset 후속 요청으로 이어진다. 검색 세대, 선택과 원문은 기존 계약을 따른다.

## 계측 결과

메모리 DC 1만 형상 전체 보기에서 세 번 측정의 p95 중앙값은 17.044 ms에서 15.884 ms로 줄었다. 확대 이동 p95 중앙값은 5.562 ms에서 5.633 ms였고 한 회는 9.935 ms였다. 각 장면의 여섯 실행에서 보존한 마지막 RGB 픽셀은 장면별로 기존과 일치했다. 메모리 DC 수치는 실제 화면 갱신과 별도로 기록한다.

실제 Windows 화면에서 동일 1만 형상·4층을 이동했고, 표는 같은 1만 형상·1천 매개변수의 프로젝트와 10만 행 원본을 사용했다. 두 차례에 걸쳐 빌드 실행 순서를 바꿨다. 각 구간은 35초였다.

| 동작 | 회차 | 기존 유효 간격 수 | 변경 유효 간격 수 | 기존 p95 ms | 변경 p95 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 대형 2D 이동 | 1 | 1755 | 1807 | 31.099 | 26.433 |
| 대형 2D 이동 | 2 | 1702 | 2087 | 31.756 | 24.824 |
| 대형 2D 도형 드래그 | 1 | 2011 | 1901 | 24.960 | 25.533 |
| 10만 행 표 스크롤 | 1 | 2029 | 2100 | 25.846 | 25.365 |
| 10만 행 표 스크롤 | 2 | 2083 | 2053 | 25.316 | 25.619 |

대형 2D 이동은 두 차례 모두 p95가 줄었다. 도형 드래그 한 쌍에서는 변경 뒤 p95가 약 0.57 ms 늘었다.

표에서 스크롤 후 가장 위 행의 값이 아직 도착하지 않은 횟수는 첫 회 115/2194에서 41/2207, 두 번째는 89/2208에서 43/2198로 줄었다. 변경 뒤 최대 간격은 두 회에서 각각 41.857 및 207.633 ms였다. 표의 데이터 도착은 개선됐으며 화면 p95 개선은 재현되지 않았다. 표의 화면 갱신과 두 2D 동작은 모두 16.667 ms 한도를 넘었다.

표의 10만 행과 필터 적용 5만 행, 1만 형상과 1천 매개변수, 저장·재열기 및 카탈로그 원본 해시를 두 빌드에서 검증했다. Windows GUI의 원호·IFA 정밀 편집과 native 선택, 카탈로그 수신, 오래된 응답 폐기, 카탈로그 없이 편집 경로의 5개가 통과했다. CTest 13개, 카탈로그 API·표기·표시 판독 16개도 통과했다. 실제 Windows 카탈로그 원본에도 제조사 표기를 대조했다.

재현에는 `tracewave_canvas_benchmark.exe report.json --f1-render`와 `tracewave_canvas_display_probe.exe report.json --scene-pan scene.json`을 쓴다. 도형 드래그는 `--scene-drag`로 설정한다. 장면 SHA256은 `0650160a5bcacb5dea470c12c8257718803ca65852a84ebff617daed9889ebe2`이다. 표는 `test_f1_view.py`의 고정 카탈로그, `--catalog-table-smoke-test`와 `RFAD_TEST_CATALOG_SCROLL_DISPLAY=1`을 사용한다. 원시 결과는 작업 폴더의 `f1-rf-followup`과 `stage12-r1-followup/f1-followup-*`에 보존했다.

기준 PC의 60 fps 수용, 2D 조작 전체와 표의 긴 정지 원인, 일반 3D 등 F1 나머지 동작의 통합 판정은 열린 상태다.
