# Windows 대형 3D 장면 합성 검증

2026-11-20 KST. PERF-F2의 대형 3D 회전과 이동을 Windows에서 계측했다. 시험 창에는 Studio와 같은 ModelView, wxGLCanvas, 표시 파일 로더, 카메라 변환과 정점 버퍼를 사용했다. 1,000,000개 삼각형과 502,002개 정점의 동일한 두 바디를 고정 카메라와 재질로 열었다. 이전 검증의 픽셀 및 OpenGL 완료 시간은 별도로 보존했다. [대형 표시 메시 검증](61_윈도우_대형표시메시_검증.md)

## 측정 경로

- 표시 영역은 1920 x 1080 픽셀이다. Windows 11 build 26300, Intel Core i7-1365U와 Iris Xe Graphics, OpenGL 4.6.0 Build 32.0.101.7088, DPI 144, 출력 2560 x 1600 및 120 Hz에서 실행했다. 현재 OpenGL context의 swap interval은 1이었다.
- 고해상도 타이머를 8 ms로 요청했다. 35초 동안 입력 120개씩 회전과 수평 이동을 교대로 적용했다. 3D 마우스 드래그가 사용하는 동일한 카메라 함수를 호출했다. 준비 시간은 입력 표본에 포함하지 않았다.
- 정점 그리기 뒤 같은 OpenGL 버퍼에 시험 번호를 넣고 SwapBuffers를 호출했다. DXGI에서 해당 번호가 읽힌 출력의 LastPresentTime을 연결했다. 전경 시험 창의 고정 96 x 1 픽셀만 검사했다. 저장 자료에는 픽셀 없이 번호와 QPC 시각만 남는다. [Windows 출력 시각 명세](https://learn.microsoft.com/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_outdupl_frame_info)

## Windows 표시 간격

| 실행 | 전달 입력 | 합성에서 관찰한 입력 | 화면 간격 수 | p95 (ms) | p99 (ms) | 최대 (ms) | 목표 초과 | 입력-합성 p95 (ms) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 대형 3D 1회차 | 4208 | 3929 | 3928 | 16.30 | 17.00 | 17.92 | 0 / 3928 | 14.13 |
| 대형 3D 2회차 | 4206 | 3994 | 3993 | 12.77 | 16.85 | 18.90 | 0 / 3993 | 13.76 |
| 2D 256개 대조군 | 4102 | 3321 | 3320 | 17.01 | 24.77 | 27.22 | 281 / 3320 | 18.48 |

3D 두 실행이 각각 필요한 30초 및 1,000개 간격을 넘겼으며, 관찰된 최대 간격도 30 fps의 33.33 ms 이내였다. 모든 전달 입력이 그려졌고 각 실행에서 279회와 212회의 그리기 번호가 합성에서는 관찰되지 않았다. 연속 합성 표본 사이의 전체 간격을 사용했다. 3D 실행별로 정점 버퍼 72,000,000바이트를 한 번 올렸다. 이 값은 버퍼 본문의 크기다.

2D 대조군은 4층, 1000 x 700 픽셀이며 60 fps 기준 16.67 ms를 사용한다. 이 확대 경로의 p95는 16.67 ms를 넘겼다. 3D의 대형 기준으로 재분류하지 않는다. [이전 2D 계측](55_윈도우_합성화면_검증.md)

이 3D 표본은 대형 표시 자료의 연속 회전과 이동에 대한 PERF-006 근거다. 전체 Studio 도킹 화면, 선택과 LOD 품질, 기준 장비의 종합 F2 수용은 별도다. DXGI 출력 시각은 패널의 광학 표본과 구분한다. [화면 성능 설계](../04_화면설계/02_화면_선정과_성능_설계.md)

## 별도 메모리 실행

동일 장면을 다시 열고 전용 시험 프로세스의 private commit, working set, 핸들과 Windows GPU Process Memory를 따로 샘플링했다. 프로세스 표본 18개 간 실제 간격은 약 2.03~2.16초였고, GPU 프로세스에 대응하는 표본은 17개였다. 관찰 최대 private commit은 208.71 MiB, Windows가 유지한 peak working set은 294.60 MiB, 최대 핸들은 351개였다. GPU shared usage는 최대 165.07 MiB였고, dedicated usage는 해당 표본에서 0이었다. 총 GPU commit 카운터 최대는 165.09 MiB였다. [Windows 카운터 수집 명세](https://learn.microsoft.com/powershell/module/microsoft.powershell.diagnostics/get-counter/)

수치는 같은 프로세스의 OpenGL과 DXGI 표식 판독 자원을 포함한다. Studio 전체 또는 GPU 드라이버의 개별 버퍼 귀속은 구분할 수 없으므로 성능 실행과 분리했다. 30회 재열기 자원 회수는 별도의 F5 검증이다.

## 재현과 회귀

```powershell
.venv/Scripts/python.exe -X utf8 tools/create_large_display_fixture.py .local/large-display
cmake --build build/windows-release --target tracewave_canvas_display_probe
./build/windows-release/bin/tracewave_canvas_display_probe.exe .local/model-display.json --model .local/large-display
.venv/Scripts/python.exe -X utf8 tools/summarize_windows_canvas_display.py .local/model-display.json
```

자원 표본을 별도로 얻으려면 PowerShell 7에서 다음을 실행한다.

```powershell
./tools/measure_windows_model_memory.ps1 -Fixture .local/large-display -Trace .local/model-memory-trace.json -Report .local/model-memory.json
```

시각 판독 회귀 4개, 실제 OCCT 경로를 포함한 Windows Studio 12개 및 CTest 13개가 통과했다. 다른 창을 활성화하거나 시험 창을 옮기면 해당 실행을 실패로 남긴다. [실행 기록](64_윈도우_대형장면_합성실행기록.json)에 각 실행의 모든 시각, 산출물 식별자 및 회귀 결과가 있다.
