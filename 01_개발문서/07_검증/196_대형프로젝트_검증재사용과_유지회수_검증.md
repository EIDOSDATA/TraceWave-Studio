# 대형 프로젝트 검증 재사용과 30초 유지 회수

2026-11-21 KST. 불변 프로젝트 문서를 읽을 때 실제 파일의 크기와 SHA256을 확인하고 새 JSON 객체를 읽는다. 인라인 전송 한도를 넘는 문서는 성공한 정규형과 의미 검증의 해시를 서비스마다 최대 16개 보관한다. 같은 해시에서 검증 결과를 재사용한다. 다른 해시는 검증을 다시 수행하며 문서나 화면 객체는 보관하지 않는다.

격리된 Windows 서비스에서 각 동작 30회의 초기 5회와 마지막 10회 중앙값 차이를 구했다. 파일·곡선만 조회했을 때 증가는 0.00 MiB였다. 대형 설계 전환만 반복했을 때 검증 재사용 전후의 private commit 증가는 26.05→12.61 MiB였고 회차 중앙값은 1.922→0.734초였다. 두 전환에서는 작업 기록 수가 동일하게 65→125로 증가했다. 할당 추적을 켠 실행은 별도 진단이며 해제되지 않은 메모리의 전체 원인을 증명하지 않는다.

같은 SegmentHeap Windows Studio와 하위 프로세스에서 100만 삼각형, 1 GiB급 필드 부분 조회 열 회, 복소 곡선 여덟 개와 대형 편집 설계를 함께 열고 전환했다. 30초씩 문맥을 유지하며 30회 반복했다.

| 지표 | 실제 Windows 표본 |
| --- | ---: |
| 초기 5회 안정화 합산 private commit 중앙값 | 220.07 MiB |
| 마지막 10회 안정화 합산 private commit 중앙값 | 229.99 MiB |
| 안정화 증가 | 9.93 MiB |
| 열림 중 합산 private commit 관찰 최대 | 357.67 MiB |
| GUI 안정화 핸들 처음 / 관찰 최대 / 마지막 | 367 / 449 / 375 |
| 유지 GPU local 최대 / nonlocal 최대 | 152.14 MiB / 0바이트 |

30회 모두 OpenGL 문맥을 유지했고 합산 메모리 증가는 32 MiB 이내였다. GUI 핸들은 회차 중 증가했다가 마지막에 관찰 최대보다 내려갔다. 다른 서비스 검증 및 대형 유휴 검증이 겹친 조건으로, 기준 호스트의 수용과 별개로 기록한다. [이전 30초 유지](174_윈도우_힙과_유지회수_검증.md), [SegmentHeap 150초 유휴](192_윈도우_힙과_유휴회수_검증.md)

원문 크기를 유지한 손상과 다른 해시의 비정규 JSON을 거부했다. 읽은 객체를 변경해도 원문과 다음 읽기는 유지됐다. 실제 제품 경로에서 F1 프로젝트와 저널·소스 묶음 등 58개, F3 등록·이관·저장·재열기 4개를 확인했다. 최신 F3의 추가 private commit은 등록 11.52 MiB와 재열기 12.38 MiB였다. [실행 기록](197_대형프로젝트_검증재사용과_유지회수_실행기록.json)
