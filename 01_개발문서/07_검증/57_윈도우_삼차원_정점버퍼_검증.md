# Windows 3D 정점 버퍼 검증

2026-11-20 KST. 12번 F1/F2 준비 범위에서 `ModelView`가 검증된 표시 메시의 위치와 법선을 현재 OpenGL context 안에 한 번 올리고 재사용하도록 했다. 회전, 확대, 선택 강조와 층 표시에서 정점 원본은 그대로 쓴다. 메시 교체는 다음 표시에서 재업로드하며, 닫기 및 context 파기는 저장소를 회수한다. 함수 미지원과 업로드 오류 시 CPU 배열 경로를 유지한다. [Windows context의 확장 함수 명세](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-wglgetprocaddress)

## 실제 Windows OpenGL 비교

Intel Iris Xe의 실제 wxGLCanvas에서 두 바디, 100,000개 삼각형을 같은 투영과 조명으로 그렸다. 두 바디의 위치와 법선 오프셋을 바꾸어 확인했으며, 같은 시점의 CPU와 GPU 뒤쪽 버퍼 RGBA가 일치했다. GPU 저장소에 7,200,000바이트를 올렸다. 애플리케이션이 요청한 데이터 바이트이며 드라이버 전체 GPU 메모리 값은 별도다.

- 같은 메시로 반복 회전할 때 업로드는 1회였다.
- 버퍼 해제 후 같은 메시를 다시 표시했고, 이전 context 파기 후 새 context에서도 같은 픽셀을 얻었다.
- 위치와 법선 배열 크기가 다른 시험 데이터를 거절한 뒤 CPU 배열 표시를 복구했다.

각 실행은 8쌍 준비 뒤 40쌍을 측정하고 CPU/GPU의 실행 순서를 번갈아 바꿨다. `glFinish` 완료까지의 함수 비용이다.

| 실행 | CPU 배열 중앙값 (ms) | CPU p95 | GPU 버퍼 중앙값 (ms) | GPU p95 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1.46 | 4.34 | 0.70 | 3.13 |
| 2 | 3.20 | 6.73 | 1.43 | 4.65 |

실제 Studio의 Windows GUI에서 네이티브 OCCT의 CAD 표시 1,512개 삼각형을 열어 정상 그리기와 취소, 저장·재열기를 확인했다. 최종 컨텍스트의 표시 버퍼는 108,864바이트였고 연결한 시험의 누적 업로드는 2회였다. 필수 두께의 미정 입력은 게시에 실패했고 메시와 GPU 버퍼가 생기지 않았다. 외부 STEP/표면층 재열기와 나머지 Windows GUI 10개, CTest 13개도 통과했다.

기존 100,000개 삼각형/16 MiB 표시 계약을 유지한다. 100만 삼각형 장면, 본선 3D의 합성 화면 간격, GPU 실제 메모리와 F1/F2 수용은 남는다. [실행 기록](58_윈도우_삼차원_정점버퍼_실행기록.json)을 보존한다.
