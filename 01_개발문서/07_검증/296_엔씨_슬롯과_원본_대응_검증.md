# NC 슬롯과 CAM 수입 원본 대응 검증

2026-11-22 KST. 일반 XNC의 명시 소수 절대좌표로 직선 G85 슬롯을 받는다. 시작의 X/Y를 확인하고 끝에서 생략한 한 축은 시작점을 사용한다. 공구 번호, 열린 가공 상태, 서로 다른 끝점도 검사한다. 원래 절삭 형식과 기존 문서의 슬롯 폭·총길이·미정 공구를 유지한다.

동박에 넷 태그가 없거나 원래 객체 태그가 사라진 경우, 해당 파일과 항목 수를 검토에 표시한다. 명시 미연결과 누락된 넷을 구분한다. XNC 도금 분류가 없으면 미정으로 두고, 검토에서 확인한다. 남아 있는 안전한 원본 객체 태그는 파일 내 순번과 함께 대응 기록과 원문 식별에 연결한다. 대응 후 생성되는 편집 객체 ID의 기존 순번 기반 규칙을 유지한다.

## 보존된 Altium 재출력

이전 실행의 원문 행을 CRLF 바이트로 복원해 두 파일의 SHA256을 각각 일치시켰다. 당시 기록의 mm 절대좌표, 원래 정수 2·소수 3자리, 0 생략 없음만 사용했다. 홀 지름 1.25 mm와 슬롯 폭 1.20 mm, 총길이 6.20 mm가 도금·비도금 파일에서 모두 유지됐다. 두 파일의 홀 중심과 슬롯 양쪽 끝은 각각 X, Y 모두 -0.001 mm였다. 이 차이는 한 좌표 단위이며 원인과 다른 출력물의 원점을 일반화하지 않는다. 보정이나 도금 분류를 적용하지 않았다. [이전 실행 기록](225_알티움_도금홀과_슬롯_실행기록.json)

고정 자릿수의 재출력 대조는 검증 도구에서 기록된 설정과 원본 해시가 있을 때 실행한다. 일반 수입에 좌표 자리수를 암시하지 않는다. 두 파일에 도금 분류와 원본 객체 ID가 없다는 손실을 확인했다. 본래 분류를 쓰려면 Studio 원본 XNC와 원본 인계 자료를 연결한다. [대조 도구](../../Code/tools/verify_altium_nc_reexport.py) [재출력 대조 기록](297_알티움_엔씨_재출력_대조기록.json)

## Windows에서 확인한 범위

별도 parser에서 명시 소수 G85 원문을 봉인했다. 도금 미정의 검토 확인 전에는 적용을 막았고, 확인 후 새 편집 개정을 저장했다. 새 서비스에서 슬롯 6.2 mm, 미정 도금·공구, TraceWaveId 원본 대응과 파일 바이트를 대조했다. KiCad 10.0.8 재저장, 같은 개정의 여섯 출력과 독립 CADability STEP 검수를 포함한 45개 회귀가 통과했다. 실제 GUI의 CAM 생성·원문 전송·적용·undo/redo·저장과 재열기도 재실행했다. 첫 GUI 계측에서 서비스 출력 종료가 보고됐고 같은 경로의 재실행에서는 재현되지 않았다.
