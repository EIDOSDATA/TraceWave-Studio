# Windows 큰 설계 표시와 재열기 검증

2026-11-20 KST. 완료 계획 12번 F1에서 현재 저장 모델이 지원하는 설계라도 초기 속성/2D 표시 응답 상한에 걸려 편집을 열 수 없던 경우를 검사했다. 이름이 긴 도체를 포함한 설계 객체 256개 중 250개가 2D 형상이며, 정규 프로젝트는 337682 bytes였다.

| 조회 | 기존 응답 | 확장 DTO bytes | 실제 RPC 응답 bytes | 항목 |
| --- | --- | ---: | ---: | ---: |
| 속성/객체 목록 | E_RESOURCE | 254283 | 251697 | 258 |
| 2D 장면 | E_RESOURCE | 295227 | 288730 | 250 |

Studio가 서비스 공개 기능을 확인하면 두 읽기 요청에 `rfad.edit-view-transport/0.1`을 전달한다. 해당 응답은 최대 384 KiB다. 구형 서비스 또는 프로필을 보내지 않는 클라이언트는 기존 60 KiB를 사용한다. 조회의 프로젝트/개정 ID, 원본 저장 한도 512 KiB와 RPC frame 1 MiB를 유지한다. 상한을 넘은 응답은 해당 요청 ID의 E_RESOURCE를 반환한다. 장면 또는 객체 이름을 잘라 응답하지 않는다.

실제 Windows Studio에서 해당 한글 경로의 프로젝트를 열고 프로젝트 속성을 편집했다. 저장, 스냅샷, 새 서비스 프로세스에서의 재열기를 확인했다. 저장 개정 번호가 일치했고 기판, 도체, 이름과 출처, 재료, 적층, 포트 원본은 시험 입력과 같았다. 확대/끝점/선·원호 편집의 기존 Windows 회귀와 CTest도 별도로 실행했다. 이 기록의 범위는 저장 모델이 이미 지원하는 설계다. F1의 10000개 형상, 1000개 매개변수, 대형 목록 paging과 합성 프레임 목표는 남는다. [실행 결과](87_윈도우_큰설계_표시와_재열기_실행기록.json)
