# Altium CAM과 MCP Inspector 수신 검증

2026-11-21 KST. 완료 계획 12번의 상호 운용 검증에 Altium Designer Enterprise 26.9.1과 MCP Inspector 2.16.0을 포함했다. 기존 KiCad 및 공식 Python SDK 왕복 기록은 [대형 설계 편집 복원 검증](125_대형설계_편집복원과_상호운용_검증.md)에 있다.

## Altium CAM

- Studio의 명시 형상 시험 프로젝트가 발행한 Gerber 세 파일과 비도금 드릴 원문을 격리 폴더로 복사했다. CAM Quick Load의 파일 확장자에 맞게 드릴 사본만 `.drl`로 저장했고 원본 SHA256을 대조했다.
- Quick Load에서 형상이 있는 동박, 외곽, 비도금 드릴을 읽었다. 빈 동박층은 선택 목록에 표시됐으며 수신 로그에서 건너뛰었다. 드릴 원문의 명시 소수 좌표와 `METRIC`에 맞춰 Metric, Absolute, None을 선택했다. [Altium 가져오기 문서](https://www.altium.com/documentation/altium-designer/preparing-for-manufacture/cam/imports-exports)
- Altium이 원점 범위 경고를 표시했다. 원점 조정은 거절했다. Quick Load 로그는 세 파일의 시작·종료, 자체 경고 0건과 오류 0건을 기록했다. 로컬 CAM 파일을 저장하고 닫은 뒤 같은 사본을 다시 열었다. 외부 앱의 좌표·구경 수치가 원문과 동일한지는 별도 비교 범위로 남는다.

## MCP Inspector

공식 MCP Inspector의 CLI를 Windows stdio 클라이언트로 실행했다. `initialize`에서 `2025-11-25` 프로토콜과 `tracewave-studio` 서버 이름을 확인했다. `tools/list`에 도구 160개가 표시됐다. `capabilities.get`의 구조화된 응답에서 `rfad.projects/0.2`와 `rfad.api/2.0`을 확인했다. 이 실행의 범위는 초기 협상, 목록, 읽기 조회다. [MCP Inspector CLI](https://github.com/modelcontextprotocol/inspector/blob/main/clients/cli/README.md)

원문과 수신 사본 해시, 실행 환경과 결과는 [기록](151_알티움_캠과_엠시피_인스펙터_실행기록.json)에 있다.
