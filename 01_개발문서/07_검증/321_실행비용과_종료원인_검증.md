# 원호와 IFA의 실행 비용과 종료 원인

2026-11-22 KST. 원형 기판의 원호 패턴 검수 모델과 40 x 60 mm IFA 검수 모델을 독립 사본에 등록했다. WSL2에서 4개 스레드로 실제 openEMS 계산을 실행했다. IFA는 NF2FF 면 출력을 포함하고 원호는 기본 포트 출력을 사용했다. 두 모델 모두 에너지 비율 0.001을 종료 기준으로 사용했다.

| 사례 | 최대 단계 기준 예상 초 | 실제 실행 초 | 예상 / 실제 최대 RSS 비교 바이트 | 예상 / 실제 원시 출력 바이트 | 종료 |
| --- | --- | --- | --- | --- | --- |
| 원호 | 35.68~107.03 | 17.52 | 148,773,248 / 84,168,704 | 228,944 / 22,037 | 910 / 20,000단계, 감쇠 30.57 dB |
| IFA | 627.15~1881.45 | 89.22 | 236,568,608 / 164,724,736 | 2,225,672 / 1,751,920 | 3,915 / 50,000단계, 감쇠 33.14 dB |

두 계산은 예상 범위에 사용한 최대 단계보다 먼저 에너지 기준에 도달했다. 검토가 반환한 예상값은 각 결과의 봉인된 예상값과 일치했다. 실제 원시 출력은 봉인 파일의 바이트 합계로 대조했다. 전체 보존 결과는 원호 323,242바이트, IFA 2,166,401바이트였다. native 시간과 후처리 시간을 분리했다.

| 미완료 사례 | 종료 근거 | 남은 관측 |
| --- | --- | --- |
| 원호 | 1,000단계 한도 도달, 에너지 비율 0.000000001 미충족 | native 20.50초, 최대 RSS 83,968,000바이트, 부분 원시 출력 23,161바이트 |
| IFA | 요청한 실행 시간 한도 0.75초 도달, WSL 종료 확인 | WSL 작업 관측 0.77초, openEMS 최대 RSS와 원시 출력 미계측 |

두 미완료 시도 뒤에도 최근 완료 결과의 ID와 원래 수치가 유지됐다. Windows에서 저장된 조건을 검토해 예상 시간, 메모리와 원시 출력을 확인한 뒤 해석 결과의 비용 비교를 열었다. 완료 결과의 세 항목을 예상·실제·비교 열에서 대조했고, 같은 창에서 최근 미완료 시도를 선택해 시간 단계 한도와 실행 시간 한도를 각각 확인했다.

기존 설치 원호 결과를 별도 사본에서 읽어 이전 원시 실행 시간과 바이트가 표시되고, 저장하지 않았던 RSS는 미계측으로 남는 것을 확인했다. Windows Release CTest 14개와 관련 Python 시험 55개를 통과했다. 이번 검수는 실행 비용과 종료 기록을 대상으로 한다. [기능 계약](../05_기능설계/04_해석결과/03_사용자기판_단일포트_해석.md), [개발 순서](../09_개발계획/15_기능채택과_개발검증_순서.md)
