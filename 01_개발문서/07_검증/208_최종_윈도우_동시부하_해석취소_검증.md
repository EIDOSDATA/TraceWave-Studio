# 최종 Windows Release 동시 부하의 해석 취소

2026-11-21 KST. 대비 테마 수정까지 적용한 Windows Release와 현행 서비스의 격리 계측 사본을 사용했다. 실제 WSL2 openEMS에 초당 약 1000행 로그를 더한 뒤 여섯 번 취소했다. 다른 Studio에서는 형상 10000개, 매개변수 1000개, 100만 삼각형, 1 GiB급 필드 단면 10개와 10만 점 복소 곡선 8개를 열고, 30초 문맥 유지 전환을 12회 완료했다. 두 번째 Studio가 열린 구간에 여섯 취소 요청이 모두 저널에 게시됐다.

| 지표 | 중앙값 | p95 |
| --- | ---: | ---: |
| 취소 버튼 비활성화 | 4.59 ms | 10.97 ms |
| Studio의 접수 응답 | 195.70 ms | 520.79 ms |
| 서비스 수신-응답 송신 | 175.23 ms | 232.97 ms |
| 실제 WSL guest 종료 확인 | 1917.33 ms | 2548.66 ms |

표본 6개의 nearest-rank p95는 최댓값이다. 버튼은 여섯 번 모두 100 ms 이내였고 접수는 두 번 200 ms를 초과했다. 각 실행의 실제 guest 종료를 확인하고, 게시된 이벤트 순서와 이전 결과의 저장 개정 및 재열기를 대조했다. 정식 표본 수와 동시 부하 접수 목표는 남는다. 앞선 교차 시험은 동일 제품의 성능 변경 비교 근거로 유지한다. [앞선 교차 시험](180_해석취소_제어와_접수순서_검증.md)

동시 부하 Studio의 12회 안정화 커널 핸들은 첫 436개와 최고 451개에서 마지막 다섯 회의 373개로 내려왔다. 별도로 조회한 2~11회 중 GDI 객체는 575~581개, USER 객체는 743~799개였다. 관찰 범위는 30초 유지의 추가 실행이며 앞선 150초 문맥 해제 시험에서 관찰한 핸들 증가의 원인은 미확립이다. [유휴 시험](198_대형프로젝트_검증재사용과_유휴회수_검증.md), [원시 실행 기록](209_최종_윈도우_동시부하_해석취소_실행기록.json)
