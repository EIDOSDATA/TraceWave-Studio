# Windows 독립 경로 재빌드 검증

2026-11-20 KST. 계획 13번의 Release 프리셋으로 같은 제품 C++ 소스와 고정 wxWidgets 원본, nlohmann/json 헤더를 서로 다른 두 디렉터리에서 빌드했다. 두 디렉터리의 GNU MinGW x64 Windows Studio EXE가 동일한 바이트로 나왔다.

## 발견과 보강

링크 시각만 고정한 상태의 독립 경로 빌드에서는 PE 해시가 달랐다. GNU 컴파일의 파일 경로 치환을 넣어 빌드 루트를 고정 상대 경로로 바꿨다. 이후에는 코드와 리소스가 일치하고 읽기 전용 데이터의 wxWidgets 컴파일 시각 4바이트만 달랐다. Windows Release 프리셋의 SOURCE_DATE_EPOCH를 고정했다. 이 시각을 읽는 wxWidgets core 객체는 프리셋 변경 시 다시 컴파일한다. 두 빌드 출력의 최종 PE 섹션 및 전체 SHA256을 다시 확인했다. [GNU 컴파일 경로 옵션](https://gcc.gnu.org/onlinedocs/gcc-16.1.0/gcc/Overall-Options.html), [GNU 컴파일 시각 규칙](https://gcc.gnu.org/onlinedocs/gcc-16.1.0/gcc/Environment-Variables.html)

같은 호스트에서 별도 소스 경로에 배포 소스를 풀고 처음부터 빌드한 뒤 수정된 Release 설정으로 확인한 결과다. 고정 도구 조합의 EXE 재현 근거이며, 다른 Windows 이미지에서의 설치와 검수는 별도다. [실행 기록](80_윈도우_독립경로_재빌드실행기록.json)
