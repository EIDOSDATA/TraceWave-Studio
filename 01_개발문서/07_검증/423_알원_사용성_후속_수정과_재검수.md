# R1 사용성 후속 수정과 재검수

2026-11-24 KST. [RC8 화면별 사용성 재진단](422_알원_알시팔_화면별_사용성_재진단.md)의 개선 순서에 따른 검증 기록이다. 검수에는 Windows 네이티브 빌드와 별도 프로젝트 사본을 사용한다.

## P1-1. 해석 실행과 결과 연결

작업에서 수신한 완료 결과의 원본만 현재 해석으로 표시한다. 접수, 실행 및 새 원본 읽기 동안 결과 열기를 잠그고 아래에 남은 그래프가 이전 실행임을 표시한다. 취소, 실패 및 프로젝트 재열기 뒤에도 보존된 원본은 이전 해석으로 열 수 있다. 프로젝트, 결과 파일과 표본의 원본 ID를 대조한 뒤 화면을 바꾼다.

Windows wxWidgets 및 실제 openEMS 0.37.0에서 원형 PCB 입력 거절, 1포트 원형/원호 PCB 해석과 과거 결과 보존, 실행 중 취소 접수와 종료 및 재시작 3건이 통과했다. 네이티브 시험은 완료 시 버튼, 새 작업 접수 시 잠금, 취소와 재열기 시 이전 결과 버튼을 확인한다.

## P1-2. 3D 갱신 중 선택한 화면 유지

3D를 요청한 시점에 3D를 표시한다. 이후 다른 작업 공간으로 이동하면 CAD 완료, 실패 및 보존 형상 조회가 현재 작업 공간을 그대로 유지한다. 화면 밖에서 확인한 형상은 대기시키고, 사용자가 다음에 3D를 열 때 실제 렌더링을 시작한다. 렌더링 완료 뒤 확대 및 갱신 제어도 복원한다.

실제 wxWidgets, OpenGL과 CAD 작업자를 사용한 시험 2건이 통과했다. 출력이 실패해도 출력 작업 공간이 유지됐다. 출력 중 결과 작업 공간으로 전환한 뒤 완료까지 현재 화면을 유지했고, 3D로 돌아가 1512개 삼각형의 표시, STEP 내용과 해시, 취소와 재열기를 확인했다. 첫 진입 및 반복 전환 시간은 최종 화면 검수에서 비교한다.

## P1-3. 목표 편집에서 적용 응답이 유실된 경우

목표 편집을 유지한 채 '적용 확인'에서 서비스에 다시 연결한다. 명령 ID로 저장된 권위 개정과 변경 사유를 읽고, 같은 명령을 다시 보내지 않는다. 승인된 개정이 확인되면 해당 목표를 표시한다. 저장되지 않았고 기준 개정이 그대로면 대역과 변경 사유를 보존하고 편집을 다시 허용한다. 이후 개정이 있거나 다른 작업도 끊겼을 때는 재열기 경로를 안내한다.

Windows 앱과 격리 시험 서비스에서 목표를 기록한 직후와 기록 직전에 각각 연결을 한 번 끊었다. 기록한 시험에서 같은 대화상자 안에 LoRaWAN 목표 1건과 변경 사유가 돌아왔다. 기록하지 않은 시험에서는 Wi-Fi 대역 2412~2462 MHz와 사유가 남았고, 명시적으로 적용한 뒤에만 신규 목표가 1건 표시됐다. 목표 RPC 검증 16건도 통과했다.

## P2-1, P2-2. 기본 수량 입력과 결과 범위

목표와 설계 규칙의 수량은 입력 방식, 값, 단위를 같은 행에 표시한다. 미정 필드의 값 칸은 비어 있고 직접 입력을 선택하면 활성화된다. 시안과 출처, 기존 수치의 보존 방식은 동일하다. 결과 목록은 전체 보존 해석과 현재 개정 자료를 구분한다. 원본이 한 건 있지만 미선택, 빈 범위, 표시 원본이 이 페이지 밖인 상태를 문구로 구분한다. 해석에서 직접 여는 원본은 전체 보존 해석 목록을 사용한다.

Windows 네이티브 시험 4건이 통과했다. 다중 목표 저장과 순차 조회, 늦은 응답 방어, 제조 규칙 및 DRC 재열기와 원래 출처의 해시, 과거 결과의 선택과 Smith 및 내보내기를 확인했다. 목표 시작 주파수의 입력 방식/값/단위가 초기 폼에서 함께 표시되는지 검증했다.

## P2-3, P2-4. 수치 판독과 연구 기본 대역

Smith 마커와 끝점 입력에 짧은 표시값을 사용한다. Smith에서는 정확한 마커 원본을 복사하고 끝점은 편집 칸에 들어가 원래 값을 확인한다. 편파 표는 자주 확인하는 지표와 상태를 앞에 두고 행 상세에서 실제 값을 그대로 복사한다. 연구는 단일 유효 포트에 맞는 기본 주파수 범위를 제시하고 범위를 벗어나면 해당 입력으로 이동한다. 해석 조건 차이에도 주파수 단위를 표시한다.

Windows 네이티브에서 과거 원본과 Smith 마커, 원형 PCB 끝점 편집과 재열기, 실제 NF2FF 편파 표의 전환과 재시작, 물성 누락 시 연구 생성/실행 차단을 확인했다. 별도 조회에서 유효한 8~12 GHz 포트가 동일한 기본 범위와 근거를 제공하고 프로젝트 저장 바이트를 그대로 유지하는 것을 확인했다. 연구 중단/재개용 WSL 전용 시험은 이번 Windows 폼 검증에 포함하지 않았다.

## P2-5, P2-6, P2-7. 기판 출처, 생성 파일과 필드 단면

카탈로그의 읽기 전용 연결 상태를 검색 전, 검색 중, 0건 및 오류와 독립 표시한다. 새 적층에서 기존 연결이 빠졌으면 변경 검토의 버튼으로 대응 열에 이동한다. 출력 직후 생성 파일과 같은 입력의 도면 미리보기를 이어서 볼 수 있다. 파일 목록에는 역할과 짧은 해시를 배치하고, 파일 행의 상세에서 원래 경로와 해시를 복사할 수 있다. 필드가 기록되지 않은 원본에서 새 해석의 기록 입력으로 이동한다. 이미 기록한 결과에서는 당시 요청값과 실제 단면 위치를 함께 표시한다.

Windows에서 카탈로그 검색과 기존 층 보존, 카탈로그 없는 직접 입력, 지연 응답 폐기 세 가지를 통과했다. PDF 생성 직후 기존 검토 도면을 유지하고 생성 버튼의 이전 승인 효력을 제거하는 자동 검사가 실제 교환 작업자에서 통과했다. 실제 openEMS 보존 원본의 10 GHz Ex 6 x 7 단면을 조회했다. 기록 요청 Z 2.1 mm와 실제 Z 1.9284615 mm, 마커 15의 X 4.25 mm와 Y 3 mm를 확인했다. 필드 미기록 원본의 버튼이 전기장 기록 영역 입력에 포커스를 옮기는 것도 확인했다.

## P2-8, P2-9, P2-10. 진단 기록, 측정 시료 및 비교 조건

시각과 사건을 요약 로그에 표시한다. 같은 화면의 옵션에서 전체 경로와 기술 로그를 읽고 복사할 수 있다. 실행 환경에는 Windows 기본 openEMS와 WSL2 연결을 표시한다. 변경 이력에서는 문서에 저장된 작업과 이름, 접수 기록이 남은 경우의 정확한 UTC 시각과 변경 사유를 먼저 읽고, 선택한 행에서 전체 개정 ID와 원시 명령을 확인한다. 접수 기록이 없는 이력의 시각은 미기록으로 표시한다. 단일 페이지에 없는 표시 원본은 다른 자료 범위가 필요함을 안내한다.

Touchstone과 HDF5에서는 CSV 입력을 접고, 시료 저장 직후에는 반환된 ID와 해시 및 개정과 일치하는 기록을 선택한다. 비교에서는 포트 수와 대응 상태, 기준면의 일치 여부와 현재 페이지에서 정확히 일치하는 주파수 표본 수를 표시한다.

Windows GUI에서 진단 요약과 전체 경로, 변경 행의 UTC 시각과 상세를 확인했다. 합성 Touchstone으로 '후속 검수 시료 01'을 저장한 직후 새 기록을 선택한 상태로 비교 버튼이 활성화됐다. Touchstone 대응 탭에서 CSV 입력이 숨겨졌고 기존 네이티브 CSV 가져오기 및 네트워크 변환 2건도 통과했다. 비교 원본 두 건의 포트를 대응하면 기준면이 일치하고 표본 3/4개가 같은 실제 주파수라는 안내가 표시됐다. 원본 고정, 계산 차이 방향과 과거 기록 및 재열기, 봉인 해시 불일치에 대한 Windows 시험을 다시 통과했다. 이전 보고서의 봉인 해시 실패는 줄바꿈된 위젯 문구를 한 문자열로 검사하던 시험을 수정하고 화면과 내부 상태를 각각 확인해 해결했다.

## P3. 작은 창에서 도구와 하단 패널 접기

2D 화면에 정밀 도구와 하단 패널을 각각 접고 펼치는 버튼을 두었다. 활성 층, 선폭, 스냅과 기본 그리기 도구에 계속 접근할 수 있다. 150%의 1128 x 767 창에서 두 영역을 접고 펼쳤다. 화면 캡처에서 캔버스 높이는 약 218픽셀에서 462픽셀로 늘었다. 접은 상태에서 F6으로 속성의 이름 입력에, Shift+F6으로 2D 도구에 돌아오는 것을 확인했다.

## 첫 결과 화면 전환 시간 재검증

2026-11-24 KST. 이전의 27,399 ms는 여러 GUI 및 해석 검증을 실행하던 세션에서 얻었다. 당시 열어 둔 검증 앱과 하위 프로세스를 종료하고, 동일한 Windows 환경에서 원형 PCB의 별도 사본을 한 번에 하나씩 열었다. 저장된 3D 형상이 표시된 뒤 결과 버튼을 눌렀다. 설계와 3D로 돌아갔다가 결과를 한 번 더 열었다. 첫 진입과 반복 진입은 앱의 기존 전환 로그를 읽었다. 이 값은 버튼 처리 시작에서 작업 공간 전환 반환까지의 시간이다. 보존 원본 두 건과 선택한 원본의 31개 표본 표시는 실제 창에서 별도로 확인했다.

결과 첫 화면의 구성에서 Smith, 전력, 방사, 필드, 후보 비교, 독립 RF 검증, 측정 및 출력의 위젯 생성을 분리했다. 해당 탭을 처음 열 때 만들고 다시 열면 이미 생성된 화면을 사용한다. 재개할 출력 기록이 있을 때는 기존 복구 시점에 출력 화면을 준비한다. 결과 원본과 고정 해시의 조회 조건을 유지한다. 최초 네트워크 화면의 남은 준비 시간은 이번 단독 관찰에서 약 1.3초였다.

같은 Windows 빌드에서 GUI 회귀 10건과 CTest 14건을 통과했다. 첫 결과 진입에서 다른 탭의 위젯을 만들지 않는지, 열린 탭의 위젯을 반복해서 사용하는지, 실제 방사 결과와 RF 보고서가 재열리는지, PDF 생성 및 취소와 CAD STEP 출력이 동작하는지 검사했다. 실제 창에서 10 GHz Ex 단면 42표본, 보존 합성 시료의 원래 Touchstone 표본 5개와 해당 조건도 읽었다.

측정 서비스 회귀 9건도 통과했다. 계측 사본 네 개에서 현재 PCB 개정의 SHA-256과 보존 해석 정규화 원본 세 건의 SHA-256이 각각 동일했다. 수정 후 두 회에 사용한 GUI SHA-256은 `c3507faa67c8c0d0f588e9d3664dc67eb820b90c7f3e67d72be723584e342105`이다.
