# Windows 대형 3D 장면 반복 회수 검증

2026-11-20 KST. 완료 계획 12번 PERF-F5의 대형 3D 표시 구성요소를 같은 Windows 프로세스에서 반복 열고 닫았다. 실제 제품 ModelView가 100만 삼각형 메시의 해시와 원본 대응을 확인하고 첫 wxGLCanvas 프레임과 72,000,000바이트 정점 버퍼를 게시한 뒤 닫았다. 다음 열기 전에는 같은 창과 OpenGL context를 유지하며 닫힌 상태로 최소 30초를 기다렸다. 새 FDTD나 CAD 데이터 생성은 없이 동일한 보존 메시를 사용했다.

## 계측 범위

- 1920 x 1080 표시 영역에서 열기와 닫기 후의 private commit, working set, 핸들 수 및 GPU 사용량을 매회 기록했다. Windows GPU adapter node 0의 local/non-local CurrentUsage를 각각 기록했다. [프로세스 메모리 명세](https://learn.microsoft.com/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex), [GPU 메모리 카운터 명세](https://learn.microsoft.com/windows/win32/api/dxgi1_4/ns-dxgi1_4-dxgi_query_video_memory_info)
- 제품 정점 버퍼는 30회 모두 열 때 한 번 올리고 닫을 때 0바이트로 돌아왔다. 종료 표본이 빠지거나 30초보다 짧으면 집계하지 않는다.
- 초기 안정화 5회와 마지막 10회의 닫힌 상태를 비교했다. F1/F3, 전체 Studio와 서비스/후처리 worker, 기본 120초와 30초 유예가 적용되는 idle 정책은 별도의 범위다. [성능 계획](../04_화면설계/02_화면_선정과_성능_설계.md)

## 관찰값

| 닫힌 상태 | 초기 5회 중앙값 | 마지막 10회 중앙값 | 차이 |
| --- | ---: | ---: | ---: |
| Private commit | 123.19 MiB | 125.38 MiB | 2.19 MiB |
| Working set | 195.79 MiB | 197.29 MiB | 1.50 MiB |
| 핸들 수 | 320 | 316 | -4 |
| GPU local | 151.82 MiB | 151.82 MiB | 0.00 MiB |
| GPU non-local | 0.00 MiB | 0.00 MiB | 0.00 MiB |

종료까지 953.65초였다. 첫 닫기 표본 이후 GPU 장치가 확보한 메모리가 일부 남았다. 제품 버퍼의 논리 해제와 OS 카운터를 별도로 보존하므로, 표의 경향을 전체 앱이나 드라이버의 누수 판정에 확대하지 않는다. 실제 기준 호스트의 F5 전체 메모리 수용은 미확립이다.

실제 30회 이후 판독과 단위 시험 2개, CTest 13개를 확인했다.

## 재현

```powershell
.venv/Scripts/python.exe -X utf8 tools/create_large_display_fixture.py .local/large-display
cmake --build build/windows-release --target tracewave_model_lifetime_probe
./build/windows-release/bin/tracewave_model_lifetime_probe.exe .local/large-display .local/model-lifetime.jsonl
.venv/Scripts/python.exe -X utf8 tools/summarize_windows_model_lifetime.py .local/model-lifetime.jsonl
```

파일을 읽는 두 회의 시험 모드는 300 ms만 대기한다. 실행 기록은 두 표본과 30회 본 실행을 서로 구분한다. [원시 실행 기록](70_윈도우_삼차원_회수실행기록.json)
