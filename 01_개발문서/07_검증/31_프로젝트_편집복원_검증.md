# 프로젝트 편집 복원 검증

2026-11-20 KST. 완료 계획 12번에서 등록 개정, 저장 기준점과 원문을 가진 프로젝트가 다른 작업 영역에서 편집 가능한지 확인했다. [기능 계약](../05_기능설계/01_프로젝트/02_프로젝트_보존묶음과_편집복원.md)의 CLI를 사용했다.

## Windows 저장과 재열기

1. 이전 인계 시험에서 사용한 합성 설계와 복소 원문을 입력으로 사용했다. CLI에서 내보내기 검토·발행과 새 작업 영역의 복원 검토·적용을 수행했다.
2. 1,503,930 B ZIP에서 등록 파일 8개, 명령 1개, 스냅샷 2개를 확인했다. 등록 전에 이미 빠졌던 상위 개정 1개는 색인에 남겼다.
3. [76번](02_실행화면/76_복원프로젝트_스튜디오열기.jpg)과 같이 기존 Studio에서 복원된 프로젝트를 열었다. 표시 이름만 편집하고 [77번](02_실행화면/77_복원프로젝트_편집저장.jpg)에서 새 개정을 저장했다. 종료 후 다시 열어 [78번](02_실행화면/78_복원프로젝트_편집후재열기.jpg)의 이름과 저장 상태를 확인했다.
4. 닫힌 두 작업 영역의 실제 봉인 개정과 스냅샷, 복소 원문 바이트를 비교했다. 원본 작업 영역의 개정과 이름, 복원본의 출처/미정값과 원문은 보존됐다. 대상에 생성된 작업은 직접 수행한 열기/저장에 한했다.

## 회귀 및 확인 범위

원본을 수정하지 않는 발행, 저장과 현재 개정의 차이, 복원 후 실행 취소/다시 실행, 선택 자료 누락, 다른 작업 영역에서의 검토 재사용 거절, 기존 경로와 모의 디스크 오류 뒤 같은 묶음의 재시도를 검사했다. 초기 시험에서 이름 변경 명령을 프로젝트가 지원하는 `metadata.set`으로 정정했다. 원래 보관되지 않은 상위 개정은 명시적인 누락으로 반영했다. [32번 실행 기록](32_프로젝트_편집복원_실행기록.json)에 실행별 관측값을 보존한다.

이번에 확인한 Windows 경로는 CLI 복원 뒤 Studio로 열기·편집·저장·재열기다. Studio에서 직접 파일 가져오기와 검토를 수행하는 연결, 외부 worker 결과의 이관, 전체 UX/성능/EDA-MCP 수용은 12번에 남는다. 새 RF 계산과 제작/측정은 수행하지 않았다.
