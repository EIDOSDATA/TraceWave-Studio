# 실행 소스 묶음 검증

개발 완료 계획 7번 선행 작업. 기준 커밋은 `a256bf51f7b0959f814b6b524a123421827e2edf`다. [실행 소스 계약](../03_아키텍처/06_실행소스_묶음과_환경식별.md)의 명시 profile/전이 의존성/소스 원문 보존과 과거 결과 읽기 호환을 검증했다. 실행 날짜는 2026-11-17 KST이며 로그/보고서의 원래 UTC 시각과 해시는 [실행 기록](16_실행소스_묶음_실행기록.json)에 보존한다.

파일 192개와 CAD 2 MiB/solver 4 MiB 상한, 프로젝트/출처 원문, 기존 runtime/승인 원문/과거 검증 기록을 변경하지 않는다. 실제 native 시험은 모듈 포장과 실행/저장/재열기의 동등성 검증이며 새 RF 물리 수용이 아니다. 이 기록은 7번의 다중 결과/Smith/3D 방사/필드 GUI 완료 기록과 구분한다.

## 1. 최종 실행 소스

마지막 제품 변경은 bootstrap의 바이트 상한 읽기/검증한 동일 bytes 실행, `max_files`의 1..192 검사다. 이후 아래 최종 회귀와 실제 native 실행 동안 제품 Python/worker를 동결했다. 실제 CAD/PCB/TE10 결과의 descriptor와 `code_files`를 문서 마감 시 현재 캡처한 목록과 대조했다.

| 실행 profile | 논리 Python 파일 | 원문 bytes 합계 | source JSON bytes | 유지한 상한 |
| --- | ---: | ---: | ---: | --- |
| CAD | 33 | 226929 | 240299 | 192개, 2097152 bytes |
| openEMS 및 supervisor | 79 | 659241 | 697347 | 192개, 4194304 bytes |
| host 계산 식별 | 160 | 1440673 | 1529602 | 192개, 4194304 bytes |

CAD의 파일 수에는 별도 entry를 포함한다. 각 source JSON은 전이 의존 소스의 본문 전체를 포함하며 압축 파일 수로 상한을 우회하지 않는다. host 계산은 이 목록의 identity를 보존하는 계약이며 worker와 같은 본문 archive를 보존한다는 뜻은 아니다. 개별 파일/원문 묶음/최종 변경 파일 해시는 실행 기록에 있다.

## 2. 최종 회귀

서로 겹치는 실행을 하나의 통과 총수로 더하지 않는다. 아래 행은 각기 독립된 실행이며 전체 서비스 수집이나 전체 GUI 재검증을 수행했다는 주장이 아니다.

| 실행 | 수집/결과 | 초 | 확인 범위 |
| --- | --- | ---: | --- |
| `source-bundle-cad-frozen.log` | 17개 통과 | 48.243 | 독립 소스 경계 15개 + 실제 staged OCCT 2개 |
| `source-bundle-host-corrected.log` | 95개 중 92개 통과, 3개 환경 제외 | 134.565 | closure, host 연구/RLC/S-Z-Y/목표 평가, runner, PCB, WSL 수명/준비 |
| `source-bundle-supervisor-final.log` | 16개 통과 | 94.787 | 실제 Linux PID/start identity/flock/pidfd, 시작 중 취소, launcher 소실 |
| `source-bundle-arc-ifa-final.log` | 1개 통과, 실제 형상 2사례 | 28.713 | 원호/IFA STEP와 출처/미정 및 재열기 |
| `source-bundle-power-final.log` | 실제 WSL workflow 통과 | 93.797 | PCB 준비/계산/NF2FF/손실/후처리/취소/재열기 |
| `source-bundle-te10-final.log` | 실제 WSL workflow 통과, 2격자 | 113.078 | TE10 준비/계산/후처리/재열기 |
| `source-bundle-legacy-reopen.log` | 과거 실제 결과 동일 조회 | 미계측 | 구형 189파일 결과, runtime 없는 복사본 재열기 |

최종 호스트 실행에서 제외한 3개는 실행 환경 플래그가 필요한 실제 WSL 시험이다. 실제 WSL 검증은 별도 workflow와 Linux supervisor 실행으로 구분한다. 로그와 보고서는 `Code/.local`의 로컬 실행 증거이며 버전 관리되는 실행 기록에는 경로/바이트/해시/수치/시점을 보존한다.

독립 소스 경계에서는 함수 내부/실행하지 않은 조건 분기/상대 import/부모 package를 포함하는지, 무관한 파일이 identity를 바꾸지 않는지 확인했다. 추가/누락 파일, 변조, root 탈출, 미등록 동적 import, 설치된 `rfad` fallback, pyc 대체, 미리 로딩된 제품 모듈을 거부한다. 개별/합계 크기, 192개 제한, 193개 실제 의존 사슬, 외부 custom entry, CRLF/LF 차이도 확인했다. import는 확인한 동일 bytes를 실행한다.

기존 CAD/solver source capture/jobs의 첫 집중 61개는 204.487초에 통과했다. 이 결과는 마지막 bootstrap 보강 전의 중간 시점이며 최종 17개/95개 회귀와 합쳐 새 전체 통과 수로 세지 않는다.

## 3. 실제 OCCT

격리된 고정 CAD runtime으로 다음 분기를 확인했다.

- 원호/평면 IFA: 각 실제 STEP 생성, 원문 출처 및 미정값 보존, CAD runtime 없는 재열기.
- 평면 영역의 구멍/패드/PTH: staged 파일 집합과 hash, pyc 부재, STEP/mesh 생성, tool 미정 및 source semantics 보존.
- 적층 표면 개구와 외부 STEP: 실제 STEP 검사/미리보기/적용/출력, 원문 bytes/hash, 재료 미정, runtime 없는 재열기.

새 CAD profile의 33파일 목록은 호스트와 실제 staged worker에서 일치했다. 마지막 두 사례의 `TemporaryDirectory`는 시험 종료 후 제거되었다. 실행 기록에는 생성 당시 artifact 식별과 보고서를 보존하며 STEP 실파일이 현재 남아 있다고 주장하지 않는다. PTH의 CAD 형상 생성은 GHz PTH 손실 정확도 검증과 다르다.

## 4. 실제 WSL openEMS

명시 시험 가정의 원형 PCB에서 31개 복소 표본을 계산했다. 실제 종료 기준 도달, 준비/분석 계획과 source 캡처, 후처리 표본/방사 결과 동일성, 편집 중 snapshot 보존, solver 없는 재열기를 확인했다. 별도 실행을 실제 취소하여 guest 종료 확인과 이전 결과 보존도 확인했다.

한 10 GHz 표본의 NF2FF와 E/J 체적 손실, E/rotH sheet 손실 분기를 실행했다. 유전체 구성요소 1개와 도체 sheet 3개가 있으며 `via_components`는 비어 있다. 원문 normalization은 `pulse_fourier_spectrum_common_squared_time_scale`, 전력 단위는 `W*s^2`, 절대 전력은 `null`이다. 전체 전력 수지의 상대 잔차 -0.004215341404542519는 이 시험의 초기 수치 예산 0.03 안에 들었다. `physics_validated`, `fabrication_validated`, `measurement_validated`는 모두 `false`다.

별도 TE10 참조 workflow에서는 1.0/0.75 mm 두 격자의 준비/계산/후처리와 재시작 후 결과 동일성을 확인했다. 기존 참조의 반사/전송/임피던스/군지연 및 격자 차이 기준을 통과했다. 이 두 격자 실행을 일반 안테나 수렴이나 새 독립 RF 물리 정확도 합격으로 확대하지 않는다. 두 실제 workflow의 원본 workspace와 결과는 로컬에 보존했다.

## 5. 과거 결과와 재개 경계

6번에서 실제 완료한 구형 189파일 source bundle 연구를 별도 경로로 복사했다. native runtime을 구성하지 않고 과거 `sweep.result` 응답 전체를 동일하게 읽었다. 구형 identity에 새 descriptor를 붙이거나 원본 workspace/보고서를 수정하지 않았다. 과거 보고서 SHA256은 `3071fb4b38c824b8156c10339d35fa7bfcec74ce0f5779f556455cac3c62cd16`이다.

host 연구 회귀에서는 구형 `0.1` source profile의 자료 조회는 허용하되 새 `0.2` 계산 환경으로 재개하는 것을 차단했다. source hash가 같더라도 profile 차이를 무시하지 않으며 definition/journal 원문을 유지했다. source/runtime 변경 차단, 기존 compact/inline 조회, host RLC/S-Z-Y와 목표 계산도 관련 회귀에서 확인했다.

## 6. 중간 실패와 증거 시점

다음은 제품 실패를 숨기거나 최종 실행에 합산하지 않고 별도 보존한 시험 작성/호출 오류다.

| 로그 | 결과 | 원인과 후속 |
| --- | --- | --- |
| `source-bundle-independent.log` | 11개 중 오류 1개, 5.284초 | 시험 metadata의 bytes를 JSON으로 기록. metadata/파일 목록만 기록하도록 수정 후 11개 통과, 경계 확장 후 최종 15개 포함 통과 |
| `source-bundle-cad.log` | 2개 오류, 26.131초 | 실제 생성/보존 검사 뒤 재열기 조회를 없는 coordinator 메서드로 호출. 공개 RPC로 수정 후 2개 24.513초 통과, bootstrap 보강 후 최종 재실행 |
| `source-bundle-host-final.log` | 70개 중 66개 통과, 2개 제외, 오류 2개, 65.513초 | 존재하지 않는 두 시험 모듈명 호출. 실제 network domain 시험은 통과했으며 올바른 목록으로 최종 95개 실행 |

처음 compact PCB/원호/IFA/전력 workflow와 중간 독립 경계 실행도 각각 원래 로그 시점으로 남긴다. 최종 제품 소스 동결 이전 실행을 동결 이후 실행으로 소급 표시하지 않는다.

## 7. 유지한 미확립 사항

RO4350B 국부 방사 도체 손실 변화 2.788446%로 초기 2% 기준은 여전히 미확립이다. GHz PTH 손실의 독립 물리 정확도, 실제 제작/납품 물성/급전 실장/측정 조건도 임의로 확정하지 않는다. 이번 source 포장 보강과 총 전력 수지/종료 조건 통과를 개별 손실/실측 정확도 합격으로 확대하지 않는다. 새 GUI/3D 방사 표현/필드 페이지와 최종 성능 수용은 이 선행 검증 범위에 포함하지 않는다.
