# Windows 작업공간의 다중 급전 해석과 결과 재열기

## 사용자 경로

1. 프로젝트에서 실제 도체와 접점을 연결한 lumped 급전을 2~4개 작성한다. 각 포트에는 신호 도체와 기준 도체, 전압 방향, 측정 기준면, 양의 실수 기준 저항이 필요하다.
2. 해석 탭의 `해석 조건 확인 및 실행`에서 수치 조건을 직접 입력하거나 저장한 조건을 불러온다. 검토를 누르면 포함 형상과 격자 표에 모든 급전과 간극이 표시된다. `종료 / 기록 출력`에는 P번호별 객체 이름, 기준 저항, 기준면과 전체 계산의 예산이 표시된다.
3. `전체 S 행렬 실행`을 누른다. Windows 서비스가 현재 설계 개정을 스냅샷으로 고정하고 WSL2 worker가 모든 포트의 수동 종단을 유지한 각 여기 XML을 준비한다. 준비 후의 계산은 해당 XML 바이트를 그대로 사용한다. 취소와 종료 상태는 기존 작업 감독과 같은 경로를 사용한다.
4. 계산이 끝나면 네트워크의 `완료 해석 결과 등록`에서 해당 결과가 선택된다. 이름을 지정하여 후보 검토와 등록을 누른다. 네트워크 탭에서 S11부터 S44까지 입력과 출력 포트를 골라 복소 표본을 조회하고 Touchstone, CSV, HDF5로 내보낸다. 저장한 네트워크 자료는 프로젝트 재개방 후에도 같은 개정과 측정 기준면을 가리킨다.
5. 해석 탭의 `해석 입력과 출처`에는 각 포트와 단자 도체의 원본값이 표시된다. `결과 조건 다시 사용`에서는 원본 개정의 설정과 현재 개정을 비교한다.

## 해석 및 출처

Windows 공개 요청 `solver.preview`, `snapshot.create`, `solver.plan`, `solver.prepare`, `job.submit`에 `rfad.openems.pcb-multiport/0.1` 계획을 연결했다. 모든 단자가 같은 Yee 격자에 실제로 접촉하는지 확인하고, 포트마다 전압/전류 원시 파형과 XML, 시간 단계 통계, 에너지 종료 로그를 봉인한다. 호스트는 원본 개정과 설정의 해시, 모든 XML과 파형 파일 해시, 각 측정 기준면과 저항, 주파수 표본, 저장할 Touchstone의 값을 대조한다.

프로젝트 작업공간에 스냅샷 원본, 실제 준비 XML, 원시 파형, 당시 계획, 전체 복소 결과가 남는다. `network.apply`로 등록한 결과는 당시 개정과 파일 해시를 유지한다. 개정 교환용 `.rfad.zip`의 기존 범위는 설계 개정과 등록 원문이다. 전체 실행 이력과 네이티브 파형까지 보존하려면 원래 작업공간을 사용한다.

## Windows 서비스 검증

2026-11-23 Windows에서 검증용 원형 PCB 개정 `ecd6f97f-76d4-5686-a20b-dc3b9e0f608b`를 실제 WSL2 openEMS 0.37.0으로 계산했다. 원본 SHA-256은 `59629ca252f7b1bcb36d565211aae6ab5689ede7934a903201714641df92f893`이고, 네 포트 공통 격자 해시는 `b24fe4cdd010f242d572840c70057abe5ab570004dd2c3d3609e7a0f8b1a32c9`이다.

| 여기 | 기준 저항 (ohm) | 실제 시간 단계 | 종료 감쇠 (dB) |
| --- | ---: | ---: | ---: |
| P1 | 70 | 1015 | 42.12 |
| P2 | 50 | 1190 | 41.98 |
| P3 | 65 | 1015 | 40.51 |
| P4 | 75 | 980 | 41.27 |

네 포트가 모두 40 dB 에너지 감쇠 목표에 도달했다. 계산 결과 ID는 `78ff65bb-ceda-4a77-97e2-c9f7a15035b9`다. 정규 결과 SHA-256은 `47fbe127915b362e727bb14e7542bef846ad562b4b4adbff37009ff0533c49a8`이고 산출물은 59개다. 전체 31개 주파수의 496개 복소 값은 독립 CalcPort와 대조한 384 검증의 CLI 결과와 최대 복소 차이 0으로 일치했다. 첫 주파수의 S43은 약 0.35808353 - j0.10076937이다.

같은 작업공간에 보존한 전압/전류로 FDTD 재실행 없이 후처리한 결과 ID는 `070ab87b-3f3c-4a3a-89e5-c4ba356e3f7f`다. 전체 네트워크 자료가 최초 계산과 일치했다. 네트워크에 `aa87e8cf-2f6a-53ac-87ba-61a41632659f`로 등록하고 서비스를 종료한 뒤 다시 열어 S43의 31개 표본과 최초 스냅샷 전체를 대조했다. 이 Windows 통합 시험은 630.248초에 통과했다. 등록 후 현재 개정이 `28ab6c09-fa4b-4a21-a045-a4d78462b869`로 바뀐 상태에서 포트 4개 각각의 객체 상세, 단자 연결표와 조건 복원을 공개 API로 열었다. 원본에는 계속 최초 설계 개정이 표시됐다.

보존된 설계와 포트 순서를 변경한 계획의 거절, 네 포트와 각각의 신호/기준 도체 연결, CSV/HDF5 왕복 및 2포트 전용 연산의 경계를 별도 시험으로 확인했다. 실제 제조 및 측정 조건은 미정이다. 다중 포트의 전계, 방사 및 손실 기록은 독립 여기를 합성할 물리 조건이 필요하므로 이 기능은 S 행렬만 출력한다.

## 재현

### 실제 Windows 화면

Windows release 실행 파일에서 원형 기판 검수 프로젝트를 열고 이름으로 저장한 조건을 선택했다. 기본 입력과 달라진 값 8개, 급전 및 설치 차이 0개를 확인했다. 현재 개정 `6fe3ab42-90ae-471e-a0e1-948f88e7388a`의 네 급전을 모두 검토했고 공통 X/Y/Z 격자선은 77/77/28, Yee 셀은 155952개였다. [격자와 네 급전](02_실행화면/102_네개급전의_공통격자_검토.png)

첫 시도에서 Windows 입력 파일 125개 중 123개를 복사한 시점에 WSL 준비 프로세스가 60.283초 제한으로 종료되었다. 실제 worker 인계 전 종료임을 확인했다. 입력 및 출력 파일 전송 기한을 240초로 분리하고 WSL 준비 60초, 상태 조회 10초, 해석당 계산 예산은 유지했다. Windows 서비스가 시작될 때 CPU를 확인하던 WMI의 반복 네이티브 종료도 커널 조회로 교정했다. 통합 검증 중 최초 서비스 응답이 30초를 넘은 세션 한 번은 닫고 다시 열었다.

같은 조건의 `전체 S 행렬 실행`으로 네 여기와 후처리가 완료되었다. 결과 ID는 `6c911d73-3a22-4166-9e30-b2e90cf8a969`, 정규 결과 SHA-256은 `edb7466a9e2e2dcda9ff83fbd37860380bab64ad2702e55f342b1a2f0edc4847`이다. 자동 표시된 결과로 등록 후보를 검토하고 등록했다. 채널 목록의 S11부터 S44까지 16개 중 S43을 선택했다. 첫 8 GHz 표본은 0.35808353 - j0.10076937, -8.5893207 dB, -15.717294도였다. 31개 표본과 네 포트 저항/기준면을 표시한 채 저장했으며, 현재 개정과 저장 개정 `58ab08ac-3472-42a8-9fd5-8a61bf3daf5f`가 같았다.
