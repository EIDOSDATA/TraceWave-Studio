# 대형 설계 편집 복원과 상호 운용 검증

2026-11-21 KST. 12번의 보존 묶음은 대형 설계 정규 문서의 저장 경계를 사용한다. 편집 복원 ZIP은 64 MiB까지 검토·발행·수신한다. 개정과 스냅샷의 바이트 읽기, 전체 ZIP의 한도와 파일 수를 각각 검사한다. 구간 조회는 파일 전체 SHA256을 스트리밍 검증하면서 128 KiB만 응답한다. 복원은 1 MiB 버퍼로 항목을 복제하고 모두 봉인한 뒤 대상 상태를 게시한다. 읽기 전용 보고서 ZIP의 한도는 8 MiB다.

형상 10000개와 매개변수 1000개를 가진 시험 설계에서 18,355,908바이트의 편집 복원용 ZIP을 발행했다. 첫·마지막 전송 청크, 전체 SHA256, 검토/예약/등록과 스냅샷을 확인했다. 새 작업 영역의 실제 Windows Studio에서 개정을 열고 저장한 뒤 서비스를 다시 시작했다. 형상과 매개변수 수, 표시 생략 0개, 재료·직접 입력·출처·미정값을 확인했다. [실행 기록](126_대형설계_편집복원_실행기록.json)

journal·복원·인계·봉인·정규 바이트 서비스 회귀 47개가 통과했다. Windows에서 일반 편집, 출력, 대형 복원과 후보 채택의 실제 조회 실패를 확인했다. 후보 채택 시험은 editor.page와 canvas.page를 차례로 일회 실패시켰다. 두 실패 뒤 편집 잠금과 생성 영수증을 유지했고, 재조회 후 이미 만든 사본을 복구했다. 최초 시험은 이전 get 메서드에만 오류를 주입했으므로 최신 page 경로에서 다시 실행했다.

공식 MCP Python SDK의 stdio 클라이언트와 실제 KiCad 10.0.8에서 발행, 별도 편집, 재수입 왕복을 확인했다. 원문과 미정 필드 및 작업 영수증을 따로 대조했다. 64 MiB 근처의 최대 규모, 전체 Windows 접근성과 여러 EDA 도구의 수용은 추가 검증 범위다.
