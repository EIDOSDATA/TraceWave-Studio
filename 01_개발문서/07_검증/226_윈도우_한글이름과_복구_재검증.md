# Windows 한글 이름 저장과 작업 영역·복구 재검증

2026-11-21 KST. 편집 우선 시작과 WSL2 취소 개선을 연결한 Windows Release를 2560 x 1600, 150%의 내장 화면에서 실행했다.

프로젝트 탐색의 선을 선택하고 F2로 이름 변경을 열었다. 이름란에 완성 한글 문자열을 넣어 Enter로 적용하고 Ctrl+S로 저장했다. Studio를 종료한 뒤 새 프로세스로 같은 프로젝트를 열었을 때 탐색 트리에서 이름을 확인했다. 저장 원본을 서비스에서 다시 읽어 이름 외 형상과 기존 출처, 제작·측정 미정값을 대조했다.

F6으로 프로젝트 탐색, Shift+F6으로 설계 버튼에 초점을 옮겼다. 오른쪽 방향키로 해석·결과·비교·출력을 차례로 열고 각 작업 영역의 버튼 초점을 확인했다. 처음 연 해석 화면은 구성 후 해석 버튼에 초점을 돌려주었다. Home으로 설계 버튼에 돌아왔다. [이전 작업 영역 키보드 검증](182_스튜디오_작업영역_키보드전환_검증.md)

Windows 화상 키보드의 한/영 키도 시험했다. 해당 창의 Windows 무결성 수준이 자동화 도구보다 높았고, Studio 이름란에서 Latin g가 들어가 자모 조합을 확인하지 못했다. 시험 뒤 화상 키보드는 접근성 설정에서 껐다. 실제 한국어 키보드의 자모 조합 중 Enter, 스크린리더 음성과 서로 다른 모니터로의 이동은 별도 검수가 필요하다.

저널, native 프로세스, 인계 ZIP 등 관련 시험 40개가 통과했다. 그중 실제 Windows GUI는 원문 손상 차단·복구, 작업 영역 잠금, 저장 중 디스크 부족 오류 주입 후 복구, 여유 공간 접수 차단 후 재시도, 한글 경로의 저장·스냅샷·재시작 다섯 경로다. 손상 복구는 첫 실행에서 출력 폴더가 없어 검증 기록 쓰기가 실패했다. 새 폴더를 만들어 같은 GUI 시험을 다시 통과했다. 실제 프로세스의 게시 전후 종료와 자식 회수도 확인했다.
