# Windows 통합 묶음 수신 검증

2026-11-20 KST. 완료 계획 13번에서 편집 조회 전송과 WSL 취소 보강을 포함한 `c253881003ff788d5b0e016ba2145c26e43f4e15`를 Windows 내부 검증 ZIP으로 받는 과정을 확인했다.

## 실행 파일과 묶음 식별

앞서 검증한 별도 소스 경로에 이번 native 변경 파일 4개를 반영해 Release를 다시 빌드했다. 두 경로에서 CTest를 각각 13개 통과했다. 원본 빌드, 별도 경로 빌드, 수신 폴더의 EXE는 모두 30437987 bytes이며 SHA256이 일치했다. 이 비교는 같은 Windows 호스트의 두 빌드 경로에서 수행했다. [독립 경로의 선행 검증](79_윈도우_독립경로_재빌드검증.md)

동일 입력으로 생성한 ZIP 두 개는 각각 13881765 bytes이며 manifest에 기록한 파일은 932개다. 두 ZIP의 SHA256은 `7dcdee2a5c3513e007c337b23973efcba2c9e151269592e52a2393f217ab9d48`이다. 수신 폴더의 EXE SHA256은 `4b48e0e25006c9f0518788efb77b95f323f030daa488340c6e491fd8d36a9223`이다. [해시와 원시 실행 기록](89_윈도우_통합묶음_수신실행기록.json)

## 수신 폴더의 편집과 재열기

새 한글 경로에 압축을 풀고 새 CPython 3.12.10 환경을 사용했다. 실행 경로에는 Windows와 System32만 두었다. 기본 2D 작업에서 선·원호, 스냅·끝점, 저장, 스냅샷 및 서비스 재시작 뒤 재열기를 확인했다.

같은 수신본에서 별도 큰 설계 시험 두 개를 실행했다. 기본 응답 한도를 넘는 조회의 오류 ID와 새 전송 한도를 대조했다. 250개 2D 형상이 있는 설계를 실제 GUI에서 열고 프로젝트 속성을 바꾸어 저장한 뒤 새 서비스에서 열었다. 기본 및 큰 설계 GUI 실행에서 저장 개정과 재열기 개정이 일치했다. 큰 설계의 기판, 도체 이름과 출처, 재료, 적층 및 포트 원본은 시험 입력과 같았다. 로컬 묶음 도구와 요구 추적 감사 시험 17개도 통과했다. [큰 설계의 입력과 조회 계약](86_윈도우_큰설계_표시와_재열기_검증.md), [시험 코드](../../Code/tests/test_edit_view_transport.py)

## 검증 범위

이번 수신 시험은 선택 worker가 없는 기본 설치 범위다. 실제 OCCT 및 WSL worker 검증 결과는 해당 묶음의 별도 실행 기록을 참조한다. 같은 소스 커밋의 전체 서비스 회귀와 별도 Windows 설치 이미지 검수는 별도로 관리한다. [이전 묶음의 선택 worker 검증](77_윈도우_내부묶음_외부환경_검증.md), [내부 검증 지원 범위](../08_운영환경/06_내부검증_지원범위와_미결.md)
