# Windows 잔여 화면과 시간 초과 재검증

2026-11-22 KST. 기준 소스는 53d4425다. [이전 캡처 검수](313_윈도우_실행화면_캡처와_사용성_검수.md)가 부분 확인으로 남긴 13개 화면을 [승인 시안 목록](../04_화면설계/13_전체화면목록.json)에 맞춰 재검수했다. 전용 조작을 확인하지 못했던 3D 단면과 통합 채택 이력도 같은 Windows 11, 150% 배율의 실제 Studio 창에서 확인했다. 프로젝트는 검수 사본과 기존 실행 결과를 사용했다. 실제 제작 및 측정 조건은 미정이다.

## 부분 확인 13개

| 화면 | 개선 및 캡처 확인 |
| --- | --- |
| S00.recovery 저장본과 복구 후보 | 저장본과 현재의 영속 적용 개정을 같은 표에서 비교한다. 이름을 변경하고 아직 저장하지 않은 IFA 사본에서 양쪽 개정과 이름을 확인했다. 현재 개정 다시 읽기와 별도 작업 영역의 보존 묶음 복원은 기존 명시적 동작으로 연결한다. |
| S11.endpoint 스냅과 끝점 편집 | 색과 기호에 끝점 또는 격자라는 텍스트를 더했다. 같은 층의 선 끝점과 격자 위치, 선택한 급전선의 편집 핸들을 각각 캡처했다. |
| D10.criteria 목표 성능 기준 | 대역과 기준면, 성능 기준을 각각 펼치거나 접는다. 사본에 저장한 S11 기준과 미정 효율을 동일한 화면에서 확인했다. |
| D11.preview 문헌 후보 형상 | 검토 기준 개정과 공통 버튼 계층을 적용하고 실제 표시 크기에 맞춰 생성 도체를 강조한다. G031 원문 치수와 직접 넣은 배치를 실제 형상으로 보고, 적용 전 검토 상태를 캡처했다. |
| S20.mesh 메시와 자원 | 같은 PCB 계획 코드의 자원 예상치와 설계 눈금을 구분한다. IFA 사본에서 0.4 mm 격자와 5 mm 공기 여유로 예상 격자점 1,068,940개와 약 291.1 MiB를 표시했다. 30 mm 여유의 상한 초과 조건은 실행 불가로 표시했다. |
| D23 수렴 보고서 비교 | 보고서 파일명, 기존 수치 표와 판정을 같은 화면에서 읽는다. 저장된 IFA 방사 수렴 JSON을 열어 메시, 기록 경계, 각도별 행을 확인했다. |
| UI24.source 출처와 채택값 | G031의 원문, 채택 당시 입력, 현재 생성 형상 값을 구분했다. 원문 위치, 해시와 선택한 행의 상세를 읽을 수 있다. |
| UI01.unknown 적용 응답 미확정 | 적용을 잠그고 닫고 개정 확인 동작을 표시한다. 별도 사본에 주입한 서비스 오류로 재현하고, 닫은 뒤 영속 개정을 다시 읽는 동작을 확인했다. |
| D20.output 해석 종료와 기록 출력 | 최대 시간 단계, 종료 에너지 비율, 기본 복소 출력, NF2FF, 독립 손실과 내부 필드 기록 범위를 나눠 표시한다. 준비와 계산은 시작하지 않고 검토 창을 닫았다. |
| D10.history 목표 출처와 변경 이력 | 선택한 목표 ID의 출처와 변경 행을 읽고 원래 목표 편집 화면으로 돌아갈 수 있다. |
| S11.port.terminals 급전 양단 도체 | 오른쪽에 신호 및 기준 도체 이름을 상시 표시한다. 두 버튼을 각각 눌러 패턴 트리, 2D 선택과 속성을 이동한 뒤 급전으로 돌아왔다. |
| S11.port.reference 급전 기준면 | 급전 속성 바로 위에 기준면 및 저항과 유효 대역 출처 수를 표시한다. 시험 사본에서 집중 포트 급전 영역과 출처 3건을 확인했다. |
| UI24.assumptions 출처 가정과 생략 | G031 보존 사본에서 포함 범위, 생략과 미정 항목을 별도 탭에 표시했다. 부분 기하 생성, 초기 추정, 해석, 수렴 및 실측 상태의 의미를 구분한다. |

## 이전에 전용 화면을 찾지 못한 2개

- S12.section. 기준 소스에는 3D 메시 표시와 선택이 있었고, 단면의 축이나 위치 또는 유지 방향을 조작하는 기능이 없었다. 현재 3D 형상에서 X/Y/Z 평면과 설계 원점 기준 mm 위치, 남기는 쪽을 지정한다. IFA X=20 mm에서 양방향과 전체 형상을 캡처했다. 클리핑된 면을 선택에서 제외하고 원본 메시, 설계 및 STEP을 보존한다. 단면 채움과 잘린 형상의 내보내기는 제공 범위 밖이다.
- UI24.history. 기준 소스에는 문헌과 스윕의 보존 레코드 및 개정별 실행 취소 이력이 있었다. 이를 한 창에 표시하는 메뉴가 없었다. 현재 보기 메뉴에서 문헌과 스윕 채택값, 목표의 보존 출처, 현재 개정의 변경 이력과 저장본을 확인한다. 현재 계보의 최근 최대 24개 변경을 읽는다. 원문 위치와 해시는 보존 사본에서 읽고 원문 파일의 외부 접근은 이 화면에서 자동으로 시도하지 않는다.

## 시간 초과 시험

| Windows 시험 | 이전 멈춤 지점 | 재검증 |
| --- | --- | --- |
| 지연 응답의 목표 및 문헌 입력 보존 | 실행에 따라 G031 미리보기 대기(29단계) 또는 저장 완료 대기(33단계). 전체 GUI 시험 제한에 도달했다. | 기준 빌드와 수정 빌드에서 35단계까지 통과. 의도적으로 지연한 응답에서 최신 입력과 선택을 보존했다. |
| 다각형 구멍, 패드 및 비아 속성과 이력 | 기존 빌드에서 미정 비아 입력 중 서비스 응답 제한. 다른 실행에서는 편집(11단계) 또는 스냅샷 완료 대기(20단계)에 전체 GUI 시험 제한에 도달했다. | 기준 빌드와 수정 빌드에서 통과. 편집, 실행 취소와 재실행, 저장과 재열기를 확인했다. |

이전 실패에는 요청별 도달과 응답 기록이 없어 근본 원인을 확정하지 못했다. 기준 빌드 재실행은 2개 시험이 47.968초에 통과했다. 서비스 내부 추적 199개가 쌍을 이루었고 최장 처리 시간은 0.360초였다. 수정 빌드는 일반 목표와 문헌 저장 및 명시·미정 급전을 더한 5개 시험이 184.429초에 통과했다. 추적 584개가 쌍을 이루었고 최장 처리 시간은 0.453초였다. 서비스 내부 처리 시간은 GUI 큐 대기와 프로세스 외부 지연을 포함하지 않는다. 캡처 최종 빌드에서도 두 시간 초과 시험을 다시 통과했다. 기존 제한 시간을 유지하고 이후 실패에 대기 수, 가장 오래된 RPC 이름과 경과 시간, GUI 시험의 작업 중 여부를 남긴다. 요청 본문은 기록하지 않는다.

- 서비스 회귀 19개를 통과했다. 이번에 추가한 검토 시험은 2개다. 목표별 변경 필터, 저장 개정 대조, 해석 메시 자원 계산 뒤 파일과 journal 보존을 확인했다.

- 승인 시안과 이전 Windows 검수, 제조·실측 조건, 기존 해석 및 출처의 원본 기록을 보존했다. 다른 PC에서의 공개 후보 독립 수신 상태는 [13번 인계](310_공개_검증후보_배포와_독립수신_인계.md)를 따른다.
