# 대형 2D 이동·드래그와 일반 3D 합성 검증

2026-11-21 KST. 완료 계획 12번 F1의 확대에 이어 Windows 화면에서 2D 이동과 선 드래그, 일반 3D 회전·이동을 계측했다. 2D는 네 층의 형상 10000개 표시 장면을 사용했다. 3D는 동일 ModelView, wxGLCanvas, 정점 버퍼와 실제 표시 파일 로더로 삼각형 100000개, 정점 50652개인 두 바디를 열었다. 3D 입력은 표시 전용 시험 자료다. [2D 확대 대조](109_대형설계_화면합성_검증.md)

35초 동안 전경에서 실제 화면의 합성 시각과 입력 번호를 확인했다. 2D는 가운데 버튼 이동 또는 실제 좌버튼으로 선택한 이동 가능 선의 드래그를 사용했다. 드래그를 취소하므로 원본 위치는 변하지 않는다. 3D는 고정 시점에서 회전과 수평 이동을 번갈아 실행했다. 출력은 2560 x 1600, 120 Hz, DPI 144였으며 2D 캔버스는 1000 x 700, 3D는 1920 x 1080이다.

| 동작 | 합성 간격 수 | p95 (ms) | p99 (ms) | 최대 (ms) | 입력-합성 p95 (ms) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2D 이동 1회 | 1760 | 25.49 | 31.99 | 42.06 | 35.49 |
| 2D 이동 2회 | 1760 | 25.48 | 31.71 | 34.11 | 35.37 |
| 선 드래그 | 1779 | 25.41 | 25.97 | 32.29 | 32.20 |
| 일반 3D 회전·이동 | 4005 | 10.33 | 16.88 | 27.28 | 10.37 |

2D 이동 p95는 25.48~25.49 ms, 드래그는 25.41 ms였다. 일반 3D의 p95는 10.33 ms였고, 이 합성 표본에서 60 fps p95 목표 16.67 ms를 충족했다.

첫 드래그 준비에서는 조밀한 형상에 대해 좌표로 고른 선과 실제 hit-test가 고른 선이 일치해야 한다고 가정해 입력 전에 종료했다. 실제 처리기가 선택한 이동 가능 선에서 시작하도록 시험을 보완해 재실행했다. [원시 실행 기록](112_대형설계_이동과_삼차원_실행기록.json)

기존 100만 삼각형 생성의 동일 SHA256을 확인했고 표시 메시 및 합성 시각 회귀 12개를 통과했다.

재현에는 Windows 합성 도구의 `--scene-pan`, `--scene-drag`, `--model-general`을 사용한다. 일반 3D 자료는 `create_large_display_fixture.py --general`로 만들 수 있다. 전체 F1의 표 스크롤·100000개 검색, 2D 프레임 목표, 전체 앱 자원 수용은 남는다.
