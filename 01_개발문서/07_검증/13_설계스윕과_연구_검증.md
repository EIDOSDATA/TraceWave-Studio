기록일: 2026-11-17 KST. 개발 완료 계획 6번. 기준 커밋은 `f79edaaf9d8740ffcc7c93c7a0d6f8ecf6fca479` 이후 작업 트리다. 실행 시점/범위/로그와 실제 source identity는 [실행 기록](14_설계스윕과_연구_실행기록.json)에 구분한다. 이후 게시 커밋을 과거 실행 기준으로 소급하지 않는다. 아래 명시 지원 범위의 서비스/GUI/저장/재열기 검증을 마쳤으며 RF/실측 수용은 별도다.

## 구현 범위

[명시적 연구 계약](../05_기능설계/06_연구/01_명시적스윕과_실행계약.md)과 [화면 계약](../04_화면설계/20_설계스윕과_연구_화면.md)에 따라 리터럴 매개변수, 허용한 수치 설정, 외부 이상 회로의 값/실장 상태를 유한 조합으로 생성한다. 원본 snapshot과 입력 원문은 봉인하고 현재 프로젝트 개정/이력은 바꾸지 않는다. 기존 `study.*` 한 축 격자 연구는 유지한다.

설계 유효성, 실제 준비/해석, 목표 표본 평가, 수치 수렴과 실측 검증을 구분한다. 실패/미지원 후보와 원문 미정값을 보존하며 동일 물리 입력의 결과 재사용도 별도 후보로 기록한다. 재개는 완료 자료의 해시와 환경을 확인한 작업 단위 재개다.

명시 조합의 순서/중복, 전체 후보를 앞서 만들지 않는 생성, 결정적 후보 개정, 표현식 의존 관계의 일괄 변경, 비유한 수량/underflow, 원문 source_refs, 단위만 다른 동치 입력, 기판 밖 도형과 미지 확장을 확인했다. 회로 후보는 PCB 형상과 독립적으로 기존 네트워크 자료를 사용하며, 기준면과 필수 소자가 미정이면 계산을 차단한다. 목표 주파수/포트/기준면을 임의 보정하지 않는다.

독립 검토에서 연구 생성 예산이 이미 알려진 거절인데도 snapshot/definition을 먼저 게시하는 경계를 발견했다. snapshot을 준비하는 단계와 게시하는 단계를 분리해 정확한 파일 비용을 검사한 뒤 게시한다. 회로 재개의 환경 식별에도 설치 패키지뿐 아니라 앱 계산 소스 전체와 Python ABI를 추가했다. 과거 definition과 결과는 수정하지 않는다.

구형 inline 작업과 새 `rfad.solver-capture/0.1` 참조 작업을 함께 읽는다. 새 작업은 큰 계획과 소스 원문을 불변 artifact로 봉인하고 실행 직전 snapshot/계획/runtime/nonce를 대조한다. 완료 자료는 재개 시 다시 계산하거나 덮어쓰지 않으며, 같은 후보의 첫 계산 진단 참조도 유지한다. 동일 물리 입력을 재사용한 후보는 별도 ordinal과 입력 원문, cache 근거를 갖는다.

## 시험 경계

- Domain/서비스: 조합 순서/상한, 단위 동치, 표현식/출처 보존, 검토 변경과 다른 프로젝트, 원본 불변, 재시작과 누적 예산.
- 회로: 실제 scikit-rf 기반 이상 저항 계산을 독립 수식과 대조. 가짜 RF 출력으로 표시하지 않는다.
- 작업: 가짜 전송의 수명/변조 시험과 실제 WSL의 준비/해석을 따로 기록한다. structured 미수렴, 시작 중 종료 불명과 취소/재개를 구분한다.
- GUI: 실제 wxWidgets 이벤트 루프의 4탭/검토/취소/재개/저장/서비스 재시작과 수동 시각 확인을 따로 남긴다.
- 원본: 기존 원문 파일, 복소 JSON/HDF5, 과거 snapshot, 재료/제작/측정/목표 기준면의 미정을 재열기 후 대조한다.

전체 회귀 수집과 마지막 보완 후 집중 시험은 실행 시점을 분리하고 중복 횟수를 합산하지 않는다. 확인하지 않은 DPI/다중 모니터/프레임/실제 최고 메모리를 합격으로 표시하지 않는다.

## 실제 WSL에서 발견한 경계

첫 한 후보 시험은 24.335초에 실패했다. FDTD 전 소스 복사/시작 인계 구간에서 응답과 종료 확인을 잃었으며 계산 횟수는 0이고 작업 예약은 종료 불명으로 유지되었다. 구형 코드가 transport 오류 원문을 저장하지 않았으므로 당시 10초 시작 제어 제한을 확정 원인으로 기록하지 않는다. 제한 시간은 진단 가설이며, 저장된 증거는 일부만 복사된 입력과 시작 소유 정보 부재다. 최초 작업 영역/로그와 `interrupted`, `resource_reserved=true`, `termination_confirmed=false`를 보존한다.

시작 lock/PID/프로세스 시작 시각/boot ID/nonce를 복사 전에 남기고, 실제 daemon으로 인계하는 identity를 대조한다. 복사 중 취소는 계속 유지되며, 소유자 소실도 lock과 실제 프로세스 종료 근거가 있을 때만 시작되지 않음을 확정한다. 구형 작업의 증거 부재를 새 규칙으로 소급 확정하지 않는다. 시작/내보내기의 유한 대기와 제어 명령 대기를 구분했으며, 시간 연장만으로 소유권 공백을 처리하지 않았다.

두 성공 실행은 각각 명시 합성 PCB gap 한 후보/31개 복소 표본이며, 각 실행에서 native solve 1회를 수행했다. 최종 시험의 누적 실행 벽시간은 53.02228307723999초, host+guest 보존 논리 크기는 14,194,472바이트이며 이 중 guest 관측은 4,779,541바이트다. 미관측 비용은 보수적 예약으로 유지한다. 실제 WSL openEMS/CSXCAD runtime identity, 입력/출력/원본 hash는 기계 기록에 남긴다.

최종 실제 보고서 SHA256은 `3071fb4b38c824b8156c10339d35fa7bfcec74ce0f5779f556455cac3c62cd16`이다. `source_profile=explicit_synthetic_pcb_gap_not_manufacturing_reference`, `physics_validated=false`, `convergence_state=solver_end_criterion_only`를 유지한다. 선택한 목표가 없어 후보 outcome은 `not_evaluated`다. solver 종료 조건 충족을 격자 수렴이나 RF 정확도 합격으로 바꾸지 않았다. 원본 프로젝트가 그대로이며 runtime 없는 서비스 재열기에서도 같은 결과와 측정 조건의 미정을 확인했다.

## Windows GUI와 최종 문서 검사

최초 실제 Windows GUI 시험은 회로 자료의 null 포트 이름을 문자열로 읽어 12.226초에 실패했다. nullable 원문을 유지한 표시 이름 처리로 보강한 뒤 1개/29.625초에 통과했다. 이후 수동 화면 검토에서 연구 문맥, 후보 결과 버튼 공간, 결과 주파수와 원문 조건 표시, 미적용 초안의 폐기 확인을 보완했다. 이 수정 뒤 `b021bb9a...` 빌드의 실제 GUI 1개/12개 검사, 26.320초와 CTest 9개/0.51초가 통과했다.

GUI 시험은 2 x 2 설계 후보를 실제 폼에서 검토/생성하되 자동 native 해석을 시작하지 않음을 확인한다. 별도 회로 후보는 50 ohm/100 ohm/0.05 kohm 입력 원문, 단위 동치와 중복 재사용, 취소/명시 재개/실제 이상 회로 계산을 검사한다. 저장 뒤 서비스 세션을 다시 열어 현재 프로젝트/원래 snapshot/원문 bytes/정규 HDF5와 제작/측정 미정이 같은지 대조한다. native solve 수는 0이며, 이 GUI 사례는 FDTD나 측정 성능 시험이 아니다.

초기 수동 캡처 15~18은 `da3e1ee82eaa6ba170c214f4327b7882ca6fe0b5264741056eb1b1e81a7ab413` 빌드다. 저장 후보의 1~2 GHz 복소 곡선, 연구 유형/변수 폼, GHz 주파수와 처음 꺼진 방사 옵션, min/GiB 실행 예산을 확인했다. 이 빌드의 CTest는 9개/0.41초 통과했지만 수동 검수에서는 Studio 제목/문맥, 결과 버튼 공간, 표본 표시와 조건 요약 문제를 발견했다. 수정 뒤 아래 19~22 화면으로 재확인했으며 초기 캡처도 원문 그대로 보존한다.

수동 저장/닫기 뒤 별도 서비스로 재열기하여 3개 연구와 3개 회로 결과를 확인했다. 원본 프로젝트 hash는 `5033e125ecf39f73e74306e8b7a023d5cf669e8c195391ab8ea20805409d83c0`, 개정은 `2879a818-ac63-4017-81da-f347bb367410`으로 유지된다. 기존 raw/dataset/HDF5/snapshot과 측정 null을 확인했으며 새 측정 자료는 추가되지 않았다.

마지막 검토에서 값 목록과 범위 입력을 전환할 때 기존 명시행의 index 대응이 남는 경계를 발견했다. 전환 확인 문구에 기존 후보 행 삭제를 명시하고 승인 시 행을 비워 새 값에 과거 index가 다시 연결되지 않게 한다. 취소하면 원문/행/검토를 유지한다. GUI의 '행별 값 직접 선택'은 명시 값 목록에서 선택하며, 범위 입력은 먼저 값 목록을 지정하도록 안내한다. 범위 전개와 단위 환산을 GUI가 대신 수행하지 않는다.

또한 다른 연구를 선택해 조회 응답을 기다리는 동안 이전 후보/조건을 비워 연구 이름과 다른 결과를 함께 표시하지 않도록 보완했다. 두 보강 뒤 최종 기본 실행 파일 SHA256은 `6f6eb63042a726b1a095a8b264b793c2e1af075678e59b61e2e6d90714dbd92a`이며 CTest 9개/0.28초가 통과했다. 기본 외형을 바꾸지 않은 두 보강이므로 기존 캡처의 출처는 `b021bb9a...` 빌드로 유지한다.

최종 실행 파일의 전용 GUI 시험은 1개/13개 검사, 25.990초에 통과했고 실제 서비스 세션 2개를 사용했다. 새 `sweep_value_mode_explicit_rows_safe_reset` 검사는 목록 -> 범위 변경을 거절하면 spec/행/검토/프로젝트 개정이 유지되고, 승인하면 행 삭제/검토 무효화가 수행되며 목록으로 돌아가도 이전 index가 남지 않음을 확인한다. 보고서 원문과 실행 파일 hash는 기계 기록에 결합했다.

동일 최종 빌드의 전체 GUI 회귀는 27개 중 25개 통과, 실제 WSL 해석 GUI 2개 환경 제외, 실패/오류 0, 481.421초였다. 실제 CAD GUI 2개와 기존 목표/문헌/정밀 편집/복소 자료 및 새 스윕을 포함한다. 전체 회귀의 스윕 보고서도 13개 검사와 서비스 2세션을 확인했다. 별도 실제 WSL 스윕 성공을 제외된 GUI 2개의 통과로 대신 표시하지 않는다. 최종 빌드에서 수동 캡처를 다시 만들지는 않았으며 `b021bb9a...` 수동 증거와 `6f6eb630...` 최종 자동 회귀의 시점을 구분한다.

요구 추적 감사 시험은 14개/2.560초 통과했다. 최종 추적표 생성과 `--check`도 141개 요구/404개 AC/407개 하위 항목/46개 기능/30개 검증 그룹/30개 API가 일치하며 `acceptance_passes_claimed=0`을 유지한다. 최종 문서 구조 검사는 승인 원문 27개 hash/폴더명 28개/번호 문서 458개/Markdown 130개/링크 7535개를 확인했고 끊어진 링크는 0개다. DrawIO/SVG/PNG 구조 10쌍을 검사했으며 native DrawIO 재열기나 GUI 실행을 이 정적 검사에 포함하지 않았다.

중간 C++ 빌드의 문자열 덧셈 오류와 접기 패널 타입 불일치도 실패 로그를 보존하고 수정 후 링크 성공과 구분했다. 실행 범위가 겹치는 전용/전체/후속 시험의 개수를 합산해 독립 시험 수로 제시하지 않는다.

## 수용 경계

RAM의 계획 추정치와 저장 파일의 논리 바이트 예산은 운영체제/WSL 가상 디스크의 실제 할당 크기 또는 전체 앱 peak 수용 증거가 아니다. 후보/native solve 최대 128개, 동시 실행 1개, worker 소스 192개, CAD 2 MiB/solver 4 MiB와 프로젝트 512 KiB/origin 256 KiB 상한은 유지한다. 새 스윕의 작업 단위 재개는 FDTD 중간장 checkpoint 재개를 뜻하지 않는다.

재료 ID/카탈로그 모델/외부 환경 시나리오 자체의 enum 교체, 자동 최적화와 일반 다축 수렴 판정, 후보 원본의 자동 채택은 포함하지 않는다. 기존 수량에 결합된 매개변수만 명시적으로 변경한다. 주파수 대역/표본 축을 바꾼 수치 연구를 같은 조건의 격자 수렴으로 자동 분류하지 않는다.

RO4350B 국부 방사 도체 손실 변화 2.788446%와 초기 2% 기준 미확립, GHz PTH 독립 물리 정확도 미확립은 유지한다. 제조/납품 물성/급전 실장/교정/시료/측정 조건을 채우지 않는다. 이후 7번 비교/방사, 8번 독립 RF 검증과 11번 측정 연결은 기존 번호로 진행한다.
