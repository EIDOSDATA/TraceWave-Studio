# Studio의 보존 묶음 발행 검증

2026-11-20 KST. 완료 계획 12번의 [복원용 프로젝트 묶음](../05_기능설계/01_프로젝트/02_프로젝트_보존묶음과_편집복원.md)을 [송신 화면](../04_화면설계/27_보고서와_인계_화면.md)에서 발행하고 별도 Windows 작업 영역에서 복원했다.

1. **출력 > 보고서 / 인계**에서 편집 복원용을 선택하고 공유할 수 있는 합성 원문을 포함했다. 개정, 출처, 검토 범위에서 ZIP 전체 10개 항목과 1,503,930 B를 확인했다. [발행 전 검토](02_실행화면/84_편집복원용_묶음범위검토.jpg)
2. 첫 실행에서 발행은 완료됐지만 사본 읽기가 읽기 전용 조회 메서드를 사용해 거절됐다. 잘못된 사본 파일은 생기지 않았다. 조회를 현재 형식에 맞춘 빌드에서 다시 열어 기존 발행 기록을 선택하고 12개 청크를 저장했다. 사본은 별도 CLI 발행물과 바이트 단위로 일치했다. [재열기 후 사본 저장](02_실행화면/85_보존발행기록_사본저장.jpg)
3. 등록 원문을 해제하고 범위를 검토하자 제외 항목 4개를 표시했다. 이후 읽기 전용으로 전환하여 과거 보고서 ZIP의 기록과 별도 프로젝트 묶음 기록이 섞이지 않는 것을 확인했다. [읽기 전용 이전 기록](02_실행화면/86_형식전환_읽기전용기록보존.jpg)
4. 다른 Windows 작업 영역에서 같은 파일을 선택하고 보존/복원 개정 비교 후 복원했다. 저장한 뒤 새 앱으로 재열기했다. [수신 검토](02_실행화면/87_스튜디오발행본_수신검토.jpg), [재열기](02_실행화면/88_스튜디오발행본_수신재열기.jpg)

독립 저장소 대조에서 현재/저장 개정, 명령, 스냅샷, 등록 파일 8개의 내용, 재료/목표와 출처, 제작 및 측정의 미정값을 확인했다. 기존 작업 큐는 복제되지 않았고 수신 과정에서 해석을 실행하지 않았다.

서비스 시험은 양식별 목록과 영수증/다운로드가 다른 형식을 거절하는지 확인했다. 수신과 기존 인계 회귀, Windows 출력 기능과 CTest도 별도로 실행했다. 검토 캡처의 첫 빌드와 이후 사본 저장 및 재열기 빌드는 [실행 기록](36_스튜디오_보존묶음발행_실행기록.json)에 구분했다.

서비스와 GUI에서 확인한 범위는 등록 개정, 스냅샷, 명령 및 지정한 원문과 복원이다. 외부 worker 결과 이동, 실제 전체 UX/성능/복구 수용, 특정 EDA/MCP 수용은 12번의 나머지 범위다. 제작과 실측 수용을 변경하지 않았다.
