# 프로젝트 기록의 개정 및 객체 검색 검증

2026-11-23 KST. 원호와 IFA의 실제 openEMS 완료 결과 및 실패 시도가 보존된 검수 사본에서 확인했다. 현재 설계의 급전 이름을 변경하고, 해석하지 않은 새 개정에 조건을 저장한 뒤 프로젝트를 다시 열었다. 각 과거 스냅샷에서 인계 보고서를 생성해 같은 프로젝트에서 검색했다. [실행 기록과 종료 근거](321_실행비용과_종료원인_검증.md), [보존된 재료와 급전 출처](322_해석결과_출처역추적_검증.md)

| 사례 | 계산 당시 개정 | 기록에서 연 결과 ID | 인계 보고서 ID |
| --- | --- | --- | --- |
| 원호 | `eb740c45-1fc7-4e5c-b85e-3a9c3e24271a` | `98d8ac25-a4e3-4cb9-8989-ae8cbf776470` | `7513cbe6-1c4f-5161-85ae-50a11e51e39b` |
| IFA | `907dd8c9-b756-4731-8fed-c53e6e82676d` | `7e7afd59-7501-4e84-8dba-67635902a329` | `985959a6-3600-5c3e-94f1-56a9a6b8d6ed` |

- 과거 개정의 앞부분, 스냅샷 전체 ID, 당시 급전 이름 및 객체 ID를 조회했다. 과거 결과는 현재 이름으로 조회되지 않았고, 이름을 바꾼 개정에서 현재 이름으로 저장 조건을 찾았다.
- 원호의 시간 단계 한도와 IFA의 실행 시간 초과를 각각 찾았다. 두 기록에서 당시 실행 설정과 설계를 읽었다. 완료 결과 연결은 비어 있었다.
- 완료 작업과 인계 보고서가 당시 결과의 동일한 ID와 고정 해시로 연결되는지 대조했다. 이름 있는 조건은 저장 기록과 실제 계산 설정이 함께 일치했을 때 동일 결과를 표시했다.
- 결과가 없는 현재 개정의 조건을 검색해 원래 설계를 열었다. 조회는 계산이나 설계 변경을 만들지 않았다. 존재하지 않는 결과 ID 연결, 보고서 종류가 다른 ID와 달라진 목록 해시는 거절했다.

Windows 앱에서 원호의 저장 조건 및 실패 실행과 IFA의 결과 없는 조건, 실패 실행 및 인계 보고서를 직접 열었다. 두 사례 모두 공통 결과의 목록과 출처 화면에서 같은 결과 ID를 확인했다. IFA에서는 출처 화면에서 2.44175 GHz NF2FF 설정도 확인했다. 기존 사본의 RF 검증 보고서 1건과 수렴 보고서 1건을 추가로 열어 각각에 기록된 6개와 3개의 결과 연결을 대조했다.

Windows Release CTest 14개 및 관련 Python 시험 31개를 통과했다. 최종 변경 후 프로젝트 기록과 조건, IFA 수렴 관련 시험을 다시 확인했다.
