# Windows CAD와 출력 작업의 취소 지연 검증

2026-11-21 KST. 실제 Windows Studio의 OCCT 3D 형상 작업과 PDF 재검수 worker를 각 6회 실행했다. 서비스가 실행 소유권을 기록한 다음 GUI의 실제 취소 버튼 이벤트를 보냈다. 두 작업군 모두 취소 뒤 이전 출력과 저장 개정 및 서비스 재열기를 확인했다. 출력 화면은 버튼을 먼저 잠그고 다른 출력 상태를 다시 계산하기 전에 취소를 전송한다.

| 경과 시간 | OCCT 형상 중앙값 / p95 (ms) | PDF 재검수 중앙값 / p95 (ms) |
| --- | ---: | ---: |
| GUI 버튼 잠금 | 0.913 / 1.217 | 0.099 / 0.192 |
| GUI에서 본 서비스 접수 | 39.873 / 44.329 | 49.450 / 54.104 |
| 서비스 취소 신호부터 native 트리 회수 | 5.370 / 6.440 | 7.542 / 8.637 |
| GUI에서 본 종료 상태 | 222.338 / 257.442 | 245.572 / 253.491 |

버튼 100 ms 이내 표본은 12/12, 접수 200 ms 이내 표본은 12/12였다. 각 6회의 nearest-rank p95는 관찰 최대값이다. native 회수는 서비스가 취소 신호를 내기 직전부터 Windows Job의 트리 회수 확인까지다. GUI의 종료 관찰은 상태 조회 지연을 포함한다.

초벌 실행은 실제 기능 검증을 통과했지만 Windows의 기본 Python 단조 시계 해상도가 15.625 ms였다. 최종 수치는 고해상도 Windows 성능 카운터를 사용한 새 실행이다. 시계 변경 중 실행한 회귀에서 세 해석 시험이 소스 고정에 걸렸다. 최종 소스를 고정하고 다시 실행한 서비스 시험 57개와 Release CTest 13개가 통과했다.

대기 작업 취소는 native 종료 증거를 생략하고, 회수 이후에 서비스가 취소를 받은 경우에는 이미 확인한 회수와 접수 이후의 회수 지연을 구분했다. 이번 표본은 정상 부하의 형상 생성과 PDF 재검수다. 실제 도면 생성 취소의 추가 시간 계측, 초당 1000행 로그 부하, 작업군별 규정 표본과 기준 호스트 수용은 남는다. [기존 Windows 검증](210_윈도우_형상과_출력_취소검증.md), [이번 원시 실행 기록](233_윈도우_형상과_출력_취소지연_실행기록.json)
