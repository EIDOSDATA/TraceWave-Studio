# Windows 한글 입력, 접근성 및 혼합 배율 검수

2026-11-22 KST. Windows 11의 실제 TraceWave Studio Release에서 별도 작업 영역으로 검수했다. 실행 파일 SHA-256은 `8eca5fc5f829c706d89187e8560a1d43ff2e3195e41d8585665c9cf1b843b8e3`다. 이 바이너리는 기존 e28a982 후보와 일치한다. [기존 후보 기록](300_윈도우_알원_내부후보_재현과_수신.md)

| 항목 | 실제 입력과 확인한 결과 | 판정 |
| --- | --- | --- |
| 한글 IME와 프로젝트 속성 | Microsoft 한국어 두벌식에서 이름을 `한글`, 설명을 `검수`로 조합했다. 첫 자음과 마지막 음절의 조합 표시를 관찰했다. Tab으로 이름을 확정하고 설명의 마지막 음절 조합 중 변경 적용을 눌렀다. 저장 후 다시 연 화면과 디스크 개정 `354c636c-5f22-426f-8940-e935b2d9e359`에서 두 값이 일치했다. | 통과 |
| 한글 IME와 도체 이름 | IFA 24 mm 검수 사본에서 트리의 선을 선택하고 F2로 이름 변경을 열었다. 실제 두벌식으로 `도체`를 조합해 마지막 음절이 반전 표시된 상태에서 적용했다. 저장 후 재열기한 트리와 디스크 개정 `2741d9cd-bdc7-463e-aefa-8575f3302b64`에서 같은 이름을 확인했다. | 통과 |
| 스크린리더와 초점 | 빈 프로젝트 이름을 키보드로 적용했다. 화면과 Windows 접근성 트리에 이름 길이 및 공백 조건이 표시됐다. Windows 내레이터가 내보낸 오류 문장을 사용자가 직접 확인했다. 초점은 이름 입력란으로 돌아왔으며 키보드로 유효한 이름을 다시 조합할 수 있었다. 검수 뒤 내레이터를 종료했다. | 통과 |
| 혼합 DPI | 사용자와 실제 창을 기본 모니터 144 DPI(150%)에서 보조 모니터 96 DPI(100%)로 옮겼다. 보조 모니터에서 Studio 창의 유효 DPI는 96이었다. 화면에서 편집 캔버스, 속성 입력란, 버튼과 탐색 트리를 확인했다. 표시 위치의 이름 입력란을 클릭해 실제 초점이 해당 입력란에 가는 것을 확인했고, 같은 화면에서 키보드로 오류 검수를 수행했다. | 통과 |

IFA 검수 사본은 기존 개정을 보존하며 현재 쓰기 형식으로 새 개정을 저장했다. 이름, 개정 정보와 스키마 승격 외에는 도체의 식별자, 치수, 연결과 출처가 일치했다. 원래 작업 영역의 저장 포인터와 기존 개정의 SHA-256도 일치했다. 적용 범위는 두 모니터와 프로젝트 속성, 도체 이름 및 검수 경로다.
