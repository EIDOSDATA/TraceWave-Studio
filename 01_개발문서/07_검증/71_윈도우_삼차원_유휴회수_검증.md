# Windows 3D 유휴 context 회수 검증

2026-11-20 KST. 완료 계획 12번 F5의 대형 3D View에 빈 장면의 OpenGL context 회수를 추가했다. 장면을 닫을 때 표시 메시, 선택 인덱스와 정점 버퍼를 반환한다. context가 120초간 빈 상태로 있으면 wxTimer가 회수한다. 다음 장면을 불러올 때 타이머를 중지하고, 필요하면 새 context를 만든 뒤 첫 프레임을 게시한다. 유지하는 장면의 context와 기존 source/pin, STEP 파일은 같은 계약을 따른다. [30회 warm 검증](69_윈도우_삼차원_반복회수_검증.md)

## 실제 대형 장면

| 상태 | private commit | GPU local | 핸들 | 제품 버퍼 | context 표시 |
| --- | ---: | ---: | ---: | ---: | --- |
| 첫 표시 | 192.00 MiB | 178.07 MiB | 323 | 68.66 MiB | 준비됨 |
| 장면 닫은 직후 | 114.82 MiB | 143.69 MiB | 321 | 0.00 MiB | 준비됨 |
| 유휴·유예 종료 | 23.49 MiB | 0.00 MiB | 290 | 0.00 MiB | 회수됨 |
| 다시 열기 | 191.80 MiB | 178.07 MiB | 321 | 68.66 MiB | 준비됨 |

같은 Windows 프로세스에서 100만 삼각형을 열고, 닫은 뒤 150.02초 이후 샘플을 얻고, 다시 열었다. context 상태는 ModelView의 렌더러 정보와 재열기의 실제 새 프레임 및 새 업로드에서 확인했다. GPU local은 Windows CurrentUsage의 해당 node 표본이다. [GPU 메모리 명세](https://learn.microsoft.com/windows/win32/api/dxgi1_4/ns-dxgi1_4-dxgi_query_video_memory_info)

120초에 유휴 context 반환을 요청하고 30초 유예 이후를 검사했다. 보유 GPU 드라이버 캐시의 내부 귀속과 전체 Studio+service+후처리 worker의 F5 두 정책 30회 수용은 별도로 남는다. 실제 OCCT/Windows GUI 회귀 2개, CTest 13개, 자원 판독 2개를 확인했다.

## 재현

```powershell
cmake --build build/windows-release --target tracewave_model_lifetime_probe
./build/windows-release/bin/tracewave_model_lifetime_probe.exe .local/large-display .local/model-idle.jsonl --idle
```
