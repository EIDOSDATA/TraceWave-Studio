# 대형 카탈로그 검색표와 Windows 메모리 검증

2026-11-21 KST. 완료 계획 12번 PERF-F1의 검색표를 실제 Windows Studio Release에서 확인했다. 자료 행은 시험용 합성 관측 100000개다. 형상 10000개와 매개변수 1000개를 가진 별도 시험 프로젝트를 편집·저장하고 서비스를 다시 시작해 같은 개정을 열었다. 이 상태에서 기판 설정의 자료 검색을 실행했다.

| 동작 | 실제 Windows 관찰 |
| --- | --- |
| 전체 자료 검색 | 100000개와 첫 행 표시 |
| 100000번째 행으로 이동 | 같은 개정의 마지막 관측 ID, 제품 표기와 미정 Df 확인 |
| Windows 표 페이지 스크롤 | 화면 좌표가 이전 구간으로 이동하고 인접 행 로딩 확인 |
| 한글 부분 문자열 필터 | 50000개와 새 첫 행 일치 |
| 닫기와 재열기 | 저장 개정과 10000개 형상·1000개 매개변수 보존, 표시 생략 0개 |

SQLite 조회는 안정 ID 순서와 같은 트랜잭션의 일치 건수를 사용한다. GUI는 필요한 행을 최대 25개씩 비동기로 받고 최대 8개 페이지를 유지한다. 합성 fixture의 끝부분에는 긴 표기를 두어 48 KiB 상한 때문에 나뉜 페이지도 이어서 표시했다. 변경된 검색에 도착한 과거 응답은 폐기한다. 시험 후 자료 DB 해시와 프로젝트의 기판·형상·매개변수·재료·출처·미정값을 대조하는 회귀를 제공한다.

실행부터 종료까지 124회 표본 중 111회에서 서비스 자식 프로세스가 관찰됐다. Windows 프로세스별 private commit을 합산한 관찰 최대값은 **308.50 MiB**로 F1의 768 MiB 예산 이내였다. 표본 간격 중앙값은 0.292초다. 계측 간격 사이의 최대값, 대형 3D 동시 부하와 GPU 메모리는 별도다. [실행 기록](116_대형자료_검색표_실행기록.json)

검색 첫 표시와 마지막 행은 각각 32.0 ms, 106.6 ms에 시험 루프가 확인했다. 스크롤과 한글 필터는 각각 124.7 ms, 66.6 ms에 확인했다. 이 값은 wx 이벤트 루프에서 검색 결과와 native 행을 발견하기까지의 한 번의 관찰이다. 디스플레이 입력 지연 p95/p99, 연속 조작 30초와 1000개 합성 간격, 60 fps 수용은 미확립이다.

재현은 Release 실행 파일을 `RFAD_GUI_EXE`로 지정하고 `test_f1_view.F1ViewTests.test_windows_saves_and_reopens_all_rows`를 실행한다. 합성 DB 생성과 실제 wxListCtrl의 스크롤을 포함한다. 원문 출처 인덱스와 과거 물성 검증 기록은 보존했다.

서비스·GUI 관련 회귀 40개 중 39개 통과, 환경 조건 1개 제외로 확인했다. 이후 긴 응답 페이지 이어 읽기를 보강한 최종 Windows 빌드에서 대형 자료와 기존 PCB GUI 4개를 다시 실행해 모두 통과했다. CTest 13개가 통과했다.
