# Windows 표시 성능과 복구 재검증

표 첫 시도는 200초의 전체 시험 대기 상한을 넘었다. 같은 복제 fixture의 재시험은 전체 대기 상한만 420초로 두고 35초 입력과 합성 계측을 유지했다. 두 빌드 모두 10000개 형상, 1000개 매개변수, 100000개 전체 표와 50000개 필터 결과를 저장·재열기하고 검색 원문 해시를 대조했다. 기존 빌드와 시험 빌드의 p95 차이가 0.151 ms였고 개선이 확인되지 않아 캐시를 채택하지 않았다. 표시 추적 판독 시험 5개가 통과했다.

F3는 실제 Windows에서 1 GiB급 필드의 단면 열 개와 10만 점 곡선 여덟 개를 열고 다른 서비스 세션에 재열었다. 관찰한 private commit 증가는 최초 가져오기 14.68 MiB, 재열기 15.36 MiB였다. 원문 해시와 부분 조회를 대조했다. 손상 원본 차단과 복원 사본 재열기, 저장 전 디스크 부족 오류 주입 뒤 재시도도 통과했다. 세 GUI 시험의 합은 89.446초다. Windows native 작업 제어 12개에서 로그 상한, 취소·부모 강제 종료 및 자식 회수를 확인했다. 실제 지원 backend의 취소 지연 공식 표본은 별도 수용이다.

공식 MCP SDK와 KiCad 10.0.8 수신 및 재가져오기 1개를 48.929초에 통과했다. SDK가 설치된 시험 Python을 사용했다. [기존 상호 운용 기록](272_윈도우_통합복구와_인계_재검증.md)

F5 이전 30회 로그는 Studio 커널 핸들에서만 7회 307개에서 8회 352개로 증가했고 다른 세 프로세스의 수는 각각 66, 252, 97로 유지됐다. 별도 9회 시험의 유휴 커널 핸들은 342~344, GDI 229~230, USER 179~195였으며 8회 증가가 재현되지 않았다. 증가의 원인과 기준 장비에서의 장시간 재현은 열린 상태다. [30회 기록](199_대형프로젝트_검증재사용과_유휴회수_실행기록.json), [9회 객체 진단](229_윈도우_유휴_사용자인터페이스객체_실행기록.json)

## 개발 PC의 시작·취소·유휴 추가 표본

- F0 warm 20회에서 첫 창 p95 1.341초, 새 프로젝트 편집 준비 p95 3.467초였다. WSL2 설치 연구가 동시에 동작했다. 이번 실행에서 첫 창은 1.5초 목표 이내였고 편집 준비는 2초 목표를 넘었다. 실제 cold 도달 시간은 미측정이다.
- F4 Windows native Job Object에서 약 1000행/초 로그 부하를 세 번 주고 취소했다. native 반환까지 10.00~13.57 ms, 세 번 모두 자식 종료를 확인했다. 이 표본의 지연은 버튼·IPC 접수 또는 WSL 정식 수용 지표와 구별한다.
- F5 100만 삼각형, 단면 열 개와 곡선 여덟 개를 여는 150초 유휴 전환을 3회 재검증했다. 정리 후 GUI 커널 핸들은 315개로 같았고 GDI는 231, 232, 233개이며 USER는 187개로 같았다. 합산 private commit은 114.30, 116.89, 118.10 MiB였고 세 번 모두 OpenGL 문맥을 해제했다. WSL2와 일부 수신 검증이 함께 실행됐으며 이 표본은 각 정책 30회의 정식 검수를 보완한다.

## 프로젝트 속성 오류와 초점

실제 Windows 창에서 빈 이름을 적용했을 때 공통 상태 표시줄만 실패를 알리고 숨겨진 객체 속성 영역에 상세 오류가 올라가는 것을 확인했다. 프로젝트 전용 속성 폼에 서버의 거절 사유를 붙이고 반환된 필드 경로에 따라 초점을 복귀시켰다. 초안을 수정하거나 현재 속성을 다시 읽으면 이전 안내를 지운다.

수정 빌드에서 같은 입력을 거절한 뒤 현재 폼과 Windows 접근성 트리에 이름의 1~256자 제한이 표시됐다. 입력란의 실제 키보드 초점 복귀와 수정 후 안내 해제를 확인했다. GUI 회귀는 오류/원래 개정 보존, 표현식, 저장 실패 및 예약 거절 재시도, 한글 경로 저장·재열기 4개가 59.750초에 통과했다. 첫 시험에서는 서버 명령의 일반 검증 문구를 예상했으나 편집기가 별도 이름 규칙으로 먼저 거절했다. 실제 편집기 필드와 실패 문구로 기대를 수정해 재검증했다.

설치된 한국어 IME에서 오른쪽 Alt와 대체 언어 전환을 시험했으나 Latin 문자열로 들어갔다. 검수 도구의 한/영 전용키 호출은 지원되지 않았다. 자모 조합과 스크린리더 실제 발화의 공식 검수는 남는다.

## 최종 빌드의 단독 warm 재검증

설치 해석과 새 경로 수신 시험을 마친 상태에서 7959227 Windows Release의 warm 20회를 재검증했다. 첫 창 p95는 0.494초, 새 프로젝트 편집 준비 p95는 1.420초로 두 목표 이내였다. 앞선 동시 부하 표본과 각각 보존했으며 재부팅 직후의 콜드 시작과 공식 기준 PC 판정은 미평가다.
