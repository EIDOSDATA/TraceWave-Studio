# Windows 대형 표시 메시 검증

2026-11-20 KST. 12번 F2의 대형 표시 profile `rfad.display-mesh/0.2`를 OCCT 생성, 서비스 봉인과 Windows 로더에 연결했다. 일반 `0.1`의 16 MiB/100,000개 삼각형/300,000개 정점 한도를 적용하며, 이 수량을 넘어가는 장면은 별도의 대형 계약 안에서 처리한다. 대형 계약과 기존 CAD 패키지 전체 상한은 [기능 계약](../05_기능설계/05_출력교환/02_기계형상_입력과_출력계약.md)에 있다.

## 실제 OCCT와 보존

반지름 700/150 mm의 곡면 토러스 STEP을 기하 시험용으로 수입해 공개 명령으로 배치했다. 실제 OCCT 출력이 142,552개 표시 삼각형의 `0.2`를 선택했다. 입력 STEP 바이트, 미정 재료와 EM 제외, 원본과 현재 스냅샷, 게시 파일 해시를 검사했다. 프로젝트 저장 후 CAD 런타임 없이 재열기를 확인했다. 초기 구형 STEP에서는 재입력 삼각형의 면적이 0이어서 검증이 새 패키지 게시를 중단했다. 퇴화면 검사와 원본 결합을 유지했다.

## 정해진 100만 삼각형

두 바디의 합성 격자 1,000,000개 삼각형과 502,002개 정점을 37,489,347바이트의 메시로 만들었다. Python host의 검증과 Windows 로더의 SHA256/스냅샷/실행 결합을 각각 확인했다. Windows Intel Iris Xe에서 1920 x 1080 wxGLCanvas에 그려 CPU 배열과 72,000,000바이트 정점 버퍼의 픽셀을 비교했다. 두 번 모두 일치했고, 새 context에서 다시 올려 같은 화면을 얻었다.

각 실행은 8쌍 준비 후 40쌍을 대조했다. 파일 로딩에는 읽기, SHA256, JSON 검증과 렌더용 정점/법선 구성이 포함된다. 그리기 표본은 `glFinish` 완료까지다.

| 실행 | 로딩 (ms) | CPU 배열 그리기 p95 (ms) | GPU 버퍼 그리기 p95 (ms) |
| --- | ---: | ---: | ---: |
| 1 | 1426.03 | 17.63 | 7.47 |
| 2 | 1419.41 | 19.28 | 8.34 |

100만 개 로딩/표시의 근거다. 합성 화면의 연속 회전/이동과 선택 지연, LOD 품질, GPU 실제 메모리 및 F2의 30 fps 수용은 별도다. 일반 10만 삼각형 픽셀 회귀, Python 24개, 실제 CAD와 Windows GUI 6개, CTest 13개가 통과했다.

## 재현

```powershell
.venv/Scripts/python.exe -X utf8 tools/create_large_display_fixture.py .local/large-display

```
