# 연관 도면과 STEP 재검수 검증

작성일: 2026-11-17 KST. 완료 계획 10번의 PDF/SVG/DXF와 STEP 재검수 구현 범위다. PCB/CAM, 독립 수신 CAD, 제조 및 RF/실측 수용은 별개다. 이 범위의 최종 Windows 보완 검증과 저장/재열기 보존 대조를 마쳤으며 아래 실행들은 시점별로 구분한다.

[기능 계약](../05_기능설계/05_출력교환/04_연관도면과_출력재검수.md), [화면 계약](../04_화면설계/24_기술도면과_스텝검수_화면.md), [개발 완료 계획](../09_개발계획/03_개발완료_계획.md)을 함께 읽는다. 기존 참고자료, 승인 기준선, 84개 시안과 과거 실행 기록은 수정하지 않는다.

## 1. 확인한 범위

고정 snapshot의 같은 원본 의미와 실제 종이 mm 배치로 연관 PDF/SVG/DXF를 생성한다. 원본 Quantity/표현식/객체 이름/출처/미정값은 sidecar에 보존한다. 생성 전 검토 hash, 비동기 TaskRef, 별도 worker와 불명 요청의 영수증 조회를 기존 명령 구조에 연결했다. 새 검수는 원래 산출물을 바꾸지 않고 별도 reader 작업과 검수 보고서를 만든다.

STEP은 기존 AP242/B-rep/mesh 출력을 재사용한다. 별도 프로세스의 동일 OCCT reader로 solid, bbox, 중심, 체적, 두께, 단면, 홀과 배치 관계를 다시 검사한다. 새 검수 기록이 최신 3D mesh를 대체하지 않는다. 같은 커널의 성공을 독립 CAD 검수로 표시하지 않는다.

## 2. 실제 입력과 환경

9번에서 보존한 IFA 24 mm와 원호 R5.5 mm 선택 사본을 별도 workspace로 복사하여 사용했다. 원래 40 x 60 mm 시험 기판, 명시 가정 물성/간극 급전과 -10 dB 목표 미달을 유지했다. 새로운 FDTD는 실행하지 않았다. 배터리/외함/실제 제작과 측정 조건을 출력 편의를 위해 채우지 않았다.

Windows x64 CPython 3.12.10의 별도 `.venv-exchange`에서 hash를 고정한 ReportLab/ezdxf/pypdf/Shapely를 사용한다. `setup_exchange.ps1`의 실제 설치 점검과 `pip check`를 통과했다. PDF는 이 PC의 Malgun Gothic TTF를 작업별로 봉인하고 부분 포함한다. 해당 OS 글꼴은 저장소에 배포하지 않는다. CAD는 기존 `.venv-cad`를 재사용한다.

실행 소스 한도는 192개를 유지했다. 최종 보강 전 HOST 186개/직렬화 1,837,101 bytes, EXCHANGE 14개/128,102 bytes였다. 적층 주석 줄바꿈과 snapshot 이름 표시 DTO 보완 후 HOST 186개/1,839,916 bytes, EXCHANGE 14개/128,155 bytes다. 최종 파일 목록과 hash는 실행 기록에서 별도로 고정한다.

## 4. 파일과 화면 검토

두 번째 8출력 실행의 IFA/원호 PDF 각각 두 페이지를 Poppler로 렌더링해 네 페이지를 직접 확인했다. 표제, 원본 이름, 단위, 실제 1:1 형상, 접지 도체 면의 구멍, 중심선 길이/반지름, 축척 막대와 실제 X-Z 적층 단면을 확인했다. 도체가 없는 하부 층을 임의 동박으로 채우지 않으며 얇은 층을 읽기 좋게 보이려고 제작 두께로 과장하지 않는다.

초기 검토에서 숫자와 단위가 줄을 달리하는 주석을 발견했다. `1984 mm^2`에 이어 접두어가 붙은 `t=0.93 mm`도 함께 줄바꿈하도록 보강했다. 원래 문자열이나 형상은 바꾸지 않았다. PDF 원호 검사는 유한 cubic 표본의 수치 허용 범위이며 제조 공차 또는 연속 곡선 오차 증명이 아니다.

이후 최종 보완 소스로 PDF만 2출력/2재검수하고 [네 페이지를 다시 렌더링](03_도면렌더링/README.md)하여 값/단위가 같은 행에 남는 것을 확인했다. 첫 실행의 파일을 덮어쓰지 않았다.

실제 Windows 초기 수동 검토에서는 조회가 성공한 뒤 미선택 상태에도 재조회 안내가 남는 문제를 발견했다. 또한 STEP 기록을 빠르게 바꿀 때의 비어 있는 3D 보기, 출력 작업 중 직접 사본 열기 경로의 전환 정책, Unix 초의 지수 표기도 보강 대상으로 확인했다. 자동시험 통과와 수동 검토 결과를 구분하여 후속 수정과 재검증을 기록한다.

`b38e5fe4...`의 실제 Windows 창에서 원래 고정 snapshot을 선택하여 PDF 미리보기/생성/별도 재검수를 수행했다. 기존 STEP을 선택해 OpenGL 형상을 확인하고 새 reader 재검수를 실행하여 body별 경계/중심/두께/체적/단면/홀의 실제 오차와 허용값을 읽었다. Ctrl+S 저장 후 정상 종료했다. [실행 화면 45~48](02_실행화면/README.md)에 당시 실행파일을 구분한다. 이 과정에서 초기 안내가 세부 영역에 남는 문제와 이름 없는 누락 항목 표시를 추가로 발견하여 마지막 표시 보완으로 분리했다.

`d547a9d0...`에서 출력 runtime 없는 새 프로세스로 초기 선택 안내를 확인했다. 마지막 `91f990d6...`에서는 앞서 생성한 PDF를 다시 선택하여 제외 객체 `실물 배터리·외함 미정`의 이름과 `include_in_export=false` 원문 사유를 실제 상세표에서 읽었다. 이름은 현재 편집값을 과거 출력에 덮어쓴 것이 아니라 그 출력의 snapshot에서 가져온다. [실행 화면 49~50](02_실행화면/README.md)과 보존 비교를 별도로 기록했다.

## 5. 보존과 미확립 범위

- 실제 출력/재검수 runner는 원본 workspace를 서비스로 열지 않고 별도 복사본을 사용했다. 원본 2509개 파일과 이전 solver 결과의 바이트 불변을 확인했다.
- 위 두 차례 8출력 실행은 `stage9-tuning1/workspace`의 2509개 파일을 원본으로 삼았다. 최종 PDF만의 후속 실행은 도면 산출물이 추가된 `stage10-exchange-final-workspace`의 3267개 파일을 별도 원본으로 복사하여 모두 불변임을 확인했다. 서로 다른 원본 파일 수를 합치지 않는다.
- `source_semantics`와 sidecar의 원문 및 미정값, 현재/저장 개정과 undo 이력을 비교했다. runtime 없는 재열기에서도 같은 완료 기록을 읽었다.
- 실제 Windows 수동 검수 workspace는 검수 전 4개 프로젝트의 문서/현재/저장/이력과 solver 결과, 기존 프로젝트 파일 322개를 고정했다. 생성/재검수/저장/종료 및 마지막 runtime 없는 재열기 후 모두 동일함을 확인했다. 이 수치는 위 runner 원본 workspace의 파일 수와 다른 범위다.
- SOLIDWORKS 2026 SP04.1은 제품 활성화가 필요하여 STEP 수신 검수를 수행하지 못했다. 활성화나 계정 입력을 진행하지 않았고 독립 커널 합격을 주장하지 않는다.
- KiCad 10.0.8 공식 배포 파일의 서명/hash와 CLI 실행을 준비했다. 아직 PCB 파일 교환의 수신 합격 근거가 아니다.
- NPTH/slot/cutout/footprint/paste, KiCad/Gerber/Excellon/Job 및 독립 수신 도구의 검수는 완료 계획 10번에 남는다.
- RO4350B 국부 방사 도체 손실 변화 2.788446%의 초기 2% 기준 미확립과 GHz PTH 독립 정확도 미확립을 유지한다. 총 전력 수지/형식 검사/화면 표시 성공으로 승격하지 않는다.
- 실제 제작/납품 물성, 급전 실장, 교정/시료/측정 조건은 자료 확보 전까지 미정이다. 전체 84개 화면, 접근성/성능/복구 및 R1 최종 수용을 완료 처리하지 않는다.
