# 대형 설계 30회 전환의 Windows 자원 검증

2026-11-21 KST. 완료 계획 12번 F5의 유지 정책에서 같은 Windows Studio와 Python 서비스를 사용해 저장된 형상 10000개와 매개변수 1000개의 F1 프로젝트를 열고, 빈 대기 프로젝트로 전환하는 절차를 30회 반복했다. 매회 저장된 개정과 표시 생략 0개, 대기 프로젝트의 형상 0개를 확인했다. 실행 중 서비스 세션은 1개였고 GUI와 하위 프로세스 3개의 PID가 유지됐다.

| 관찰 구간 | 합산 private commit |
| --- | ---: |
| 첫 열기 전 대기 프로젝트 | 104.06 MiB |
| 대형 프로젝트 열린 직후 관찰 최대 | 187.64 MiB |
| 초기 5회, 전환 30초 뒤 중앙값 | 119.11 MiB |
| 마지막 10회, 전환 30초 뒤 중앙값 | 134.20 MiB |
| 초기와 마지막의 중앙값 차이 | +15.09 MiB |
| 전환 30초 뒤 관찰 최대 | 155.82 MiB |

중앙값 증가는 F5의 수치 기준 32 MiB 이내였다. GUI 핸들은 298개에서 294개, 애플리케이션 서비스 핸들은 224개에서 214개가 됐다. 나머지 프로세스의 핸들 수는 같았다. GUI와 서비스 모두 후반의 private commit 중앙값이 늘었고, 26회와 30회에서 각각 서비스와 GUI의 일시적 고점이 관찰됐다. 증가 원인은 확인이 필요하다. 이 실행은 합성 설계의 프로젝트 교체, 동일 서비스 유지와 요청 종료 뒤 30초 표본을 검증한다. F2/F3, 150초 유휴 회수 30회, 전체 GPU 자원과 메모리 증가 원인의 수용은 남는다. [실행 기록](129_대형설계_반복전환_실행기록.json)

격리한 새 디렉터리에서 `tools/measure_windows_project_switch.py run <Windows Release 실행 파일> <새 시험 디렉터리>`로 재현한다. 실제 Studio 제품의 프로젝트 열기 경로로 실행한다. `--cycles 1` 예비 실행에서 같은 수집 절차도 확인했다.
