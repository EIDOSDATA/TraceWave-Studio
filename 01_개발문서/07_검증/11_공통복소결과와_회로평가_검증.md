# 공통 복소 결과와 회로 평가 검증

기록일: 2026-11-17 KST. 개발 완료 계획 5번. 승인 기준선 RFAD-D0-3.4와 기존 1~13번 순서를 유지한다. 실행 기준은 공통 외형 보강 커밋 `dd9a20d319822d8f4269ed26b2ae4b0db92f409d` 이후 작업 트리다. 실제 실행 시점/바이너리/로그 hash는 [기계 기록](12_공통복소결과와_회로평가_실행기록.json)에 구분하며 이후 게시 커밋을 과거 실행 기준으로 소급하지 않는다.

## 1. 구현과 검수 범위

- 공통 S/Z/Y, 1~2포트, 1001표본, 복소 Z0/미정 조건의 원본 보존과 유효 mask.
- 양의 실수 Z0의 명시 변환/재정규화, 독립 조건수/잔차와 특이 표본 마스크.
- 1포트 부하 앞의 이상 직렬/병렬 RLC 16요소, DC/open/short/DNP, 소자 미정 저장과 계산 차단.
- Touchstone/명시 CSV/정규 HDF5, 원문 bytes/표시 이름/조건과 source SHA256, 별도 파생 파일 및 내보내기 sidecar.
- 정확한 목표 주파수/포트/Z0/기준면 판정, 목표 원본과 개정별 과거 평가, 누락과 조건부 표본 통과.
- 실제 wxWidgets의 결과 3열 화면, 가져오기/회로/변환 입력, Studio 목표 평가 본 화면과 저장/재열기.

상세 범위는 [계산/저장 계약](../05_기능설계/04_해석결과/06_공통복소자료와_회로평가.md), [파일 계약](../05_기능설계/05_출력교환/03_복소결과_파일교환.md), [화면 계약](../04_화면설계/19_복소결과와_회로평가_화면.md)을 따른다. 기존 core 0.5와 프로젝트 512 KiB, origin 256 KiB, worker 파일 192개 및 CAD 2 MiB/solver 4 MiB 상한을 완화하지 않았다.

실행 범위는 겹치며 단순 합계로 독립 시험 수를 부풀리지 않는다. 1001표본/16소자의 전체 진단 봉인과 32개 페이지, 1001개 명시 목표의 원본/평가 페이지, 실수부/허수부와 두 포트 축 순서, 서로 다른 포트 Z0, 누락/특이/무한대, 공개 RPC의 512 KiB 원문 전송 예외, 영수증 재시도와 no-engine 재열기를 검사했다.

독립 검토에서 Z0 텍스트/Quantity를 SI 배열로만 보존하던 문제를 발견했다. `original_options`와 `reference_quantity`를 추가해 입력 단위/추정 상태/출처를 남긴다. 파서는 극단 지수와 underflow를 명시 오류로 처리하며 작은 값을 0으로 바꿔 소자를 생성하지 않는다. 표시 단위만 바꾸면 SI/출처/상태를 유지한다.

마지막 연결 검토에서는 복소 자료 목록과 정밀 편집 출처가 있는 설계를 PCB 계획에서 미지원 확장으로 거절하던 경계를 수정했다. 프로젝트 validator가 검증한 두 메타데이터를 원본 사본에 그대로 보존하며 물리 계획 입력은 변하지 않는다. 미지 확장, 잘못된 버전/출처 해시와 256 KiB 계획 상한은 유지한다. 첫 회귀 14개는 새 시험이 선폭을 바꿔 포트 접촉을 깨뜨려 실패 1개/오류 1개였다. 시험을 유효한 방사선 길이 변경으로 바로잡은 뒤 14개가 통과했으며 원 실패 로그도 보존한다. 이 서비스 소스 변경은 새 worker identity에 반영하고 과거 계획/원문은 수정하지 않는다.

## 3. 실제 Windows GUI와 발견한 문제

첫 통합 GUI 실행은 가져오기 창 생성에서 access violation으로 실패했다. GDB에서 한국어 `wxString::Format` 직접 literal의 Windows 문자열 변환 경계를 확인하고 UTF-8 표시 변환을 적용했다. 실패 로그를 보존하고 성공 실행과 구분한다. 수정 뒤 집중 시험 1개가 15.344초에 통과했으며 15개의 실제 창/서비스 상태 검사를 포함했다.

이후 시안 40과 다른 모달 중심 목표 평가 흐름을 수정해 Studio 결과의 실제 하위 페이지로 연결했다. 입력 조건만 기존 모달로 편집하고 저장된 판정은 왼쪽 목록/가운데 기준표와 실제 표본/오른쪽 당시 조건과 출처에 표시한다. 해당 페이지와 원본 자료 일치, 표본 조회, 2D 복귀 선택 보존을 추가한 당시 통합 시험은 16개의 명시 검사를 수행했다.

전체 GUI 회귀는 26개 중 24개 통과, 실제 WSL 계산 2개 환경 제외, 실패/오류 0, 431.645초였다. 실제 CAD GUI 2개와 새 네트워크 시험을 포함한다. 이 실행은 마지막 표시 문구/축 제목 정리 전 빌드이며 이후 기본 실행 파일의 집중 확인과 수동 검수를 별도 기록한다. CTest는 9개 통과했다.

표시 문구 정리 뒤 기본 실행 파일의 집중 시험은 1개/16개 검사, 18.381초에 통과했다. 이어 실제 1648 x 954 창을 직접 조작하여 목표 평가 표본표가 0 높이로 압축되고, 평가와 다른 자료를 보던 목록의 강조가 복귀 후 남는 문제를 발견했다. 자동 시험 통과만으로 외형을 수용하지 않았다. 평가 중앙을 세로 스크롤로 바꾸고 기준표 136 DIP/표본표 128 DIP를 보장했다. 결과 목록은 실제 자료의 선택/초점/표시 위치를 함께 맞춘다.

이 수정 뒤 `cbb69880...` 기본 실행 파일의 집중 시험 1개/16개 검사, 16.708초와 CTest 9개/0.26초가 통과했다. 표의 실제 표시 높이와 목록의 선택/초점/자료 일치를 검사하며 overflow가 있을 때만 스크롤 접근을 검사한다. 같은 빌드의 수동 재열기에서도 3개 표본이 보이고 미정 원본 -> 명시 원본의 목표 평가 -> 네트워크 복귀 시 명시 원본이 강조되는 것을 확인했다. 모든 창 크기/DPI의 접근성을 검사했다는 뜻은 아니다.

수동 대조에서 그래프가 너무 납작하고 RLC의 소자 추가 버튼이 첫 화면 아래로 잘리는 문제를 확인했다. 그래프 여백과 표 높이를 조정하고 소자 추가를 그림 다음/표 앞에 배치했다. 적은 소자는 회로 그림의 가용 너비를 사용하며 많은 소자는 가로 스크롤을 유지한다. 조건 object가 존재해도 제작/측정 값이 null이면 각각 미정으로 표시한다. 공통 Sij의 0 크기는 반사라는 이름을 붙이지 않고 크기 0으로 표시한다.

GUI 자동 시험은 실제 Windows wx 이벤트 루프와 별도 Python 서비스에서 수행한다. 부정확 파일 거절, 명시 조건 채택, CSV 열 대응, 검토 후 입력 변경 무효화, 늦은 응답/닫힌 창/불명 mutation 잠금, 단일 undo/redo, 미정 RLC 저장, 별도 정의/결합 저장, S -> Z, 목표 평가, 파일+sidecar 및 기존/원본 경로 보호를 검사한다. 그 뒤 프로젝트 저장과 서비스 재시작을 수행하고 별도 서비스가 실제 저장 파일을 다시 읽어 대조한다. 자동 시험과 수동 시각검수는 별도 증거다.

마지막 주파수 표시 보완에서는 긴 Hz 숫자를 Hz/kHz/MHz/GHz로 표시하고 전체 자료/평가 범위로 자동 단위를 고정했다. 표와 곡선은 같은 단위를 사용하며 페이지를 넘겨도 자동 단위가 바뀌지 않는다. 원본 SI 수치와 입력 Quantity는 변경하지 않는다. 첫 주파수 GUI 시험 1개는 4.295초에 실패했으나, 원인은 시험에서 `GetColumn`으로 머리글을 읽을 때 `wxLIST_MASK_TEXT`를 지정하지 않은 것이었다. 시험의 열 조회를 수정했고 이 실패를 제품의 주파수 계산 오류나 성공 실행으로 바꾸지 않는다.

주파수 보완 뒤 최종 기본 실행 파일의 SHA256은 `c5f3e6b2a36e5692f9cfffef39ab4b14d12e5fd91bd6153f1b58d7c679069b61`이다. 이 빌드의 실제 GUI 집중 시험은 1개/17개 명시 검사, 14.049초에 통과했고 CTest 9개는 0.38초에 통과했다. GUI에서는 자동 1 GHz -> 명시 1000 MHz -> 1 GHz 전환 후 원본 선택 DTO/프로젝트 개정/undo 이력이 같고 새 요청이 발생하지 않음을 확인했다. 평가 표의 GHz 머리글과 실제 표본, 최소 표 높이, 기존 원문/회로/변환/평가의 저장과 재열기 검사를 함께 수행했다. 앞의 전체 서비스/전체 GUI 수집을 이 최종 빌드에서 다시 수행했다고 표시하지 않는다.

같은 최종 빌드를 직접 조작하여 [09 복소 결과와 미정 조건](02_실행화면/09_복소결과와_미정조건.jpg), [10 외부 회로 구성](02_실행화면/10_외부회로_구성과_출처.jpg), [11 목표 평가와 실제 표본](02_실행화면/11_목표평가와_실제표본.jpg), [12 원문 가져오기 검토](02_실행화면/12_원문_가져오기_검토.jpg), [13 S -> Z 변환 후보](02_실행화면/13_명시변환_후보검토.jpg), [14 외부 회로 결합 후보](02_실행화면/14_외부회로_결합후보.jpg)의 JPEG 6장을 다시 캡처했다. GHz/MHz 표시, 원문 미정값과 평가 당시 조건, 변환 및 RLC의 실제 후보 값과 표를 재확인했다. 이는 해당 창 크기의 최종 수동 표시 검수이며 새로운 FDTD나 실측 시험은 아니다.

최종 문서/요구 추적 감사 시험 14개는 1.265초에 통과했다. 문서/추적 검사와 CTest, 실제 GUI 검사는 서로 다른 실행이며 서비스 시험 수에 합산하지 않는다.

## 4. 보존 확인

6개 수동 화면을 보존한 뒤, 평가의 전체 주파수 범위가 없을 때 사용할 대체 자료의 동일성 검사를 추가로 바로잡았다. 평가의 canonical hash와 파일 bytes의 SHA256을 서로 비교하던 코드를, 양쪽의 봉인 artifact SHA256 비교로 변경했다. 정상 서비스 응답에는 전체 범위가 있어 앞선 수동 화면에는 영향이 없었다. 같은 자료/다른 자료/누락·잘못된 형식의 회귀를 추가했다. 마지막 실행 파일 `02e2d4caf62ff142a43f2faf999366519ab85de3f8344d33b3dab039e4afc6cb`에서 CTest 9개/0.38초, 실제 Windows GUI 1개/17개 검사/20.494초와 서비스 2회 수명의 저장·재열기를 통과했다. 최신 근거 재생성 후 감사 14개/1.930초도 통과했다. 앞선 수동 캡처는 `c5f3e6b2...` 빌드의 증거로 유지하며 마지막 바이너리에서 재촬영한 것으로 소급하지 않는다.

GUI 자동 시험의 이전 자료 bytes/정규 JSON/HDF5/raw SHA256, 이전 network entry, 기하/목표/재료/적층/포트/제조 규칙/매개변수, source extension과 초기 snapshot을 대조한다. 원래 미정 기준면/시간 규약/제작·측정 조건, 재료 Df 미정 및 목표 Quantity의 출처가 유지된다. 가져오기에서 명시 채택한 조건은 최초 원문 사본과 별도로 저장된다.

새 자료/회로/평가 적용은 기존 writer/영수증과 한 개의 역명령을 사용한다. GUI 시나리오의 이전 1개와 새 6개 명령 이력을 확인하며 재열기에 CAD/solver를 요구하지 않는다. HDF5 재해석은 같은 고정 환경에서 정규 JSON과 대조한다. 원본 해석기를 설치하지 않아도 저장된 정규 JSON/이력/평가를 읽을 수 있다는 범위와 새 HDF5/계산의 선택 의존성을 구분한다.

수동 검수 프로젝트는 `Code/.local/network-visual-20261117-9359aa97`이며 제목은 '복소 자료 GUI 검수 - 수식 시험 / 실측 아님'이다. 1/1.5/2 GHz에서 명시 복소수 0.1 + j0 및 이상 직렬 50 ohm을 사용한다. 제작/측정과 Df는 미정이다. 이 프로젝트의 두 선은 서비스 경계 검수용이고 실제 안테나/비콘 artwork 또는 FDTD 결과가 아니다. 기준 원본/저장본/불변 snapshot은 기계 기록에 hash로 고정한다.

실제 파일 선택 -> 원문/조건 검토 -> 가져오기 -> Ctrl+S -> 창 종료 -> 별도 서비스 재열기 -> Windows 앱 재열기를 수행했다. 추가한 원문 자료는 1개이며 원래 3개 자료/1개 회로/1개 평가와 모든 artifact hash가 유지됐다. 프로젝트 개정/부모 개정/변경 시각과 새 자료 entry를 제외한 원본 필드 전체가 같다. 새 원문의 bytes와 원래 파일이 같으며 파 정의/시간 규약/기준면/조건 null이 보존됐다. 불변 snapshot도 원래 SHA256과 일치한다. 검수 스크립트의 첫 대조는 정상적인 부모 개정/변경 시각을 제외하지 않아 실패했고, 두 번째는 조건 object 자체가 null인 형식을 잘못 가정하여 실패했다. 실제 저장 자료가 바뀐 문제는 아니며 해당 기대를 바로잡고 대조를 통과했다.

마지막 주파수 표시 보완과 6개 화면 재캡처 뒤에도 같은 `c5f3e6b2...` 빌드에서 수동 재열기를 확인했다. 프로젝트 개정 `11e90024-1443-4390-8c36-be8f664350f2`와 프로젝트 파일 SHA256 `5793680ca03a87dd7c7bea820a0e47198116b2268d0359e8013ac474776889a8`이 유지됐다. 주파수 표시 변경과 결과 조회를 새 설계/회로/평가 적용 명령으로 기록하지 않았다.

## 5. 수용의 경계

새 FDTD, 메쉬 수렴, 실물 제작/측정, 도체/PTH 독립 정확도 시험을 수행하지 않았다. RO4350B 국부 방사 도체 손실 변화 2.788446%의 초기 2% 미확립과 GHz PTH 미확립을 유지한다. 표본 판정은 연속 대역 합격이 아니며 외부 RLC 파생 결과에 기존 방사 효율을 복사하지 않는다.

복소/미정 Z0의 원본 보존과 현재 양의 실수 Z0 계산 범위, 제한된 파일 구문과 일반 Touchstone/혼합모드 지원, 기본 RLC와 실제 부품 기생/정합 합성은 별개다. Smith/다중 결과 비교/3D 방사, 기준면 이동/보간, 측정 교정/불확도 및 전체 84개 시안/접근성/성능/R1 수용은 아직 완료되지 않았다. 기본 실행 파일과 시험용 별칭은 같은 구현에서 빌드하지만 각 바이너리 hash는 따로 기록한다.
