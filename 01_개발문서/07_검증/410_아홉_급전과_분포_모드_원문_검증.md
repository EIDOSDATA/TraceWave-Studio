# 아홉 집중 급전과 공간 분포 모드 파일

2026-11-23 KST. PCB 설계와 복소 자료의 집중 급전 상한을 12개로 확장했다. 9개 및 12개에서 모든 포트와 단자 순서, 비대칭 Touchstone 행렬, CSV 열 대응, HDF5 및 전체 복소 행렬 교환을 시험했다. 열 번호는 0부터 288까지이고, 행 길이는 8192자, 원문 파일은 4 MiB 상한을 적용한다. GUI 입력란에서는 같은 열과 포트 범위를 선택한다.

## 9포트 실제 계산과 재열기

합성 원형 PCB의 적층과 동박을 제품의 동일 격자에 투영하고 9개의 물리 급전을 한 번씩 여기했다. 나머지 포트는 각자 실수 저항으로 종단했다. Windows x64의 upstream openEMS 0.37.0, CSXCAD 0.7.0, CPython 3.14 휠을 계산에 사용했다. 복소 결과의 프로젝트 저장과 재열기는 고정 CPython 3.12 수치 환경에서 실행했다. [upstream 릴리스](https://github.com/thliebig/openEMS-Project/releases/tag/v0.37.0)

| 확인 | 관측 |
| --- | --- |
| 실제 여기와 격자 | 9개 모두 에너지 종료 기준 충족. 실행별 54.64~84.58초. 525,532 격자점, 8~12 GHz 31개 표본 |
| 독립 CalcPort | 81개 입출력 조합의 파형으로 전체 2,511개 복소 계수를 다시 계산. 최대 오차 6.866351e-16 |
| 원시 자료 재처리 | 모든 여기의 파일 SHA-256을 확인한 뒤 원래 전압/전류를 재처리. 정규 네트워크 전체가 처음 결과와 일치 |
| 저장 및 새 세션 | 같은 개정의 실제 Touchstone을 원문으로 가져와 저장했다. 새 ProjectService에서 81개 행/열의 31개 표본과 원문 바이트가 동일했다. 등록 ID는 `9772b5b3-5bdc-5a74-8a66-c096903e7969` |

원본 개정 SHA-256은 `92e7ef0b59851ca804f30732ec3898e9ecfa0a2de462f3e018ded54e55c0cd16`, 격자는 `8bacdae2ce6ce66d24576ca7abd947cee5e671766c51c50e1e327200fdeeb271`, 정규 네트워크는 `52035477154e0b7d0b38d394159fa17cc8fc0238429bf9d03277b2d16f106c0a`다. 12개의 물리 여기까지 실행한 수치는 없다.

## 단면 모드의 분포 여기

`waveguide-mode-files`는 409 단면의 TE/TM 접선장을 표본화해 openEMS가 읽는 전계/자계 HDF5 원문 두 개를 만든다. 공통 요소 변에서는 면적 가중 평균을 적용한다. 출력에 단면과 편파, 입사 방향, 기준면, 차단 및 진행 파수, 주파수, 기준 임피던스, 1 W 계수와 두 원문 해시를 남긴다. 내보낸 TE10 분포는 독립 사인 분포와 대조했다. [409 단면 모드](409_일반_도파관_단면의_티이_티엠_결합_검증.md) [openEMS 일반 모드 포트](https://docs.openems.de/en/v0.37.0/concepts/ports.html#generic-waveguide-port)

20 x 10 mm 공기 도파관에서 제품 단면 TE1의 차단값은 7.496331 GHz였다. 10.5 GHz에서 +Z로 실제 모드 여기를 수행하고 Z=20 mm와 40 mm에 전력 참조면을 두었다. 복소 반사는 `0.00052561 + j0.00082463`, 전달은 `-0.99817514 - j0.05855653`였다. 409에서 구한 진행상수와 openEMS의 시간 위상 규약으로 예측한 전달 `-0.99821412 - j0.05973760`과 최대 복소 차이 0.001182였다. [재현 도구](../../Code/tools/verify_windows_openems_mode_files.py)

```powershell
& $numeric -c "import json; from test_waveguide_section import rectangular_step; print(json.dumps(rectangular_step([20,10],[20,10],[0,0],0.45,10.5e9,14)))" | Set-Content -Encoding utf8 .local/straight-guide.json
& $numeric -m rfad waveguide-mode-files .local/straight-guide.json --side wide --mode TE1 --frequency-hz 10500000000 --pitch-mm 0.5 --output .local/te-source
& $native tools/verify_windows_openems_mode_files.py .local/te-source $openEms .local/te-run
```

## 남은 실행 범위

등록된 `TraceWave-Dev`의 원래 VHDX 경로가 사라져 해당 배포판과 자료를 보존한 채 별도 `TraceWave-NineLab`을 설치했다. Ubuntu 24.04 WSL2가 부팅되지만 guest에서 Ubuntu 저장소의 HTTP 및 HTTPS와 GitHub HTTPS가 타임아웃되어 공식 고정 Linux 런타임을 빌드하지 못했다. guest에서 패키지와 고정 소스를 내려받을 수 있거나 기존 VHDX 백업을 복원하면 Linux native 감사 및 Windows 감독 경로의 실제 작업과 원시 결과 재처리를 재개한다. 위의 프로젝트 재열기는 실제 Windows solver의 Touchstone 가져오기 경로다. 같은 모드 파일을 직사각 PCB의 양쪽에 연결한 Windows 실제 실행은 413에 기록했다.
