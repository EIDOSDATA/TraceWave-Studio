# 도파관 대칭면과 FDTD 재개 검증

2026-11-23 / Windows 개발 PC, WSL2 TraceWave-Dev / openEMS 0.37.0

## 전기 벽과 자기 벽을 사용한 절반 영역

진공 직사각 도파관의 전체 단면 20 x 10 mm와 두 종류의 반영역에서 동일한 TE10 모드를 여기했다. 도파관 길이는 80 mm, 측정면 거리는 50 mm, 주파수는 9.5~10.5 GHz의 31점이다. 축소한 단면에서도 원래 단면의 모드 함수와 차단 주파수를 사용했다. x=10 mm는 접선 자기장이 사라지는 PMC 면으로 두고, y=5 mm는 접선 전기장이 사라지는 PEC 면으로 두었다. PMC는 Yee 격자에서 마지막 전기장 격자선 두 개의 중간에 위치한다. 두 격자 모두 전체 모델의 해당 표본 위치와 일치시켰다.

| 목표 셀 mm | 모델 | 격자 구간 x/y/z | 종료 스텝 | 전체 모델과의 최대 abs(S11 차이) | 전체 모델과의 최대 abs(S21 차이) |
| --- | --- | --- | ---: | ---: | ---: |
| 1.00 | 전체 | 21/10/80 | 4312 | 0 | 0 |
| 1.00 | x PMC 반영역 | 11/10/80 | 4312 | 6.271e-4 | 1.312e-6 |
| 1.00 | y PEC 반영역 | 21/5/80 | 4312 | 1.948e-13 | 4.105e-13 |
| 0.75 | 전체 | 27/14/109 | 6003 | 0 | 0 |
| 0.75 | x PMC 반영역 | 14/14/109 | 6003 | 3.731e-4 | 1.111e-6 |
| 0.75 | y PEC 반영역 | 27/7/109 | 6003 | 8.728e-14 | 4.233e-13 |

여섯 해석 모두 설정 에너지 비 1e-7에 도달했다. 각 해석에서 기존 도파관의 해석식 대비 반사, 투과 진폭, 포트 임피던스, 군지연 기준을 통과했다. 위의 차이는 주파수별 복소수 차이의 절댓값이다. 전체와 반영역의 추가 회귀 검사는 S11, S21 모두 최대 0.03을 적용한다.

저장소 루트에서 아래 명령으로 재현한다. 해석 입력과 출력은 실행마다 새 임시 디렉터리에 작성하며, 표의 수치는 표준 출력에 JSON으로 반환한다.

```powershell
wsl.exe -d TraceWave-Dev -u tracewave --exec /home/tracewave/rfad-runtime/openems-venv/bin/python Code/tools/verify_te10_symmetry.py --openems /home/tracewave/rfad-runtime/openems/0.37.0/bin/openEMS
```

사용자 PCB에는 형상, 재료, 급전 위치 및 극성의 반사 대칭 확인, 계산 영역 절단과 급전 임피던스 환산을 별도로 구현해야 한다. 기존 PCB 화면에서 전체 외곽의 한 면을 PEC 또는 PMC로 바꾸면 격자 범위는 유지된다. 이 시험의 검증 범위는 위 도파관의 대칭 모드다.

## 주기 경계와 체크포인트

설치된 바이너리의 소스는 `305df56aa7df4d2f18c687083f484a96f9a22610`이다. Python 바인딩 `SetBoundaryCond`에 마주 보는 두 면을 `Periodic`으로 전달한 실기는 `Unknown boundary condition`을 반환했다. 기본 연산자는 PEC와 PMC, 추가 연산자는 MUR와 PML을 처리한다. PCB의 주기 경계는 양 끝 Yee 표본의 성분별 대응, 격자 일치 검사, 양방향 장 교환과 Bloch 위상에 대한 구현 및 독립 검증이 남았다. [고정 버전 경계 처리](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/openems.cpp#L398) [고정 버전 Python 바인딩](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/python/openEMS/openEMS.pyx#L306)

실제 실행 파일의 도움말과 고정 소스에서 FDTD 상태를 저장하거나 재개하는 옵션을 찾지 못했다. 엔진은 생성 시 스텝을 0으로 초기화하고 준비 후 시간 반복을 시작한다. Python 객체의 직렬화 시도도 `no default __reduce__ due to non-trivial __cinit__`로 종료했다. 실행 XML, 진행 로그, 출력 프로브에는 전체 동적 상태가 없다. 정확한 재개에는 전압/전류 Yee 배열, 현재 스텝과 구동 파형 위치, PML 및 도체 모델의 내부 이력, 종료 에너지 이력, 프로브와 누적 주파수 데이터의 저장 및 복원이 필요하다. 입력과 엔진 해시를 묶고, 끊김 없는 실행과 재개 실행의 시간 파형, 복소 S, 종료 스텝이 일치하는지 대조해야 한다. 이 항목은 소프트웨어 개발 작업으로 남는다. [고정 버전 엔진 초기화](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/FDTD/engine.cpp#L38) [실제 시간 반복](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/openems.cpp#L1485)
