# Windows 2D 표시 비용 검증

2026-11-20 KST. 12번 F1의 표시 경로에서 선과 원호 10,000개를 다루는 비용을 분리해 측정했다. [기존 wxMemoryDC 도구](../../Code/tools/canvas_render_benchmark.cpp)의 `--f1-render` 모드에서 1000 x 700 픽셀의 같은 두 장면을 그렸다. 전체 보기는 1.6 px/mm, 확대 이동은 8 px/mm로 고정하고 같은 경로로 시점을 이동했다. 양 끝이 창을 벗어난 관통 선과 중심이 창 밖이지만 호 및 선택 강조가 창 안에 걸리는 원호를 함께 넣었다.

## 표시 동작

[표시 코드](../../Code/ui/wxwidgets/canvas_renderer.cpp)에서 native 좌표 범위 검사를 먼저 수행한다. 일반 선은 기존 클리핑을 path 생성 전에 적용한다. 원호는 전체 원의 경계에 선폭과 강조 여백을 더해 화면과 닿을 수 있을 때만 native path를 만든다. 화면에 남는 경로의 색, 두께와 그리기 순서, 범위 초과 진단 및 선택과 원본 명령의 경계를 유지한다.

전체 보기와 확대 이동 각각의 마지막 RGB 2,100,000바이트를 비교했다. 최초 실행과 교차 비교 3쌍에서 변경 전후 픽셀이 모두 일치했다. 실제 Windows GUI 회귀 10개와 CTest 13개가 통과했다. GUI 시험은 기존 선·원호 편집, 속성, undo와 저장·재열기 경로를 포함했다.

## 그리기 시간

각 장면에서 준비 5회와 60개 표본을 수집했다. 교차 비교 3쌍의 실행 순서를 번갈아 바꿨다. 표의 p95는 nearest-rank 방식이다.

| 실행 | 전체 보기 이전 p95 (ms) | 전체 보기 개선 p95 (ms) | 확대 이동 이전 p95 (ms) | 확대 이동 개선 p95 (ms) |
| --- | ---: | ---: | ---: | ---: |
| 별도 빌드 직후 | 16.83 | 18.67 | 10.29 | 6.63 |
| 교차 비교 1 | 16.91 | 17.45 | 10.57 | 5.08 |
| 교차 비교 2 | 16.53 | 16.15 | 9.78 | 5.89 |
| 교차 비교 3 | 18.96 | 19.81 | 11.90 | 5.80 |

확대 이동은 교차 비교 세 번 모두 p95가 줄었다. 전체 보기의 개선 빌드 p95는 교차 비교에서 16.15~19.81 ms로 변동했다. 이 표본은 합성 projection을 그리는 비용이다. 서비스 프로젝트의 10,000개 형상, 1,000개 매개변수, 검색 레코드와 UI 표, 실제 입력부터 표시까지의 간격 및 합산 메모리는 아직 F1 규격으로 측정해야 한다. 같은 이유로 60 fps 수용 판정은 미확립이다.

## 재현

```powershell
cmake --build build/windows-release --target tracewave_canvas_benchmark
./build/windows-release/bin/tracewave_canvas_benchmark.exe .local/f1-render.json --f1-render
```

JSON과 별도 RGB 파일 2개를 새 경로에 기록한다. 1픽셀당 RGB 3바이트를 저장하고 쓰기와 비교는 그리기 시간에서 제외한다. [실행 기록](54_윈도우_이차원_표시비용_실행기록.json)에 최초 및 교차 표본, 실행 파일과 픽셀 해시, 회귀 결과를 담았다.
