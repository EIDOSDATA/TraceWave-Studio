# 실제 Windows 저장 여유 공간 거절과 재시도

2026-11-21 KST. 저장 준비에 필요한 여유 공간이 부족하면 Studio에 저장 실패와 재시도 안내를 표시한다. 기존 상태 파일을 쓰는 중 실패해 게시되지 않았다는 진단에도 같은 복구 흐름을 사용한다. 마지막 저장 기준과 현재 편집을 유지하고 사용자가 공간을 확보한 뒤 저장을 다시 선택한다.

| 실제 Windows GUI 검증 | 실패 조건 | 확인 |
| --- | --- | --- |
| 저장 요청 접수 전 여유 부족 | 첫 저장에서만 운영체제 여유 조회를 1 MiB로 주입해 journal의 기존 16 MiB 검사를 발동 | 미접수 요청의 작업 기록 없음, 이전 저장 기준 유지, 재시도 후 같은 개정 저장과 두 번째 서비스 세션에서 재열기 |
| 저장 파일 게시 전 쓰기 실패 | 첫 쓰기에서 ENOSPC 주입 | 실패 작업과 성공 재시도의 요청 개정 일치, 마지막 저장 기준 유지, 재열기 |
| 원문 손상과 writer 충돌 | 봉인 파일 변경, 실제 중복 writer | 각각 다른 진단과 기존 원문 보존 |

실제 Windows GUI 4개와 저널 17개가 98.361초에 통과했다. Release CTest 13개도 통과했다. [실행 기록](189_저장_여유공간과_재시도_실행기록.json), [이전 복구 실행](160_윈도우_손상차단과_복구_검증.md)

별도 시도에서 WSL2에 32 MiB 격리 tmpfs를 만들고 Windows에서 전체 용량을 확인했다. 해당 공유 경로는 Windows writer의 바이트 잠금에서 오류를 반환했다. 64 MiB 동적 Windows 테스트 디스크의 생성은 현재 계정의 권한이 부족해 중단했다. WSL 격리 볼륨과 디렉터리는 원상 복구했다. 실제 Windows 저장 볼륨 소진과 전원 차단은 미검증이다.
