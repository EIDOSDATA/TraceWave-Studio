# IPC-2581C 및 ODB++ 출력 후보 검증

2026-11-23 / Windows 개발 PC / EDA15, EDA16

## 사용

Studio가 같은 개정에서 게시한 KiCad 보드 패키지의 다섯 파일을 같은 폴더에 둔다. [변환 명령](../../Code/tools/export_manufacturing_exchange.py)은 패키지의 각 파일 hash, worker 기록, 봉인한 개정과 source sidecar를 대조한다. KiCad CLI가 읽은 입력 사본에서만 두 형식을 생성한다. 원본, 실행 버전, 형식별 검사와 hash를 한 후보 ZIP에 넣는다. 기존 ZIP이 있으면 새 이름을 요구한다.

~~~powershell
python Code/tools/export_manufacturing_exchange.py --input .\kicad_pcb --output .\manufacturing.zip --kicad-cli C:\KiCad\bin\kicad-cli.exe
~~~

옵션 --format ipc2581 또는 --format odb로 한 형식만 생성할 수 있다. 도구는 설치된 CLI의 버전을 기록한다. 입력은 Studio의 원래 manifest를 포함해야 한다. [KiCad CLI 공식 명세](https://docs.kicad.org/10.0/en/cli/cli.html)

## 검증

- Windows에서 KiCad 10.0.8이 제품 출력 worker의 원호와 IFA 보드를 각각 수신했다. 두 형식 모두 mm의 외곽 치수가 원호 16 x 12, IFA 40 x 60과 일치했다. IPC XML과 ODB++ profile을 별도로 읽었으며 ODB++ 층과 EDA 자료가 존재했다.
- 이전에 게시한 KiCad 샘플의 CLI 출력도 실행했다. 원본 다섯 파일 동등성, 출처 개정, 기존 목적 파일 보호와 원본 변조 거절을 확인했다.
- Windows 실제 제조 교환 및 기존 가져오기/내보내기 Python 시험 19건에 통과했다. 출력은 제조 후보로 표시하고, 미정 물성과 공구의 판단 기준은 이전 설계의 source sidecar에 유지한다.

IPC 논리·물리 넷, 개별 홀/슬롯, 실장과 패널 속성의 완전한 대응은 수신 CAM 또는 EDA에서 별도로 검수한다. Studio에서 IPC-2581 및 ODB++로 설계를 왕복하고 편집을 반영하는 작업과 GUI 연결은 남아 있다.
