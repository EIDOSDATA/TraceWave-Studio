# WSL 해석 작업의 입력 전송과 실행 기한

2026-11-23 / Windows 개발 PC, WSL2 TraceWave-Dev

## 대형 IFA 기록

같은 1,089,835점 IFA의 첫 후속 해석에서 guest는 900초 예산을 소진하고 `timeout` 상태와 종료 확인을 기록했다. 동일 입력을 재개한 두 번째 시도에서는 Windows가 guest의 종료 확인 기한을 초과했다고 기록하고 취소를 보냈다. guest가 기록한 실제 작업 시간은 895.468초, 최종 상태는 `cancelled`였고 Windows 연구는 `interrupted` 상태를 보존했다. 두 시도의 마지막 에너지 관측값은 -16.41 dB였으며 지정한 -50 dB 에너지 기준에는 도달하지 않았다. [원본 연구와 두 실행 기록](396_직전_전계에서_국부격자를_반복하는_연구.md)

기존 코드는 입력 복사를 시작하기 전에 계산 예산, 10초 lease, 15초 종료 확인 여유를 합산해 하나의 기한을 설정했다. 큰 입력을 복사하고 작업 소유권을 인계하는 동안 Windows 쪽 계산 감시 시간도 경과했다.

## 적용한 동작

- 시작 요청의 입력 복사, 해시 검사 및 작업 인계에는 전송과 상태 조회의 유한한 상한을 적용한다. 제품 기본값은 전송 240초, 상태 조회 10초다. 시작 응답을 잃으면 같은 실행 ID와 nonce로 상태를 조회한다.
- Windows는 소유권을 확인한 guest 응답에서 실제 worker PID를 처음 관측한 시각부터 계산 예산, lease와 종료 확인 여유를 센다. 이후 heartbeat는 종료 확인 기한을 연장하지 않는다. 실제 계산 상한과 에너지 종료 조건은 guest가 계속 적용한다.
- 시작 중 worker PID를 확인하지 못한 경우와 이미 인계한 작업의 종료를 확인하지 못한 경우는 각각 해당 원인을 기록하고 취소를 요청한다. 출력은 원래 소유권과 종료가 확인된 완료 결과에서 읽는다.

## 자동 검증

모의 시간축에서 입력 전송 30초, 실제 worker 인계까지 10초를 주었다. 900초 예산의 끝에서 정상 완료와 guest 시간 초과를 각각 반환하고, 시작 응답을 정상 수신하는 경우와 유실 후 상태 조회로 복구하는 경우를 교차 검증했다. 수정 전 고정 소스는 네 조합 모두 조기 취소를 전송했고, 수정 후에는 시작 중복 없이 네 조합이 각각 원래 종료 사유를 반환했다. 시작 중 worker를 찾지 못한 경우와 worker가 종료 상태를 전하지 않는 경우에는 지정한 감시 기한 한 번만 적용하고 취소했다. 사용자 취소, 종료 미확인 시 출력 비공개, 응답 유실 복구도 포함해 Windows 호스트 회귀 16개가 통과했다.

실제 Windows와 WSL2에서 보존 출력을 생성하는 짧은 작업과 2초 예산을 지정한 대기 작업을 실행했다. 두 시험은 입력 복사, 작업 인계, 실행, 종료 확인과 정리를 포함해 53.976초에 통과했다.
