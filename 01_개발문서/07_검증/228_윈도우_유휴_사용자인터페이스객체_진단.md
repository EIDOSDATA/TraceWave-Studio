# Windows 대형 프로젝트 유휴 GUI 객체 진단

2026-11-21 KST. 편집 우선 시작과 취소 개선을 적용한 같은 Windows Studio에서 150초 유휴 전환을 아홉 번 실행했다. 각 회차는 형상 10000개와 매개변수 1000개의 설계, 100만 삼각형, 1 GiB급 필드 열 번 부분 조회, 복소 곡선 여덟 개를 열고 대기 프로젝트로 전환했다. 별도의 UX·복구·서비스 시험과 시간이 겹쳤다.

시험 보고서에 Studio 프로세스의 기존 커널 핸들과 별도로 GDI와 USER 객체 수를 추가했다. Windows가 계측 오류를 보고한 경우만 미정으로 기록한다. [Microsoft GetGuiResources](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguiresources), [Microsoft GetProcessHandleCount](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesshandlecount)

| 관측 항목 | 열린 상태 | 전환 후 150초 |
| --- | ---: | ---: |
| Studio 커널 핸들 | 372~394 | 342~344 |
| Studio GDI 객체 | 275~283 | 229~230 |
| Studio USER 객체 | 182~210 | 179~195 |

초기 세 회차에서 안정화 private commit의 합산 중앙값은 120.51 MiB, 마지막 세 회차는 129.83 MiB로 9.32 MiB 증가했다. 열림 중 최대는 345.65 MiB였다. 아홉 회차 모두 OpenGL 문맥을 해제했고, 안정화 GPU의 local과 nonlocal 사용량은 0바이트였다.

이전 30회 관찰은 8회 차에 커널 핸들이 307개에서 352개로 늘었다. 이번 8회 차는 344개였고 아홉 회까지 같은 범위를 유지했다. 두 실행의 GUI와 부하가 달라 이전 증가의 원인은 미확립이다. 이 짧은 진단은 기준 호스트의 30회 수용을 대체하지 않는다. [이전 150초 실행](198_대형프로젝트_검증재사용과_유휴회수_검증.md), [원시 표본](229_윈도우_유휴_사용자인터페이스객체_실행기록.json)
