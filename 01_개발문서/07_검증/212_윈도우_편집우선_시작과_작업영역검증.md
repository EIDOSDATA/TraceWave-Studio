# Windows 편집 우선 시작과 작업 영역 검증

2026-11-21 KST. 구간 표시를 넣은 진단 빌드의 10회 기록에서, 화면을 띄우기 전 해석·출력·네트워크·연구·결과·검증·측정 화면을 만드는 데 중앙값 995.81 ms가 걸렸다. 진단 빌드의 수치는 합격 비교 표본과 분리했다.

시작 시 2D 편집, 3D와 해석 상태에 필요한 공통 위젯 및 작업 표를 구성한다. 감춰진 나머지 작업 영역은 처음 들어갈 때 한 번 만든다. 첫 진입 뒤에는 페이지와 입력 상태를 재사용한다. 대기 중인 출력 영수증이 있거나 복구 기록을 읽지 못하면, 프로젝트를 열 때 출력 작업 공간을 만들어 기존 전환 잠금을 복원한다. 늦게 만든 위젯도 시스템 대비 색 변경을 받는다.

같은 Windows 부팅, 서비스 소스·Python 실행기, 2560 x 1600 화면과 150% 배율에서 대조판 10회, 개선판 10회씩 두 묶음, 대조판 10회 순서로 실행했다. 묶음별 준비 실행 1회는 집계에서 제외했다.

| 새 프로젝트 편집 준비 | 2.372 / 2.831 / 3.164초 | 1.308 / 1.545 / 1.682초 | 2초 |

두 warm 목표를 이 PC의 교차 실행에서 충족했다. 별도 최초 대조판 20회도 원시 기록에 보존했다. 실제 새 프로세스 실행 이후의 첫 2D 그리기와 새 프로젝트 명령의 활성화를 기록했다. 첫 진입 때 만드는 추가 화면의 전환 시간은 별도로 계측하지 않았다. cold 시작은 Windows 재부팅 후 첫 실행을 서로 다른 부팅에서 5회 수집해야 한다. [실행 도구](../../Code/tools/measure_windows_startup.ps1), [원시 실행 기록](213_윈도우_편집우선_시작과_작업영역_실행기록.json)

관련 Windows 회귀 15개와 Release CTest 13개가 모두 통과했다. 빈 화면에서 초기 페이지 3개로 시작하고 처음 해석 결과로 이동할 때 논리 페이지 17개가 준비됐다. 기존 캔버스와 출력 페이지를 반복 이동에서 재사용했으며 편집·저장, 실제 필드와 복소 원문의 재열기, 고정 도면 출력, CAM 가져오기와 재시작을 검증했다.
