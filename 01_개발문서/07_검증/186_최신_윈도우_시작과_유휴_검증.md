# Windows Release 시작과 빈 작업 영역 유휴 검증

2026-11-21 KST. Windows 11에서 새로 링크한 Release 실행 파일과 동일한 서비스 원본을 사용했다. 별도의 대형 Studio 유휴 검증을 실행하던 중 빈 작업 영역에서 warm 준비 1회와 계측 20회를 수집했다. 같은 실행 파일을 새 빈 작업 영역에서 다시 실행하고 조작과 UI Automation 호출 전에 30초 유휴 CPU와 프로세스 메모리를 측정했다.

| 지표 | 중앙값 | p95 | 최대 | warm 목표 |
| --- | ---: | ---: | ---: | ---: |
| 첫 2D 화면 | 2.002초 | 4.142초 | 6.630초 | 1.5초 이하 |
| 새 프로젝트 편집 준비 | 2.204초 | 4.142초 | 6.630초 | 2초 이하 |

warm 20회에서 두 이정표는 모두 관측됐고 두 p95는 각각 목표를 초과했다. 대형 창과 진단이 동시에 동작한 조건이다. 부하를 줄인 앞선 warm 20회의 2.135초와 2.333초는 별도 기록에 유지한다. [이전 부하 완화 계측](168_윈도우_시작_부하완화_재검증.md)

유휴 30.010초의 CPU는 단일 논리 프로세서 대비 0.26%였다. GUI 최대 private commit은 38.51 MiB, 하위 프로세스 포함 관찰 최대는 101.71 MiB였다. 30초 유휴 목표와 150/300 MiB 기준 이내였다. 현재 Windows의 재부팅 이후 최초 실행 표본은 이 실행에 포함되지 않았다. [원시 실행 기록](187_최신_윈도우_시작과_유휴_실행기록.json)
