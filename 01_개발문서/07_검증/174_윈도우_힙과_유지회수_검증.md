# Windows 힙과 30초 유지 회수 검증

2026-11-21 KST. 10000개 형상, 매개변수 1000개, 100만 삼각형, 1 GiB급 필드 단면 10회와 복소 곡선 8개를 같은 Studio에서 열고 닫았다. 30초 동안 OpenGL 문맥을 유지한 뒤 다음 전환을 시작했다. 30회 동안 프로세스 소유권을 대조했다. 기존 30회 실행과 같은 대형 좌표 읽기 코드를 사용하고, 비교 실행에서 GUI 실행 파일의 Windows 힙 설정을 바꿨다. [기존 유지 회수 기록](166_대형_좌표읽기보강_유지회수_검증.md)

| --- | ---: | ---: | ---: | ---: |
| 기존 Windows 힙 | 221.77 MiB | 317.11 MiB | 95.34 MiB | 420.88 MiB |
| Windows SegmentHeap | 214.83 MiB | 251.27 MiB | 36.44 MiB | 384.20 MiB |

Windows SegmentHeap에서 안정화 합계의 증가 폭은 58.90 MiB 줄었다. 32 MiB 목표를 4.44 MiB 초과했다. GUI의 안정화 핸들은 처음 324개에서 마지막 453개였고, 범위는 320~457개다. 다른 프로세스의 핸들은 유지되거나 10개 감소했다. 30회 모두 OpenGL 문맥이 유지됐다. 안정화 GPU local 최대는 152.14 MiB, nonlocal 최대는 0바이트였다. 핸들 및 메모리의 증가 원인은 추가 검수 범위다.

wxWidgets 공용 컨트롤, 관리자 권한 요청 정책과 PerMonitorV2 설정을 그대로 포함하는 Studio Windows 매니페스트에 SegmentHeap을 적용했다. Release 바이너리에서 리소스를 꺼내 비교했고, 고정 원문을 읽는 실제 전체 Studio에서 결과와 3D의 한 차례 전환 및 원본·축소 표시를 재확인했다. CTest 13개가 통과했다. 150초 유휴를 포함한 같은 구성의 반복 검증은 별도로 기록한다.
