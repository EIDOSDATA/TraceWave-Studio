# Windows F0 시작 시간과 유휴 계측

2026-11-20 KST. [F0 성능 기준](../04_화면설계/02_화면_선정과_성능_설계.md)에 따라 Release Studio를 별도 빈 작업 영역에서 실행했다. CAD, 출력, 카탈로그와 WSL 해석 worker를 연결하지 않은 경량 프로젝트 서비스 구성이다.

## 시작 이정표

- 시작 기준은 Windows 런처가 프로세스 시작을 호출하기 직전에 읽은 QPC 카운터다. 같은 카운터로 비어 있는 2D 캔버스의 첫 버퍼 그리기 완료와 서비스 연결 후 새 프로젝트 명령 활성화 시점을 기록했다. 편집 준비는 두 조건이 모두 갖춰진 시점이다.
- 계측 창은 실제 표시 경로를 사용한다. 계측만 마친 뒤 일반 창 종료 경로를 사용하고, 실패 또는 불완전한 구간을 원시 기록에 남긴다. 첫 화면 값은 애플리케이션 캔버스 그리기 완료 시점이다. 모니터의 실제 주사나 조작 중 프레임 간격은 별도 계측 범위다.
- Warm은 같은 빈 작업 영역에서 준비 실행 1회와 연속 계측 실행 20회로 구성했다. 준비 실행과 20개 표본을 함께 보존했고 계산에는 20개 표본을 모두 포함했다. p95는 nearest-rank 방식이다.

| Warm 항목 | 중앙값 | p95 | 최대 | p95 목표 | 이번 PC의 표본 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| 첫 화면 | 1.381 s | 1.424 s | 1.551 s | 1.500 s | 목표 이내 |
| 새 프로젝트 준비 | 3.803 s | 4.011 s | 4.103 s | 2.000 s | 목표 초과 |

PERF-001과 PERF-002의 cold 검증에는 다섯 차례 재부팅 후 첫 실행이 필요하다. 이번 검증에서는 재부팅을 수행하지 않았다. Warm 수치와 cold 합산 도구의 검증을 독립적으로 기록했다.

## 유휴 재측정

일반 실행 경로로 다시 연 동일 바이너리에서 화면 자동화 조회 없이 같은 빈 창의 30초 구간 두 개를 수집했다. GUI의 최대 표본 private commit은 39.66 MiB, 경량 서비스와 하위 프로세스 포함 최대값은 76.78 MiB였다. 논리 코어 하나 기준 CPU는 0.416%와 0.312%였다. 두 구간은 이 PC에서 PERF-003과 PERF-008 예산 이내였으며 [이전 구간의 변동](45_유휴확인주기_비교_검증.md)도 보존한다.

Windows GUI 회귀 10개와 CTest 13개를 통과했다. 실제 시작 이정표와 서비스 실패, 기존 출력 덮어쓰기 거절, 합성 cold 합산과 동일 부팅 거절을 확인했다.

## 재현

Code 경로에서 PowerShell 7로 수집한다. 출력 파일과 전용 빈 작업 영역을 새 이름으로 만든다.

```powershell
./tools/measure_windows_startup.ps1 -Gui build/windows-release/bin/tracewave_gui.exe -Python .venv/Scripts/python.exe -Source src -Output .local/startup-warm.json
```

Cold는 동일한 빌드, 서비스, 화면 크기와 DPI를 유지한 채 재부팅 직후 Studio를 처음 실행할 때 위 명령에 `-Mode Cold`를 추가하고 새 출력 경로를 지정한다. 계측 전에는 Studio 미리 실행, GUI 자동화 조회 및 실행 파일의 내용 읽기를 생략한다. 다섯 건 이상 수집한 뒤 PowerShell 세션에서 합산한다.

```powershell
$records = (Get-ChildItem -Path .local -Filter 'startup-cold-*.json').FullName
./tools/measure_windows_startup.ps1 -ColdReports $records -Output .local/startup-cold-summary.json
```

[원시 표본과 실행 기록](50_윈도우_에프영_시작시간_실행기록.json)에 바이너리 및 서비스 출처 해시, 창 DPI와 크기, 타임스탬프, 별도 유휴 표본 및 시험 결과를 보존한다.
