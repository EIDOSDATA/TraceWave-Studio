# Windows 구버전 설계의 이름 표시 성능 검증

2026-11-21 KST. 완료 계획 12번 F1의 기존 저장 범위에서 구버전 설계의 목록과 캔버스 조회를 개선했다. 이름이 미정인 객체마다 전체 이름 목록을 다시 계산하던 비용을 줄였다. 같은 개정의 목록을 만들 때 접두어별 첫 번호를 계산하고, 이후에는 UUID 순서로 번호를 배정한다. 탐색 트리와 2D, 정밀 편집, 연결 도체 선택 및 교환 화면의 표시 조회에서 같은 배정 규칙을 사용한다.

## 서비스 조회 비교

동일 CPython에서 형상 250개와 이름 미정 형상 247개가 있는 프로젝트를 사용했다. 각 경로에서 1회 준비 실행 뒤 6회씩 직접 조회했고 중앙값을 비교했다. 선택 속성 조회는 포트와 양극·기준 도체 목록을 함께 만드는 경로를 사용했다.

| 조회 | 개선 전 중앙값 (ms) | 개선 후 중앙값 (ms) | 출력 (bytes) |
| --- | ---: | ---: | ---: |
| 2D 캔버스 | 2764.736 | 5.823 | 69380 |
| 탐색 트리와 선택 속성 | 8009.292 | 1.216 | 82034 |
| 정밀 편집 | 2732.742 | 1.623 | 45774 |

세 응답의 UTF-8 JSON 바이트, 이름, 임시 이름 상태와 개정이 모두 일치했다. 조회 후 프로젝트 원본 바이트도 일치했다. 위 시간은 표시 자료 조립과 크기 검사를 포함한 서비스 함수의 진단값이다. F1의 10,000개 형상·1,000개 매개변수·100,000개 검색 레코드와 입력 반영 시간 및 실제 60 fps 수용은 별도다. [원시 실행 기록](101_윈도우_구버전_객체이름_실행기록.json)

## Windows 저장과 재열기

Windows Release GUI에서 명시 이름이 긴 설계와 구버전 혼합 설계를 각각 편집, 저장, 스냅샷 생성하고 두 번째 서비스 세션에서 다시 열었다. 원래 이름과 이름 미정 형상, 보드, 재료와 적층 및 포트가 저장 전과 일치했다. 재료의 미정 Df와 입력 출처를 함께 대조했다. 두 실제 GUI와 전송·이름 경로 2개를 통과했다. 관련 객체 이름, 편집, DRC, 정밀 편집과 교환 회귀에서는 105개 중 103개를 통과했고 환경 조건으로 2개가 제외됐다.

기본 회귀에서 제외된 실제 PCB 출력 worker 시험은 고정 교환 Python을 연결해 별도로 통과했다. KiCad 수신 시험은 지정 환경이 필요하다. CTest 13개가 통과했다.
