# MCP와 KiCad 기판 교환 검증

2026-11-20 KST. 완료 계획 12번에서 공식 MCP Python SDK와 실제 KiCad로 [기판 교환 계약](../05_기능설계/05_출력교환/05_기판형상과_제조파일_교환.md)의 유한 보드 출력을 검증했다. 보드는 60 x 40 mm 외곽, 명시된 도체층 2개, 트랙 2개와 비도금 완성 홀 1 mm를 가진 합성 검증 시료다.

## 실제 흐름

1. 고정 스냅샷과 기존 저장 개정을 준비하고 프로젝트 서비스 연결을 닫았다. 공식 클라이언트가 격리 출력 환경을 지정한 별도 stdio 프로세스를 열었다.
2. MCP 2025-11-25 초기화, 도구 검색과 선택적 `_meta`를 전달했다. `export.get`의 읽기 표시와 `export.build`의 변경 표시, `capabilities.get`의 런타임 상태를 확인했다. 작업 진행은 기존 영속 `job.status`로 읽었다. [MCP 도구 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [공식 Python SDK 1.26.0](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v1.26.0)
3. `export.preview`로 같은 스냅샷의 공구 직경 미정을 확인했다. 검토 해시로 `export.build`를 요청하고 같은 요청 키 재전송이 기존 작업을 반환하는지 확인했다. 파일 봉인 후 `export.verify`를 별개 작업으로 완료했다.
4. 출력 환경 없이 MCP를 재실행해 과거 결과를 그대로 읽었다. 다른 프로젝트 ID는 거절했다. 서비스로 다시 연 원본과 저장 개정, 원본 사본 및 공구 직경 미정과 그 출처를 대조했다.
5. 작업의 봉인 파일을 읽어 실제 KiCad 10.0.8의 `pcbnew.LoadBoard`로 수신했다. 도체층과 트랙 2개 및 1 mm x 1 mm 드릴 치수를 대조하고 수신 사본에 쓴 파일의 바이트가 유지된 것을 확인했다.

MCP 3개와 기판 교환 회귀 35개, 별도 Windows Studio 회귀 1개가 모두 통과했다.

Windows Studio에서는 별도 기존 시험으로 실제 CAM 발행, 원문 청크 수신, 명시 적용, undo 및 저장/재열기를 검증했다. 이 시험과 공식 MCP에서 발행한 KiCad 보드의 수신 시험은 [실행 기록](40_엠시피와_키캐드_교환_실행기록.json)에 분리했다.

## 재현 방법

Code에서 MCP 호스트의 로컬 stdio 실행 파일로 서비스 Python을 지정하고 다음 인수를 준다. 같은 작업 영역을 Studio 또는 다른 서비스가 열고 있다면 기존 세션을 정상적으로 닫은 뒤 연결한다.

```powershell
./.venv/Scripts/python.exe -X utf8 tools/mcp_stdio.py --workspace "C:/작업/검증" --exchange-python "C:/환경/교환/Scripts/python.exe"
```

출력 프로그램과 설치 환경은 프로세스를 시작할 때 정해진다. 도구 요청에서 이 경로를 지정하지 않는다. 출력 환경을 지정하지 않아도 이미 봉인된 결과를 조회할 수 있다. `_meta`는 MCP 요청 메타데이터의 수신만 지원하며 프로그램 데이터와 영수증 계산에는 포함되지 않는다.

[공식 클라이언트 시험](../../Code/tests/test_mcp_pcb_exchange_process.py)은 SDK 1.26.0을 별도 검증 환경에 설치한 뒤 `PYTHONPATH=src;tests`, `RFAD_EXCHANGE_PYTHON`과 `RFAD_TEST_KICAD`를 설정해 실행한다. `RFAD_TEST_KICAD`는 KiCad의 `bin` 폴더다. 서비스 Python을 따로 쓸 때는 `RFAD_MCP_SERVER_PYTHON`도 설정한다.

보드 수신, 제조 DRC 합격, 제작 물성 및 RF/측정 정확도는 각각 별도 판정이다. 이번 공식 클라이언트 시험 범위는 동결된 KiCad 보드 발행과 조회다. 외부 host별 수용, MCP를 통한 수입 대응 적용 및 다른 EDA 형식의 의미 매핑은 별도로 검증한다.
