# Windows 도형 드래그 부분 갱신과 자료 표 지연

2026-11-22 KST. Windows Release의 db5c980과 후속 빌드를 개발 PC에서 대조했다. 내장 화면은 2560 x 1600, 144 DPI, 120 Hz다. F1은 실제 화면에서 연속 조작 30초 이상 및 유효 갱신 간격 1000개 이상을 요구한다. 60 fps의 p95 한도는 16.667 ms다. 아래 세션은 각각 35초다. [이전 전후 계측](288_대형_이차원과_표_스크롤_성능_대조.md)

## 2D 도형 드래그

일반 선분이나 원호를 움직이는 동안 이전 위치와 새 위치의 도형 및 강조선 영역을 다시 그린다. 갱신 영역과 겹치지 않는 단순 경로는 그리기를 건너뛰며, 시작·취소·종료와 범위 밖의 도형은 기존 전체 갱신으로 처리한다. 같은 위치에서 마지막 부분 갱신과 이어서 강제한 전체 갱신의 실제 Windows 창 픽셀이 일치했다.

| 빌드 | 유효 갱신 간격 수 | 중앙값 ms | p95 ms | p99 ms | 최대 ms | 입력-표시 p95 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| db5c980 | 1938 | 16.769 | 25.195 | 31.919 | 32.307 | 34.012 |
| 부분 갱신 | 3736 | 8.597 | 16.911 | 22.951 | 26.905 | 12.146 |
| 부분 갱신 재계측 | 3762 | 8.514 | 16.621 | 17.541 | 27.264 | 11.965 |

같은 4개 층과 형상 1만 개에 같은 드래그 경로를 적용했다. 독립 타이머의 입력 제안은 4203, 4199, 4203회였고 실제 처리는 1954, 4198, 4202회였다. 두 후속 p95는 16.667 ms 한도의 양쪽에 걸쳤고, 첫 회와 재계측에서 모두 실제 픽셀이 일치했다. 개발 PC에서 드래그 개선이 재현됐으며 수용 판정은 열린 상태다. [드래그 계측과 픽셀 비교](../../Code/tools/canvas_display_probe.cpp)

## 카탈로그 표 스크롤

직전 207.633 ms 정지를 원시 QPC에서 재검토했다. 이전 표식이 화면에 나온 뒤 다음 스크롤 입력이 처리될 때까지 178.985 ms였다. 뒤이어 입력 3개가 처리됐고 세 번째 입력의 표식이 다음 화면에 나타났다. 당시에는 화면 스레드의 타이머만 썼으므로 제안과 처리 사이의 지연을 분리할 수 없었다.

페이지가 도착하면 실제 보이는 행만 다시 그린다. 표준 wxTimer와 별도로 화면 스레드 밖에서 입력 제안을 기록할 수 있게 했다. 대기 중 이벤트는 최대 1개이며 세션의 일반 동작에는 해당 진단이 켜지지 않는다.

| 빌드와 계측 | 유효 갱신 간격 수 | p95 ms | p99 ms | 최대 ms | 처리 입력 중 첫 행 미수신 |
| --- | ---: | ---: | ---: | ---: | ---: |
| db5c980, 표준 타이머 | 2061 | 25.949 | 32.406 | 42.658 | 47/2224 |
| 화면 행 갱신, 표준 타이머 | 2043 | 25.830 | 31.583 | 47.537 | 40/2222 |
| 화면 행 갱신 재계측, 표준 타이머 | 2052 | 25.877 | 33.216 | 41.552 | 48/2203 |
| 화면 행 갱신, 독립 타이머 진단 | 3086 | 23.445 | 25.874 | 31.104 | 107/3401 |

독립 타이머의 제안 3402회 중 3401회가 처리됐다. 제안 간격 최대 11.354 ms, 화면 스레드 입력 간격 최대 16.169 ms, 입력-표시 p95 12.109 ms였다. 독립 타이머 진단의 입력 주기가 달라 표준 타이머 전후 비교와 별도로 기록했다. 207.633 ms 정지는 재현되지 않았다. 표준 타이머의 표시 p95는 두 후속 계측 모두 16.667 ms를 넘었고, 이번 전후 비교에서 일관된 개선도 확인되지 않았다. 페이지 수신 시 셀 문자열을 미리 만든 시안은 표준 타이머 p95가 27.871 ms로 올라 제품에서 제외했다. ## 실행 범위

장면 SHA256은 `0650160a5bcacb5dea470c12c8257718803ca65852a84ebff617daed9889ebe2`다. `tracewave_canvas_display_probe.exe report.json --scene-drag scene.json`으로 조작하고 `summarize_windows_canvas_display.py`로 유효 표시 간격을 읽는다. 표는 `test_f1_view.py`의 10만 행, 검색 후 5만 행 카탈로그와 형상 1만 개·매개변수 1천 개 설계를 쓰며 `--catalog-table-smoke-test` 및 `RFAD_TEST_CATALOG_SCROLL_DISPLAY=1`로 계측한다. 별도 제안 진단은 `RFAD_TEST_CATALOG_WAITABLE_TIMER=1`로 켠다. 시험 전후 같은 저장 개정과 입력 자료 수를 확인했다. 카탈로그 SHA256은 `cdca6146f8d35e6869a18effab3ca68205b291dd02cc8c93374090315685b6a8`다. 원시 QPC와 결과는 작업 폴더의 `f1-drag-rf` 및 `stage12-r1-followup/drag-rf-table-*`에 보존했다.

Windows CTest 13개와 실제 GUI 원호/IFA 편집·3D 선택, 카탈로그 검색·오래된 응답 폐기·카탈로그 없이 수동 편집의 5개 시험이 통과했다.

이 실행의 수치는 개발 PC의 성능 기록으로 보존한다. 현행 R1에서 진행할 Windows 사용성 및 별도 환경 수신 항목은 [작업표](../09_개발계획/04_현행버전_남은작업.md)에 있다.
