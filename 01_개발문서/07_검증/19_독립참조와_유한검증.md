# 독립 RF 참조와 유한 검증 기록

기록일: 2026-11-17 KST. 완료 계획 8번의 작업 기록이다. 기준 커밋은 `a23671f9e07c19c3284058facf841fa851519424`이며, 이 문서의 신규 시험은 해당 커밋 이후 작업 트리에 대한 것이다. 승인 기준선 RFAD-D0-3.4, 과거 검증 기록과 참고자료 원문을 변경하지 않는다.

현재 상태: 이번 유한 범위의 실제 WSL 계산과 재후처리/재열기, Windows 화면과 원문 보존 대조를 완료했다. 준비 실패, 순수 계약 시험과 실제 FDTD의 범위를 구분하며 8번 전체 RF 수용 완료로 표시하지 않는다. [기계 판독 실행 기록](20_독립참조와_유한검증_실행기록.json)에 실행별 범위와 해시를 보존한다.

## 1. 실행 전 범위와 예산

고정 PEC 다이폴, 대칭 평면 도체, 유한 급전 손실의 세 군을 각각 세 수준으로 정의했다. 평면 도체의 native 여기/경계와 유한 급전의 단면/단자 계약은 미확정이므로 여섯 사례는 실행 전에 차단한다. 차단된 예약을 다른 사례나 추가 격자로 전용하지 않는다.

다이폴은 진공/PEC, 전체 길이 60 mm, 반경 1 mm, 이상 급전 간극 1 mm와 2.4 GHz의 합성 사례다. 내부 격자는 3/2.5/2 mm, PML 외부/내부는 각각 +/-90/+/-74 mm, PML은 편측 8개 2 mm 셀, NF2FF는 +/-60 mm로 고정한다. 실제 사용자 PCB의 치수나 제작 조건으로 채택하지 않는다.

캠페인 상한은 native solve 9회, worker 27회, 분석 시간 합계 4500 s, worker와 감독 예약 시간 8280 s, 중단을 포함한 벽시계 10800 s다. 이 숫자는 예상 완료 시간이 아니다. 논리적 디스크 예약 8 GiB, 단일 파일 64 MiB, 사례 출력 128 MiB, 메모리 추정 1 GiB를 적용한다. native 단계는 host/guest 입력 두 사본과 출력/봉인 세 사본의 각 128 MiB 및 소스/명세 32 MiB를 합친 672 MiB, host 계획은 8 MiB를 예약한다. 실패/중단/재개로 예약을 환급하거나 초기화하지 않는다. 같은 workspace의 native 슬롯 한 개를 재사용하며 OS의 물리 메모리 강제 한도로 표현하지 않는다.

모든 수준의 실제 준비가 성공한 뒤 해당 군의 첫 FDTD를 허용한다. 원본 snapshot, runtime 소스, 판정 구현 해시, 초기 기준과 물리 조건을 미리 봉인한다. 동일 단계 재접수와 자동 재시도는 거절한다.

## 2. 판정 범위

이상적인 가는 반파장 도선의 정규화 전력 패턴과 지향성 1.6409를 독립 식으로 계산한다. 기존 초도 기준인 phi=0 패턴 최대 절대 오차 0.15, 지향성 상대 오차 0.10, PEC 효율 절대 오차 0.15를 유지한다. 유한 반경의 실제 계산 형상과 이상적인 무한히 가는 반파장 모델의 차이를 명시한다. 전체 phi 오차와 인접 격자 변화는 관찰값이며 새 합격 한계를 결과를 본 뒤 만들지 않는다.

평면 도체식은 exp(+j*omega*t), 균질/등방/선형 좋은 도체, 변위 전류 무시, 양면 대칭 여기와 총 peak 표면 전류를 가정한다. 이 산술을 native 모델의 여기/경계 검증이나 GHz PTH 정확도 합격으로 표시하지 않는다.

RO4350B 국부 방사 도체 손실 변화 2.788446%는 초기 2% 기준 미확립으로 유지한다. 총 전력 수지의 초기 3%와 개별 손실 기준을 혼용하지 않는다. GHz PTH의 독립 물리 정확도, 실제 제작/납품 물성, 급전 실장과 측정 조건은 미확립/미정이다.

## 3. 최초 실행 접수와 수정

첫 준비 도구 실행은 `solver.plan`에 이미 봉인된 계획용 compact capture를 요청하여 접수 단계에서 `E_UNSUPPORTED`로 종료됐다. 캠페인 기록은 만들어졌으나 solver 작업과 native worker 접수는 각각 0회였다. `.local/stage8-campaign1-prepare.json`과 같은 이름의 로그를 보존한다.

계획 생성은 기존 일반 캡처를, 준비와 해석은 기존 compact capture를 사용하도록 수정했다. 아직 접수되지 않은 native 실행을 성공으로 집계하거나 실패 보고서를 덮어쓰지 않는다. 판정 화면의 미평가 설명도 계획 미선택 문구와 실제 보존 판정의 미평가 문구를 구분했다.

첫 추가 host 테스트 명령에서 존재하지 않는 클래스 이름을 지정한 수집 오류도 별도 로그에 보존한다. 제품 오류나 실행된 테스트 통과 수에 합산하지 않는다.

## 5. 서비스와 GUI 검증 시점

독립 산술/계약/worker/fake 전송 19개는 32.834 s, 별도 신규 host 8개는 30.939 s, 기존 공통 결과 호환 26개는 10.836 s, 캠페인 통합 6개는 47.102 s에 통과했다. 이 집계들은 서로 겹치며 합쳐 고유 시험 개수로 표시하지 않는다. fake 전송은 RF 정확도 시험이 아니다.

전체 서비스 회귀는 1163개를 수집하여 1065개 통과, 98개 환경 조건 제외, 실패/오류 0개로 1121.120 s에 끝났다. 이 수집 시점은 신규 GUI process 시험과 아래 읽기 상태/표시 선택의 후속 보완 전이다. 이후 보완은 별도 집중 회귀로 확인하며 전체 수집을 다시 수행했다고 기록하지 않는다.

전체 서비스 수집 후 읽기 상태를 보강했다. guest 종료가 미확인인 취소는 목록과 본문 모두 `cancel_requested`를 유지한다. 완료한 단계는 `planned/prepared/solved/postprocessed`로 구분하고 원래 phase 작업의 completed 기록은 그대로 둔다. 해당 6개 집중 회귀는 77.347 s, 취소 단독 1개는 7.112 s, 목록/본문 취소 및 GUI fixture 2개는 8.592 s에 통과했다.

첫 GUI 통합 빌드는 새 프레임 연결 파일명이 기존 `studio_validation.cpp`와 겹쳐 `ValidateInput` 링크 오류가 발생했다. 기존 입력검사 파일을 복원하고 새 연결을 `studio_rf_validation.cpp`로 분리했다. 이 실패 빌드를 제품 GUI 검증 성공으로 표시하지 않는다. 같은 프로젝트/epoch 재연결 때 이전 in-flight 조회가 남는 C++ 경계도 독립 검토에서 찾아 수정했다. 단순 busy 상태와 실제 연결 끊김을 구분한다.

최초 Windows 검증 기록 자동시험은 중간 빌드 `2714e815...`에서 9개 내부 확인을 포함한 1개 시험이 11.300 s에 통과했다. 이후 원본 목록/표시 경계와 파일 게시를 보완한 빌드의 결과는 아래에 별도로 기록한다. 과거 단계의 시험 결과를 이번 변경 전체에 대한 통과 증거로 옮기지 않는다.

## 6. 후속 GUI에서 발견한 파일 게시 경계

검증 기록/결과/문헌 후보의 연속 GUI 회귀는 첫 40.757 s 실행에서 2개 통과와 결과 내보내기 파일 존재 검사 1개 실패였다. C++ 결과 화면의 12개 내부 확인과 저장/재열기 원문 대조는 통과했지만 이를 전체 시험 통과로 집계하지 않는다. 같은 바이너리의 결과 단독 시험은 12.587 s에 통과했다. 이어 같은 세 시험 순서로 39.013 s에 재현했을 때 CSV와 조건 sidecar의 실제 파일명 뒤에 불필요한 Unicode 문자가 붙은 것을 실패 진단에 확보했다. 첫 실패와 진단/재현 로그는 모두 보존한다.

기존 Windows 파일 게시의 `FILE_RENAME_INFO` 가변 버퍼를 검토했다. [Microsoft 구조체 계약](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)은 파일명 길이를 바이트로 지정하고 `FileName`을 NUL 종료 문자열로 설명한다. 기존 버퍼는 이름 바이트만 예약했으므로 종료 문자를 명시적으로 보장했다. 열린 handle의 실제 게시 경로도 요청 이름과 대조하고 불일치하면 commit 전에 자신이 만든 파일을 회수한다. RF 결과 수치, 선택 source/pin 또는 봉인 원문의 변경으로 문제를 우회하지 않았다.

수정 빌드 `639fd7ee2694fae2ec792b88c8585ade44d9998d82207934f8f9405aa328802e`에서 검증 기록(내부 10개 확인), 결과(내부 12개 확인), 문헌 후보, 기존 network의 GUI 시험 4개가 65.436 s에 통과했다. 실제 CSV와 sidecar의 존재/조건 및 원문 저장/재열기까지 포함한다. 신규 파일 게시 시험을 포함한 CTest 11개는 2.73 s에 통과했다. 한글과 가변 길이 16쌍의 정확한 전체 파일명/CSV 바이트/sidecar/미정값과 기존 파일/sidecar 충돌 및 작업 영역 안 출력 거절을 확인한다.

신규 CTest의 첫 두 실행은 제품 저장 호출 전에 시험 fixture의 경로에서 실패했다. 첫째는 임시 폴더 끝 구분자의 안전 비교, 둘째는 시험 하위 폴더 끝 공백의 Windows 정규화였다. 시험 경로를 바로잡고 실제 저장 함수와 회귀를 실행했다. 두 실패 로그도 보존하며 제품 저장 검증 통과 수에 포함하지 않는다.

## 7. 실제 Windows 수동 검토와 보존 대조

원래 계산 workspace를 보존하고 격리 복사본에서 `639fd7ee...`를 실행했다. 프로젝트 검증 목록, 명시한 과거 판정, 실행 차단 행과 비활성 결과 버튼, source/pin으로 연결한 해석 실행 목록의 같은 행 선택을 확인했다. 원본 목록은 6개 실제 계산/재후처리 결과이며 임의 최신 원본으로 대체하지 않는다. 2.4 GHz, 복소 S11, VSWR 2.876403, 실제 phi 0/180 deg 절단면과 OpenGL 3D 방사의 마우스 회전을 확인했다. 다이폴은 한 주파수의 합성 검증 모델이며 실물 PCB/사용자 안테나 성능을 나타내지 않는다.

한글 CSV 경로를 실제 파일 대화상자에서 지정해 내보내고 Ctrl+S, 종료, 같은 실행 파일로 재열기 후 같은 판정을 다시 읽었다. 미정 제작/측정 조건과 실행 전 차단은 그대로다. 별도 runtime 없는 서비스 대조는 0.453 s에 통과했다. 보고서 전체/프로젝트 원문/세 결과 pin, 원래 계산 workspace의 보호 파일 9개 hash가 같고 GUI CSV/sidecar의 실제 이름과 바이트/조건도 공개 내보내기 응답과 같다. 실제 창의 캡처 33~38은 [실행 화면](02_실행화면/README.md)에 있으며 기계 기록에 실행 파일 hash/시점을 연결한다.

마지막 계획 조회의 미차단 행은 source가 없다는 이유로 `결과 미기록`이라고 표시하던 문구를 `판정 선택 필요`로 보완했다. 같은 선택의 오른쪽 설명도 명시 보고서를 선택하도록 안내한다. 과거 판정과 DTO/서비스는 바꾸지 않았다. 표시 모델 회귀 1건은 0.15 s(CTest 전체 0.16 s)에 통과했다. 최종 실행 파일 `d7d64a58b7e88db3601342183d77290959e7ffb72c2dd08899a71e4b31eb83a2`로 저장된 프로젝트/판정과 계획을 다시 열어 후처리 완료와 판정 선택 안내가 함께 표시됨을 확인했다. 캡처 39와 마지막 원문 보존 대조 0.422 s를 따로 남긴다. 이 표시 문구 보완 후 전체 서비스/GUI 4건을 다시 실행했다고 집계하지 않는다.

## 8. 남은 수용 범위

다이폴의 사전 초도 비교와 이번 기능/표시 연결을 마감한다. 평면 도체/유한 급전 6사례, RO4350B 개별 손실, GHz PTH, 경계/종료조건의 독립 수렴, 사용자 원호/IFA 및 실제 제작/측정 수용은 미확립이다. 9번의 후보 선정/재검증은 이 상태를 승계하며 값이나 조건을 임의로 채우지 않는다. 전체 화면/DPI/프레임/메모리/복구 수용은 기존 12번에 남긴다. 참고자료, 승인 보관본과 과거 실행 기록은 수정하지 않았다.

문서 검사에서는 승인 보관본 27개 hash, 폴더 28개, 번호 파일 486개, 현재 문서 138개와 링크 7773개를 확인했으며 끊어진 링크는 0개였다. DrawIO/SVG/PNG 구조 10개도 확인했다. 이는 native DrawIO 왕복이나 전체 GUI 수용 시험을 수행했다는 뜻이 아니다. 요구 추적 14개 시험은 2.386 s에 통과했고 최종 생성물 대조도 통과했다. 수용 합격 상태를 새로 주장하지 않는다.
