# GUI 구분자와 문구 재검수

2026-11-24 KST. [승인 화면 84개 목록](../04_화면설계/13_전체화면목록.json)과 [이전 가독성 검수](424_전체화면_가독성_검수와_개선.md)를 기준으로 Windows 앱의 표시 문구를 검토했다.

## 표시 규칙

- 메뉴와 탭에서는 작업이나 항목의 관계를 드러낸다. 예를 들어 "실행 환경 및 진단", "종료 및 기록"으로 표시한다. 도움말에서 참조하는 이름도 해당 메뉴나 탭과 맞춘다.
- 축과 열 머리글에서 단위는 괄호에 넣는다. 페이지에서는 현재 범위와 전체 건수를 구분한다. 상태와 다음 동작이 붙어 있을 때는 문장을 나눈다.
- 단위식, 좌표와 경로의 원문, 사용자 이름, 문헌 인용과 증거 파일을 보존했다. 결과는 짧은 목록 이름과 전체 이름을 각각 받아 표시한다. 이전 서비스가 짧은 이름을 제공하지 않을 때는 기존 표시 형식으로 읽는다.
- 문헌 카드와 미리보기에서는 제목과 항목 목록을 다시 배치했다. 출처와 검토에 쓰는 원본 카드, 식별자와 해시는 그대로 읽는다.
- 과거 결과의 고정 식별자와 내보내기 메타데이터는 기존 개정 레이블을 사용한다. 창의 읽기 응답에는 프로젝트 이름 뒤에 개정 시각을 괄호로 표시한다.
- 승인 시안, 과거 캡처와 저장된 프로젝트를 보존했다. 진단 화면에서는 단계를 이름으로 구분하고 소요 밀리초를 함께 표시한다.

## 실제 Windows 화면

승인 화면 84개를 Windows 개발 빌드에서 열어 확인했다. 화면 색인 `Windows_문구_검수.html`은 검수 산출물 폴더 `TraceWave-UI-문구-검수`에 있다. 화면 상태 89개와 이미지 142장을 연결했다. 여러 항목이 같은 창에 있으면 한 캡처에 연결했다.

- 실제 2D 설계, 작은 창 배치, 3D CAD 형상과 단면, G001 문헌 후보, 급전 기준면과 과거 변경 이력을 확인했다.
- 보존 해석의 네트워크 차트, Smith 차트, 10 GHz 방사와 편파 수치, 전력과 손실, 42개 표본의 전계 단면을 확인했다. 시험 Touchstone은 실제 파일을 열어 조건과 표본을 검토했다.
- 해석 준비, 연구, 선택한 원본의 비교와 수렴 보고서, 도면, STEP, PCB 및 CAM, 보고서와 인계를 열었다. 결과가 없는 상태와 적용 응답 유실 뒤 재연결해 이미 적용된 개정을 확인하는 상태도 재현했다.
- 회귀시험에서 한글 서식 처리 오류로 가져오기와 네트워크 차트가 종료되는 문제를 재현했다. UTF-8을 명시적으로 변환하여 Windows에서 가져오기, 곡선 표시와 재열기를 다시 검증했다. 연구 화면은 실제 창 폭에 맞춰 안내를 다시 줄바꿈한다.

## 회귀시험

- Windows Release 빌드와 CTest 14개가 통과했다.
- Python 서비스 시험 106개 중 102개가 통과했고 4개는 환경 조건에 따라 건너뛰었다. 과거 결과의 고정 식별자와 기존 내보내기 메타데이터가 유지되는지 결과 서비스 시험 18개를 다시 실행해 확인했다.
- Windows GUI 회귀시험 14개가 통과했다. 설계 제약, 외부 STEP, PCB 카탈로그와 직접 입력, PDF 검수, 연구 취소와 재개, 목표와 문헌 후보, 원본의 가져오기와 변환, RLC 정합, 과거 결과 내보내기, 독립 RF 검증 기록을 점검했다.
- 두 주파수 ROI 10회와 E/J/rotH 원본 3종을 확인하는 자동시험은 해당 보존 원본이 필요하다. 이번 검수에서는 보존 Ex 기록의 단면을 직접 열었다. E/J/rotH가 포함된 보존 실행을 확보하면 자동시험을 재개한다.
