# Windows 해석 취소 뒤 실제 WSL 종료를 확인하는 대기 개선

2026-11-21 KST. 다음 heartbeat를 기다리는 동안 취소 신호를 바로 받을 수 있게 바꿨다. WSL의 종료 응답이 확인되면 추가 poll 간격을 기다리지 않고 출력을 보존하거나 종료 상태를 처리한다. 종료가 확인되기 전에는 다음 조회의 간격을 지키며, coordinator 접수와 실제 guest 종료를 별도로 기록한다.

같은 Windows GUI에서 동시 부하를 유지한 채 기존과 개선 감독 루프를 두 회씩 교차했다. 실제 openEMS 해석에 초당 약 1000행의 계측 로그를 추가했다. 네 실행에서 같은 작업의 실제 종료, 저장 개정과 과거 결과의 재열기를 확인했다.

| 지표 | 기존 개별 관찰 (ms) | 개선 개별 관찰 (ms) |
| --- | --- | --- |
| Studio 접수 | 120.80, 140.43 | 119.05, 131.91 |
| 실제 WSL guest 종료 확인 | 1444.52, 1775.91 | 1000.20, 1076.47 |

실제 종료 확인의 중앙값은 1610.22 ms에서 1038.33 ms로 줄었다. 이 교차의 규모는 각 두 건이다. 별도의 파일 검사 개선 때 확보한 취소 접수 p95 표본과 섞지 않았다. host 감독과 준비 검증 15개도 통과했다. [접수 교차 시험](214_윈도우_취소접수와_파일검사_검증.md), [실행 기록](217_윈도우_게스트종료_대기축소_실행기록.json)
