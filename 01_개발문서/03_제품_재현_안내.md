# TraceWave Studio를 다시 만드는 순서

이 문서는 수용된 R1 Windows 제품의 재현 절차다. 새 GUI 시제품은 [리팩토링 인계](09_개발계획/08_새채팅_개발인계.md)에서 시작한다.

Windows에서 서비스를 먼저 실행해 저장 형식과 통신을 확인한 뒤 편집기, 해석, 결과, 출력을 연결한다. 기존 파일을 읽을 구현을 작성할 때는 문서의 예시와 함께 저장소의 고정 입력 및 시험을 사용한다. 구현할 순서와 각 단계에서 얻어야 할 결과는 다음과 같다.

| --- | --- | --- |
| 1. 데이터 모델 | 프로젝트, 개정, 객체는 서로 다른 ID를 갖는다. 값에는 수치, 단위, 상태와 출처가 있다. 원래 입력과 계산용 SI 값을 구분한다. [데이터 형식](02_시스템명세/03_데이터_모델과_파일_형식.md) [표현식과 데이터](02_시스템명세/09_표현식과_설계데이터.md) | [옛 IFA 파일](../Code/fixtures/design/initial_ifa.json)의 0.2 문서와 미정 물성을 읽는다. 열기만 했을 때 원래 바이트가 유지되고, 편집한 새 개정에서만 현재 쓰기 형식 0.6을 쓴다. ## 첫 실행에서 확인할 두 가지

아래 명령은 저장소의 `Code` 폴더에서 Windows PowerShell로 실행한다. 첫 예제에는 Windows x64 CPython 3.12와 저장소 소스만 필요하다. 해석이나 특정 확장 기능의 시험에는 해당 의존성을 추가한다. [개발 환경](08_운영환경/01_파이썬_개발환경.md)

### 서비스 응답과 프로젝트 재시작

```powershell
$env:PYTHONPATH = 'src;tests'
Get-Content -Encoding utf8 fixtures/rpc/capabilities.get.ndjson |
    py -3.12 -X utf8 -m rfad serve |
    ConvertFrom-Json |
    ForEach-Object { $_.id; $_.result.contract_version; $_.result.profile }

py -3.12 -X utf8 -m unittest -v test_rpc test_project_process
```

작업 영역 없이 질의하면 차례로 `hello-1`, `rfad.api/2.0`, `rfad.bootstrap/0.1`을 받는다. 같은 서비스에 `--workspace`로 작업 폴더를 지정하면 프로젝트 프로필은 `rfad.projects/0.2`가 된다. 앱은 그 응답에서 이번 세션의 가능 작업과 변경 요청용 epoch를 얻는다. [요청 한 줄](../Code/fixtures/rpc/capabilities.get.ndjson) [서비스 진입점](../Code/src/rfad/__main__.py)

재시작 시험은 임시 작업 폴더에 '첫 설계'를 생성한 뒤 `metadata.rename`으로 '저장된 설계'로 바꾼다. 스냅샷과 저장 작업이 완료되면 프로세스를 종료하고 새 프로세스에서 같은 요청을 다시 보낸다. 응답이 이전 응답과 같고, 복구한 `revision_id`가 `saved_revision`과 같으며 스냅샷 파일 바이트도 일치해야 한다. 구현을 바꿔도 비교할 수 있는 예제다. [실제 프로세스 시험](../Code/tests/test_project_process.py)

### 다른 기능의 입출력 계약 찾기

[기계 판독 추적표](07_검증/01_구현감사/03_구현추적.json)의 `functions`에서 기능 ID를 찾으면 코드, 시험, 실행 근거가 연결된다. `public_api`는 승인 API 30개의 이름과 등록 여부를 담는다. `extension_methods`는 작업 영역 서비스가 추가로 광고한 메서드, `capability_profiles`는 그때의 프로필과 한도를 담는다. 이 표를 생성한 환경에는 CAD, 카탈로그와 해석 작업자가 연결되지 않았다. 설치한 프로그램에서 호출할 수 있는 메서드는 그 서비스의 첫 응답에서 확인한다.

예를 들어 외부 결과를 구현할 때는 [파일 교환 계약](05_기능설계/05_출력교환/03_복소결과_파일교환.md)에서 Touchstone의 행렬 순서와 파일 형식을 확인하고, [결과 조회 계약](05_기능설계/04_해석결과/07_다중결과와_방사표시.md)에서 `source`와 `pin`을 확인한다. 서로 다른 송수신 포트의 표본을 구별할 수 있는 입력으로 왕복 시험한다. 과거 결과를 내보내면 파일 원문과 개정 식별자가 원본과 일치해야 한다. [입출력 시험](../Code/tests/test_network_files.py) [원본 보존 시험](../Code/tests/test_result_sources.py)

### 기준 계산과 허용 오차

유전체 격자는 CAD, 해석기 설치, GUI 없이 행렬 계산과 전력 수지를 검사할 수 있는 첫 입력이다. Windows x64 CPython 3.12용 고정 수치 라이브러리를 빈 가상환경에 설치한다. PowerShell의 현재 폴더는 계속 `Code`다.

```powershell
py -3.12 -m venv .local/rf-check
$rfPython = (Resolve-Path .local/rf-check/Scripts/python.exe).Path
& $rfPython -m pip install --only-binary=:all: --require-hashes -r runtime_profiles/python-network-windows-x64.txt
& $rfPython -m pip check
$env:PYTHONPATH = 'src;tests'
$env:OPENBLAS_NUM_THREADS = '1'
& $rfPython -m rfad floquet fixtures/floquet_dielectric_grating.json
& $rfPython -m rfad waveguide-modes fixtures/waveguide_te_step.json
& $rfPython -m unittest -v test_floquet test_waveguide_modes test_pcb_floquet test_waveguide_section
```

입력은 주기 38 mm, 두께 4 mm, 입사각 17도, TE 편파다. 9, 10, 11 GHz의 회절 결과가 나와야 한다. 403의 고정 비교에서는 비균질 얇은 격자의 복소 계수 18개를 독립 전달 행렬과 절대 오차 `2e-9` 이내에서 대조한다. 동박과 손실이 있는 2차원 주기 셀은 별도 입력과 독립 유한요소 대조를 쓴다. 계산 성공 여부와 허용 오차 충족 여부를 각각 기록한다. [403 예제와 수치](07_검증/403_유전체_격자의_주기_플로케_경계_검증.md) [408 동박 PCB 입력과 한계](07_검증/408_동박_피시비의_이중주기_플로케_검증.md)

도파관 예제는 15 GHz에서 TE(1,0) 입사에 대한 같은 쪽 TE(2,0) 반사 계수를 확인한다. [도파관 입력과 수치 대조](07_검증/404_직사각_도파관_폭단차의_다중모드_검증.md)

같은 수치 환경으로 `& $rfPython -m unittest -v test_project_archive test_result_sources`를 실행하면 보존 묶음과 과거 결과의 재열기도 검사한다. 이 시험은 합성 Touchstone에서 정규 HDF5를 생성하므로 고정 h5py와 NumPy가 필요하다. [의존성 목록](../Code/runtime_profiles/python-network-windows-x64.txt)

## Windows 앱까지 조립하기

위 두 예제는 서비스와 수치 모델을 각각 점검한다. 네이티브 창까지 빌드하려면 Windows x64에서 CMake, Ninja, MinGW-w64 GCC와 tar를 PATH에 준비한다. 서비스 환경 설치 및 GUI 실행 시 필요한 CAD, 교환 도구, 카탈로그의 선택 방법은 [개발 실행 안내](../Code/README.md#실행)에서 이어간다. 버전과 해시의 기준은 [네이티브 도구 목록](../Code/runtime_profiles/native-windows-x64.json)이다.

```powershell
.\tools\setup_native.ps1 -Jobs 4
ctest --preset windows-release --output-on-failure
```

빌드 결과는 `Code/build/windows-release/bin/tracewave_gui.exe`다. CTest는 표시 모델과 상태 전이 등 14개 시험을 실행한다. 실제 입력, 작업자 실행, 앱 설치 및 제거는 별도 경로에서 확인한다. 원문 데이터나 과거 worker 산출물이 필요한 시험에는 해당 파일을 함께 인계한다. 실물 PCB와 교정된 측정 원문이 필요한 판정은 시뮬레이션으로 채우지 않는다.
