# 문서 관리와 변경 규칙

문서 ID는 TWS-DOC-001이다. 제품의 현재 동작을 바꿀 때는 담당 계약을 수정하고, 실행 당시의 결과와 승인 사본은 그 시점의 근거로 보존한다.

## 어디에 무엇을 쓰는가

| 내용 | 정식 위치와 변경 방법 |
| --- | --- |
| 요구와 승인 | [요구사항](01_요구사항/README.md)은 요구 ID와 수용 의미를 소유한다. RFAD-D0-3.4 승인 원문의 바이트, 해시, manifest는 [기준선 보관함](12_보관이력/01_승인기준선/01_삼점사/README.md)에 고정한다. 현행 편집본은 기존 번호와 연결한다. |
| 데이터와 동작 | [시스템 명세](02_시스템명세/README.md), [아키텍처](03_아키텍처/README.md), [기능 설계](05_기능설계/README.md)에 지원 입력, 파일 형식, 단위, 명령, 실패와 호환 조건을 둔다. 화면에는 사용자 행동과 전환을 쓴다. [화면 설계](04_화면설계/README.md) |
| 출처와 연구 | 외부 원문, 기존 추출본과 수집 기록은 [참고자료](../00_참고자료/README.md)에 보관한다. 내부 이름과 상대 경로, 내용, 출처 해시 및 사용자가 복구한 자료를 보존한다. 새 분석은 [분석 연구](06_분석연구/README.md)에 쓴다. |
| 실행과 판정 | [검증](07_검증/README.md)에 개정, 환경, 입력, 실행 결과, 판정 및 재개 조건을 남긴다. 이후 실행은 새 기록에 연결한다. 사용자 결정으로 특정 사례를 허용하면 [R1 작업표](09_개발계획/04_현행버전_남은작업.md)에 원래 기준, 관찰값, 허용 범위를 기록한다. |
| 운영과 배포 | [운영 환경](08_운영환경/README.md)에 명령을 실행할 디렉터리와 의존성을 적는다. 배포된 바이너리, 로컬 후보와 개발 빌드는 소스 개정과 파일 해시로 식별한다. 남은 작업의 기준은 [개발 계획](09_개발계획/README.md)이다. |
| 코드와 증거 파일 | [Code](../Code/README.md)에 소스, 빌드 정의, 시험 입력과 도구를 둔다. 실행 환경을 구성할 때 읽는 고정 의존성 목록과 당시 실행을 보관한 보고서는 [runtime_profiles](../Code/runtime_profiles)에 있다. 과거 보고서의 경로와 해시는 당시 개정에 속한다. |

README는 필요한 첫 문서로 연결한다. 숫자 한도나 API를 변경할 때는 담당 계약 한 곳에서 정의하고, 다른 안내에서는 해당 절에 연결한다. 처음 제안한 내용을 현재 구현으로 오해할 수 있으면 제안 시점과 현행 계약을 함께 적는다. 쓰이지 않는 중복 설명은 제거한다. 동일 바이트의 원문과 추출물은 출처, 라이선스 및 보존 근거가 있을 수 있다.

## 재현 가능한 기능 계약

- 사용자의 시작 상태와 입력, 각 값의 출처와 단위, 누락값, 원본을 소유하는 모듈을 기록한다.
- 화면에서 확정되는 시점, 명령과 역명령, 영속화되는 버전 및 과거 버전의 읽기 규칙을 기록한다. 정상 완료와 취소, 실패, 저장 응답 유실 뒤 사용자가 보는 상태를 설명한다.
- 입력 예제와 기대 결과, 자원 한도, 비교 기준 및 실행 시험을 연결한다. 미구현 제안과 검증 대기 항목은 상태를 표시한다. 수치를 확정할 수 없는 경우 필요한 장비, 원본 또는 수신 환경을 명시한다.
- 승인 요구, 실제 제공하는 동작, 독립 수치 검증과 실측 판정에 각각 근거를 붙인다. 특정 모델에서 허용한 편차는 해당 사례에 한정한다.

## 경로와 변경 확인

`01_개발문서` 아래의 폴더와 파일은 각 폴더 안에서 `숫자번호_한글명`으로 관리한다. `README.md`는 안내용 예외다. 이 번호는 승인 요구 ID, 기능 ID, 화면 ID 및 개발 단계와 독립적이다. 이동할 때는 [이전 경로 대응표](10_문서목록/01_이전경로대응.json), 상대 링크, 감사 입력과 그림 연결을 함께 수정한다. 보관 원문에 기록된 예전 경로는 대응표로 찾는다.

1. 기능 변경 시 담당 계약, 관련 화면 및 요구 연결을 갱신한다. 승인 원문과 시안, 원본 출처, 사용자 편집값 및 과거 계산 결과를 보존한다.
2. 변경한 동작은 실제 진입점과 회귀시험에서 확인한다. 문서 변경은 명령, 링크, 그림, 기준선 해시와 실제 지원 범위를 대조한다.
3. 감사 입력이 달라졌으면 구현 추적을 재생성해 검사한다. 문서 목록은 마지막에 갱신한다. [갱신 명령](10_문서목록/README.md#갱신과-검사)
4. 확인한 범위와 남은 조건을 기록하고 한국어로 커밋한다. R1 최종 수용과 이후 리팩토링의 착수 상태는 작업표에서 관리한다.
