# 새 채팅 개발 인계

**다음 구현은 일반 도파관 단면의 다중모드다.** 평면 PCB X/Y 주기 해석과 독립 동박 패치 대조 조건, 복잡 형상의 격자 민감 사례를 408에 기록했다. 재개할 때에는 GitHub의 최신 `main`에서 작업표와 구현을 확인한다. [개발 순서](15_기능채택과_개발검증_순서.md#다음-작업-순서) [408 검증](../07_검증/408_동박_피시비의_이중주기_플로케_검증.md)

## 새 PC 또는 기존 작업 폴더에서 시작

새 PC의 PowerShell에서 원하는 상위 폴더로 이동한 뒤 실행한다. 코드는 원래 PC와 다른 경로에 받아도 된다.

```powershell
git clone -c core.longpaths=true --branch main https://github.com/EIDOSDATA/TraceWave-Studio.git "TraceWave Studio"
Set-Location -LiteralPath "TraceWave Studio"
git status --short --branch
git rev-parse HEAD
git ls-remote origin refs/heads/main
```

기존 PC의 저장소는 `C:/Users/eidos/GitHub/TraceWave-Studio`다. 기존 사본에서는 해당 폴더에서 `git fetch origin`과 `git status --short --branch`로 로컬 작업과 원격 개정을 먼저 확인한다. `main`이 뒤에 있고 작업 트리가 깨끗하면 `git pull --ff-only origin main`으로 갱신한다.

| 필요한 작업 | 준비할 환경과 위치 |
| --- | --- |
| 소스와 문서 확인 | 원격에 제품 소스, 시험, 재현용 입력, 고정 의존성 목록과 문서가 있다. 제품 명령은 복제한 저장소의 `Code` 폴더에서 실행한다. [개발 실행 안내](../../Code/README.md#실행) |
| 1번의 기존 Floquet 계산 재현 | Windows x64 CPython 3.12와 고정 수치 환경을 준비한다. 아래 명령은 제품에 포함된 유전체 격자 입력과 독립 대조 시험을 사용한다. [403 검증의 조건과 예상 수치](../07_검증/403_유전체_격자의_주기_플로케_경계_검증.md) |
| GUI, CAD 또는 실제 PCB FDTD 개발 | 해당 단계에 필요한 Windows 빌드, CAD 또는 WSL2의 전용 openEMS를 구성한다. [GUI 빌드](../../Code/ui/wxwidgets/README.md#개발-환경과-빌드), [Python 환경](../08_운영환경/01_파이썬_개발환경.md), [WSL2](../08_운영환경/02_리눅스하위시스템_개발환경.md), [openEMS](../08_운영환경/03_리눅스_개발환경.md) |

저장소 루트에서 아래 명령을 실행한다. Floquet와 도파관 예제는 각각 세 주파수의 결과를 출력한다. 마지막 시험은 Floquet 4개와 도파관 3개, 총 7개가 제외 없이 통과해야 기존 계산을 재현한 것이다.

```powershell
Set-Location Code
py -3.12 -m venv .local/rf-check
$rfPython = (Resolve-Path .local/rf-check/Scripts/python.exe).Path
& $rfPython -m pip install --only-binary=:all: --require-hashes -r runtime_profiles/python-network-windows-x64.txt
& $rfPython -m pip check
$env:PYTHONPATH = 'src;tests'
& $rfPython -m rfad floquet fixtures/floquet_dielectric_grating.json
& $rfPython -m rfad waveguide-modes fixtures/waveguide_te_step.json
& $rfPython -m unittest -v test_floquet test_waveguide_modes
```

2026-11-23 개발 PC에서 등록된 `TraceWave-Dev` 실행을 확인했다. WSL이 이전 저장소 폴더의 `ext4.vhdx`를 찾지 못해 `HCS/ERROR_PATH_NOT_FOUND`로 종료했다. 실제 PCB FDTD는 기존 VHDX/백업을 복원하거나 이전 자료를 보존한 새 전용 환경을 구성한 뒤 openEMS native 감사를 통과하면 재개한다.

가상환경, GUI 빌드 산출물, WSL 배포판과 `Code/.local`의 개발 PC 작업공간은 머신별로 구성한다. 과거 해석의 실행 ID와 수치는 검증 문서에 있고, 새 PC에서 같은 원시 결과를 열려면 해당 프로젝트와 결과 파일을 별도로 옮겨야 한다. 편집 이력과 선택한 원문은 Studio의 프로젝트 보존 묶음으로 옮길 수 있다. 외부 worker의 결과 파일은 묶음의 누락 목록을 확인해 별도로 인계한다. [보존 묶음과 편집 복원](../05_기능설계/01_프로젝트/02_프로젝트_보존묶음과_편집복원.md)

개발 PC의 `stage-check`, `tracewave-cadpose`, `tracewave-sensitivity` 세 작업 트리에서 보존할 소스는 모두 원격 커밋에서 확인했다. 새 PC에서는 위에서 복제한 `main`으로 이어간다. [작업 트리별 대조 기록](../11_검토기록/08_문서정비와_인계검토.md#새-pc로-옮길-때의-연결-작업-트리)

## 개발과 릴리스 판단

- 일차원 유전체 격자, 직사각 도파관 TE(m,0), 최대 8개 PCB 집중 급전, 삼각 곡면의 기록장 적분, 관통 패드스택과 단일 보드 ODB++ 반복 패널까지 확인했다. 사례와 지원 범위는 [403~407 검증 요약](15_기능채택과_개발검증_순서.md#후속-기능-5개-검증)에 있다.
- 실제 제작과 측정 조건은 미정이다. 실측 비교는 선택 사항이다. 고정 RO4350B 사례의 7/8분할 편차 2.788446%는 허용했다. Windows IME, 오류 안내, 혼합 DPI 검수를 마쳤고 기준 PC 성능은 R1 승인에서 제외했다. [R1 작업표와 근거](04_현행버전_남은작업.md)
- 기능 개발 후 그 개정으로 새 후보를 만들고, 온라인 상태의 별도 클린 Windows/WSL2 PC에서 수신 검수한다. `r1-rc1`은 이전 후보의 태그다. R1 최종 수용 후 리팩토링에 착수한다. [배포와 수신 절차](../08_운영환경/05_윈도우_내부검증_배포.md)
