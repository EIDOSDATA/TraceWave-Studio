# TraceWave Studio 개발 완료 계획

갱신일: 2026-11-17 KST

이 문서는 승인된 RFAD-D0-3.4, 현재 Code 구현과 검증 기록을 대조하여 정한 개발 순서다. 이전 대화의 7/8단계 권장 목록을 대체한다. 기존 목록은 손실 검증 이후의 일부 작업만 다뤘으며 R1 전체 기능을 포함하지 않았다. 앞으로 작업 순서는 이 문서를 기준으로 관리하고, 실제 완료 증거는 [개발 상태](02_개발착수와_현재상태.md)에 기록한다.

## 1. 무엇을 완성하는가

첫 완료 대상은 Windows 11 x64의 wxWidgets GUI와 local WSL2 openEMS worker를 사용하는 R1 내부 검증용 제품이다. 사용자가 원호/IFA 단일 포트 안테나를 만들고 PCB/물성/급전/환경을 설정하여 계산, 비교, 기본 측정 파일 확인과 2D/STEP/CAM 출력을 수행하는 전체 흐름을 완성한다.

- wxWidgets, Qt 제외, 필수 유료 GUI 부품 없음과 기존 직접 입력을 유지한다.
- 일반 편집 60 fps, 대형 장면 30 fps 및 승인된 성능 예산은 초기 목표다. 실제 측정 전 합격으로 표시하지 않는다.
- 제조업체 출처, 사용자 수정, 근사/가정과 실제 미정값을 구분한다.
- 코드 구현 완료, 수치 안정성, 목표 성능 충족, 제조/측정 검증은 서로 다른 상태다.
- R1의 모든 필수 수용 증거가 없는 중간 배포는 개발 검토용 빌드다. 이를 R1 완료로 표시하지 않는다.

근거는 [06 기능](../05_기능설계/01_기능_설계.md), [12 출력](../05_기능설계/05_출력교환/01_도면과_제조_파일_출력.md), [13 스윕과 측정](../05_기능설계/04_해석결과/01_최적화와_측정.md), [14 수용](../07_검증/01_검증과_수용_기준.md), [15 구현 선행](01_구현_계획.md)이다. 승인 원문과 승인 hash는 변경하지 않는다.

## 2. 현재 출발점과 빠진 부분

3번의 목표 공간/매개변수 강제 제약, 기대 연결과 실제 도체 성분 비교, 사용자 제조 규칙과 기본 DRC를 서비스와 GUI에 연결했다. 복합 형상/공정 검사와 4번 정밀 편집은 기존 순서로 이어간다. [설계 규칙 계약](../05_기능설계/02_설계편집/11_목표제약과_연결_설계규칙검사.md)

3번의 기본 적층 검토, 표면층과 개구, 설치 시나리오 및 간이/외부 STEP 물체를 서비스와 GUI에 연결했다. 기본 CAD 배치/검사와 범위별 무효화를 제공하며 환경을 포함한 EM, 복합 조립체와 제작 검수는 지원표에 남긴다. [적층과 외부 환경](../05_기능설계/02_설계편집/12_적층과_외부환경.md)

3번에서 앞서 추가한 범위는 [G001/G008/G009 문헌 카드와 조건부 초기 길이](../05_기능설계/02_설계편집/10_추가문헌과_조건부_초기길이.md)다. 원문 일부 도체와 G001의 제한된 초기 길이만 연결했고, 4번 시안의 작업 탭/레이어/세로 도구/실제 작업 상태를 함께 보강했다. 정밀 편집과 전체 UX 수용은 기존 순서에서 이어간다. 아래 기존 순서는 변경하지 않는다.

프로젝트 명령/저장/표현식/snapshot, PCB 재료 카탈로그와 직접 입력, 기본 2D 편집, OCCT CAD/STEP/3D 표시, WSL 실행/취소/결과 재열기, 제한된 단일 포트 해석, NF2FF, 독립 손실/전력 수지와 격자 한 축 연구 GUI는 기초 구현과 개별 시험이 있다. 이 기능을 다시 처음부터 구현하지 않는다.

현재 GUI가 전체 사용자 흐름과 성능 수용을 마친 상태는 아니다. [84개 구현 시안](../04_화면설계/16_전체화면_둘러보기.html)과 [구현 화면 기준](../04_화면설계/12_구현화면_설계기준.md)을 실제 구현에 적용한다. 스냅/끝점의 재검증은 [개별 검증 기록](../07_검증/07_스냅과_끝점_검증.md)을 따른다. 시안 문서의 과거 미구현 표기를 최신 완료 증거로 사용하지 않는다.

4번의 Studio 공통 화면과 정밀 편집은 [현재 계약](../05_기능설계/02_설계편집/13_정밀편집과_평면연산.md)과 [실행 검증](../07_검증/08_스튜디오와_정밀편집_검증.md)으로 범위를 고정한다. 기본 평면 연산은 같은 층/넷/역할의 planar_region이며 임의 도체를 자동으로 면으로 변환하지 않는다. 도면 출력은 10번, 전체 UX/성능/복구 수용은 12번을 유지한다. 일반 기하 구속 솔버는 R2 범위이며 현재 목표 제약/연결/DRC를 대체하지 않는다.

현재 확인한 주요 미완성 범위는 다음과 같다.

8번의 유한 후속에서는 PEC 다이폴 3수준을 실제 계산하고 독립 이상 패턴/지향성과 비교했다. [실행 기록](../07_검증/19_독립참조와_유한검증.md)의 사전 초도 기준과 관찰값을 구분한다. 평면 도체와 유한 급전 6사례는 여기/경계/단자 계약이 미확정이어서 실행을 차단한다. RO4350B 개별 손실/GHz PTH, 경계/종료조건을 포함한 일반 수렴과 실제 제조/측정 수용은 남으며, 아래 8번의 전체 종료 조건을 충족했다고 표시하지 않는다.

9번에서는 완료된 리터럴 매개변수 스윕의 [새 프로젝트 후보 채택](../05_기능설계/06_연구/02_후보채택과_새작업사본.md)을 연결했다. 명시 IFA/원호 6후보와 선택 사본 2개의 실제 재계산, 단일 undo/redo와 원본 보존을 확인했으며, 6후보의 -10 dB 목표 미달도 그대로 남긴다. Windows GUI의 재연결/조회 실패 보강 후 전용 12검사와 기존 GUI 8개, CTest 11개를 통과했고 실제 IFA 24 mm 후보의 별도 수동 채택/저장/재열기와 미정 조건 보존을 확인했다. 이상 간극 사례를 SMA/실장/실제 설치 환경, 일반 수렴과 제작/실측 검증으로 대체하지 않는다. [9번 검증 기록](../07_검증/21_후보채택과_원호아이에프에이_검증.md)에 소프트웨어 작업 흐름과 미확립 RF 범위를 구분한다.

## 3. 개발과 통합 순서

아래 순서는 전체 제품을 완성하는 의존관계에 따른다. 각 단계에서 서비스/API, 필요한 GUI, 의미 있는 시험과 설명을 함께 끝낸다. 모든 backend를 만든 뒤 GUI를 한 번에 붙이는 방식으로 진행하지 않는다.

| 순서 | 작업 | 먼저 필요한 이유 | 단계 종료 때 남길 결과 |
| --- | --- | --- | --- |
| 1 | 현재 RO4350B 연구 종료 | 실행 중인 작업과 원시 결과를 먼저 확정해야 이후 모델 변경과 섞이지 않음 | 사전 고정 N8까지 판정, 비용/예산 개선, 재후처리/재열기, 실패/미확립을 포함한 증거와 제한 |
| 2 | R1 세부 간극표와 공통 계약 확정 | 누락 기능과 부분 구현을 구분하고 이후 GUI/해석/출력의 중복 설계를 줄임 | FN/VT별 구현 위치/상태/증거/후속 작업, 지원 profile, 입력/결과 DTO, 화면 이동/상태 흐름 |
| 3 | 설계 모델과 기하 의미 보강 | 편집, 스윕, CAD/CAM이 같은 원본과 연결 의미를 써야 함 | 원호/IFA 템플릿/초기 후보, 목표/매개변수, 연결/기본 제조 검사, 적층/표면층, 기본 외부 STEP/환경 배치와 변경 무효화 |

## 4. 순서 안에서 함께 진행할 일

- 3번의 기하/단위/연결 계약이 고정되면 10번의 파일 adapter 개발을 앞서 진행할 수 있다. 최종 roundtrip은 실제 완성 후보와 다시 확인한다.
- 5번의 데이터 계약이 고정되면 7번의 비교 화면과 11번의 측정 조건 폼을 함께 연결할 수 있다. 측정 파일 읽기와 graph 비교를 두 번 구현하지 않는다.
- 8번의 고비용 계산 대기 중에는 solver source identity를 바꾸지 않는 독립 GUI/문서/파일 작업을 진행한다. 원래 실행의 코드/입력을 보존한다.
- 제작/측정에 걸리는 외부 대기는 9/10번의 입력과 전달물이 준비되는 즉시 시작할 수 있다. 그동안 12번과 배포 준비를 진행한다. 미정 자료 때문에 가능한 소프트웨어 작업까지 중단하지 않는다.
- 상태머신, 비동기 작업, 페이지 조회, 단위/출처/명령 처리는 기존 모듈을 재사용한다. 새 화면마다 별도 실행기나 저장 형식을 만들지 않는다.
- 성능 예산/복구/접근성 검사는 각 단계에도 적용한다. 12번은 처음 검사하는 시점이 아니라 전체 제품 조건의 최종 수용이다.

이는 작업 의존관계상 가능한 동시 진행을 뜻하며 현재 별도 agent를 생성하거나 여러 작업을 무제한 실행한다는 지시가 아니다. 계산 자원과 수정 범위를 제한한다.

## 6. GUI 작업의 끝과 누락 보강

GUI는 2번에서 이동/상태 계약, 4번에서 설계 화면, 6번에서 연구/실행, 7번에서 결과, 10/11번에서 출력/측정 흐름을 완성한다. 12번에서 아이콘/간격/단축키/키보드 이동/한국어 입력, 오류 위치와 다음 행동, DPI/패널 배치 및 실제 성능을 전체 흐름으로 점검한다. 사용자는 구현 세부를 알아야만 기본 작업을 수행할 수 있는 구조가 되어서는 안 된다.

각 단계의 종료 때 요구사항, 실패 경로, 저장/재열기, 이전 revision과의 관계, 비용/메모리, 사용자 설명을 확인한다. 발견한 간극은 연결 FN/VT, 재현 조건, 영향, 담당 단계와 함께 기록한다. 필수 간극은 릴리스 전에 해결하고, 후속 기능은 지원표와 미결표에 남긴다. 단순히 나중에 찾겠다고 미루거나 검증 범위를 말없이 줄이지 않는다.

고비용 RF 계산은 수식/단위/계약/작은 참조를 먼저 검사한 뒤 지원 조건을 고정해 수행한다. 같은 완료 연구를 코드 수정마다 전부 재실행하지 않으며 변경 영향에 맞는 시험을 선택한다. 재사용에는 원본 입력/실행 identity/파일 봉인을 검증한다.

## 7. 실제 자료와 R1 이후의 경계

실제 제작 적층, 납품 물성, 동박/마스크/표면처리, SMA/케이블/지그, VNA 교정과 방사 측정은 확보 시 확정한다. 현재 탐색 모델을 실제 납품값으로 승격하지 않는다. 실제 자료 없이 측정 비교 기능을 구현/시험할 수 있지만 실물 정확도 검증을 합격시킬 수는 없다. 필수 실물 AC가 남으면 소프트웨어 기능 완료와 R1 전체 수용을 구분해 보고한다.

R1 이후에는 관련 선행이 끝난 범위에서 다음으로 확장한다. 이 순서는 장기 기능의 의존 방향이며 R1 완료 전에 모두 구현해야 한다는 뜻이 아니다.

1. R2 고급 재료/포트/복소 network/다중포트 field basis와 해당 독립 검증.
2. 해당 기반을 사용하는 UWB/MIMO/배열, 고급 보정/OTA 처리, 자동/다목적 최적화와 공차/정합 합성.
3. R3 NFC/RFID/flex/body 전문 물리, 추가 solver/원격 HPC, 장비 직접 연결, 대리모델/역설계/AI 확장.

장기 로드맵에는 PCB 평면 패턴 외에 공간에 배치된 3차원 도체와 급전을 직접 모델링하고 해석하는 안테나를 포함한다. 입체 형상의 원본 표현, 급전/기준면, 재료, 해석 격자와 독립 참조 사례의 지원 범위를 별도로 검증한다. R1 PCB 해석과 3D CAD 뷰의 작업 순서는 유지한다.

Linux GUI는 승인한 후속 출시 범위이며 버전은 미정이다. 외부 공개/상용/소스 공개 방침도 내부 검증용 R1과 별도다. 이 계획으로 새 비용 지출이나 외부 배포를 실행하지 않는다.

## 9. 현재 위치

9번의 유한 후보 채택과 검증은 `ce9b618`, 10번의 도면/STEP 재검수는 `de8b5ac`로 게시했다. 같은 10번의 PCB 기계 형상, 유한 KiCad/Gerber X2/XNC/Job 출력/수입과 GUI를 연결하고 실제 Windows 수동 검수의 표시 보강과 저장/재열기를 확인했다. [10a 기록](../07_검증/23_연관도면과_스텝재검수_검증.md)과 [10b 기록](../07_검증/25_기판교환과_원문수입_검증.md)에 구현/형식 재입력/실제 수신/원문 보존 증거와 실행 시점을 각각 남긴다. 단계 마감 때 커밋/푸시하고 11번 시료/교정/기준면/불확도와 측정 비교로 이어간다. 전체 10번의 독립 STEP/제조 수용을 완료한 것으로 표시하지 않는다. 8/9번의 미확립 물리 항목은 그 번호에 남기며 다음 기능으로 진행했다는 사실로 완료 처리하지 않는다. 아래는 앞선 단계별 구현 근거와 당시 상태 설명이다.

2026-11-17 갱신: 4번의 스냅/끝점과 공통 Studio/이름/치수/회전/미러/기본 평면 연산은 `d0cfa79`, `4abd952`로 게시했고, 공통 외형 보강은 `dd9a20d`로 게시했다. 5번의 [공통 복소 자료/외부 이상 회로](../05_기능설계/04_해석결과/06_공통복소자료와_회로평가.md)와 [파일 교환](../05_기능설계/05_출력교환/03_복소결과_파일교환.md)은 위 유한 범위로 구현하고 실제 Windows GUI/원문 보존/저장/재열기 검증을 마쳤다. 실행별 시점과 범위는 [5번 검증 기록](../07_검증/11_공통복소결과와_회로평가_검증.md)을 따른다. 6번의 유한 연구/스윕을 서비스/GUI에 연결하고 실제 Windows/WSL 및 원문 보존을 [6번 검증 기록](../07_검증/13_설계스윕과_연구_검증.md)에 정리했다. 7번의 공통 결과/비교/Smith/방사/지원 필드를 위 profile로 연결하고 실제 Windows 저장/재열기, 회귀와 후속 보완 검증을 마쳤다. 이후 8번의 유한 독립 참조와 9번의 후보 채택으로 이어졌고 기존에 남긴 3/4/6/8/9번과 11/12번 수용 항목은 유지한다. 아래 3/4번의 작업 트리 및 문서 정비 설명은 이전 착수 시점 기록이다. 전체 84개 시안/접근성/성능 수용과 3/4번의 남은 범위를 완료 처리하지 않는다.

7번의 실제 Windows 주요 화면과 저장/재열기에서 원문/hash 보존을 확인했다. 전체 서비스/GUI 회귀, 후속 수치 보완과 실제 보존 산출물 재대조는 [7번 검증 기록](../07_검증/17_다중결과_표시검증.md)에 마감했다. 초기 실패와 집중 재검증, 환경 제외를 실행 시점별로 구분하며 여러 실행을 한 번의 전체 무실패 실행으로 합치지 않는다. 입력의 제작/측정 미정과 과거 목표 판정을 보존하고, 수치 종료 기준 달성과 독립 수렴/물리 검증을 분리한다. 표시 기능 구현을 새로운 FDTD/실물 검증이나 R1 전체 수용 완료로 확대하지 않는다.

현재 1번의 고정 N8까지 계산과 후처리/해석기 없는 재열기를 완료했다. 격자 축은 초기 기준을 충족했지만 국부 7/8분할의 방사 도체 변화가 최대 2.788446%여서 전체 개별 손실은 미확립이다. 원본 봉인 파일 135개와 기존 native 작업 ID를 보존했으며 신규 FDTD 없이 재후처리 결과가 같았다. 세부 결과는 [RO4350B 연구](../06_분석연구/11_고주파기판_도체손실_정밀연구.md)를 따른다. 이 미확립 항목은 8번에서 후속 검증한다.

2번의 요구/FN/VT 대조와 공통 계약 정리를 완료했다. 이후 [목표 편집](../04_화면설계/10_목표와_형상템플릿_화면.md), [명시 기하](../05_기능설계/02_설계편집/08_원호와_평면역에프_형상템플릿.md), [G031](../05_기능설계/02_설계편집/09_문헌기반_부분기하_카드.md), [추가 문헌/초기 길이](../05_기능설계/02_설계편집/10_추가문헌과_조건부_초기길이.md), [목표 제약/연결/기본 DRC](../05_기능설계/02_설계편집/11_목표제약과_연결_설계규칙검사.md), [적층/외부 STEP](../05_기능설계/02_설계편집/12_적층과_외부환경.md)을 연결했다. 최신 게시 기능 커밋은 `2c88d26`이다. 스냅/선과 원호 끝점 편집은 작업 트리에 보존되어 있고 최종 검증 정리/커밋은 별도다. 3/4번 전체 수용 완료로 확대하지 않는다.

2026-11-16 사용자 지시에 따라 기능 확장에 앞서 [화면설계서](../04_화면설계/README.md)와 전체 문서의 분류/내용 검토를 수행한다. 화면별 구성/이벤트/전환/예외와 이름 정책을 정리하고 각 기능 구현 때 함께 갱신한다. 이 문서 정비는 위 1~13번 번호를 대체하는 새 개발 순서가 아니다. 이후 구현은 미확정 의존성과 미정값을 유지하며 [문서 검토](../11_검토기록/README.md) 및 해당 기능 계약을 따른다. 완료 일정은 실제 구현량과 외부 검증 시간으로 갱신한다.
