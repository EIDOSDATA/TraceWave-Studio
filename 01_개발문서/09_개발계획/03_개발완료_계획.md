# TraceWave Studio 개발 완료 계획

이 문서는 RFAD-D0-3.4에서 승인한 R1 작업 1~13번과 당시 개발 순서를 보존한다. RC10의 내부 수용 결과와 사례별 한계는 [R1 작업표](04_현행버전_남은작업.md)에 있다. 새 GUI 개발은 [리팩토링 계획](07_현행버전_완료후_리팩토링.md#지금-이어갈-작업)과 [새 채팅 인계](08_새채팅_개발인계.md)에서 이어간다. [R1 수용 기준](../07_검증/01_검증과_수용_기준.md) [변경별 검증 선별 기준](05_현행버전_검증선별_기준.md)

## 1. 무엇을 완성하는가

첫 완료 대상은 Windows 11 x64의 wxWidgets GUI와 기본 Windows openEMS worker를 사용하는 R1 내부 검증용 제품이다. 사용자가 원호/IFA 단일 포트 안테나를 만들고 PCB/물성/급전/환경을 설정하여 계산, 비교, 기본 측정 파일 확인과 2D/STEP/CAM 출력을 수행하는 전체 흐름을 완성한다.

- R1 GUI는 wxWidgets를 사용한다. 필수 유료 GUI 부품 없이 기존 직접 입력을 지원한다.
- 12번은 실제 Windows 입력, 접근성과 화면 배치를 검수한다. 기준 PC 성능 측정은 현행 R1 승인 조건에서 제외했다.
- 제조업체 출처, 사용자 수정, 근사/가정과 실제 미정값을 구분한다.
- 코드 구현 완료, 수치 안정성, 목표 성능 충족, 제조/측정 검증은 서로 다른 상태다.
- R1의 모든 필수 수용 증거가 없는 중간 배포는 개발 검토용 빌드다. 이를 R1 완료로 표시하지 않는다.

근거는 [06 기능](../05_기능설계/01_기능_설계.md), [12 출력](../05_기능설계/05_출력교환/01_도면과_제조_파일_출력.md), [13 스윕과 측정](../05_기능설계/04_해석결과/01_최적화와_측정.md), [14 수용](../07_검증/01_검증과_수용_기준.md), [15 구현 선행](01_구현_계획.md)이다. 승인 원문과 승인 hash는 변경하지 않는다.

## 2. R1에서 확인한 범위와 수용 결과

1~7번, 10번의 동일 개정 교환과 11번의 선택형 측정 비교 소프트웨어를 검증했다. 8번 사례별 수용 범위와 한계는 잔여 작업표에 있다. 9번에서 고정한 두 합성 설치 후보의 격자 및 외부 여백을 바꿔 대역 목표 충족을 확인했다. [잔여 작업표](04_현행버전_남은작업.md), [대역 검증](../07_검증/311_설치후보_격자와_외부경계_대역검증.md)

Windows에서 실제 두벌식 입력, 오류 발화와 초점 복귀, 혼합 DPI 이동, 저장 및 복구를 확인했다. 개발 PC의 RC6 설치 검수와 로컬 RC9 계측을 마쳤다. 후속 화면 수정을 담은 RC10을 별도 온라인 Windows 11 x64 PC에서 검수하고 내부 R1으로 수용했다. [RC10 클린 PC 검수](../07_검증/427_알원_알시십_클린피시_수신과_수용.md) [B0 기준선](../07_검증/430_알원_비제로_기준선_확정.md) [R1 작업표](04_현행버전_남은작업.md)

1번 종료는 수렴 성공을 보장한다는 뜻이 아니다. N8까지 확인한 결과가 미확립이면 그 상태와 원인을 검토할 후속 항목을 8번에 남긴다. 결과를 본 뒤 기준을 완화하거나 더 큰 FDTD 연구를 무기한 추가하지 않는다.

2번은 전체 설계를 다시 쓰는 단계가 아니다. 승인된 FN/VT와 현재 기능을 연결하는 구현 간극표를 확정하는 짧은 정리다. 공통 계약은 필요한 변경만 하고, 모든 모듈을 한 번에 다시 작성하지 않는다.

## 4. 순서 안에서 함께 진행할 일

- 3번의 기하/단위/연결 계약이 고정되면 10번의 파일 adapter 개발을 앞서 진행할 수 있다. 이미 검증한 동일 개정의 교환 결과는 재사용하고 변환 또는 수신 조건이 바뀐 경로를 다시 확인한다.
- 5번의 데이터 계약이 고정되면 7번의 비교 화면과 11번의 측정 조건 폼을 함께 연결할 수 있다. 측정 파일 읽기와 graph 비교를 두 번 구현하지 않는다.
- 8번의 고비용 계산 대기 중에는 solver source identity를 바꾸지 않는 독립 GUI/문서/파일 작업을 진행한다. 원래 실행의 코드/입력을 보존한다.
- 설계 편집, 스윕, 해석과 계산 결과 검토는 명시한 모델 입력으로 진행한다. 11번 비교 기능은 합성 자료로도 검수한다. 제작과 측정이 필요한 대표 검증 사례는 9/10번의 해당 개정과 전달물이 준비된 뒤 수행한다.
- 상태머신, 비동기 작업, 페이지 조회, 단위/출처/명령 처리는 기존 모듈을 재사용한다. 새 화면마다 별도 실행기나 저장 형식을 만들지 않는다.
- 변경에 영향을 받는 복구 및 접근성 경로를 확인한다. 12번에서 실제 Windows 사용성 결과를 모은다.

## 6. GUI 작업의 끝과 누락 보강

GUI는 2번에서 이동/상태 계약, 4번에서 설계 화면, 6번에서 연구/실행, 7번에서 결과, 10/11번에서 출력/측정 흐름을 완성한다. 12번에서 아이콘/간격/단축키/키보드 이동/한국어 입력, 오류 위치와 다음 행동, DPI와 패널 배치를 전체 흐름에서 점검한다. 사용자는 구현 세부를 알아야만 기본 작업을 수행할 수 있는 구조가 되어서는 안 된다.

각 단계의 종료 때 요구사항, 실패 경로, 저장/재열기, 이전 revision과의 관계, 비용/메모리, 사용자 설명을 확인한다. 발견한 간극은 연결 FN/VT, 재현 조건, 영향, 담당 단계와 함께 기록한다. 필수 간극은 릴리스 전에 해결하고, 후속 기능은 지원표와 미결표에 남긴다. 단순히 나중에 찾겠다고 미루거나 검증 범위를 말없이 줄이지 않는다.

고비용 RF 계산은 수식/단위/계약/작은 참조를 먼저 검사한 뒤 지원 조건을 고정해 수행한다. 같은 완료 연구를 코드 수정마다 전부 재실행하지 않으며 변경 영향에 맞는 시험을 선택한다. 재사용에는 원본 입력/실행 identity/파일 봉인을 검증한다.

### 12번의 현재 검증 범위

서비스 중단, 프로젝트 손상, 디스크 부족과 쓰기 충돌 뒤의 복구, 한글 경로 저장 및 재열기, EDA/MCP 왕복은 Windows에서 확인했다. 개발 PC의 추가 프레임 개선 및 반복 계측은 종료했다. [복구 검증](../07_검증/299_윈도우_서비스_종료와_복구_회귀.md), [드래그와 표 스크롤의 마지막 계측](../07_검증/291_드래그_부분갱신과_표_지연_검증.md)

실제 Windows에서 한글 IME의 조합과 저장, 스크린리더의 오류 안내와 키보드 초점 복귀, 150%에서 100%로 배율이 바뀌는 모니터 이동을 확인했다. [Windows 사용성 결과](../07_검증/309_윈도우_한글입력과_접근성_검수.md)

## 7. 실제 자료와 R1 이후의 경계

실제 제작 적층, 납품 물성, 동박/마스크/표면처리, SMA/케이블/지그, VNA 교정과 방사 측정은 확보 시 확정한다. 현재 탐색 모델을 실제 납품값으로 승격하지 않는다. 2026-11-22 작업 지시에 따라 외부 측정 파일 비교는 선택 기능으로 제공한다. R1 소프트웨어 검수에는 명시 모델과 합성 비교 자료를 사용한다. 제작 및 시험소 측정은 사용자가 해당 실물의 정합이나 방사 성능을 평가하는 경우에 적용한다. 그 대표 사례의 실물 결과와 원래 승인 수용 기준은 별도 상태로 추적한다.

R1 이후에는 관련 선행이 끝난 범위에서 다음으로 확장한다. 이 순서는 장기 기능의 의존 방향이며 R1 완료 전에 모두 구현해야 한다는 뜻이 아니다.

1. R2 고급 재료/포트/복소 network/다중포트 field basis와 해당 독립 검증.
2. 해당 기반을 사용하는 UWB/MIMO/배열, 고급 보정/OTA 처리, 자동/다목적 최적화와 공차/정합 합성.
3. R3 NFC/RFID/flex/body 전문 물리, 추가 solver/원격 HPC, 장비 직접 연결, 대리모델/역설계/AI 확장.

장기 로드맵에는 PCB 평면 패턴 외에 공간에 배치된 3차원 도체와 급전을 직접 모델링하고 해석하는 안테나를 포함한다. 입체 형상의 원본 표현, 급전/기준면, 재료, 해석 격자와 독립 참조 사례의 지원 범위를 별도로 검증한다. R1 PCB 해석과 3D CAD 뷰의 작업 순서는 유지한다.

Linux GUI는 승인한 후속 출시 범위이며 버전은 미정이다. 외부 공개/상용/소스 공개 방침도 내부 검증용 R1과 별도다. 이 계획으로 새 비용 지출이나 외부 배포를 실행하지 않는다.

## 9. 단계별 진행 이력

9번의 유한 후보 채택과 검증은 `ce9b618`, 10번의 도면/STEP 재검수는 `de8b5ac`로 게시했다. 같은 10번의 PCB 기계 형상, 유한 KiCad/Gerber X2/XNC/Job 출력/수입과 GUI를 연결하고 실제 Windows 수동 검수의 표시 보강과 저장/재열기를 확인했다. [10a 기록](../07_검증/23_연관도면과_스텝재검수_검증.md)과 [10b 기록](../07_검증/25_기판교환과_원문수입_검증.md)에 구현/형식 재입력/실제 수신/원문 보존 증거와 실행 시점을 각각 남긴다. 이 기록 이후 11번 측정 비교 소프트웨어를 연결했다. 해당 시점의 전체·부분 수용은 8절에서 확인한다. 이후 독립 STEP과 동일 개정 수신은 [교환 검증](../07_검증/276_동일개정_교환수신_재검증.md)에서 확인했다. 실제 제조 조건은 미정이다. 8/9번의 미확립 물리 항목은 그 번호에 남기며 다음 기능으로 진행했다는 사실로 완료 처리하지 않는다. 아래는 앞선 단계별 구현 근거와 당시 상태 설명이다.

2026-11-17 갱신: 4번의 스냅/끝점과 공통 Studio/이름/치수/회전/미러/기본 평면 연산은 `d0cfa79`, `4abd952`로 게시했고, 공통 외형 보강은 `dd9a20d`로 게시했다. 5번의 [공통 복소 자료/외부 이상 회로](../05_기능설계/04_해석결과/06_공통복소자료와_회로평가.md)와 [파일 교환](../05_기능설계/05_출력교환/03_복소결과_파일교환.md)은 위 유한 범위로 구현하고 실제 Windows GUI/원문 보존/저장/재열기 검증을 마쳤다. 실행별 시점과 범위는 [5번 검증 기록](../07_검증/11_공통복소결과와_회로평가_검증.md)을 따른다. 6번의 유한 연구/스윕을 서비스/GUI에 연결하고 실제 Windows/WSL 및 원문 보존을 [6번 검증 기록](../07_검증/13_설계스윕과_연구_검증.md)에 정리했다. 7번의 공통 결과/비교/Smith/방사/지원 필드를 위 profile로 연결하고 실제 Windows 저장/재열기, 회귀와 후속 보완 검증을 마쳤다. 이후 8번의 유한 독립 참조와 9번의 후보 채택으로 이어졌고 기존에 남긴 3/4/6/8/9번과 11/12번 수용 항목은 유지한다. 아래 3/4번의 작업 트리 및 문서 정비 설명은 이전 착수 시점 기록이다. 전체 84개 시안/접근성/성능 수용과 3/4번의 남은 범위를 완료 처리하지 않는다.

7번의 실제 Windows 주요 화면과 저장/재열기에서 원문/hash 보존을 확인했다. 전체 서비스/GUI 회귀, 후속 수치 보완과 실제 보존 산출물 재대조는 [7번 검증 기록](../07_검증/17_다중결과_표시검증.md)에 마감했다. 초기 실패와 집중 재검증, 환경 제외를 실행 시점별로 구분하며 여러 실행을 한 번의 전체 무실패 실행으로 합치지 않는다. 입력의 제작/측정 미정과 과거 목표 판정을 보존하고, 수치 종료 기준 달성과 독립 수렴/물리 검증을 분리한다. 표시 기능 구현을 새로운 FDTD/실물 검증이나 R1 전체 수용 완료로 확대하지 않는다.

1번 연구 당시 고정 N8까지 계산과 후처리/해석기 없는 재열기를 완료했다. 격자 축은 초기 기준을 충족했지만 국부 7/8분할의 방사 도체 변화가 최대 2.788446%여서 전체 개별 손실은 미확립이다. 원본 봉인 파일 135개와 기존 native 작업 ID를 보존했으며 신규 FDTD 없이 재후처리 결과가 같았다. 세부 결과는 [RO4350B 연구](../06_분석연구/11_고주파기판_도체손실_정밀연구.md)를 따른다. 이후 8번의 추가 연구와 사례별 허용 결정은 [현행 작업표](04_현행버전_남은작업.md)에 연결했다.

2번의 요구/FN/VT 대조와 공통 계약 정리를 완료했다. 이후 [목표 편집](../04_화면설계/10_목표와_형상템플릿_화면.md), [명시 기하](../05_기능설계/02_설계편집/08_원호와_평면역에프_형상템플릿.md), [G031](../05_기능설계/02_설계편집/09_문헌기반_부분기하_카드.md), [추가 문헌/초기 길이](../05_기능설계/02_설계편집/10_추가문헌과_조건부_초기길이.md), [목표 제약/연결/기본 DRC](../05_기능설계/02_설계편집/11_목표제약과_연결_설계규칙검사.md), [적층/외부 STEP](../05_기능설계/02_설계편집/12_적층과_외부환경.md)을 연결했다. 초기 구현 당시 게시 커밋은 `2c88d26`였다. 이후 3번의 공개 자료 범위를 마감하고 원호·IFA 정밀 편집과 설치 폼 선택 복귀를 검증했다. 4번 급전과 양단 도체의 선택 연동은 이후 [Windows 검증](../07_검증/264_윈도우_급전단자와_진단_선택검증.md)으로 마감했다.

2026-11-16 당시 사용자 지시에 따라 기능 확장에 앞서 [화면설계서](../04_화면설계/README.md)와 전체 문서의 분류/내용 검토를 수행한다. 화면별 구성/이벤트/전환/예외와 이름 정책을 정리하고 각 기능 구현 때 함께 갱신한다. 이 문서 정비는 위 1~13번 번호를 대체하는 새 개발 순서가 아니다. 이후 구현은 미확정 의존성과 미정값을 유지하며 [문서 검토](../11_검토기록/README.md) 및 해당 기능 계약을 따른다. 완료 일정은 실제 구현량과 외부 검증 시간으로 갱신한다.
