# 개발 순서, 작업 분해, 완료 조건

RFAD-D0-3.4 기준선의 작업 분해와 종료 조건을 설명한다.

2026-11-07 승인 당시 내용과 승인 기록은 [기준선 보존본](../12_보관이력/01_승인기준선/01_삼점사/17_구현_계획.md)으로 분리했다. 이 문서는 현재 구현과 남은 설계의 관계를 정리한 편집본이며, 문서 수정만으로 구현/시험 상태를 승격하지 않는다.

## 1. 개발 방식

R1의 1~13번 작업은 내부 수용을 마쳤다. 아래 WBS는 승인 요구와 구현의 의존 관계를 찾는 데 쓴다. R1의 Windows GUI는 wxWidgets를 사용하며 Windows openEMS가 기본이고 기존 WSL2 작업자는 선택 경로다. 기준 PC 성능 검수는 2026-11-22 결정으로 R1 승인 범위에서 제외했다. GUI와 같은 도메인 명령으로 저장, STEP, 해석 및 결과 조회를 실행해 동작을 비교할 수 있다. [R1 완료 계획](03_개발완료_계획.md) [R1 수용 근거](04_현행버전_남은작업.md) [현재 리팩토링 작업](07_현행버전_완료후_리팩토링.md#지금-이어갈-작업)

미결 항목은 [25번 미결 항목 처리 기준](../07_검증/05_문서_검토와_승인.md#remaining-decision-policy)에 따라 처리한다. 실제 CPU/GPU, runtime 버전, IFA 실제 물성과 측정 장비 등은 개발 중 담당자가 구체화하고 해당 시험/제작/측정/배포 전에 고정한다. 모든 실물 조건을 확보해야 데이터/GUI/CAD 개발을 시작할 수 있는 것으로 해석하지 않는다. 채택된 성능/기능 목표 변경이나 외부 배포는 별도 결정으로 관리한다.

구현 단계는 R0/R1/R2/R3이고 실제 일정, 인력, 해석 runtime은 이 문서에서 임의로 산정하지 않는다. [통합 요구](../01_요구사항/01_사용자_요구사항.md)의 core stage와 개별 강화 clause의 stage를 함께 따른다.

WBS 숫자 순서가 엄격한 직렬 일정은 아니다. 원본 A가 현재 없다는 이유만으로 WBS-001 및 모든 후속 작업을 중단하지 않는다. 현존 문서의 요구/AC와 원본 B를 기준으로 검사하고 원본 A의 완전성은 미확인 상태로 추적한다. 선행이 분리된 CAD writer와 solver adapter는 병행할 수 있다. 단, 공통 unit/frame/phasor/schema 계약을 임의로 다르게 구현하면 안 된다.

Linux desktop wxGTK GUI는 후속 출시 범위이며 출시 버전은 아직 정하지 않았다. WBS-002의 Linux worker 기본 계산 검증은 R0에서 유지하고, 후속 wxGTK GUI 통합/배포 수용은 별도 작업 범위로 추적한다. 이를 자동으로 R2에 배정하거나 R1 Windows 완료 조건에 포함하지 않는다.

## 3. R0 종료 기준

- Linux native/headless worker의 의존성 버전을 실제 환경에서 고정하고 doctor와 기본 계산을 검증한다. Windows host/local WSL2 경로도 별도 증거를 남기며, worker 검증을 Linux GUI 제품 수용으로 표시하지 않는다.
- 원호의 좌표/width/endpoint/source grid와 units를 재현한다.
- thin copper, via/slot가 STEP에서 재열린다. writer 그림만으로 통과하지 않는다.
- known port/power/field fixture로 native normalization과 domain RMS 변환을 검증한다.
- 최소 방사체에서 실제 openEMS 결과, mesh/boundary/time 변화 데이터를 생성한다.
- source formula와 구현식의 부호, 단위, 가정을 audit하고 차이를 기록한다.

R0의 형상 검증 예제는 G031이다. 실제 RF 검증은 입력과 독립 기대 근거가 완비된 참조 계산 사례를 먼저 통과시킨 뒤, 물성이 완비된 단일포트 IFA를 첫 제품 사례로 진행한다. R1 원호 검증도 필수이며 IFA 합격으로 대체하지 않는다. 대역/보드 외형/적층 목표/급전은 [21번 IFA 초기 검증 기준](../07_검증/04_사례와_계약.md#ifa-initial-baseline)로 채택했으며 실제 재료 물성, 상세 형상 및 제작/측정 조건을 후속 fixture 명세에 채운다. 명시적 가정을 사용하는 탐색 해석은 실제 보드 검증과 구분하고, 비교 시험은 해당 조건, 불확도 산정 방법과 판정 규칙을 실행 전에 고정하고 실제 측정에서 얻는 수치 근거는 합격 판정 전에 확정한다. G031의 미정 물성에 임의값을 넣은 결과를 원본 비콘의 재현 성능으로 명명하지 않는다.

## 4. R1 완료 기준

Windows 11 x64 wxMSW GUI와 기본 Windows openEMS worker에서 사용자가 원호/IFA 단일포트 프로젝트를 만들고 물성, 급전, 환경 조건을 입력한 뒤 실제 해석, 전력/방사 검증과 수렴 상태를 확인하며 같은 revision의 실제 2D/STEP/CAM/결과/보고서를 내보낼 수 있다. 두 형상 모두 R1 검증이 필요하다. 알려진 supported profile에서 반복 가능하고, 실패, 누락, 미지원, 미수렴, stale 결과는 구별된다. 기본 측정 파일과 교정/환경 정보 비교, explicit sweep, 후보/작업 관리가 제공된다. 공개 수신 검수 후보와 최종 R1 배포의 판정은 [R1 작업표](04_현행버전_남은작업.md)에서 관리한다.

필수 결과를 fake JSON이나 미리 계산한 demo로 대신하지 않는다. mock은 단위/UI/계약시험이라는 이름과 출처를 붙이고 실제 analysis run과 분리한다. 데모 결과를 사용해도 snapshot hash와 맞지 않으면 현재 설계 결과로 표시하지 않는다.

## 5. 시험 계층

| 계층 | 대상 | 실행 시점 |
| --- | --- | --- |
| 단위, 수식 | units, expressions, EQ vector, transformations | 변경마다 빠르게 |
| 계약, schema | IDs, API payload, migration, cache dependency, error states | core/adapter 변경 |
| CAD, 파일 | critical geometry, solid/region, import/export/roundtrip | geometry/export 변경 |
| 실제 solver smoke | 설치/준비/실행/port/field 기본 결과 | runtime/adapter 변경 |
| 수렴, 독립 physics | mesh/PML/time/material/power/비교기준 | 기능 승격과 릴리스 |
| 측정 상관 | 실제 제작, 교정, OTA, 응용 성능 | 기준 시제품/환경 준비 후 |
| UI, 운영 | selection, worker, save/cancel/recover, platform | 사용자 흐름 변경과 릴리스 |

CI에서 모든 고비용 EM을 매 수정마다 돌리지 않는다. 변경 영향에 맞는 gate를 선택하고 nightly/release 기준군으로 나눈다. raw cache의 binary/software key를 고정해 구버전 결과로 새 solver 시험을 통과시키지 않는다.

## 6. 개발 산출물의 Definition of Done

각 작업은 연결 requirement/FN/API/EQ/VT IDs, 실제 구현, 필요한 사용자 설명, 조건부 기능표, 의미 있는 검증 결과를 가진다. 함수가 존재하거나 UI 버튼이 눌리는 것만으로 물리 기능 완료로 처리하지 않는다. known limitation은 issue와 capability 상태에 남긴다. 지원 범위 변경은 ADR와 matrix를 갱신하며 미실행 시험을 passed로 적지 않는다.

## 7. 변경 관리

Codex가 더 적합한 기술 선택이나 문서 오류를 발견하면 해당 ADR/수식/계약과 영향을 받는 요구, 화면, 시험을 함께 수정한다. 기존 user-required 2D/STEP/material/EM 조건을 편의상 삭제하지 않는다. 이전 데이터 migration과 결과 무효화 영향도 기록한다. 불확실한 성능 숫자를 정당화하기 위해 수용기준을 몰래 느슨하게 바꾸지 않는다.

## R0 최소 subcase의 명시적 포함

VT-001 geometry, VT-005 단위, VT-006/008 thin copper/via/slot, VT-011 수렴 series, VT-012/021 전력/정규화, VT-020 산술, VT-029 runtime을 포함한다. R0 일부 통과와 R1 전체 제품 수용은 별도다. GUI 기술은 C++ wxWidgets로 확정되었으며 승인 당시 선택 상태는 `selected_pending_validation`이다. GUI-SPIKE-001~007은 선택한 기술의 기능 통합, 복구 및 사용성을 검수한다.

## 8. 기준선과 현재 구현 상태 관리

D0 산출물은 00~22 및 24~25 설계 문서, 23 원문 B, 요구/AC/설계/VT 추적과 미결 결정표다. 현재 폴더에 없는 과거 JSON registry나 실행 기록을 전제로 개발 완료를 선언하지 않는다. R1 Windows 우선 범위, 원호/IFA 단일포트, 첫 검증 순서, 내부 검증용 배포가 확정 사항이다. 최초 IFA의 대역/외형/적층 목표/급전 초기 기준도 채택했다. 실행별 manifest는 검증 증거에 연결한다. IFA 실제 재료 물성과 상세 제작/측정 조건은 자료 확보 시 기록한다. Linux GUI 출시와 상용 배포는 별도 결정이다. 물성 입력 기능의 설계/구현과 실물 검증용 값의 확보는 별도 작업이다. 승인 원본은 기준선 보존본으로 남기고, 현재 구현 상태/설계 보완은 편집본과 날짜별 검토 기록에 연결한다. 현재 문서 보완을 새 기준선 승인으로 기록하지 않는다.

WBS-003의 기존 protocol/DTO와 WBS-011의 wxWidgets 통합을 재사용하며, GUI 보강을 CAD/solver의 기능별 계약과 함께 진행한다. UI-only 측정과 실제 backend 포함 측정을 분리한다. 일반 편집과 대형 장면의 fixture 및 frame 판정은 24번에서 관리하고 idle 상태의 60 fps 강제 redraw loop는 금지한다. Avalonia 비교 구현은 현재 작업에 포함하지 않으며 Qt로 자동 대체하지 않는다. 유료 GUI 부품을 필수로 요구하지 않는 기본 구성은 유료 부품의 모든 사용 금지나 제품 무료 배포 결정과 구별한다.

WBS별 상태는 planned/active/blocked/done, 증거는 not_run/passed/failed/inconclusive로 분리한다. D0 기준선 승인/문서 정합성 검사는 완료 기록으로 보존한다. 현재 WBS는 부분 구현과 미완료 수용이 섞여 있으므로 각 항목을 일괄 planned/done으로 표시하지 않는다. 실제 코드/시험/제한은 [구현 감사](../07_검증/06_승인요구와_구현대조.md)와 [개발 상태](02_개발착수와_현재상태.md)에서 확인한다. 문서 승인으로 제품 WBS를 done으로 올리지 않는다. 승인 대상과 잔여 gate는 [25번](../07_검증/05_문서_검토와_승인.md)을 따른다.

## 9. 기존 1~13번과 WBS의 대응

아래 번호는 사용자가 정한 기존 완료 계획 번호이며 WBS 번호나 R0/R1 릴리스 단계를 대체하지 않는다. 상세 선행/종료 산출물은 [개발 완료 계획](03_개발완료_계획.md)이 소유한다.

| 순서 | 원래 작업 묶음 | 연결 WBS와 당시 범위 |
| --- | --- | --- |
| 1 | RO4350B 사전 고정 연구 종료 | WBS-007~009. 연구 종료와 개별 손실 2% 기준 미확립을 함께 보존 |
| 2 | 세부 구현 간극/공통 계약 | WBS-001/003. 대조표 작성 완료, 새 기능마다 갱신 |
| 3 | 문헌/초기 후보, 목표 제약, 연결/DRC, 적층/환경 | WBS-004/005/012. 기본 경로 구현, 추가 합성/복합 제조/환경 EM은 제한 유지 |
| 4 | Studio 흐름과 정밀 2D 편집 | WBS-004/011. 공통 화면/이름/모델 치수/회전/미러/제한된 다각형 연산 연결. 실제 검증과 지원 경계는 [단계 기록](../07_검증/08_스튜디오와_정밀편집_검증.md). 전체 84개 화면/사용성 수용은 후속 기능과 분리 |
| 5 | 공통 복소 결과, RLC, Touchstone/CSV, 목표 평가 | WBS-009/013 |
| 6 | 설계 스윕/다축 연구와 예산/취소/재개 | WBS-013. 기존 수치조건 연구 재사용 |

| 11 | 교정/기준면/시료/불확도와 측정 비교 | WBS-013 |

화면별 기능/전환/오류/키보드 흐름은 [화면 설계](../04_화면설계/README.md)에서 관리하고 기능 구현과 함께 갱신한다. 기능별 관련 검증과 검토를 마친 단계는 사용자가 지시한 한국어 커밋/푸시로 인계한다. 문서 정비 중 보존된 미완료 제품 변경은 자동으로 완료 커밋에 포함하지 않는다. Linux GUI, R2/R3 및 일반 3차원 안테나 RF 장기 로드맵은 현재 1~13의 번호를 바꾸지 않는 후속 범위다.
