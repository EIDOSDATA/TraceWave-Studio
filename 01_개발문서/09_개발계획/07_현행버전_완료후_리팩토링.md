## 기술 선택을 좌우하는 조건

- **창, 한글과 접근성.** 한 창 안의 도킹과 다른 모니터로 패널을 분리하는 동작을 각각 확인한다. Dear ImGui는 Wayland의 별도 OS 창 배치에 제약을 명시한다. Windows 셸을 채택하기 전에 B0의 화면 이동, 초점 복귀, 한글 후보창, 스크린리더 이름·역할·동작을 같은 흐름으로 시험한다. 다른 플랫폼의 창 배치와 입력 제한은 해당 플랫폼 검수에서 판단한다. AccessKit 연동은 이 요구를 구현하는 후보이며 SDL3 파일 선택 콜백은 UI 스레드의 명령 큐로 전달한다. [ImGui 다중 창](https://github.com/ocornut/imgui/wiki/Multi-Viewports), [SDL3 파일 대화상자](https://wiki.libsdl.org/SDL3/SDL_ShowOpenFileDialog)
- **바이트 일치와 물리적 등가.** 원본 파일, canonical JSON, 버전 접두사를 포함한 SHA256, 공개 문서의 ID와 미정 상태는 정확히 비교한다. STEP 재출력은 단위, 형상, 공차와 source ID로 판정하고 RF 출력은 위상 규약, 포트 순서, mask와 물리량별 허용오차로 판정한다. 곡선 축약이나 표시 메시가 달라도 커서, 판정과 출력은 봉인 원문을 참조한다. [정규화 구현](../../Code/src/rfad/application/canonical.py), [물리 모델](../02_시스템명세/04_수식과_물리_모델.md)
- **원본, 파생물과 되돌리기.** SQLite는 카탈로그와 파생 인덱스에, HDF5 원문은 기존 봉인 자료에 쓴다. 새 캐시는 버전별 경로로 격리한다. 비교 실행에는 프로젝트 복사본과 단일 writer를 사용한다. 해석, 파일 발행처럼 외부 효과가 있는 명령은 별도 시험 영역에서 실행한다. 스키마 변경은 이식과 별도 개정으로 처리하고 원본과 이전 reader를 남긴다. [데이터 모델](../02_시스템명세/03_데이터_모델과_파일_형식.md), [편집 복원 계약](../05_기능설계/01_프로젝트/02_프로젝트_보존묶음과_편집복원.md)
- **비용과 라이선스.** 후보 채택 시 실제 배포하는 DLL, Python wheel, 셰이더와 폰트마다 버전, 고지 원문, 포함 방식과 재배포 조건을 고정한다. OCCT/GEOS와 openEMS/CSXCAD는 실제 빌드 및 전달 형태를 확인한다. Dear ImGui와 선택 도구인 ImGui Test Engine의 배포 조건도 각각 검토한다. 내부 배포와 외부 공개의 의사결정 및 비용은 릴리스별로 기록한다. [현행 Windows 묶음의 고지와 공급 출처](../08_운영환경/05_윈도우_내부검증_배포.md)

구현 중에는 바뀐 경계의 기존 회귀를 사용한다. 화면 이식에는 동일 입력의 편집과 저장, 전송 이식에는 대용량 결과의 부분 조회와 회수, 계산 이식에는 해당 수치의 기존 독립 참조를 연결한다. 같은 기능을 양쪽에서 매번 전수 재계산하는 방식은 제외한다. 범용 비평면 3D 안테나, 새 해석 방법과 재료/실측 수용은 별도의 제품 기능 및 물리 검증 결정이다. 해당 개발의 정확도는 리팩토링 전후의 동작 일치만으로 확정할 수 없다.
