R1은 별도 Windows 11 x64 PC에서 수용을 마쳤다. `main`에서 새 GUI를 개발하고, 최신 공개 Windows 설치본의 wxWidgets 제품으로 동작을 대조한다. [RC10 수용 기록](../07_검증/427_알원_알시십_클린피시_수신과_수용.md) [B0 소스와 보존 자료](../07_검증/430_알원_비제로_기준선_확정.md)

## 지금 이어갈 작업

**1단계 Windows 수용 완료.** 독립 시제품에서 Windows Vulkan, B0 S11 표본 31개, 창 분리와 배치 복원, 서로 다른 배율의 모니터 이동을 확인했다. 본창과 분리 창의 실제 Microsoft 두벌식 조합, 확정, 취소와 한자 후보창, 이동한 분리 창의 후보 위치를 확인했다. Windows UI Automation, 키보드, 실제 내레이터와 분리 창을 닫은 뒤 본창 초점 복귀도 확인했다. [시제품 빌드와 실행](../../Code/ui/prototype/README.md#빌드와-실행) [432 후보창 실기 검수](../07_검증/432_창과_렌더러_시제품_검증.md#분리-입력-창의-실제-microsoft-한자-후보창)

**2단계 서비스 연결과 시험 사본 비교 완료.** 새 클라이언트로 공개 RC10과 현재 Python의 `capabilities.get`을 확인했다. 보존 브랜치와 RC10 배포본 및 현재 소스에서 공개 API와 MCP, 개정·오류·취소·재시도와 양방향 재열기를 시험 사본에서 대조했다. 각 런타임의 RF 회귀 12건과 실제 Windows openEMS 작업 취소 및 과거 S11 표본 31개 재열기를 확인했다. [서비스 계약 대조](../07_검증/432_창과_렌더러_시제품_검증.md#새-클라이언트의-공개-명령-재생)

**Windows 비교 기준은 최신 공개 설치본이다.** 현재 기준은 공개 RC10 소스 개정 `6fd099136d5c`이다. 같은 독립 시험 자료를 설치본과 새 클라이언트에서 열어 저장 개정, 과거 결과와 출처, 공개 API 및 MCP를 대조한다. 유실된 B0 원본 작업 영역의 복원과 재생 항목은 종료했다. [RC10 배포](https://github.com/EIDOSDATA/TraceWave-Studio/releases/tag/r1-rc10)

**3단계 Windows 기능 이식 진행 중.** 최신 공개 RC10 설치본을 기준으로 작업한다. 새 창에서 프로젝트를 열어 실제 2D 기판을 표시하고 객체 선택, 이동, 되돌리기, 저장 개정과 재열기를 연결했다. 게시된 CAD의 3D 미리보기와 최신 완료 해석의 S11을 화면에서 재열고 출력 개정, 출처와 MCP 표본을 확인했다. 새 화면에서 RC10 CAD 작업자를 실행해 3D 생성, 실행 중 취소, 재시도와 AP242 STEP 게시를 확인했다. 저장한 해석 조건 선택, 개정에 결합한 계획 검토와 승인, Windows openEMS 실제 실행과 실행 중 취소를 새 화면에서 확인했다. 과거 RF 결과 목록에서 개정별 결과를 선택하고 당시 출처와 S11 표본을 대조했다. SVG/DXF 기술 도면과 선택한 KiCad 풋프린트도 생성 및 재검수했고, 과거 RF의 Touchstone, HDF5 및 원문 저장과 실제 두 포트 해석의 복소 표본을 대조했다. 새 화면의 S 행렬에서 채널별 복소 표본과 과거 결과 재열기를 확인했다. 게시 KiCad 보드에서 제조 교환 후보 ZIP을 만드는 경로를 이식했고, KiCad 10.0.8로 두 제조 형식의 변환과 실제 시험 자료의 재수신을 확인했다. ## R1 이후 이식 순서

개발과 단계별 수용의 기준 환경은 Windows 11 x64다. Windows에서 1단계의 한글 입력과 접근성을 검증한 뒤 2~6단계의 서비스 연결, 사용자 작업 이식과 최적화를 순서대로 진행한다. Windows에서 이식한 기능과 배포를 검증한 뒤 Linux, macOS 순서로 실제 환경에서 호환성을 확인한다. 운영체제마다 입력, 창, 렌더링과 설치 동작을 검수해 지원 범위를 정한다.

| 제안서 단계 | 실행 단위 | 다음 단계로 넘어갈 근거 |
| --- | --- | --- |
| 0. B0 동결 | 릴리스 패키지와 소스, 대표 프로젝트 및 해석 원문, 공개 API/MCP 응답과 검수 범위를 고정했다. [B0 기준선](../07_검증/430_알원_비제로_기준선_확정.md) | 동결 당시의 검수 기록이다. 이후 기능 검수는 최신 공개 설치본과 같은 시험 사본으로 진행한다. |
| 1. 창과 렌더러 시제품 | 독립 C++20 실행 파일에 SDL3, Dear ImGui docking, bgfx, ImPlot을 연결했다. Windows Vulkan에서 B0 S11 곡선, 입력, 도킹, 별도 창과 배율 처리를 시험했다. [시제품 검증](../07_검증/432_창과_렌더러_시제품_검증.md) | Windows 본창과 분리 창에서 실제 한글 IME, 키보드 이동과 화면 읽기를 검증하면 Windows 서비스 연결로 넘어간다. Linux와 macOS의 창 검수는 7단계에서 진행한다. |
| 2. 호환 계층 | 기존 Python 서비스에 새 클라이언트를 연결한다. 같은 고정 명령을 독립 작업 사본에 재생한다. | 도메인 오류, 개정, 출처, 미정값, 취소와 재시도 결과가 기존 계약에 맞는다. |
| 3. 사용자 작업 이식 | 한 프로젝트 열기, 2D 선택/수정, 3D 확인, 되돌리기, 저장/재열기, RF 결과 조회와 MCP 읽기를 먼저 잇는다. CAD, 해석, 내보내기는 기존 worker를 사용한다. 이후 84개 시안의 실제 사용자 작업별로 확대한다. | 화면에서 선택한 객체 ID와 서비스 개정이 맞고 구판으로 복귀해 원본을 다시 열 수 있다. |
| 4. 큰 배열 전달과 GPU 수명 | 복사 비용이 큰 경로에서 형식 버전, 자료형, 배열 길이, 소유자, 바이트 범위와 개정을 담은 내부 전달 형식을 시험한다. FlatBuffers와 읽기 전용 파일 또는 공유 메모리를 비교한다. | 크기 제한, 무결성, 늦은 결과 폐기, 취소/프로세스 종료 후 매핑 회수, 선택 및 원문 수치가 맞으며 복사 비용 또는 응답 지연 개선이 관측된다. |
| 5. CAD/평면 연산 | 동일 버전 OCCT/GEOS에서 기존 Python 경로와 네이티브 작업자를 비교한다. B-rep, 표시 메시 및 STEP 출력 수명을 분리한다. | 형상 단위, 원호와 접촉 공차, 층/net 연결, 출력과 원본 객체 대응이 유지된다. 실행 파일, 빌드, 의존성, 입력 출처를 재현할 수 있다. |
| 6. 서비스와 수치 병목 | 실제 프로파일에서 지연 또는 배포 비용이 확인된 모듈을 차례로 이식한다. 병렬 계산이 필요하면 oneTBB 등 후보와 커널 내부 스레드의 합산 예산을 측정한다. | 저장 복구, 복소 위상, 편파, 좌표, 비교 허용오차 및 유효 상태를 충족하고 개선량이 확인된 모듈을 채택한다. |
| 7. 플랫폼별 배포 | Windows 후보의 빌드와 설치를 우선 검증한다. 이후 Linux Vulkan(X11·Wayland), macOS Metal 순으로 실제 장비에서 호환성을 확인하고, 채택한 플랫폼의 컴파일러, SDK, 라이브러리와 셰이더를 고정한다. | 각 플랫폼의 지원을 선언하기 전에 실제 창과 입력, 프로젝트 저장·재열기, 해석 worker의 실행·취소, 설치 패키지와 고지를 검수한다. |
| 8. 구 경로 정리 | 기존 배포본의 지원 작업별 이식 결과, 구판 복귀 가능 지점과 남길 회귀 자료를 기록한다. | 대체된 구현과 캐시를 제거할 때도 원본 프로젝트, 과거 실행 자료와 비교용 reader를 계속 사용할 수 있다. |

## 기술 선택을 좌우하는 조건

- **창, 한글과 접근성.** 한 창 안의 도킹과 다른 모니터로 패널을 분리하는 동작을 각각 확인한다. Dear ImGui는 Wayland의 별도 OS 창 배치에 제약을 명시한다. Windows 셸을 채택하기 전에 기존 배포본의 화면 이동, 초점 복귀, 한글 후보창, 스크린리더 이름·역할·동작을 같은 흐름으로 시험한다. 다른 플랫폼의 창 배치와 입력 제한은 해당 플랫폼 검수에서 판단한다. AccessKit 연동은 이 요구를 구현하는 후보이며 SDL3 파일 선택 콜백은 UI 스레드의 명령 큐로 전달한다. [ImGui 다중 창](https://github.com/ocornut/imgui/wiki/Multi-Viewports), [SDL3 파일 대화상자](https://wiki.libsdl.org/SDL3/SDL_ShowOpenFileDialog)
- **바이트 일치와 물리적 등가.** 원본 파일, canonical JSON, 버전 접두사를 포함한 SHA256, 공개 문서의 ID와 미정 상태는 정확히 비교한다. STEP 재출력은 단위, 형상, 공차와 source ID로 판정하고 RF 출력은 위상 규약, 포트 순서, mask와 물리량별 허용오차로 판정한다. 곡선 축약이나 표시 메시가 달라도 커서, 판정과 출력은 봉인 원문을 참조한다. [정규화 구현](../../Code/src/rfad/application/canonical.py), [물리 모델](../02_시스템명세/04_수식과_물리_모델.md)
- **원본, 파생물과 되돌리기.** SQLite는 카탈로그와 파생 인덱스에, HDF5 원문은 기존 봉인 자료에 쓴다. 새 캐시는 버전별 경로로 격리한다. 비교 실행에는 프로젝트 복사본과 단일 writer를 사용한다. 해석, 파일 발행처럼 외부 효과가 있는 명령은 별도 시험 영역에서 실행한다. 스키마 변경은 이식과 별도 개정으로 처리하고 원본과 이전 reader를 남긴다. [데이터 모델](../02_시스템명세/03_데이터_모델과_파일_형식.md), [편집 복원 계약](../05_기능설계/01_프로젝트/02_프로젝트_보존묶음과_편집복원.md)
- **비용과 라이선스.** 후보 채택 시 실제 배포하는 DLL, Python wheel, 셰이더와 폰트마다 버전, 고지 원문, 포함 방식과 재배포 조건을 고정한다. OCCT/GEOS와 openEMS/CSXCAD는 실제 빌드 및 전달 형태를 확인한다. Dear ImGui와 선택 도구인 ImGui Test Engine의 배포 조건도 각각 검토한다. 내부 배포와 외부 공개의 의사결정 및 비용은 릴리스별로 기록한다. [현행 Windows 묶음의 고지와 공급 출처](../08_운영환경/05_윈도우_내부검증_배포.md)

구현 중에는 바뀐 경계의 기존 회귀를 사용한다. 화면 이식에는 동일 입력의 편집과 저장, 전송 이식에는 대용량 결과의 부분 조회와 회수, 계산 이식에는 해당 수치의 기존 독립 참조를 연결한다. 같은 기능을 양쪽에서 매번 전수 재계산하는 방식은 제외한다. 범용 비평면 3D 안테나, 새 해석 방법과 재료/실측 수용은 별도의 제품 기능 및 물리 검증 결정이다. 해당 개발의 정확도는 리팩토링 전후의 동작 일치만으로 확정할 수 없다.
