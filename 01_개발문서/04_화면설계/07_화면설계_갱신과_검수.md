# 화면 설계의 갱신과 검수

기록일: 2026-11-16 KST. 이 문서는 문서 산출물 검수와 제품 GUI 수용을 분리한다.

## 기능 개발과 함께 갱신할 항목

| 변경 유형 | 같은 변경에서 갱신할 문서 / 그림 | 검수 |
| --- | --- | --- |
| 새 화면/명령/버튼 | 화면 목록, W/C 요소, 이벤트/입출력/활성 조건, 해당 DrawIO/PNG | 모든 진입과 복귀, 취소/오류, 키보드 |
| 입력/적용/저장 | 상태도, 초안/권위 개정 계약, 오류 문구 | 단위/출처/미정, undo/redo, 저장/새 서비스 재열기 |
| 객체/표시 이름 | 공통 이름 규칙, migration/DTO, 트리/속성/참조 선택 | 같은 UUID, 중복/한글/긴 이름, 과거 snapshot 보존 |
| 실행/취소/재개 | S20/P11 및 작업/연결 상태 | 접수/결과 불명/실제 종료, 이전 결과 보존 |
| 결과/출력 | 입력 개정, 유효 범위, 변환/검수/미평가 | 원본과 파생 구분, 실패/부분 파일, 조건 불일치 |
| 공통 테마/도킹 | 배치 그림과 접근성 표 | 실제 Windows DPI/포커스/IME/고대비, 화면 밖 복원 |

설계 변경은 기능 구현 전에 해당 화면 명세에 반영한다. 구현 후 `현재` 열을 코드와 맞추고 실행 검증을 별도 기록한다. 그림만 바뀐 상태를 구현으로, 버튼이 눌린 상태를 전체 수용으로 표시하지 않는다. 의미 있는 단위가 끝나면 검토/관련 시험 후 한국어 커밋과 origin/main 푸시를 수행한다.

번호와 선후 관계는 기존 개발 완료 계획을 유지한다. Linux GUI, 승인 R2/R3 및 일반 비평면 3차원 안테나 RF는 장기 범위로 별도 관리한다.

## 이번 산출물의 검수 범위

- 10개 그림의 DrawIO XML과 SVG를 같은 좌표/문자 정의로 생성했다. 도형 셀 ID, geometry, 연결선 종점 및 XML 형식을 검사한다.
- 로컬 headless Edge에서 한글 SVG를 PNG로 렌더하고, 글자 bounding box가 소유 도형을 넘지 않는지 검사한다. 실제 Studio GUI 조작이나 DrawIO 앱의 열기/저장 시험을 대신하지 않는다.
- 렌더 이미지를 직접 확인하여 글자 잘림, 겹침, 번호와 명세 연결을 검토한다. 앱의 접근성/성능 시험은 이번에 실행하지 않는다.
- 첨부 원본 2개는 바이트를 보존한다. 화면의 일부만 보이므로 전체 해상도/DPI/스크린리더 동작을 사진만으로 판정하지 않는다.
- Markdown의 로컬 링크와 원본/생성 파일을 검사한다. 실제 명령과 로그/해시는 [문서 검토 기록](../11_검토기록/README.md)에 기록한다.

## 재생성

저장소의 `Code`에서 다음을 실행한다. 두 번째 명령은 문서 도구용 Playwright와 Chromium 계열 실행 파일 경로를 사용한다. 제품 runtime 의존성은 변경하지 않는다.

```powershell
.venv/Scripts/python.exe -X utf8 tools/documentation/render_screen_design.py
node tools/documentation/render_screen_png.cjs '<문서 도구 node_modules 경로>' '<msedge.exe 경로>'
```

DrawIO에서 직접 편집할 때에는 같은 파일의 SVG/PNG를 재출력하고 화면 명세를 함께 수정한다. 생성기와 수동 파일이 불일치한 채 다음 실행으로 덮어쓰지 않도록 README의 관리 방식을 따른다. 새 화면을 추가하면 그림 목록과 전체 승인 UI 대응표에도 같은 ID를 추가한다.
