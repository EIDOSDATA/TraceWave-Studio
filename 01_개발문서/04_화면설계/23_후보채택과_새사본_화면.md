# 23. 후보 채택과 새 프로젝트 작업 사본 화면

작성일: 2026-11-17

개발 완료 계획 9번 중 S40의 후보 검토와 새 작업 사본 열기 흐름을 구체화한다. 서비스와 명시 원호/IFA 계산/사본 재계산을 검증했다. Windows 재연결/편집 상태 조회 실패 보강 후 전용 GUI 12검사와 기존 GUI 8개를 통과했다. 실제 IFA 24 mm 후보의 Windows 사본 생성/명시 열기/저장과 runtime 없는 재열기, 미정 조건 보존을 별도로 확인했다. 실제 화면 수용은 [9번 검증 기록](../07_검증/21_후보채택과_원호아이에프에이_검증.md)의 실행 근거를 따른다. 기존 84장 시안과 승인 원문은 변경하지 않는다. [연구 화면](20_설계스윕과_연구_화면.md), [공통 결과 화면](21_다중결과와_방사필드_화면.md), [후보 채택 기능 계약](../05_기능설계/06_연구/02_후보채택과_새작업사본.md)을 함께 따른다.

## 1. 진입과 작업 사본의 의미

Studio의 연구 목록에서 보존된 후보를 선택하고 `새 작업 사본으로 채택`을 누른다. 행 선택이나 결과 보기만으로 프로젝트를 만들거나 기존 설계를 바꾸지 않는다. 원본 프로젝트의 활성 개정, 저장 기준과 실행 취소 이력을 유지한다. 현재 원본에 미적용 편집 초안이 있으면 초안을 보존한 채 진입을 막고 먼저 해당 편집을 정리하도록 안내한다. 채택 진입을 위해 초안을 자동 적용하지 않는다.

새 작업 사본은 별도 프로젝트 ID와 경로를 갖는다. 사본 생성 성공과 사본 열기는 별도 동작이다. 성공한 뒤 `새 사본 열기`를 명시적으로 눌렀을 때만 Studio가 새 프로젝트로 전환한다. 원본 프로젝트로 복귀하여 기존 설계와 결과를 계속 볼 수 있다.

## 2. 검토 대화상자

공통 wxWidgets 대화상자 수명과 네이티브 탭을 사용한다. 읽기 전용 사용자 정의 2D 캔버스는 검토 대상 기하만 표시하며, 이 창에서 그리기/끝점 편집/삭제를 수행하지 않는다. 숫자 입력 해석, 후보 판정, 형상 원본과 저장은 서비스가 담당한다.

| 탭 | 기본 내용 |
| --- | --- |
| 후보 검토 | 연구 이름과 후보 순번, 매개변수 이름, 기준/선택 값과 단위, 기준/선택 후보의 읽기 전용 2D 전환, 채택 가능 여부와 구체적 차단 사유. |
| 출처와 조건 | 연구 기준 snapshot, 선택 후보의 원문/단위/출처, 실제 계산 후보와 source/pin, 당시 목표 판정, 수렴/물리/제작/실측 상태. |
| 새 작업 사본 | 새 프로젝트 이름과 경로, 선택 사유, 원본 보존 안내, 검토/생성/열기 동작. |

처음에는 `새 작업 사본` 탭을 연다. 필수 입력 뒤 `후보 / 저장 위치 검토`를 누르면 서비스의 검토 응답을 표시하는 `후보 검토` 탭으로 이동한다. 연구 기준과 원본 프로젝트의 현재 개정이 다르면 현재의 후속 편집이 새 사본에 포함되지 않는다고 명시한다.

사용자 이름과 후보 순번을 먼저 표시한다. UUID와 hash는 복사 가능한 읽기 전용 상세 근거에 둔다. `캐시 재사용`은 실제 계산 후보가 별도로 존재한다는 뜻이며 선택 후보의 원문이 같다는 뜻으로 표시하지 않는다.

미정은 0이나 기본값으로 채우지 않는다. 표본 목표 평가, 연속 대역, 수치 수렴과 실측은 따로 표시한다. 후보가 계산됐다는 이유만으로 `검증됨` 배지를 만들지 않는다. 긴 단일 JSON을 기본 사용자 인터페이스로 사용하지 않으며 상세 원문은 처음 접힌 영역에 둔다.

## 3. 전환 시나리오

1. 연구 목록에서 후보를 선택한다. 완료된 유효 `grid_sweep`의 리터럴 매개변수 후보가 대상이다. 지원하지 않는 연구 종류나 근거가 부족한 후보에는 사유를 표시한다.
2. `sweep.selection.context`로 선택 근거를 조회한 뒤 채택 검토 창을 연다. 원본 프로젝트와 고정 연구/후보의 조합을 연결하고 서비스가 제공한 예상 개정/정의 hash/source pin을 유지한다.
3. 제안된 새 사본 이름/경로를 확인하고 필수 채택 사유를 입력한다. 입력 변경은 이전 검토를 무효화한다. 최초 경로 제안은 검토할 초안이며 생성 시 충돌을 자동 회피하는 동작이 아니다.
4. `후보 / 저장 위치 검토`를 실행하여 실제 변경 목록, 기하, 출처와 차단 사유를 확인한다. 미리보기는 사본을 저장하지 않는다.
5. 현재 입력과 검토 hash가 일치하고 서비스가 허용한 경우에만 새 사본 생성을 접수한다. 생성 중 닫기/중복 적용을 차단한다.
6. 성공하면 생성된 프로젝트와 원본 보존 결과를 표시한다. 목록 재조회 실패를 생성 실패로 취급하여 같은 사본을 다시 만들지 않는다.
7. `새 사본 열기`를 누르면 기존 프로젝트 열기 경로로 전환한 뒤 2D 설계를 표시한다. 새 사본의 saved는 채택 후 개정이며, undo 1회는 같은 새 ID/이름의 연구 기준 사본으로 복원한다. 원본 프로젝트 이력은 변경되지 않는다.
8. 열기 실패 시 이미 생성된 사본의 식별자/경로를 유지한다. 열기를 다시 시도할 수 있으나 생성 버튼을 다시 활성화하지 않는다.

## 4. 수명, 오류와 선택 일치

| 상황 | 처리 |
| --- | --- |
| 새 검토 요청 | 이전 적용 가능 상태와 검토 hash를 해제한다. |
| 이름/경로/사유 변경 | 검토가 현재 입력과 일치하지 않음을 표시한다. 서비스 입력에 표시용 값을 임의 재환산해 넣지 않는다. |
| 늦은 조회 응답 | 프로젝트/연결/창 수명과 검토 요청 세대를 대조하고 옛 응답을 폐기한다. |
| 현재 프로젝트 개정 변경 | 원래 검토 근거와 현재 UI 상태를 혼합하지 않고 재검토 또는 창 재진입을 안내한다. |
| 기존 대상 경로 | 덮어쓰지 않고 사용자가 다른 경로를 명시하게 한다. |
| 변조/없는 근거/예산 초과 | 구체적 원인을 표시하고 생성하지 않는다. 출처를 버리는 자동 복구는 제공하지 않는다. |
| 적용 결과 불명 | 입력과 중복 생성을 잠그고 기존 request key/epoch를 보존해 `sweep.selection.receipt`로 확인한다. `unresolved`/`expired`는 실패 증거가 아니므로 새 키로 재시도하지 않는다. |
| 생성 성공 후 조회/열기 실패 | 생성 성공과 후속 조회 실패를 구별하며 이미 생성된 사본의 경로를 유지한다. |
| 창 닫기 | 미적용 이름/경로/사유가 있으면 폐기를 확인한다. 닫힌 창을 늦은 콜백이 호출하지 않는다. |

새 사본 생성 응답을 원본 프로젝트의 일반 변경 응답으로 처리하지 않는다. 원본 Studio의 개정, 저장 표시와 undo 상태는 그대로 두고 명시적인 열기 성공 후 새 프로젝트 상태로 교체한다.

미확정 요청의 원 request key/epoch와 복구 문맥은 GUI의 `wxConfig`에 보존한다. 복구용 표시 상태를 저장하기 위해 프로젝트 원문이나 현재 개정을 수정하지 않는다. 재진입하더라도 미확정 상태를 지우고 새로운 생성 요청부터 시작하지 않는다.

생성 성공 화면을 명시적으로 닫으면 해당 복구 키를 회수한다. `새 사본 열기`를 선택한 경우에는 새 프로젝트와 편집 상태 조회까지 성공한 뒤에만 회수하며, 열기 실패 시 같은 영수증과 생성 경로를 유지한다. Windows 작업공간 경로의 대소문자, 구분자와 점 경로 표기는 같은 복구 정체성으로 비교하되 저장한 workspace 원문은 변경하지 않는다.

프로젝트 열기 뒤 편집 또는 캔버스 조회가 실패하면 이전 DTO로 새 프로젝트를 편집하지 않는다. 두 DTO의 profile/프로젝트/개정과 캔버스 단위가 현재 원본에 일치할 때까지 편집, 저장, undo/redo와 캔버스 변경을 잠그고 `F5` 및 명시 열기만 복구 경로로 제공한다. 재연결은 최초 실행 인수의 프로젝트보다 현재 선택 경로를 우선하며, 같은 새 사본의 `F5` 재조회가 성공한 경우에도 보존한 열기 완료 동작을 거쳐 복구 키를 회수한다.

파일 복사 미지원도 입력 오류와 구별한다. 미지 확장, solver 자료나 과거 평가가 포함되어 현재 사본 profile이 처리할 수 없으면 보존할 수 없는 항목과 사유를 표시한다. 그 항목을 삭제하면 된다는 기본 동작을 제공하지 않는다. 이 화면은 일반 프로젝트 copy 또는 전체 이력 이관 창이 아니다.

## 5. 접근성과 검수

기존 Studio의 공통 글꼴, 간격과 색을 유지한다. 탭/표/입력/버튼의 키보드 순서를 제공하고 색만으로 미정/차단/성공을 구별하지 않는다. 표와 형상에는 최소 크기와 스크롤을 두며 아래쪽 동작 버튼이 가려지지 않도록 한다.

실제 Windows 검수에는 선택 후보와 계산 재사용 후보의 구분, 입력 변경 후 재검토, 기존 경로 거절, 원본 복귀, 사본 생성/명시 열기, undo/redo, 저장/재열기와 결과 불명 경계를 포함한다. 모든 DPI/해상도, 전체 84장 시안, 정밀 편집 성능과 최종 접근성 수용은 단계 12 및 R1 최종 검수에서 별도 확인한다.
