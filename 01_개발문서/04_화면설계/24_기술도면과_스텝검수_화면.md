# 24. 기술 도면과 STEP 검수 화면

작성일: 2026-11-17. 완료 계획 10번의 첫 구현 범위다. [49 기술 도면 시안](03_구현시안/49_기술도면_출력.png), [50 STEP 시안](03_구현시안/50_스텝_출력과_검수.png), [S50 전환도](02_전환도원본/09_출력과_검수.drawio)를 따른다. 기존 84장 시안은 보존하며 현재 구현 계약과 실제 실행 근거를 별도로 관리한다.

관련 기능은 [연관 도면과 재검수 계약](../05_기능설계/05_출력교환/04_연관도면과_출력재검수.md), 기존 3D 형상은 [기계 형상 계약](../05_기능설계/05_출력교환/02_기계형상_입력과_출력계약.md)을 따른다.

## 1. 작업 공간과 책임

상단 `출력` 작업 공간에 기술 도면/STEP/PCB-CAM 탭을 둔다. 현재 이 계약은 기술 도면과 STEP을 담당한다. PCB-CAM은 후속 기능 안내이며 보고서 화면은 12번에서 연결한다. 각 단계의 실제 capability가 준비되어야 활성 동작을 제공한다. 파일 목록만 있는 큰 JSON 창을 시안의 종이 미리보기로 대체하지 않는다.

| 영역 | 내용 |
| --- | --- |
| 왼쪽 탐색 | 기존 프로젝트/객체/층 탐색을 유지. 도면에 쓰는 snapshot과 현재 편집 원본을 구분 |
| 중앙 기술 도면 | 종이 경계, 실제 표제/치수/형상과 페이지 이동. 오른쪽에 용지/형식/축척/뷰/치수/주석 옵션 |
| 중앙 STEP | 출력 원본, 포함 층/형상/환경 개수와 생략 범위, 기존 출력 및 새 검수 기록 |
| 오른쪽 속성 | 출력 기준. 입력 이름/개정, 제작/측정 미정과 파일 근거. UUID/hash 원문은 접힌 상세 영역 |
| 하단 | 기존 문제/작업/로그. 출력 및 재검수 작업의 상태/취소와 후속 오류를 구분 |

GUI는 wxWidgets 입력/선택/표와 wxAUI 도킹을 사용한다. 종이 캔버스는 서비스가 계산한 mm 배치만 표시하고 단위 환산, 연관 치수 계산, 원본 저장이나 파일 생성을 소유하지 않는다. CAD의 3D 보기에는 기존 wxGLCanvas/OpenGL 표시 mesh를 사용한다.

## 2. 정상 전환

1. 출력 작업 공간에 진입하여 현재 프로젝트와 보존 snapshot 목록을 조회한다. 새 snapshot은 적용된 현재 개정만 고정한다. 미적용 편집 초안은 그대로 유지하며 출력 원본에 포함되지 않는다는 안내를 입력 행과 도움말에 표시한다. 초안을 포함하려면 먼저 해당 편집 화면에서 명시적으로 적용한다.
2. 새 snapshot 또는 보존된 snapshot을 명시적으로 선택한다. 당시 프로젝트/층 이름으로 옵션을 구성하고 현재 개정의 층을 과거 원본에 섞지 않는다.
3. 기술 도면에서 용지, 방향, 형식, 축척, 뷰와 치수/주석을 정한다. 지원 범위를 벗어난 옵션은 구체적 이유와 함께 거절한다.
4. `출력 내용 검토`에서 서비스의 비동기 미리보기를 요청한다. 완료한 종이 배치, 페이지 수, 포함 대상, 생략과 미정 조건을 확인한다.
5. 입력과 `review_hash`가 일치할 때만 출력을 접수한다. 출력 중 설계 원본은 고정 snapshot이고 현재 편집 상태와 독립적이다.
6. 완료 후 출력 목록에서 파일 근거와 검수 결과를 연다. 새 검수는 선택한 완료 작업의 manifest hash를 사용하며 같은 파일을 다시 생성하지 않는다.
7. STEP 검수는 원래 STEP/sidecar를 새 reader 프로세스에서 읽고 별도 검수 작업을 만든다. 완료 표시는 `동일 OCCT 커널` 범위이며 독립 CAD 또는 제작 검증의 성공 배지가 아니다.
8. 저장 후 다시 열어도 원래 출력과 새 검수 기록을 조회한다. 출력 runtime이 없으면 새 출력만 차단하고 보존 기록은 계속 읽을 수 있다.

사용자가 보는 주 이름은 프로젝트명, 층명, 형식과 작업의 의미다. 긴 UUID/hash는 상세에서 복사할 수 있으며 기본 목록의 이름을 대신하지 않는다. mm 등 단위를 숫자와 함께 표시하고 미정은 0으로 나타내지 않는다.

snapshot과 출력 이력의 시각은 `YYYY-MM-DD HH:mm:ss UTC`로 표시한다. 원래 epoch 값은 보존하며 지수 표기의 Unix 초를 기본 이름으로 내보내지 않는다. 포함/생략 항목의 이름도 당시 snapshot에서 조회하고 현재 편집 원본의 후속 이름 변경을 과거 출력에 덮지 않는다.

## 3. 입력 변경과 오류

| 상황 | 동작 |
| --- | --- |
| snapshot/형식/옵션 변경 | 이전 생성 가능 상태와 검토 hash를 해제하고 새 검토 필요를 표시 |
| 종이 범위/페이지 한도 초과 | 치수나 형상을 자르지 않고 오류와 수정할 옵션을 표시 |
| snapshot 조회 실패 | 이전 프로젝트나 다른 snapshot의 표시값으로 출력하지 않음 |
| 늦은 콜백 | 현재 연결/프로젝트/화면 수명과 요청 세대를 확인하고 오래된 응답 폐기 |
| 중복 실행 | 실행 중 같은 요청을 추가 접수하지 않음 |
| mutation 결과 불명 | 원 request key/epoch를 보존하고 영수증 조회. 새 키로 자동 반복하지 않음 |
| 생성 성공 후 목록 실패 | 생성 성공을 유지하고 목록 재조회만 허용. 생성 실패로 되돌리지 않음 |
| 취소/저장 실패/프로세스 중단 | 과거 완료 출력 유지. 닫힌 중간 파일을 검수 완료로 표시하지 않음 |
| worker 미설치/폰트 변경 | 어떤 출력 환경이 필요한지 안내. 프로젝트 저장/열기와 과거 파일 조회 유지 |

오류 메시지에 내부 프로토콜 구현을 기본 작업 절차로 요구하지 않는다. 고급 상세에는 원본/실행 식별과 구체적 진단을 보존한다. 성공, 미정, 차단은 글자로 구분하며 색상만 사용하지 않는다.

## 4. 검수 범위

기술 도면의 실제 화면 검수는 종이/도형/치수선/텍스트/표제란/축척 막대, 페이지 이동과 작은 창 스크롤을 포함한다. 파일 자체는 별도 reader의 실제 좌표, 원호 방향, 외곽/구멍 경계와 원문 대응 검사 및 PDF 렌더링으로 확인한다. GUI 캡처가 맞는 것과 파일 좌표가 맞는 것은 서로 다른 증거다.

Windows 실행에는 새 출력, 기존 출력 조회, 별도 STEP 재검수, 저장/종료/재열기 및 runtime 없는 조회를 포함한다. 실제 제조/측정 조건의 미정과 최초 출처를 출력 전후 비교한다. 독립 CAD를 실행할 수 없는 환경은 사유와 미수행 범위를 기록하며 같은 커널의 성공으로 대신 합격 처리하지 않는다.

현재 종이 캔버스는 선택 페이지를 영역에 맞춰 표시한다. 화면 확대/이동을 포함한 정밀 도면 열람, 전체 DPI/키보드/스크린리더/도킹 복구와 전체 84개 화면 수용은 완료 계획 12번에 남는다. 이 화면의 구현으로 후속 PCB/CAM/보고서와 전체 R1 수용을 완료했다고 표시하지 않는다.
