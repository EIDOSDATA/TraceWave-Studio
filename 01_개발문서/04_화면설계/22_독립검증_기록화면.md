# 22. 독립 RF 검증 기록 화면

작성일: 2026-11-17

이 문서는 개발 완료 계획 8번의 읽기 전용 검증 화면 계약이다. 기존 84장 시안 중 [48번 검증 보고서](03_구현시안/48_수렴_연구보고서.png)의 목록, 판정 표, 근거 패널 구조를 기존 Studio에 연결한다. 시안 파일의 정확한 경로와 상세 화면 목록은 [전체 화면 목록](13_전체화면목록.json)을 따른다. 이 문서는 기존 승인 원문, 과거 검증 기록이나 시안을 소급 변경하지 않는다.

## 1. 위치와 책임

- 상단 `비교` 작업의 하위 탭 `독립 RF 검증`을 사용한다. 내부 논리 페이지는 15번이며 기존 0~14번 페이지를 유지한다.
- 왼쪽은 검증 기록 목록, 중앙은 명시 선택한 계획 또는 보존 판정, 오른쪽은 판정 근거와 출처다. 작은 창에서는 기존 명시적 탐색/조건 탭과 스크롤을 사용한다.
- 공통 결과의 조건 패널과 전력/손실 화면에 `프로젝트 검증 기록` 진입 버튼을 둔다. 이 버튼은 프로젝트 전체의 검증 목록을 열며, 현재 선택한 결과가 검증되었다는 뜻이 아니다.
- 기존 `수렴 연구` 페이지와 `기존 수렴 보고서 열기` 파일 조회를 유지한다. 새 독립 검증 앱이나 중복 프로젝트 편집기를 만들지 않는다.
- GUI는 저장된 기록을 읽는다. 캠페인 생성, 실행, 취소, 예산 변경, 판정 생성, 물성 확정, RF 계산은 이 화면의 권한이 아니다.

## 2. 화면 구성

| 영역 | 표시와 동작 |
| --- | --- |
| 검증 기록 목록 | 사람이 읽는 이름과 저장 상태, 목록 새로고침, 25개 단위 이전/다음. UUID는 기본 이름으로 쓰지 않는다. |
| 표시 기록 선택 | `계획 / 현재 작업 상태 (판정 아님)`과 개별 보존 판정을 분리한다. 보존 판정의 목록 순번과 실제 저장 시각(UTC)을 표시하며 없는 시각을 생성하지 않는다. 같은 초에 작성된 판정도 순번으로 구분한다. |
| 보존 판정 목록 | 25개씩 조회하며 선택한 보고서가 다른 목록 페이지에 있으면 선택을 보존한다. 페이지 이동만으로 판정을 바꾸지 않는다. |
| 사례 표 | 사례 이름, 비교 축, 수준, 실제 실행 상태, 관련 결과 유무, 차단 사유. 실행 전 차단을 계산 실패나 수치 0으로 대체하지 않는다. |
| 검증 축 표 | 격자, 경계, 시간 종료, 독립 참조, 제작, 실측의 여섯 축과 각각의 상태/사유. |
| 기준과 기록 값 | 사례, 지표, 주파수, 참조 값, 기록 값, 오차, 고정 한계, 단위, 판정, 사유. 수치는 서비스 기록을 그대로 표시하며 임의 합격 기준을 만들지 않는다. |
| 원본과 실행 범위 | 계획/보존 판정의 구분, 서비스가 제공한 예산, 누적 예약과 기록한 실행 횟수/벽시계 시간. 디스크 예약과 메모리 추정 상한을 실측 사용량 또는 수용 합격으로 표시하지 않는다. |
| 출처와 가정 | 보존 출처, 모델 가정과 적용 범위, 사전에 고정한 알려진 기준. 원문 비율은 비율로 표시하며 백분율로 재계산하지 않는다. |
| 미확립과 제작/측정 | 제작 조건과 측정 조건의 미정 여부, 물리/실측 검증의 남은 한계. |
| 선택 지표의 기준/사유 | 선택한 지표 또는 사례의 구체적 판정 사유와 기준 출처. |
| 고급/보존 원문 | 복사 가능한 읽기 전용 원문. 처음에는 접혀 있으며 기본 화면에서 JSON을 읽도록 요구하지 않는다. |

표의 실제 행을 가리지 않도록 최소 높이와 중앙 세로 스크롤을 확보한다. 긴 지표와 복소 결과는 표 내부의 가로 스크롤로 접근한다. 기본 동작 버튼은 줄바꿈할 수 있는 네이티브 배치에 둔다. 주파수는 공통 표시 모델의 Hz/kHz/MHz/GHz로 읽기 좋게 표시하며 원본 SI 값은 변경하지 않는다.

## 3. 전환 시나리오

1. 사용자가 `비교 > 독립 RF 검증`을 선택한다. 현재 프로젝트의 검증 목록을 읽는다.
2. 목록 행을 선택하면 목록이 제공한 명시적 최신 보고서 ID를 읽는다. 보고서가 없으면 `report_id: null`인 계획/현재 작업을 읽는다.
3. 표시 기록에서 `계획`을 선택하면 계획과 현재 작업만 조회한다. 서비스와 GUI 모두 최신 보고서로 자동 대체하지 않는다.
4. 다른 보존 판정을 선택하면 그 보고서의 불변 자료를 읽는다. 현재 계산 상태나 현재 설계 개정으로 과거 판정을 덮어쓰지 않는다.
5. 사례를 선택하면 관련 결과 열기 가능 여부와 사유를 표시한다. `source`와 `pin`이 실제로 보존된 경우에만 버튼을 활성화한다.
6. 관련 결과 열기는 기존 공통 결과 화면으로 이동한다. `result.describe` 응답의 원본과 전체 `pin`을 보고서와 대조하고 일치할 때만 곡선과 조건을 표시한다. 왼쪽 종류도 `해석 실행`으로 전환하고 실제 목록을 25개씩 최대 64페이지 조회하여 동일 원본 행을 선택한다. 사용자가 다른 종류나 원본을 선택하면 이전 목록 탐색을 폐기한다. 조회 범위에 없거나 목록 조회가 실패하면 봉인 원본을 유지하면서 그 사유를 표시하고 다른 행을 자동 선택하지 않는다. 미기록 사례에서 합성 곡선을 만들지 않는다.
7. 사용자는 기존 Smith, 전력/손실, 방사/편파와 필드 탭을 이어서 사용한다. 검증 기록으로 복귀하면 선택한 보고서와 출처를 유지한다.

## 4. 대기, 오류와 수명

| 상황 | 처리 |
| --- | --- |
| 프로젝트 없음 | 프로젝트 열기 안내와 빈 상태. 참조 사례를 자동 생성하지 않는다. |
| 조회 capability 없음 | 지원되지 않는 서비스라는 안내. 기존 수렴 보고서 파일 조회는 유지한다. |
| 저장 기록 없음 | 기록이 없음을 명시하며 예시 합격 행이나 그래프를 채우지 않는다. |
| 다른 사례/보고서 선택 중 | 이전 중앙 판정과 관련 결과 버튼을 비우고 새 조회 상태를 표시한다. |
| 빠른 선택과 늦은 응답 | 프로젝트/연결 세대, 검증 ID, 보고서 ID, 선택 세대를 모두 확인한다. 다른 선택의 응답은 폐기한다. |
| 목록 조회 실패 | 마지막 정상 목록과 기록을 보존하고 오류를 표시한다. |
| 선택 기록 조회 실패 | 선택 기록의 표와 관련 결과를 비우고 재선택/새로고침을 안내한다. |
| 프로젝트 전환/서비스 재시작 | 이전 요청 세대를 폐기하고 새 프로젝트의 목록을 다시 읽는다. |
| 창 종료 이후 응답 | 약한 수명 토큰과 요청 세대를 먼저 확인하고 닫힌 View를 호출하지 않는다. |
| 대기열 | 같은 종류의 미전송 조회는 최신 요청만 유지한다. 유한 상한 초과는 오류로 해제하며 영구 대기 상태를 만들지 않는다. |

## 5. 판정과 출처 보존

계산 종료, 격자 변화 관측, 경계 안정성, 시간 종료, 독립 모델 비교와 실측은 서로 다른 근거다. 한 축의 초기 기준 충족을 전체 물리 검증이나 납품 합격으로 확대하지 않는다. 합성 PEC 다이폴은 사용자 PCB와 별개이며 유한 반경 형상을 이상적인 얇은 반파장 해석식의 정확한 재현으로 표시하지 않는다.

RO4350B 국부 방사 도체 손실 변화 2.788446%와 초기 2% 기준의 미확립 상태, GHz PTH의 독립 정확도 미확립을 유지한다. 제작과 측정이 null이면 그대로 미정이다. 기준값, 예산, 출처, 각 판정의 원문과 과거 보고서는 조회/표시/페이지 이동/저장/재열기로 수정하지 않는다.

## 6. 구현과 검증 경계

`RfValidationView`는 네이티브 표, 선택 컨트롤, 접기 패널과 스크롤만 담당한다. `RfValidationUi`는 숫자/단위/상태 문구의 표시 모델이며 RF 판정을 계산하지 않는다. `RfValidationController`는 공개 `rf.validation.list`, `rf.validation.reports`, `rf.validation.get`과 수명을 연결한다. `studio_rf_validation.cpp`가 기존 프레임과 공통 결과의 진입만 담당한다.

GUI 자동시험은 실제 네이티브 이벤트, 계획/과거 판정 선택, 늦은 응답, 빈 상태, 미정과 원문의 저장/재열기 보존을 검사한다. 계약 시험용 미실행 또는 합성 전송은 FDTD 정확도나 실측 검증의 증거가 아니다. 실제 실행 결과와 Windows 수동 화면 검증의 바이너리, 시점, 범위는 별도 8번 검증 기록에 남긴다. 이 문서만으로 전체 84장 구현, 접근성, 성능 또는 독립 RF 정확도 합격을 선언하지 않는다.
