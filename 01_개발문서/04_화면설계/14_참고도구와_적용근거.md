# 참고 도구와 화면 구현 적용 근거

문서 ID: TWS-SD-014. 검토일: 2026-11-17 KST. 목적은 실제 wxWidgets/wxAUI 기반 화면의 구성과 작업 흐름을 구체화하는 것이다. 타사 제품 설치, 실제 조작, 접근성, 성능 또는 RF 정확도 비교 시험은 수행하지 않았다. 공식 도움말의 설명과 공개 화면 예시를 검토한 수준이다. 타사 화면 이미지나 아이콘을 제품 자산으로 복제하지 않는다.

## 기존 조사 범위와 이번 확인의 구분

[기존 화면 계약](08_스튜디오_화면계약.md) 8절은 2026-11-12의 UI 비교 9개를, 9절은 [원본 추가 요구사항](../01_요구사항/02_원본_추가_요구사항.md)에서 이어받은 조사 대상 26개를 기록한다. 26개에는 해석 엔진, Python API, 변환기와 GUI 제품이 섞여 있다. 사용자가 기억한 약 15~17개를 과거의 정확한 조사 수량으로 단정하지 않는다. 이번에는 기존 목록 전체의 역할을 다시 대조하고, 요청에 명시한 Altium과 SOLIDWORKS를 시각 구성의 추가 근거로 확인했다.

아래의 '채택'은 TraceWave의 설계 판단이며 해당 제품의 성능이나 구현을 그대로 승계한다는 뜻이 아니다. 웹에서 확인한 공급자 설명을 제조/측정 정확도의 증거로 사용하지 않는다. Altium 등의 유료 부품, Qt, 타사 해석 엔진을 필수 의존성으로 추가하지 않는다.

## 기존 조사 26개 항목의 누락 확인

`화면`은 공식 UI 설명/예시, `흐름`은 기능/작업 설명, `엔진`은 계산/API/변환 계약의 참고를 뜻한다. 링크를 열었다는 사실과 제품을 실행했다는 사실은 다르다.

## 구현 가능한 형태로 바꾸는 결정

1. wxFrame + wxMenuBar + 작은 공통 도구막대 + 작업 전환 + wxAuiManager의 좌/우/하단 패널을 기본 구조로 한다. 모든 화면을 웹 카드 대시보드처럼 만들지 않는다.
2. 중앙은 현재 wxNotebook을 재사용하는 내용 영역이다. 실제 탭 재배열/분할이 필요할 때 wxAuiNotebook을 검토한다. 설계의 2D/3D는 동일 모델의 보기이며 상위 설계/해석/결과 전환과 별도의 줄로 표시한다.
3. 프로젝트는 현재 wxTreeCtrl을, 입력 표는 wxGrid를, 결과/문제 목록은 wxListCtrl 또는 필요한 모델 기반 wxDataViewCtrl을 사용한다. 속성은 기존 EditorPanel의 표준 wx 컨트롤과 sizer를 유지한다. wxPropertyGridManager 도입이나 전체 폼 교체를 새 시안의 필수 조건으로 두지 않는다. 캔버스/그래프/3D와 작은 공통 장식만 사용자 정의 렌더링한다.
4. native 선택/입력 포커스/스크롤/키보드 동작을 보존한다. 비활성 버튼은 가능한 이유를 인접 문구로 설명하고, 색만으로 상태를 구별하지 않는다.
5. 원호/급전/접지의 표시 이름은 편집 가능하되 식별 ID와 생성 당시 사본은 서비스에서 분리한다. F2와 문맥 메뉴는 이름 입력을 열고, 이름 입력 상태에서 Enter 적용/Esc 취소를 수행한다.
6. 도구막대는 시안에 큰 그림과 긴 텍스트가 반복되는 70~90px 버튼을 쌓지 않는다. 기본 선택/선/원호/원/사각/치수에 작은 아이콘과 접근 가능한 이름, 현재 도구 설명, 메뉴 대안을 제공한다. 아이콘만 남겨야 하는 좁은 보기에도 명령 이름을 확인할 수 있는 도구 목록을 둔다. 삭제는 주 조작 열에서 분리하고 선택이 있을 때 활성화한다.
7. 오른쪽 속성은 형상, 층/재료, 출처/가정, 고급으로 나눈다. 적용/되돌리기는 패널 하단의 안정된 위치에 두고 초안 표시를 유지한다. 변경 명령은 자동 재전송하지 않는다.
8. 3D는 wxGLCanvas/OpenGL에 그리며 2D 위에 항상 덮인 독립 창을 기본값으로 두지 않는다. 2D/3D 분할은 넓은 화면의 선택 옵션으로 두고 각 뷰의 조작 모드/축/단위를 노출한다.
9. 결과 예시의 선/숫자/방사 모양은 별도 시안 데이터임을 명시한다. 실제 앱에서는 결과가 없을 때 빈 상태와 다음 행동을 보여주고 합격/측정 완료를 만들어 채우지 않는다.
10. 실측, 수렴, 출력 검수, 자료 출처, 제작 조건의 상태를 같은 녹색 완료 배지로 뭉치지 않는다. 기술 식별자와 검증 한계는 상세 문서/근거 창으로 연결하되 필요한 단위/미정 상태는 화면에서 바로 읽히게 한다.

위 수치/배치는 구현 설계이며, 실제 DPI 100/150/200%, 키보드/IME, 고대비, 스크린리더, 모니터 제거 후 도킹 복구는 후속 Windows GUI 수용 시험으로 확인한다. wxAUI의 버전별 기능은 저장소에 고정된 wxWidgets 버전과 코드로 확인해야 한다. 공식 docs.wxwidgets.org의 3.2 API 웹 페이지는 이번 조회에서 403/접근 실패가 있어 읽은 것으로 기록하지 않는다. 대신 아래의 공식 wxWidgets 3.2.12 저장소 API 문서와 실제 로컬 코드를 대조했다.

## wxWidgets 공식 API와 현재 코드 대조

현재 로컬 의존성의 wxWidgets 버전은 3.2.12다. 아래 링크는 wxWidgets 공식 저장소의 해당 태그에 고정한 API 문서 원문이다. 이번 조사에서 읽은 API 설명과 저장소 코드의 구성으로 구현 경로를 판단했으며, 모든 환경에서의 실제 조작/접근성/성능을 시험한 것은 아니다.

빌드의 `wxUSE_WEBVIEW=OFF`, `wxUSE_RIBBON=OFF`, core/base/aui/gl 연결을 유지한다. wxPropertyGrid 또는 웹 차트로 모든 기존 입력을 교체해야 새 외형을 구현할 수 있는 것은 아니다. 현재 차트는 제한된 단일 포트 DTO와 최대 201 표시 표본을 사용하므로 Smith/공통 복소 결과/다중 곡선은 별도 기능 구현이다.

wxAUI 문서에서 PinButton은 float 동작에 관한 버튼이다. 자동 숨김 레일, hover popup과 Windows IDE의 전체 docking 동작을 모두 기본 제공한다고 가정하지 않는다. 사용자 배치 영속화, 화면 밖 복원, 좁은 화면의 탭 묶음은 명시적인 표시 상태와 시험으로 구현한다. native 위젯의 API 존재는 제품의 키보드/IME/DPI/메모리/60 또는 30 fps 합격 근거가 아니다.
