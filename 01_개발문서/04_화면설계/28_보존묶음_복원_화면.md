# 보존 묶음 복원 화면

Studio의 **파일 > 프로젝트 보존 묶음 복원**에서 받는 작업 영역 안에 등록할 파일을 선택한다. [03번 저장본과 복구 시안](03_구현시안/03_저장본과_복구.png)의 세 열 비교 표, 제한 안내, 최하단 선택 흐름을 이 입력에 맞춰 적용했다. 시안의 정상 저장본과 비정상 종료 후보 비교는 현재 작업 영역의 별도 복구 흐름이다.

| 단계 | 중앙 검토와 아래 버튼 | 다음 상태 |
| --- | --- | --- |
| 열기 | 받는 작업 영역을 확인하고 기존 편집 복원용 `.rfad.zip`을 고른다. | 원문 읽기와 수신 진행 |
| 검토 | 보존 저장본과 가져올 개정, 경로, 작업 범위와 제작/실측 상태를 비교한다. 아래에는 스냅샷 개수, 누락 목록과 SHA256이 있다. | 닫기 또는 검토한 프로젝트 복원 |
| 복원 | 검토했던 입력을 예약한 뒤 전체 파일을 게시해 새 프로젝트를 등록한다. 이때 기존 프로젝트는 그대로 열린 상태다. | 복원 프로젝트 열기 또는 닫기 |
| 결과 불명 | 복원 결과 다시 확인에서 같은 SHA256의 권위 상태를 조회한다. 새 변경은 상태를 확인한 뒤 선택한다. | 등록 완료, 같은 묶음으로 이어가기 또는 미등록 |
| 복원 프로젝트 열기 | 사용자가 열기를 선택한다. 기존 편집의 미적용 초안 확인은 일반 프로젝트 전환과 같다. | 설계 작업 공간 |

읽기 전용 보고서 ZIP, 손상된 파일, 이미 등록된 경로/ID와 현 한도 초과는 사유를 표시한다. 파일이 다르면 이전 검토를 폐기한다. 열기와 복원에는 자동 해석을 연결하지 않는다. [편집 복원 계약](../05_기능설계/01_프로젝트/02_프로젝트_보존묶음과_편집복원.md) 및 [Windows 검증](../07_검증/33_스튜디오_보존묶음복원_검증.md)에 구조와 실제 화면을 기록한다.
