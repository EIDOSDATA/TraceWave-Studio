# Windows 설치, 제거와 배포 후보 만들기

온라인 Windows 11 x64에서 사용하는 사용자별 설치 프로그램이다. 설치하려는 사람은 Setup.exe 하나를 실행한다. 소스에서 후보를 만드는 개발자는 아래의 빌드 절차를 사용한다.

## 단일 Windows Setup.exe

| 2026-11-25 기준 | 설치 파일과 적용 범위 |
| --- | --- |
| 공개 프리릴리스 `r1-rc6` | GitHub에 게시된 Setup.exe와 해시. 개발 PC의 기본 설치, Windows 해석, 제거와 작업 보존을 확인했다. [RC6 다운로드](https://github.com/EIDOSDATA/TraceWave-Studio/releases/tag/r1-rc6), [통합 검수](../07_검증/419_알원_설치본의_통합_검수.md) |
| 개발 PC의 로컬 RC9 | 소스 개정 `40ab200`. 이 PC의 `Code/.local/rc9-release`에 Setup.exe와 해시가 있다. 기본 Windows 해석기 설치와 결과 첫 진입, 반복 전환의 계측 근거다. [RC9 파일과 해시](../07_검증/423_알원_사용성_후속_수정과_재검수.md#rc9-설치-후보와-결과-전환-계측) |
| RC9 이후 개발 빌드 | 424~425의 가독성 개선은 이후 `main`에 있다. 이 동작을 독립 PC에서 검수하려면 해당 개정으로 새 후보를 만든다. [화면 검수](../07_검증/424_전체화면_가독성_검수와_개선.md), [문구 재검수](../07_검증/425_화면_구분자와_문구_재검수.md) |

공개 RC6를 설치할 때는 릴리스의 `.exe`와 `.exe.sha256`을 같은 폴더에 받는다. 아래 PowerShell 명령을 그 폴더에서 실행한다. 다른 후보를 검수할 때는 전달받은 정확한 파일명을 사용한다.

```powershell
$setup = Get-Item -LiteralPath '.\TraceWave-Studio-R1-rc6-Setup.exe'
$expected = ((Get-Content -LiteralPath ($setup.FullName + '.sha256') -Raw).Trim() -split '\s+')[0]
$actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $setup.FullName).Hash
if ($expected -notmatch '^[0-9a-fA-F]{64}$' -or $actual -ne $expected)
{
    throw '설치 파일의 SHA-256을 다시 확인하세요.'
}
& $setup.FullName
```

기본 설치에는 인터넷 연결이 필요하다. Setup.exe는 내부 후보 ZIP의 SHA-256을 대조한 뒤 앱 전용 CPython과 WinLibs DLL, Windows openEMS를 원 공급처에서 받는다. 고정 목록으로 서비스, CAD, 네트워크, 출력 및 해석 환경을 구성한다. 시작 메뉴에서 **TraceWave Studio**를 연다. [설치 소스](../../Code/tools/windows_setup/install.ps1), [Windows 해석기 구성](../../Code/tools/setup_openems_windows.py)

| 기본 위치 | 확인할 내용 |
| --- | --- |
| `%LOCALAPPDATA%\TraceWaveStudio\Setup-status.json` | `revision`이 후보 개정과 일치하고 `windows_ready=true`, `simulation=ready`, `solver_platform=windows`이면 기본 설치가 완료됐다. |
| 같은 폴더의 `Setup.log` | 실패한 설치 단계와 오류. 다른 설치가 실행 중이면 그 설치가 끝난 뒤 다시 실행한다. |
| `Versions`, `Cache`, `Workspace` | 개정별 프로그램, 설치 캐시, 사용자 프로젝트와 결과를 각각 보관한다. |

기존 WSL2 환경 재현에는 `-WithWsl`을 지정한다. 해석 환경 준비를 미루는 `-WithoutSimulation`은 `simulation=deferred`를 기록한다. [선택형 WSL2 환경](02_리눅스하위시스템_개발환경.md)

## 업데이트와 제거

같은 사용자와 설치 위치에서 새 Setup.exe를 실행하면 기존 Workspace를 다시 연결하고 시작 메뉴와 Windows의 앱 항목을 갱신한다.

1. 열려 있는 프로젝트를 저장하고 Studio를 닫는다.
2. **설정 > 앱 > 설치된 앱 > TraceWave Studio > 제거**를 선택한다. 제어판의 **프로그램 및 기능**에서도 같은 제거기를 연다.
3. 제거하면 해당 설치의 앱, 전용 런타임, 설치 캐시와 바로가기가 정리된다. Workspace와 별도로 구성한 WSL 환경은 보존된다. 같은 위치에 재설치하면 기존 작업을 열 수 있다. [제거 소스](../../Code/tools/windows_setup/uninstall.ps1), [프로젝트 보존 확인](../07_검증/418_윈도우_표준_앱_제거_검증.md)

## 묶음 생성과 검증

검수할 소스 개정에서 [Windows Release GUI](../../Code/ui/wxwidgets/README.md#개발-환경과-빌드)를 빌드하고 CTest를 실행한다. 아래 명령은 이 개정으로 체크아웃한 저장소의 `Code`에서 실행한다. CPython 3.12 x64, 해당 빌드의 EXE와 런타임 DLL, wxWidgets 원본 압축, 고정한 고지 파일, PATH의 GNU objdump와 Windows .NET Framework x64 C# 컴파일러가 필요하다. [후보 입력 목록](../../Code/tools/internal_bundle_inputs.py), [고정 배포 프로필](../../Code/runtime_profiles/windows-internal-bundle-x64.json)

```powershell
$candidateCommit = git rev-parse HEAD
$shortCommit = $candidateCommit.Substring(0, 12)
$candidateZip = ".local/TraceWave-Studio-$shortCommit-windows-x64.zip"
$candidateSetup = ".local/TraceWave-Studio-$shortCommit-Setup.exe"
$profile = Get-Content -Encoding utf8 runtime_profiles/windows-internal-bundle-x64.json -Raw | ConvertFrom-Json
$notices = (New-Item -ItemType Directory -Path .local/release-notices -Force).FullName
foreach ($notice in $profile.external_notices.PSObject.Properties)
{
    $target = Join-Path $notices $notice.Name
    if (-not (Test-Path -LiteralPath $target))
    {
        Invoke-WebRequest -Uri $notice.Value.url -OutFile $target -ErrorAction Stop
    }
}
py -3.12 tools/build_internal_bundle.py --source-ref $candidateCommit --notice-dir $notices --external-compiler-runtime --output $candidateZip
if ($LASTEXITCODE -ne 0)
{
    throw '후보 ZIP 생성 실패'
}
py -3.12 tools/build_internal_bundle.py --verify $candidateZip
if ($LASTEXITCODE -ne 0)
{
    throw '후보 ZIP 검증 실패'
}
py -3.12 tools/build_windows_setup.py $candidateZip $candidateSetup
if ($LASTEXITCODE -ne 0)
{
    throw 'Setup.exe 생성 실패'
}
$hash = (Get-FileHash -Algorithm SHA256 -LiteralPath $candidateSetup).Hash.ToLowerInvariant()
"$hash  $(Split-Path -Leaf $candidateSetup)" | Set-Content -Encoding ascii -LiteralPath "$candidateSetup.sha256"
```

ZIP 검증 결과의 `source_revision`, 파일 수, ZIP 해시와 최종 Setup.exe의 해시를 검수 기록에 남긴다. 설치 소스와 아이콘은 같은 후보 ZIP에서 가져온다. 표시 버전은 기본적으로 커밋 앞 12자리다. 이름이 정해진 후보에는 Setup 생성 시 `--display-version 'R1 RC9'`와 같이 그 후보의 실제 이름을 준다. [ZIP 생성 및 검증](../../Code/tools/build_internal_bundle.py), [Setup 생성](../../Code/tools/build_windows_setup.py)

ZIP에는 Git 커밋에서 고른 제품 소스, 시험과 예제, 운영 문서, 빌드한 GUI 및 상류 고지가 들어간다. 공개용 ZIP은 컴파일러 DLL의 해시와 수신처를 기록한다. 설치가 원 공급처 자산을 받아 검증한다. 제조사 원본 자료, 사용자 프로젝트, WSL 배포판과 운영체제 글꼴은 별도로 인계한다. MCF 런타임의 상류 고지는 수록했으며 공급 빌드의 정확한 원본 커밋 연결은 미정이다. [배포 고지 및 DLL 식별값](../../Code/runtime_profiles/windows-internal-bundle-x64.json)

## 별도 클린 Windows PC 온라인 검수

기존 TraceWave 설치와 개발 캐시가 없는 별도 Windows 11 x64 PC, 인터넷 연결, 같은 개정의 Setup.exe와 해시를 준비한다. 시험에는 예제 사본을 사용한다.

1. 해시를 대조하고 기본 설치를 실행한다. Windows 빌드, 설치 개정, 의존성 버전과 Setup 상태를 기록한다.
2. 시작 메뉴에서 앱을 열어 제목 표시줄 아이콘을 확인한다. 한글 경로에서 예제를 편집하고 저장한 뒤 새 세션에서 해당 값을 읽는다.
3. Windows openEMS로 해석을 완료한다. 별도 해석은 진행 중 취소하고 종료 상태를 확인한다. 이전 결과와 출처를 다시 열고 도면 또는 보고서를 출력한다. 정상 저장본을 복구해 개정과 입력값을 확인한다.
4. 결과 화면 전환을 재측정할 때는 다른 시험을 닫고 같은 PCB의 3D에서 결과로 처음 들어갈 때와 다시 들어갈 때를 각각 기록한다. 사용한 원본의 수와 해시를 함께 남긴다. [RC9 비교 조건](../07_검증/423_알원_사용성_후속_수정과_재검수.md#rc9-설치-후보와-결과-전환-계측)
5. 설치된 앱의 버전과 아이콘을 확인한 뒤 표준 제거를 실행한다. 전용 런타임, 시작 메뉴와 앱 등록의 정리 여부를 기록한다. 같은 위치에 재설치하고 보존한 프로젝트와 결과를 다시 연다.
6. 독립 PC에서 관찰한 결과와 실패 재현 조건을 해당 개정 및 해시에 연결해 R1 수용을 판단한다. [R1 작업표](../09_개발계획/04_현행버전_남은작업.md)

## 이전 공개 ZIP 수신과 실행

`r1-rc1`과 `r1-rc2`는 DLL과 기능별 Python 환경을 수동으로 준비하던 ZIP 후보였다. 당시 수신 절차, 고정 해시, 캔버스 시간 초과와 재시도 근거는 [RC1 수신 인계](../07_검증/310_공개_검증후보_배포와_독립수신_인계.md), [RC2 수신 검증](../07_검증/414_알원_두번째_후보_배포와_수신_검증.md)에 있다. 내부 ZIP의 새 경로 수신은 [내부 묶음 검수 도구](../../Code/tools/verify_windows_internal_bundle.py)로 재현한다.
