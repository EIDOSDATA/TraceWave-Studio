# Windows 내부 검증 배포

2026-11-23 KST. 계획 13번의 Windows 11 x64 내부 검증 묶음을 생성하고 새 폴더에 설치하는 절차다. 사용자의 기존 작업 영역은 그대로 두고 별도 작업 폴더를 선택한다. 배포 묶음에 제품 GUI와 Python 서비스 소스, 재현용 소스 및 실행에 필요한 native DLL을 함께 둔다. 원문 참고자료, 설치된 Python 또는 사용자 프로젝트, 제조사 카탈로그 원본, WSL 배포판과 운영체제 글꼴은 별도로 유지한다.

공개 후보 `r1-rc1`의 제품 개정은 `71c601679a08cc881ffb7e8b4302e8141d253f00`이다. 개발 PC에서 새 경로로 수신해 편집, 저장과 재열기를 확인했다. 별도 클린 Windows/WSL2 PC의 독립 검수는 인터넷에 연결한 상태로 진행한다. 내부 ZIP `e28a9827b95502d657f510f0b8d1644167ae31d5`에서 확인한 선택 CAD/도면/복소 계산과 WSL2 연결은 해당 시험 기록에 있다. [공개 후보와 해시](../07_검증/310_공개_검증후보_배포와_독립수신_인계.md), [이전 내부 후보](../07_검증/300_윈도우_알원_내부후보_재현과_수신.md)

## 수신과 실행

현재 다운로드용 ZIP과 SHA-256은 [GitHub 프리릴리스](https://github.com/EIDOSDATA/TraceWave-Studio/releases/tag/r1-rc1)에 있다. 고정 소스와 실행 기록은 [공개 후보 수신 인계](../07_검증/310_공개_검증후보_배포와_독립수신_인계.md)에 있다.

1. 전달받은 ZIP의 SHA256을 함께 받은 실행 기록과 대조한다. 새 폴더에 압축을 푼다.
2. Windows 11 x64에서 CPython 3.12 x64를 준비한다. 압축을 푼 Code 폴더에서 아래를 실행한다.
3. Studio에서 새 작업 영역을 만들고 저장한다. 프로젝트를 다시 열 때 파일 메뉴의 기존 프로젝트 열기를 사용한다. CAD/STEP/해석 작업은 해당 worker 환경을 연결한 뒤 실행한다.

```powershell
py -3.12 -m venv .venv
./tools/launch_gui.ps1 -Python .venv/Scripts/python.exe -Workspace .local/내부검증 -NoCatalog
```

압축 풀기와 가상환경 준비는 사용자 권한으로 실행한다. 편집·저장·보존된 JSON 결과의 기본 조회는 GUI와 Python 서비스를 사용한다. STEP, 도면, 복소 네트워크 계산/필드와 WSL 해석의 외부 고정 환경은 기능별로 준비한다. [Windows Python](01_파이썬_개발환경.md), [WSL 환경](02_리눅스하위시스템_개발환경.md), [개발 실행 안내](../../Code/README.md)

## 별도 클린 Windows/WSL2 PC 온라인 검수

1. 기존 TraceWave Studio 설치와 작업 데이터에 의존하지 않는 별도 Windows 11 x64 PC에서 인터넷에 연결한 상태로 GitHub 프리릴리스 ZIP과 SHA-256 파일을 내려받는다. ZIP의 해시를 대조하고 CPython 3.12 x64를 설치한다. [공개 후보](https://github.com/EIDOSDATA/TraceWave-Studio/releases/tag/r1-rc1), [Windows Python 환경](01_파이썬_개발환경.md)
2. 고정 WinLibs ZIP을 내려받고, 후보 `bundle-manifest.json`의 `external_compiler_runtime`에 지정된 DLL 세 파일을 확인한다. 후보 ZIP의 `Code` 폴더에서 다음 검수 도구를 실행한다. 도구는 DLL의 SHA-256을 대조하고 새 수신 폴더에서 기본 편집, 저장과 재열기를 검수한다. [고정 WinLibs 릴리스](https://github.com/brechtsanders/winlibs_mingw/releases/tag/16.1.0mcf-14.0.0-ucrt-r1)

   ```powershell
   $bundle = 'C:/수신/TraceWave-Studio-R1-rc1-windows-x64.zip'
   $compilerBin = 'C:/수신/winlibs/mingw64/bin'
   py -3.12 ./tools/verify_windows_internal_bundle.py $bundle C:/수신/독립검수 --compiler-bin $compilerBin
   ```

3. 새 수신본의 `독립검수/실제 배포 수신본/Code`에서 같은 후보의 `runtime_profiles`로 서비스와 검수 대상 worker의 고정 의존성을 온라인 설치한다. 도면이나 보고서 출력이 필요한 경로에는 해당 worker를 구성한다. WSL2의 전용 배포와 openEMS는 설치 후 native 감사를 완료한다. [WSL2 환경](02_리눅스하위시스템_개발환경.md), [고정 openEMS 구성](03_리눅스_개발환경.md)

   ```powershell
   $traceWavePython = py -3.12 -c 'import sys; print(sys.executable)'
   ./tools/setup_python.ps1 -Python $traceWavePython -SkipCad
   ./tools/setup_exchange.ps1 -Python $traceWavePython
   ./tools/launch_gui.ps1 -Python .venv/Scripts/python.exe -Workspace .local/독립검수 -NoCatalog -OpenEmsWsl
   ```

   STEP 검수를 함께 진행하는 경우 `setup_python.ps1`에서 `-SkipCad`를 생략한다. 복소 네트워크 환경을 검수할 때는 같은 후보의 `runtime_profiles/python-network-windows-x64.txt`를 사용해 별도 가상환경에 `pip install --only-binary=:all: --require-hashes -r`로 설치하고 `pip check`를 실행한다.

4. 인터넷에 연결한 상태에서 예제를 열고 편집한 뒤 저장하고 새 세션에서 열어 값을 확인한다. 로컬 WSL2 해석 완료와 별도 실행의 취소, 이전 결과와 출처 재열기, 도면 또는 보고서 출력, 정상 저장본 복구를 확인한다.
5. 후보 커밋과 ZIP SHA-256, 실제 Windows/WSL2 및 의존 버전, 예제, 실행 결과와 출력 위치를 기록한다. 실패 경로는 재현 방법과 원인을 남긴다. [독립 수신 인계](../07_검증/310_공개_검증후보_배포와_독립수신_인계.md)

## 묶음 생성과 검증

소스는 지정한 Git 커밋의 Code 추적 파일과 이 운영 안내에서 가져온다. 개발 중 변경, 생성 캐시, 팀 저장 데이터 및 참고자료는 소스 선택 대상에서 제외한다. 별도로 공급한 실제 Windows Release 실행 파일, PE import에서 확인한 DLL과 상류 고지의 바이트를 검사한다. 현재 profile은 WinLibs GCC 16.1.0 UCRT MCF의 3개 DLL을 고정한다. [WinLibs 고정 릴리스](https://github.com/brechtsanders/winlibs_mingw/releases/tag/16.1.0mcf-14.0.0-ucrt-r1)

고지 원문과 DLL hash는 [고정 의존 정의](../../Code/runtime_profiles/windows-internal-bundle-x64.json)에 있다. 개발용 wxWidgets 원본 아카이브의 SHA256을 확인한 뒤 포함 컴포넌트의 고지 원문을 읽는다. GCC/MinGW, nlohmann/json 및 MCF의 상류 고지를 ZIP의 third-party-notices 폴더에 둔다. MCF DLL에서 읽은 2.3.ga 표기와 상류 GA 고지는 기록했으며 공급 빌드의 정확한 source commit 연결은 미정이다. [wxWidgets 원본](https://github.com/wxWidgets/wxWidgets/releases/tag/v3.2.12), [GCC 런타임 고지](https://github.com/gcc-mirror/gcc/blob/releases/gcc-16.1.0/COPYING.RUNTIME), [MCF 상류 고지](https://github.com/lhmouse/mcfgthread/blob/v2.3-ga.2/LICENSE.TXT)

아래 명령은 위 내부 후보를 재현할 때 사용한다. Code 작업 위치에서 해당 개정의 Release GUI, DLL, 고지 원문과 CPython을 준비한다.

```powershell
$profile = Get-Content runtime_profiles/windows-internal-bundle-x64.json -Raw | ConvertFrom-Json
$notices = (New-Item -ItemType Directory -Path .local/release-notices -Force).FullName
foreach ($notice in $profile.external_notices.PSObject.Properties)
{
    $target = Join-Path $notices $notice.Name
    if (-not (Test-Path -LiteralPath $target))
    {
        Invoke-WebRequest -Uri $notice.Value.url -OutFile $target
    }
}
.venv/Scripts/python.exe -X utf8 tools/build_internal_bundle.py --source-ref e28a9827b95502d657f510f0b8d1644167ae31d5 --notice-dir $notices --output .local/TraceWave-Studio-internal.zip
.venv/Scripts/python.exe -X utf8 tools/build_internal_bundle.py --verify .local/TraceWave-Studio-internal.zip
```

내부 검증 담당자는 묶음 시험 도구로 새 한글 경로와 기본 Python에서 편집, 저장, 서비스 재열기를 확인할 수 있다.

```powershell
.venv/Scripts/python.exe -X utf8 tools/verify_windows_internal_bundle.py .local/TraceWave-Studio-internal.zip .local/새수신_검증
```

묶음의 manifest는 추적 소스 커밋, 제품 EXE/DLL과 고지 파일의 상대 경로, 길이 및 SHA256을 기록한다. 동일 커밋과 입력 파일, 압축 라이브러리 조합으로 만든 ZIP은 동일 바이트를 목표로 한다. 새 컴파일의 EXE 바이트 재현성과 ZIP 자체의 발행자 서명은 별도다. 내부 검증 ZIP을 대상으로 하며 전체 R1 수용과 외부 배포 권리는 별도 검수 항목이다.
