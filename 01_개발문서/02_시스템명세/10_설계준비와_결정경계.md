## 구현할 때 유지할 구체적 계약

### 결과와 가져오기

가져온 파일은 바이트/hash/파일명/형식/읽기 profile과 측정 문맥을 artifact로 보존한다. 파싱 후보는 읽기 전용이며 검토 후 프로젝트 참조를 한 명령으로 추가한다. 실패하면 기존 자료와 비교 집합을 유지한다. 큰 배열은 프로젝트 JSON에 넣지 않는다. `DatasetDescriptor`의 shape/dtype/units/axis/port order/Z0/phasor/reference plane/mask가 없는 자료를 비교 가능한 복소 네트워크로 승격하지 않는다.

지원 파서 profile에서 주파수 단위, 복소 표현, 포트 순서, 중복/비단조 표본과 누락을 검증한다. CSV의 열/단위/실수-허수 또는 크기-위상 대응은 사용자가 검토한다. 미지 구문은 조용히 버리지 않고 해당 profile의 미지원으로 거절한다. profile별 유한 파일/행/포트/표본 예산을 구현 전에 공개 계약에 고정하고 경계 시험을 함께 둔다. 입력 파일에는 해당 파서의 상한을 적용한다. 프로젝트 개정의 24 MiB 저장 한도와 512 KiB 인라인 전송 한도는 [공통 자원 계약](08_공통구현_계약.md)을 따른다.

주파수 정렬, 보간, Z0/기준면 변환은 근거와 가정이 있는 파생 연산이다. 원본을 수정하지 않으며 변환 chain/version/input hash와 유효 구간을 남긴다. 지원하지 않는 기준면 변환은 차단한다. 기본 외부 RLC는 EM 영역 밖 회로와 모델 내부 소자를 구분한다. 회로 변경 시 기존 raw EM의 재사용 가능 여부는 서비스가 실제 의존성으로 판정한다.

목표 평가는 특정 목표 개정/metric version/표본 구간/조건을 참조하는 별도 Assessment다. 데이터가 없거나 목표 영역을 덮지 못하면 `not_evaluated` 또는 명시 조건부 상태다. 목표 수정은 원시 결과를 덮지 않고 재평가한다. 지표 수식과 부호/단위는 승인 09 및 공통 계약이 소유한다.

### 연구와 비교

연구는 고정 base snapshot, 변수/단위/범위/명시 후보, 전체 후보 수, 예산/실패 정책으로 생성한다. 전수 후보 수를 산출해 사용자가 검토하기 전 실행하지 않는다. 실행 순서와 별개인 후보 ID, 후보 patch/snapshot/plan/run을 보존한다. 부분 실패는 해당 후보 상태이며 완료 후보를 지우지 않는다. 예산 초과는 실행 전 거절하거나 명시적으로 중단하며 무한 자동 재시도하지 않는다.

재개는 이전 source/runtime/input identity와 봉인 artifact를 확인한 명시적 명령이다. 현재 완료 단계 재사용과 향후 worker checkpoint 재개를 구분한다. 취소 요청은 실제 프로세스 종료가 확인된 뒤에만 완료 상태가 된다. 비교 자료는 원래 실행/목표/조건/유효 구간을 항상 열 수 있어야 한다.

### 출력, 복구와 전달

미리보기 -> 생성 -> 파일 검사 -> 지원 profile 검수의 상태를 분리한다. 원본 객체/net/layer와 출력 객체의 매핑을 manifest에 둔다. 제한으로 생략한 형상/물성/메타데이터를 숨기지 않는다. 독립 검수는 다른 reader/수신 도구와 그 버전, 비교 항목/허용 오차를 기록한다. 같은 OCCT 재입력을 독립 검수로 대체하지 않는다.

프로젝트 archive는 참조 closure와 hash를 검사하고 별도 위치에서 복원해 CAD/solver 원래 runtime 없이도 보존 자료를 읽는 범위를 확인한다. 원본 경로만 복사한 ZIP을 독립 전달 패키지로 표시하지 않는다. 복구 후보 선택은 원본 정상본과 차이를 보인 뒤 새 명령/작업 사본으로 진행하며 손상 자료를 정상본 위에 자동 덮어쓰지 않는다.

### 문서 상태와 외부 의존성

이 표의 계약은 지원하는 구현과 검증 범위를 읽기 위한 기준이다. 공개 필드, 등록 기능, 파서의 수치 상한과 수신 도구는 각 구현 계약에서 확인한다. 다음 실행과 환경 보류 항목은 [현행 버전의 남은 작업](../09_개발계획/04_현행버전_남은작업.md), 개별 파일은 [문서 분류](../10_문서목록/README.md)에서 찾는다.

Linux GUI/R2/R3 및 PCB 평면 패턴 밖의 3차원 안테나는 장기 범위다. 장기 3D RF는 원본 solid/wire/surface 표현, 공간 급전/기준면/재료/격자/독립 참조를 별도 지원 profile로 설계한다. 현재 STEP 표시가 그 해석 지원을 의미하지 않는다.
