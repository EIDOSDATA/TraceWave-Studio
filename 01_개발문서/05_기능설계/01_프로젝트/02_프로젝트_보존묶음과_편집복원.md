# 프로젝트 보존 묶음과 편집 복원

완료 계획 12번의 편집 복원 프로파일은 `rfad.project-archive/0.1`이다. CLI에서 내보내기와 복원을 검토·적용한다. Windows Studio의 파일 메뉴에서도 받은 ZIP의 검토, 복원, 새 프로젝트 열기를 수행한다. [읽기 전용 인계](../05_출력교환/06_고정설계_보고서와_인계.md)는 별도 프로파일이다.

## 보존과 누락

- 현재와 저장 개정의 정확한 정규 바이트, 작업 영역에 등록된 전체 개정, 스냅샷, 실행 취소/다시 실행, 명령 원문을 복제한다. 증거에서 이미 빠진 상위 개정은 누락 목록에 표시한다. 새 ID나 수정한 부모를 채우지 않는다.
- 원문 포함을 명시하면 복소 라이브러리, PCB 수입, 측정 기록 및 첨부, 등록한 계산 출처에서 소유 프로젝트에 속하는 봉인 참조를 복제한다. 선택하지 않았거나 원본 저장소에 없거나 외부 저장에 남긴 파일은 원래 경로/해시와 사유를 색인에 보존한다. 미지 확장의 문서 바이트와 출처는 유지한다.
- 작업 큐, 전송 세션, 요청 영수증, 외부 worker 결과/실행 환경과 다른 프로젝트의 자료는 복원 범위 밖이다. 새 작업 영역에서 프로젝트를 열어도 계산이 자동으로 시작되지 않는다. 제작/RF/실측 합격은 기존 상태와 범위를 따른다.
- ZIP은 8 MiB, 파일 최대 512개, 복원 색인은 4 MiB, 작업 영역의 복원 기록은 최대 32개다. 프로젝트 단일 문서 512 KiB와 기존 journal/명령/스냅샷 상한을 유지한다.

## CLI에서 검토하고 적용하기

CLI와 Studio는 같은 작업 영역을 동시에 쓰지 않는다. 기존 소스 프로젝트의 ID와 현재 개정을 알아야 하며, 목적지는 원본과 다른 작업 영역을 선택한다. 공유 권한을 확인한 등록 원문을 복제할 때는 내보내기 검토와 적용 모두에 `--include-sources`를 사용한다.

| 명령 | 입력 |
| --- | --- |
| `rfad archive review-export` | `--workspace`, `--project`, `--revision` 및 원문 포함 선택 |
| `rfad archive export` | 같은 입력, 검토 결과 `--review-hash`, 저장할 작업 영역 밖 새 `--file` |
| `rfad archive review-restore` | 받는 쪽 `--workspace`, 받은 `.rfad.zip`의 `--file` |
| `rfad archive restore` | 같은 위치/파일과 복원 검토의 `--review-hash` |

`python -m rfad archive --help`에서 명령과 옵션을 확인한다. 복원 검토는 ZIP 전체와 소유권, 현재/저장 개정 및 참조 폐쇄를 확인하고 작업 영역 경로도 해시에 고정한다. 같은 프로젝트 ID나 경로의 기존 파일을 덮어쓰지 않는다. 저장 공간과 범위 검사 뒤 각 원문을 봉인하고 검증된 상태만 한 번에 등록한다. 디스크 오류로 중단됐으면 같은 묶음과 검토 위치를 다시 사용한다. 이전에 등록이 완료됐다면 같은 영수증을 확인한다.

등록 후에는 Studio에서 대상 작업 영역을 사용해 `projects/<원래 프로젝트 폴더명>`을 연다. 새 편집은 대상 작업 영역에만 기록한다. 실제 Windows 저장/재열기는 [복원 검증](../../07_검증/31_프로젝트_편집복원_검증.md)을 따른다. ## Windows Studio 수신 경계

[복원 화면](../../04_화면설계/28_보존묶음_복원_화면.md)에서 선택한 파일은 한 번에 128 KiB씩 현재 작업 영역의 서비스에 전송한다. 전송은 단일 파일로 제한되며 서비스는 파일 경로를 받지 않는다. 전체 SHA256과 검토 hash가 일치해야 예약과 등록을 접수한다. 각 접수는 기존 request key/epoch의 영속 영수증을 쓴다. 임시 전송은 앱을 종료하거나 전송을 닫으면 해제되며, 등록 중 끊긴 경우에 같은 바이트의 등록 여부를 저장소에서 확인한다.

`archive.receive.review`의 누락 목록은 앞 16개를 표시한다. 전체는 묶음 색인에 있다. Studio에서의 복원과 등록 후 편집을 [수신 실행 검증](../../07_검증/33_스튜디오_보존묶음복원_검증.md)에 남긴다. 편집용 ZIP 발행은 현재 CLI가 담당한다.
