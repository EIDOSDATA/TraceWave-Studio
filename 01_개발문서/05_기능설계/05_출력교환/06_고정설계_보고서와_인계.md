# 고정 설계 보고서와 인계

완료 계획 12번의 보고서 및 읽기 전용 인계 프로파일은 `rfad.project-handoff/0.1`이다. Windows Studio의 [보고서와 인계 화면](../../04_화면설계/27_보고서와_인계_화면.md)과 같은 서비스를 사용한다.

## 입력과 근거

- `evidence.query`는 프로젝트 ID와 명시 스냅샷 ID 및 그 내용 hash를 받는다. 종류와 근거 ID에 대한 필터 및 offset/limit를 지원한다. 현재 편집본이나 최신 계산으로 자동 대체하지 않는다. 페이지 최대 32개, 명시 근거 선택 최대 64개, 공개 응답 최대 256 KiB다.
- 재료 모델, 가정, 적용 범위와 출처, 목표, 복소 결과와 저장된 판정, 측정 원문 및 기록 개정은 해당 설계에서 조회한다. 보존 해석, RF 검증과 완료 출력은 같은 스냅샷에서 실행한 기록에 한한다. 자료 등록, 파일 복사, 물리 판정의 상태를 각각 유지한다.
- `package.preview`는 고정 설계, JSON/Markdown 보고서와 선택 파일의 목록, 바이트 수와 기록 해시를 반환한다. 모든 근거를 보고서에 기록한다. 선택 파일 모드는 공유 권한 확인과 근거 ID를 요구한다. 소유 프로젝트 밖에 저장된 파일은 등록 참조만 남기며, 미포함은 `copy_state`에서 확인한다.

## 발행과 수령

| 호출 | 동작 |
| --- | --- |
| `package.build` | 원래 검토 hash를 일치시킨 뒤 파일의 길이와 SHA256을 읽어 ZIP을 완성하고 다시 검증한다. 같은 입력과 적용 키는 기존 접수 결과를 반환한다. |
| `package.receipt` | 같은 프로젝트에 보존된 원래 요청 키와 epoch의 결과를 확인한다. 영수증을 확인할 수 없으면 새 생성의 근거로 사용하지 않는다. |
| `package.list` | 현재 프로젝트가 발행한 파일 식별자와 크기 및 SHA256을 조회한다. |
| `package.read` | 명시 파일 ID와 발행 SHA256으로 고정 offset의 128 KiB 청크를 읽는다. |

ZIP에는 `manifest.json`, `project-index.json`, `report.json`, `report.md`, `workspace/<프로젝트 경로>/...`의 검토된 사본을 넣는다. manifest는 파일별 바이트 수와 SHA256을 기록한다. 소유 경로, 중복 이름과 파일/폴더 충돌, 역슬래시와 부모 이동, Windows 예약 이름, 링크/장치/압축 항목을 검사한다. 스냅샷 파일의 SHA256과 스냅샷 내용 hash는 각각 원래 계약으로 대조한다. 아카이브 검증은 파일을 풀기 전에 완료한다.

제품 발행은 ZIP 8 MiB, 작업 영역 32묶음이다. 파일을 넘기기 전 GUI에서 전체 청크와 발행 SHA256을 대조하고, 작업 영역 밖 새 이름에 게시한다. 기존 파일이나 원본 경로는 보존한다. 보고서는 물성, 제작, 환경과 측정의 미정값을 고정 설계와 함께 전달한다.

`active_restore_supported=false`는 수령인의 범위를 나타낸다. 이 버전에서 수령하는 것은 검토용 데이터다. 편집 가능한 프로젝트 등록은 [별도 CLI 복원 프로파일](../01_프로젝트/02_프로젝트_보존묶음과_편집복원.md)에서 수행한다. 외부 작업 이력, 자료 재확보, PDF 보고서 및 요구-시험 추적 통합은 남아 있다. 원본을 공유할 권한은 자료를 고르는 사용자가 확인한다. 기존 물리 수용 증거의 상태는 그대로 유지한다.
