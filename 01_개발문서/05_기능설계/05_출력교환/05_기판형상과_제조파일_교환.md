# 기판 형상과 제조 파일 교환 계약

현행 편집본: 2026-11-17 KST. 완료 계획 10번 중 구현한 PCB 기계 형상과 KiCad/Gerber/XNC/Job 교환의 유한 범위를 정의한다. 실행별 확인과 미확립 범위는 [검증 기록](../../07_검증/25_기판교환과_원문수입_검증.md)에 구분한다. 승인 RFAD-D0-3.4, 원래 출처와 과거 실행 기록은 변경하지 않는다.

상위 설계는 [출력 상세 설계](01_도면과_제조_파일_출력.md), 기존 도면과 별도 재검수는 [연관 도면 계약](04_연관도면과_출력재검수.md)을 따른다. 같은 실행에서 실제로 확인한 범위만 검증 기록으로 연결한다. 제조 적합성, EM 지원, 파일 재입력과 수신 도구 검사를 구분한다.

## 1. 원본 모델과 기존 파일 호환

`rfad.project/0.6`은 선택적인 `pcb` 객체와 `board.cutouts`를 추가한다. 0.1~0.5 파일을 조회한다는 이유만으로 필드를 만들거나 기존 개정을 다시 저장하지 않는다. 첫 PCB 명령은 새 필드를 만들 수 있으며 undo는 원래 필드 부재까지 복원한다.

| 원본 | 용도와 분리 원칙 |
| --- | --- |
| `board.cutouts` | 명시한 내부 절삭. 외곽은 사각형/원형/직선 다각형 |
| `pcb.holes` | 완성 홀/슬롯, 도금 상태, 실제 공구 지름, 선택한 표면층 절삭 |
| `pcb.footprints` | 이름/참조명/값/라이브러리 출처, 배치 기준점, 소유 객체와 핀 대응 |
| `pcb.artwork_layers` | 면별 마스크/페이스트 제조 이미지. 사용/사용 안 함/미정 구분 |
| `pcb.apertures` | 명시 형상 또는 패드 기반 여유값/비율로 정의한 개구 |
| `pcb.keepouts` | 명시 평면 영역과 대상 층, 금지 대상 종류 |
| `pcb.imports` | 불변 원문 파일, parser 보고서, 원문 객체와 현재 객체의 대응 |

모든 새 객체는 안정 UUID와 사람이 읽는 이름을 별도로 가진다. 도체의 기존 `material_ref`, `source_ref`, net, Quantity의 `source_refs/status`, 제조/측정 조건은 유지한다. 제조 이미지 층은 물리 마스크 재료/두께와 동일한 객체가 아니며 `physical_surface_id`로 명시 연결했을 때만 관계가 생긴다.

구멍은 원형 또는 회전한 capsule이다. capsule의 `finished_length`는 끝의 반원을 포함한 완성 전체 길이이며 중심선 길이는 `finished_length - finished_width`다. 실제 공구 지름과 완성 지름/폭, 도금 두께는 서로 다른 입력이다. 자료 없는 공구나 도금 두께를 계산값으로 채우지 않는다.

풋프린트 소유 도체/개구/홀은 프로젝트 world 좌표를 권위 원본으로 사용한다. 배치 변경은 기존 배치의 역변환과 새 배치를 한 번 적용한다. 하면 미러는 한 번만 적용하고 상대 면의 실제 층을 명시 대응한다. 매개변수에 연결된 위치를 묵시 리터럴로 바꾸지 않는다. 소유 해제는 현재 world 형상을 유지하고 소유 관계만 해제한다.

## 2. CAD, 도면, DRC와 EM 경계

CAD는 실제 기판/도체/유전체에서 명시 홀과 내부 절삭을 제거한다. 도금 배럴의 바깥쪽 제거 형상은 완성 홀에 명시 도금 두께를 더한 기하이며, 이것을 실제 드릴 공구값으로 저장하지 않는다. 도금 배럴은 별도 고체이고 명시 패드/net/material 및 접촉을 확인한다. 표면층은 `surface_cut_ids`에 있는 객체만 완성 홀 형상으로 절삭한다. 명시하지 않은 물리 표면층을 자동 관통시키지 않는다.

경계에 닿는 절삭, 서로 중첩된 홀/절삭, 미정 도금 상태, 허용 범위 밖의 치수 또는 실제 접촉 조건 부족은 명시 오류다. 현재 기계 홀은 기본 적층 전체 관통 범위이며 blind/buried hole을 추정하지 않는다. 임의 자동 치유로 원본 치수를 변경하지 않는다.

PDF/SVG/DXF에서는 해석형 선/원호 경계의 Boolean 차집합을 사용한다. 절삭으로 한 객체가 둘 이상의 도체 섬으로 나뉘면 각 외곽을 보존한다. DXF HATCH의 외곽/구멍 플래그는 실제 포함 깊이에 맞춘다. 동일 원/선의 겹침과 판정 불명 접선은 지원 범위 밖으로 거절한다. 기본 비아 bore가 다른 도체 경계를 부분 절단하는 옛 경로의 제한은 별도로 유지한다.

DRC는 절삭 후 실제 경계로 거리/단락을 검사한다. 현재 연결 그래프의 한 객체가 여러 도체 섬으로 나뉘면 이를 한 연결로 합격시키지 않고 `not_evaluated`로 표시한다. 새 도금 홀/슬롯의 수직 연결은 CAD 접촉 검사와 객체 단위 DRC의 평가 범위를 구분한다.

새 기계 절삭을 가진 프로젝트는 현재 PCB openEMS profile에서 지원하지 않는다는 진단으로 차단한다. CAD 출력이 성공했다는 이유로 EM에서 홀을 무시한 해석을 실행하지 않는다. 기존 미확립 RO4350B 개별 손실과 GHz PTH 정확도의 상태를 바꾸지 않는다.

## 3. 출력과 미리보기

기존 `snapshot.create`, `export.context/preview/build/list/get/verify/receipt`를 재사용한다. 형식별 새 profile은 다음과 같다.

| profile | format | 명시 options |
| --- | --- | --- |
| `rfad.exchange.kicad-board/0.1` | `kicad_pcb` | 빈 객체 |
| `rfad.exchange.kicad-footprint/0.1` | `kicad_mod` | `footprint_id` |
| `rfad.exchange.cam/0.1` | `gerber_job` | `layer_ids` |

KiCad profile은 실제 2~32개의 짝수 도체층을 요구한다. 단면 설계에 없는 하면 동박을 발명하여 호환 파일로 표시하지 않는다. 실제 Z 상부가 F.Cu, 하부가 B.Cu이며 중간 도체는 순서대로 대응한다. 원본의 아래/위 보기와 KiCad 파일의 Y 방향 변환을 혼동하지 않는다.

CAM 패키지는 모든 명시 도체층과 사용 중인 마스크/페이스트 층, 기판 외곽, 존재하는 도금/비도금 drill 및 Job을 함께 생성한다. 선택한 일부 층만 출력한 파일을 완전한 Job으로 표시하지 않는다. 미정/사용 안 함 제조층은 누락 이유와 원문 상태를 sidecar에 남긴다.

GUI의 `view_layer_id`는 표시 전용이고 `export.preview`만 받는다. 실제 옵션과 snapshot이 같으면 표시 층 변경은 검토 hash를 바꾸지 않는다. `export.build`에 표시 전용 필드를 보내면 거절한다. 서비스가 제공하는 실제 원본 층/대상 파일명/역할/면/포함 상태를 표에 표시하며 GUI에서 다시 단위를 환산하거나 파일 대응을 계산하지 않는다.

KiCad 보드에는 수신 도구가 파일을 다시 채우는 데 필요한 기술 설정 파일을 동반한다. 수신 프로그램의 내부 기본값과 오차 설정은 원본 제조 규칙/물성으로 채택하지 않는다. 초기 표시 cache의 곡선 근사와 KiCad 재채움 후 경계 비교를 별도로 검사한다. 현재 파일 profile의 비교 한계는 실제 제조 공차가 아니다.

패키지의 sidecar는 전체 원본 의미 정보, 입력 snapshot, 객체/net/층 이름, 미정값과 옵션을 보존한다. 출력 파일은 해당 profile로 표현 가능한 의미만 가진다. 원문과 sidecar를 무시한 다른 도구가 RF 재료/목표/포트 의미를 재현했다고 주장하지 않는다.

## 4. 가져오기와 한 번의 적용

원문 수입은 현재 설계에 직접 파일 경로를 실행하거나 자동으로 새 층/넷/기판을 만드는 작업이 아니다. 원문 업로드, 별도 parser, 명시 대응, 후보 검토, 한 번의 적용을 분리한다.

| API | 상태와 입력 |
| --- | --- |
| `pcb.import.context` | 현재 기판/좌표계/층/넷과 과거 전송 목록, 환경 및 한도 |
| `pcb.import.begin` | format과 원래 파일명/bytes/SHA256을 선언하고 `upload_id` 발급 |
| `pcb.import.chunk` | 파일명과 정확한 offset, 최대 256 KiB의 base64 원시 바이트 |
| `pcb.import.parse` | 전송 완료와 전체 hash 확인 후 불변 원문 봉인, 별도 출력 슬롯 TaskRef |
| `pcb.import.get` | 권위 전송 진행, parser 상태/보고서/원문 참조. 실행 환경 없이 조회 가능 |
| `pcb.import.preview` | 고정 parser 결과, 현재 개정, 명시 층/net/배치 대응과 손실 확인으로 후보 생성 |
| `pcb.import.apply` | 같은 입력과 검토 hash, command ID로 한 개 원자 명령 적용 |
| `pcb.import.receipt` | 불명 요청의 기존 key/epoch 조회. 미발견을 미접수로 추정하지 않음 |
| `pcb.import.abandon` | 전송 중 작업을 명시 폐기 상태로 변경. 원문 청크는 삭제하지 않음 |

일반 형식은 `kicad_pcb/kicad_mod/gerber_job/gerber_x2/xnc`다. 같은 전송·검토·적용에 공식 바이트를 대조하는 [제조사 안테나 라이브러리](07_제조사_안테나_라이브러리.md)도 연결한다. 파일명은 단일 원래 이름을 보존하며 경로, 디렉터리 탈출, 대소문자 별칭 중복과 Windows 장치명은 거절한다. Job의 외부 파일 참조나 자동 네트워크 읽기는 허용하지 않는다.

`mapping`은 `board_id`, `frame_id`, `layers`, `nets`, `placement`를 가진다. 층과 넷은 `source/target` 쌍이다. KiCad net의 source는 원문 코드 문자열이고 CAM은 원문 net명이다. 미연결도 명시 null 대응을 요구한다. 이름이 같다는 이유만으로 연결을 선택하지 않는다. 단독 풋프린트의 명시 배치 외에는 파일의 world 좌표를 자동 이동하지 않는다.

기판 파일은 원문 외곽과 기존 기판을 대조한다. 적층과 물성은 기존 원본을 유지하며 수신 파일의 기본 FR4, 유전율, 손실값을 확정 조건으로 채택하지 않는다. 기록되지 않은 도금 두께/실제 공구는 미정으로 보존한다. 원문의 unsupported token 등은 원문 보존과 별도로 손실 목록에 남기고 각 항목을 확인해야 적용할 수 있다. XNC의 명시 소수 절대 좌표 G85 슬롯을 읽고, 도금 분류와 원본 객체 태그 및 Gerber 동박의 넷 속성 누락을 해당 파일의 검토에 표시한다. 남아 있는 원본 태그를 파일 내 순번과 함께 대응 기록에 연결한다. [NC 슬롯과 원본 대응 검증](../../07_검증/296_엔씨_슬롯과_원본_대응_검증.md)

지원하지 않는 임의 곡선 Gerber region, clear polarity 합성 또는 편집 모델로 정확히 표현하지 못하는 기하는 원문을 보존하고 적용을 차단한다. 읽지 못한 형상을 근사 다각형으로 대체하거나 생략한 채 재현 완료로 표시하지 않는다. 자체 출력의 모든 가능한 파일이 현재 편집 수입의 지원 범위라는 뜻은 아니다.

적용 결과에는 원문 ArtifactRef, parser 보고서, parser runtime hash와 객체별 출처가 남는다. undo/redo는 보존된 역명령을 사용하며 파일을 다시 읽거나 parser를 다시 실행하지 않는다. 이미 적용한 동일 전송을 새 키로 다시 적용하지 않는다. 되돌린 적용은 redo로 복원한다.

## 5. 유한 자원과 복구

| 항목 | 한도 |
| --- | --- |
| 새 기계 홀 / 풋프린트 / 제조 이미지 층 / 개구 | 64 / 32 / 4 / 128 |
| 출력 입력 / 파일 / 전체 패키지 | 1 MiB / 16 MiB / 64 MiB |
| 도면 출력 파일 / PCB 출력 파일 | 기존 35 / 최대 43, manifest 포함 |
| 수입 원문 파일 / 원문+parser 보고서 | 40개 / 합계 16 MiB |
| 단일 수입 파일 / 청크 | 16 MiB / 256 KiB |
| parser 보고서 / 서비스 응답 | 각 768 KiB |
| 전송 보존 | 프로젝트 16개, 작업영역 64개 |
| 프로젝트 원본 / journal / worker 소스 파일 | 기존 512 KiB / 8 MiB / 192개 |

보고서/페이지/진단이 응답 한도를 넘으면 조용히 자르지 않고 명시 차단한다. 큰 출력 패키지가 더 작은 수입 원문 한도에 들어오지 않을 수 있다. 원문을 삭제해서 한도를 맞추지 않는다.

청크 전송, parser 접수와 적용은 같은 영수증 ledger를 사용한다. 응답 불명 시 원래 요청을 영속 보존하고 권위 영수증을 조회한다. 진행 중 parser의 종료를 확인하지 못한 재시작은 `interrupted`와 자원 잠금을 유지한다. 자동 재실행으로 중복 파일/중복 객체를 만들지 않는다.

## 6. GUI 구현 기준과 확인 항목

시안 51/70/71/72의 PCB/CAM 작업 공간을 기존 Studio 출력 탭과 wxAUI 배치에 연결한다. 큰 메뉴 버튼을 세로로 계속 추가하는 구조를 사용하지 않는다. 세부 설정은 형식별 표/폼, 고정 snapshot, 실제 도면 미리보기, 포함/누락과 검수 결과를 함께 보여준다.

가져오기는 원문 파일, 층/net 대응, 후보/손실 확인, 보존 원문의 네 탭을 사용한다. 전송과 parser 진행, 수정하지 않은 현재 원본, 적용 완료 개정을 구분한다. GUI가 원문 코드를 다시 해석하거나 null을 0으로 표시하지 않는다. 파일명을 전송 선택 이름으로 사용하며 UUID는 상세 식별로 남긴다.

확인할 실제 흐름은 홀/슬롯/개구/풋프린트의 추가와 수정, 선택/F2/이름 변경, 검토 후 원자 적용, undo/redo, 파일 생성과 별도 재읽기, 가져오기 대응과 손실 확인, 저장/재열기다. 같은 빌드의 실제 Windows 창과 서비스 원본을 대조한다. 단위 시험과 GUI 화면 확인을 서로 대체하지 않는다.

## 7. 형식 근거와 검증 상태

- [KiCad PCB S-expression 형식](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/)과 [공통 형식](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/)에서 층/좌표/패드/zone 의미를 확인한다.
- [KiCad CLI](https://docs.kicad.org/10.0/en/cli/cli.html)는 실제 수신 파일 재열기/재채움 검증의 도구 근거다.
- [Ucamco Gerber 2026.05](https://www.ucamco.com/files/downloads/file_en/554/gerber-layer-format-specification-revision-2026-05_en.pdf), [XNC 2021.11](https://www.ucamco.com/files/downloads/file_en/452/xnc-format-specification-revision-2021-11_en.pdf), [Job 2020.08](https://www.ucamco.com/files/downloads/file_en/435/gerber-job-format-specification-revision-2020-08_en.pdf)를 기준으로 유한 읽기/쓰기 profile을 정의한다.
- [ezdxf HATCH 경계](https://ezdxf.readthedocs.io/en/stable/dxfentities/hatch.html)는 여러 외곽과 구멍의 플래그 근거다.

TraceWave parser 재입력은 `passed_profile`이며 `recipient_application_verified=false`, `kernel_independent=false`, `manufacturing_verified=false`, `physics_verified=false`를 유지한다. 실제 KiCad 실행은 별도 실행 기록으로 증명한다. 이 기록을 STEP의 독립 kernel 검수, 제조 전달 승인이나 안테나 실측 정확도로 확대하지 않는다.

## 8. Altium CAM의 비도금 홀 검토 사본

`python -m rfad altium-drill-copy "nonplated.xnc" "altium-review.drl"`로 Studio의 명시 좌표 XNC에서 별도 Altium CAM 검토 사본을 만든다. 입력은 명시 mm, 비도금 원형 홀이다. 좌표는 0 이상 100 mm 미만이며 0.001 mm로 정확히 나타나야 한다. 완성 지름은 0.0001 mm 자릿수로 보존한다. 좌표나 지름의 반올림이 필요하거나 슬롯·도금 홀·도금 미정·inch 형식이면 거절한다.

사본은 새 파일로만 만든다. CLI는 원문과 사본의 SHA256을 출력한다. 원본의 도금 구분, 객체 ID와 기타 속성은 XNC 및 기존 인계 묶음에서 조회한다. 사본의 C 값은 완성 홀 지름을 시각화하는 데 쓰인다. 실제 공구 지름과 제작·측정 조건은 미정으로 유지한다.

Altium CAMtastic에서는 File > Import > Drill에서 사본을 선택하고 Metric, Absolute, Integer 2, Decimal 3, Zero Suppression None을 사용한다. 동박과 외곽은 기존 Gerber를 사용한다. CAM 저장·재열기 후 지름과 좌표를 확인한다. [실제 왕복 검증](../../07_검증/172_알티움_동박외곽과_비도금홀_왕복검증.md)

별도 2.3 G85 시험에서는 도금·비도금 홀과 슬롯의 기하를 재출력했으며, 도금 분류와 객체 ID 복원은 미확립으로 기록했다. 도금 홀·슬롯을 인계할 때는 Studio 원본 XNC를 사용한다. [도금 홀·슬롯 시험](../../07_검증/224_알티움_도금홀과_슬롯_왕복검증.md)
