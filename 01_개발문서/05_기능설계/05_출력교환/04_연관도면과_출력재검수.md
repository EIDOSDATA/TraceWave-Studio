# 연관 도면과 출력 재검수 계약

현행 편집본: 2026-11-17 KST. 완료 계획 10번의 PDF/SVG/DXF와 기존 STEP 출력 흐름을 연결한다. RFAD-D0-3.4의 새 승인본이 아니며 KiCad/CAM 교환과 독립 수신 CAD 검수까지 완료했다는 뜻이 아니다.

이후 0.6 기계 원본과 PCB/CAM 작업의 현재 계약은 [기판 형상과 제조 파일 교환](05_기판형상과_제조파일_교환.md)에 분리한다. 앞선 10a 검증 기록은 당시 실행 범위를 그대로 보존한다.

상위 설계는 [도면과 제조 출력](01_도면과_제조_파일_출력.md), 기존 STEP 형상 범위는 [기계 형상 계약](02_기계형상_입력과_출력계약.md)을 따른다. 원본은 기존 `rfad.project`이며 별도의 도면 숫자를 영구 설계값으로 만들지 않는다.

## 1. 원본과 실행 경계

`snapshot.create`로 고정한 개정, 프로젝트 소유권, snapshot 내용 hash와 실제 artifact bytes를 확인한다. 표현식과 연관 치수의 평가는 서비스가 담당한다. GUI는 서비스가 제공한 종이 mm 배치를 `wxGraphicsContext`로 표시한다. 같은 배치와 원본 기하를 독립 출력 worker가 읽으므로 화면 캡처를 PDF로 변환하는 경로가 아니다.

도면 profile은 `rfad.exchange.drawing/0.1`이다. `--exchange-python`은 서비스 실행자가 선택하는 환경이며 프로젝트 내용으로 실행 파일, worker, 글꼴 또는 모듈 경로를 지정하지 않는다. Qt 없는 CPython 3.12 Windows x64와 hash를 고정한 의존성을 사용한다. `Code/tools/setup_exchange.ps1`과 `Code/runtime_profiles/python-exchange-windows-x64.txt`가 설치 진입점이다.

PDF의 한글은 실행 환경에서 검증한 Malgun Gothic TTF를 부분 포함한다. 글꼴 이름, 실제 경로, bytes, SHA256과 부분 포함 정책을 runtime manifest에 고정하고 작업별 staging 복사본의 봉인을 확인한다. 운영체제 글꼴 자체를 저장소에 재배포하지 않는다. 글꼴이 없거나 바뀌면 출력 오류로 표시하며 빈 글자나 다른 글꼴을 조용히 대체하지 않는다.

각 PDF 문자열을 실제 TTF cmap과 대조하고 글리프가 없는 문자, 현재 profile에서 조판하지 못하는 분해형 한글/방향 제어/결합 제어 문자는 `E_UNSUPPORTED`로 거절한다. 원문을 임의로 정규화하거나 대체하지 않으며 부족한 codepoint, 페이지와 객체를 진단에 남긴다. 별도 PDF reader는 각 표시 객체의 텍스트와 좌표 대응까지 검사한다. 페이지 전체에서 문자열이 검색된다는 사실만으로 다른 위치에 놓인 문자도 합격시키지 않는다.

## 2. 옵션과 용지 배치

| 항목 | 유한 지원 범위 |
| --- | --- |
| 형식 | PDF, SVG, DXF |
| mode | `drawing`, `fabrication_geometry` |
| 용지 | A4/A3, 세로/가로 |
| 축척 | 0.01~100의 명시적 유한값 |
| 뷰 | 1~8개. 명시 층, 외곽, 적층 단면, 명시 bounds의 상세 뷰 |
| 상세 뷰 | 선택 층과 원본 mm 범위, 이름. 자동 최적 정렬로 잘못된 원점을 숨기지 않음 |
| 치수/주석 | 원본 Quantity/표현식의 평가 결과와 이름. 사용자 입력으로 도면 수치만 변경하지 않음 |
| 제작 기하 | SVG/DXF만, 단일 층 또는 외곽, 1:1, 주석/치수 제외 |

실제 외곽, 도체/패드/비아와 층 위치는 기존 CAD projection에서 얻는다. 표시를 위한 과장 높이를 제작 두께에 더하지 않는다. 필수 치수 미정이나 미지원 형상을 조용히 생략하여 성공한 빈 패턴으로 대체하지 않는다. 원래부터 도체 객체가 없는 명시 층의 빈 기하는 이 경우와 구분한다. 미정 물성, 원래 출처와 실물 제작/측정 조건은 sidecar의 전체 원본 의미 정보에 보존한다.

`drawing`은 표제란, 개정, 단위, 축척 및 기준 길이를 갖는 종이 도면이다. PDF 인쇄 프로그램의 '페이지에 맞춤'은 출력 축척 수용에 포함하지 않는다. `fabrication_geometry`는 주석을 실제 패턴으로 포함하지 않는 별도 좌표 파일이며, 이 파일의 생성만으로 제조 전달이 승인되지 않는다.

`notes` 옵션은 하단의 제작/측정 안내를 제어한다. 도면을 식별하는 필수 표제란, 단위, 개정, snapshot과 축척은 이 옵션을 꺼도 유지한다. 연관 수치 목록과 치수선은 `dimensions` 옵션을 따른다.

적층 뷰는 Y 중앙의 실제 X-Z 절단면이다. 도체 객체가 없는 층을 전체 동박으로 채우지 않으며 중공 PTH의 절단면은 배럴 양옆 구간을 구분한다. 기존 비아 bore가 다른 도형 경계를 부분 절단하는 경로와 임의 외부 3D 환경의 2D 투영은 지원하지 않는다. 새 NPTH/slot/cutout은 위 0.6 기계 계약의 해석형 Boolean 범위로 처리한다. 외부 환경 원문은 sidecar에 남는다. 명시되지 않은 feed gap이나 미정 치수를 자동 생성하지 않는다.

## 2.1 파일 표현과 별도 읽기 경로

| 형식 | 표현 및 실제 재입력 검사 |
| --- | --- |
| PDF | mm를 `72/25.4` pt로 변환. ReportLab TTF 부분 포함, 별도 pypdf parser의 페이지/좌표/텍스트/글꼴 검사. 원호는 최대 15도 구간의 cubic이며 표본 반경 오차 `1e-4 mm` 범위를 검사 |
| SVG | physical mm width/height와 viewBox, 명시적인 Y 변환. XML parser로 경로/원호/구멍/단위/clip을 다시 읽음. 글꼴 자체는 미포함 |
| DXF | R2018, `INSUNITS=4`, `MEASUREMENT=1`. 실제 닫힌 HATCH 경계 또는 외곽 LWPOLYLINE bulge, 객체/net/layer XDATA. ezdxf의 분리된 reader 경로로 다시 읽음. 글꼴 자체는 미포함 |

SVG/DXF의 좌표 대조 허용오차는 `1e-6 mm`, PDF는 `1e-4 mm`다. 원호 cubic의 표본 검사와 연속 경계 오차의 수학적 증명을 혼동하지 않는다. writer와 다른 코드 경로로 parser를 실행했더라도 DXF의 동일 ezdxf 라이브러리 사용을 독립 수신 CAD 검수로 표시하지 않는다. PDF는 제작 기하 profile이 아니다.

라이브러리 근거는 [ReportLab의 Unicode/TTF 글꼴](https://docs.reportlab.com/reportlab/userguide/ch3_fonts/), [ezdxf HATCH 경계와 원호 방향](https://ezdxf.readthedocs.io/en/stable/dxfentities/hatch.html)이다. 위 수치 한계와 지원 subset은 TraceWave의 현재 출력 계약이며 실제 제조 공차가 아니다.

## 3. API와 상태

모든 조회는 `rfad.api/2.0`과 `context.project_id`를 사용한다. 기존 `export.preview/build`의 STEP 입력과 TaskRef 계약은 보존한다.

| 요청 | 입력과 결과 |
| --- | --- |
| `export.context` | 현재 개정 및 선택 snapshot의 명칭/층을 구분하여 조회. snapshot 목록은 25개 페이지 |
| `export.preview` | snapshot ID/hash, profile, format, options를 받아 비동기 TaskRef 반환. 완료 시 실제 용지 배치, 진단, `review_hash` |
| `export.build` | 같은 도면 입력에 `review_hash`를 더함. 원본/옵션/runtime이 달라지면 새 검토 필요 |
| `export.list` | 프로젝트에 속한 출력/재검수 작업의 상태와 manifest를 25개씩 조회 |
| `export.get` | 선택 작업의 보존 결과/manifest/오류. 새 계산을 하지 않음 |
| `export.verify` | 완료 출력의 `job_id`, 검토한 `manifest_sha256`. 새 TaskRef와 별도 검수 artifact를 만듦 |
| `export.receipt` | 결과가 불명확한 mutation의 기존 request key/epoch를 조회. 미발견을 미접수로 단정하지 않음 |

접수 후 현재 설계를 편집해도 기존 작업은 고정 snapshot을 사용한다. 목록/미리보기/조회/재검수는 현재 개정, 저장 포인터, undo/redo를 변경하지 않는다. 출력 artifact의 경로는 서비스가 정하며 사용자 입력을 worker 명령줄로 실행하지 않는다.

포함/누락의 표시 이름은 해당 고정 snapshot에서 조회한다. `preview/get`의 표시 DTO에 추가한 label/name/name_state는 원래 id/reason을 유지하며 원본 projection, 검토 hash, sidecar와 과거 manifest를 다시 쓰지 않는다. 현재 편집 화면에서 후속 이름을 바꿔도 과거 출력의 당시 이름을 보여준다.

도면 재검수는 원래 writer runtime과 현재 reader runtime을 별도로 보존한다. 같은 version의 profile 입력을 읽는 현재 reader로 검수할 수 있으며, 소스 변경 사실을 숨기거나 과거 검수 기록을 바꾸지 않는다. 새 reader가 원래 기하와 다르게 해석하면 새 검수 작업의 실패로 남긴다.

작업 상태는 `queued/running/cancel_requested/cancelled/completed/failed/interrupted`를 기존 작업 계약대로 사용한다. 도면 미리보기는 `preview_only`, 생성한 파일과 재검수 패키지는 `generated_unverified`다. 파일별 재입력 비교 결과와 제조/물리 검증을 별도 필드로 보존한다. 파일을 읽었다는 이유로 `manufacturing_verified` 또는 `physics_verified`를 참으로 바꾸지 않는다.

## 4. STEP의 새 프로세스 재검수

기존 STEP 출력의 manifest, snapshot, 원본 의미 정보와 파일 SHA256을 확인한다. 같은 단일 CAD 실행 슬롯에서 새 worker 프로세스를 시작하고 원래 `model.step`, `sidecar.json`, `manifest.json`을 검증된 staging 사본으로 읽는다. 원래 STEP, `validation.json`, sidecar와 원래 완료 작업은 수정하지 않는다.

기대값은 원래 불변 sidecar의 body별 측정값이다. 새 reader는 stable body 이름, 고체 수, 경계/중심/부피, 해당 평면 body의 단면적/두께/구멍과 루프 수를 비교하고 body 중첩 및 명시 비아-패드 접촉을 검사한다. 선형 허용오차는 기존 profile의 `1e-6 mm`, 상대 체적/단면적 허용오차는 `1e-7`이다. 이는 제조 공차가 아니다.

결과에는 원래 작업 ID와 manifest hash, 당시 writer runtime, 현재 reader runtime, 입력 봉인, 개별 비교값 및 미평가 항목을 기록한다. 새 검사는 형상을 재생성하여 '생성 전후 검사'를 반복하지 않으므로 `body_overlap_checked_before_and_after=false`, `body_overlap_checked_after_read=true`로 구분한다.

`OCP STEPCAFControl_Reader`를 새 프로세스에서 실행한 성공은 `passed_same_kernel`, `kernel_independent=false`다. 다른 제품이 같은 OCCT를 사용하는 경우도 독립 kernel의 합격으로 확대하지 않는다. SOLIDWORKS 같은 별도 수신 CAD의 실제 열기/선택/측정 및 자동 치유 여부는 별도의 실행 증거가 필요하다.

재검수 결과는 새 `verification.json`과 manifest로만 게시한다. 최신 3D mesh 선택에는 재검수 작업을 사용하지 않는다. 기존 결과는 CAD runtime이 없는 재열기에서도 조회할 수 있으나 새 STEP 재검수에는 구성된 CAD 환경이 필요하다.

## 5. 유한 자원과 실패 처리

도면 worker는 단일 슬롯이며 입력 1 MiB, 조회 응답 768 KiB, 파일당 16 MiB, 패키지 64 MiB 및 최대 35개 파일로 제한한다. 뷰는 8개, 페이지는 32개를 넘기지 않는다. 넘친 치수, 긴 라벨 또는 원문을 조용히 자르고 성공 처리하지 않는다. host/worker의 실행 소스는 기존 공통 192개 상한과 profile별 byte 상한을 유지한다. 별도로 봉인한 PDF 글꼴은 실행 소스 파일 목록에 포함하지 않는다.

STEP 재검수는 기존 CAD의 파일당 64 MiB, 패키지 128 MiB, 입력 128 KiB와 결과 메타데이터 256 KiB 한도를 유지한다. STEP 파일은 streaming hash/복사를 사용하고 제한된 metadata만 메모리에서 읽는다.

임시 출력이 닫힌 뒤 schema/역할/파일 목록/hash/원본 결합/재입력 결과를 검증하고 manifest를 마지막에 발행한다. 취소가 게시 전에 접수되면 닫힌 파일이 있어도 성공 artifact를 노출하지 않는다. 실패/디스크 부족/출력 초과/종료 불명은 과거 정상 패키지를 덮지 않는다. 종료 불명은 임의로 슬롯을 반환하거나 자동 재실행하지 않는다.

## 6. 완료 계획 10번의 남은 수용

기술 도면과 STEP 재검수의 유한 profile을 KiCad/Gerber/드릴/Job, NPTH/slot/cutout/footprint/paste 전체 모델 또는 제조 납품 합격으로 대체하지 않는다. 각 형식의 실제 단위/좌표/층/net/위상 비교, 지원 수신 도구별 재열기와 원호/IFA 완성 후보의 검수는 [완료 계획](../../09_개발계획/03_개발완료_계획.md)의 같은 10번 안에서 이어간다. 실제 제작 적층, 공구 치수와 도금/급전 실장/측정 자료는 제공받기 전까지 미정으로 보존한다.
