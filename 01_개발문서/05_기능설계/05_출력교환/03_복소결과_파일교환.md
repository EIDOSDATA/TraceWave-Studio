# 복소 결과의 Touchstone, CSV와 HDF5 교환

완료 계획 5번의 파일 교환 계약이다. 5~8포트로 확장한 파일 왕복과 실제 해석 검산은 [여덟 급전 검증](../../07_검증/405_여덟_급전의_실제_복소행렬과_복원검증.md)에 있다. 승인 기준선 RFAD-D0-3.4, [데이터 모델](../../02_시스템명세/03_데이터_모델과_파일_형식.md)과 [설계 준비 경계](../../02_시스템명세/10_설계준비와_결정경계.md)를 따른다. 파일을 읽었다는 사실은 시료/교정/제작 조건이나 실제 측정 정확도 검증이 아니다.

## 1. 원문과 공통 자료

원문 내보내기는 원래 bytes와 안전한 원래 파일명/확장자를 유지한다. Touchstone 1.0의 `.s1p`/`.s2p`처럼 재해석에 필요한 확장자를 `.bin`으로 바꾸지 않는다. 기존 solver 원시 JSON은 `.json`으로 내보내며 파생 결과에는 가져온 원문이 없다는 상태를 유지한다.

서비스가 원본 bytes, SHA256과 사용자가 검토한 입력 대응을 별도 artifact에 보존한다. 파서는 외부 경로를 열거나 원본 파일을 변경하지 않는다. 텍스트 파서의 반환값은 `network`, `port_count`, `source_port_names`, `parser_metadata`다. `network`는 `rfad.network-data/0.1`의 19필드를 가지며 `port_ids`만 빈 목록이다. 서비스가 원래 포트 순서대로 안정 ID를 부여한 뒤 공통 validator를 호출한다.

행렬은 `values_ri[frequency][output_port][input_port][real_or_imag]` 순서다. Z0는 `z0_ohm[frequency][port][real_or_imag]` 또는 null이며, 배열 안의 개별 포트 값도 null을 유지할 수 있다. 주파수의 원문 순서를 바꾸거나 중복 표본을 버리지 않는다. 원시 파일의 `source_sha256`, bytes, encoding, parser profile, 열/옵션 해석은 provenance에 남긴다. 텍스트 파서가 만드는 표본의 최초 `sample_origin`은 `imported`이며 파일 확장자나 한글 주석을 근거로 `measured`를 만들지 않는다. 정규 HDF5는 이미 저장된 표본 구분을 그대로 보존한다.

기준면/포트 이름/제작과 측정 조건은 없는 경우 null이다. 파 정의와 phasor/current orientation은 원문이 정하지 않으면 unknown이다. 지원 Touchstone의 단일종단 여부만 `single_ended`로 기록한다. 데이터에 없는 시간 규약을 추측하여 Z/Y 변환이나 외부 RLC 계산을 실행하지 않는다. 사용자가 추가하는 조건은 원문과 별도로 보존해야 한다.

## 2. 유한 자원 경계

| 항목 | 현재 상한 또는 동작 |
| --- | --- |
| 텍스트/HDF5 원본 | 4 MiB, 크기를 줄여서 읽지 않음 |
| 포트와 표본 | 1~8포트, 1~1001표본 |
| 텍스트 행 | 한 행 4096문자, 물리 행 100000개 |
| CSV | 최대 129열, 헤더 셀 최대 256문자 |
| 수치 토큰 | 최대 128문자, 유한 float64. E 지수 허용, Fortran D 지수/NaN/Infinity 거절 |
| 내부 공통 자료 | 1~4포트 1 MiB, 5~8포트 4 MiB, provenance/conditions 각각 64 KiB |
| HDF5 생성물 | 8 MiB 이내. 현재 고정 배열은 원본 4 MiB 읽기 예산 안에서 왕복 시험 |

GUI/RPC의 전송 상한과 이 파일 파서 상한은 별도다. 큰 파일을 작은 protocol frame으로 전송할 수 있다고 가정하지 않는다. 잘못된 타입/열/숫자는 E_SCHEMA, 미지원 구문/손실 출력은 E_UNSUPPORTED, 크기 초과는 E_RESOURCE로 위치와 함께 거절한다. SI 환산 overflow와 0으로 사라지는 수치 underflow도 거절한다.

## 3. Touchstone 지원 profile

`rfad.touchstone-s/0.1`은 1.0/2.0/2.1의 단일종단 S, Full 행렬, RI/MA/DB를 지원한다. 1.0의 2포트는 S11/S21/S12/S22, 2.x는 `[Two-Port Data Order]`의 21_12 또는 12_21을 사용한다. 1.0은 파일 확장자 `.s1p`~`.s8p`에서 포트 수를 읽는다. 2.x는 `[Number of Ports]`를 읽고 포트 수가 있는 확장자와 충돌하면 거절한다.

Hz/kHz/MHz/GHz, deg 위상과 포트별 양수 실수 `[Reference]`를 지원한다. 옵션 생략은 명세 기본값이며 R 생략의 50 ohm은 `spec_default`로 표시한다. 원문에 명시된 R과 같은 출처로 만들지 않는다. 2.x의 여러 줄 Reference와 분할 데이터 행을 지원하지만 주파수 시작은 새 행이어야 한다. 근거는 [IBIS Touchstone 2.1 공식 명세, pp.4~16](https://www.ibis.org/touchstone_ver2.1/touchstone_ver2_1.pdf)다.

현재 profile은 1.1의 포트별 옵션 R, S 이외의 Z/Y/H/G, 9포트 이상, Upper/Lower, noise, mixed-mode, information 블록, 미지 키워드와 두 번째 옵션 행을 거절한다. 공식 명세 전체를 지원한다고 표시하지 않는다. 특히 1.x와 2.x의 Z/Y 정규화 차이를 S처럼 처리하지 않는다. 거절한 값이나 블록을 조용히 버리지 않는다.

공식 Touchstone은 ASCII다. 현재 importer는 UTF-8 주석과 BOM을 추가로 읽되 `utf8_comment_extension`과 `bom`으로 구분한다. 데이터/키워드에는 ASCII만 허용하며 주석을 실행하거나 기준면/포트 이름으로 추측하지 않는다. 원문 주석은 원본 artifact에 남긴다.

`write_touchstone(network)`는 2.1/Hz/S/RI/Full과 명시 Reference를 출력한다. 단일종단, 모든 행렬 값 유효, 주파수에 따라 변하지 않는 포트별 양수 실수 Z0만 허용한다. null/mask, 복소/주파수별 Z0를 0 또는 대표값으로 바꾸지 않는다. 출력 때문에 원본 값/출처를 수정하지 않는다. 파일 하나로 표현할 수 없는 기준면/파 정의/조건은 서비스의 sidecar에 보존한다.

## 4. CSV 명시 열 대응

`rfad.network-csv/0.1`은 UTF-8/BOM과 콤마/세미콜론/탭 구분자를 지원한다. `parse_csv(raw, mapping)`에서 다음 항목을 명시한다.

| mapping 필드 | 의미 |
| --- | --- |
| delimiter, header | 실제 구분자 문자, 첫 행의 헤더 여부 |
| frequency_column, frequency_unit | 0부터 시작하는 열 번호와 Hz/kHz/MHz/GHz |
| parameter_kind, value_unit | S/1, Z/ohm, Y/S 중 일치하는 조합 |
| complex_format | RI, MA 또는 DB. MA/DB의 두 번째 값은 deg |
| port_count | 1 또는 2 |
| pairs | 각 원소의 row/column/first_column/second_column. 모두 0부터 시작 |
| ignored_columns | 사용하지 않을 열의 명시 목록 |
| z0_ohm | 선택적 포트별 양수 실수 목록. 생략/null이면 미정 |

모든 파일 열은 값 또는 무시 열에 정확히 한 번 대응해야 한다. 헤더 이름으로 포트/단위/복소 표현을 추측하지 않는다. 행렬 원소 누락, 중복 열, 변한 열 수, 빈 숫자, 비단조/중복 주파수와 locale 소수점은 거절한다. 여러 줄에 걸친 따옴표 필드는 현재 미지원이다. 파서 metadata의 탭 구분자는 제어 문자를 원문 출처 문자열에 넣지 않도록 `\\t` 문자열과 `mapping_encoding`으로 기록한다.

`write_csv(network)`는 `frequency_Hz,S11_re,S11_im,...` 고정 열과 RI 숫자를 내보낸다. `csv_export_mapping(network)`는 이 열을 다시 읽는 대응표다. CSV에 포함되지 않은 Z0는 재가져오기 때 null이며 기존 자료의 Z0를 삭제했다는 뜻이 아니다. sidecar는 원본 자료 참조와 출처/조건 요약을 보존하지만 주파수별 Z0의 전체 배열을 CSV 안에 넣지는 않는다. 전체 배열과 조건을 함께 교환할 때는 아래 HDF5를 사용한다. 현재 CSV 출력은 유효한 모든 행렬 값이 있을 때만 제공하며 누락 셀을 빈칸/0으로 출력하지 않는다.

## 5. 정규화 HDF5

`rfad.network-hdf5/0.1`은 일반 HDF5 자동 해석기가 아니다. `encode_network_hdf5(network)`와 `decode_network_hdf5(raw)`는 이 profile만 교환한다. reader는 port_ids를 포함한 검증된 공통 19필드를 반환한다. h5py 3.16.0/NumPy 2.5.4는 별도 고정 환경에서 연산할 때만 불러온다. 미설치/버전 불일치는 E_CAPABILITY이며 일반 JSON 조회와 기존 프로젝트 보존은 native import를 요구하지 않는다.

루트에는 아래 11개 dataset만 허용한다. 고정 contiguous 배치, 무압축, little-endian float64와 마지막 real/imag 축을 사용한다. dataset/루트의 시간 추적은 끄고 생성 순서를 고정하여 같은 입력의 반복 encode가 같은 bytes를 만든다.

| dataset | 자료형과 축 |
| --- | --- |
| profile | uint8 UTF-8 고정 레이아웃/버전/상태 코드 표 |
| metadata_json | uint8 canonical JSON, 공통 19필드 전체 |
| frequency_hz | float64 [Nf] |
| s 또는 z 또는 y | float64 [Nf,Np,Np,2] |
| network_value_present | uint8 [Nf,Np,Np], null과 숫자 구분 |
| valid_mask, sample_status | 각각 uint8 [Nf,Np,Np] |
| sample_origin | uint8 [Nf] |
| z0_ohm | float64 [Nf,Np,2] |
| z0_value_present | uint8 [Nf,Np] |
| port_ids | 고정 ASCII 36 bytes [Np], 원래 순서 |

null은 HDF5 수치 배열에서 NaN 쌍과 존재 mask 0으로 표현하지만 canonical JSON은 null로 유지한다. 유효하지 않은 유한 원문 숫자는 그대로 보존한다. reader는 metadata를 검증한 뒤 모든 배열/축/상태/존재 mask를 대조한다. 유효 값에 NaN을 넣거나 숫자와 mask가 충돌하면 거절한다. metadata와 배열은 어느 한쪽이 다르다는 이유로 자동 보정하지 않는다.

soft/external 링크, hard-link 별칭, VDS, 외부 저장소, 필터/압축/chunk, variable-length 타입, 다른 endian, 속성/추가 객체와 크기 상한 밖 shape는 값을 읽기 전에 거절한다. 지원하는 HDF5 데이터 표현/파일 image/링크 API 근거는 [h5py dataset](https://docs.h5py.org/en/stable/high/dataset.html), [group](https://docs.h5py.org/en/stable/high/group.html), [in-memory file](https://docs.h5py.org/en/stable/high/file.html#in-memory-files) 문서다. 이 경계 검사는 임의 native 파일 파서의 모든 공격에 대한 보증이 아니다.

## 6. 실제 가져오기 화면

`NetworkImportDialog`는 시안 46/66/68의 파일 선택, 열/포트 대응, 검토 흐름을 native 탭으로 연결한다. 파일은 최대 512 KiB를 한 번 읽어 같은 bytes를 검토와 적용에 전달한다. 원문 표시만 최대 16 KiB로 제한하며 보존할 원문을 자르지 않는다. CSV는 열 대응 확인 전 전송하지 않고, 단위와 복소수 환산은 서비스가 수행한다.

첫 검토에서 확인한 포트 수와 원문 조건을 기준으로 명시 조건 입력을 활성화한다. 파/시간 규약/프로젝트 포트의 기본 선택은 원문 유지이며, 기준면을 명시하지 않으면 원래 null 또는 저장값을 보존한다. 원문 조건과 사용자 채택값은 별도로 기록한다. 원시 파일 형식/열 대응을 바꾸면 기존 조건 채택과 검토를 무효화한다.

검토 화면은 서비스가 반환한 첫 채널 최대 201개 표본의 곡선/표와 조건 요약을 보여 준다. 이는 원문 전체 행렬의 일부를 표시하는 것이며 파서가 나머지를 생략했다는 뜻이 아니다. 입력이 바뀌면 적용을 차단하고, 일치하는 검토 해시만 한 명령으로 저장한다. 확정 거절은 초안을 유지하고, 적용 결과가 불명인 경우 잠금과 권위 상태 재조회를 요구한다.

주파수는 자료 전체 범위에 맞춰 Hz/kHz/MHz/GHz로 표시하며, 표본 페이지가 바뀌어도 자동 단위를 유지한다. 한 표의 단위는 열 머리글에 명시한다. 예를 들어 원본 1000000000 Hz는 화면에서 1 GHz로 보인다. 이 표시 형식은 CSV의 명시 원문 단위와 구분하며, SI 원본/검토 해시/출처를 변경하지 않는다.

내보내기는 서비스의 bytes/base64/SHA256을 대조한 뒤 교환 파일과 `<파일명>.conditions.json`을 함께 저장한다. 프로젝트 작업 영역 내부와 기존 파일을 거절하므로 원본/과거 artifact를 덮어쓰지 않는다. 같은 폴더에 새 임시 파일 두 개를 먼저 완성하고, Windows에서 열린 자신의 파일 handle로 대상 이름을 게시한다. 둘 중 하나라도 실패하면 새 파일을 회수한다. 회수에 실패한 경우 남은 경로와 미완료 상태를 알리며 두 파일을 모두 게시하기 전에 성공으로 표시하지 않는다.

원문 출력은 안전한 원래 파일명과 확장자를 제안하여 Touchstone 1.0의 포트 수 해석을 보존한다. 두 파일의 게시 사이에 프로세스가 강제 종료되거나 전원이 끊기는 경우까지 파일 쌍의 원자성을 보장하지 않는다.

## 7. 검증과 수용 경계

`test_network_files.py`는 비상호 2포트 순서, RI/MA/DB, 기본값/UTF-8 표시, 부정 입력/예산과 출력 왕복을 검사한다. `test_network_hdf5.py`는 실제 고정 h5py에서 S/Z/Y, 복소/미정 Z0, null/유효 mask/원문 조건, 최대 표본과 재현 bytes, 변조/외부 저장 구조/선택 런타임 부재를 검사한다. `test_gui_network_process.py`는 Windows 실제 창의 가져오기/RLC/평가와 저장/서비스 재시작 후 원문, 과거 결과, 미정 조건과 snapshot을 대조한다. 시험 존재와 실행 합격을 구분하며 실제 집계는 검증 기록에 남긴다.

기존 제작/납품 물성, 시료/교정/측정 조건의 미정값과 과거 결과를 유지한다. 파일 가져오기/내보내기를 실제 측정, 독립 물리 정확도, RF 튜닝 또는 전체 R1 수용 완료로 표시하지 않는다. 기준면 보정과 제조 파일 교환의 남은 범위는 기존 완료 계획 번호를 따른다.
