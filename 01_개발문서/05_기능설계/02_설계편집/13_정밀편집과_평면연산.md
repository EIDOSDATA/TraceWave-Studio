# 정밀 편집과 제한된 평면 연산

## 1. 범위와 상태

개발 완료 계획 4번의 정밀 2D 편집 계약이다. 기존 스냅/끝점/직접 입력을 이어서 회전, 미러, 모델 연관 치수, 명시 매개변수 결합과 직선 다각형 집합 연산을 추가한다. 승인 설계 RFAD-D0-3.4의 R1 매개변수 제약을 사용하며, R2 일반 기하 구속 솔버를 구현한 것으로 표시하지 않는다.

본 기능은 명시 기하 편집이다. 생성, 연결/DRC 검사, CAD 출력, 해석, 수렴, 제조/측정 검증 상태를 별개로 유지한다. 물성, 제작/급전 실장/기준면/측정 조건을 채우지 않으며, 과거 템플릿 출처 사본과 결과도 수정하지 않는다. 화면과 서비스 시험의 실제 수행 결과는 검증 기록에서 별도로 확인한다.

연관 치수는 현재 모델에서 유도한 표시값이다. 형상 또는 연결된 매개변수가 바뀌면 재조회한 치수도 바뀐다. 도면용 자유 배치 주석, 수동 치수 문자열 덮어쓰기와 기술 도면 출력은 계획 10번과 구분한다.

## 2. 사용자 동작

1. 현재 개정의 도체를 선택하고 정밀 편집을 연다. 선택은 안정 UUID로 전달하며 이름은 공용 이름 서비스의 영속 또는 임시 표시 이름이다. 다중 객체는 최대 16개다.
2. 회전/미러/치수/매개변수 연결/영역 연산을 선택한다. 사용 불가 작업은 이유를 표시한다. 숨김이나 선택 필터가 실제 해석/출력 포함 여부를 바꾸지 않는다.
3. 입력 후 후보를 조회한다. 후보는 읽기 전용이며 아직 원본, 개정, undo 또는 영수증을 만들지 않는다. 변경 객체/삭제 객체/생성 객체, 치수, 미정 및 표시 생략을 함께 확인한다.
4. 후보 검토 이후 입력이나 선택이 바뀌면 검토 상태를 해제한다. 같은 기준 개정과 입력에 대한 `review_hash`가 있을 때만 적용한다. 변경 이유/메모는 선택 입력이다.
5. 적용은 한 명령이다. 다중 객체와 출처 사본이 모두 적용되거나 모두 취소된다. undo/redo도 한 단계다. 응답 불명 시 자동 재전송하지 않고 기존 권위 상태 복구 절차를 따른다.
6. 적용 후 현재 개정에서 목표/연결/제조 규칙을 다시 검사한다. 도형 편집 성공이 연결/제조 규칙 통과를 의미하지 않는다.

## 3. 지원 기하와 입력

| 작업 | 입력 `values` | 의미와 제한 |
| --- | --- | --- |
| `rotate` | `pivot_x_mm`, `pivot_y_mm`, `angle_deg` | 명시한 중심에 대해 반시계 양의 각도로 회전. 최대 16개, 선/원호/영역/패드/비아 |
| `mirror` | `axis`, `offset_mm` | `x`는 `Y=offset_mm` 수평선, `y`는 `X=offset_mm` 수직선. 층 또는 상하면을 바꾸지 않음 |
| `dimension_set` | `dimension_key`, `value`, `unit` | 객체 한 개의 지원 치수. 서비스에서 단위 환산 |
| `bind_dimension` | `dimension_key`, `parameter_id` | 직접 수량 필드만 같은 차원의 기존 매개변수에 명시 결합 |
| `union` | 빈 object | 선택한 2~16개 도체 영역의 합집합 |
| `difference` | 빈 object | `selection_ids[0]`에서 이후 선택 영역을 순서대로 뺌 |
| `intersection` | 빈 object | 선택한 2~16개 영역의 교집합 |
| `offset` | `distance_mm`, `join`, `mitre_limit` | 영역 한 개. 양수 확장/음수 축소. `mitre`/`bevel`만 지원 |

회전/미러는 기존 UUID, 선/원호 종류, 선폭/반경, 재료/net/층/역할, 포함 플래그를 보존한다. 원호 반사에서는 시작각을 변환하고 signed sweep의 부호를 반전한다. 원호를 직선 다각형이나 닫힌 링으로 바꾸지 않는다. 실제 바뀌는 위치/방향이 매개변수에 연결되어 있으면 직접 변환을 차단하고 해당 매개변수 편집으로 안내한다.

직접 치수 목록:

| 객체 | 치수 key | 동작 |
| --- | --- | --- |
| 선 | `line.length`, `line.width` | 길이는 시작점/진행 방향을 유지하고 끝점을 변경. 길이 자체의 직접 parameter 결합은 미지원 |
| 원호 | `arc.radius`, `arc.width`, `arc.start_angle`, `arc.sweep_angle` | 직접 수량 또는 명시 parameter 결합 |
| 원호 | `arc.length` | 중심선 경로 길이. 읽기 전용 |
| 사각 패드 | `pad.width`, `pad.height`, `pad.rotation` | 직접 수량 또는 명시 parameter 결합 |
| 원형 패드 | `pad.diameter` | 두 저장 지름을 같은 값/참조로 유지 |
| 비아 | `via.finished_hole_diameter`, `via.plating_thickness`, `via.tool_hole_diameter` | 사용자가 명시 입력한 값만 변경. 미정값은 그대로 표시 |
| 영역 | `region.area`, `region.perimeter` | 구멍을 뺀 면적, 구멍을 포함한 경계 길이. 읽기 전용 |

표시 치수에는 `object_id`, `key`, `value`, `unit`, `status`, `anchors_mm`, `kind`, `editable`, `parameter_id`, `binding_supported`, `field_path`, `read_only_reason`, `source_refs`가 있다. `value`는 `unit`에 따른 표시값이며 SI 원본값이 아니다. 미정은 `null`이다. 길이는 mm, 각도는 deg, 면적은 mm^2로 표시하며, 기존 원본의 표시 단위와 출처는 변경된 수량에서도 보존한다.

## 4. 평면 연산 profile

첫 profile은 `planar_region`의 직선 외곽과 구멍만 연산한다. 입력들의 `frame_id`, `layer_id`, `net_id`, `material_ref`, `role`, `include_in_em`, `include_in_export`가 같아야 한다. 값이 미정이거나 parameter 참조인 좌표를 자동으로 풀어 쓰지 않는다.

결과는 새 `planar_region` UUID이며 공용 이름 배정 규칙을 사용한다. 분리된 면이 나오면 최대 16개 객체를 한 명령으로 생성한다. 기존 선택 영역은 교체되지만 입력 사본, 결과 사본, 의존 매개변수와 출처가 프로젝트의 정밀 편집 출처에 남는다. 포트, 비아 또는 기대 연결이 참조하는 객체는 자동 재매핑하지 않고 차단한다.

상한은 객체당 외곽/구멍 전체 64점, 8개 구멍, 결과 16개 영역이다. 좌표/치수 절댓값은 1000000 mm 이내다. 결과가 상한을 넘으면 명시적으로 차단한다. 작은 조각 제거, 구멍 채우기, `simplify`, `make_valid`, `set_precision`, 암묵적 수치 격자 반올림은 수행하지 않는다. 선/점 잔여 결과와 빈 결과도 조용히 버리거나 전체 삭제로 적용하지 않는다.

오프셋의 `mitre_limit`는 1~100이며 모서리 잘림 규칙을 명시한다. 둥근 모서리와 선/원호를 포함하는 Boolean은 현재 지원하지 않는다. 이를 추가하려면 곡선 chord tolerance, 분할 예산, 변환된 형상과 연결의 검토, 원문/엔진/허용오차 출처가 별도 계약에 있어야 한다. Shapely는 곡선을 직선 조각으로 표현하고 XY 평면에서 연산한다. 따라서 장기 3D 안테나 기하 엔진을 대체하지 않는다. [공식 기하 모델](https://shapely.readthedocs.io/en/2.2.0/manual.html#spatial-data-model), [공식 buffer 계약](https://shapely.readthedocs.io/en/stable/reference/shapely.buffer.html)

GEOS가 double precision 수치 엔진이라는 사실을 정확한 유리수 기하 또는 제조 공차 검증으로 확대하지 않는다. 같은 층의 시각적 인접과 실제 net 접속도 별도 검사한다. [GEOS 수치 표현](https://libgeos.org/usage/faq/#robustness)

## 5. 공개 API와 저장 경계

공통 envelope는 `rfad.api/2.0`, context는 `{project_id}`다. profile은 `rfad.precision-editor/0.1`이다.

| 메서드 | input |
| --- | --- |
| `precision.get` | `{expected_revision, selection_ids}` |
| `precision.preview` | `{expected_revision, selection_ids, operation, values}` |
| `precision.apply` | preview 입력 + `{command_id, review_hash, reason}`와 기존 요청 영수증 필드 |

`get`는 선택/전체 객체 목록, 치수, 매개변수, 작업별 활성 상태와 이유, 엔진/자원 한계를 반환한다. `preview`는 `can_apply`, `review_hash`, 기존 `rfad.canvas/0.1` 장면 `scene`, `changes`, `result_ids`, `dimensions`, `notices`, `engine`을 반환한다. 차단 후보는 `can_apply=false`, `review_hash=null`, `scene=null`이고 원본을 유지한다. GUI는 현재 원본 장면과 차단 이유를 표시한다.

검토 해시는 전체 기준 원본 해시/개정, 선택 순서, 작업/입력, 엔진 버전, 변경 전후 객체와 의존 매개변수를 묶는다. 메모는 선택 입력이므로 검토 후 작성할 수 있다. `apply`는 같은 writer transaction 안에서 후보를 다시 계산하고 해시를 비교한 뒤 내부 `geometry.precision.apply` 한 명령으로 게시한다. 공개 `project.apply_command`로 내부 명령을 직접 실행할 수 없다. 반환에는 새 개정/무효화/이력과 `selection_ids`, `origin_id`가 있다.

원본의 `extensions.rfad.precision-origin`은 schema `rfad.precision-origin/0.1`로 변경 전후 객체, 입력, 관련 parameter/표현식 사본, 엔진, 검토 hash, 선택 메모를 보존한다. 출처는 최대 128개 레코드와 256 KiB, 프로젝트 전체는 기존 512 KiB다. 상한 초과 시 과거 사본을 지우지 않고 적용을 차단한다. 현재 원본의 이후 직접 편집은 과거 사본을 바꾸지 않는다.

undo/redo는 저장된 정확한 객체와 출처 사본을 적용하며 GEOS를 다시 실행하지 않는다. 선택 엔진을 제거한 환경에서도 저장 프로젝트의 재열기/이력 복원/기본 편집은 가능하다. 후보 응답 전체는 256 KiB이며 내부 장면에는 기존 60 KiB 상한도 적용한다. 특정 객체의 표시가 불가능하면 scene의 생략 이유와 후보 notice를 함께 유지한다.

R1 제약 편집/검사는 기존 `design.rules.get/apply/check`를 사용한다. parameter 상하한/정수, 외곽/간격/제조 규칙의 정책을 별도로 복제하지 않는다. 위반 설계의 편집/저장은 허용하되 현재 검사 결과와 실행 preflight 차단을 구분한다. 임의 일치/평행/접선/대칭과 미구속/과구속 진단 solver는 R2 범위다.

## 6. 선택 엔진 설치와 라이선스

순수 회전/미러/치수/기존 프로젝트 재열기는 외부 평면 엔진이 없어도 동작한다. Boolean/offset만 고정 Shapely/GEOS 환경을 요구한다. 미설치 또는 다른 엔진 버전이면 해당 작업의 비활성 이유를 표시하며 다른 모델로 대체하지 않는다.

일반 `capabilities.get`은 배포 메타데이터의 설치 버전만 읽고 Shapely/NumPy/native 라이브러리를 import하지 않는다. `planar_engine.runtime_checked`는 `false`, 실제 GEOS 버전은 `null`이며 설치 버전이 일치해도 실행 가능 여부 `available`은 `null`이다. 실제 `precision.get`/`precision.preview` 요청에서 엔진을 읽고 고정 버전과 사용 가능 상태를 확인한다. 설치 메타데이터의 일치를 실행 검증 통과로 확대하지 않는다.
