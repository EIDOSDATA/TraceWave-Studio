# 객체 이름과 표시 계약

작성일: 2026-11-17 KST

개발 완료 계획 4번의 객체 탐색과 선택 연동을 위한 현재 서비스 계약이다. [화면 이름 설계](../../04_화면설계/05_객체이름과_선택연동.md), [속성 편집](02_속성편집과_실행취소.md), [프로젝트 저장](../01_프로젝트/01_프로젝트_명령과_저장.md)을 함께 따른다. 이름은 표시 메타데이터이며 형상, 물성, 목표 충족 또는 제작/측정 검증 상태가 아니다.

## 저장과 읽기 호환

새 원본은 `rfad.project/0.5`다. 0.1~0.4 원본도 그대로 읽고, 실제 편집 명령을 적용한 복제본만 0.5로 승격한다. `board`와 각 `geometry` 객체에 선택적인 `name` 문자열을 허용한다. 이름 없는 0.5 객체도 유효하므로 다른 속성만 바꿔도 무명 객체를 자동 이관하지 않는다. 0.1~0.4의 기판/도체 원본에는 name을 임의 추가하지 않는다.

기존 프로젝트, 매개변수, 재료, 적층, net, 포트의 name 필드는 그대로 사용한다. 목표와 적층/외부 환경 이름은 기존 전용 모델의 이름을 사용하며 별명을 중복 저장하지 않는다. 이름 변경은 UUID, 표현식 원문/bindings, 포트/넷 참조, Quantity의 SI/status/source_refs, 출처 사본과 과거 snapshot을 바꾸지 않는다. 이름 문자열은 저장 경로나 출력 파일 이름으로 사용하지 않는다.

기판/도체에 저장하는 이름과 편집 화면에서 새로 입력하는 이름은 1~256 Unicode 문자다. 빈값, 앞뒤 공백, 제어 문자와 고립 surrogate는 거부하며 자동으로 잘라내거나 정규화하지 않는다. 같은 geometry collection 안에서는 층이 달라도 정확히 같은 이름을 거절한다. 기존 이름 필드가 있는 collection도 원래 중복 검사를 유지한다. 다른 collection끼리의 같은 이름은 허용한다. 기존 파일의 이름을 읽기만 해서 바꾸거나 새로운 공백 정규화를 강제하지 않는다.

## 자동 이름과 임시 표시

`canvas.apply`의 기판/선/원호/영역/패드/비아 생성은 서비스가 객체와 함께 이름을 배정한다. 기본 접두어는 `기판`, `선`, `원호`, `면`, `패드`, `비아`다. 명시된 ground 영역은 `접지면`, feed 선은 `급전선`을 쓴다. 이름으로 역할을 역추론하지 않는다.

현재 접두어의 최대 번호 다음을 최소 두 자리로 배정한다. 기존 영속 이름, UUID 순으로 배정한 무명 객체의 임시 표시, 같은 후보에서 예약한 이름을 피한다. 삭제/정렬/역할/층 변경으로 기존 이름을 다시 번호 매기지 않는다. 가장 큰 번호가 삭제되면 새 UUID가 그 번호를 다시 쓸 수 있다. 생성 redo는 최초 이름과 UUID를 복원한다.

구버전 무명 객체는 UUID 정렬을 기준으로 `선 01`과 같은 읽기 전용 임시 표시를 사용한다. 해당 개정에서 GUI 정렬/필터를 바꿔도 이름은 같으며 조회가 원본/hash/revision/저장 상태를 바꾸지 않는다. 다른 개정의 무명 객체 구성이 바뀌면 임시 번호가 달라질 수 있다. 영속화하려면 이름 필드에 명시 입력하고 적용한다.

## API와 표시 DTO

`capabilities.get.object_name_profile`은 `rfad.object-name/0.1`, 최대 256자와 `editor.apply` 진입점을 공개한다. 별도 정식 API 번호는 추가하지 않는다.

`editor.get.items`와 `canvas.get`의 board/shapes는 다음 정보를 함께 전달한다.

| 필드 | 의미 |
| --- | --- |
| id | 기존 안정 UUID |
| name | 원본에 저장한 이름. 무명은 null |
| name_state | `stored` 또는 `temporary` |
| label | 실제 화면에 표시할 사용자 이름 또는 임시 이름 |

속성, 급전/비아 참조 선택지, 기대 연결 편집과 정밀 편집 목록은 같은 공통 표시 함수를 사용한다. 이름을 객체 결합 키로 쓰지 않는다. 무명 기판/도체의 속성 `name.value`는 빈 문자열이며 help에 임시 표시 이름과 저장되지 않은 상태를 안내한다. 다른 필드만 변경하면 빈 name을 원본에 넣지 않는다.

이름 변경은 기존 mutation envelope로 `editor.apply`에 `selection:{kind,id}`, `values:{name:"새 이름"}`, `expected_revision`, `command_id`를 보낸다. 기존 request_key 영수증, 단일 writer, revision 검사, 원자 명령, 영속 undo/redo와 저장 경계를 공유한다. stale, 중복 이름, 잘못된 입력이면 원본/이력을 유지한다. 이름만 변경해도 보수적 개정 무효화 정책을 유지하며 과거 CAD/해석을 현재 개정 결과로 다시 표시하지 않는다.

## 급전 선택의 조회 항목

단일 포트가 있으면 `editor.get` 및 `editor.page`의 첫 응답에 `port_links`가 있다. `id`, `label`, `terminal_ids`를 제공하며 두 ID의 순서는 신호, 기준이다. `canvas.get`과 `canvas.page`의 첫 응답은 `port_marker`에 동일한 ID 및 단자 순서와 `point_mm`, `reason`을 제공한다. 위치는 명시한 급전 영역 두 끝점의 XY 중점이다. 한 좌표가 미정이거나 표시 범위를 벗어나면 위치를 null로 두고 사유를 반환한다.

표식과 양단 강조는 표시 계층에서 동작한다. 3D에서는 현재 메시의 source ID에 해당하는 기존 바디를 강조한다. 도면에서 고른 단자는 `editor.apply`에 적용하기 전까지 속성 초안이다. [Windows 선택 검증](../../07_검증/264_윈도우_급전단자와_진단_선택검증.md)

## 템플릿과 검토 후보

새 템플릿 후보는 도체뿐 아니라 매개변수/net/명시 포트에도 읽기 쉬운 이름을 배정한다. 생성 사본에 `naming_profile:"rfad.object-name/0.1"`을 기록한다. 이름은 후보 objects/record_hash/preview_hash에 포함되며 적용 시 몰래 다시 배정하지 않는다. 개정이 바뀌면 재검토한다.

이 필드가 없는 과거 template-origin record는 당시 명명 규칙으로 계속 검증한다. 저장된 생성 사본과 source_document의 schema/bytes/hash를 새 이름으로 바꾸지 않는다. 새 후보를 구버전 프로젝트에서 만들 때도 source_document는 당시 원본이며 새 후보 검증본만 0.5다. 현재 객체를 이름 변경한 뒤 최초 사본은 그대로 두고 instance_status의 수정 차이로 구분한다. 카드 출처, 미정 물성, 검증 단계는 유지한다.

정밀 평면 연산의 생성 이름도 [정밀 편집 계약](13_정밀편집과_평면연산.md)의 후보/검토 hash에 포함한다. 회전/미러는 기존 객체의 이름을 유지한다. 연관 치수는 별도 파생 조회/정밀 편집 계약이며 이번 core 확장을 추가 수량 기본값을 채우는 수단으로 사용하지 않는다.

## 검증 경계

[서비스 시험](../../../Code/tests/test_object_names.py)은 legacy 읽기 비변경, 자동 번호/삭제/redo, 이름 오류/중복, 기존 출처/미정/표현식 보존, 후보 이름 hash, 과거 생성 사본, 실제 저장/서비스 재시작/재열기, undo/redo와 snapshot 바이트 보존을 확인한다. 기존 canvas/editor/template/project 회귀도 함께 수행한다. 실제 Windows F2/선택/포커스와 화면 배율 검증 결과는 단계 4 GUI 검증 기록에 별도로 남기며 서비스 시험으로 GUI 합격을 대신하지 않는다.
