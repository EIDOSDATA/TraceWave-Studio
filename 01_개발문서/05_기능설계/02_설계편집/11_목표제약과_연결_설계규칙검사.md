# 목표 제약, 실제 연결과 기본 DRC

RFAD-D0-3.4의 FN-004 및 FN-009에 연결한 개발 완료 계획 3번 범위다. 설계 메뉴의 **설계 제약, 연결 및 DRC** 또는 하단 **문제** 탭의 **제약, 연결 및 DRC**를 연다. 기존 wxWidgets 편집 폼과 사용자 정의 2D 캔버스를 사용한다.

1. **기판 크기와 제조 규칙**에서 기존 목표를 고르고 기판의 X/Y 최대 크기, 원형 기판 최대 지름, 전체 적층 최대 두께를 지정한다. 필요하면 저장한 제조 규칙을 연결한다.
2. **매개변수 범위 / 정수**에서 목표와 기존 매개변수를 고른다. 현재 개정의 평가된 값에 하한/상한을 적용한다. 같은 값으로 두 한계를 고정할 수 있고, 무차원 매개변수에 정수 조건을 추가할 수 있다.
3. **기대 연결 / 분리**에서 두 도체를 선택하고 연결, 의도적 분리 또는 기생 도체의 DC 분리를 지정한다.
4. **제조 규칙**에서 기존 profile을 선택하거나 이름과 버전을 가진 새 profile을 작성한다. 규칙별로 직접 입력, 미정, 적용 안 함을 고른다. 공정 자료나 설계 가정은 변경 사유/출처에 입력한다.
5. 필요한 변경을 적용하고 검사할 형상 범위를 선택한다. **현재 개정 검사** 결과에는 만족, 위반, 미평가, 적용 안 함의 수가 표시된다. 위반이나 미평가 행을 선택하면 연관 도체와 서비스가 반환한 위치가 2D에 표시된다. 확인을 마친 뒤 주 창에서 저장한다.

선택한 목표와 그 제조 규칙을 함께 검사한다. 제조 규칙 섹션에서 한 profile을 선택하면 해당 profile도 명시적으로 검사에 넣는다. 목표가 선택되지 않은 상태에서는 현재 목표 전체를 검사한다. 도체 검사 범위는 전체, EM 포함, 출력 포함 중 하나다. 대상 도체가 검사 범위에 없거나 치수가 미정이면 기대 연결은 미평가다. 목표의 RF 성능 평가 상태는 계속 미평가다.

## 저장과 API

목표 제약과 연결/제조 규칙은 0.4에서 도입했으며 현재 프로젝트 쓰기는 `rfad.project/0.6`이다. 0.1~0.5 원본과 봉인 snapshot의 바이트는 읽을 때 보존한다. 편집으로 새 개정을 만들 때 0.6으로 승격하고 이전 개정과 schema 이동을 기록한다. 0.5의 객체 이름 확장은 제약과 연결 의미를 바꾸지 않는다. 이미 보존된 내장 카드, 문헌 카드, 적층/재료 원문, 목표/측정 출처는 일반 편집 계약에 따라 유지한다.

- 목표의 선택적 `constraints`에는 기판 한계 Quantity 4개, 최대 16개 매개변수 범위, 선택 제조 profile UUID 및 출처를 저장한다. 매개변수 대상이 없거나 단위 차원이 다르거나 범위가 역전되면 거절한다. 설계 값이 강제 한계를 벗어나면 원본을 수정할 수 있도록 저장과 검사를 각각 수행한다.
- `connections`에는 최대 64개의 기대 연결 레코드를 저장한다. 두 도체의 UUID, 역할 `connected`, `isolated`, `parasitic` 및 출처를 유지한다. 각 도체 참조는 명시적으로 미정일 수 있다.
- `manufacturing_profiles`에는 최대 8개의 이름/버전/출처를 갖는 규칙 레코드를 저장한다. 수량과 출처는 고정 literal Quantity를 사용한다. 형상/매개변수/제조 profile이 삭제 대상이면 먼저 관련 제약 참조를 정리해야 한다.

`design.rules.get`과 `design.rules.check`는 `rfad.api/2.0`의 현재 프로젝트/개정 읽기 요청이다. `get`은 `selection={section,record_id,target_id,parameter_id}`로 선택 객체의 필드와 2D 표시를 받는다. section은 `target`, `parameter`, `connection`, `manufacturing_profile` 중 하나며 미선택 ID에는 null을 쓴다. `check`는 `inclusion`, `target_ids`, `manufacturing_profile_id`를 받는다. 목표 ID의 null은 전체 목표를 의미한다. 빈 배열은 목표 제외다. 읽기는 영수증이나 worker 작업을 생성하지 않는다.

`design.rules.apply`는 기존 mutation envelope, `command_id`, `selection`, `operation`, 변경된 `values` 및 `reason`을 받는다. 각각 `target.constraints.set`, `connection.set/remove`, `manufacturing_profile.set/remove`로 적용한다. 단위만 바꾸면 SI 값, 입력 상태와 수량 출처를 유지한다. 내용 변경에는 기존 출처와 새 사유를 함께 보존한다. 이력과 재접수는 기존 writer와 영수증을 사용한다. 결과에 결합된 프로젝트 개정이 달라지면 다시 검사한다.

편집 API profile은 `rfad.design-rules-editor/0.1`이며 읽기/검사 응답 상한은 256 KiB다. 검사 행을 상한 때문에 생략하면 checks_truncated/issues_truncated와 전체 개수를 남긴다. 원본 규칙이나 출처를 잘라 저장하는 기능은 아니다. get/check는 동기 읽기이며 TaskRef나 새 명령을 만들지 않는다. 검사 성공 응답과 만족/위반/미평가 판정은 구분한다. revision과 입력 범위가 다른 과거 진단은 현재 도체의 검사 결과로 표시하지 않는다.

## 검사 범위

선분과 원호의 경계 및 그 교점과 최근접점을 해석적으로 계산한다. 회전 사각/원 패드, 구멍이 있는 polygon과 원형 비아 배럴을 처리한다. 해석적 극값으로 만든 AABB를 사용해 근접쌍을 제한한다. 보고서는 규칙, 객체 UUID, 위치, 측정값, 한계값, 단위와 출처를 제공한다. 표시 행에는 상한이 있고, 전체 개수와 생략 여부를 함께 반환한다. 근접쌍 4096개와 경계쌍 200000개를 초과하면 자원 오류를 반환한다. 평면 계산은 절대 좌표 1000000 mm 및 폭/반경 등의 최소 형상 수치 0.000001 mm 범위에서 수행한다.

실제 도체 접촉으로 연결 성분을 만들고 저장한 기대 연결과 비교한다. 양수 간격은 연결로 간주하지 않는다. 미세 경계의 수치 보호 구간이나 자료 미정이 판정에 영향을 주면 미평가다. IFA의 같은 net에서 요구된 단락 경로는 실제 연결 여부로 평가한다. 명시된 PTH pad는 층 범위와 배럴 피복을 검사한 뒤 연결한다. 미정 높이, 복합 비아 절삭과 실장에 의존하는 연결은 미평가로 남긴다.

| 기본 규칙 | 검사 대상 |
| --- | --- |
| 최소 폭 | 선, 원호, 패드, 구멍 없는 축 정렬 사각 도체 |
| 최소 간격 | 같은 층의 다른 net 도체 경계. 구멍과 round cap을 포함 |
| 기판 외곽 거리 | 사각/원형 기판의 도체 경계와 가장 가까운 외곽 여유. 외부는 음수 |
| 최소 공구 드릴 | 입력된 공구 구멍 지름 |
| 최소 환형 링 | 비아 중심에서 명시 패드 경계까지의 최소 거리에서 공구 반지름을 뺀 값 |
| 최대 비아 종횡비 | 시작 도체층 아래 면부터 도착 도체층 위 면까지의 길이를 공구 지름으로 나눈 값 |

선언한 강제 한계 및 연결의 확인된 위반은 기존 입력 검사와 PCB solver 계획에서 차단한다. 미정값은 결과에 남기며 후속 목적에 필요한 필수 입력은 해당 검사에서 확인한다. 기계 STEP 출력의 자체 형상 검사는 기존 경로를 사용한다.

다각형의 국부 목 폭, 임의 절삭 도체와 비아의 최소 간격, 슬롯 공정, 제조 업체 공차와 프로파일 자동 가져오기는 후속 범위다. 사용자 제약 만족과 납품 제조 검증은 별도 상태로 기록한다. 지원하는 설치 물체, 적층과 표면층의 해석 범위는 [적층/외부 환경](12_적층과_외부환경.md)에 정리한다. RF 목표 평가 및 수렴·실측 검증은 기존 개발 완료 계획 순서를 따른다.

관통 홀이나 내부 절삭이 도체의 실제 경계와 떨어져 있으면 원래 도체의 폭·출처로 기존 한계를 적용한다. 접하거나 일부를 제거하는 경우에는 절삭 후 경계를 연결에 사용하고 국부 폭은 미평가로 둔다. 도금이나 치수 미정을 자료 없이 단정하지 않는다. [Windows 제조 규칙 검증](../../07_검증/257_윈도우_관통부와_제조규칙_검증.md)

객체 이름/상호 선택의 화면 개선은 [이름과 선택 설계](../../04_화면설계/05_객체이름과_선택연동.md)를 따른다. 서비스는 이름과 별개인 UUID로 결과 및 과거 검사 대상을 연결한다. [서비스 시험](../../../Code/tests/test_design_rules.py)과 [Windows GUI 시험](../../../Code/tests/test_gui_design_rules_process.py)의 기존 실행 근거는 [개발 상태](../../09_개발계획/02_개발착수와_현재상태.md)에 보존한다.

## 전 도체층 금지 영역

PCB **금지 영역**에서 기존 개별 도체층 또는 **모든 도체층에 적용**을 선택할 수 있다. 모든 도체층을 선택하면 검사 시점의 적층에서 도체층을 계산한다. 원래 개별 층 목록은 보존하며 전층 옵션을 끄면 다시 사용한다. 비아는 시작층부터 종료층까지 통과하는 도체층으로 검사한다. 금지 영역이 확인된 경우 별도 목표·연결 제약 없이도 해석 계획을 차단한다.

템플릿 미리보기는 새로 추가할 도체가 확인된 금지 영역을 침범할 때 해당 객체와 위치를 표시하고 적용을 차단한다. 기존 설계의 미정 입력은 일반 준비 진단에서 그대로 표시한다. [Windows 폼과 서비스 검증](../../07_검증/253_윈도우_전도체층_금지영역_검증.md)
