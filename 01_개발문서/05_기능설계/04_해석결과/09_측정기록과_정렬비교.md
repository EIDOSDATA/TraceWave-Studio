# 09. 측정 기록과 정렬 비교

완료 계획 11번의 유한 서비스 계약이다. 구현 시험과 실제 장비 자료의 정확도 수용을 각각 확인한다. [공통 복소자료](06_공통복소자료와_회로평가.md) / [고정 결과 비교](07_다중결과와_방사표시.md) / [기존 측정 설계](01_최적화와_측정.md)

## 1. 자료와 근거의 분리

원문 파일, 정규 복소 dataset, 시료/교정 기록, 정렬 파생 dataset, 고정 비교 보고서는 서로 다른 불변 artifact다. 파일을 읽었다는 사실로 자료 분류를 측정으로 채우지 않는다. `data_class`는 `unknown`, `measurement`, `synthetic_fixture` 중 명시 선택이며 분류 자체가 독립 실측 검증을 뜻하지 않는다.

프로젝트의 `extensions.rfad.measurement`에는 기록, 정렬, 비교의 ID/이름/artifact 참조만 둔다. 컬렉션마다 최대 32개, 전체 색인은 64 KiB다. 기록 본문은 64 KiB, 정렬 이력은 256 KiB, 비교 보고서는 1 MiB 이내다. 프로젝트 512 KiB, 일반 artifact 8 MiB와 기존 원문 한도를 변경하지 않는다. 한도를 넘으면 명시 진단으로 차단하고 기존 기록을 삭제하거나 표본을 조용히 줄이지 않는다.

기록 수정은 이전 ID를 참조하는 새 기록이다. 한 이전 기록에서 두 최신 기록으로 분기하지 않는다. 이전 기록의 이름/입력/미정 상태를 소급 변경하지 않는다. 사용자가 정한 이름을 기본 목록에 표시하고 UUID/hash는 상세 식별과 검증에 사용한다.

| 항목 | 보존 내용 |
| --- | --- |
| 시료 | 식별/serial/lot, 제작/조립 개정, 장착 회차, 수정 기록, 설계 snapshot, 납품 물성 원문 |
| 취득 | 장비/serial/firmware, 명시 측정 일시와 시간대, IFBW/평균/전력, 설정 원문 |
| 교정 | 방식/일시/시간대/kit/표준, 증명 원문, 포트와 기준면, 유효 대역, 확인 기록 |
| 설치 | 커넥터/케이블/지그, 경로/장착, 포함 효과와 외부 보정 효과 |
| 환경 | 온도/습도, 케이스/배터리/자세/주변 물체, 제출 환경 원문 |
| 불확도 | 정의/단위/표준 또는 확장 분류, 값/k/coverage/가정/출처 |
| 외부 처리 | 입력/출력 anchor, 도구/버전/처리 순서/기준면/근거 |

각 항목은 null 또는 `value/evidence/source_refs` leaf다. 근거는 `planned/declared/reported/unknown`이며 unknown의 값은 null이다. 계획값을 실제 수행값으로 바꾸지 않는다. 두 미정 조건을 일치로 판정하지 않는다. k=2, 독립성/RSS, 교정 날짜, 0 dBm, 실제 제조 물성을 기본값으로 생성하지 않는다.

`created_at_utc`는 서비스가 처음 제공한 기록 초안 작성 시각이다. 검토와 적용에서 같은 값을 사용하며 실제 측정 일시나 명령 게시 시각과 구분한다. 바뀐 필드만 제출한다. 서비스가 주파수의 Hz/kHz/MHz/GHz와 수량 단위를 환산하고, 단위만 바꾼 경우 기존 canonical 값/출처를 유지한다. 실제 입력한 수치와 단위는 기록 wrapper의 원래 요청에 보존한다.

## 2. 고정 anchor와 첨부

기존 계산/가져오기 자료에는 공통 `source + pin`을 사용한다. pin은 원본 identity hash와 dataset SHA-256을 함께 고정한다. 새 원문과 기록을 동시에 가져올 때는 미래 프로젝트 hash를 참조하지 않고 `network_artifact` anchor에 project/dataset ID와 dataset/raw/HDF5 artifact를 직접 고정한다.

조회 시 명시 과거 개정의 색인, 최초 생성 명령과 실제 생성 개정, wrapper hash/ID/이름, 원본 소유와 바이트를 대조한다. 현재 목록에서 자료를 제거하거나 기하를 편집한 뒤에도 최초 생성 개정의 source/pin으로 읽는다. snapshot 연결은 해당 프로젝트의 등록 snapshot ID, 내용 hash, 실제 문서와 개정을 확인한다. 환경 JSON은 사용자가 제출한 내용과 첨부 근거로 유지한다.

첨부 원문은 파일당 512 KiB, 프로젝트당 16개/합계 8 MiB다. 서비스가 생성한 불변 경로를 사용하며 원래 파일명을 저장 경로로 실행하지 않는다. 역할/MIME/bytes/hash와 원문을 함께 보존하고 128 KiB 이하 청크로 조회한다. 외부 처리와 교정 근거에 넣는 artifact는 같은 프로젝트의 등록 첨부 또는 명시 결과 anchor여야 한다. 임의 경로/다른 프로젝트 파일을 따라가지 않는다.

첨부 보관은 별도 영수증이 있는 작업이다. 기록 편집을 취소해도 이미 보관한 원문을 삭제하지 않는다. 기록에는 사용자가 명시 연결한 첨부만 포함한다.

## 3. 검토와 원자 적용

`measurement.preview`는 원본 개정, 입력, 초안 시각, 계산 환경, 후보 파일 hash와 실제 명령/역명령을 준비한다. `measurement.apply`는 같은 내용을 다시 검증하고 review hash가 일치할 때만 게시한다. 원문 가져오기와 시료 기록은 한 복합 명령으로 적용되며 한 번의 undo/redo로 두 색인을 함께 전환한다. 불변 원문과 과거 개정은 유지한다.

명령/역명령/응답을 포함한 journal 예산, 파일 크기/기존 hash 충돌과 디스크 공간을 게시 전에 검사한다. 내부 registry/workspace 교체 명령은 일반 `project.apply_command`로 우회할 수 없다. 요청 영수증은 동일 요청의 중복 적용을 막는다. 응답 불명에서는 원래 키를 조회하며, 미발견/만료를 미적용 증거로 삼아 새 키로 자동 재전송하지 않는다.

## 4. 명시 정렬의 지원 범위

정렬은 최대 세 연산의 명시 순서를 보존하며 기존 dataset을 덮어쓰지 않는다. 주파수 자동 정렬/외삽/곡선 평행 이동은 수행하지 않는다.

| 연산 | 현재 범위와 차단 조건 |
| --- | --- |
| 포트 순열 | 포트 ID/이름/양축 network 행렬/Z0/기준면/메타데이터를 함께 재배열 |
| 기준 임피던스 | 명시 양의 실수 Z0와 기존 지원 wave 계약의 S 재정규화. 미정 basis를 임의 채우지 않음 |
| 선형 RI 보간 | 1~1001개 명시 주파수 또는 2~1001개 범위 표본. 실수/허수 선형 보간, 명시 최대 간격, 원래 범위 내부만 지원 |

기존 주파수의 표본/마스크/출처는 그대로 유지한다. 새 보간점만 `interpolated`로 표시하며 양쪽 원래 index와 가중치를 남긴다. 무효 표본을 건너뛰거나 미정 기준면/변동 Z0를 숨겨 보간하지 않는다. GUI 수량 입력의 원문과 실제 정규 연산을 모두 저장한다. 외부 도구의 보정 이력은 입출력 소유/hash를 확인해 보존하지만 해당 보정을 TraceWave가 실행/재현했다고 표시하지 않는다. 고급 fixture de-embedding, 기준면 이동, OTA 보정과 불확도 전파는 현재 지원 범위 밖이다.

## 5. 비교와 과거 보고서

공통 복소 비교의 정확 주파수/포트 대응/파 정의/기준면 조건을 재사용한다. 수치 차이는 비교 자료에서 기준 자료를 뺀 복소 값이며 비교 불가 이유를 표본별로 남긴다. 측정 기록/시료/교정/환경의 차이는 수치 비교 가능성과 별도 표시한다. 보간을 포함한 차이를 새 실측값으로 표시하지 않는다.

화면은 표본 최대 201개, 조건 최대 32개씩 조회한다. 보고서 저장은 전체 표본과 전체 조건 페이지를 모아 당시 source/pin/record 참조, 계산 영수증과 출처 원문을 고정한다. 과거 보고서 조회는 현재 설정이나 새로운 계산으로 갱신하지 않는다. `measurement.history`는 summary/points/conditions/lineage를 페이지로 반환한다.

S-parameter 파일만으로 방사 효율/절대 이득/방사 패턴을 실측했다고 표시하지 않는다. 실제 VNA/OTA/교정/시료 자료가 확보되지 않은 현재 사례는 미평가다. 수학 변환 시험과 프로그램 저장 검증을 물리 정확도 합격으로 확대하지 않는다.

## 6. 계산 출처와 기존 자료 호환

HOST 계산 Context가 단일 journal/저장소/이력/영수증을 소유한다. 변환/RLC/평가/비교/측정 정렬은 닫힌 JSON 입력의 별도 수학 worker를 사용한다. 제어 코드와 실제 수학 코드의 source 합집합을 같은 실행 identity에 고정하고 원문 바이트도 저장한다. 두 profile로 나누어도 합집합 전체의 192개/4 MiB 상한을 적용한다.

로딩 당시 source와 디스크가 달라지거나 source를 고정하지 못한 경우 새 계산/게시를 차단한다. 이전 기록 조회/저장/재열기와 진행 중 작업의 취소는 가능한 범위에서 유지한다. 기존 결과에 새 실행 영수증이 있었다고 소급 기록하지 않는다. 계산 영수증은 operation/input/identity/result hash이며 자료 수입의 parser 성공을 수학 worker 실행으로 위장하지 않는다.

측정 registry를 포함한 새 프로젝트 후보 복사는 아직 지원하지 않는다. 복사 범위 밖의 측정 artifact를 조용히 버리지 않고 명시 차단한다. 기존 원본 프로젝트의 기록/해석/비교는 계속 보존한다.

## 7. API와 조회 페이지

요청은 `rfad.api/2.0` 봉투의 `context.project_id`와 해당 `input`을 사용한다. 변경에는 영수증 키와 epoch를 포함한다.

| 메서드 | 입력의 핵심과 결과 |
| --- | --- |
| `measurement.context` | 현재 또는 명시 `revision_id`, 기록 `offset/limit`. 생성 개정의 각 기록 ref와 첨부/정렬/비교 목록을 반환 |
| `measurement.get` | `record`에 ID/SHA-256/개정. 원래 기록, source/pin, 복소 표본, 폼과 원래 입력을 반환 |
| `measurement.preview` / `measurement.apply` | `expected_revision`, `draft_time_utc`, `operation`, `parameters`. 적용에는 `command_id`, `review_hash` 추가 |
| `measurement.align` | `measurement.apply`와 같은 봉투에 `operation=align`. 수량 입력은 `text/unit/source_refs`로 제출 |
| `measurement.compare` / `measurement.conditions` | 양쪽 `source/pin/record` 고정. 비교는 포트 순서, 행/열, `exact_only` 주파수 정책과 페이지를 명시 |
| `measurement.history` | 컬렉션과 고정 record ref, summary/points/conditions/lineage, offset/limit |
| `measurement.quantity` | 필드 경로, 원래 canonical 값이나 입력, 선택 표시 단위 |
| `measurement.attachment.add` / `measurement.attachment.read` | 역할/이름/MIME/base64/SHA-256을 게시하거나 등록된 ID와 offset/limit로 읽기 |
| `measurement.receipt` | 원래 접수 키와 epoch. 확인됨, 만료, 결과 불명을 구분 |
