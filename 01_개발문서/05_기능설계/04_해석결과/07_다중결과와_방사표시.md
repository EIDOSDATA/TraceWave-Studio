# 다중 결과, Smith와 방사 표시 계약

개발 완료 계획 7번의 공통 조회 계약이다. 설계 기준선 RFAD-D0-3.4와 기존 완료 계획 번호를 유지한다. 2026-11-17 작성 중이며, 전체 서비스와 GUI 통합 검증은 별도 실행 기록에 확정한다. 이 문서의 기능 설계만으로 검증 완료를 주장하지 않는다.

기존 [공통 복소 자료](06_공통복소자료와_회로평가.md), [PCB 방사 계산](04_사용자기판_방사계산.md), [명시적 스윕](../06_연구/01_명시적스윕과_실행계약.md)을 이어서 사용한다. 결과를 읽기 위해 새 FDTD, 회로 계산이나 목표 평가를 자동 실행하지 않는다. 화면 배치는 [다중 결과 화면 계약](../../04_화면설계/21_다중결과와_방사필드_화면.md)을 따른다.

## 1. 결과의 선택과 원본 고정

공개 읽기 API는 `rfad.api/2.0`, `context={project_id}`를 사용한다. `source`는 다음 세 종류 중 하나다.

| 종류 | 필수 선택 | 실제 원본 |
| --- | --- | --- |
| `network` | `dataset_id`, `revision_id`, `snapshot_id` | 선택 개정의 불변 library 자료. snapshot_id는 명시 사본을 선택할 때만 UUID, 나머지는 null |
| `solver` | `artifact_id` | 해당 프로젝트에 등록된 실제 완료 해석 record와 normalized 및 봉인 snapshot |
| `sweep` | `study_id`, `index` | 저장된 연구 후보의 실제 dataset과 원래 계산의 snapshot/결과 참조 |

현재 개정을 암묵적으로 가리키는 source alias는 없다. 카탈로그에서 현재 개정을 선택하더라도 응답에는 그 시점의 실제 개정을 고정한다. 과거 개정이 없거나 손상되면 현재 자료로 대체하지 않는다. snapshot은 프로젝트 소유자, 개정, 실제 문서의 canonical hash와 artifact hash를 함께 확인한다.

`result.describe`가 반환한 `pin={identity_hash,dataset_sha256}`을 표본, 마커, Smith, 비교, 전력, 방사와 필드 요청에 사용한다. 선택과 내용이 달라지면 조회를 거절한다. 이후 설계를 편집해도 과거 결과는 읽을 수 있으며 현재 개정과 다르다는 상태를 표시한다. 늦은 응답을 현재 선택의 값으로 채택하지 않는다.

스윕 후보는 현재 코드로 다시 생성하지 않는다. EM 후보는 실제 보존 snapshot과 결과를 사용하고, 회로 후보는 연구 당시 baseline 및 명시 후보 값과 계산 출처를 구분한다. 재사용 후보는 원래 계산 ordinal과 선택 ordinal을 함께 보존하며, 참조 순환과 evaluation key/hash 불일치를 거절한다.

현재 프로젝트 library의 해석 import라도 원본 normalized bytes, 같은 프로젝트의 solver record 및 같은 복소 dataset 투영이 일치할 때만 방사/필드를 연결한다. RLC 결합, S/Z/Y 변환이나 조건 수정의 파생 자료에는 원래 안테나의 효율/패턴을 자동 승계하지 않는다. 원래 해석 파일에 이르는 연결이 없으면 해당 표시가 불가능한 이유를 안내한다.

과거 `solver-artifacts/<UUID>/...` 저장 경로를 프로젝트 폴더 밖이라는 이유만으로 버리지 않는다. 먼저 journal의 소유 record와 실제 snapshot을 확인하고, 그 record에 등록된 정확한 artifact 참조만 읽는다. 임의 경로나 다른 프로젝트의 산출물을 source로 받지 않는다. 기존 자료를 새 저장 형식으로 소급 이동하지 않는다.

## 2. 카탈로그, 네트워크와 비교

`result.revisions`는 사용자가 읽을 수 있는 개정 이름과 설명, 당시 시간을 제공한다. `result.sources`는 network/solver/sweep를 구분하고 한 번에 최대 25개를 조회한다. 연구는 특정 study를 명시한다. 여러 연구의 큰 후보 결과를 한 응답에 중복하지 않는다. 카탈로그 해시가 바뀌면 이전 페이지를 현재 목록에 이어 붙이지 않는다.

`result.page`와 `result.marker`는 실제 복소 표본과 원래 missing/singular 상태를 보존한다. 한 페이지는 최대 201개다. 마커 주파수가 원문에 없으면 `found=false`이며 가장 가까운 표본이나 보간값으로 바꾸지 않는다. 표와 그래프의 주파수 단위는 전체 자료 범위를 기준으로 Hz/kHz/MHz/GHz를 사용하고 페이지 전환으로 바꾸지 않는다. 원본 Hz 수치와 해시는 그대로다.

`result.compare`는 두 개의 고정 source/pin과 명시 포트 대응을 받는다. 화면의 최대 8개 자료는 유한한 쌍별 조회로 구성하며 한 응답에 모든 행렬과 원문을 중복하지 않는다. 비교 정책은 `exact_only`다. 공통 주파수, 같은 S/Z/Y 종류, 확인된 파/시간 규약, 포트 모드/전류 방향/기준면 및 대응 포트의 동일한 Z0가 수학 비교 조건이다. 조건을 충족하지 않으면 각자의 곡선을 읽을 수 있어도 차이값을 만들지 않는다. 다른 포트를 임의 정합하거나 포트 수를 줄이지 않는다.

설계 형상이나 재료가 다른 것은 연구 비교의 정상적인 경우다. 설계 조건 차이를 수학적 비교 가능성 및 물리 검증 상태와 분리한다. 조건 표는 항목/왼쪽/오른쪽/단위/상태/영향을 표시한다. 같은 복소 수학 기저라는 사실이 서로 다른 제작 조건의 물리적 동등성을 보장하지 않는다. 기준면이나 파 정의가 미정이면 확인된 조건으로 추정하지 않는다.

과거 목표 평가는 평가 당시의 목표와 데이터에 계속 연결된다. 현재 목표가 달라졌다는 표시와 저장된 판정은 별개다. 비교 화면을 여는 것만으로 현재 목표에 재평가하거나 과거 판정을 수정하지 않는다.

`result.export`는 고정 source/pin의 실제 dataset을 기존 CSV/Touchstone/정규 HDF5 serializer로 내보낸다. 보존 원문은 실제 대응 파일이 있을 때만 제공한다. 가용 형식과 실제 거절 이유를 표시하고, 과거 결과를 현재 library에 추가하거나 새 계산을 실행하지 않는다. 응답 원문 512 KiB와 출처를 포함한 900 KiB 상한을 유지한다. sidecar에는 당시 자료/조건/개정/평가와 선택 pin을 보존한다. GUI는 두 임시 파일 준비 후 새 파일 게시와 실패 회수 경로를 사용하고 기존 출력이나 workspace 원본을 덮지 않는다. 두 파일은 순차적으로 게시하므로 전원 손실까지 파일 쌍의 원자성을 보장하지 않으며 해당 복구 수용은 12번에서 확인한다.

## 3. Smith 표시

`result.smith`는 확인된 S 대각 채널, 실수 양수 Z0, 지원하는 파/시간 규약과 명시 포트를 사용한다. 입력 임피던스와 어드미턴스는 서비스가 계산한다. GUI는 반환한 Gamma와 격자를 그린다.

다중 포트의 Sii에서 얻는 입력 임피던스는 다른 포트를 해당 Z0로 정합한 조건의 값이다. 이를 Z 행렬의 Zii로 표기하지 않는다. 포트 기저와 정합 조건이 불명확하면 수치를 만들지 않는다. 일반 복소 Z0의 power/pseudo/traveling 파 변환은 이 실수 Z0 표시 profile과 동일한 공식으로 처리하지 않는다. 일반식의 차이는 [scikit-rf 공식 s2z 문서](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.network.s2z.html)를 참고한다.

Gamma=1의 개방, Gamma=-1의 단락, Gamma=0의 정합과 유한/정의 불가/overflow를 구분한다. 분모가 작은 값을 임의 epsilon으로 개방이나 단락에 합치지 않는다. 단위원 밖의 유한 값은 능동 또는 검토 대상 상태로 보존하며 단위원에 잘라 붙이지 않는다. 화면 범위 때문에 일부 점이 보이지 않으면 제외 개수를 알린다.

임피던스/어드미턴스 격자 선택과 각 마커에는 실제 주파수, Gamma RI, 정규화 값, 실제 ohm/S 값, Z0 및 원본 표본 상태가 연결된다. 격자 원호와 곡선 연결은 표시 도형이며 추가 측정점이 아니다.

## 4. 전력과 효율

`result.metrics`는 같은 계산에 봉인된 NF2FF와 선택적 독립 손실을 읽는다. 포트 대역 표본은 `result.page`, 방사 효율 표본은 실제 NF2FF 기록 1~3개로 분리한다. S11만 있는 자료에는 방사 효율을 만들지 않는다. 한 주파수 기록을 전체 대역 곡선으로 늘리지 않는다.

| 항목 | 정의 또는 원본 | 상태 |
| --- | --- | --- |
| 입사/수용/방사 전력 | 동일 펄스 Fourier 스펙트럼의 실제 값 | `W*s^2`, 절대 W는 null |
| 반사 전력 | 입사 - 수용 | 음수도 보존하고 검토 가능 |
| 방사 효율 | 방사 / 수용 | 무차원 비율, 표는 % |
| 총 효율 | 방사 / 입사 | 정합을 포함한 비율, 표는 % |
| 최대 지향성/이득/실현 이득 | 기존 검증된 방사 지표 | dBi, 계산/물리 검증 구분 |
| 유전체/도체/박막/비아 손실 | 해당 기록이 있는 독립 적분 | 기록되지 않으면 미기록 |
| 전력 수지 잔차 | 수용 - 방사 - 독립 흡수 | 부호와 수용 전력 대비 비율 보존 |

표의 각 항목은 값/단위/상태/분모를 포함한다. 효율 1 초과, 음수 손실과 큰 잔차를 정상 범위에 잘라 숨기지 않는다. 독립 적분 없이 수용과 방사의 차이를 유전체/도체에 임의 분배하지 않는다. 원문 normalized의 balance와 별도 power_balance artifact가 같은지도 검증한다.

원문 전력은 유한하지만 새 총 효율의 나눗셈이나 백분율 변환이 표현 범위를 넘을 수 있다. 이 경우 해당 파생 표시값만 null/overflow로 구분하며 원문 전력과 유한 비율은 유지한다. 큰 유한 값, 미기록 값과 표현 범위 초과를 같은 0으로 바꾸지 않는다.

`within_initial_numerical_budget`는 저장된 초기 수치 기준 상태다. 개별 손실의 독립 물리 정확도나 실측 합격으로 승격하지 않는다. RO4350B 국부 방사 도체 손실 변화 2.788446%의 초기 2% 기준 미확립 및 GHz PTH 손실의 독립 물리 정확도 미확립을 유지한다.

## 5. 3D 방사와 편파

`result.radiation`은 source/pin, 실제 frequency_index, theta 페이지, 관측량, 표시 척도/하한 및 명시 편파 기저를 받는다. 원본 theta/phi, 복소 Etheta/Ephi, normalized_power와 directivity를 그대로 제공하고 별도 projection을 추가한다. 원래 `solver.radiation` 계약은 변경하지 않는다.

각도는 theta=+z 극각, phi=+x에서 +y로 증가한다. `radius_m`와 `center_m`는 계산에 사용한 물리 좌표이고 projection의 xyz/radius는 무차원 표시 좌표다. CAD 형상 mesh와 혼합하지 않는다. 기본 총 패턴의 선형 반경은 `sqrt(normalized_power)`다. Etheta/Ephi/RHCP/LHCP도 같은 총 전계 표본 peak로 정규화하여 관측량을 바꿀 때 각 성분을 각각 1로 확대하지 않는다.

선형 진폭 또는 dB 진폭을 선택한다. dB 하한은 -120~-10 중 명시 값, 기본 -40이다. 영전계는 실제 dB가 -infinity인 상태와 화면의 하한 적용을 구분한다. 바닥으로 잘린 표시는 `clipped`로 알리고 원래 값은 남긴다. phi 이음면과 인접 각도 사이의 mesh/색 보간은 화면 표시이며 RF 표본을 추가한 것이 아니다.

방향별 directivity/gain/realized_gain도 선택할 수 있다. 이때 반경은 계속 총장 peak의 정규화 모양이고 색은 해당 방향의 실제 선형 값 또는 dBi다. `quantity_linear`, `quantity_db`와 별도 `color_unit/color_range`를 사용한다. 정규화 반경의 dB와 절대 지향성/이득 dBi를 혼동하지 않는다. 색의 dB 하한은 해당 지표 peak에 상대 하한을 더해 정하며 원래 방향별 수치는 유지한다.

한 요청의 theta_limit은 1~5지만 응답 128 KiB 상한에 따라 실제 반환 행이 더 적을 수 있다. 클라이언트는 returned_count와 next_offset을 사용한다. 주파수 최대 3개, theta 최대 37개, phi 최대 72개라는 실제 기록 범위를 유지한다. 조회만으로 다른 각도나 주파수를 계산하지 않는다.

편파는 `exp(+j*omega*t)`, 바깥쪽 `e_r` 전파, 오른손 구면 기저와 openEMS 0.37.0의 `E_cprh`/`E_cplh` 정의를 명시한다.

```text
RH = exp(+j*phi) * (Etheta + j*Ephi) / sqrt(2)
LH = exp(-j*phi) * (Etheta - j*Ephi) / sqrt(2)
AR = (abs(RH) + abs(LH)) / abs(abs(RH) - abs(LH))
```

축비는 원형/타원형/직선의 무한 축비/영전계의 정의 불가/overflow를 구분한다. 성분이 0이면 상대 위상을 0도로 채우지 않는다. 기본은 theta/phi이며, co/cross 역할은 사용자가 `theta_co` 또는 `phi_co`를 명시했을 때만 붙인다. 특정 제품의 주편파 축을 자동 추정하지 않는다.

작은 타원 축의 소거를 피하려고 원본 float의 정확한 행렬식과 큰 특이값 제곱으로 축비를 계산한다. 실제 행렬식 0, 유한한 큰 축비와 float 표현 범위 초과를 별도로 표시한다. 입력을 더 정밀한 측정값으로 바꾸거나 원래 Etheta/Ephi를 보정하는 처리는 아니다.

[공식 NF2FF 문서](https://docs.openems.de/en/latest/python/openEMS/nf2ff.html)와 설치된 0.37.0의 nf2ff.py를 대조했다. 확인한 소스 SHA-256은 `f9efb634b16439e92ec398df8e92571374fc28ad0cc65237d10bd461255142e2`다. native HDF5 phi와 해당 판독기의 sin/cos는 float32이므로 원문 요청 degree에서 double로 계산한 새 표시 편파와 작은 반올림 차이가 있다. 이 차이는 검증 기록에서 따로 측정하며 native 복소 원문을 덮지 않는다. 같은 원문으로 판독기와 일치하는지 확인한 것은 독립 RF 물리 검증이 아니다.

## 6. 기록 필드의 단면

`result.field.describe/page`는 실제 봉인된 손실 검증용 E/J/rotH의 성분과 기록 주파수를 대상으로 한다. 일반 H, 시간 영역 monitor, 표면 전류나 NF2FF 폐곡면의 필드를 내부 체적 필드로 바꾸어 표시하지 않는다. 없는 관측량은 미지원 사유를 알린다.

원래 dump_mode=0의 Yee 성분은 서로 다른 위치에 있으므로 명시 재표본화 없이 Ex/Ey/Ez를 같은 위치의 벡터로 합쳐 abs(E)를 만들지 않는다. 성분별 실제 격자 좌표/shape, 단면 index와 선택 ROI를 보존한다. 주파수/공간 모두 exact_only이며, stride에 따라 생략한 위치와 미기록 값을 구분한다.

describe는 기록 역할/파일 hash, 주파수, 성분별 좌표와 지원 단면, 단위/정규화와 미지원 사유를 제공한다. page는 monitor/frequency/component, plane normal_axis/index, ROI와 stride를 받는다. 최대 4096점 및 256 KiB 안에서 원본 index/좌표, 복소수, magnitude/phase, 상태와 명시 색 범위를 반환한다. 필드마다 색 단위와 실제 범위를 표기한다.

HDF5는 원본 해시를 스트리밍 검증하고 경로/shape/dtype/link/filter/storage를 확인한 뒤 필요한 hyperslab만 읽는다. 전체 큰 필드를 GUI 응답에 넣지 않는다. pulse Fourier 성분을 입력 정규화 근거 없이 V/m 또는 절대 W로 바꾸지 않는다. dump 종류와 Yee 위치는 [CSXCAD 공식 dump 문서](https://docs.openems.de/en/latest/python/CSXCAD/CSProperties/CSPropDumpBox.html)를 따른다.

성분 좌표는 normalized에 보존된 실제 전체 격자 `mesh_statistics.lines_mm`와 기록 범위에서 읽는다. edge 끝의 다음 격자도 원문에서 확인한다. 과거 자료에 실제 격자가 없으면 명시 미지원이며 현재 격자 생성기로 복원하지 않는다. `color_scope=returned_page_magnitude`는 이번 반환 ROI의 크기 범위다. ROI가 다른 화면끼리 색만으로 절대 크기를 비교하지 않는다. rotH의 원문 시간 위치와 복소 위상을 유지하며, 손실 적분에 사용하는 시간/위상 보정을 필드 원문에 적용하지 않는다.

필드 읽기 전용 경계는 원시 파일당 64 MiB, 기존 심화 해석의 300만 격자점까지 지원한다. 어댑터도 직접 단면 읽기에서 4096점, 한 평면과 유한 성분·주파수 인덱스를 확인한다. 기존 계산 계획과 매니페스트의 한도는 적용된다.

단면 페이지는 최대 4096점을 배열로 구성하기 전에 검사하고, 반환하는 ROI 좌표만 위치 환산한다. HDF5의 원래 복소64를 표본 추출까지 보존한다. 캔버스는 실제 좌표와 서비스 색 값만 표시 상태로 구성하고, 마커는 View에서 유한 응답의 원래 복소값/위상을 유지한다. [실제 Windows 단면 조회](../../07_검증/65_실제_필드단면_검증.md)

## 7. 검증과 책임

View는 source 선택, 표시 상태, 표와 그래프, 카메라/확대 및 응답 수명을 관리한다. 단위 환산, 복소 계산, 기저/물리 조건 판단, 원본 해시와 영구 데이터는 서비스가 맡는다. Python은 필요한 읽기만 수행하고 UI가 정한 빈 상태를 실제 데이터처럼 저장하지 않는다.

수치 시험, 실제 과거 해석 산출물 조회, Windows GUI 및 저장/재열기 시험은 별도 항목으로 기록한다. 실제 원문을 시험용 workspace에 복사할 경우 원래 검증 workspace와 과거 기록을 수정하지 않는다. 서비스/GUI 성공을 연속 대역, 수렴, 물리, 제작 또는 측정 완료로 확대하지 않는다. 장기 3D 안테나 원본 형상과 full-wave 모델 범위는 이번 3D 방사 결과 표시와 별도다.
