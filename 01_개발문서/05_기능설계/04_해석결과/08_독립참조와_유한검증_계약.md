# 독립 참조와 유한 검증 계약

작성일: 2026-11-17. 적용 범위: 개발 완료 계획 8번의 고정 합성 RF 참조와 별도 판정 기록.

이 문서는 구현 계약이다. 실제 FDTD 실행 여부, 결과 오차와 실행 시간은 해당 실행의 검증 기록에서 확인한다. 이 문서 작성만으로 물리 수용을 선언하지 않는다. 승인 기준선 RFAD-D0-3.4, 과거 검증 결과와 참고 원문은 변경하지 않는다.

## 1. 목적과 범위

빈 참조 프로젝트의 봉인 snapshot을 기준으로 고정 PEC 다이폴을 준비하고 계산한다. 실제 사용자 PCB, 문헌 IFA, 제조사 물성 또는 측정 조건을 이 사례에 대신 소비하지 않는다. 계산과 별개로 독립 수식과 비교한 보고서를 새 불변 자료로 저장한다.

지원 상태는 다음과 같다.

| 구분 | 현재 계약 | 제외하거나 미확립으로 유지하는 사항 |
| --- | --- | --- |
| PEC 다이폴 | 명시한 내부 격자 3/2.5/2 mm의 세 수준, 공통 worker 준비/해석/후처리 | 임의 치수/추가 수준, 사용자 3D 안테나 편집 지원 |
| 평면 sheet 독립식 | 좋은 도체의 양면 대칭 slab 식을 순수 산술로 제공 | 실제 여기/경계가 닫히지 않아 native 3사례 실행 전 차단 |
| 새 유한 급전 IFA | 단면과 단자 미정 사유를 계획에 보존 | native 3사례 실행 전 차단, 임의 z 높이 또는 제작 치수 채택 |
| 독립 모델 비교 | 기존 초도 다이폴 기준과 실제 기록 표본의 비교 | 유한 반경 형상의 정확해, 제작/실측 정확도 |
| 격자 비교 | 세 수준 지향성/효율의 인접 상대 변화 관찰 | 새 격자 합격 한계의 사후 설정, 경계/시간 축 수렴 합격 |

RO4350B 사례의 편차 허용 결정과 PTH의 합성 접합 검증 범위는 [RF 연구 기록](../../06_분석연구/README.md)에 정리했다. 각 실행은 원래의 기준과 보고서 판정을 보존한다.

관련 현재 계약은 [해석 작업](02_해석작업_계약.md), [사용자 기판 단일 포트](03_사용자기판_단일포트_해석.md), [방사 계산](04_사용자기판_방사계산.md), [다중 결과 표시](07_다중결과와_방사표시.md)다. 여기서 정의하는 reference schema를 PCB schema로 바꾸어 저장하지 않는다.

## 2. 고정 사례와 단위

계획 profile은 `rfad.openems.reference-benchmark/0.1`, 실행 가능한 사례는 `pec-dipole-nf2ff` 하나다. `solver.plan`의 설정은 아래 두 키만 허용한다.

```json
{"case": "pec-dipole-nf2ff", "grid_mm": 3.0}
```

`grid_mm`는 3.0, 2.5, 2.0 중 하나다. sheet/유한 급전, 다른 값, 추가 필드는 명시적으로 거절한다.

| 입력 | 고정값 및 의미 |
| --- | --- |
| 공간/재료 | 진공, PEC. 제조 물성 또는 실제 구리가 아님 |
| 형상 | z 축 PEC 원통 두 개. 끝점 -30~-0.5 mm 및 0.5~30 mm, 반지름 1 mm |
| 급전 | z 방향 이상 lumped box. 시작 [-1,-1,-0.5] mm, 끝 [1,1,0.5] mm, 물리 저항 50 ohm |
| 기준면 | `ideal_lumped_gap_terminals`, 이동 0. 실제 커넥터 교정면으로 추정하지 않음 |
| 여기 | 중심 2.4 GHz, 폭 0.4 GHz의 Gaussian pulse |
| 기록 주파수 | 2.4 GHz 한 개. 대역 전체 평가 또는 연속 대역 검증이 아님 |
| 계산 종료 | 최대 30,000 timestep, 에너지 종료 비율 1e-5, exact end-criteria 사용 |
| 실행 | 고정 native 2 threads, 같은 서비스의 단일 해석 slot |
| PML | 여섯 면 PML_8. 바깥 +/-90 mm, 안쪽 +/-74 mm, 2 mm 셀 8개 |
| NF2FF | start [-60,-60,-60] mm, stop [60,60,60] mm, 중심 [0,0,0] m, 평가 반경 1 m |
| 각도 | theta 0~180 degree 간격 5, phi 0~355 degree 간격 5. 37 x 72 기록 표본 |

외곽 z 길이 60 mm에는 1 mm gap이 포함된다. 두 금속 팔의 길이는 각각 29.5 mm다. 이 유한 반경 형상은 2.4 GHz의 이상적인 무한히 가는 정확한 반파장 도선과 같지 않다. 기존 초도 합성 모델 정의를 보존한 비교 사례다.

세 격자에서 내부 정수배 좌표와 critical lines `[-60,-30,-1,-0.5,0,0.5,1,30,60]`을 합치고 PML 좌표를 고정한다. 계획상 각 축 선 개수는 71/81/95, 전체 점은 357,911/531,441/857,375다. 실제 준비에서는 CSXCAD가 반환한 좌표와 XML이 이 계획과 정확히 같은지 검사한다. 계획 수치는 native 준비/계산 결과로 표기하지 않는다.

## 3. 출처와 실행 식별

`AnalysisPlan`은 snapshot, 원본 프로젝트 사본, 고정 사례, 정규화, runtime identity와 자원 추정을 포함한다. `PreparedPlan`은 그 계획과 준비 artifact의 해시를 참조한다. 원래 프로젝트의 material/source/미정 조건을 변경하지 않는다. reference 프로젝트는 해석 가능한 사용자 형상을 대신 담는 용도가 아니다.

표준 `tools/openems_worker.py`와 `tools/wsl_supervisor.py`를 사용한다. `source_bundle`의 정적 의존 closure와 명시 profile을 그대로 적용하며 공통 192파일, solver 소스 4 MiB 상한을 유지한다. 임의 entry 교체, 전체 패키지 무조건 복사, 빈 runtime, 외부 설치 `rfad` fallback은 허용하지 않는다. [실행 소스와 환경 식별](../../03_아키텍처/06_실행소스_묶음과_환경식별.md)의 기존 읽기 호환 정책을 따른다.

별도 판정식의 식별은 `rfad.rf-assessment-source/0.1`이다. `rf_validation_plan.py`, `rf_validation_assessment.py`, `domain/rf_reference.py`의 원문 바이트 수와 SHA-256을 캠페인 정의에 고정한다. 판정 시 현재 파일 식별이 다르면 새 판정을 거절하고 새 캠페인 검토를 요구한다. 기존 보고서의 읽기는 계속 허용한다. 기준 지향성 1.6409와 허용치도 정의에 저장한다.

## 4. 공개 RPC와 화면 조회 흐름

모든 요청은 기존 `rfad.api/2.0` 봉투와 명시적인 `context.project_id`를 사용한다. 변경 요청은 공통 `request_key`와 `request_key_epoch` 영수증 계약을 따른다. 객체 식별자는 정규 UUID이며 캠페인/보고서의 프로젝트 소유권을 확인한다.

| 메서드 | input | 동작 |
| --- | --- | --- |
| `rf.validation.preview` | `expected_revision`, `name` | 현재 원본, 고정 정의, runtime과 평가식 식별의 검토 hash. 읽기만으로 snapshot을 게시하지 않음 |
| `rf.validation.create` | 위 필드와 `review_hash` | 같은 개정/환경/정의를 대조한 뒤 불변 정의와 snapshot 게시 |
| `rf.validation.list` | `offset`, `limit` | 현재 프로젝트 캠페인 목록 |
| `rf.validation.get` | `validation_id`, `report_id` | report_id=null이면 현재 실행 계획, UUID이면 명시한 과거 보고서 |
| `rf.validation.reports` | `validation_id`, `offset`, `limit` | 같은 캠페인의 불변 보고서 목록 |
| `rf.validation.advance` | `validation_id`, `case_id`, `phase` | 선택한 한 사례의 한 단계만 접수 |
| `rf.validation.cancel` | `validation_id` | 캠페인 작업에 취소 요청. 요청과 실제 종료 확인은 구분 |
| `rf.validation.assess` | `validation_id` | 보존된 실제 계산만 읽어 새 보고서 추가. FDTD를 실행하지 않음 |

페이지 limit는 1~25, 일반 응답은 256 KiB 이하다. 이름은 제어 문자가 없는 1~80자다. 전체 보존 캠페인은 16개, 캠페인별 보고서는 16개까지다. 보고서 본문은 128 KiB 이하다. 상한 초과 시 출처나 행을 조용히 삭제하지 않는다.

`advance`의 phase 순서는 `plan -> prepare -> solve -> postprocess`다. 내부에서 기존 `solver.plan`, `solver.prepare`, `job.submit`을 재사용한다. 선행 작업이 completed이고 자원 예약이 해제되어야 다음 단계를 받는다. 첫 solve 전에 같은 군의 모든 수준이 실제 prepare를 완료해야 한다. 각 사례의 각 단계는 한 번만 접수하며 자동 재시도나 네 번째 수준을 만들지 않는다.

현재 상태 조회와 선택한 과거 보고서는 분리한다. 최신 보고서 ID가 목록에 있더라도 조회 요청의 report_id가 null이면 과거 판정을 현재 상태로 섞지 않는다. 결과 화면은 저장된 solver source/pin과 해당 snapshot을 선택해 공통 복소, Smith, 방사·편파 뷰를 재사용한다. reference의 미기록 필드는 unavailable로 유지하고 PCB 자료를 자동 계승하지 않는다.

## 5. 유한 예산과 중단

캠페인은 세 군 각 3수준을 보존하되 현재 실행 가능한 군은 다이폴뿐이다. 차단된 sheet/유한 급전 6개를 다른 사례나 추가 수준으로 대체하지 않는다.

| 예산 | 누적 상한 |
| --- | --- |
| native solve 접수 | 9회 |
| worker 호출 | 27회 |
| analysis 단계 제한 합계 | 4,500초. solve와 최초 postprocess를 포함 |
| worker 단계 예약 합계 | 8,280초 |
| 캠페인 벽시계 | 10,800초. 최초 실행 이후 중단 시간을 포함하며 초기화하지 않음 |
| 논리 디스크 | 8 GiB. OS/WSL 가상디스크 allocated 크기의 측정 합격이 아님 |
| worker 출력 묶음/파일 | 128 MiB / 64 MiB |
| 예상 RAM | 1 GiB. OS hard limit 또는 실측 peak 수용값이 아님 |

다이폴 analysis는 사례당 300초, prepare/postprocess는 각각 120초이며 worker 호출마다 감독/종료 확인 60초를 예약한다. 현재 차단된 sheet에는 analysis 300초, 유한 급전에는 900초의 제안 예약을 남긴다. 전체 최대 예약 산식은 `4500 + 9*120 + 9*120 + 27*60 = 8280`이다. 상한은 완료 예상 시간이 아니며 모든 제안 사례가 실행 가능하다는 약속도 아니다.

디스크 예약은 host 계획마다 8 MiB, native 단계마다 672 MiB다. 후자는 host/guest 입력 두 사본과 출력/봉인 세 사본의 각 최대 128 MiB에 source/명세 여유 32 MiB를 더한 보수적 예약이다. 실제 측정 사용량으로 표시하지 않으며 실패나 재개 후 환급하지 않는다. 정의/snapshot/보고서 바이트도 누적 보존 비용에 포함한다.

slot 공유는 동일 `ProjectService` workspace의 보장이다. 서로 다른 workspace 전체의 전역 lock으로 주장하지 않는다. 실제 guest 종료가 불명이면 기존 solver 예약을 유지하며 다음 작업을 시작하지 않는다. 취소한 캠페인은 자동 재개하지 않는다. 환경이 달라진 캠페인의 실행도 거절하지만 과거 보고서는 runtime 없이 읽을 수 있다.

## 6. 정규화와 산출물

포트 raw는 `2*dt*sum(value*exp(-j*2*pi*f*t))`를 유지한다. 전압은 V*s, 전류는 A*s다. 이를 임의 RMS나 정현파의 절대 전력으로 바꾸지 않는다. 기록한 native 전류의 Yee 시간축도 그대로 소비한다.

```text
U_inc = (U + R*I) / 2
S11 = (U - U_inc) / U_inc
Z = U / I
P_acc_spectral = 0.5 * Re(U * conj(I))
```

유효 여기·전류, 유한 표본과 양의 정규화 전력을 확인한다. 한 여기로 얻는 S11과 입력 임피던스만 제공하며, S21 또는 완전한 다중 포트 행렬을 채우지 않는다. VSWR은 abs(S11)<1에서만 정의하고 그 밖은 명시 상태로 둔다.

정규화 결과 schema는 `rfad.openems-reference-result/0.1`, 방사 결과는 `rfad.reference-radiation/0.1`이다. 방사 전계는 V*s/m, spectral power는 W*s^2이며 `absolute_power_w=null`이다. 효율/지향성/이득은 같은 여기의 공통 배율이 상쇄되는 비율이다. 1을 넘는 효율이나 불일치를 잘라 합격값으로 만들지 않는다.

필수 raw는 `port_ut_1`, `port_it_1`, 두 native 통계 파일, `native.log`, `reference.xml`, 여섯 면의 E/H HDF5 12개다. `raw_manifest`는 계획, PreparedPlan, 실제 XML, 실행·로딩·종료 근거와 각 파일 바이트/hash를 결합한다. 후처리 전용 작업은 등록된 같은 PreparedPlan의 `raw_result_id`만 받는다. 외부 raw-stage 경로나 미검증 HDF를 끼워 넣지 않는다.

`converged=true`인 기존 정규화 assessment 필드는 native 에너지 종료 계약의 확인이다. 독립 격자/경계/시간 수렴을 확립했다는 뜻으로 사용하지 않는다. 별도 보고서의 검증 상태와 `physics_validated=false`를 함께 표시한다.

## 7. 별도 판정과 수학적 근거

### 7.1 이상 반파장 다이폴

정현파 전류, 가는 도선, 자유공간 원거리장 모델의 정규화 전력은 다음과 같다. theta=0/180 degree에서는 해석적 극한 0을 쓴다.

```text
P_normalized(theta) = (cos((pi/2)*cos(theta)) / sin(theta))^2
D_reference = 1.6409
```

근거는 [Toronto University, Half-wave Dipole](https://radiance.ece.utoronto.ca/ece422/notes/07-halfwave.pdf)의 전류 적분과 원거리장 식이다. 정규화 전력식은 전계 크기의 제곱이며 구면 적분으로 지향성을 확인할 수 있다. 유한 반경 native 형상의 정확해와 구분한다.

기존 초도 기준을 그대로 사용한다.

| 비교 | 오차 | 상한 |
| --- | --- | --- |
| phi=0 기록 절단면 패턴 | 정규화 전력 최대 절대 차이 | 0.15 |
| 지향성 | abs(D/1.6409-1) | 0.10 |
| PEC 방사 효율 | abs(efficiency-1) | 0.15 |

전체 phi 최대 오차는 추가 관찰값이다. 기존 phi=0 기준에 새로운 전체 phi 합격 조건을 사후 추가하지 않는다. 세 수준의 지향성/효율 인접 변화율도 `observed`이며 별도 합격 한계는 null이다. RO4350B 국부 손실의 2%를 다른 관측량에 자동 적용하지 않는다.

### 7.2 양면 대칭 sheet 독립식

선형/균질/등방 평면 도체, 변위 전류를 무시하는 좋은 도체, 양면 대칭 여기와 `exp(+j*omega*t)` 조건에서 다음을 사용한다.

```text
omega = 2*pi*f
delta = sqrt(2/(omega*mu*sigma))
gamma = (1+j)/delta
Z_sheet = gamma/(2*sigma) * coth(gamma*t/2)
P_per_area = 0.5 * Re(Z_sheet) * abs(K_peak)^2
```

K는 양면을 합한 peak 표면 전류 밀도다. [MIT, Circuits, Transmission Lines, and Waveguides](https://fab.cba.mit.edu/classes/862.25/notes/circuits.pdf)의 도체 확산식에 대칭 slab 경계 조건을 적용한 유도이며, 이 완성식을 원문의 직접 인용이라고 표시하지 않는다. 저주파 극한은 `1/(sigma*t) + j*omega*mu*t/12`, 충분히 두꺼운 slab은 두 반공간 표면의 병렬 임피던스에 접근한다.

산술 함수가 값을 계산했다는 사실은 실제 native 여기/경계의 적합성을 입증하지 않는다. conducting-sheet fitted 계수나 동일 native 출력에서 정답을 역생성하지 않는다. 현재 캠페인은 이 물리 fixture가 확정되지 않았으므로 세 sheet 사례를 `blocked_before_execution`으로 남긴다.

## 8. 미정 유한 급전과 기존 결과 보존

설치된 고정 openEMS의 `LumpedPort`는 `caps=True`와 단면 중앙 전압선, dual-mesh 전류 폐곡선을 만든다. cross-axis 폭이 0이면 전류 probe가 인접 dual line으로 확장한다. 내부 primary line의 zero-z 단면에서 유효 폭은 `(delta_z_below + delta_z_above)/2`다. x 폭만 고정해도 z 이산 단면은 고정되지 않는다. [고정 포트 소스](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/python/openEMS/ports.py), [전류 적분 소스](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/Common/processcurrent.cpp)

pure R는 실제 edge 면적/길이의 직병렬 합에 맞춰 정규화되므로 지정 R 자체가 격자 폭에 비례해 바뀐다고 설명하지 않는다. 반면 공간적 여기/적분/기존 유전체 용량은 다른 문제다. 자동 캡 이후 conducting-sheet extension이 겹친 edge 계수를 다시 계산할 수 있어 caps 설정만으로 최종 PEC 접촉을 보증하지 않는다. [고정 연산자](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/FDTD/operator.cpp), [sheet extension](https://github.com/thliebig/openEMS/blob/305df56aa7df4d2f18c687083f484a96f9a22610/FDTD/extensions/operator_ext_conductingsheet.cpp)

새 유한 급전의 x 폭, z 높이/배치, 단자 면·접촉, 최종 재료 우선순위와 source/PEC/손실 제외 영역은 미정이다. 현재 점/선 기반 PCB 접촉 검사만으로 이를 수용하지 않는다. 새 모델을 고정하더라도 과거 N8과 같은 수렴열로 합치거나 기존 실패를 대체하지 않는다.

## 9. 보고서 상태와 영구 저장

캠페인 정의와 보고서는 workspace journal의 소유 레코드와 불변 artifact로 보존한다. 보고서는 원래 normalized/raw를 수정하지 않으며, source/pin, snapshot, fixture/runtime hash, 실제 원본 참조와 판정 시점을 함께 담는다. 일반 프로젝트 파일만 별도 복사하는 행위가 이 workspace 실행 자료 전체의 교환을 보장하지는 않는다.

| 상태 | 의미 |
| --- | --- |
| `blocked_before_execution` | 물리 입력/경계가 미정이어서 실행하지 않음 |
| `not_evaluated` | 해당 비교를 위한 성공 결과가 없음 |
| `within_preliminary_reference` | 명시한 초도 이상 모델 기준 안에 있음 |
| `requires_review` | 초도 기준 초과 또는 충분한 결과 없음. 이유와 실제 값을 보존 |
| `observed` / `observed_not_established` | 변화량을 관찰했으나 수렴 합격 한계/범위 미확립 |
| `identical` | 같은 원시 자료의 별도 후처리 결과가 같음 |
| `partial_evidence` | 캠페인 보고서의 범위 한정 상태. 전체 R1 또는 물리 검증 완료가 아님 |

제작·측정 조건은 null/unknown을 유지한다. 경계 조건 축과 시간 종료 조건 축의 독립 수렴은 별도 미확립이다. 보고서 선택/복사/재열기는 계산을 다시 실행하지 않는다.

## 10. 구현 위치와 검증 연결

- `Code/src/rfad/domain/rf_reference.py`: 독립 패턴/대칭 sheet 산술과 명시 적용 범위.
- `Code/src/rfad/application/rf_reference_contract.py`: 고정 사례, 계획/준비/결과 validator.
- `Code/src/rfad/adapters/solvers/openems/reference_benchmark.py`: 공통 worker의 실제 준비/해석/후처리. 공통 NF2FF 산술을 재사용한다.
- `Code/src/rfad/application/rf_validation_plan.py`, `rf_validation_records.py`, `rf_validation_execution.py`, `rf_validation_assessment.py`: 검토·영속 정의·유한 실행·별도 판정.
- `Code/tools/verify_nf2ff_reference.py`: 공개 서비스로 한 수준을 검증하는 CLI. `--prepare-only`는 solve를 접수하지 않는다. 구형 직접 entry는 실행을 거절한다.
- `Code/tests/test_rf_reference.py`: 독립 구면 적분, sheet 저주파/표피 극한, 미정·수치 범위와 상태 경계.
- `Code/tests/test_rf_reference_contract.py`, `test_rf_reference_worker.py`, `test_rf_reference_jobs.py`: 닫힌 사례/출처/계획, 원시 봉인, 미지원 분기, 공개 작업 게시와 runtime 없는 읽기.

시험 fixture의 가짜 포트/HDF 바이트와 전송 대역은 수명/계약 시험 근거이며 실제 FDTD 물리 결과로 표시하지 않는다. 실제 실행의 소스 식별, 준비 XML, 종료/실패, 오차와 후처리 동일성은 별도 검증 기록으로 연결한다.
