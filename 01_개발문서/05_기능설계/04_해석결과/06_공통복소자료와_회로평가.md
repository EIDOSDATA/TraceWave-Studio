# 공통 복소 자료와 회로 평가

분류: 기능 계약. 적용 기준: RFAD-D0-3.4, 개발 완료 계획 5번의 R1 범위.

원본 해석/측정 파일과 프로젝트의 직접 입력은 보존한다. 가져오기, 조건 채택, S/Z/Y 변환, 기준 임피던스 재정규화, 외부 이상 회로 결합, 목표 평가는 서로 다른 동작이며 새 자료와 근거를 생성한다. 이 문서는 계산 수식과 유한 자료 계약이다. GUI 저장/작업 흐름과 실제 시험 결과는 별도 화면 계약 및 검증 기록을 함께 확인한다.

## 1. 범위와 상태

| 항목 | 현재 계산 범위 | 구분할 한계 |
| --- | --- | --- |
| 공통 복소 자료 | S/Z/Y, 1~2포트, 1~1001개 주파수 | 여러 포트/혼합 모드/일반 회로 그래프는 후속 |
| 변환 | 명시 S/Z/Y 변환, S의 양의 실수 Z0 재정규화 | 복소/미정 Z0는 원본 보존 가능, 현재 계산 불가 |
| 외부 회로 | 1포트 복소 S/Z 부하와 이상 R/L/C, 직렬/병렬 1~16요소, 입사전력 기준의 이상 회로 소산 | EM 내부 소자, 기생 성분, 실제 부품 Q/ESR/ESL/SRF를 추정하지 않음 |
| 목표 | 정확히 일치하는 요구 표본의 S11/효율 부등식 | 표본 통과와 연속 대역/수렴/실물 검증을 구분 |
| FBW | 명시 S11 한계와 기준 주파수에 따른 통과 표본 폭 추정 | 임계 교차점과 연속 대역을 검증하지 않아 최종 합격은 미평가 |
| 효율 | 동일 네트워크 해시에 연결한 1포트 여기의 계산 비율 | 다중 포트 여기, 외부 정합 후 전자기장 결합은 후속 |

기하 생성 완료, 초기 추정, 해석 완료, 수치 수렴, 실물 검증은 이 기능의 수치 통과로 대체하지 않는다.

PCB 해석 계획은 프로젝트 검증을 통과한 복소 자료 목록과 정밀 편집 출처를 `source_semantics`에 그대로 보존한다. 이 메타데이터 자체를 EM 형상이나 내부 정합 소자로 투영하지 않는다. 알 수 없는 확장, 잘못된 출처 해시와 지원하지 않는 버전은 계속 차단한다. 프로젝트 개정 24 MiB와 별도 해석 계획 256 KiB 상한을 유지하므로 출처가 큰 계획은 삭제나 축약 없이 명시적으로 거절될 수 있다.

이 유한 profile의 지원은 승인 API-017/API-018 전체와 동등한 수용 완료를 뜻하지 않는다. 비교 작업 공간과 Smith/3D 방사는 완료 계획 7번, 독립 RF 참조/손실 정확도/수렴은 8번, 교정/기준면/시료/불확도를 포함한 측정 비교는 11번에서 이어간다. 여기서 측정 자료를 가져왔다는 사실만으로 실제 측정 조건이나 물리 정확도를 확정하지 않는다.

## 2. 공통 자료 계약

`rfad.network-data/0.1`은 다음 19개 필드를 정확히 갖는다. JSON 정규 자료 상한은 1 MiB다. API는 전체 대형 배열을 반복 전송하지 않고 표본 페이지를 조회한다.

| 필드 | 내용 |
| --- | --- |
| `schema` | `rfad.network-data/0.1` |
| `parameter_kind`, `unit` | `S`/`1`, `Z`/`ohm`, `Y`/`S` |
| `frequency_hz` | 0 이상인 유한 수, 중복 없이 증가, 최대 1001개. DC 자료 자체는 보존 가능 |
| `port_ids`, `port_names` | 원소 순서가 행렬 축과 같은 1~2개 고유 UUID 및 이름 또는 null |
| `values_ri` | `[frequency][outgoing i][incident j][real, imag]`; 없는 값은 null |
| `valid_mask`, `sample_status` | 같은 주파수/포트 축의 bool 및 상태 |
| `z0_ohm` | null 또는 `[frequency][port][real, imag]`; 포트별 null 허용 |
| `wave_definition` | `power`, `pseudo`, `traveling`, `unknown` |
| `phasor_convention` | `exp(+j*omega*t)`, `exp(-j*omega*t)`, `unknown` |
| `reference_planes` | 포트별 기준면 원문 또는 null |
| `port_modes`, `current_orientation` | 포트별 `single_ended`/`unknown`, `into_dut`/`unknown` |
| `sample_origin` | 주파수별 `computed`, `measured`, `imported`, `derived`, `interpolated`, `unknown` |
| `provenance`, `conditions`, `source_refs` | 해석 근거 object, 조건 object 또는 null, 출처 참조 목록 |

`sample_status`는 `valid`, `missing`, `singular`, `ill_conditioned`, `unsupported`, `outside_validity`, `nonfinite` 중 하나다. `valid_mask=true`와 `status=valid`는 서로 일치해야 한다. 비유효 셀에 원문 유한 수가 남아 있어도 계산에서 유효값처럼 사용하지 않는다. 원문 NaN/Infinity를 정규 JSON의 수치로 저장하지 않는다.

출처/조건은 각각 최대 64 KiB의 유한 JSON이다. 깊이 16, object 128개 필드, 목록 1001개, 문자열 4096문자 상한을 적용한다. 큰 출처를 조용히 삭제하지 않고 저장 전에 차단한다. 기존 제작/납품/측정 조건의 null, 사용자의 이름 및 입력 출처를 유지한다.

Touchstone/CSV의 `imported`는 실제 측정 확인을 뜻하지 않는다. 원문에 없던 기준면과 시간 규약을 가져오기 단계에서 만들어내지 않는다. 별도 명시 조건 채택은 원문과 채택 근거를 나누어 기록한다.

## 3. S/Z/Y 변환과 재정규화

승인 수식 EQ-010/EQ-012 및 [수식과 물리 모델](../../02_시스템명세/04_수식과_물리_모델.md)을 따른다. 제품의 행렬 역변환은 고정 scikit-rf를 호출하고, 독립 잔차로 결과를 검사한다. 파/포트/전류/기준면이 미정이면 계산을 차단한다. 주파수 보간, 포트 재배열, 기준면 이동은 변환 요청에 포함되지 않는다.

양의 실수 Z0에서 power/pseudo/traveling 정의가 일치하는 범위만 계산한다. 원문 파 정의는 보존하고 엔진 호출에는 실수 Z0를 명시한다. 라이브러리 기본 50 ohm을 이용하지 않는다.

`transform_dataset(data, options)` 입력은 아래 중 하나다.

```json
{"operation": "convert", "parameter_kind": "Z"}
```

```json
{"operation": "renormalize", "z0_ohm": [[[75.0, 0.0]]]}
```

두 번째 입력의 Z0 배열은 입력 자료의 주파수/포트 축 전체를 명시한다. 반환은 `{dataset, diagnostics, engine}`다. 재정규화는 S -> Z -> S 경로이며 기준면은 바뀌지 않는다. 이 경로에서 개방 등 중간 변환이 특이하면 해당 표본을 특이 상태로 남긴다. 큰 유한 저항으로 대체하여 통과시키지 않는다.

각 변환은 분모 행렬의 특이값/조건수와 독립 상대 잔차를 검사하고, 상태/조건수/잔차를 진단에 기록한다. 특이값 배열 자체는 현재 진단 출력에 포함하지 않는다. 현재 조건수 상한은 `1e9`, 잔차 상한은 `1e-8`이다. 엔진의 미소 고유값 보정이 개입할 수 있는 절대 특이값 `1e-12` 이하도 차단한다. 이 수치는 현재 유한 계산 profile의 수치 거절 기준이며 물리 정확도/수렴의 합격 기준이 아니다. overflow, 특이값, 비유효 입력은 마스크와 이유로 반환한다.

파생 자료에는 입력 canonical SHA256, 명시 옵션, 엔진 버전/정책, 원래 표본 종류를 보존한다. 연산 출처는 최대 32단계며 이전 출처를 잘라내서 계속 적용하지 않는다.

서비스의 상수 Z0 입력은 `{operation: renormalize, reference: {text, unit, source_refs}}` 또는 reference에 기존 Quantity를 받는다. 서비스에서 모든 표본/포트에 같은 SI 값을 적용한 배열로 해석하며, 파생 연산의 `original_options`와 `reference_quantity`에 입력 원문과 표시 단위/상태/출처를 별도로 보존한다. 배열로 환산했다는 이유로 새 입력의 근거를 버리지 않는다. 현재 GUI는 ohm 고정 입력이며 빈칸을 기본값으로 두고, 새 출처 입력란이나 포트별/주파수별 Z0 편집은 제공하지 않는다.

S/Z/Y 변환과 실수 Z0 재정규화는 원래 phasor_convention을 그대로 유지한다. 시간 규약이 unknown이라는 이유만으로 부호를 정하거나 변환을 차단하지 않는다. 주파수에 따른 j 성분을 생성하는 외부 RLC 계산은 아래의 명시 시간 규약이 필요하다.

공식 API/수식 근거:

- [scikit-rf S -> Z와 파 정의](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.network.s2z.html)
- [scikit-rf Z -> S](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.network.z2s.html)
- [scikit-rf 재정규화](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.network.renormalize_s.html)

## 4. 외부 이상 RLC 계약

`validate_circuit(definition)`은 엔진 없이 정의를 검증한다. `apply_circuit(data, definition)`은 실제 엔진을 지연 호출하여 `{dataset, diagnostics, engine}`을 반환한다.

```text
schema: rfad.ideal-rlc/0.1
name: 사용자 이름
em_scope: outside_em
input_reference_plane: 회로 입력 기준면 원문 또는 null
load_reference_plane: 원본 부하 기준면 원문 또는 null
elements: 1~16개, 입력에서 부하 방향 순서
source_refs: 출처 목록
assumptions: 가정 목록
```

각 요소는 `id`, `name`, `connection`, `kind`, `state`, `value`, `source_refs`를 갖는다. 연결은 `series`/`shunt`, 종류는 `R`/`L`/`C`, 상태는 `connected`/`open`/`short`/`dnp`다. 값은 기존 Quantity의 `value_si`, `dimension`, `display_unit`, `status`, `source_refs`를 그대로 사용한다. R은 impedance, L은 inductance, C는 capacitance 차원이다.

지원 표시는 ohm/kohm, H/uH/nH, F/uF/nF/pF다. 이 단위 추가 때문에 기존 표현식의 H/F/C/nH/pF 같은 변수 이름을 새 예약어로 바꾸지 않는다. RLC 정의는 literal Quantity이며 매개변수 연결은 별도 후속이다. 공통 Quantity의 L/C 차원은 기존 표현식 단위 조합 `ohm*s`, `s/ohm` 및 명시 binding에서 처리할 수 있다.

미정 소자값과 기준면은 저장 가능하다. 실제 결합에는 connected 소자의 양수 값, 알려진 시간 규약, 입력 기준면 및 원본과 같은 부하 기준면이 필요하다. 내부 EM 소자라는 선언이나 다른 기준면을 무시하지 않는다.

`exp(+j*omega*t)`에서 `Z_R=R`, `Z_L=j*2*pi*f*L`, `Z_C=1/(j*2*pi*f*C)`를 사용한다. 반대 시간 규약은 허수 부호가 반대다. 각 유한 소자는 scikit-rf의 직렬 임피던스/병렬 어드미턴스 2포트와 cascade로 결합한다. 여기서 모든 연결의 Z0는 같은 주파수의 원본 실수 Z0다. 일반 임의 그래프의 노드 소거나 역행렬을 새로 구현하지 않는다.

| 상태 | 직렬 | 병렬 |
| --- | --- | --- |
| open 또는 dnp | 입력에서 부하가 끊어짐 | 분기 제거 |
| short | 우회 연결 | 입력 접지 |
| DC의 L | short로 처리 | short로 처리 |
| DC의 C | open으로 처리 | open으로 처리 |

연결 분모가 특이하거나 불안정하면 결과 표본은 마스크 처리한다. 이상 소자의 DC/open/short를 `1e99` 같은 임의 수로 표현하지 않는다. 파생 자료의 기준면은 회로 입력 기준면으로 바뀌고 원래 부하 기준면과 요소 출처는 회로 사본에 남는다. 회로 해시와 전체 정의, 기생 성분 미제공, 전자기장 효율 미승계를 기록한다.

공식 근거: [SeriesImpedance](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.circuit.Circuit.SeriesImpedance.html), [ShuntAdmittance](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.circuit.Circuit.ShuntAdmittance.html), [cascade](https://scikit-rf.readthedocs.io/en/latest/api/generated/skrf.network.cascade.html).

복소 Z 부하는 명시 열 대응 CSV 또는 지원 HDF5에서 가져올 수 있다. 사용자가 선언한 양의 실수 Z0, 시간 규약, 기준면과 포트 대응을 사용한다. 내부 Z -> S 변환은 기존 복소 변환과 진단을 재사용한다. 입력 파일과 Z 데이터는 원래 형식으로 보존하며 결합 미리보기에는 정합 전 S11과 정합 후 S11을 각 기준면과 함께 표시한다. 지원 Touchstone 가져오기는 기존 S 범위를 유지한다.

같은 양의 실수 Z0의 파 정의에서 입사전력을 1로 놓는다. 부하 단독의 수용 비율은 1 - |Gamma_load|^2다. 이상 회로를 결합하면 각 요소에서 다음 단으로 향하는 파는 S21 / (1 - S22 * Gamma_downstream)을 곱해 구한다. 부하까지 전달되어 수용된 전력과 입력 반사전력을 빼면 이상 회로의 순소산이 남는다. 원본이 능동이거나 전력 수지를 평가할 수 없는 표본은 소산을 미평가로 둔다. 이상 회로 소산은 입사전력 대비 백분율로 표시한다. 실제 소자 손실, 방사 효율과 측정 조건은 별도로 평가한다. [파의 전력 정의 원문](https://ieeexplore.ieee.org/document/1125964/)

결합 자료는 원본 부하의 해시와 입력/부하 기준면을 보존한다. 표본별 Z 변환과 이상 회로의 소산은 봉인된 회로 진단 파일에 남는다. 정합 결과를 대상으로 저장한 목표 평가는 그 파일, 원본 부하와 회로 ID를 함께 참조한다.

## 5. 목표 평가와 효율

`evaluate_target(target, data, context, metrics=None)`은 목표 원본을 수정하지 않는 `rfad.target-assessment/0.1` 기록을 반환한다. 목표 ID/개정/hash, 자료 hash와 조건을 저장하므로 과거 목표와 평가를 현재 입력에 맞춰 다시 쓰지 않는다.

context는 `port_id`(자료 포트), `target_port_id`(목표가 원래 참조한 포트), `reference_plane`, `frequency_policy=exact_only`를 정확히 갖는다. 명시 포트 대응과 기준면, 양의 실수 Z0가 맞아야 수치 판정한다. 목표 Z0와 자료 Z0가 다르면 별도 재정규화가 필요하다.

목표의 `reference_plane`이 지정되면 평가 요청과 자료 포트 기준면이 저장된 이름에 일치해야 한다. 일치하지 않는 표본은 미평가와 이유를 기록한다. 목표 평가 화면은 저장된 기준면을 읽기 전용으로 표시하고, 목표에서 기준면을 미정으로 둔 경우에는 개별 평가 기준면을 입력받는다. [대역 목표 입력 계약](../02_설계편집/06_대역목표_입력계약.md#2-목표-원본)

목표의 linear/explicit 표본에서 정확히 같은 Hz 값을 조회한다. nearest, 소수 반올림, interpolation, 외삽을 묵시적으로 하지 않는다. 없는 주파수/마스크/미정 한계/미정 기준은 `not_evaluated`다. 실제 확인된 실패 표본이 있으면 다른 표본이 부족해도 `fail`이다.

각 criterion에는 원문 한계, 표본별 값/특수 상태/판정/이유, 필요한 표본 수/가능한 표본 수/누락 수가 있다. 모든 요구 표본 통과는 `sample_status=pass`, `status=conditional`이다. 전체 `continuous_band_verified=false`, `physics_validated=false`를 유지한다.

반사가 0이면 S11 dB는 음의 무한대, return loss는 양의 무한대, VSWR는 1이다. 반사 크기 1의 VSWR는 양의 무한대이고 1보다 큰 능동 반사의 VSWR는 정의 불가다. JSON에서는 비유한 숫자 대신 null과 `negative_infinity`, `positive_infinity`, `undefined_active` 상태를 쓴다. 반사 크기를 1로 잘라내지 않는다.

효율 metrics는 다음 필드를 가진 별도 입력이다.

```text
dataset_hash: 평가할 공통 자료의 canonical SHA256
source_refs: 출처 목록
physics_validated: false
frequency_hz: 증가하는 정확 표본
radiation_efficiency: 표본별 유한 비율 또는 null
total_efficiency: 표본별 유한 비율 또는 null
```

현재는 1포트 여기의 효율만 허용한다. 두 포트의 S 행렬 해시만으로 어느 포트 여기의 방사인지 알 수 없으므로 다중 포트 효율을 연결하지 않는다. 기존 PCB 방사 요약의 Prad/Pacc 및 Prad/Pinc를 같은 원본 자료에 연결할 수 있다. 펄스 Fourier 전력 단위 `W*s^2`의 공통 배율이 비율에서 상쇄되어도 절대 W 또는 실물 정확도가 확립된 것은 아니다. 비율이 0~1 밖이면 clipping 없이 미평가다. 서비스는 외부 정합/재정규화 등 파생 자료에 기존 효율을 연결하지 않아 해당 효율을 미평가로 남긴다. 도메인 계산에 다른 자료 해시의 효율을 직접 전달하면 E_HASH로 거절한다.

FBW는 목표의 명시 S11 한계와 기준 주파수가 있어야 표본 폭을 추정한다. 기준 주파수 자체가 통과 표본이어야 하고 그 점을 포함한 연속된 통과 표본들의 `2*(high-low)/(high+low)`를 `sampled_estimate`로 표시한다. 한계를 -10 dB로 자동 선택하지 않는다. 임계 교차점이 검증되지 않아 FBW criterion은 `not_evaluated`를 유지한다.

## 6. 파일과 불변 저장

정확한 지원 구문, 열 대응과 sidecar 계약은 [복소결과 파일교환](../05_출력교환/03_복소결과_파일교환.md)을 따른다.

공통 HDF5는 `[frequency, outgoing, incident, real_imag]` 축, little-endian float64, 무압축 contiguous 배열과 canonical metadata를 함께 보존한다. null/valid mask/표본 종류/Z0 존재 여부를 별도 배열로 대조한다. 현재 reader는 고정 `rfad.network-hdf5/0.1`만 받으며 임의 HDF5나 외부 링크/저장소/VDS/필터를 읽지 않는다.

Touchstone은 단일종단 S 1~2포트, Full, RI/MA/DB의 명시 profile이다. 1.0/2.0/2.1의 지원 구문만 읽는다. 원문 R 생략에 따른 규격 기본 50 ohm은 `spec_default` 출처로 구분한다. CSV는 사용자가 검토한 모든 열의 대응/무시 여부, 수치 표현과 단위를 명시한다. CSV를 측정 파일로 추정하지 않는다.

내보내기는 원본을 수정하지 않는다. 텍스트 파일에 표현되지 않는 기준면/위상/출처와 미정 상태는 sidecar와 저장한 원본에 남는다. 마스크 셀을 0으로 채우거나 실패 행을 지워서 출력하지 않는다. HDF5에는 null/mask를 그대로 보존할 수 있다. 서비스의 가져오기 및 아티팩트 상한은 파서의 독립 파일 4 MiB 상한과 구분한다.

프로젝트는 네트워크 자료/회로/평가 각각 최대 32개를 보존한다. 자료는 정규 JSON/HDF5와 원본 또는 부모 참조를, 회로는 불변 정의 사본을, 평가는 전체 판정 파일 참조를 저장한다. 가져온 자료와 기존 solver 자료에는 원본 bytes도 봉인한다. 파생 자료는 새 원시 측정 파일을 만들지 않고 부모 자료를 참조한다. 새 정의/참조는 원자 명령으로 추가하며 undo/redo는 계산을 재실행하지 않고 참조와 회로 정의를 복원한다. 네트워크 변경만으로 기존 CAD/solver 입력을 자동 변경하지 않는다.

## 7. 서비스와 원자 명령

API envelope는 기존 `rfad.api/2.0`을 사용한다. 모든 읽기/쓰기에 context.project_id와 input.expected_revision을 지정한다. 쓰기는 기존 request_key/request_key_epoch 영수증을 재사용한다. API profile은 `rfad.network-workspace/0.1`이다.

| 메서드 | input의 추가 필드 | 결과와 역할 |
| --- | --- | --- |
| `network.library` | 없음 | 자료/회로/평가 목록, 현재 목표/포트, 봉인 solver 결과 후보와 상한 |
| `network.get` | dataset_id, offset, limit, row, column | 원본 참조/조건과 실제 표본 최대 201개. 주파수 Hz, SI 복소수, dB/위상/VSWR는 서비스가 계산 |
| `network.preview` | operation, parameters | 읽기 전용 후보, can_apply, review_hash, 적용 불가 원인 |
| `network.apply` | operation, parameters, command_id, review_hash | 동일 후보 재계산 후 불변 파일과 참조를 하나의 명령으로 게시 |
| `network.quantity` | quantity, display_unit | SI/상태/출처를 유지한 Quantity와 표시 문자열. GUI에서 단위 환산하지 않음 |
| `network.diagnostics` | dataset_id, offset, limit | 전체 계산 진단 중 최대 32개와 봉인 파일 참조 |
| `network.assessment` | assessment_id | 과거 목표 평가 요약과 현재 목표 개정 변경 여부 |
| `network.assessment.points` | assessment_id, criterion, offset, limit | 기준별 실제 평가 표본 최대 201개 |
| `network.compare` | left_id, right_id, right_port_order, offset, limit, row, column | 아래의 같은 기준 비교. 원본은 변경하지 않음 |
| `network.export` | dataset_id, format | touchstone/csv/hdf5/source bytes의 base64, SHA256와 조건 sidecar |

preview/apply의 operation별 parameters는 다음과 같다.

| operation | 필수 parameters |
| --- | --- |
| import | name, file_name, format, source_base64, mapping, declarations |
| solver | name, artifact_id |
| transform | name, dataset_id, options |
| circuit_save | name, definition |
| circuit_apply | name, dataset_id, circuit_id |
| evaluate | name, dataset_id, target_id, context |
| remove | collection, id |

가져오기 원문 상한은 512 KiB다. 1 MiB NDJSON frame 안에서 `network.preview`/`network.apply`의 import parameters.source_base64만 이 크기의 base64 문자열을 허용한다. 다른 문자열의 기존 8192 byte 상한은 유지한다. CSV mapping은 파일 교환 계약을 따르고 Touchstone/HDF5에는 null이다. declarations의 원문 조건 사본은 UUID 생성과 사용자의 포트 대응을 적용하기 전에 저장한다. 원문에 없는 조건을 선언한 경우에도 원문 bytes와 원래 미정 상태는 바뀌지 않는다.

프로젝트의 선택적 확장인 `extensions.rfad.network-library`에 `rfad.network-library/0.1`을 저장한다. 종류별 최대 32개, 참조/회로 전체 128 KiB, 프로젝트 개정 24 MiB 상한이다. 자료 참조는 dataset JSON, normalized_hdf5, raw 또는 null, diagnostics 또는 null과 각각의 URI/SHA256/bytes를 갖는다. 부모 자료와 회로 ID는 삭제 시 참조 검사를 받으며 순환 출처를 허용하지 않는다. 회로 편집은 새 불변 정의를 만들어 과거 파생 결과가 참조한 정의를 보존한다.

회로 입력은 기존 Quantity를 그대로 받거나 변경한 필드의 `{text, unit, source_refs}`를 서비스가 해석한다. 빈 문자열은 missing으로 저장하며 0을 대입하지 않는다. 표시 단위만 바꾸면 원래 SI/출처/추정 상태가 유지된다. 검토한 circuit_display가 화면의 표시 값과 단위를 제공한다.

진단 전체는 별도 diagnostics.json에 봉인한다. 미리보기는 앞 8개, 전체 개수/원본 참조/페이지 조회 메서드를 명시한다. 목표 평가 전체와 평가 당시 목표 원본도 별도 assessment.json에 보존하며 화면 요약은 기준별 앞 8개 표본만 표시한다. 이를 전체 표본 또는 전체 대역 수용 결과로 표시하지 않는다. 응답 상한은 일반 조회 256 KiB, export와 sidecar 합계 900 KiB다. 상한 초과는 명시 오류이며 출처를 조용히 삭제하지 않는다.

평가 요약의 `frequency_min_hz`/`frequency_max_hz`는 봉인된 전체 요구 표본에서 읽은 표시 범위이며, 표본이 없으면 null이다. 화면은 이 범위로 주파수 단위를 고정하므로 201개씩 조회해도 단위가 바뀌지 않는다. 큰 목표 원문이 요약되거나 원문 입력이 표현식이어도 GUI에서 다시 계산하지 않으며, 이 읽기 응답을 만들기 위해 과거 봉인 파일을 수정하지 않는다.

현재 solver 투영은 봉인된 단일 포트 PCB의 원래 S11 실수/허수, 명시 실수 Z0/기준면/규약과 snapshot을 재사용한다. dB에서 위상을 추정하지 않는다. 도파관 등 대응을 검증하지 않은 profile은 차단한다. 일반 자료 조회와 프로젝트 저장/재열기/undo/redo는 선택 수치 엔진을 import하지 않는다. 새 자료의 검토/적용에서 정규 HDF5를 만들 때는 고정 h5py 환경이, S/Z/Y 변환과 RLC 계산에는 고정 scikit-rf 환경도 필요하다. 엔진이 없다고 기존 자료/회로/평가를 지우지 않는다.

## 8. 같은 기준 비교

`network.compare`는 명시된 오른쪽 포트 순서(right_port_order, 0부터 시작)를 왼쪽 행렬 축에 대응한다. 이름/UUID 일치를 추측하지 않으며 입력 자료를 재배열해 덮어쓰지 않는다. 복소 종류, 알려진 파 정의/시간 규약, 기준면, 모드/전류 방향과 각 표본의 Z0가 일치해야 비교 가능하다. 주파수는 왼쪽 표본과 정확히 일치하는 오른쪽 Hz만 찾는다.

같은 조건의 유효 표본은 왼쪽 - 오른쪽의 복소 차이와 두 원문 인덱스를 반환한다. 없는 주파수/미정 조건/마스크/비유한 차이는 `not_comparable`과 이유를 반환한다. 주파수 보간, 기준면 이동, 재정규화와 제조 조건 추정을 수행하지 않는다. 제조/측정 조건 object의 동일 여부는 별도 conditions_equal로 표시하며 같거나 둘 다 null이라고 실물 조건이 검증된 것으로 해석하지 않는다. 다중 곡선 중첩과 비교 작업 공간 전체는 완료 계획 7번에서 이 API를 재사용한다.

## 10. 검증 범위

실제 실행과 환경 제외, GUI 초기 실패/수정, 원문과 과거 결과의 저장/재열기 대조는 [단계 5 검증](../../07_검증/11_공통복소결과와_회로평가_검증.md)을 따른다.

독립 복소 임피던스식, 비대칭 2포트 및 서로 다른 Z0의 변환/왕복, 명시 재정규화, 특이/불안정 마스크, 원본 조건 불변을 검사한다. 회로는 직렬/병렬 저항, L/C 순서와 양쪽 시간 규약, DC/open/short/DNP 및 특이 연결을 검사한다. 목표는 완전 정합의 특수값, 부정확 주파수, 미정 한계/포트/기준면/Z0, 효율 원본 해시, FBW 표본 추정을 검사한다.

이 시험은 현재 수식/자료/프로그램 경계의 검증이다. 새 FDTD, 메쉬 수렴, 실물 측정 또는 개별 도체/유전체/PTH 손실 정확도 검증을 수행했다는 의미가 아니다. 최종 GUI 및 저장/재열기 검증 수치는 별도 실행 기록을 기준으로 한다.

## 군지연 조회

공통 결과 표본에서 군지연은 선택 S 채널의 인접 위상차와 원래 시간 위상 부호를 사용해 ns로 계산한다. 페이지 순번을 바꾸어도 같은 시료를 참조한다. 위상 규약이 미정이거나 인접 채널 값이 미정·영점일 때, 또는 인접 위상차가 180도인 경우에는 별도 상태를 표시한다. 표본 사이의 실제 위상 변화가 180도를 넘을 때에는 지연을 이 자료만으로 결정할 수 없다.
