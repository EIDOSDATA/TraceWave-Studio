# 후보 채택과 새 프로젝트 작업 사본

작성일: 2026-11-17

이 문서는 개발 완료 계획 9번 중 연구 후보를 새 프로젝트 작업 사본으로 채택하는 기능 계약이다. 서비스와 명시 원호/IFA의 실제 계산/사본 재계산 및 Windows GUI 재연결/조회 실패 경계의 자동시험을 확인했다. 실제 IFA 24 mm 후보의 Windows 사본 채택/저장과 runtime 없는 재열기, 설치 조건 미정 보존도 별도로 확인했다. 실행별 범위는 [9번 검증 기록](../../07_검증/21_후보채택과_원호아이에프에이_검증.md)을 따르며 이 기능 계약만으로 전체 RF/제작/실측 수용을 선언하지 않는다. 기존 [명시적 스윕](01_명시적스윕과_실행계약.md), [공통 결과 조회](../04_해석결과/07_다중결과와_방사표시.md), [프로젝트 명령과 저장](../01_프로젝트/01_프로젝트_명령과_저장.md)을 재사용한다.

## 1. 승인 요구와 적용 범위

승인 화면 설계 UI-18은 후보를 "새 작업 사본으로 채택"하도록 명시한다. 승인 API-002의 프로젝트 copy는 원본을 보존한 새 project ID를 생성한다. 이 단계는 원본 프로젝트의 활성 개정, 저장 기준과 undo/redo까지 보존하도록 새 프로젝트 작업 사본을 만드는 경로를 사용한다. 같은 프로젝트의 현재 개정을 자동 변경하는 동작으로 축소하지 않는다.

이 기능은 보존된 연구 후보의 명시적인 설계 채택이다. 지원 대상은 완료된 `grid_sweep`의 유효 후보이며, 변경 축은 기존 리터럴 설계 매개변수로 제한한다. 미실행/실패/미지원 후보를 현재 생성기로 재구성하여 완료 후보처럼 채택하지 않는다. 수치 조건 연구나 외부 회로 연구를 PCB 형상 변경으로 해석하지 않는다.

일반 `project.open(open_mode=copy)`, 임의 프로젝트 폴더 복제, 독립 archive 가져오기, 전체 실행 이력 이관과 동일하지 않다. 새 사본도 현재 workspace의 journal을 사용하는 프로젝트다. 새 프로젝트 폴더만 복사하면 독립적으로 열 수 있다는 의미가 아니다.

후보의 기하 생성, 초기 추정, 해석 종료, 목표 판정, 격자/경계/시간 수렴, 독립 물리 정확도와 실측 검증은 서로 다른 상태다. 목표를 만족하지 않거나 아직 평가하지 못했다는 사실을 사본 생성으로 바꾸지 않는다. RO4350B 국부 방사 도체 손실 변화 2.788446%의 초기 2% 기준 미확립, GHz PTH의 독립 정확도 미확립과 제작/측정 조건 미정을 유지한다.

## 2. 원본과 사본의 구분

| 대상 | 보존 규칙 |
| --- | --- |
| 원본 프로젝트 | current, saved, revisions, undo/redo와 이력 head를 그대로 유지한다. |
| 연구 기준 | 저장 당시 전체 snapshot과 원문/정규 연구 정의를 읽는다. 현재 편집 문서를 기준으로 바꾸지 않는다. |
| 선택한 후보 | 선택 ordinal, 축 인덱스와 원문 Quantity의 SI/표시 단위/상태/출처를 보존한다. |
| 실제 계산 | 계산을 재사용한 경우 실제 계산 ordinal과 source/pin을 선택 후보와 별도로 남긴다. |
| 새 작업 사본 | 새 프로젝트 ID와 새 경로를 사용한다. 객체 역할과 상호 참조는 유지하며 과거 사본의 UUID를 재귀 치환하지 않는다. |
| 과거 출처 | 템플릿 최초 생성 사본, 목표 개정, 정밀 편집의 전후 사본, 재료/기판 원문은 당시 내용과 해시를 유지한다. |
| 과거 결과 | 원래 계산 프로젝트/snapshot/설정/기준면의 결과다. 새 프로젝트에서 재해석하거나 재검증한 결과로 표시하지 않는다. |

같은 SI 값이지만 단위나 출처가 다른 후보가 계산을 공유할 수 있다. 이 경우 실제 계산 문서만 복사하여 선택 후보의 원문을 잃으면 안 된다. 선택 후보의 저장 값과 실제 계산 근거를 각각 검증하고 함께 기록한다.

## 3. 검토와 원자 적용

사용자가 연구와 후보를 선택한 다음 새 사본 이름, 저장 경로와 선택 사유를 검토한다. 미리보기는 파일, 프로젝트, snapshot이나 명령 이력을 만들지 않는다. 새 사본에 적용될 변수의 변경 전후, 읽기 전용 형상, 출처, 목표 판정과 미확립 조건을 먼저 보여 준다.

서비스는 프로젝트 소유권, 고정 연구 정의, 후보 기록, 결과 source/pin과 대상 경로를 검사한다. 검토 hash는 선택한 근거와 새 사본 입력을 결합한다. 이후 입력이나 근거가 바뀌면 같은 검토 hash로 적용하지 않는다. 최초 context의 이름/경로 제안은 사용자가 검토할 초안이며, 적용 도중 충돌한 경로를 덮어쓰거나 다른 이름/경로로 자동 변경하지 않는다. 이름과 채택 사유는 필수이며 사유는 최대 2048자다.

후보 값은 하나의 명령으로 일괄 적용하고 한 번의 undo로 되돌릴 수 있어야 한다. 여러 `parameter.set` 명령으로 중간에만 유효한 상태를 차례로 게시하지 않는다. 생성할 사본과 명령/역명령, 출처 참조와 접수 영수증은 같은 journal 게시 경계에 묶는다. 원본 프로젝트의 undo에는 사본 생성 명령을 넣지 않는다.

새 사본의 명시적 저장 기준은 채택 후 개정이다. undo 1회는 같은 새 프로젝트 ID/이름 아래의 연구 기준 사본으로 돌아간다. 새 프로젝트를 삭제하거나 원본 프로젝트로 전환하는 동작이 아니다. redo는 보존된 채택 명령을 다시 적용한다. 실행 취소 이후의 저장 상태는 채택 후 저장 기준과 다르므로 일반 프로젝트 저장 표시를 따른다.

### 3.1 공개 API

모든 요청은 `rfad.api/2.0`과 원본 프로젝트의 context를 사용한다. 변경은 기존 request key/epoch 영수증을 사용한다.

| 메서드 | 입력과 역할 |
| --- | --- |
| `sweep.selection.context` | `study_id`, `index`로 선택 후보의 고정 정의 hash, source/pin, 원본 예상 개정과 기본 사본 이름/경로를 조회한다. 프로젝트를 생성하지 않는다. |
| `sweep.selection.preview` | `expected_revision`, `study_id`, `index`, `definition_hash`, `source_pin`, `name`, `path`, `reason`을 검토한다. |
| `sweep.selection.apply` | 같은 입력에 `review_hash`, `command_id`를 추가하여 검토한 새 사본과 단일 채택 명령을 게시한다. |
| `sweep.selection.receipt` | 결과가 불명확한 원래 접수의 request key/epoch로 권위 영수증을 조회한다. 새 생성 요청을 만들지 않는다. |

GUI는 서비스가 제공한 `changes`, `scene`/`before_scene`, `states`, `historical_assessments`, `copy_summary`, `issues`를 표시한다. 변경 전후 표시값과 단위는 서비스 응답을 사용하며 입력 원문을 GUI에서 재구성하지 않는다. API의 JSON 키와 수명은 구현된 DTO를 기준으로 검사한다.

`found`인 영수증은 원래 접수 결과로 복구한다. `unresolved` 또는 `expired`는 생성 실패가 확인됐다는 뜻이 아니다. 확인되지 않은 상태에서 잠금을 풀거나 새 키로 같은 사본을 자동 생성하지 않는다.

## 4. 과거 계산과 현재 해석기의 경계

과거 후보 읽기는 현재 solver 설치나 현재 후보 생성기를 요구하지 않는다. 저장된 기준, 선택 값과 계산 원본을 읽어 검증한다. 현재 `candidate_at`으로 과거 후보를 다시 생성한 뒤 그 결과가 원래 계산 입력이었다고 가정하지 않는다.

보존된 선택 Quantity를 기준 문서에 일괄 적용하고 표현식을 한 번 평가한 뒤 실제 계산 snapshot과 SI 물리 의미를 대조한다. 표현식이나 기하 의미가 당시 봉인된 값과 다르면 명시적으로 차단한다. 최신 코드로 다시 계산하여 차이를 조용히 덮지 않는다. 현재 전체 runtime identity의 일치를 과거 결과 읽기의 전제조건으로 삼지 않는다.

새 사본의 향후 해석은 새 snapshot과 현재 명시 설정으로 별도 접수한다. 사본 생성 자체는 solver 실행, 목표 재평가 또는 수렴 판정이 아니다. `rfad.sweep-selection/0.1` 출처에는 원본 snapshot/정의/후보, 실제 계산 pin, 선택 Quantity와 사유를 남긴다. 이전 채택 출처는 덮어쓰지 않고 최대 16개 기록/64 KiB 안에서 보존한다. 이 출처 확장 자체는 새 물리 형상이나 재료를 추가하지 않는다.

## 5. 파일과 소유권

파일 참조를 가진 알려진 데이터는 실제 바이트, 크기, 해시와 소유자를 검사한다. 새 사본이 소유할 파일은 새 프로젝트 영역에 게시하고, 과거 계산 출처는 원래 소유자와 연결해 보존한다. JSON 안의 모든 `project_id`나 경로 문자열을 일괄 치환하지 않는다.

알려진 템플릿/정밀 편집/기판 선택/물리 구성의 자기완결 출처는 원문을 보존한다. 외부 STEP이 프로젝트에 포함된 경우 원문 바이트와 해시를 유지한다. 문헌/제조사 source reference는 인용 원문이며 임의 파일 복사 지시가 아니다.

네트워크 목록은 `imported`/`derived` 자료와 회로 정의만 지원한다. 자료의 정규 JSON/HDF5, 원문과 진단 파일을 최대 32개 참조/총 16 MiB 안에서 새 경로로 복사한다. 파생 자료의 입력/회로 연결을 유지하며 파일 내용 안의 과거 계산 출처는 바꾸지 않는다. `solver` 종류의 자료 또는 저장된 목표 평가가 포함된 목록은 복합 소유권 이관을 지원하지 않으므로 미리보기에서 차단한다. 자료나 평가 행을 빼서 성공시키지 않는다.

미지 확장은 복사 의미와 외부 의존성을 확인하지 못하므로 초기 profile에서 명시적으로 차단한다. 내용을 지우거나 이해한 것으로 간주하여 외부 파일을 탐색/실행하지 않는다. 원본의 미지 값과 확장은 그대로 남으며 지원 범위를 넓힐 때 별도 계약과 검증이 필요하다.

새 사본의 파일 게시 전에 프로젝트/명령/응답과 전체 복사 예산을 검사한다. 기존 유한 상한을 조용히 늘리거나 큰 출처를 생략하지 않는다. 기록 또는 게시가 실패하면 원본 프로젝트와 기존 대상 경로를 유지한다. 결과 불명은 새 요청으로 재생성하지 않고 같은 영수증의 권위 결과를 먼저 확인한다.

## 6. 검증 경계

검증은 원본 상태 불변, 후보 원문/계산 재사용 구분, 단일 명령 undo/redo, 파일 소유권/변조/예산, 재전송/결과 불명과 실제 Windows 저장/재열기를 나누어 수행한다. 합성 전송 또는 과거 결과 조회는 새 FDTD 실행이나 실측 정확도의 증거가 아니다.

9번의 목표 대역 원호/IFA 튜닝, 실제 급전/SMA와 외부 환경 사례는 이 채택 기능 외의 범위다. 필요한 부품/적층/급전 실장/측정 자료가 없는 항목은 미정 또는 차단으로 남긴다. 단계 8의 독립 RF 기준, 단계 11의 교정/시료/불확도와 단계 12의 전체 UX/성능 수용을 이 기능으로 대신하지 않는다.

## 7. 원호/IFA의 유한 작업 흐름 검증

이번 단계의 별도 실행 사례는 아래 명시 가정으로 연구, 결과 선택, 새 사본 채택과 재계산의 연결을 확인한다. 문헌 G031 또는 nRF 자료의 재현 완료 사례가 아니다. 실제 실행 횟수/성공/실패와 바이너리/소스 시점은 별도 단계 검증 기록에서 확정한다.

| 항목 | 실행 사례의 고정 범위 |
| --- | --- |
| IFA | 기존 40 x 60 mm 가정 기판, 방사 가지 길이 24/26/28 mm의 3후보. |
| 원호 | 명시 합성 기하, 반지름 4.5/5/5.5 mm의 3후보. 중심 x는 `25 - R` mm, 급전 위치는 (25, 52) mm로 고정. |
| 주파수 | 2.4~2.4835 GHz의 양끝을 포함하는 정확한 51개 표본. |
| 방사 기록 | 2.44175 GHz 한 주파수, theta/phi 15도 표본. |
| 급전 | 이상적인 국부 gap 포트. 실제 SMA 또는 급전 실장 모델이 아님. |
| 후보 선택 | 51개 표본의 최악 S11이 가장 작은 후보. 동률이면 앞 ordinal. 사전에 고정한 규칙이며 결과를 보고 바꾸지 않음. |
| 실행 상한 | 후보 6회와 선택한 새 사본의 재계산 2회. 무한 튜닝 또는 실패 후보의 자동 대체 없음. |

S11의 -10 dB 목표가 실패하면 실패로 보존한다. 선택한 값은 편집용 후보이며 성능 합격 설계로 승격하지 않는다. 51개 표본의 판단을 연속 대역이나 격자/경계/시간 수렴 합격으로 확대하지 않는다.

실제 납품 물성, 설치 시나리오의 배터리/외함 치수와 재료는 미정 원문을 보존한다. 해당 외부 부품의 `include_in_em=false`는 이번 계산에서 제외됐다는 뜻이며 환경 영향이 없다는 뜻이 아니다. SMA, 설치 환경 EM과 실측 자료가 갖춰지지 않은 상태를 이 작업 흐름 검증으로 해소했다고 표시하지 않는다.

소프트웨어 시험은 [기본 채택 시험](../../../Code/tests/test_sweep_selection.py)과 [독립 경계 시험](../../../Code/tests/test_sweep_selection_review.py)에 구분한다. 합성 복소 표본 fixture에는 FDTD가 아님을 명시한다. 독립 시험은 공간/기존 경로 거절 시 무게시, 출처를 재해시한 변조, 내부 명령 우회, 게시 직전/직후 장애와 runtime 없는 undo/redo를 검사한다.
