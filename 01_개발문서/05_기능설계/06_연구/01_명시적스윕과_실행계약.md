# 명시적 스윕과 실행 계약

기준: RFAD-D0-3.4, 개발 완료 계획 6번. 상태: 아래 유한 범위 구현. 실행 증거와 수용 상태는 [단계 검증](../../07_검증/13_설계스윕과_연구_검증.md)으로 별도 관리한다.

## 1. 범위

기존 `study.*`의 `rfad.project-study-definition/0.1`은 최대 6개 격자 수준의 수렴 연구로 유지한다. 새 `sweep.*`와 `rfad.design-sweep/0.1`은 다음 세 종류를 구분한다. 여러 축을 바꾼 연구 결과를 단일 축 수렴으로 표시하지 않는다.

| 종류 | 변경 대상 | 계산 |
| --- | --- | --- |
| `grid_sweep` | 기존 리터럴 설계 매개변수 | 변경한 설계 사본의 새 EM 계획/준비/해석 |
| `numerical_study` | 명시 격자, 곡선 오차, 종료 기준, 선택한 NF2FF 기록 거리/각도 등 | 고정 설계에 대한 수치 조건별 새 EM 실행 |
| `circuit_sweep` | 기존 외부 이상 RLC의 소자값/실장 상태 | 봉인된 복소 자료 재사용, native EM 실행 없음 |

연구 종류 사이의 축을 한 정의에 혼합하지 않는다. `grid_sweep`의 grid는 변수값의 유한 조합을 의미하며 PCB mesh 격자와 다르다. 표현식 매개변수는 직접 리터럴로 덮지 않고 그 표현식의 명시 입력 변수를 선택한다. 실제 부품 기생/실측 모델을 없는 상태에서 추가하지 않는다.

기하, 주파수 기반 초기 추정, 실제 해석 완료, 수치 수렴, 실물 검증은 각각 별도 상태다. 3차원 안테나 형상 원본/solver의 장기 로드맵을 기존 PCB 또는 CAD 표시 mesh만으로 구현 완료라 부르지 않는다.

## 2. 정의와 입력 보존

`rfad.design-sweep-spec/0.1`의 고정 필드는 `schema`, `name`, `type`, `combination`, `variables`, `rows`, `settings`, `network`, `target_ids`, `target_contexts`, `budget`, `source_refs`다. `rows`와 `target_contexts`가 생략되면 빈 목록으로 정규화한다. 원문 정의와 정규 정의는 모두 봉인하며 한쪽으로 대체하지 않는다.

변수는 `{kind, id, dimension, values}` 또는 `values` 대신 `{range:{start,stop,count}}`를 갖는다. Quantity 원본이나 `{text,unit,source_refs}` 입력을 서비스가 환산한다. 최대 8축, 축마다 최대 128값, 전체 후보 최대 128개다. 범위는 양끝을 그대로 남기고 유한 표본을 생성한다. 미정값을 0으로 대체하지 않는다.

| 조합 | 순서/조건 |
| --- | --- |
| `cartesian` | 마지막 축이 가장 빨리 증가하는 순서. 전체 곱을 먼저 검사하고 ordinal로 한 후보씩 생성 |
| `paired` | 모든 축의 목록 길이가 같아야 함. 짧은 축의 값을 자동 반복하지 않음 |
| `explicit_rows` | 각 변수 값 목록의 0기반 인덱스 행. GUI에는 실제 값/단위를 표시 |

회로 상태 축은 `dimension:state`, 값은 `connected/open/short/dnp`다. 동일 소자의 값 축과 실장 상태 축을 함께 둘 수 있으나 동일 `(kind,id)` 축을 중복 선언할 수 없다.

`settings_inputs`는 변경한 수치 설정의 Quantity 입력만 담는 선택 필드다. 기존 native 설정 사본에 서비스가 반영한다. `radiation.frequency_hz`는 1~3개 명시 Quantity 목록이며 수치 변수 축과 구분한다. NF2FF/독립 손실은 명시적 선택을 할 때만 추가한다. 제안한 수치 설정은 수렴을 검증한 권장값이 아니다.

`budget_inputs`는 변경한 시간/RAM/디스크의 `{text,unit}`를 담는다. 시간은 s/min/h, RAM/디스크는 MiB/GiB다. 메모리는 정수 바이트로 정확히 표현할 수 있어야 한다. 표시 단위만 바꿀 때 SI와 원문 상태/출처를 재해석하지 않는다. 원문 요청은 64 KiB, 정규 정의는 128 KiB 상한을 적용한다.

## 3. 기준과 후보

저장 시 현재 프로젝트의 전체 원본 snapshot, 목표 원본/개정, 설정, 회로/네트워크 artifact, runtime identity와 계산 엔진 정보를 고정한다. 연구 저장은 설계 수정이나 EM 실행이 아니며 프로젝트 개정/undo 기록을 바꾸지 않는다. 영수증을 재전송해도 같은 연구가 두 번 생성되지 않는다.

각 후보는 기준 사본에 모든 축을 한 번에 넣고 표현식을 재평가한 뒤 전체 검증/기본 DRC를 수행한다. 같은 입력으로 후보 revision과 patch를 재현하며 기준 revision을 부모로 남긴다. 기준 원본의 변경 시각은 수정하지 않고 실제 연구 생성 및 EM 작업 시각은 별도 기록한다. 후보 생성 시각을 원본 metadata에 새로 쓰지 않는다. 단위/표시 이름/출처만 다른 동치 값은 같은 계산 key를 사용할 수 있으나 사용자 지정 행과 최초 원문은 삭제하지 않는다. 불확실한 물리 필드는 보수적으로 key에 포함한다.

`valid`는 구조와 명시 강제 제약 검사 상태다. 물성 미정, unsupported EM 형상, native 미설치까지 해결되었다는 뜻이 아니다. 최종 계획 생성기가 실제 해석 입력을 검사한다. 기본 DRC의 미평가 항목도 후보 진단에 남긴다. 외부 회로 스윕은 저장된 복소 자료를 사용하므로 현재 PCB의 다른 DRC 실패를 회로 계산의 새로운 입력으로 적용하지 않는다.

후보 자료는 연구별 불변 파일에 저장하고 journal에는 작은 참조만 둔다. 첫 검토와 후보 조회는 파일을 만들지 않는다. 실행할 후보의 원본/계획을 필요한 시점에만 봉인한다. 프로젝트 512 KiB, 계획 256 KiB, journal 8 MiB, 작업 512개, snapshot 1024개, worker 소스 192개 상한을 조용히 늘리지 않는다. 큰 출처를 생략해서 적합하게 만들지 않는다.

## 4. 실행 예산과 재개

`budget`은 `max_candidates`, `max_native_solves`, `wall_seconds`, `ram_bytes`, `disk_bytes`, `concurrency`를 명시한다. 동시성은 1이며 기존 solver 슬롯을 공유한다. 과거 격자 연구와 새 스윕을 동시에 시작하지 않는다. 재시도도 native solve 횟수와 누적 시간 예산을 소비한다.

RAM은 계획의 초기 메모리 추정치 예약 검사이며 실제 프로세스 peak 측정 합격을 뜻하지 않는다. 디스크에는 원본/정의/후보/계획, source/capture, staging 복사본 및 결과 보존 비용을 포함한다. 기존 공유 journal의 모든 과거 commit, 설치 환경 및 사용자 파일 전체의 용량 제한과는 구분한다. 전체 후보의 정확한 자원량을 검토 화면에서 계산했다고 주장하지 않으며 실행 직전 후보별 계획을 검사한다.

시간은 활성 연구의 누적 경과 시간이다. 서비스 중단 후 실제 종료 시각을 알 수 없는 구간은 재시작 시 보수적으로 포함한다. 재개가 예산을 초기화하지 않는다. 예산 때문에 멈췄다면 완료 결과와 시도는 유지한다. 예산을 늘리는 것은 과거 정의의 수정이 아닌 새 연구 검토로 진행한다.

새 solver 작업은 `rfad.solver-capture/0.1`의 불변 캡처 참조를 저장한다. 실행 직전에 원본 계획/runtime/준비 자료를 검증해 메모리에서 복원한다. 과거 inline 작업 형식은 계속 읽는다. native 실행이 끝났는지 불명확하면 슬롯을 먼저 해제하거나 같은 후보를 다시 실행하지 않는다. 회로 계산도 패키지 버전만으로 동일 환경이라 판단하지 않고 Python ABI/버전 및 유한 앱 소스 manifest를 함께 고정한다. 소스 확인 실패나 변경은 시작/재개를 차단하며 저장된 결과 읽기는 유지한다.

연구를 저장할 때는 snapshot descriptor와 정의의 정확한 보존 바이트를 파일 게시 전에 계산한다. 확정된 디스크 예산 거절을 반복해도 새 snapshot/정의 파일을 남기지 않는다. 실제 디스크 쓰기 중 장애와 journal commit 실패의 복구 경계는 공통 저장 계약을 따른다.

취소는 실제 작업 종료를 확인한 뒤 확정한다. 완료 후보와 원문을 보존하고 실패/중단된 단계는 명시적 재개에서만 다시 접수한다. 재개 전 정의, snapshot, 후보/계획/결과 및 실행 캡처 해시를 대조한다. runtime이 달라지면 과거 결과 읽기는 유지하되 새 실행은 차단한다. 이 기능은 작업 단위 재개이며 FDTD timestep checkpoint 재개가 아니다.

## 5. 상태와 결과

연구 진행 상태와 후보의 물리/수치 판정은 분리한다. 후보의 순번, 입력값, 단계, 실제 시도, 완료 결과 참조, 실패 이유를 보존한다. `invalid_input`(회로값 등 입력 오류), `invalid_geometry`, `unsupported`, `solver_failed`, `nonconverged`, `evaluated`와 미평가를 구분하며 실패 후보를 목록이나 분모에서 없애지 않는다. 미수렴은 native 단계 상한 등 명시적인 구조화 근거가 있을 때만 표시하고 오류 문장으로 추측하지 않는다.

결과는 공통 복소 자료와 원문 목표 평가를 사용한다. 목표의 port/기준면 대응이 없으면 미평가다. 요구 주파수는 `exact_only`로 평가하며 보간/가장 가까운 점을 채워 목표를 통과시키지 않는다. 외부 RLC 뒤에 원래 안테나 효율을 복사하지 않는다. 일반적인 수렴 비교나 물리 정확도가 확립되지 않은 수치 연구에는 그 상태를 명시한다.

후보 결과를 기존 network 목록에 자동 추가하지 않는다. 연구의 128개 후보와 일반 자료 목록의 32개 보존 상한을 혼동하지 않는다. 후보 조회는 한 페이지 최대 25개, 결과 표본은 한 페이지 최대 201개다. 선택 후보 보기와 원래 설계/자료 채택은 별도 동작이다.

## 6. API와 검수

읽기: `sweep.context/preview/list/get/page/result/quantity`. 변경: `sweep.create/start/cancel/resume`. `rfad.api/2.0`의 프로젝트 소유권과 변경 영수증을 사용한다. preview/create는 같은 예상 개정과 입력 및 검토 hash를 요구한다. get/page/result는 저장 당시 원본을 읽으므로 현재 편집 개정이 달라도 출처를 바꾸지 않는다.

검수는 유한 조합/단위 동치/표현식/원본 출처, 실제 회로 계산, native 작업 접수와 종료, 중단/명시 재개, 자원·변조·수명 경계를 나누어 기록한다. 가짜 전송을 이용한 수명 시험, 실제 Windows GUI, 실제 WSL 계산을 합쳐 하나의 RF 정확도 합격으로 표시하지 않는다. RO4350B 2.788446%와 초기 2% 기준 미확립, GHz PTH 독립 정확도 미확립 및 제작/측정 조건의 미정은 유지한다.
